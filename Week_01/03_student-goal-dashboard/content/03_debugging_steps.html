บทเรียน 03 · ทบทวนและการ Debug (Recap & Debugging)

Debug อย่างเป็นขั้นตอนด้วย console.log

Debugging Step by Step

เมื่อจบบทนี้ คุณจะสามารถ

  • ไล่หาปัญหาตามขั้นตอน debug 4 ขั้น แทนการเดาไปเรื่อย ๆ
  • เปิด Console ของเบราว์เซอร์เพื่ออ่าน error และดูผลของ console.log
  • ใช้ console.log ตรวจว่า JavaScript หา element เจอหรือไม่ (ได้ element หรือได้ null)
  • ใช้ console.log ดูค่าจริงของตัวแปรระหว่างทาง

Error เป็นเรื่องปกติ

เวลาเขียนโปรแกรมจริง สิ่งที่ยากไม่ใช่การเขียนให้ถูกตั้งแต่แรก แต่คือการรู้ว่า เวลามันพัง เราควรเริ่มไล่จากตรงไหน Developer ทุกคนเจอ error ทุกวัน สิ่งที่แยกคนที่แก้ได้เร็วออกจากคนที่ติดอยู่นาน ๆ คือการ debug อย่างมีขั้นตอน ไม่ใช่เดาแล้วแก้มั่วไปเรื่อย ๆ

หลัก debug เบื้องต้น 4 ขั้น

  1. อ่าน error หรือสังเกตอาการ — มีข้อความ error ใน Console ไหม? หน้าเว็บเป็นอย่างไร (ไม่มีอะไรเกิดขึ้นเลย, แสดงผิด, แสดงซ้ำ)?
  2. ดูว่าเพิ่งแก้อะไรไปล่าสุด — ถ้าเมื่อกี้ยังทำงานได้ ปัญหามักอยู่ในสิ่งที่เพิ่งแก้
  3. เช็กการเชื่อมโยงระหว่าง HTML, CSS, JavaScript — เชื่อมไฟล์ครบไหม? id และ class ตรงกันไหม?
  4. ใช้ console.log เพื่อดูค่าระหว่างทาง — อย่าเชื่อว่าค่า “น่าจะ” ถูก ให้พิมพ์ออกมาดูจริง ๆ

เปิด Console ของเบราว์เซอร์

ทั้ง error และผลลัพธ์ของ console.log จะไปแสดงในแท็บ Console ของ DevTools วิธีเปิดใน Google Chrome:

  • คลิกขวาบนหน้าเว็บ แล้วเลือก Inspect (ตรวจสอบ) จากนั้นเลือกแท็บ Console
  • หรือกด F12 (Windows) / Cmd + Option + J (macOS)

ทำให้เป็นนิสัย: เปิด Console ค้างไว้ตลอดเวลาที่เขียน JavaScript ข้อความสีแดงคือ error ที่บอกทั้งประเภทของปัญหาและชื่อไฟล์กับเลขบรรทัดที่เกิด (เช่น script.js:12) คลิกที่ชื่อไฟล์นั้นเพื่อกระโดดไปดูบรรทัดที่มีปัญหาได้เลย

console.log คืออะไร

console.log คือการสั่งให้ JavaScript แสดงค่าบางอย่างออกมาใน Console เพื่อช่วยให้เรารู้ว่าโค้ด ณ ตอนนี้ “เจอสิ่งที่เราคิดไว้หรือเปล่า” ผู้ใช้ทั่วไปจะไม่เห็นข้อความนี้บนหน้าเว็บ มันมีไว้ให้ developer ดูเท่านั้น

ตรวจว่า JavaScript หา element เจอหรือไม่

สมมติเรามี input ใน form ที่มี id="fullName":

const fullNameInput = document.getElementById("fullName");

console.log(fullNameInput);
สิ่งที่เห็นใน Consoleแปลว่า
element <input id="fullName" ...>JavaScript หา element เจอ ไปต่อได้
nullJavaScript หา element ไม่เจอ ให้เช็กว่า id ใน HTML ตรงกับใน JavaScript หรือไม่

ตรวจค่าที่ผู้ใช้กรอกจริง ๆ

const fullName = fullNameInput.value;

console.log(fullName);

บรรทัดนี้ช่วยให้เราเห็นว่าค่าที่ผู้ใช้กรอกเข้ามาจริง ๆ คืออะไร นี่คือวิธี debug ที่สำคัญมาก เพราะบางครั้งเรา คิดว่า ค่ามีแล้ว แต่จริง ๆ อาจว่างอยู่ก็ได้

ระวังตำแหน่งของ console.log ถ้าเราอ่าน .value ตั้งแต่ตอนโหลดหน้าเว็บ (นอกฟังก์ชันที่ทำงานตอน submit) ค่าที่ได้จะเป็นข้อความว่าง เพราะตอนนั้นผู้ใช้ยังไม่ได้พิมพ์อะไรเลย ให้อ่านค่าและ console.log ภายในฟังก์ชันที่ทำงานตอนกดปุ่มหรือ submit

ใส่ป้ายกำกับให้ console.log

ถ้า log หลายค่าพร้อมกัน Console จะเต็มไปด้วยค่าที่แยกไม่ออกว่าอันไหนมาจากบรรทัดไหน เราส่งข้อความนำหน้าเข้าไปได้ โดยคั่นด้วยเครื่องหมายจุลภาค:

console.log("fullNameInput:", fullNameInput);
console.log("fullName:", fullName);

ฝึก: debug ตามขั้นตอน

ลองกลับไปที่หน้าเว็บที่คุณทำพังไว้ในบทที่แล้ว (id สะกดผิด, ลืม script, ลืม .value) แล้วไล่ทีละข้อตาม 4 ขั้นด้านบน:

  1. เปิด Console แล้วดูว่ามี error สีแดงหรือไม่ อ่านข้อความและเลขบรรทัด
  2. ใส่ console.log หลังบรรทัด getElementById ทุกบรรทัด แล้วดูว่ามีตัวไหนได้ null
  3. ใส่ console.log หลังบรรทัดที่อ่านค่าจาก input แล้วดูว่าค่าเป็นสิ่งที่คุณพิมพ์จริงหรือไม่
  4. ถ้า Console ว่างเปล่าแม้แต่ console.log ก็ไม่แสดง ให้สงสัยว่าไฟล์ JavaScript ยังไม่ได้เชื่อมกับ HTML

เมื่อแก้ปัญหาได้แล้ว ลบ console.log ที่ใส่ไว้เพื่อ debug ออก หรือเก็บไว้เฉพาะตัวที่ยังมีประโยชน์ จะได้ไม่รก Console ตอนทำงานชิ้นต่อไป

  • จำหลัก debug 4 ขั้นได้: อ่าน error/สังเกตอาการ, ดูสิ่งที่เพิ่งแก้, เช็กการเชื่อมโยง, ใช้ console.log
  • เปิดแท็บ Console ของเบราว์เซอร์ได้
  • รู้ว่าถ้า console.log ผลของ getElementById แล้วได้ null ต้องไปเช็ก id
  • ใช้ console.log ดูค่าจริงของตัวแปร แทนการเดาว่าค่า “น่าจะมี”
