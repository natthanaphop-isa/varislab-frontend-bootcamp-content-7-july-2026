บทเรียน 02 · ทบทวนและการ Debug (Recap & Debugging)

ข้อผิดพลาดที่เจอบ่อยจากการทำ Assignment

Common Mistakes

เมื่อจบบทนี้ คุณจะสามารถ

  • เข้าใจว่า Code Review คือการช่วยกันปรับปรุงโค้ด ไม่ใช่การจับผิด
  • ตรวจได้ว่า id ใน HTML ตรงกับที่ JavaScript เรียกหรือไม่
  • เช็กได้ว่าไฟล์ JavaScript ถูกเชื่อมกับ HTML แล้ว
  • แยกได้ระหว่าง “ตัวกล่อง input” กับ “ค่าที่ผู้ใช้กรอก” (.value)
  • ใช้เช็กลิสต์ 3 ข้อแรกเมื่อหน้าเว็บไม่เปลี่ยนตามที่แก้

Code Review ไม่ใช่การจับผิด

บทนี้เราจะดูข้อผิดพลาดที่มักพบในงาน assignment ของผู้เริ่มต้น ก่อนอ่านต่อ อยากให้มองแบบนี้: Code Review คือการช่วยกันดูว่าโค้ดอ่านง่ายไหม มีจุดไหนปรับให้ดีขึ้นได้ไหม และมี bug ที่อาจเกิดขึ้นในอนาคตหรือเปล่า Developer ตัวจริงก็ทำ Code Review กันตลอด การได้รับ feedback จึงเป็นเรื่องปกติมาก และเป็นทางลัดที่ดีที่สุดในการเก่งขึ้น

ข้อผิดพลาดด้านล่างนี้เป็นสิ่งที่เจอบ่อยมากในงานของผู้เริ่มต้น ถ้าคุณเคยเจอสักข้อ ไม่ต้องกังวล — ทุกคนเคยเจอมาแล้วทั้งนั้น

1. id ใน HTML กับ JavaScript ไม่ตรงกัน

สมมติใน HTML เราเขียนแบบนี้:

<p id="summary">ข้อความเดิม</p>

แต่ใน JavaScript เขียนว่า:

const summary = document.getElementById("profileSummary");

JavaScript กำลังหา element ที่มี id ชื่อ profileSummary แต่ใน HTML ไม่มี id นี้เลย (มีแค่ summary) ผลคือมันหา element ไม่เจอ และตัวแปร summary จะได้ค่าเป็น null — พอเราเอาไปใช้ต่อ เช่น summary.textContent = "..." โค้ดจะพังทันที

วิธีแก้: ชื่อ id ใน HTML และใน JavaScript ต้องตรงกัน 100% ทั้งตัวสะกดและตัวพิมพ์เล็ก–ใหญ่

const summary = document.getElementById("summary");

id แยกตัวพิมพ์เล็ก–ใหญ่ studentList, studentlist และ StudentList ถือเป็นคนละชื่อกัน วิธีที่ปลอดภัยคือ copy ชื่อ id จาก HTML มาวางใน JavaScript แทนการพิมพ์ใหม่

2. ลืมเชื่อมไฟล์ JavaScript

ในไฟล์ HTML ต้องมีบรรทัดนี้ (ปกติวางไว้ก่อนปิด </body>):

<script src="script.js"></script>

ถ้าไม่มีบรรทัดนี้ เบราว์เซอร์จะไม่รู้จักไฟล์ script.js เลย ปุ่มจะกดไม่ทำงาน ถึงแม้โค้ดใน script.js จะถูกทุกบรรทัดก็ตาม ให้เช็กด้วยว่าชื่อไฟล์ใน src ตรงกับชื่อไฟล์จริง (เช่น ไม่ใช่ scripts.js ทั้งที่ไฟล์ชื่อ script.js)

3. ลืม .value

ถ้าเราต้องการค่าที่ผู้ใช้กรอก ต้องเขียนแบบนี้:

const name = nameInput.value;

ไม่ใช่แบบนี้:

const name = nameInput;

เพราะ nameInput คือ ตัวกล่อง input ทั้งกล่อง ส่วน nameInput.value คือ ข้อความที่ผู้ใช้กรอกในกล่องนั้น ลองนึกภาพกล่องจดหมาย: nameInput คือตัวกล่อง ส่วน .value คือจดหมายที่อยู่ข้างใน

เขียนว่าได้อะไร
nameInputelement <input> ทั้งตัว
nameInput.valueข้อความที่ผู้ใช้พิมพ์ในช่องนั้น

4. ไม่ได้ save ไฟล์ หรือไม่ได้ refresh เบราว์เซอร์

ข้อนี้ฟังดูง่าย แต่เป็นสาเหตุอันดับต้น ๆ ของอาการ “แก้แล้วแต่หน้าเว็บไม่เปลี่ยน” ทุกครั้งที่หน้าเว็บไม่เปลี่ยนตามที่แก้ ให้เช็ก 3 อย่างแรกนี้ก่อนเสมอ:

  1. Save file แล้วหรือยัง (ใน VS Code แท็บไฟล์ที่ยังไม่ save จะมีจุดวงกลมแสดงอยู่)
  2. Refresh browser แล้วหรือยัง
  3. แก้ถูกไฟล์ หรือเปล่า (เช่น เปิดไฟล์ในโฟลเดอร์หนึ่ง แต่เบราว์เซอร์เปิดอีกโฟลเดอร์หนึ่งอยู่)

ข้อ 3 เจอบ่อยมากเมื่อมีโฟลเดอร์หน้าตาคล้ายกันหลายชุด เช่น start/ และ finish/ ให้ดู path ในแถบที่อยู่ของเบราว์เซอร์ว่าตรงกับไฟล์ที่คุณกำลังแก้ใน editor หรือไม่

ลองทำให้พังเอง

วิธีจำข้อผิดพลาดเหล่านี้ได้ดีที่สุดคือลองทำให้เกิดขึ้นเองแล้วดูอาการ เปิดงานหน้าเว็บที่มี form หรือปุ่มที่คุณเคยทำไว้ แล้วลองทีละข้อ (อย่าลืมแก้กลับหลังลองแต่ละข้อ):

  1. เปลี่ยนชื่อ id ใน JavaScript ให้สะกดผิดหนึ่งตัวอักษร แล้วลองใช้งานหน้าเว็บ
  2. ลบ (หรือ comment) บรรทัด <script src="script.js"></script> แล้วลองกดปุ่ม
  3. ลบ .value ออกจากบรรทัดที่อ่านค่าจาก input แล้วดูว่าข้อความที่แสดงออกมาเป็นอะไร

สังเกตว่าบางข้อหน้าเว็บ “เงียบ” ไม่บอกอะไรเลย ในบทถัดไปเราจะเรียนวิธีไล่หาสาเหตุอย่างเป็นขั้นตอน แทนการเดาไปเรื่อย ๆ

  • อธิบายได้ว่าทำไม getElementById ถึงได้ null เมื่อ id ไม่ตรงกัน
  • รู้ว่าต้องมี <script src="script.js"></script> ใน HTML และชื่อไฟล์ต้องตรงกับไฟล์จริง
  • แยกได้ว่า nameInput กับ nameInput.value ต่างกันอย่างไร
  • จำเช็กลิสต์ 3 ข้อได้: save แล้วหรือยัง, refresh แล้วหรือยัง, แก้ถูกไฟล์หรือเปล่า
ก่อนหน้า: ทบทวนพื้นฐานและเป้าหมายของคอร์ส สารบัญบทเรียน ถัดไป: Debug อย่างเป็นขั้นตอนด้วย console.log
