บทเรียน 14 · คอมโพเนนต์กลาง (Shared UI)

คอมโพเนนต์แสดงผล

Display Components

บทสุดท้ายของช่วงคอมโพเนนต์กลาง คราวนี้เป็นชุดคอมโพเนนต์แสดงผล (presentational components) สี่ตัว — งานของพวกมันคือรับ props เข้ามาแล้ว render ให้สวย ไม่ยุ่งกับ API ไม่รู้จัก business logic ของแอปเลย (มีตัวเดียวที่มี state ภายใน คือ CountdownTimer ซึ่งจะได้ทวนเรื่อง effects กันเต็ม ๆ) แต่ละตัวมีที่ไปชัดเจน:

  • StarReview — ดาวคะแนนรีวิว จะโผล่ทั้งบน ProductCard (บทเรียน 18) และหน้า Product detail ทั้งส่วนข้อมูลสินค้าและการ์ดรีวิว (บทเรียน 21)
  • FeatureCard — การ์ดจุดขายของร้าน (ส่งฟรี, คืนสินค้าได้, …) เรียงแถวอยู่บนหน้า Home (บทเรียน 19)
  • CountdownTimer — นาฬิกานับถอยหลังของโซนดีลพิเศษบนหน้า Home (บทเรียน 19)
  • ImageZoom — รูปที่ซูมนุ่ม ๆ ตอน hover ใช้กับรูปดีลและแบนเนอร์บนหน้า Home (บทเรียน 19)

ไม่มีไลบรารีใหม่ให้ติดตั้งบทนี้ — ทุกอย่างสร้างจากของที่มีอยู่แล้ว และเป็นบทแรกที่เราจะได้ใช้ Font Awesome ชุด free-regular ที่ติดตั้งค้างไว้ตั้งแต่บทเรียน 10 โดยยังไม่เคยแตะ

StarReview: เลขคณิตของดาว

ทุกเว็บขายของต้องมีดาว โจทย์ของเราคือ: รับตัวเลขคะแนนมาหนึ่งตัว แล้ว render ดาว 5 ดวงโดยแบ่งเป็นดวงทึบ (ได้คะแนน) กับดวงโปร่ง (ไม่ได้) — Font Awesome มีดาวให้ทั้งสองแบบ ชื่อ faStar เหมือนกันเป๊ะแต่มาจากคนละแพ็กเกจ (free-solid-svg-icons กับ free-regular-svg-icons) เราจึงต้องใช้ as ตั้งชื่อเล่นแยกกันตอน import

สี่ท่าที่อยู่ในไฟล์สั้น ๆ นี้ และเป็นสิ่งที่ต้องตรวจให้ออกทีหลัง:

  • Math.round(score / 2) — contract ของคอมโพเนนต์ (ตาม comment ในโค้ด) คือรับ score สเกล 0–10 การหารสองแปลงเป็นสเกล 0–5 แล้วปัดเป็นจำนวนเต็ม ได้ "จำนวนดาวทึบ" เช่น score 9 → 4.5 → ปัดเป็น 5 ดวงทึบ — คำว่า "สเกล 0–10" นี้เป็นสมมติฐานที่มาจาก comment ในโค้ดต้นฉบับ ไม่ใช่สิ่งที่ใครไปตรวจกับข้อมูลจริง บทเรียน 21 จะเอามันไปเทียบกับ payload ของ dummyjson แล้วคุยกันว่าเกิดอะไรขึ้น
  • [...Array(5)] — ท่าสร้าง array ยาว 5 ช่องเพื่อเอาไว้ .map() — ทำไมต้อง spread? เพราะ Array(5) เฉย ๆ ได้ array โปร่ง (sparse) ที่ .map() จะข้ามช่องว่างไปเลย spread ก่อนหนึ่งทีจะเติม undefined ให้ครบทุกช่อง map ได้ครบ 5 รอบ
  • index < stars ? solidStar : regularStar — ดาวดวงที่ index 0 ถึง stars - 1 เป็นดวงทึบ ที่เหลือเป็นดวงโปร่ง เงื่อนไขเดียวบรรทัดนี้คือทั้งหมดของ "ดาวสามดวงครึ่ง" ที่ผู้ใช้เห็น
  • key={index} — ปกติเราหลีกเลี่ยง index เป็น key แต่กรณีนี้ list ยาว 5 ตายตัว ไม่มีการสลับลำดับหรือเพิ่มลด ใช้ index ได้ปลอดภัย

CountdownTimer: ตัวเดียวในบทนี้ที่มีชีวิต

นาฬิกาถอยหลังของโซน "ดีลจะหมดใน…" บนหน้า Home ตัวเลขต้องเดินทุกวินาที ซึ่งแปลว่าเราต้องได้ใช้สองเครื่องมือจากคอร์ส React พื้นฐาน พร้อมกัน: useState เก็บเวลาที่เหลือ และ useEffect จัดการ side effect (ตั้ง interval) พร้อม cleanup

มาแกะการคำนวณเวลาที่เหลือกันช้า ๆ เพราะนี่คือโจทย์คลาสสิกที่เจอบ่อยในงานจริง:

  • หา "ระยะห่าง" เป็นมิลลิวินาที — new Date(targetDate).getTime() แปลงเวลาเป้าหมาย (string เช่น วันพรุ่งนี้เที่ยงคืน) เป็นตัวเลข timestamp แล้วลบด้วยเวลาปัจจุบัน ได้ difference = จำนวนมิลลิวินาทีที่เหลือ
  • วัน — หนึ่งวันมี 1000 * 60 * 60 * 24 มิลลิวินาที (ms → วินาที → นาที → ชั่วโมง → วัน) หาร difference แล้ว Math.floor ปัดลง ได้จำนวนวันเต็ม
  • ชั่วโมง — หารด้วยมิลลิวินาทีต่อชั่วโมง ได้จำนวนชั่วโมงทั้งหมด (เช่น 50 ชั่วโมง) แล้ว % 24 ตัดส่วนที่ถูกนับเป็นวันไปแล้วออก เหลือ 2 ชั่วโมง — modulo คือพระเอกของสูตรนี้
  • นาที / วินาที — ตรรกะเดียวกัน: หารให้เป็นหน่วยนั้น แล้ว % 60 เอาเฉพาะเศษที่ไม่ถูกหน่วยใหญ่กว่านับไปแล้ว
  • กันเวลาติดลบ — ถ้าเลยเวลาเป้าหมายไปแล้ว (difference <= 0) ตั้งทุกช่องเป็นศูนย์ ไม่ปล่อยให้โชว์ตัวเลขติดลบประหลาด ๆ

ส่วนโครง effect คือแพตเทิร์น interval + cleanup ตรงตำราจากคอร์ส React พื้นฐาน: setInterval(calculateTimeLeft, 1000) สั่งให้คำนวณใหม่ทุกวินาที (แต่ละรอบเรียก setTimeLeft → re-render → ตัวเลขบนจอเดิน) และบรรทัดที่สำคัญที่สุดคือ return () => clearInterval(timer) — ถ้าไม่มี cleanup ตอนคอมโพเนนต์ unmount (ผู้ใช้กดไปหน้าอื่น) interval จะยังวิ่งอยู่เบื้องหลังและเรียก setState ใส่คอมโพเนนต์ที่ตายไปแล้ว กลายเป็น memory leak สะสม dependency array [targetDate] ก็ทำงานร่วมกับ cleanup อย่างถูกต้อง: ถ้าเป้าหมายเปลี่ยน React จะ cleanup interval เก่าก่อนแล้วตั้งตัวใหม่ให้เอง

จำย่อหน้านี้ไว้ให้ดี เพราะบรรทัด return บรรทัดเดียวนั้นคือข้อแรกของ checklist ในบทนี้ และเป็นบรรทัดที่หายไปแล้วไม่มีเครื่องมือตัวไหนในโปรเจกต์เราบอกให้

ImageZoom: เอฟเฟกต์ที่ทั้งหมดอยู่ใน CSS

ตัวปิดท้ายเบา ๆ — เอฟเฟกต์ที่เจอได้ทั่วไปในเว็บขายของ: เอาเมาส์ชี้รูปแล้วรูปขยับซูมเข้านิด ๆ ความลับคือมันเป็น CSS ล้วน ตัว TSX แค่จัดโครงให้ กลไกอยู่ที่การจับคู่สอง class: .image ขยายตัวเป็น 105% ตอน hover (พร้อม transition ครึ่งวินาทีให้เคลื่อนนุ่ม ไม่กระตุก) ส่วน container ครอบด้วย overflow: hidden — ส่วนที่ขยายเกินขอบถูกตัดทิ้ง ผลลัพธ์เลยดูเหมือน "ซูมอยู่ในกรอบ" ไม่ใช่รูปบวมดันเพื่อนบ้าน

ส่วน FeatureCard ไม่มีอะไรให้อธิบายเป็นพิเศษ — presentational แท้ ๆ ไม่มีสักบรรทัดที่เป็น logic: icon ใหญ่ด้านซ้าย หัวข้อกับคำอธิบายด้านขวา ที่ควรสังเกตมีจุดเดียวคือ type ของ prop icon ซึ่งเป็น IconDefinition (ตัว object icon ตรง ๆ จากแพ็กเกจ solid) ต่างจาก IconProp ที่ Button ใช้ในบทเรียน 12 ทั้งคู่ใช้ได้ นี่คือความจริงของ codebase ที่มีวิวัฒนาการ — และเป็นจุดที่ Agent มีสิทธิ์ "ช่วย" ทำให้เหมือนกันโดยที่เราไม่ได้สั่ง

สัญญาของแต่ละไฟล์ — และสิ่งที่มันต้องไม่ทำ:

  • StarReview — ต้องรับคะแนนสเกล 0–10 ตัวเดียวแล้ว render ดาวห้าดวงเสมอ ต้องไม่รับ prop จำนวนดาวสูงสุด ไม่รับสี และไม่รู้จักคำว่า product
  • FeatureCard — ต้องเป็น presentational ล้วน: ไม่มี state ไม่มี event handler ไม่มี onClick
  • CountdownTimer — ต้องมี cleanup ที่ clearInterval ใน return ของ effect และ dependency array ต้องมี targetDate ต้องไม่มีการเรียก API และไม่มี setTimeout ซ้อนกันเป็นชั้น ๆ
  • ImageZoom — ต้องบังคับให้ทุกคนที่ใช้ส่ง alt มา (prop ไม่เป็น optional) ต้องไม่มี JavaScript ที่จัดการ hover เอง เอฟเฟกต์ทั้งหมดอยู่ในไฟล์ SCSS

  useState เก็บ object ที่มีสี่ field เป็น number: days, hours, minutes, seconds
    ค่าเริ่มต้นเป็นศูนย์ทั้งสี่
    ระบุ type ของ state เป็น type literal ในวงเล็บมุมของ useState ตรง ๆ ห้ามประกาศ interface แยก
  ใน useEffect ประกาศฟังก์ชัน calculateTimeLeft ที่:
    หา difference = เวลาเป้าหมาย ลบ เวลาปัจจุบัน (ทั้งคู่ผ่าน getTime())
    ถ้า difference > 0 ให้ setTimeLeft ด้วยค่าที่คำนวณจาก difference:
      days   = Math.floor(difference / (1000 * 60 * 60 * 24))
      hours  = Math.floor((difference / (1000 * 60 * 60)) % 24)
      minutes = Math.floor((difference / (1000 * 60)) % 60)
      seconds = Math.floor((difference / 1000) % 60)
    ถ้าไม่ ให้ setTimeLeft เป็นศูนย์ทั้งสี่ค่า
  แล้วตั้ง const timer = setInterval(calculateTimeLeft, 1000)
  effect ต้อง return () => clearInterval(timer) และมี dependency array เป็น [targetDate]
  return div className={`${styles.countdownContainer} flex flex-center pt-15 pb-15
    pl-30 pr-30 fs-18 gap-20 fw-medium`} ข้างในเป็น span ของทั้งสี่ค่าคั่นด้วย :
  ห้ามเรียก calculateTimeLeft นอก interval และห้ามใช้ setTimeout

- ห้ามแก้ type ของ prop icon ใน src/shared/components/Button/Button.tsx ให้เหมือน FeatureCard
- ห้ามสร้าง index.ts หรือไฟล์ barrel
- ยังไม่ต้องเอาสี่ตัวนี้ไปใช้ในหน้าไหน

  • dependency array ของ effect เป็น [targetDate] ไม่ใช่ [] — ถ้าเป็น array ว่าง ค่า targetDate ที่เปลี่ยนทีหลังจะไม่มีผล และ npm run lint จะเตือน react-hooks/exhaustive-deps ให้เห็น
  • calculateTimeLeft ถูกประกาศข้างใน effect ไม่ใช่ข้างนอกคอมโพเนนต์หรือระดับ component body — ถ้าย้ายออกไปข้างนอก มันจะกลายเป็น dependency ที่ต้องใส่ใน array เพิ่ม

  • StarReview import ดาวสองตัวจากคนละแพ็กเกจพร้อม as — ถ้าเจอ faStar ตัวเดียวแล้วเปลี่ยนสีเอาเอง แปลว่ามันไม่ได้ใช้ชุด regular ตามที่สั่ง
  • FeatureCard ใช้ type IconDefinition และ Button.tsx ยังใช้ IconProp เหมือนเดิม — สองไฟล์นี้ต้องไม่ถูกทำให้เหมือนกัน
  • ImageZoom ไม่มี useState, ไม่มี onMouseEnter — ถ้าเจอ แปลว่ามันไปทำ hover ด้วย JavaScript ซึ่งได้ผลลัพธ์คล้ายกันบนจอแต่หนักกว่าและกระตุกกว่า
  • prop alt ของ ImageZoom เป็น string แบบบังคับ ไม่ใช่ alt?: string
  • ทุกไฟล์ .module.scss ที่ใช้ตัวแปรขึ้นต้นด้วย @use "../../../styles/variables"; และไม่มีค่า hex โผล่มาสักค่า — ยกเว้น ImageZoom.module.scss ที่ต้องไม่มีบรรทัด @use เลย เพราะไม่ได้ใช้ตัวแปร
  • ค้นชื่อ class ทุกตัวใน className ว่ามีจริงใน src/styles/ (grep -rn "ชื่อ-class" src/styles/) โดยเฉพาะกลุ่ม pl-30 pr-30 ที่ยาวผิดหูผิดตา
  • ไม่มี useEffect โผล่ในสามตัวที่เหลือ — StarReview, FeatureCard และ ImageZoom ต้องไม่มี state และไม่มี effect เลยแม้แต่ตัวเดียว

src/shared/components/CountdownTimer/CountdownTimer.tsx:

import React, { useState, useEffect } from "react";
import styles from "./CountdownTimer.module.scss";

interface CountdownTimerProps {
  targetDate: string;
}

const CountdownTimer: React.FC<CountdownTimerProps> = ({ targetDate }) => {
  const [timeLeft, setTimeLeft] = useState<{
    days: number;
    hours: number;
    minutes: number;
    seconds: number;
  }>({
    days: 0,
    hours: 0,
    minutes: 0,
    seconds: 0,
  });

  useEffect(() => {
    const calculateTimeLeft = () => {
      const now = new Date().getTime();
      const target = new Date(targetDate).getTime();
      const difference = target - now;

      if (difference > 0) {
        setTimeLeft({
          days: Math.floor(difference / (1000 * 60 * 60 * 24)),
          hours: Math.floor((difference / (1000 * 60 * 60)) % 24),
          minutes: Math.floor((difference / (1000 * 60)) % 60),
          seconds: Math.floor((difference / 1000) % 60),
        });
      } else {
        setTimeLeft({ days: 0, hours: 0, minutes: 0, seconds: 0 });
      }
    };

    const timer = setInterval(calculateTimeLeft, 1000);

    return () => clearInterval(timer);
  }, [targetDate]);

  return (
    <div
      className={`${styles.countdownContainer} flex flex-center pt-15 pb-15 pl-30 pr-30 fs-18 gap-20 fw-medium`}
    >
      <span>{timeLeft.days}</span>:<span>{timeLeft.hours}</span>:
      <span>{timeLeft.minutes}</span>:<span>{timeLeft.seconds}</span>
    </div>
  );
};

export default CountdownTimer;
💡 สังเกตอะไรไหม? calculateTimeLeft ถูกเรียกครั้งแรกเมื่อ interval ครบวินาทีแรก แปลว่าหลัง mount นาฬิกาจะโชว์ 0:0:0:0 ประมาณหนึ่งวินาทีก่อนกระโดดเป็นค่าจริง — ถ้าอยากให้ขึ้นทันทีก็แค่เรียก calculateTimeLeft() หนึ่งครั้งก่อน setInterval โปรเจกต์นี้เลือกแบบเรียบง่ายตามต้นฉบับ (และ prompt ของเราก็สั่งห้ามไว้ เพื่อให้ของที่ได้ตรงกับโค้ดอ้างอิง) แต่การมองเห็นรายละเอียดแบบนี้ในโค้ดคือทักษะ code review ที่ดี
