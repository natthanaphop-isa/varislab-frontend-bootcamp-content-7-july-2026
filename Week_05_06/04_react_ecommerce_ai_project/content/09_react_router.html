ตอนนี้โปรเจกต์ของเรามีโครงสร้างโฟลเดอร์ครบแล้ว แต่ยังแสดงได้แค่หน้าเดียว เว็บ E-commerce ของเรามีถึง 6 หน้า — Home, Category, Product detail, Cart, Checkout และ Order Success — ผู้ใช้ต้องเดินไปมาระหว่างหน้าเหล่านี้ได้ด้วย URL ที่กด back/forward และ bookmark ได้จริง นั่นคือหน้าที่ของ router และในบทนี้เราจะวางมันให้เสร็จทั้งระบบ

ทำไมต้อง react-router

ในคอร์ส React พื้นฐาน คุณใช้ TanStack Router มาแล้ว ดังนั้นแนวคิดทั้งหมดของบทนี้คุณรู้จักอยู่แล้ว: แอปมี route หลายเส้น แต่ละเส้นจับคู่ URL กับ component, มี layout ที่ครอบทุกหน้า และมี <Outlet /> เป็นช่องว่างที่หน้าปัจจุบันจะถูกเสียบเข้าไป คราวนี้เราจะใช้ react-router ซึ่งเป็น router ที่ใช้กันแพร่หลายที่สุดตัวหนึ่งในโลก React — โอกาสสูงมากที่โปรเจกต์แรกในงานจริงของคุณจะใช้ตัวนี้ การได้ลองทั้งสองตัวจะทำให้คุณเห็นชัดว่าสิ่งที่คุณเข้าใจคือแนวคิดของ routing ไม่ใช่แค่ API ของ library ใดตัวหนึ่ง

เทียบของที่คุณรู้จักจาก TanStack Router กับของที่กำลังจะเจอ:

  • createRouter + route tree → ที่นี่คือ createBrowserRouter + array ของ RouteObject
  • root route ที่ครอบทุกหน้า → ที่นี่คือ layout route (route ที่มี element แต่ไม่มี path และมี children)
  • <Outlet /> → ชื่อเดียวกัน หน้าที่เดียวกันเป๊ะ
  • <RouterProvider router={router} /> → ชื่อเดียวกันอีกเช่นกัน
  • dynamic segment $postId → ที่นี่เขียนเป็น :id

react-router รุ่นปัจจุบันมีโหมดการใช้งานหลายแบบ เราจะใช้ data mode คือสร้าง router ด้วย createBrowserRouter จาก object ที่บรรยาย route ทั้งหมด แทนการเขียน <Routes><Route> ซ้อนกันใน JSX แบบรุ่นเก่า ข้อดีคือ route กลายเป็นข้อมูลที่อยู่ในไฟล์เดียว อ่านผังทั้งเว็บได้ในสิบวินาที และปลดล็อกความสามารถระดับ router เช่น errorElement ที่เราจะใช้ในบทนี้

จำย่อหน้านี้ไว้ให้ดี เพราะเดี๋ยวมันจะกลายเป็นข้อแรกของ checklist: ความแตกต่างระหว่าง data mode กับ JSX mode ไม่ใช่เรื่องรสนิยม แต่คือสองวิธีเขียนที่หน้าเว็บออกมาเหมือนกันจนดูผ่าน ๆ แล้วแยกไม่ออก

หน้า stub: ให้โครงเดินได้ก่อน

Router ต้องรู้ว่าแต่ละ URL จะแสดง component ตัวไหน แต่หน้าจริง ๆ ของเรายังไม่มีสักหน้า เราจะใช้เทคนิคที่ทีมพัฒนาจริงใช้กันตลอด: สร้าง stub — component เปล่า ๆ ที่มีแค่ชื่อหน้า — เพื่อให้โครงของระบบ routing ทำงานครบวงจรได้ก่อน แล้วค่อยกลับมาเติมเนื้อแต่ละหน้าในบทของมันเอง วิธีนี้ทำให้เราทดสอบ router ได้ทันทีโดยไม่ต้องรอหน้าไหนเสร็จ

แต่ละหน้าจะได้โฟลเดอร์ของตัวเอง (src/pages/Home/Home.tsx ไม่ใช่ src/pages/Home.tsx) — เพราะอีกไม่นานแต่ละหน้าจะมีไฟล์ .module.scss, เทสต์ และ components ย่อยของตัวเองมาอยู่ข้าง ๆ ตามหลัก colocation ที่คุยกันในบทเรียน 05

errorElement และหน้าที่ของ RouteErrorFallback

ก่อนประกอบ router เราต้องเตรียมของอีกสองชิ้น ชิ้นแรกคือ component กลางสำหรับแสดงข้อความ error ซึ่งไม่ใช่ของเฉพาะระบบ routing — หน้า Home, Category และ Product ก็จะใช้มันเวลาโหลดข้อมูลไม่สำเร็จ (ตั้งแต่บทเรียน 19 เป็นต้นไป) มันจึงควรอยู่ใน src/shared/components/

ชิ้นที่สองคือหน้าที่จะแสดงเมื่อระบบ routing เองมีปัญหา เช่น ผู้ใช้พิมพ์ URL ที่ไม่มีอยู่จริง หรือ component ของหน้าไหนสักหน้า throw error ระหว่าง render ถ้าไม่มีตัวรับ ผู้ใช้จะเจอหน้าขาวเปล่าหรือหน้า error ดิบ ๆ ของ react-router ซึ่งทั้งสองแบบไม่ใช่สิ่งที่เว็บจริงควรปล่อยให้เกิด

หลักการทำงาน: เราผูก component ตัวนี้เข้ากับ router ผ่าน property ชื่อ errorElement เมื่อเกิด error ที่ route ไหนก็ตาม react-router จะ render component นี้แทนหน้าปกติ แล้วภายใน component เราเรียก hook useRouteError() เพื่อดึงตัว error ออกมาดู

แต่ error มีสองพันธุ์: ถ้าเป็น error ที่ router สร้างเอง (เช่น 404 จาก URL ที่ไม่ match route ไหนเลย) มันจะมีรูปร่างมาตรฐานที่มี status และ statusText — ฟังก์ชัน isRouteErrorResponse() เป็น type guard สำหรับเช็คกรณีนี้ พอเช็คผ่าน TypeScript ก็ยอมให้เราอ่าน error.status ได้อย่างปลอดภัย ส่วน error พันธุ์อื่น (โค้ดเรา throw เอง) เราไม่รู้รูปร่างของมัน จึงแสดงข้อความกลาง ๆ แทน — สังเกตว่าเราไม่เอา error ดิบไปแปะหน้าจอ เพราะข้อความ error ภายในอาจมีรายละเอียดที่ผู้ใช้ไม่ควรเห็น

MainLayout: โครงที่ทุกหน้าใช้ร่วมกัน

ทั้ง 6 หน้าของเราจะมีโครงเดียวกัน: Header อยู่บนสุด เนื้อหาของหน้าอยู่ตรงกลาง Footer อยู่ล่างสุด เราไม่เขียนโครงนี้ซ้ำในทุกหน้า แต่เขียนครั้งเดียวเป็น layout component แล้วให้ router เสียบหน้าปัจจุบันเข้ามาตรงกลางผ่าน <Outlet /> — แบบเดียวกับ root route ของ TanStack Router ที่คุณใช้ในคอร์ส React พื้นฐาน ไม่มีผิด

บทนี้เราจะได้ MainLayout เวอร์ชันแรก ที่มีแค่ <Outlet /> เท่านั้น ยังไม่มี Header, Footer และยังไม่มีไฟล์ .module.scss เพราะสองตัวแรกยังไม่ถูกสร้าง และ style ของ layout เป็นเรื่องเดียวกับการวาง Header/Footer — ทั้งชุดจะมาพร้อมกันในบทเรียน 10

เป้าหมายของบทนี้

จบบทนี้ src/ ต้องมีไฟล์ใหม่ 11 ไฟล์ตามนี้ (บวกการแก้ main.tsx และการลบ src/App.tsx เดิม):

src/
├── app/
│   ├── App.tsx                      # ห่อ router ให้ React render
│   ├── router.tsx                   # ผังเส้นทางทั้งแอป
│   ├── RouteErrorFallback.tsx       # แปลง error ของ router เป็นข้อความ
│   └── layouts/
│       └── MainLayout/
│           └── MainLayout.tsx       # เวอร์ชันแรก: มีแค่ Outlet
├── pages/
│   ├── Home/Home.tsx                # stub
│   ├── Category/Category.tsx        # stub
│   ├── Product/Product.tsx          # stub
│   ├── Cart/Cart.tsx                # stub
│   ├── Checkout/Checkout.tsx        # stub
│   └── Order/OrderSuccess.tsx       # stub
└── shared/
    └── components/
        └── ErrorMessage/ErrorMessage.tsx

สังเกตว่า App.tsx ย้ายบ้าน: ตามสถาปัตยกรรมที่วางไว้ในบทเรียน 05 ของที่เป็น "ระดับแอป" ทั้งหมด — ตัวแอป, router, layout, providers — ต้องอยู่ใน src/app/ แต่ตอนนี้ App.tsx ของเรายังนอนอยู่ที่ src/App.tsx จากตอน scaffold ในบทเรียน 02 prompt จึงสั่งทั้งสร้างตัวใหม่ที่ src/app/App.tsx และลบตัวเก่าทิ้ง

สัญญาที่แต่ละไฟล์ต้องทำให้ได้ — และสิ่งที่มันต้องไม่ทำ:

  • router.tsx — ต้อง export ทั้ง routes (array ดิบ) และ router (ตัวที่สร้างจาก createBrowserRouter) ต้องไม่มีแท็ก <Routes> หรือ <BrowserRouter> อยู่ในไฟล์
  • RouteErrorFallback.tsx — ต้องแยกสองกรณีของ error ด้วย isRouteErrorResponse() ต้องไม่ render markup ของหน้า error เอง (นั่นเป็นงานของ ErrorMessage)
  • MainLayout.tsx — ต้อง render <Outlet /> ในแท็ก main ต้องไม่มี Header, Footer หรือไฟล์ .module.scss คู่กัน
  • App.tsx — ต้องอยู่ที่ src/app/ และ import RouterProvider จาก react-router/dom ต้องไม่มี src/App.tsx เดิมเหลืออยู่
  • ErrorMessage.tsx — ต้องรับ prop message แบบไม่บังคับพร้อมค่า default และมี role="alert" ต้องไม่รู้จักอะไรที่เป็นเรื่องของ E-commerce เลย (นั่นคือเงื่อนไขที่ทำให้มันอยู่ shared/ ได้)
  • หกหน้าใน pages/ — ต้องเป็น export default ที่คืนแท็ก h1 ชื่อหน้าเท่านั้น ต้องไม่มี state, ไม่มีการเรียก API และไม่มี .module.scss

ติดตั้ง react-router ด้วยมือ

ตามกติกาจากบทเรียน 08: dependency เราติดตั้งเอง ไม่ปล่อยให้ Agent ทำ เพราะการเลือก package และเวอร์ชันเป็นการตัดสินใจ ไม่ใช่การพิมพ์

npm install react-router
git add -A && git commit -m "chore: install react-router"
🚨 สังเกตชื่อ package ให้ดี: react-router เฉย ๆ ไม่ใช่ react-router-dom — ตั้งแต่เวอร์ชัน 7 เป็นต้นมาทุกอย่างถูกรวมเข้า package เดียวแล้ว บทความและคำตอบเก่า ๆ ใน Stack Overflow จำนวนมากยังสอนให้ลง react-router-dom อยู่ ถ้าเผลอทำตามคุณจะได้ package ซ้ำซ้อนมาโดยไม่จำเป็น และอีกเรื่อง: react-router 8 กำหนด Node ขั้นต่ำไว้ที่ 22.22 ถ้าคำสั่งติดตั้งฟ้อง engine error ให้กลับไปเช็ค node -v แล้ว nvm use ตามที่ตั้งค่าไว้ในบทเรียน 02

เช็ค git status ให้สะอาดก่อนไปขั้นถัดไป — ขั้นที่หนึ่งของวงจรตรวจงานคือการอ่าน git diff ถ้า working tree ยังมีของค้างอยู่ diff ที่ได้จะปนกันจนอ่านไม่ออกว่าบรรทัดไหนเป็นฝีมือใคร

สร้างเราเตอร์ หน้าเปล่าทั้งหกหน้า และ component แสดงข้อความ error ของแอป

บริบท: @src/app @src/pages @src/shared/components @src/main.tsx
ติดตั้ง react-router 8 ไว้แล้ว
src/app/, src/pages/ และ src/shared/components/ ยังเป็นโฟลเดอร์ว่าง
ส่วน src/main.tsx render placeholder App จาก ./App และ import ./styles/main.scss อยู่
alias @/ ชี้ไปที่ src/ ตั้งค่าไว้แล้วทั้งใน vite.config.ts และ tsconfig.app.json

โครงสร้าง: สร้างไฟล์ตามนี้ ไม่มากไม่น้อยกว่านี้
- src/app/router.tsx
- src/app/RouteErrorFallback.tsx
- src/app/layouts/MainLayout/MainLayout.tsx
- src/app/App.tsx
- src/shared/components/ErrorMessage/ErrorMessage.tsx
- src/pages/Home/Home.tsx
- src/pages/Category/Category.tsx
- src/pages/Product/Product.tsx
- src/pages/Cart/Cart.tsx
- src/pages/Checkout/Checkout.tsx
- src/pages/Order/OrderSuccess.tsx
และแก้ src/main.tsx ให้ render App ตัวใหม่ จากนั้นลบ src/App.tsx เดิมทิ้ง (ย้ายมาเป็น src/app/App.tsx แล้ว)

ข้อกำหนดทางเทคนิค:
- router.tsx: export const routes: RouteObject[] และ export const router = createBrowserRouter(routes)
  โดย import createBrowserRouter กับ RouteObject จาก "react-router"
- routes มี route แม่หนึ่งตัว element เป็น MainLayout และ errorElement เป็น RouteErrorFallback
  ไม่ต้องใส่ path ให้ route แม่
- children ของ route แม่ เรียงตามลำดับนี้:
  "/"               -> Home
  "/categories"     -> Category
  "/products/:id"   -> Product
  "/cart"           -> Cart
  "/checkout"       -> Checkout
  "/order/success"  -> OrderSuccess
- MainLayout: default export ที่ render Outlet ของ react-router ไว้ในแท็ก main
- ErrorMessage: default export รับ prop message ที่เป็น string และไม่บังคับ
  ค่า default ของ message คือ "Something went wrong. Please try again."
  render div ที่มี role="alert" และ className="text-center pt-30 pb-30"
  ข้างในเป็นแท็ก p ที่มี className="fs-18 text-muted" แสดงค่า message
- RouteErrorFallback: default export ที่ใช้ useRouteError() กับ isRouteErrorResponse()
  ถ้าเป็น route error response ให้ message เป็น `${error.status} ${error.statusText}`
  ถ้าไม่ใช่ ให้ message เป็น "Something went wrong. Please reload the page."
  แล้ว render ErrorMessage พร้อม prop message ครอบด้วย div className="container pt-60 pb-60"
- หน้าทั้งหกเป็น stub: default export ที่ return แท็ก h1 ชื่อหน้าเท่านั้น ยังไม่ต้องมี state หรือข้อมูล
- App.tsx: default export ที่ return RouterProvider พร้อม prop router={router}
  โดย import RouterProvider จาก "react-router/dom"
- src/main.tsx: render App จาก "./app/App" และคงบรรทัด import "./styles/main.scss" ไว้
- import ไฟล์ที่อยู่คนละโฟลเดอร์ใช้ alias @/ ไฟล์ที่อยู่โฟลเดอร์เดียวกันใช้ ./ ได้

ขอบเขต:
- ห้ามติดตั้ง dependency ใหม่
- ยังไม่ต้องสร้าง Header, Footer, QueryClientProvider หรือไฟล์ .module.scss ใด ๆ
- ห้ามแก้ไฟล์อื่นนอกจากที่ระบุไว้ข้างบน

ถ้าจำที่มาของบรรทัดไหนไม่ได้ ย้อนกลับไปอ่านหัวข้อ "ที่มาของแต่ละบรรทัด" ในบทเรียน 08 ก่อนกดส่ง — บทนี้จะไม่อธิบายซ้ำ เพราะตั้งแต่บทหน้าเป็นต้นไปคุณจะต้องอ่าน prompt ออกเองว่าทำไมมันถึงมีหน้าตาแบบนั้น

  • AI มักพลาดตรงนี้: router.tsx ออกมาเป็นแบบ react-router v6 คือ <BrowserRouter> ครอบ <Routes> ครอบ <Route> ใน JSX แทนที่จะเป็น createBrowserRouter + RouterProvider ของ data mode — เพราะโค้ด v6 ในโลกยังมีมากกว่ามาก เปิด src/app/router.tsx เป็นไฟล์แรก ถ้าเจอแท็ก <Routes> หรือ <Route> แม้แต่ตัวเดียว นั่นคือ "รูปทรงผิด" ให้ git restore . ลบไฟล์ใหม่ทิ้ง แล้วสั่งใหม่ ไม่ใช่ไล่แก้ทีละบรรทัด — สังเกตว่าทั้งสองแบบทำให้หน้าเว็บขึ้นเหมือนกันเป๊ะ และ lint กับ typecheck ผ่านทั้งคู่ นี่จึงเป็นข้อที่ต้องดูด้วยตา ไม่มีเครื่องมือตัวไหนบอกให้
  • git status มีไฟล์ใหม่ 11 ไฟล์พอดี ไม่มี index.ts, types.ts หรือไฟล์ barrel แถมมา
  • src/App.tsx เดิมขึ้นสถานะ deleted และมี src/app/App.tsx ขึ้นมาแทน — ไม่ใช่มีทั้งสองไฟล์
  • src/main.tsx ยังมีบรรทัด import "./styles/main.scss"; อยู่ครบ และ import App จาก "./app/App"
  • router.tsx export ชื่อ routes และ router ตรงตัว ไม่ใช่ appRouter หรือ AppRoutes
  • route ตัวนอกสุดไม่มี path และมี errorElement อยู่ที่ตัวนอกสุดตัวนี้ ไม่ใช่กระจายอยู่ในลูกแต่ละตัว
  • path ทั้งหกเส้นสะกดตรงกับ prompt โดยเฉพาะ "/products/:id" — ถ้าเป็น :productId ให้แก้เดี๋ยวนี้ ไม่งั้นบทเรียน 21 พังตาม
  • App.tsx import RouterProvider จาก "react-router/dom" ไม่ใช่ "react-router"
  • ไม่มีไฟล์ .module.scss โผล่มาสักไฟล์ (กติกาในไฟล์ rules บอกให้สร้าง แต่ prompt ยกเว้นไว้)
  • import ข้ามโฟลเดอร์ใช้ @/ ทุกจุด ไม่มี ../../ โผล่มาแม้แต่บรรทัดเดียว
  • ErrorMessage มี role="alert" และใช้ class text-center pt-30 pb-30 กับ fs-18 text-muted ตรงตัว — ถ้าเจอ py-8 หรือ text-gray-500 แปลว่ามันเดาว่าเรามี Tailwind
  • RouteErrorFallback ใช้ isRouteErrorResponse() จริง ไม่ใช่ error instanceof Error หรือ cast ด้วย as
  • หน้าทั้งหกเป็น stub จริง — ไม่มี useState, useEffect หรือ markup อื่นนอกจาก h1

lint ตกรอบแรกเป็นเรื่องปกติ

ขั้นที่สามของวงจรคือ npm run lint และ npm run typecheck รอบแรกมีโอกาสสูงที่ lint จะฟ้อง import-x/order หลายจุด — กฎนี้ตั้งเป็น error ไว้ตั้งแต่บทเรียน 03 และมันบังคับลำดับของบรรทัด import (ของจาก package มาก่อน ของในโปรเจกต์มาทีหลัง) ซึ่งเป็นสิ่งที่โมเดลไม่ค่อยเรียงให้ตรงตั้งแต่รอบแรก

npx eslint . --fix
npm run lint
npm run typecheck

นี่ไม่ใช่สัญญาณว่าโค้ดผิด และไม่ต้องกลับไปสั่ง Agent ให้แก้ — --fix จัดลำดับ import ให้เองโดยไม่แตะตรรกะสักบรรทัด สิ่งที่ต้องระวังคือหลัง fix แล้วต้องรัน npm run lint ซ้ำให้ผ่านเงียบ ๆ จริง ๆ ถ้ายังเหลือ error อยู่ นั่นคือของจริงที่ต้องอ่าน ไม่ใช่เรื่องลำดับบรรทัด

โค้ดอ้างอิง

ของที่ควรได้กลับมามีหน้าตาแบบนี้ รายละเอียดปลีกย่อยอาจต่างได้ (เช่นเขียนเป็น function หรือ arrow function, มี React.FC หรือไม่มี) แต่ทุกข้อใน checklist ต้องเป็นจริง

หกหน้า stub — ทั้งหมดหน้าตาเดียวกัน ต่างแค่ชื่อ เช่น src/pages/Home/Home.tsx (หน้านี้จะกลายเป็นหน้าจริงในบทเรียน 19):

export default function Home() {
  return <h1>Home</h1>;
}

อีกห้าไฟล์คือ Category (หน้าจริงบทเรียน 20), Product (บทเรียน 21), Cart (บทเรียน 24), Checkout (บทเรียน 28) และ OrderSuccess (บทเรียน 28 เช่นกัน)

src/shared/components/ErrorMessage/ErrorMessage.tsx:

import React from "react";

interface ErrorMessageProps {
  message?: string;
}

const ErrorMessage: React.FC<ErrorMessageProps> = ({
  message = "Something went wrong. Please try again.",
}) => {
  return (
    <div role="alert" className="text-center pt-30 pb-30">
      <p className="fs-18 text-muted">{message}</p>
    </div>
  );
};

export default ErrorMessage;

สามจุดที่น่าสนใจในไฟล์สั้น ๆ นี้:

  • message? เป็น optional prop พร้อม default value — ที่ไหนอยากใช้ข้อความมาตรฐานก็เขียนแค่ <ErrorMessage /> ได้เลย ที่ไหนมีข้อความเฉพาะก็ส่งมา
  • role="alert" บอก screen reader ว่านี่คือข้อความสำคัญที่ควรอ่านให้ผู้ใช้ฟังทันทีที่ปรากฏ — accessibility ไม่ใช่ของแถม แต่เป็นส่วนหนึ่งของการ "ทำให้ถูกวิธี"
  • class ทั้งหมด (text-center, pt-30, fs-18, text-muted) คือ utility classes ที่เราเขียนไว้เองในบทเรียน 04 — component เล็กแบบนี้ไม่จำเป็นต้องมี .module.scss ของตัวเอง

src/app/RouteErrorFallback.tsx:

import { isRouteErrorResponse, useRouteError } from "react-router";
import ErrorMessage from "@/shared/components/ErrorMessage/ErrorMessage";

export default function RouteErrorFallback() {
  const error = useRouteError();
  const message = isRouteErrorResponse(error)
    ? `${error.status} ${error.statusText}`
    : "Something went wrong. Please reload the page.";

  return (
    <div className="container pt-60 pb-60">
      <ErrorMessage message={message} />
    </div>
  );
}

สังเกตการแบ่งงานของสองไฟล์นี้: RouteErrorFallback รับผิดชอบแค่แปลง error ให้เป็นข้อความ ส่วนหน้าตาเป็นงานของ ErrorMessage — นั่นคือเหตุผลที่ตัวหลังถูกยกไปใช้ซ้ำในหน้าอื่นได้ทีหลัง

src/app/layouts/MainLayout/MainLayout.tsx เวอร์ชันแรก:

import { Outlet } from "react-router";

const MainLayout = () => {
  return (
    <main>
      <Outlet />
    </main>
  );
};

export default MainLayout;
💡 นี่คือ MainLayout เวอร์ชันแรก — ยังไม่มี Header กับ Footer เพราะเรายังไม่ได้สร้างมัน บทเรียน 10 เราจะสร้างทั้งสองตัว แล้วกลับมาเติมในไฟล์นี้พร้อมกับ MainLayout.module.scss ที่ทำให้ Footer ติดขอบล่างจอเสมอ ตอนนี้ขอแค่โครง <Outlet /> ทำงานได้ก่อน

src/app/router.tsx — ไฟล์นี้คือแผนที่ทั้งเว็บของเรา:

import { createBrowserRouter, RouteObject } from "react-router";
import RouteErrorFallback from "./RouteErrorFallback";
import MainLayout from "@/app/layouts/MainLayout/MainLayout";
import Home from "@/pages/Home/Home";
import Category from "@/pages/Category/Category";
import Product from "@/pages/Product/Product";
import Cart from "@/pages/Cart/Cart";
import Checkout from "@/pages/Checkout/Checkout";
import OrderSuccess from "@/pages/Order/OrderSuccess";

export const routes: RouteObject[] = [
  {
    element: <MainLayout />,
    errorElement: <RouteErrorFallback />,
    children: [
      { path: "/", element: <Home /> },
      { path: "/categories", element: <Category /> },
      { path: "/products/:id", element: <Product /> },
      { path: "/cart", element: <Cart /> },
      { path: "/checkout", element: <Checkout /> },
      { path: "/order/success", element: <OrderSuccess /> },
    ],
  },
];

export const router = createBrowserRouter(routes);

ไล่ดูทีละส่วน:

  • RouteObject[] — เราประกาศ type ให้ array ชัด ๆ เพื่อให้ TypeScript ตรวจทุก route ให้: สะกด property ผิด ใส่ element เป็นอย่างอื่นที่ไม่ใช่ JSX หรือลืม path ก็โดนเส้นแดงทันที
  • Layout route — route ตัวนอกสุดมี element เป็น <MainLayout /> แต่ไม่มี path แปลว่ามันไม่จับคู่กับ URL ไหนเป็นพิเศษ แต่ครอบทุก route ที่อยู่ใน children — ทุกหน้าจะถูก render แทนที่ <Outlet /> ข้างใน MainLayout เสมอ
  • errorElement — วางไว้ที่ route นอกสุด error จากทุกหน้าจึงลอยขึ้นมาถึงตัวนี้ รวมถึงกรณี URL ไม่ match route ไหนเลย (ได้ 404) ด้วย
  • /products/:id — :id คือ dynamic segment: /products/1, /products/42 หรือ /products/อะไรก็ตาม จะเข้า route นี้ทั้งหมด โดยค่าที่อยู่ตรงตำแหน่งนั้นจะถูกเก็บเป็น param ชื่อ id ซึ่งหน้า Product จะอ่านผ่าน hook useParams() ในบทเรียน 21 (ฝั่ง TanStack Router คุณเคยเขียนสิ่งเดียวกันนี้ว่า $id)
  • ทำไม export routes แยกจาก router — ตัวแอปจริงใช้ router ที่สร้างจาก createBrowserRouter (ผูกกับ History API ของเบราว์เซอร์) แต่ตอนวางชุดทดสอบในบทเรียน 30 เราจะเอา array routes ตัวเดียวกันนี้ไปสร้าง router แบบ in-memory ด้วย createMemoryRouter แทน — ประกาศผังเว็บครั้งเดียว ใช้ได้ทั้งแอปจริงและเทสต์

src/app/App.tsx เวอร์ชันแรก:

import { RouterProvider } from "react-router/dom";
import { router } from "./router";

function App() {
  return <RouterProvider router={router} />;
}

export default App;

จุดที่มักสะดุด: RouterProvider ถูก import จาก react-router/dom ไม่ใช่ react-router ตรง ๆ — subpath /dom คือ entry สำหรับแอปที่รันบนเบราว์เซอร์ (ตัวมันใช้ความสามารถของ react-dom ในการอัปเดตหน้าจอให้ทันจังหวะ) ส่วน package หลัก react-router เก็บของที่ใช้ได้ทุกสภาพแวดล้อมอย่าง createBrowserRouter, Outlet และ hooks ต่าง ๆ ถ้า Agent เขียนผิดจุดนี้ TypeScript จะฟ้องให้เห็นตั้งแต่ npm run typecheck

และ src/main.tsx ที่ถูกแก้ ทั้งไฟล์ต้องเหลือแค่นี้:

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import "./styles/main.scss";
import App from "./app/App";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);

ไฟล์นี้จะนิ่งอยู่แบบนี้ไปอีกนาน — จะมีของมาเพิ่มอีกครั้งเดียวคือบรรทัด import CSS ของ react-loading-skeleton ในบทเรียน 18 ถ้าตอนนี้บรรทัด import "./styles/main.scss"; หายไป แปลว่า Agent เขียนไฟล์นี้ใหม่ทั้งไฟล์แทนที่จะแก้เฉพาะจุด เติมกลับเข้าไปเองได้เลย ไม่ต้องสั่งใหม่

✍️ ส่วนนี้พิมพ์เอง

prompt ข้างบนสร้าง router.tsx มาให้ด้วย และเราจงใจไม่ตัดมันออกจาก prompt — คำสั่งที่บอกว่า "สร้างทุกไฟล์ยกเว้นไฟล์นี้" จะได้ App.tsx ที่ import ./router ที่ยังไม่มีอยู่จริง typecheck ไม่ผ่าน และตรวจอะไรไม่ได้เลย เราจึงให้มันสร้างครบ แล้วค่อยเอาส่วนที่สำคัญที่สุดของไฟล์กลับมาเป็นของเราเอง

✍️ ส่วนนี้พิมพ์เอง — เมื่อวงจรตรวจงานถึงขั้นที่สามและ npm run lint กับ npm run typecheck ผ่านแล้ว ให้ทำตามนี้ตามลำดับ:

  1. เปิด src/app/router.tsx
  2. ลบ array routes ทั้งก้อนทิ้ง — ตั้งแต่บรรทัด export const routes ลงไปจนถึง ]; เก็บบรรทัด import ทั้งเก้าบรรทัดข้างบนและบรรทัด export const router ข้างล่างไว้
  3. พิมพ์ array กลับเข้าไปเองทั้งก้อน ห้าม undo ห้ามก๊อป ห้ามเลื่อนขึ้นไปดูของเดิม (ถ้านึกไม่ออกจริง ๆ ให้เปิดดูได้ แต่ต้องกลับมาพิมพ์เองอยู่ดี)
  4. npm run typecheck แล้วเดินขั้นที่สี่ของวงจร — ไล่ URL ทั้งหกเส้นตาม checkpoint ท้ายบท

เหตุผล: แผนที่ของแอปทั้งใบ ต้องอยู่ในหัวคุณ — สิบสี่บรรทัดนี้บอกว่าเว็บนี้มีกี่หน้า หน้าไหนอยู่ URL อะไร อะไรครอบอะไร และ error ตกที่ไหน ทุกบทหลังจากนี้จะอ้างถึงมันตลอด และตอนที่ AI สร้าง route ผิดที่ในบทหลัง ๆ สิ่งเดียวที่ทำให้คุณจับได้คือคุณรู้ว่าผังที่ถูกต้องหน้าตาอย่างไรโดยไม่ต้องเปิดไฟล์ดู

ถ้าพิมพ์แล้วผลลัพธ์ออกมาเหมือนของ Agent ทุกตัวอักษร นั่นคือผลที่ควรได้ ประเด็นไม่ได้อยู่ที่ diff แต่อยู่ที่ผังชุดนี้ผ่านมือคุณไปแล้วหนึ่งรอบ

🤔 อธิบายให้ได้

  1. route ตัวนอกสุดใน routes ไม่มี path — แล้วมันจับคู่กับ URL ไหน และถ้าเราใส่ path: "/" ให้มัน จะเกิดอะไรขึ้นกับลูกที่ path เป็น "/cart"
  2. createBrowserRouter import จาก "react-router" แต่ RouterProvider import จาก "react-router/dom" — เปิดสองไฟล์นั้นแล้วตอบว่าเกณฑ์อะไรทำให้ของชิ้นหนึ่งอยู่ subpath /dom และอีกชิ้นอยู่ที่ package หลัก
  3. ไล่เส้นทางของค่า message ใน RouteErrorFallback ทั้งสองกรณี: ตอนผู้ใช้พิมพ์ /banana ค่ามาจากบรรทัดไหน และตอนหน้า Product throw error เองระหว่าง render ค่ามาจากบรรทัดไหน
💡 Checkpoint: รัน npm run dev แล้วเปิดเบราว์เซอร์ ลองเข้าทีละ URL: / ต้องเห็นคำว่า Home, /categories เห็น Category, /products/1 เห็น Product, /cart เห็น Cart, /checkout เห็น Checkout และ /order/success เห็น Order Success — ครบทั้งหกแปลว่า router ต่อติดทุกเส้น จากนั้นลองพิมพ์ URL มั่ว ๆ เช่น /banana ต้องเห็นข้อความ 404 Not Found จาก RouteErrorFallback ไม่ใช่หน้าขาวเปล่า ปิดท้ายด้วย npm run lint และ npm run typecheck ให้ผ่านทั้งคู่แล้ว commit ถ้าจุดไหนไม่ตรงตามนี้ อย่าเพิ่งไปต่อ — เช็คว่า path ใน router.tsx สะกดตรงกับที่พิมพ์ และทุกหน้า stub ถูก export default ครบ — ถ้าข้อ "อธิบายให้ได้" ยังตอบไม่ได้ อย่าเพิ่งไปบทถัดไป
