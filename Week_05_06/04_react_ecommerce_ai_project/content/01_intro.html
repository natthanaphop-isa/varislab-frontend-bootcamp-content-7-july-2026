บทเรียน 01 · เริ่มต้น (Welcome)

บทนำ: โปรเจกต์ E-commerce ที่เราจะสร้างกัน

Intro

ยินดีต้อนรับสู่โปรเจกต์ใหญ่ของคอร์สนี้! ในคอร์ส React พื้นฐาน คุณได้เรียนพื้นฐาน React ครบทุกเรื่องแล้ว ไม่ว่าจะเป็น components, hooks, effects, context, การเรียก API, การทำ routing, TanStack Query ไปจนถึงการเขียนเทสต์ — แต่การเรียนแนวคิดทีละเรื่องกับการประกอบทุกอย่างเข้าด้วยกันเป็นแอปจริงคือคนละทักษะกัน และทักษะอย่างหลังนี่แหละที่บริษัทจ้างคุณไปทำ

ตลอด 34 บทเรียนต่อจากนี้ เราจะสร้างเว็บ E-commerce ที่ทำงานได้จริงทั้งเว็บ ตั้งแต่คำสั่ง npm create vite บรรทัดแรก ไปจนถึงแอปที่มีเทสต์ครอบคลุมและพร้อม deploy โดยไม่ใช่แค่ "ทำให้มันทำงานได้" แต่ทำให้ถูกวิธีแบบเดียวกับโปรเจกต์มืออาชีพ: โครงสร้างโฟลเดอร์แบบ feature-based, ชั้นข้อมูลที่เป็นระบบ, การจัดการ error ที่ครบถ้วน และชุดเทสต์ที่ทำให้เรากล้าแก้โค้ดโดยไม่กลัวของพัง

ที่ต่างจากคอร์สทั่วไปคือ โค้ดส่วนใหญ่คุณจะไม่ได้พิมพ์เอง — Cursor เป็นคนพิมพ์ คุณเป็นคนตัดสินใจว่าจะสร้างอะไร สั่งงานให้ชัด แล้วตรวจของที่ได้กลับมา การสั่งงานให้ชัดและการตรวจงานให้ออกเป็นทักษะคนละตัวกับการพิมพ์โค้ดได้เร็ว และเป็นสองอย่างที่เราจะฝึกกันอย่างจริงจังตลอดคอร์ส

เว็บที่เราจะสร้าง

แอปของเราคือหน้าร้านออนไลน์ (storefront) ที่ดึงข้อมูลสินค้าจริงจาก dummyjson.com ซึ่งเป็น API ฟรีสำหรับฝึกซ้อมที่มีข้อมูลสินค้า รูปภาพ รีวิว และหมวดหมู่ให้ครบ ผู้ใช้ของเราจะทำสิ่งเหล่านี้ได้:

  • หน้า Home — แบนเนอร์แบบ carousel, สินค้าขายดี, ดีลพิเศษพร้อมตัวนับเวลาถอยหลัง และแถบหมวดหมู่สินค้า
  • หน้า Category — เลือกดูสินค้าตามหมวดหมู่ พร้อมระบบแบ่งหน้า (pagination) ที่เปลี่ยนหน้าได้ลื่นไหลไม่กะพริบ
  • หน้า Product — แกลเลอรีรูปสินค้า ข้อมูลราคาและส่วนลด คะแนนรีวิวแบบละเอียด และปุ่ม Add to Cart
  • ตะกร้าสินค้า — เพิ่ม ลบ ปรับจำนวนสินค้า โดยตะกร้าจำของไว้ได้แม้ปิดเบราว์เซอร์ไปแล้ว (localStorage)
  • หน้า Checkout — ฟอร์มที่อยู่จัดส่งที่ validate ด้วย zod, ตัวเลือกวิธีจัดส่งและการชำระเงิน และสรุปยอดคำสั่งซื้อ
  • หน้า Order Success — ยืนยันคำสั่งซื้อสำเร็จ พร้อมล้างตะกร้าให้อัตโนมัติ

โค้ดฉบับสมบูรณ์ของโปรเจกต์นี้อยู่ที่ github.com/manjarb/varis-lab-project-06-react-ecommerce-app — เปิดเก็บไว้ใน tab หนึ่งได้เลย ในคอร์สนี้มันมีหน้าที่ชัดเจนอย่างหนึ่ง คือเป็นของจริงที่เอาไว้เทียบกับสิ่งที่ Cursor สร้างให้ ตอนที่คุณตรวจงาน และเวลาติดขัดก็เปิดดูได้เสมอ แต่อย่าเปิดมันก่อนเขียน prompt — ถ้าคุณ copy ไฟล์ต้นฉบับมาวางตั้งแต่แรก คุณจะข้ามสองอย่างที่คอร์สนี้ตั้งใจฝึก คือการสั่งงานให้ชัดพอจนได้ของที่ถูก และการมองออกว่าของที่ได้มันผิดตรงไหน

เครื่องมือที่เราจะใช้

ทุกตัวคือของที่คุณเจอมาแล้วในคอร์ส React พื้นฐาน หรือเป็นญาติใกล้ชิดของมัน:

  • React 19 + TypeScript บน Vite 8 — ฐานเดิมที่คุณคุ้นเคย
  • react-router 8 (data mode) — ในคอร์ส React พื้นฐาน เราใช้ TanStack Router คราวนี้เราจะใช้ react-router ซึ่งเป็น router ที่เจอบ่อยที่สุดในโปรเจกต์จริง แนวคิดเดิมทั้งหมด (routes, layout, Outlet, dynamic params) แค่หน้าตา API ต่างกันนิดหน่อย — การใช้เครื่องมือคล้ายกันสองตัวได้ คือสัญญาณว่าคุณเข้าใจแนวคิด ไม่ใช่แค่จำ API
  • TanStack Query 5 — จัดการ server state ทั้งหมด คราวนี้เราจะใช้ท่าขั้นกว่า: query key factory และ queryOptions
  • axios — HTTP client ที่มาแทน fetch ตรง ๆ พร้อม interceptor ที่แปลง error ให้อยู่ในรูปแบบเดียวกันทั้งแอป
  • Context + useReducer — จัดการ state ของตะกร้าสินค้า (client state) แยกจาก server state อย่างชัดเจน
  • react-hook-form + zod — ฟอร์ม checkout ที่ validate จริงจัง ต่อยอดจากบท Uncontrolled Forms ของคอร์ส React พื้นฐาน
  • SCSS Modules — เขียน style แบบ scoped ต่อ component ไม่มี class ชนกันข้ามไฟล์
  • Vitest + React Testing Library + MSW — ชุดเทสต์เดิมจากคอร์ส React พื้นฐาน เพิ่ม MSW (Mock Service Worker) สำหรับจำลอง API ในเทสต์
  • Cursor — editor ที่มี AI อยู่ข้างใน คนที่พิมพ์โค้ดส่วนใหญ่ให้เรา เราจะติดตั้งและตั้งค่ากันในบทเรียน 06

"ถูกวิธี" หมายความว่าอย่างไร

แอปเดียวกันนี้เขียนแบบลวก ๆ ให้เสร็จใน 3 วันก็ได้ แต่เราจะค่อย ๆ สร้างทีละขั้นเพื่อฝึกนิสัยที่ทีมพัฒนาจริงคาดหวัง:

  • โครงสร้างแบบ feature-based — โค้ดแบ่งตามฟีเจอร์ (products, cart, checkout) ไม่ใช่ตามชนิดไฟล์ ใครเปิดโปรเจกต์มาก็หาของเจอใน 10 วินาที
  • ติดตั้งเครื่องมือคุณภาพตั้งแต่วันแรก — ESLint, Prettier และ TypeScript แบบ strict ทำงานให้เราตั้งแต่ commit แรก ไม่ใช่มาไล่แก้ทีหลัง
  • ข้อมูลแบบ declarative — ไม่มีการยิง API ใน useEffect แล้วเก็บใส่ useState เอง ทุก query ประกาศผ่าน TanStack Query ให้ cache ทำงานเต็มที่
  • จัดการ error ทุกจุด — โหลดไม่สำเร็จต้องมีข้อความบอก ไม่ใช่หน้าเปล่าค้างตลอดกาล
  • เทสต์ที่พิสูจน์พฤติกรรมจริง — ตั้งแต่ unit test ของ reducer ไปจนถึง integration test ของหน้า Checkout ทั้งหน้า

ทั้งห้าข้อนี้ยิ่งสำคัญขึ้นเมื่อมี AI พิมพ์โค้ดให้ เพราะมันคือมาตรฐานที่คุณใช้ตัดสินว่าโค้ดที่ได้กลับมา "ใช้ได้" หรือ "แค่รันผ่าน" — ถ้าคุณไม่มีมาตรฐานในหัว การตรวจงาน AI จะเหลือแค่การกด Accept

เราจะทำงานกับ AI อย่างไรในคอร์สนี้

คอร์สนี้ไม่ได้สอน "วิธีให้ AI เขียนแอปให้" แต่สอนลำดับการทำงานแบบเข้าใจก่อน แล้วค่อยมอบงาน ทุกบทที่เราสร้างโค้ดด้วย Cursor (บทเรียน 09–28 และ 30–33) จึงเดินตามจังหวะเดียวกันสี่ก้าว: อ่านแนวคิดของบทนั้นให้เข้าใจ → เขียน prompt ที่ละเอียดพอจะสั่งงานได้จริง → ให้ Cursor สร้างโค้ด → ตรวจของที่ได้ทีละข้อกับ checklist ที่บทนั้นให้ไว้ ส่วนอธิบายแนวคิดไม่ได้ถูกตัดทิ้งเพราะมี AI แล้ว มันยาวเท่าเดิม เพราะมันคือส่วนที่ทำให้ก้าวที่สองกับก้าวที่สี่เป็นไปได้

🚨 กติกาข้อเดียวของคอร์สนี้ — AI พิมพ์แทนคุณได้ แต่คุณต้องอธิบายทุกบรรทัดได้ ถ้าอธิบายไม่ได้ แปลว่ายังไม่ผ่านบทนั้น ไม่ใช่เพราะเราอยากเข้มงวด แต่เพราะวันที่โค้ดพัง คนที่ต้องแก้คือคุณ ไม่ใช่ AI

เพื่อให้รู้ตลอดเวลาว่าตอนนี้ใครทำอะไร บทเหล่านั้นใช้สัญลักษณ์สี่ตัวนี้เหมือนกันหมด — ส่วนบทเรียน 29, 34 และ 35 เป็นบทคนละแบบ (ไม่ได้สร้างฟีเจอร์ใหม่) จึงมีโครงของตัวเองต่างออกไป:

  • 🤖 Prompt ที่ส่งให้ Cursor — หัวข้อกลางบท มี prompt เต็ม ๆ ให้ใช้จริง ทุก prompt ประกอบด้วยสี่ส่วน: บริบท: (ไฟล์ที่มีอยู่แล้วและกติกาของโปรเจกต์) โครงสร้าง: (ไฟล์ที่ต้องสร้าง ชื่ออะไร อยู่ที่ไหน) ข้อกำหนดทางเทคนิค: (ต้องทำอะไรได้บ้าง) และ ขอบเขต: (ห้ามทำอะไร) อ่านให้ออกว่าทำไมแต่ละบรรทัดต้องอยู่ในนั้น เพราะเวลาคุณสั่งงานเองในโปรเจกต์จริง คุณจะไม่มี prompt สำเร็จรูปให้ก๊อป
  • ✅ ตรวจโค้ดที่ AI สร้าง — มาต่อจาก prompt ทันที เป็น checklist ที่ทุกข้อเป็นข้อเท็จจริงที่ตรวจได้ในโค้ดตรงหน้า ไม่ใช่ความรู้สึก (เช่น "reducer ไม่มี push หรือ += แม้แต่ที่เดียว") ทุกบทในกลุ่มนี้จะมีบรรทัด AI มักพลาดตรงนี้: ที่บอกจุดพลาดจริงของโค้ดชุดนั้น ให้ไล่ดูจุดนั้นก่อนเสมอ
  • ✍️ ส่วนนี้พิมพ์เอง — กล่องที่บอกว่าโค้ดชุดนี้ห้ามให้ AI เขียน มี 10 จุดตลอดคอร์ส และเลือกมาแล้วว่าเป็นจุดที่ "รู้จำ ๆ" ไม่พอ เช่น cartReducer, query key factory ของสินค้า, zod schema ของ checkout, เทสต์ unit ตัวแรกและ integration test ตัวแรก ทุกกล่องจะบอกเหตุผลไว้หนึ่งบรรทัดว่าทำไมจุดนั้นต้องผ่านมือคุณ
  • 🤔 อธิบายให้ได้ — คำถาม 2–3 ข้อท้ายบท ตอบได้จากโค้ดที่เพิ่งได้มาเท่านั้น และเราไม่มีเฉลยให้ ถามคำอธิบายจาก Cursor ได้ แต่ต้องกลับไปยืนยันกับโค้ดจริงว่ามันพูดตรงกัน — คำอธิบายที่ฟังดูดีแต่ไม่ตรงกับไฟล์ที่คุณมี เป็นสิ่งที่เจอบ่อยกว่าที่คิด

พูดกันตรง ๆ ว่า AI ช่วยอะไรได้จริงในโปรเจกต์นี้ มันเร็วและค่อนข้างแม่นกับงานที่มีแบบแผนวางไว้แล้ว — component หนึ่งตัวพร้อม SCSS module ที่หน้าตาเหมือนอีกสิบตัวที่มีอยู่, ฟิลด์ฟอร์มสามช่องที่โครงเหมือนกันทุกช่อง, เทสต์ตัวที่สี่ที่โครงเหมือนสามตัวแรก งานพวกนี้คุณสั่งได้ในสามบรรทัดและตรวจจบได้ในสามสิบวินาที นั่นคือจุดที่มันคุ้มที่สุด

ส่วนที่มันไม่น่าไว้ใจคือการตัดสินใจ — รูปแบบของ cache key ควรเป็นอย่างไร, อะไรควรอยู่ใน shared/ อะไรควรอยู่ในฟีเจอร์ของมันเอง, เทสต์ตัวนี้ควรพิสูจน์อะไรกันแน่ คำตอบของเรื่องพวกนี้ขึ้นกับบริบทของโปรเจกต์และสิ่งที่จะเกิดขึ้นในอีกสามเดือน ซึ่งเป็นข้อมูลที่ AI ไม่มี มันจะตอบทันทีและตอบด้วยน้ำเสียงมั่นใจเท่ากันทุกครั้ง ซึ่งเป็นคนละเรื่องกับตอบถูก การตัดสินใจพวกนี้เป็นงานของคุณตลอดคอร์ส และบทเรียน 29 จะพาไปดูของจริงว่าเวลา AI ตอบผิดแบบมั่นใจ หน้าตามันเป็นอย่างไรและจับได้อย่างไร

อีกอย่างที่ควรรู้ไว้ตั้งแต่ตอนนี้: AI จะมีประโยชน์ก็ต่อเมื่อมีของให้มันอ้างอิง เราจึงยังไม่แตะ Cursor ในช่วงติดตั้งโปรเจกต์ (บทเรียน 02–05) โครงโปรเจกต์ ค่า config ผัง SCSS และโครงสร้างโฟลเดอร์ คุณพิมพ์เองทั้งหมด เพราะของพวกนั้นคือบริบทที่คุณจะใช้สั่งงาน Cursor ตั้งแต่บทเรียน 06 เป็นต้นไป

สิ่งที่ต้องมีก่อนเริ่ม

  • เนื้อหาคอร์ส React พื้นฐาน ทั้งหมด — ถ้าเรื่องไหนลืมไปแล้ว (โดยเฉพาะ hooks, context และ TanStack Query) เปิดกลับไปทวนได้ตลอด เราจะอ้างถึงบ่อย
  • Node.js เวอร์ชัน 22.22 ขึ้นไป — react-router 8 กำหนดขั้นต่ำไว้เท่านี้ เดี๋ยวบทถัดไปเราจะตั้งค่ากันด้วย nvm
  • เครื่องมือเดิม: VS Code (หรือ editor ที่ถนัด), Terminal และ Git
  • Cursor — ติดตั้งในบทเรียน 06 ยังไม่ต้องโหลดตอนนี้ บทเรียน 02–05 เราพิมพ์เองใน editor ที่คุณใช้อยู่ก็พอ
  • ไม่ต้องผ่าน workshop Tailwind + Cursor มาก่อน — คอร์สนี้ไม่ได้ถือว่าคุณเคยเรียนมัน เรื่อง Cursor ทุกอย่างที่ต้องใช้ อธิบายใหม่ครบตั้งแต่ต้นในบทเรียน 06–08 และโปรเจกต์นี้ใช้ SCSS Modules ไม่ใช่ Tailwind ถ้าเคยผ่าน workshop มาก็ถือว่าได้เปรียบเรื่องการเขียน prompt เท่านั้น

  3. ตั้งวงกับ Cursor (Setting Up Cursor) — บทเรียน 06–08: ติดตั้ง Cursor, เขียน .cursor/rules ของโปรเจกต์ และฝึกวงจร prompt → review ให้คล่องก่อนลงสนามจริง
  4. โครงแอปและเราเตอร์ (App Shell & Routing) — บทเรียน 09–11: react-router 8, Header/Footer และ providers พร้อม QueryClient
  5. คอมโพเนนต์กลาง (Shared UI) — บทเรียน 12–14: Button, Input, Modal, Pagination และคอมโพเนนต์แสดงผลที่ทุกหน้าจะหยิบไปใช้
  6. ชั้นข้อมูลสินค้า (Products Data Layer) — บทเรียน 15–17: axios client, types และ query factories
  7. สร้างหน้าเพจ (Pages) — บทเรียน 18–21: Home, Category และ Product detail
  8. ตะกร้าสินค้า (Cart) — บทเรียน 22–24: reducer, localStorage, mini cart และหน้า Cart
  9. ชำระเงิน (Checkout) — บทเรียน 25–28: zod schema, ฟอร์มที่อยู่, สรุปรายการ และการสั่งซื้อ
  10. เมื่อ AI เขียนผิด (When AI Gets It Wrong) — บทเรียน 29: ดูของจริงว่าโค้ดที่ "รันผ่านแต่ผิด" หน้าตาเป็นอย่างไร และจับมันได้ด้วยอะไร
  11. การทดสอบ (Testing) — บทเรียน 30–33: ติดตั้งชุดเทสต์และเขียนเทสต์ครบทุกชั้น ตั้งแต่ unit ถึง integration
  12. ส่งท้าย (Wrap Up) — บทเรียน 34–35: ใช้ AI ตรวจงานตัวเอง, build, deploy และก้าวต่อไป
💡 ทุกบทจะจบด้วยจุดตรวจสอบ (checkpoint) ว่าแอปควรอยู่ในสภาพไหน ถ้ารันแล้วไม่เหมือนที่บอก อย่าเพิ่งข้ามไปบทถัดไป — bug ที่ถูกทิ้งไว้จะโตขึ้นเรื่อย ๆ และตามแก้ยากขึ้นทุกบทที่ผ่านไป และถ้าข้อ "อธิบายให้ได้" ยังตอบไม่ได้ ก็นับว่ายังไม่ผ่านเหมือนกัน
