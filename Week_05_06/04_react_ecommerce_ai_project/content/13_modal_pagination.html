Modal และ Pagination

Modal & Pagination

บทที่แล้วเราสร้างคอมโพเนนต์จากศูนย์ทั้งหมด บทนี้เปลี่ยนโจทย์: เราจะสร้างคอมโพเนนต์ที่ห่อ (wrap) ไลบรารีภายนอกอีกชั้น — Modal ที่ห่อ react-modal และ Pagination ที่ห่อ react-paginate ทั้งสองตัวมีนัดใช้งานชัดเจน: Modal จะเด้งยืนยันตอนกด Add to Cart ในบทเรียน 23 ส่วน Pagination จะพาผู้ใช้ไล่ดูสินค้าทีละหน้าใน Category บทเรียน 20

ทำไมต้องห่อไลบรารี

ทำไมไม่ใช้ไลบรารีตรง ๆ ในแต่ละหน้า? นี่คือแพตเทิร์นที่อยากให้จำไปใช้ตลอดชีวิตนักพัฒนา: อย่าปล่อยให้ API ของไลบรารีภายนอกกระจายทั่ว codebase ห่อมันไว้ในคอมโพเนนต์ของเราหนึ่งชั้น แล้วให้ทั้งแอปรู้จักแค่ API ของเรา ผลที่ได้:

  • เปลี่ยนไลบรารีได้โดยแก้ไฟล์เดียว — วันหนึ่ง react-modal เลิกพัฒนา หรือทีมอยากย้ายไปใช้ <dialog> ของ HTML แท้ ๆ เราแก้แค่ Modal.tsx ไฟล์เดียว หน้าที่เหลือไม่ต้องแตะ
  • API แคบลงเหลือแค่ที่เราใช้จริง — react-modal มี props เป็นสิบตัว แต่แอปเราต้องการแค่ เปิด/ปิด/เนื้อหา คนในทีมไม่ต้องอ่าน docs ของไลบรารีก็ใช้ Modal เราเป็น
  • หน้าตาสม่ำเสมอ — ปุ่มกากบาทปิด modal อยู่มุมเดิมทุกครั้ง ไม่ต้องเขียนซ้ำในทุกจุดที่ใช้

แพตเทิร์นนี้มีผลกับวิธีสั่งงาน Agent ด้วย และเป็นเรื่องที่ต้องระวังเป็นพิเศษในบทนี้: โมเดลเห็นโค้ดที่เขียน pagination เองมาเยอะมาก (วนลูปทำปุ่มเลขหน้า, คำนวณ ... เอง) มากกว่าโค้ดที่ห่อ react-paginate หลายเท่า ถ้า prompt ไม่ยืนยันว่า "ต้องห่อไลบรารีตัวนี้" ของที่ได้กลับมามีโอกาสสูงที่จะเป็น pagination เขียนมือที่ทำงานได้ หน้าตาดี และผิดโจทย์ทั้งดุ้น

ติดตั้งไลบรารีด้วยมือ

npm install react-modal react-paginate
npm install -D @types/react-modal
git add -A && git commit -m "chore: install react-modal and react-paginate"

สังเกตความไม่สมมาตร: ทำไม react-modal ต้องลง @types/react-modal เพิ่ม แต่ react-paginate ไม่ต้อง? เพราะ react-modal เขียนด้วย JavaScript ล้วนและไม่แถม type declarations มาในตัว — ถ้า import เฉย ๆ TypeScript จะฟ้อง Could not find a declaration file for module 'react-modal' ชุมชนเลยเขียน type ให้แยกต่างหากในโปรเจกต์กลางชื่อ DefinitelyTyped ซึ่งเผยแพร่ทุกตัวใต้ชื่อ @types/... (ลงเป็น -D เพราะ type ใช้ตอน dev/compile เท่านั้น ไม่ไปกับ bundle) ส่วน react-paginate แถมไฟล์ .d.ts มาในแพ็กเกจแล้ว ลงตัวเดียวจบ — เวลาเจอไลบรารีใหม่ วิธีเช็กง่ายสุดคือ import แล้วดูว่า TypeScript บ่นไหม

และนี่คือเหตุผลอีกข้อที่เราติดตั้ง dependency เอง: การตัดสินใจว่าอะไรเป็น dependency อะไรเป็น devDependency เป็นเรื่องที่ต้องคิด ไม่ใช่เรื่องที่ปล่อยให้ Agent เดา

💡 ทั้ง react-modal และ react-paginate เป็นแพ็กเกจ CJS แบบเดียวกับ react-spinners — ที่มันทำงานบน Vite 8 ได้เพราะ legacy.inconsistentCjsInterop ที่เราตั้งไว้บทที่แล้ว ถ้าคุณข้ามบทนั้นมา กลับไปทำก่อน

Modal: ของที่อยู่ผิดที่โดยธรรมชาติ

ย้อนความจากคอร์ส React พื้นฐาน เรื่อง portals: modal เป็น UI ที่อยู่ผิดที่โดยธรรมชาติ — ตัวมันถูกเรียกจากลึก ๆ ในหน้าเพจ แต่ต้องแสดงลอยทับทุกอย่าง ถ้า render ตรงนั้นเลยจะโดน overflow: hidden หรือ stacking context ของ parent เล่นงาน ทางแก้คือ createPortal ที่พาไป render นอก DOM tree ของ parent — react-modal จัดการเรื่องนี้ให้เราหมดแล้ว แถม overlay, การกด ESC เพื่อปิด, การคลิกนอกกล่องเพื่อปิด และการจัดการ focus มาให้ครบ เราแค่ห่อมันให้เข้ากับแอปเรา

เรื่องที่ต้องตัดสินใจก่อนเขียน prompt คือ ariaHideApp ปกติ react-modal อยากรู้ว่า "ตัวแอปหลัก" คือ element ไหน (บอกผ่าน ReactModal.setAppElement("#root")) เพื่อใส่ aria-hidden ให้ฉากหลังตอน modal เปิด — screen reader จะได้ไม่หลงไปอ่านเนื้อหาข้างหลัง ถ้าไม่ตั้งค่านี้มันจะเตือนใน console ทุกครั้งที่เปิด modal โปรเจกต์นี้เลือกปิด feature นี้ด้วย ariaHideApp={false} เพื่อให้ wrapper เรียบง่าย ซึ่งเป็น trade-off ที่ต้องรู้ตัว: แอปที่จริงจังเรื่อง accessibility ควรเรียก setAppElement ให้ถูกต้องแทนการปิด

ประเด็นสำหรับบทนี้คือ ตัวเลือกนี้เป็นการตัดสินใจของเรา ไม่ใช่ของ Agent — ดังนั้น prompt ต้องเขียนออกมาตรง ๆ ว่าเอาแบบไหน ถ้าเงียบไว้ คุณจะได้ทางใดทางหนึ่งแบบสุ่ม แล้วต้องมานั่งเดาว่ามันเลือกแบบนั้นเพราะอะไร

Pagination: ซ่อนความประหลาดของไลบรารีไว้ในไฟล์เดียว

หน้า Category จะแสดงสินค้าทีละ 12 ชิ้น ผู้ใช้ต้องกดเปลี่ยนหน้าได้ — ตัวเลข, ปุ่ม Previous/Next, จุดไข่ปลาตอนหน้าเยอะ ๆ ทั้งหมดนี้ react-paginate ทำให้ แต่มันมีเรื่องกวนใจหนึ่งอย่างที่เราจะซ่อนไว้ใน wrapper: react-paginate นับหน้าจากศูนย์ (หน้าแรกคือ index 0) ในขณะที่มนุษย์และ URL ของเรานับจากหนึ่ง

contract ที่เราออกแบบให้คนใช้จึงมีสาม props และนับจากหนึ่งทั้งหมด: currentPage (หน้าปัจจุบัน 1, 2, 3, …), totalPages (จำนวนหน้าทั้งหมด) และ onPageChange (callback ที่ได้รับเลขหน้าใหม่ นับจากหนึ่งเช่นกัน) การแปลงระหว่างสองโลกเกิดขึ้นในไฟล์นี้ที่เดียว หน้า Category ในบทเรียน 20 จะได้ทำงานกับเลขหน้าปกติโดยไม่ต้องรู้เลยว่าเบื้องหลังมีการ +1/-1 อยู่ ส่วน totalPages นั้นหน้า Category จะคำนวณจากจำนวนสินค้าทั้งหมดที่ API ตอบมา ด้วยฟังก์ชัน calculateTotalPages ที่เราจะเขียนในบทเรียน 16

เป้าหมายของบทนี้

src/
└── shared/
    └── components/
        ├── Modal/
        │   ├── Modal.module.scss        # ใหม่ — มี class เดียว: ปุ่มปิด
        │   └── Modal.tsx                # ใหม่ — wrapper ของ react-modal
        └── Pagination/
            ├── Pagination.module.scss   # ใหม่ — style ให้ markup ที่ไลบรารี render
            └── Pagination.tsx           # ใหม่ — wrapper ของ react-paginate

สัญญาของแต่ละไฟล์ — และสิ่งที่มันต้องไม่ทำ:

  • Modal.tsx — ต้องเปิดรับแค่สาม props (isOpen, onRequestClose, children) และเป็น controlled ล้วน ต้องไม่มี useState ที่เก็บสถานะเปิด/ปิดของตัวเอง และต้องไม่ปล่อย props ของ react-modal ทะลุออกไปให้คนเรียกเห็น
  • Modal.module.scss — ต้องมี class เดียวคือปุ่มปิด ต้องไม่มีบรรทัด @use (ไฟล์นี้ไม่ได้ใช้ตัวแปรสีสักตัว การ @use ทิ้งไว้เฉย ๆ คือ import ที่ไม่มีใครใช้)
  • Pagination.tsx — ต้อง render ReactPaginate จาก react-paginate ต้องไม่มี map, ไม่มีการวนสร้างปุ่มเลขหน้าเอง และต้องไม่มีเลข index ดิบ ๆ หลุดออกไปหา caller
  • Pagination.module.scss — ต้อง style ผ่าน selector ลูกใต้ class ที่ถูก scope ต้องไม่มี selector ระดับ global อย่าง ul หรือ li ลอย ๆ ที่ไม่มี class ของเราครอบ

🤖 Prompt ที่ส่งให้ Cursor

🤖 Prompt ที่ส่งให้ Cursor — แชทใหม่ โหมด Agent สังเกตว่า บริบท: ยังชี้ไป Button.tsx เหมือนบทที่แล้ว แม่แบบที่พิมพ์เองรอบเดียวยังทำงานให้เราต่อในบทนี้และบทหน้า:

สร้างคอมโพเนนต์กลาง Modal และ Pagination โดยห่อไลบรารี react-modal และ react-paginate

บริบท: @src/shared/components/Button/Button.tsx @src/shared/components @src/styles
ใช้ Button เป็นแม่แบบของรูปทรงไฟล์เหมือนบทที่แล้ว
ติดตั้ง react-modal, react-paginate และ @types/react-modal (ตัวหลังเป็น devDependency) ไว้แล้ว
vite.config.ts เปิด legacy.inconsistentCjsInterop ไว้แล้ว ทั้งสองไลบรารีจึง default import ได้ตามปกติ
Font Awesome ครบทั้งห้า package ติดตั้งไว้ตั้งแต่บทที่ทำ Header/Footer
utility class ที่งานนี้ใช้มีอยู่จริงใน src/styles/ แล้ว: flex, gap-10, fs-20

โครงสร้าง: สร้างไฟล์ตามนี้ ไม่มากไม่น้อยกว่านี้
- src/shared/components/Modal/Modal.module.scss
- src/shared/components/Modal/Modal.tsx
- src/shared/components/Pagination/Pagination.module.scss
- src/shared/components/Pagination/Pagination.tsx

ข้อกำหนดทางเทคนิค:
- Modal.module.scss: มี class เดียวชื่อ .closeButton
  position: absolute, top: 5px, right: 5px, background: none, border: none, cursor: pointer
  ไฟล์นี้ไม่ต้อง @use variables เพราะไม่ได้ใช้ตัวแปรสีเลย
- Modal.tsx: import ตัวไลบรารีเป็นชื่อ ReactModal จาก "react-modal"
  ประกาศ object ชื่อ customStyles ที่ระดับ module (นอกคอมโพเนนต์) มีแค่ key content:
    top: "50%", left: "50%", right: "auto", bottom: "auto",
    transform: "translate(-50%, -50%)"
  interface ModalProps: isOpen: boolean, onRequestClose: () => void,
    children: React.ReactNode
  default export ชื่อ Modal เป็น React.FC ที่ return ReactModal พร้อม prop
    isOpen, onRequestClose, style={customStyles} และ ariaHideApp={false}
  ห้ามเรียก ReactModal.setAppElement ในไฟล์นี้ โปรเจกต์นี้เลือกปิด ariaHideApp แทน
  ข้างใน ReactModal มีสองอย่างเรียงตามนี้:
    1) button onClick={onRequestClose} className={styles.closeButton}
       aria-label="Close Modal" ข้างในเป็น FontAwesomeIcon icon={faTimes} className="fs-20"
       โดย import faTimes จาก "@fortawesome/free-solid-svg-icons"
    2) div ที่ครอบ {children}
  ห้ามมี state ภายใน ทั้ง isOpen และ onRequestClose มาจากคนเรียกเท่านั้น
- Pagination.module.scss: เขียนเป็น selector ลูกใต้ .pagination ทั้งหมด
  .pagination -> display: flex, justify-content: center, list-style: none, padding: 0
  .pagination li -> margin: 0 5px
  .pagination li a -> padding: 8px 12px, border: 1px solid #ddd, border-radius: 4px,
    text-decoration: none, cursor: pointer
  .pagination li.active a -> background-color: #007bff, color: white, border-color: #007bff
  .pagination li.previous a และ .pagination li.next a -> font-weight: bold
  .pagination li.disabled a -> color: #ccc, cursor: not-allowed
  ใช้ค่าสีตามนี้ตรง ๆ ไม่ต้องแทนด้วยตัวแปรจาก _variables.scss
- Pagination.tsx: ห้ามเขียนตรรกะแบ่งหน้าเอง ต้อง render ReactPaginate จาก "react-paginate"
    เท่านั้น ห้ามมี map, ห้ามมี Array.from, ห้ามสร้างปุ่มเลขหน้าเอง
  interface PaginationProps มีสามตัว: currentPage: number, totalPages: number,
    onPageChange: (page: number) => void — ทั้งหมดนับหน้าจากหนึ่ง
  ส่งให้ ReactPaginate ตามนี้:
    previousLabel={"Previous"} nextLabel={"Next"} breakLabel={"..."}
    pageCount={totalPages}
    forcePage={currentPage - 1}
    pageRangeDisplayed={5}
    onPageChange={(data) => onPageChange(data.selected + 1)}
    containerClassName={`${styles.pagination} flex gap-10`}
    activeClassName={styles.active}
    previousClassName={styles.previous}
    nextClassName={styles.next}
    disabledClassName={styles.disabled}
  ใส่ comment สั้น ๆ ได้สองจุดเท่านั้น: ตรง forcePage และตรง onPageChange
    เพื่อบอกว่าไลบรารีนับหน้าจากศูนย์ ห้ามใส่ comment ที่อื่น

ขอบเขต:
- ห้ามติดตั้ง dependency ใหม่
- ห้ามแก้ vite.config.ts, package.json หรือไฟล์ใด ๆ นอกสี่ไฟล์ข้างบน
- ห้ามสร้าง index.ts หรือไฟล์ barrel
- ยังไม่ต้องเอา Modal หรือ Pagination ไปใช้ในหน้าไหน และยังไม่ต้องเขียนฟังก์ชันคำนวณ
  จำนวนหน้า (จะทำในบทของ pagination utils)

บรรทัดที่ยาวผิดสัดส่วนที่สุดใน prompt นี้คือข้อห้ามของ Pagination.tsx — "ห้ามเขียนตรรกะแบ่งหน้าเอง ห้ามมี map ห้ามมี Array.from" ปกติเราไม่ไล่ห้ามละเอียดขนาดนั้น แต่จุดนี้ต่างออกไป เพราะมันคือกรณีที่ของที่ผิดโจทย์ทำงานได้จริงและดูดีด้วย ข้อห้ามที่ตรวจได้ (คำว่า map มีในไฟล์ไหม) ดีกว่าคำขอที่ตรวจไม่ได้ ("ให้ใช้ไลบรารีนะ")

✅ ตรวจโค้ดที่ AI สร้าง

เดินวงจรตรวจงานตามลำดับเดิม: ขั้นที่หนึ่งอ่าน diff, ขั้นที่สองคือ checklist ข้างล่างนี้ (อ่านบรรทัด AI มักพลาดตรงนี้: ก่อนเสมอ), ขั้นที่สามคือ npm run lint และ npm run typecheck ซึ่งบทนี้มีโอกาสตกจริงมากกว่าสองบทก่อน เพราะ type ของ react-modal มาจากแพ็กเกจแยก

✅ ตรวจโค้ดที่ AI สร้าง — git status และ git diff ก่อน แล้วไล่ทีละข้อ:

  • AI มักพลาดตรงนี้: สองเรื่องที่มาคู่กันประจำในบทนี้ — (1) เรื่อง aria ของ Modal ถ้า ariaHideApp={false} หายไปโดยที่ไม่มีการเรียก ReactModal.setAppElement(...) ที่ไหนเลย ผลคือ react-modal เตือนใน console ทุกครั้งที่เปิด modal ซึ่งเป็นอาการที่มองไม่เห็นจนกว่าจะมีใครเปิด DevTools ในบทเรียน 23 และถ้ามันเติม setAppElement("#root") มาให้เอง นั่นคือทำเกิน prompt — บรรทัดนั้นต้องมั่นใจว่า element ที่ selector ชี้ไปมีอยู่จริง ณ เวลาที่โค้ดทำงาน ซึ่งไม่จริงเสมอไป เช่นตอนที่ component ถูก render ในชุดทดสอบที่ไม่มี <div id="root"> อยู่ในหน้า อีกจุดที่หายบ่อยคือ aria-label="Close Modal" บนปุ่มกากบาท ปุ่มที่มีแต่ไอคอนแล้วไม่มี label ผู้ใช้ screen reader จะได้ยินแค่คำว่า "button" — (2) เรื่อง pagination เขียนมือ เปิด Pagination.tsx แล้วค้นคำว่า map เป็นอย่างแรก ถ้าเจอ แปลว่ามันเขียนปุ่มเลขหน้าเอง ไม่ได้ห่อ react-paginate ซึ่งเป็น "รูปทรงผิด" — git restore . ลบไฟล์ใหม่ทิ้งแล้วสั่งใหม่ ไม่ใช่ไล่แก้ เพราะของที่ได้จะไม่มีอะไรตรงกับ contract สามบรรทัดที่เราออกแบบไว้เลย
  • ไฟล์ใหม่ 4 ไฟล์พอดี ไม่มีไฟล์อื่นใน git status โดยเฉพาะ package.json ที่ต้องไม่ถูกแตะ
  • Modal.tsx import ไลบรารีในชื่อ ReactModal — ไม่ใช่ Modal ซึ่งจะชนกับชื่อคอมโพเนนต์ของเราเองในไฟล์เดียวกัน
  • customStyles ถูกประกาศนอกตัวคอมโพเนนต์ ถ้ามันย้ายเข้าไปข้างใน object จะถูกสร้างใหม่ทุกรอบ render
  • ใน customStyles มี right: "auto" และ bottom: "auto" ครบ — สองบรรทัดนี้ล้างค่า default ของไลบรารีที่ทำให้กล่องกางเต็มจอ ขาดไปกล่องจะไม่ได้ขนาดตามเนื้อหา
  • ปุ่มปิดใช้ onRequestClose ตัวเดียวกับที่ส่งให้ react-modal ไม่ใช่ callback คนละตัวหรือ state คนละก้อน
  • Modal ไม่มี useState, ไม่มี useEffect และไม่มี prop ชื่อ onClose หรือ title ที่แถมมาเอง
  • Pagination.tsx ส่ง forcePage={currentPage - 1} และแปลงกลับด้วย data.selected + 1 — ทั้งสองจุดต้องมีคู่กัน ถ้าเจอแค่ข้างเดียว เลขหน้าจะเพี้ยนไปหนึ่งหน้าแบบเงียบ ๆ (อาการที่จะไปโผล่ตอนหน้า Category ในบทเรียน 20 แสดงสินค้าซ้ำหรือข้ามหน้า)
  • ชื่อ prop ของ PaginationProps ตรงตัว: currentPage, totalPages, onPageChange — ไม่ใช่ page, pageCount หรือ onChange
  • containerClassName ผสม styles.pagination กับ utility flex gap-10 ไว้ใน template literal เดียว
  • ทุก selector ใน Pagination.module.scss มี .pagination นำหน้า — ไม่มี li หรือ a ลอย ๆ ที่จะรั่วไปโดน element อื่นทั้งแอป
  • ค่าสีใน Pagination.module.scss ยังเป็น #ddd / #007bff / #ccc ตามที่ prompt สั่ง ไม่ถูกแทนด้วย variables.$primary-color — บทนี้เป็นข้อยกเว้นที่ตั้งใจ (เหตุผลอยู่ในกล่อง 💡 ใต้ไฟล์นี้) ต่างจากบทเรียน 12 และ 14 ที่ข้อ "ไม่มี hex โผล่มาสักค่า" ยังใช้ตามปกติ
  • ไม่มี comment เกินสองจุดที่ระบุไว้ในไฟล์ Pagination.tsx
  • npm run typecheck ผ่าน — ถ้าฟ้อง Could not find a declaration file for module 'react-modal' แปลว่าลืมติดตั้ง @types/react-modal

import { FontAwesomeIcon } from "@fortawesome/react-fontawesome";
import React from "react";
import ReactModal from "react-modal";
import { faTimes } from "@fortawesome/free-solid-svg-icons";
import styles from "./Modal.module.scss";

const customStyles = {
  content: {
    top: "50%",
    left: "50%",
    right: "auto",
    bottom: "auto",
    transform: "translate(-50%, -50%)",
  },
};
interface ModalProps {
  isOpen: boolean;
  onRequestClose: () => void;
  children: React.ReactNode;
}

const Modal: React.FC<ModalProps> = ({ isOpen, onRequestClose, children }) => {
  return (
    <ReactModal
      isOpen={isOpen}
      onRequestClose={onRequestClose}
      style={customStyles}
      ariaHideApp={false}
    >
      <button
        onClick={onRequestClose}
        className={styles.closeButton}
        aria-label="Close Modal"
      >
        <FontAwesomeIcon icon={faTimes} className="fs-20" />
      </button>
      <div>{children}</div>
    </ReactModal>
  );
};

export default Modal;

ไล่ดูทีละส่วน:

  • API ของเราเหลือ 3 props — isOpen (เปิดอยู่ไหม), onRequestClose (จะให้ทำอะไรตอนผู้ใช้ขอปิด) และ children (เนื้อหาใน modal) — สังเกตว่า modal เป็น controlled component เหมือน radio บทที่แล้ว: ตัวมันไม่ตัดสินใจเองว่าเปิดหรือปิด state อยู่กับหน้าที่เรียกใช้เสมอ
  • onRequestClose ถูกใช้สองทาง — ส่งให้ react-modal (ครอบคลุมการกด ESC และคลิกที่ overlay ด้านนอก) และผูกกับปุ่มกากบาทของเราเอง ทุกช่องทางปิดวิ่งมาที่ callback เดียวกัน
  • customStyles จัดกึ่งกลางจอ — react-modal รับ inline style ผ่าน prop style โดยแยกเป็นส่วน content (ตัวกล่อง) กับ overlay (ฉากหลัง) ตรงนี้เราใช้ท่าจัดกึ่งกลางคลาสสิก: ปักหมุดมุมบนซ้ายของกล่องไว้กลางจอ (top/left: 50%) แล้ว translate(-50%, -50%) ดึงกลับมาครึ่งหนึ่งของขนาดกล่องเอง — ได้กึ่งกลางเป๊ะไม่ว่ากล่องจะกว้างยาวเท่าไร ส่วน right/bottom: "auto" ล้างค่า default ของไลบรารีที่ตั้งให้กล่องขยายเต็มจอ
  • prop style ไม่ใช่ inline style ที่ไฟล์ rules ห้าม — ข้อห้ามในกติกาหมายถึงการเขียน style={{ ... }} ใส่ element ของเราเองแทนการใช้ SCSS ส่วนตรงนี้คือ API ของไลบรารีที่บังคับให้ส่ง object เข้าไป ไม่มีทางอื่น — เวลาเจอกติกาที่ชนกับความจริงแบบนี้ สิ่งที่ต้องทำคือรู้ว่าทำไมถึงยกเว้น ไม่ใช่ดัดโค้ดให้เข้ากติกาจนพัง
  • ariaHideApp={false} — ตัวเลือกที่เราคุยกันไปแล้วข้างบน: ปิด feature นี้เพื่อความเรียบง่ายของ wrapper แลกกับ accessibility ที่ด้อยลงหนึ่งขั้น โปรเจกต์นี้ไม่กลับมาแก้จุดนี้อีกตลอดคอร์ส ถ้าคุณเอาโค้ดชุดนี้ไปใช้ในงานจริงที่มีผู้ใช้ screen reader นี่คือบรรทัดแรกที่ควรกลับมาแก้
  • aria-label="Close Modal" — ปุ่มปิดมีแต่ icon ไม่มีข้อความ ถ้าไม่ใส่ label ผู้ใช้ screen reader จะได้ยินแค่ "button" เฉย ๆ ไม่รู้ว่ากดแล้วเกิดอะไร

src/shared/components/Pagination/Pagination.tsx:

import React from "react";
import ReactPaginate from "react-paginate";
import styles from "./Pagination.module.scss";

interface PaginationProps {
  currentPage: number;
  totalPages: number;
  onPageChange: (page: number) => void;
}

const Pagination: React.FC<PaginationProps> = ({
  currentPage,
  totalPages,
  onPageChange,
}) => {
  return (
    <ReactPaginate
      previousLabel={"Previous"}
      nextLabel={"Next"}
      breakLabel={"..."}
      pageCount={totalPages}
      forcePage={currentPage - 1} // ReactPaginate is zero-indexed
      pageRangeDisplayed={5}
      onPageChange={(data) => onPageChange(data.selected + 1)} // Add 1 to convert zero-indexed to one-indexed
      containerClassName={`${styles.pagination} flex gap-10`} // Use custom or predefined classes
      activeClassName={styles.active} // Highlight active page
      previousClassName={styles.previous}
      nextClassName={styles.next}
      disabledClassName={styles.disabled}
    />
  );
};

export default Pagination;

โค้ดต้นฉบับของโปรเจกต์มี comment สี่บรรทัด ไม่ใช่สองตามที่ prompt สั่ง — สองบรรทัดแรก (zero-indexed) คือ comment ที่มีค่า เพราะมันอธิบายสิ่งที่โค้ดบอกไม่ได้ ส่วน // Use custom or predefined classes กับ // Highlight active page คือ comment ที่บอกสิ่งที่ชื่อ prop บอกอยู่แล้ว ซึ่งไฟล์ rules ห้ามไว้ตั้งแต่บทเรียน 07 ถ้า Agent ของคุณไม่ได้สร้างสองบรรทัดหลังมา นั่นคือผลที่ถูกกว่าต้นฉบับ — และถ้าสร้างมา ลบทิ้งได้เลย

การแปลงระหว่างสองโลกเกิดขึ้นในไฟล์นี้ที่เดียว: ขาเข้า forcePage={currentPage - 1} แปลงเลขหน้ามนุษย์เป็น index ของไลบรารี ขาออก data.selected + 1 แปลงกลับก่อนส่งให้คนเรียก นี่แหละคุณค่าของ wrapper: ความประหลาดของไลบรารีถูกขังไว้ในไฟล์เดียว ปิดท้ายด้วย props ตกแต่ง: pageRangeDisplayed={5} โชว์เลขหน้ารอบ ๆ หน้าปัจจุบันสูงสุด 5 ตัวก่อนย่อเป็น breakLabel จุดไข่ปลา และ className ทั้งห้าตัวคือจุดที่เรายื่นชื่อ class จาก module ของเราให้ไลบรารีแปะลง element ที่มัน render
