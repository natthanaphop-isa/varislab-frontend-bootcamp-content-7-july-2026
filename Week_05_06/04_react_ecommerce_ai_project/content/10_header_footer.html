Header และ Footer

Header & Footer

ตอนนี้ทุก URL ของเราเปิดได้แล้ว แต่หน้าตายังเป็นแค่ตัวหนังสือลอย ๆ กลางหน้าขาว บทนี้เราจะเติมสองชิ้นส่วนที่ทำให้มัน "ดูเป็นเว็บ" ขึ้นมาทันที: Header ที่มีโลโก้และเมนูนำทางอยู่บนสุดของทุกหน้า และ Footer ที่มีข้อมูลร้านอยู่ล่างสุดของทุกหน้า — และเพราะเราวาง MainLayout ไว้แล้วในบทที่แล้ว ทั้งสองตัวจะเขียนครั้งเดียวแล้วโผล่ครบทุกหน้าโดยอัตโนมัติ

Font Awesome คืออะไร แบ่งเป็นห้า package ทำไม

Footer ของเรา (และอีกหลาย component ในบทถัด ๆ ไป) ใช้ไอคอนจาก Font Awesome ซึ่งเป็นชุดไอคอนที่แพร่หลายที่สุดชุดหนึ่งของเว็บ มันแตกเป็นห้า package ที่แบ่งหน้าที่กันชัดเจน:

  • fontawesome-svg-core — เครื่องยนต์กลางที่แปลงข้อมูลไอคอนเป็น SVG
  • react-fontawesome — component <FontAwesomeIcon> สำหรับใช้ใน JSX
  • free-solid-svg-icons / free-regular-svg-icons / free-brands-svg-icons — ตัวไอคอนจริง ๆ สามสไตล์: แบบทึบ แบบเส้น และโลโก้แบรนด์ต่าง ๆ

วันนี้เราใช้แค่ชุด solid ส่วนชุด regular จะได้ใช้ตอนทำดาวรีวิวในบทเรียน 14 และหน้า Home ในบทเรียน 19 ข้อดีของ Font Awesome ยุคใหม่คือมันเป็น SVG + tree-shaking: เรา import ไอคอนเป็นราย ๆ ตัว ตัวไหนไม่ได้ import ก็ไม่ติดไปกับ bundle — ไม่เหมือนสมัยก่อนที่ต้องโหลดฟอนต์ไอคอนทั้งพันตัวมาเพื่อใช้สามตัว

useProductRoute: รวมเส้นทางไว้ที่เดียว

ก่อนสร้าง Header เราจะสร้าง hook เล็ก ๆ ที่เป็นการตัดสินใจเชิงสถาปัตยกรรมที่ดีมากของโปรเจกต์นี้ ลองนึกภาพ: ปุ่ม "ดูสินค้า" บนการ์ดสินค้า, ปุ่มไอคอนตะกร้าบน Header, ปุ่ม "ไปชำระเงิน" ในหน้า Cart — ทุกจุดต้องสั่ง navigate ไปยัง URL สักเส้น ถ้าแต่ละจุดเขียน navigate(`/products/${id}`) เองกระจัดกระจายทั่วแอป วันที่เราอยากเปลี่ยน URL scheme (เช่น /products/:id เป็น /p/:id) จะต้องไล่แก้ทุกไฟล์แล้วภาวนาว่าไม่ตกหล่นสักที่

ทางแก้คือรวม "เส้นทางที่แอปนี้เดินได้" ไว้ใน hook เดียว ซึ่งห่อ useNavigate ของ react-router (ฝั่ง TanStack Router ในคอร์ส React พื้นฐาน ก็มี hook ชื่อเดียวกันนี้เลย) อีกชั้นเพื่อให้ได้ประโยชน์สามข้อ:

  • แก้ที่เดียว — URL string ของทุกเส้นทางอยู่ในไฟล์นี้ไฟล์เดียว เปลี่ยนเมื่อไหร่ก็จบในไฟล์เดียว
  • อ่านรู้เรื่อง — จุดที่เรียกใช้เขียนว่า goToProductDetails(id) ซึ่งบอกเจตนา ชัดกว่า navigate(`/products/${id}`) ที่บอกแค่กลไก
  • type-safe — goToProductDetails บังคับรับ id: number จะลืมส่ง id หรือส่งผิด type ก็โดน TypeScript จับตั้งแต่ตอนพิมพ์

จบบทนี้ยังไม่มีใครเรียกใช้มันสักที่ — แต่อีกไม่กี่บทมันจะกลายเป็น hook ยอดนิยมของโปรเจกต์: หน้า Home, Category, Cart และตัว Header เอง (ในบทเรียน 23) ล้วนต้องใช้

Link ไม่ใช่ a

จุดที่สำคัญที่สุดของ Header คือทุกลิงก์ต้องเป็น <Link to="..."> ของ react-router ไม่ใช่ <a href="..."> ธรรมดา สองตัวนี้หน้าตาผลลัพธ์เหมือนกัน (Link ก็ render เป็น <a> ใน DOM) แต่พฤติกรรมต่างกันสุดขั้ว:

  • <a href> สั่งเบราว์เซอร์โหลดหน้าใหม่ทั้งหน้า — JavaScript ทั้งแอปถูกโยนทิ้งแล้วเริ่มใหม่หมด state ทุกอย่าง (เช่น ของในตะกร้าที่ยังไม่ได้ save) หายเกลี้ยง แถมผู้ใช้เห็นจอกะพริบ
  • <Link to> ดัก click ไว้แล้วบอก router ให้สลับ component พร้อมอัปเดต URL ผ่าน History API — ไม่มีการโหลดหน้าใหม่ แอปยังมีชีวิตต่อเนื่อง เร็วกว่ากันคนละโลก

กฎจำง่าย: ลิงก์ภายในแอปใช้ Link เสมอ ลิงก์ออกไปเว็บอื่นใช้ <a> และของที่ผู้ใช้กดเพื่อไปหน้าอื่น ต้องเป็นลิงก์จริง ๆ ไม่ใช่ <div onClick> ที่หน้าตาเหมือนลิงก์ — เพราะ div กดผ่านคีย์บอร์ดไม่ได้ คลิกขวาเปิดแท็บใหม่ไม่ได้ และ screen reader ไม่รู้ว่ามันพาไปไหน

เมื่อไหร่ถึงต้องมี .module.scss

บทนี้จะเห็นทั้งสองฝั่งของกติกาข้อนี้ในบทเดียว: Header ไม่มี ไฟล์ .module.scss เพราะทุกอย่างที่มันต้องการ — ระยะห่าง (pt-25), การจัดแถว (flex space-between align-item-center), หน้าตาลิงก์ (nav-link) — มีครบใน utility classes ที่เราเขียนไว้บทเรียน 04 แล้ว ส่วน Footer มี เพราะมันต้องการของที่ utility class ไม่ครอบคลุม: พื้นหลังสีเข้มทั้งแถบ หลักคิดคือ สร้างไฟล์ style เมื่อมี style เฉพาะตัวจริง ๆ เท่านั้น

ไฟล์ที่สามคือ MainLayout.module.scss ที่บทที่แล้วเว้นไว้ ในนั้นมีสองกฎที่รวมกันเป็นสูตรคลาสสิกชื่อ sticky footer: ตัว container เป็น flex column ที่สูงอย่างน้อยเต็มจอ (min-height: 100vh) และส่วนเนื้อหากลางถูกสั่งให้ flex-grow: 1 คือยืดกินพื้นที่ที่เหลือทั้งหมด ผลคือหน้าที่เนื้อหาสั้น ๆ Footer ก็ยังถูกดันไปอยู่ขอบล่างของจอเสมอ ไม่ลอยขึ้นมากลางหน้า

สองไฟล์นี้คือไฟล์ SCSS Module ชุดแรกของโปรเจกต์ สังเกต pattern ให้ดีเพราะเราจะใช้ซ้ำตลอดทั้งคอร์ส: ตั้งชื่อไฟล์ลงท้าย .module.scss, import เข้ามาเป็น object ชื่อ styles, แล้วอ้าง class ผ่าน styles.container — ตอน build ชื่อ class จะถูกแปลงเป็นชื่อไม่ซ้ำใคร (เช่น _container_x7f2k) ดังนั้นต่อให้ไฟล์อื่นมี class ชื่อ .container เหมือนกันก็ไม่มีทางชนกัน

เป้าหมายของบทนี้

src/
├── app/
│   └── layouts/
│       └── MainLayout/
│           ├── MainLayout.module.scss   # ใหม่ — sticky footer
│           └── MainLayout.tsx           # แก้ — เติม Header/Footer
└── shared/
    ├── components/
    │   ├── Header/Header.tsx            # ใหม่ — เวอร์ชันแรก
    │   └── Footer/
    │       ├── Footer.module.scss       # ใหม่
    │       └── Footer.tsx               # ใหม่
    └── hooks/
        └── useProductRoute.tsx          # ใหม่

สัญญาของแต่ละไฟล์:

  • useProductRoute.tsx — ต้องคืนฟังก์ชันสี่ตัวที่ครอบ useNavigate และต้องเป็นที่เดียวในโปรเจกต์ที่มี URL string ของการ navigate ต้องไม่มีใครเรียกใช้มันในบทนี้ สังเกตนามสกุลไว้ด้วย: ไฟล์นี้เป็น .tsx ทั้งที่ข้างในไม่มี JSX เลยสักบรรทัด (ตามหลักแล้วควรเป็น .ts — บทเรียน 11 จะบังคับข้อนี้กับ queryClient.ts) เราคงตามโค้ดต้นฉบับไว้ เพราะนี่คือสิ่งที่เกิดขึ้นจริงในโปรเจกต์ที่โตขึ้นเรื่อย ๆ: ธรรมเนียมที่ไม่มีเครื่องมือบังคับ จะค่อย ๆ เพี้ยนไปทีละไฟล์ และไม่มีใครสังเกตจนกว่าจะมีคนมาไล่อ่านทั้งโฟลเดอร์
  • Header.tsx — ต้องมีโลโก้และเมนูสองรายการที่เป็น Link ทั้งหมด ต้องไม่มีไอคอนตะกร้า ไม่มี badge จำนวนสินค้า และไม่มีไฟล์ .module.scss
  • Footer.tsx + Footer.module.scss — ต้องใช้สีจาก _variables.scss ผ่าน @use ต้องไม่ hardcode ค่าสีเป็น hex ในไฟล์ใด ๆ
  • MainLayout — ต้องกลายเป็นเวอร์ชันสมบูรณ์: Header ข้างบน <Outlet /> ตรงกลาง Footer ข้างล่าง และ Footer ต้องติดขอบล่างจอแม้เนื้อหาสั้น ต้องไม่แตะ router.tsx หรือหน้าใด ๆ ใน pages/
💡 Header ที่ได้จากบทนี้เป็นเวอร์ชันแรก — เว็บ E-commerce จริงต้องมีไอคอนตะกร้าพร้อม badge บอกจำนวนสินค้าอยู่มุมขวา แต่ตัวเลขนั้นต้องอ่านจาก cart state ซึ่งเรายังไม่ได้สร้าง บทเรียน 23 เราจะกลับมาเติม component <CartSummary /> ตรงมุมขวานี้ พร้อมเรียก goToCartSummary จาก useProductRoute ที่กำลังจะสร้าง — อย่าเพิ่งทำในบทนี้ และเหตุผลที่ยังไม่เขียนบรรทัด useProductRoute() ค้างไว้ใน Header ตั้งแต่ตอนนี้ ก็เพราะตัวแปรที่ประกาศแล้วไม่ได้ใช้จะโดน ESLint ของเราฟ้องทันที (และมันฟ้องถูกแล้ว)

ติดตั้ง Font Awesome ด้วยมือ

ติดตั้งตาม package.json ของโปรเจกต์จริงให้ครบชุดในครั้งเดียว แล้ว commit ก่อนเปิดแชท:

npm install @fortawesome/fontawesome-svg-core @fortawesome/react-fontawesome @fortawesome/free-solid-svg-icons @fortawesome/free-regular-svg-icons @fortawesome/free-brands-svg-icons
git add -A && git commit -m "chore: install font awesome"

🤖 Prompt ที่ส่งให้ Cursor

🤖 Prompt ที่ส่งให้ Cursor — แชทใหม่ โหมด Agent สังเกตว่า ข้อกำหนดทางเทคนิค: รอบนี้ยาวกว่าบทที่แล้วมาก เพราะเนื้อหาใน Header/Footer เป็นข้อความจริงที่เดาไม่ได้ ทุกอย่างที่คุณไม่พิมพ์ Agent จะแต่งให้เอง:

สร้าง Header, Footer และ hook รวมเส้นทางของแอป แล้วเติมสองตัวแรกเข้า MainLayout

บริบท: @src/app/layouts/MainLayout @src/shared/components @src/shared/hooks @src/styles
ติดตั้ง Font Awesome ครบทั้งห้า package ไว้แล้ว
MainLayout ตอนนี้ render แค่ Outlet ในแท็ก main ยังไม่มี Header, Footer และยังไม่มีไฟล์ .module.scss
src/shared/hooks/ ยังเป็นโฟลเดอร์ว่าง ส่วน src/shared/components/ มีแค่ ErrorMessage จากบทที่แล้ว
utility class ทุกตัวที่งานนี้ใช้มีอยู่จริงใน src/styles/ แล้ว: container, flex, space-between,
align-item-center, gap-20, list-none, nav-link, m-0, p-0, mr-10, mb-10, mb-20, mb-25,
fw-bold, fs-14, fs-24, fs-32, pt-25, pb-25, pt-60, pb-60
ตัวแปรสีอยู่ใน src/styles/_variables.scss เช่น $black02 และ $white
alias @/ ใช้ได้เฉพาะไฟล์ .ts และ .tsx ส่วนไฟล์ .scss ต้องอ้าง path แบบ relative

โครงสร้าง: สร้างไฟล์ตามนี้ ไม่มากไม่น้อยกว่านี้
- src/shared/hooks/useProductRoute.tsx
- src/shared/components/Header/Header.tsx
- src/shared/components/Footer/Footer.tsx
- src/shared/components/Footer/Footer.module.scss
- src/app/layouts/MainLayout/MainLayout.module.scss
และแก้ src/app/layouts/MainLayout/MainLayout.tsx ให้เติม Header กับ Footer เข้าไป

ข้อกำหนดทางเทคนิค:
- useProductRoute: default export ชื่อ useProductRoute ที่เรียก useNavigate จาก "react-router"
  คืน object ที่มีสี่ฟังก์ชัน:
    goToProductDetails(id: number) -> /products/{id}
    goToCartSummary()              -> /cart
    goToCheckout()                 -> /checkout
    goToOrderSuccess()             -> /order/success
  บทนี้ยังไม่มีใครเรียกใช้ hook นี้ สร้างไว้เฉย ๆ ห้ามไปเสียบใน Header
- Header: default export ไม่รับ prop
  โครงคือ header className="pt-25 pb-25" > div className="container"
  > div className="flex space-between align-item-center"
  ซ้าย: Link to="/" className="nav-link fw-bold fs-24" ข้อความ My Store
  ขวา: แท็ก nav ครอบ ul className="flex gap-20 m-0 p-0 list-none" มีสอง li
    Link to="/" className="nav-link" ข้อความ Home
    Link to="/categories" className="nav-link" ข้อความ Products
  ลิงก์ทุกจุดใช้ Link จาก "react-router" ห้ามใช้แท็ก a และห้ามใช้ div ที่มี onClick
- Footer.module.scss: ขึ้นต้นด้วย @use "../../../styles/variables";
  แล้วประกาศ class .footer ที่มี background-color: variables.$black02
  color: variables.$white และ nested rule ให้แท็ก p มี line-height: 2
- Footer: default export ที่ import styles from "./Footer.module.scss"
  แท็กนอกสุดคือ footer className={`pt-60 pb-60 ${styles.footer}`} ครอบ div className="container"
  ครอบ div className="flex space-between" ที่มีสามคอลัมน์เรียงตามนี้:
  1) h2 className="fs-32 fw-bold text-white mb-25" ข้อความ My Store
     ตามด้วยสาม div ที่ขึ้นต้นด้วย FontAwesomeIcon className="mr-10" แล้วตามด้วยข้อความ:
       faMapMarkerAlt + "Bangkok Thailand 10150"      (div className="fs-14 mb-20")
       faPhone        + "Call Us: 123-456-7898"        (div className="fs-14 mb-20")
       faEnvelope     + "Email Us: admin@mystore.com"  (div className="fs-14")
     ไอคอนทั้งสามตัว import จาก "@fortawesome/free-solid-svg-icons"
  2) h3 className="fs-24 fw-bold text-white mb-25" ข้อความ Categories
     ตามด้วย ul className="list-none p-0 m-0" ที่มี li className="mb-10" ห้ารายการ:
     Beauty, Fragrances, Furniture, Groceries, Laptops
  3) h3 className="fs-24 fw-bold text-white mb-25" ข้อความ Pages
     ตามด้วย ul className="list-none p-0 m-0" ที่มี li className="mb-10" สามรายการ:
     Home, Products, Cart
  รายการในสองคอลัมน์หลังเป็นข้อความเปล่า ยังไม่ต้องทำเป็นลิงก์
- MainLayout.module.scss: class .container เป็น flex column ที่ min-height: 100vh
  และ class .main ที่ flex-grow: 1
- MainLayout.tsx: div className={styles.container} ครอบ Header, แท็ก main className={styles.main}
  ที่มี Outlet อยู่ข้างใน และ Footer เรียงตามลำดับนี้
  import Header กับ Footer ด้วย alias @/

ขอบเขต:
- ห้ามติดตั้ง dependency ใหม่
- ยังไม่ต้องทำไอคอนตะกร้า badge จำนวนสินค้า หรือ CartSummary ใด ๆ ใน Header
- ห้ามสร้าง Header.module.scss
- ห้ามแก้ router.tsx, App.tsx, main.tsx และไฟล์ใน src/pages/

สังเกตบรรทัดในส่วน บริบท: ที่ไล่ชื่อ utility class ทั้งหมดออกมา — มันดูเยิ่นเย้อ แต่นี่คือบรรทัดที่กันปัญหาที่บทเรียน 08 เตือนไว้: ชื่อ class ของเราหน้าตาคล้าย Tailwind มาก ถ้าไม่ยืนยันว่ามีตัวไหนอยู่จริงบ้าง Agent จะแต่ง text-gray-400 หรือ py-6 ขึ้นมาเอง แล้วหน้าเว็บจะขึ้นตามปกติโดยไม่มี style และไม่มีเครื่องมือตัวไหนบ่น

  • AI มักพลาดตรงนี้: การนำทาง — สองอาการที่เจอบ่อยคือเขียนลิงก์เป็น <a href="/categories"> หรือ <div onClick={() => navigate("/cart")}> แทนที่จะใช้ <Link to> ค้นในไฟล์ที่ได้มาด้วยคำว่า href= และ onClick เป็นอย่างแรก — ทั้งสองคำนี้ไม่ควรเจอเลยสักจุดในบทนี้ เพราะ Link ใช้ prop ชื่อ to — ทั้งสองแบบดูเหมือนใช้ได้บนจอ แต่แบบ <a> โหลดหน้าใหม่ทั้งแอปทุกครั้งที่กด และแบบ <div> กดด้วยคีย์บอร์ดไม่ได้เลย
  • ไฟล์ใหม่ 5 ไฟล์ ไฟล์ที่ถูกแก้ 1 ไฟล์ (MainLayout.tsx) — ไม่มีอย่างอื่นใน git status
  • ไม่มี Header.module.scss เกิดขึ้น (กติกาในไฟล์ rules บอกให้สร้าง แต่ prompt ยกเว้นไว้)
  • Header ไม่มีไอคอนตะกร้า ไม่มี badge และไม่มีบรรทัด useProductRoute() ค้างอยู่
  • Footer.module.scss ขึ้นต้นด้วย @use "../../../styles/variables"; และใช้ variables.$black02 ไม่ใช่ #212121
  • ไม่มีค่าสีแบบ hex โผล่ในไฟล์ .tsx หรือ .module.scss ที่สร้างใหม่เลยสักจุด
  • Footer import ไอคอนเป็นราย ๆ ตัวจาก @fortawesome/free-solid-svg-icons ไม่ใช่ import ทั้งชุด
  • ข้อความใน Footer ตรงกับ prompt ทุกตัวอักษร — เบอร์โทร อีเมล ที่อยู่ และรายชื่อหมวดหมู่ห้ารายการ
  • ไม่มี comment แบบ {/* Company Info Section */} คั่นแต่ละคอลัมน์ใน Footer — comment ที่บอกสิ่งที่โค้ดบอกอยู่แล้วผิดกติกาในไฟล์ rules ตั้งแต่บทเรียน 07 นี่ไม่ใช่เรื่องรสนิยม แต่เป็นข้อที่เขียนห้ามไว้แล้ว
  • ค้นทุกชื่อ class ที่โผล่ใน className ของไฟล์ใหม่ ว่ามีอยู่จริงใน src/styles/ ครบทุกตัวไหม (grep -rn "ชื่อ-class" src/styles/) — class ที่ไม่มีนิยามอยู่ที่ไหนเลยจะเงียบสนิท ไม่ error ไม่ warn และไม่ทำอะไรทั้งนั้น
  • MainLayout.tsx เรียงเป็น Header → <main> ที่มี Outlet → Footer และ <Outlet /> ยังอยู่ในแท็ก main ไม่ได้ถูกย้ายออกมา
  • MainLayout.module.scss มีทั้ง .container และ .main และ .main มี flex-grow: 1 จริง (ถ้าขาดข้อนี้ Footer จะลอยขึ้นมากลางจอในหน้าที่เนื้อหาสั้น)
  • import ข้ามโฟลเดอร์ในไฟล์ .tsx ใช้ @/ แต่ @use ในไฟล์ .scss เป็น path แบบ relative — สองระบบนี้คนละเรื่องกัน
  • useProductRoute มีครบสี่ฟังก์ชัน และ goToProductDetails รับ id: number ไม่ใช่ string หรือ any

รอบนี้ก็เหมือนบทที่แล้ว: npm run lint อาจตกเรื่อง import-x/order ก่อน แก้ด้วย npx eslint . --fix แล้วรันซ้ำให้ผ่านเงียบ ๆ จากนั้นค่อย npm run typecheck

โค้ดอ้างอิง

src/shared/hooks/useProductRoute.tsx:

import { useNavigate } from "react-router";

const useProductRoute = () => {
  const navigate = useNavigate();

  const goToProductDetails = (id: number) => {
    navigate(`/products/${id}`);
  };

  const goToCartSummary = () => {
    navigate("/cart");
  };

  const goToCheckout = () => {
    navigate("/checkout");
  };

  const goToOrderSuccess = () => {
    navigate("/order/success");
  };

  return {
    goToProductDetails,
    goToCartSummary,
    goToCheckout,
    goToOrderSuccess,
  };
};

export default useProductRoute;

src/shared/components/Footer/Footer.module.scss:

@use "../../../styles/variables";

.footer {
  background-color: variables.$black02;
  color: variables.$white;

  p {
    line-height: 2;
  }
}

บรรทัด @use ดึงไฟล์ _variables.scss จากบทเรียน 04 เข้ามาภายใต้ namespace ชื่อ variables เราจึงอ้างสีกลางของแอปได้ด้วย variables.$black02 แทนการ hardcode #212121 ซ้ำอีกรอบ — สีหลักของแบรนด์เปลี่ยนเมื่อไหร่ Footer ก็เปลี่ยนตามเองโดยไม่ต้องแตะไฟล์นี้

ไฟล์เล็ก ๆ ไฟล์นี้มีของแถมสองอย่างที่คุ้มกับการหยุดดู เพราะทั้งสองอย่างคือหน้าตาของโค้ดจริงที่คุณจะต้องตรวจในงาน:

  • p { line-height: 2; } ตอนนี้ยังไม่มีผลกับอะไรเลย — เปิด Footer.tsx ดูจะพบว่ามันไม่ได้ render แท็ก p สักตัว (ข้อความทุกก้อนอยู่ใน div กับ li) กฎนี้มีอยู่ในโค้ดต้นฉบับของโปรเจกต์จริง เราคงไว้ตรง ๆ ไม่ตัดออก แต่ต้องรู้ว่ามันเป็นกฎที่รออยู่เฉย ๆ ไม่ใช่กฎที่ทำงานอยู่
  • text-white ใน Footer.tsx ไม่มีนิยามอยู่ที่ไหนเลย — ลอง grep -rn "text-white" src/styles/ ดู จะไม่เจออะไร ตัวอักษรใน Footer เป็นสีขาวเพราะบรรทัด color: variables.$white; ใน .footer ต่างหาก ไม่ใช่เพราะ class นั้น นี่คือ class ที่หลงเหลือมาจากโค้ดเดิม และมันคือพฤติกรรมที่ต้องจำ: class ที่ไม่มีนิยามจะไม่ทำอะไรเลยแบบเงียบสนิท ไม่มี error ไม่มี warning ไม่มีเส้นแดง — ต่างจากตัวแปรที่พิมพ์ผิดซึ่งพังทันที นี่คือเหตุผลที่ checklist ข้างบนบังคับให้ค้นชื่อ class ทุกตัวใน src/styles/ ด้วยตาตัวเอง

ไฟล์นี้สาธิตวิธีใช้ Font Awesome ครบวงจร: import ตัว component FontAwesomeIcon หนึ่งครั้ง, import ไอคอนที่ต้องการเป็นราย ๆ ตัวจากชุด solid, แล้ววางใน JSX ด้วย <FontAwesomeIcon icon={faPhone} /> — ตัวมัน render ออกมาเป็น SVG จึงคมทุกขนาด และรับ className ได้เหมือน element ปกติ (เราใช้ mr-10 ดันข้อความให้ห่างจากไอคอน)

สังเกตการผสม class สองระบบบนบรรทัด <footer>: `pt-60 pb-60 ${styles.footer}` — utility class จากระบบ global อยู่ร่วมกับ class จาก SCSS Module ได้สบาย ๆ ผ่าน template literal นี่คือ pattern ที่จะเห็นตลอดทั้งโปรเจกต์: ของทั่วไปใช้ utility ของเฉพาะตัวใช้ module

นี่แหละคือผลตอบแทนของการลงทุนทำ layout route ในบทที่แล้ว: เพิ่มโค้ดสี่บรรทัดในไฟล์เดียว แล้วทั้งหกหน้าได้ Header กับ Footer พร้อมกันทันที ไม่ต้องไปตามแปะทีละหน้า และเมื่อผู้ใช้เปลี่ยนหน้า react-router สลับเฉพาะส่วน <Outlet /> ตรงกลาง — Header กับ Footer ไม่ถูก render ใหม่โดยไม่จำเป็น

🤔 อธิบายให้ได้

  1. <Link to="/"> render ออกมาเป็นแท็ก <a> ใน DOM เหมือน <a href="/"> ทุกประการ — เปิด DevTools แล้วบอกวิธีพิสูจน์ตอนรันจริงว่าอันไหนเป็นอันไหน โดยไม่เปิดดูซอร์สโค้ด
  2. MainLayout.module.scss มี class ชื่อ .container และ src/styles/ ก็มี utility class ชื่อ container ที่ Header กับ Footer ใช้อยู่ — สองตัวนี้ชนกันหรือไม่ ตอบจากสิ่งที่เกิดขึ้นกับชื่อ class ตอน build
  3. useProductRoute จบบทนี้ยังไม่มีใครเรียกใช้ แต่ npm run lint ผ่านสบาย ๆ ในขณะที่ถ้าเราเขียน const { goToCartSummary } = useProductRoute(); ค้างไว้ใน Header มันจะฟ้องทันที — สองกรณีนี้ต่างกันตรงไหนในสายตาของ ESLint
💡 Checkpoint: รัน npm run dev แล้วไล่เปิดทุก route จากบทที่แล้ว — ทุกหน้าต้องมี Header (โลโก้ My Store + เมนู Home/Products) อยู่บนสุด และ Footer พื้นดำอยู่ล่างสุดติดขอบจอเสมอแม้เนื้อหากลางจะสั้นนิดเดียว (ฝีมือ sticky footer) จากนั้นลองคลิกสลับเมนู Home กับ Products ไปมา — หน้าต้องเปลี่ยนโดยจอไม่กะพริบและไม่มีการโหลดหน้าใหม่ ถ้าไม่แน่ใจ เปิด Network tab ของ DevTools ดู: คลิก Link แล้วต้องไม่มี request ของ document ใหม่โผล่มา สุดท้ายรัน npm run lint และ npm run typecheck ให้ผ่านทั้งคู่ก่อน commit — ถ้าข้อ "อธิบายให้ได้" ยังตอบไม่ได้ อย่าเพิ่งไปบทถัดไป
