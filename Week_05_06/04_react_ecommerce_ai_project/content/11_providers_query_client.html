Providers และ QueryClient

Providers & QueryClient

บทนี้เป็นชิ้นสุดท้ายของโครงแอป: วางระบบจัดการข้อมูลจาก server ให้พร้อมใช้ทั่วทั้งแอป ก่อนลงมือ ทวนแนวคิดสำคัญจากคอร์ส React พื้นฐาน กันหนึ่งย่อหน้า — state ในแอปเรามีสองพันธุ์ที่ต้องจัดการคนละวิธี:

  • Server state — ข้อมูลที่เจ้าของตัวจริงอยู่บน server เช่น รายการสินค้า ราคา รีวิว เราเป็นแค่ผู้ยืมมาแสดง มันเลยมีปัญหาเฉพาะตัว: ต้องโหลด อาจโหลดพลาด อาจหมดอายุ ต้อง cache — ทั้งหมดนี้คือหน้าที่ของ TanStack Query
  • Client state — ข้อมูลที่เกิดและจบในเบราว์เซอร์ เช่น ของในตะกร้า modal เปิดอยู่ไหม — อันนี้เป็นหน้าที่ของ React เอง (ในโปรเจกต์นี้คือ Context + useReducer ซึ่งจะสร้างกันในบทเรียน 22)

บทเรียนราคาแพงข้อหนึ่งของมือใหม่คือการเอา useEffect + useState ไปจัดการ server state เอง — ได้โค้ดที่ไม่มี cache, โหลดซ้ำซ้อน และ race condition เพียบ เราจะไม่ทำแบบนั้นแม้แต่บรรทัดเดียวในโปรเจกต์นี้ และไฟล์ rules ของเราก็เขียนห้ามไว้ตั้งแต่บทเรียน 07 แล้ว

QueryClient: cache หนึ่งก้อนต่อหนึ่งแอป

ทุกอย่างใน TanStack Query หมุนรอบ object ตัวเดียวชื่อ QueryClient — มันคือทั้งตัว cache และศูนย์ตั้งค่าพฤติกรรมของทุก query ในแอป ค่า default สองตัวที่เราจะตั้ง คือการตัดสินใจที่คิดมาแล้วสำหรับแอปแบบนี้โดยเฉพาะ:

  • staleTime: 60 * 1000 — ข้อมูลที่โหลดมาแล้วถือว่า "ยังสด" อยู่ 60 วินาที ระหว่างนั้นถ้า component ไหนขอข้อมูลก้อนเดิม TanStack Query จะส่งของจาก cache ให้ทันทีโดยไม่ยิง API ซ้ำ (ค่า default ของ library คือ 0 — สลับหน้าไปมาทีเดียวยิงใหม่ทุกครั้ง) ข้อมูลสินค้าของเราไม่ได้เปลี่ยนวินาทีต่อวินาที หนึ่งนาทีจึงเป็นจุดสมดุลที่ดีระหว่างความสดกับจำนวน request — เขียน 60 * 1000 แทน 60000 เพื่อให้อ่านออกทันทีว่าหน่วยคือ "60 วินาที คูณเป็น milliseconds"
  • retry: 1 — query ที่ล้มเหลวจะถูกลองใหม่อีก 1 ครั้งก่อนประกาศว่า error จริง (default คือ 3 ครั้งพร้อม delay ที่เพิ่มขึ้นเรื่อย ๆ ซึ่งแปลว่าผู้ใช้ต้องจ้องหน้า loading นานหลายวินาทีกว่าจะเห็นข้อความ error) ลองหนึ่งครั้งพอกันเหตุ network สะดุดชั่วขณะ แต่ถ้าพังจริงก็บอกผู้ใช้ให้เร็ว

เรื่องที่สำคัญกว่าค่าทั้งสองคือตำแหน่งที่สร้างมัน: client ต้องถูกสร้างไว้นอก component ที่ระดับ module ไฟล์จะถูกประมวลผลครั้งเดียวตอนแอปเริ่ม เราจึงได้ singleton: cache หนึ่งก้อนต่อหนึ่งแอปตลอดอายุของมัน ถ้าเผลอไปเขียน new QueryClient() ข้างในตัว component จะได้ client ตัวใหม่ (cache เปล่า ๆ) ทุกครั้งที่ component นั้นถูก render ใหม่ — เท่ากับ cache ที่ลืมทุกอย่างตลอดเวลา

อีกเหตุผลที่แยกเป็นไฟล์ของตัวเอง: ตอนวางชุดทดสอบในบทเรียน 30 เราจะสร้าง client คนละตัวสำหรับเทสต์โดยเฉพาะ การที่ "ตัว client" กับ "ตัว provider" แยกจากกันทำให้สลับได้ง่าย

providers.tsx: รวมทุก provider ไว้ประตูเดียว

แอปจริงมักมี provider หลายตัวซ้อนกันเป็นหัวหอม: query client, theme, auth, cart ฯลฯ ถ้าซ้อนกันสด ๆ ใน App.tsx ไฟล์นั้นจะรกขึ้นเรื่อย ๆ ทุกครั้งที่มีของใหม่ pattern ที่โปรเจกต์นี้ใช้คือสร้าง component AppProviders ที่เดียวจบ — ใครอยากรู้ว่าแอปนี้มี provider อะไรบ้าง ลำดับไหน เปิดไฟล์เดียวเห็นครบ

  • children: ReactNode — pattern เดียวกับที่เรียนในคอร์ส React พื้นฐาน: component ที่รับ "อะไรก็ได้ที่ render ได้" มาห่อ ทำให้ AppProviders ไม่ต้องรู้จักเนื้อในของแอปแม้แต่นิดเดียว
  • QueryClientProvider — ส่ง queryClient ของเราลงไปผ่าน context ให้ทุก component ใต้ต้นไม้เรียกใช้ useQuery ได้ ตัว client อยู่ไฟล์หนึ่ง ตัว provider อยู่อีกไฟล์ — แยกหน้าที่ "สร้างของ" กับ "แจกของ" ออกจากกัน
  • import.meta.env.DEV — ตัวแปรพิเศษที่ Vite แทนค่าให้ตอน build: ระหว่าง npm run dev มันคือ true แต่ใน production build มันคือ false ทั้งบรรทัดจึงกลายเป็น dead code ที่ถูกตัดทิ้งจาก bundle ไปเลย — Devtools จึงไม่มีทางหลุดไปถึงหน้าจอผู้ใช้จริงแม้แต่ byte เดียว สอดคล้องกับที่เราติดตั้งมันเป็น devDependency
  • initialIsOpen={false} — ให้ Devtools เริ่มแบบหุบอยู่ เหลือแค่ปุ่มลอยเล็ก ๆ ไว้กดเปิดเมื่ออยากดู
💡 providers.tsx ที่ได้จากบทนี้เป็นเวอร์ชันแรก — ในบทเรียน 22 เมื่อเราสร้างระบบตะกร้าสินค้าเสร็จ จะมี <CartProvider> เข้ามาห่อ {children} เพิ่มอีกหนึ่งชั้นตรงนี้ อย่าเพิ่งสร้างในบทนี้ — และนั่นแหละคือจุดขายของ pattern นี้: วันนั้นเราจะแก้แค่ไฟล์นี้ไฟล์เดียว App.tsx ไม่ต้องรู้เรื่องเลย

ลำดับการห่อใน App.tsx

สุดท้ายคือการเอา AppProviders ไปห่อ RouterProvider ใน App.tsx — และหลังบทนี้ไฟล์นั้นจะไม่เปลี่ยนอีกเลยตลอดคอร์ส อ่านจากนอกเข้าใน: providers ห่อ router, router เลือกหน้า, หน้าถูกวางใน layout — สามบรรทัดนี้เล่าโครงสร้างทั้งแอปจบ

การที่ providers อยู่นอก RouterProvider สำคัญนะ: มันแปลว่าทุกหน้า ทุก layout รวมถึง RouteErrorFallback ล้วนอยู่ใต้ QueryClientProvider และใช้ query ได้หมด ไม่มีมุมอับ

เป้าหมายของบทนี้

src/
└── app/
    ├── App.tsx          # แก้ — ให้ AppProviders ห่อ RouterProvider
    ├── providers.tsx    # ใหม่ — เวอร์ชันแรก มีแค่ QueryClientProvider
    └── queryClient.ts   # ใหม่ — singleton ที่ระดับ module
  • queryClient.ts — ต้องสร้าง QueryClient ที่ระดับ module และ export ชื่อ queryClient ต้องไม่มี JSX ในไฟล์ (นามสกุลจึงเป็น .ts ไม่ใช่ .tsx)
  • providers.tsx — ต้อง export ชื่อ AppProviders แบบ named export และ Devtools ต้องอยู่ใต้เงื่อนไข import.meta.env.DEV ต้องไม่มีคำว่า new QueryClient อยู่ในไฟล์นี้เลย
  • App.tsx — ต้องยังใช้ router ตัวเดิมจาก ./router และยัง import RouterProvider จาก react-router/dom ต้องไม่มีอะไรอื่นเพิ่มเข้ามาในไฟล์นี้

ติดตั้ง TanStack Query ด้วยมือ

ตัว library หลักเป็น dependency ปกติ ส่วน Devtools ติดตั้งเป็น -D (devDependency) เพราะเป็นเครื่องมือของนักพัฒนา ไม่ใช่ของที่ผู้ใช้จริงต้องได้รับ — สังเกตว่าเราเป็นคนตัดสินใจเรื่องนี้เอง ไม่ได้ปล่อยให้ Agent เลือกให้:

npm install @tanstack/react-query
npm install -D @tanstack/react-query-devtools
git add -A && git commit -m "chore: install tanstack query"

ตั้งค่า TanStack Query: สร้าง queryClient กับ AppProviders แล้วเอาไปห่อ RouterProvider ใน App.tsx

บริบท: @src/app/App.tsx @src/app/router.tsx @src/app
ติดตั้ง @tanstack/react-query และ @tanstack/react-query-devtools (ตัวหลังเป็น devDependency) ไว้แล้ว
src/app/App.tsx ตอนนี้ return RouterProvider พร้อม prop router={router} เท่านั้น
โปรเจกต์นี้เป็น Vite ใช้ import.meta.env.DEV ได้เลย

โครงสร้าง: สร้างไฟล์ตามนี้ ไม่มากไม่น้อยกว่านี้
- src/app/queryClient.ts
- src/app/providers.tsx
และแก้ src/app/App.tsx ให้ AppProviders ห่อ RouterProvider

ข้อกำหนดทางเทคนิค:
- queryClient.ts: export const queryClient = new QueryClient({ ... }) ที่ระดับ module
  สร้างนอก component เท่านั้น ห้ามสร้างข้างใน function หรือใน useState/useMemo
  defaultOptions.queries ตั้งสองค่า: staleTime: 60 * 1000 และ retry: 1
  เขียน 60 * 1000 แบบนี้ ไม่ต้องแปลงเป็น 60000
  ไฟล์นี้เป็น .ts ไม่มี JSX
- providers.tsx: export function AppProviders (named export ไม่ใช่ default)
  รับ prop children: ReactNode โดย import ReactNode จาก "react"
  return QueryClientProvider ที่มี prop client={queryClient} ครอบ {children}
  ถัดจาก {children} ให้ render ReactQueryDevtools initialIsOpen={false}
  ภายใต้เงื่อนไข import.meta.env.DEV (ห้ามใช้ process.env.NODE_ENV)
  import queryClient จาก "./queryClient"
- App.tsx: ให้ AppProviders ครอบ RouterProvider
  RouterProvider ยัง import จาก "react-router/dom" และยังใช้ router ตัวเดิมจาก "./router"
  ห้ามเปลี่ยนชื่อ export หรือย้ายไฟล์ใด ๆ

ขอบเขต:
- ห้ามติดตั้ง dependency ใหม่
- ยังไม่ต้องสร้าง CartProvider, ThemeProvider หรือ provider อื่นใด
- ยังไม่ต้องเขียน useQuery, queryOptions หรือฟังก์ชันเรียก API ใด ๆ
- ห้ามสร้างไฟล์ .module.scss
- ห้ามแก้ไฟล์อื่นนอกจากที่ระบุไว้ข้างบน

สังเกตบรรทัด "ห้ามสร้างข้างใน function หรือใน useState/useMemo" — ปกติเราไม่เขียนข้อห้ามละเอียดขนาดนี้ แต่จุดนี้ต่างออกไป เพราะเอกสารทางการของ TanStack Query เองก็มีตัวอย่างที่สร้าง client ใน useState (สำหรับแอปแบบ server-rendering ที่หนึ่ง request ต้องได้ cache ของตัวเอง) โมเดลจึงเห็น pattern นั้นมาเยอะ ทั้งที่แอปของเราเป็น SPA ล้วน ๆ ที่ต้องการ cache ก้อนเดียว

✅ ตรวจโค้ดที่ AI สร้าง

✅ ตรวจโค้ดที่ AI สร้าง — git diff ก่อน แล้วไล่ทีละข้อ:

  • AI มักพลาดตรงนี้: สร้าง QueryClient ไว้ในตัว component — function AppProviders(...) { const queryClient = new QueryClient(); ... } ผลคือได้ client ตัวใหม่ทุกครั้งที่ component ถูก render ใหม่ cache ทั้งก้อนถูกโยนทิ้งแล้วยิง API ใหม่หมด วิธีตรวจตรงที่สุด: ค้นคำว่า new QueryClient ในโปรเจกต์ ต้องเจอที่เดียวคือ src/app/queryClient.ts และบรรทัดนั้นต้องไม่มีการเว้นวรรคย่อหน้า (indent) ใด ๆ ข้างหน้า เพราะมันอยู่ระดับบนสุดของไฟล์ — อาการนี้ในวันนี้ lint ผ่าน typecheck ผ่าน หน้าเว็บขึ้นปกติ และยังไม่มี query สักตัวให้เห็นผล มันจะไปโผล่เป็น "ทำไมโหลดสินค้าใหม่ทุกครั้งที่กดเข้าออกหน้า" ในบทเรียน 19 (กฎที่จับเรื่องนี้ได้มีอยู่จริง ชื่อ @tanstack/query/stable-query-client แต่มันมากับ @tanstack/eslint-plugin-query ที่เราจะต่อเข้า config ในบทเรียน 17 วันนี้จึงยังไม่มีอะไรมาช่วยคุณ) และมีญาติอีกตัวที่ต้องแยกให้ออก คือ useState(() => new QueryClient()) — แบบนี้ไม่ได้ทำให้ cache หาย เพราะ useState เรียก initializer ครั้งเดียวตอน mount และมันผ่านทั้ง lint และ typecheck ตลอดไป ไม่ใช่แค่วันนี้ เหตุผลที่เราไม่เอาจึงเป็นคนละเรื่องกัน: โปรเจกต์นี้ตกลงว่ามี client ตัวเดียวและอยู่ใน queryClient.ts เพราะไฟล์นั้นคือที่ตั้งค่า staleTime กับ retry ของทั้งแอป
  • ไฟล์ใหม่ 2 ไฟล์ ไฟล์ที่ถูกแก้ 1 ไฟล์ ไม่มีอย่างอื่นใน git status
  • queryClient.ts ลงท้ายด้วย .ts จริง ไม่ใช่ .tsx และไม่มี JSX อยู่ในนั้น
  • staleTime เขียนเป็น 60 * 1000 และ retry เป็น 1 — ไม่ใช่ค่าอื่นที่มันคิดว่า "ดีกว่า"
  • providers.tsx export ชื่อ AppProviders แบบ named export — ถ้ากลายเป็น export default บรรทัด import ใน App.tsx จะต่างจากที่บทหลัง ๆ อ้างถึง
  • เงื่อนไขของ Devtools ใช้ import.meta.env.DEV ไม่ใช่ process.env.NODE_ENV === "development" (ตัวหลังไม่มีอยู่จริงในเบราว์เซอร์ฝั่ง Vite)
  • <ReactQueryDevtools /> อยู่ข้างใน QueryClientProvider ไม่ใช่ข้างนอก — ถ้าอยู่นอก มันจะหา client ไม่เจอ
  • package.json ไม่ถูกแก้: @tanstack/react-query-devtools ยังอยู่ใน devDependencies ไม่ถูกย้ายขึ้นไป dependencies
  • App.tsx ยัง import RouterProvider จาก "react-router/dom" และ AppProviders อยู่นอก RouterProvider ไม่ใช่ข้างใน
  • ไม่มี useEffect, ไม่มี fetch, ไม่มี useQuery โผล่มาในสามไฟล์นี้

โค้ดอ้างอิง

src/app/queryClient.ts:

import { QueryClient } from "@tanstack/react-query";

export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 60 * 1000,
      retry: 1,
    },
  },
});

src/app/providers.tsx เวอร์ชันแรก:

import { ReactNode } from "react";
import { QueryClientProvider } from "@tanstack/react-query";
import { ReactQueryDevtools } from "@tanstack/react-query-devtools";
import { queryClient } from "./queryClient";

export function AppProviders({ children }: { children: ReactNode }) {
  return (
    <QueryClientProvider client={queryClient}>
      {children}
      {import.meta.env.DEV && <ReactQueryDevtools initialIsOpen={false} />}
    </QueryClientProvider>
  );
}

และ src/app/App.tsx ฉบับสมบูรณ์ — ไฟล์นี้จะไม่เปลี่ยนอีกแล้วตลอดทั้งคอร์ส:

import { RouterProvider } from "react-router/dom";
import { AppProviders } from "./providers";
import { router } from "./router";

function App() {
  return (
    <AppProviders>
      <RouterProvider router={router} />
    </AppProviders>
  );
}

export default App;

  2. บรรทัด {import.meta.env.DEV && <ReactQueryDevtools ... />} ยังอยู่ในซอร์สโค้ดตอน build production — แล้วทำไม Devtools ถึงไม่ติดไปกับ bundle ที่ผู้ใช้โหลด อธิบายว่าอะไรเกิดขึ้นกับบรรทัดนี้ตอน npm run build
  3. เปิด App.tsx แล้วสมมติว่าเราสลับลำดับเป็น <RouterProvider> อยู่นอกและ <AppProviders> อยู่ใน — component ตัวไหนบ้างในแอปที่จะเรียก useQuery ไม่ได้อีกต่อไป
💡 Checkpoint: รัน npm run dev — แอปต้องขึ้นเหมือนเดิมทุกประการ (Header, Footer, หน้า stub ครบ) แต่มีของใหม่หนึ่งชิ้น: ปุ่มลอยของ TanStack Query Devtools ที่มุมล่างของจอ กดเปิดดูได้เลย ตอนนี้แผง queries ยังว่างเปล่าเพราะเรายังไม่ได้เขียน query สักตัว (ตัวแรกจะมาในบทเรียน 17) ปิดท้ายด้วย npm run lint, npm run typecheck และ npm run build ให้ผ่านทั้งหมด — ถ้า build ผ่าน แปลว่าโครงแอปทั้งสามบทของช่วงนี้ประกอบกันสนิทดีแล้ว จากนั้น commit — ถ้าข้อ "อธิบายให้ได้" ยังตอบไม่ได้ อย่าเพิ่งไปบทถัดไป
ก่อนหน้า: Header และ Footer สารบัญบทเรียน ถัดไป: Button, Input และ RadioInput
