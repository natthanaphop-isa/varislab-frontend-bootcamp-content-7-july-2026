บทเรียน 02 · ติดตั้งโปรเจกต์ (Project Setup)

สร้างโปรเจกต์ด้วย Vite

Project Scaffold

ถึงเวลาลงมือแล้ว ในบทนี้เราจะเริ่มจากโฟลเดอร์ว่าง ๆ ไปจนถึง dev server ที่รันได้จริง: เตรียม Node ให้ถูกเวอร์ชัน สร้างโปรเจกต์ด้วย Vite เดินสำรวจว่า Vite สร้างอะไรให้บ้าง แล้วเก็บกวาด boilerplate ที่เราไม่ใช้ออก เพื่อให้บทถัด ๆ ไปเริ่มจากพื้นที่สะอาด

เตรียม Node.js ด้วย nvm

อย่างที่บอกไว้ในบทนำ react-router 8 กำหนด Node ขั้นต่ำไว้ที่ 22.22 วิธีจัดการเวอร์ชัน Node ที่สะดวกที่สุดคือ nvm (Node Version Manager) เพราะมันติดตั้ง Node ได้หลายเวอร์ชันพร้อมกันและสลับไปมาได้ตามโปรเจกต์ เปิด Terminal แล้วรัน:

nvm install 22
node -v

nvm install 22 จะติดตั้ง Node สาย 22 เวอร์ชันล่าสุดแล้วสลับมาใช้ให้ทันที ส่วน node -v คือการตรวจงาน — ผลลัพธ์ต้องขึ้นต้นด้วย v22 และตัวเลขต้องไม่ต่ำกว่า v22.22.0

💡 ถ้าเครื่องคุณยังไม่มี nvm ให้ติดตั้งก่อนตามคู่มือที่ github.com/nvm-sh/nvm (ผู้ใช้ Windows ให้ใช้ nvm-windows ซึ่งคำสั่งแทบเหมือนกัน) ติดตั้งเสร็จแล้วปิด-เปิด Terminal ใหม่หนึ่งรอบก่อนรันคำสั่งข้างบน

สร้างโปรเจกต์

cd ไปยังโฟลเดอร์ที่คุณเก็บโปรเจกต์ทั้งหลายไว้ แล้วรัน:

npm create vite@latest react-ecommerce-app -- --template react-ts

แกะคำสั่งนี้ทีละท่อน: npm create vite@latest คือการเรียกตัว scaffold ของ Vite เวอร์ชันล่าสุด, react-ecommerce-app คือชื่อโฟลเดอร์โปรเจกต์, เครื่องหมาย -- ตรงกลางบอก npm ว่า "ของที่เหลือหลังจากนี้ส่งต่อให้ create-vite นะ ไม่ใช่ของ npm เอง" และ --template react-ts เลือก template แบบ React + TypeScript ให้เลย ไม่ต้องตอบคำถามทีละข้อ

เสร็จแล้วเข้าไปในโปรเจกต์:

cd react-ecommerce-app

บันทึกเวอร์ชัน Node ไว้กับโปรเจกต์

ตอนนี้เครื่องคุณใช้ Node 22 อยู่ แต่เพื่อนร่วมทีม (หรือตัวคุณเองในอีกสามเดือน) จะรู้ได้อย่างไรว่าโปรเจกต์นี้ต้องใช้เวอร์ชันไหน? ธรรมเนียมของ nvm คือเก็บคำตอบไว้ในไฟล์ชื่อ .nvmrc ที่ root ของโปรเจกต์ สร้างไฟล์ .nvmrc โดยมีเนื้อหาแค่บรรทัดเดียว:

22

ต่อจากนี้ใครก็ตามที่ cd เข้ามาในโปรเจกต์แล้วรัน nvm use จะถูกสลับไปใช้ Node 22 ให้อัตโนมัติโดยไม่ต้องเดา — ไฟล์เล็ก ๆ ที่ประหยัดเวลา debug ปัญหา "ทำไมเครื่องฉันรันไม่ได้" ไปได้มหาศาล

สำรวจโครงที่ Vite สร้างให้

ก่อนจะแตะอะไร มาเดินดูก่อนว่า template react-ts ให้อะไรมาบ้าง:

react-ecommerce-app/
├── public/              # ไฟล์ static ที่เสิร์ฟตรง ๆ ไม่ผ่าน bundler (มี vite.svg)
├── src/
│   ├── assets/          # ไฟล์ static ที่ import ผ่านโค้ด (มี react.svg)
│   ├── App.css          # style ของหน้าตัวอย่าง — เดี๋ยวลบ
│   ├── App.tsx          # component ตัวอย่าง — เดี๋ยวเขียนใหม่
│   ├── index.css        # style ระดับหน้า — เดี๋ยวลบ
│   ├── main.tsx         # จุดเริ่มต้นของแอป (entry point)
│   └── vite-env.d.ts    # type ของ Vite เช่น import.meta.env
├── .gitignore
├── eslint.config.js     # ESLint จาก template — บทหน้าเราจะเขียนของเราเอง
├── index.html           # หน้า HTML เดียวของแอป
├── package.json
├── README.md
├── tsconfig.json        # ไฟล์แม่ที่ชี้ไปยัง tsconfig อีกสองไฟล์
├── tsconfig.app.json    # การตั้งค่า TypeScript ของโค้ดใน src/
├── tsconfig.node.json   # การตั้งค่า TypeScript ของไฟล์ config (เช่น vite.config.ts)
└── vite.config.ts       # การตั้งค่า Vite

จุดที่ควรเข้าใจให้ชัด:

  • index.html คือประตูหน้าแอป — เบราว์เซอร์โหลดไฟล์นี้ก่อน แล้วเจอ <script type="module" src="/src/main.tsx"> ซึ่งลากโค้ดทั้งแอปเข้ามา นี่คือเหตุผลที่แอปแบบนี้เรียกว่า SPA (Single-Page Application) — HTML มีหน้าเดียว ที่เหลือ React จัดการ
  • src/main.tsx — จับ React ยึดกับ <div id="root"> ใน index.html แล้ว render <App /> ครอบด้วย StrictMode แบบเดียวกับที่เจอในคอร์ส React พื้นฐาน
  • tsconfig สามไฟล์ — โค้ดในเบราว์เซอร์ (src/) กับโค้ดที่รันบน Node (ไฟล์ config) อยู่คนละสภาพแวดล้อม จึงแยกการตั้งค่ากันคนละไฟล์ โดยมี tsconfig.json เป็นแม่ที่อ้างถึงทั้งคู่ ไฟล์ที่เราจะแก้บ่อยคือ tsconfig.app.json

ติดตั้ง dependencies แล้วรัน

npm install
npm run dev

เปิดเบราว์เซอร์ไปที่ http://localhost:5173/ คุณควรเห็นหน้าตัวอย่างของ Vite — โลโก้หมุน ๆ กับปุ่ม counter ที่กดแล้วเลขเพิ่ม ถ้าเห็นแบบนี้แปลว่าทุกอย่างพร้อมแล้ว

เก็บกวาด boilerplate

หน้าโลโก้หมุนสวยดี แต่มันไม่ใช่แอปของเรา เราจะรื้อออกให้เหลือแต่โครงที่สะอาดที่สุด เริ่มจากลบไฟล์ CSS ตัวอย่างทั้งสองไฟล์:

rm src/App.css src/index.css

เหตุผลที่ลบทิ้งเลยไม่เก็บไว้แก้: ในบทที่ 04 เราจะสร้างระบบ SCSS ของเราเองทั้งชุด ตั้งแต่ design tokens ไปจนถึง utility classes การเริ่มจากศูนย์ง่ายกว่าการไล่ลบของเก่า ส่วนรูป public/vite.svg กับ src/assets/react.svg ปล่อยไว้ได้ ไม่เกะกะอะไร

ต่อมาเขียน src/App.tsx ใหม่ทั้งไฟล์ให้เหลือ placeholder เรียบ ๆ:

function App() {
  return <h1>React E-commerce App</h1>;
}

export default App;

แล้วแก้ src/main.tsx ให้เลิกอ้างถึง index.css ที่เราเพิ่งลบ ไฟล์ทั้งไฟล์จะเหลือแค่นี้:

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);

สังเกตว่าตอนนี้ main.tsx ไม่มีการ import ไฟล์ CSS เลยสักบรรทัด — เป็นสภาพชั่วคราวเท่านั้น ในบทที่ 04 บรรทัด import "./styles/main.scss"; จะเข้ามาแทนที่ index.css เดิม ระหว่างนี้หน้าเว็บของเราจะโล่ง ๆ ด้วย style ดั้งเดิมของเบราว์เซอร์ไปก่อน ซึ่งตั้งใจให้เป็นแบบนั้น

อีกอย่างที่ไม่ต้องทำ: title ใน index.html — โปรเจกต์ต้นฉบับคงค่า default Vite + React + TS ไว้ตามเดิม เราจะทำเหมือนกันเพื่อให้โค้ดตรงกับต้นฉบับทุกไฟล์ (ในโปรเจกต์จริงของคุณเอง เปลี่ยนได้ตามใจชอบแน่นอน)

💡 ตอนนี้ App.tsx อยู่ที่ src/App.tsx ตรง ๆ ซึ่งยังไม่ใช่ตำแหน่งสุดท้ายของมัน — ในบทที่ 09 เมื่อเราเริ่มวางโครงสถาปัตยกรรมจริง ไฟล์นี้จะย้ายเข้าไปอยู่ใน src/app/ ระหว่างนี้ปล่อยมันไว้ตรงนี้ก่อน

สร้างไฟล์ .env

แอปของเราดึงข้อมูลจาก dummyjson API และ URL ของ API แบบนี้ไม่ควรฝังตายอยู่ในโค้ด — มันคือ configuration ที่อาจต่างกันไปตามสภาพแวดล้อม (เครื่อง dev ชี้ไป mock server, production ชี้ไปของจริง เป็นต้น) ที่ทางมาตรฐานของมันคือไฟล์ .env สร้างไฟล์ .env ที่ root ของโปรเจกต์:

# Base URL for the API
VITE_API_BASE_URL=https://dummyjson.com

สองเรื่องต้องรู้เกี่ยวกับไฟล์นี้:

  • ทำไมต้องขึ้นต้นด้วย VITE_ — Vite จะส่งตัวแปรจาก .env เข้าไปในโค้ดฝั่งเบราว์เซอร์ (อ่านผ่าน import.meta.env.VITE_API_BASE_URL — เราจะใช้จริงในบทที่ 15) เฉพาะตัวที่ขึ้นต้นด้วย VITE_ เท่านั้น นี่คือกลไกความปลอดภัย: ตัวแปรอะไรก็ตามที่เข้าเบราว์เซอร์ได้แปลว่าผู้ใช้ทุกคนเปิดดูได้ การบังคับ prefix ทำให้คุณต้องตั้งใจเลือกว่าจะเปิดเผยอะไร ไม่ใช่หลุดไปทั้งไฟล์
  • ทำไม commit ไฟล์นี้ลง git ได้ — ปกติคุณอาจเคยได้ยินว่า "ห้าม commit .env!" ซึ่งจริงเมื่อในนั้นมี secret เช่น API key หรือรหัสผ่าน แต่ไฟล์ของเรามีแค่ URL สาธารณะที่ใครก็รู้ การ commit จึงปลอดภัยและช่วยให้เพื่อนร่วมทีม clone แล้วรันได้ทันที ถ้าวันหนึ่งมีค่าลับจริง ๆ ให้แยกไปไว้ใน .env.local ซึ่ง .gitignore ของ template กันไว้ให้แล้วผ่าน pattern *.local

ล็อกเวอร์ชัน Node ใน package.json

.nvmrc ช่วยคนที่ใช้ nvm แต่คนที่ไม่ได้ใช้ล่ะ? เราเพิ่มการประกาศ engines ลงใน package.json เป็นด่านที่สอง เปิดไฟล์แล้วเพิ่ม field นี้ (ตำแหน่งตามต้นฉบับคือถัดจาก "type"):

{
  "name": "react-ecommerce-app",
  "private": true,
  "version": "0.0.0",
  "type": "module",
  "engines": {
    "node": ">=22.22.0"
  },
  ...
}

(ส่วน scripts และ dependencies ที่เหลือคงไว้ตามเดิม) ต่อจากนี้ถ้าใครรัน npm install ด้วย Node ที่เก่ากว่า 22.22.0 npm จะเตือนทันทีว่าเวอร์ชันไม่ตรงตามที่โปรเจกต์ประกาศไว้ — ดีกว่าปล่อยให้ไปเจอ error ประหลาดตอนรันแล้วงมหาสาเหตุกันเป็นชั่วโมง

ปิดท้ายด้วยข้อสังเกตเรื่องวิธีทำงาน: บทนี้กับอีกสามบทถัดไปเราพิมพ์เองล้วน ๆ ไม่มี AI มาช่วยพิมพ์สักบรรทัด เพราะการตั้งค่าโปรเจกต์คือชุดการตัดสินใจ ไม่ใช่โค้ดที่ลอกแบบได้ และเราต้องมีโปรเจกต์ที่มีรูปทรงชัดเจนก่อน ถึงจะบอก AI ได้ว่าให้เขียนโค้ดแบบไหน

💡 Checkpoint: รัน npm run dev แล้วเปิด http://localhost:5173/ — คุณควรเห็นหัวข้อ React E-commerce App โดด ๆ บนพื้นขาว ฟอนต์เป็น default ของเบราว์เซอร์ ไม่มีอะไรสวยงามทั้งสิ้น และ console ต้องไม่มี error สีแดง ถ้าหน้ายังเป็นโลโก้หมุนอยู่แสดงว่า browser cache ค้าง ให้ refresh แรง ๆ หนึ่งที (Cmd+Shift+R หรือ Ctrl+Shift+R) หน้าโล่ง ๆ นี้คือผืนผ้าใบของเรา — บทหน้าเราจะติดอาวุธคุณภาพโค้ดให้มันก่อนเริ่มลงสี
