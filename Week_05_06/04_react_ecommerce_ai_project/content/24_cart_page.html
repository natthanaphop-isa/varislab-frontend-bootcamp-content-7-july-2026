บทเรียน 24 · ตะกร้าสินค้า (Cart)

หน้า Cart: ตาราง ยอดรวม และ empty state

Cart Page

ตอนนี้ผู้ใช้เพิ่มของเข้าตะกร้าได้ badge นับเลขได้ แต่พอคลิกไอคอนตะกร้าเข้ามาก็เจอหน้า stub ว่างเปล่าที่เราวางไว้ตั้งแต่บทเรียน 09 บทนี้เราจะเปลี่ยนมันเป็นหน้า Cart จริง: ตารางรายการสินค้า ปรับจำนวนได้ ลบได้ เห็นยอดรวม มี empty state เวลาตะกร้าว่าง และปุ่ม Checkout พาไปหน้าถัดไปของ flow งานมีสองชิ้น: component CartTable และตัวหน้า Cart.tsx

บทนี้จะส่ง promptรอบเดียว ต่างจากสามบทที่ผ่านมา — เกณฑ์จากบทเรียน 19 บอกว่าให้แบ่งเมื่อของที่ต้องตรวจเกินหนึ่งหน้าจอ และของนั้นแยกเป็นก้อนที่ทดสอบแยกกันได้ งานวันนี้ไม่เข้าทั้งสองข้อ: สองไฟล์ที่ผูกกันแน่นจนถ้าได้มาไฟล์เดียวก็ยังเปิดดูอะไรไม่ได้ และ diff ทั้งหมดสั้นพอที่จะอ่านจบในครั้งเดียว

CartTable — อ่านเอง แต่ให้พ่อเป็นคนแก้

คอมโพเนนต์นี้มีท่าที่แปลกกว่าทุกตัวที่เราเคยสร้างมา และมันคือประเด็นออกแบบหลักของบท: CartTable เรียก useCart() เพื่ออ่าน cart.items มาวาดตารางเองตรง ๆ แต่การแก้ไข (ลบ, ปรับจำนวน) กลับไม่เรียก store เอง — มันรับ onRemoveItem กับ onUpdateQuantity เป็น props แล้วโยนขึ้นไปให้หน้า Cart ตัดสินใจ

ทำไมต้องแยกครึ่ง ๆ แบบนี้ ทำไมไม่ให้มันเรียก removeFromCart เองไปเลยในเมื่อ useCart ก็คืนมาให้อยู่แล้ว? เพราะสองฝั่งนี้ตอบคำถามคนละข้อ ฝั่งอ่านตอบว่า "ตารางนี้แสดงอะไร" — คำตอบคือตะกร้า และไม่มีทางเป็นอย่างอื่นได้ การส่ง items ลงมาเป็น prop จึงเป็นแค่พิธีกรรม ส่วนฝั่งเขียนตอบว่า "ใครมีสิทธิ์แก้ตะกร้า" — คำตอบนี้ควรอ่านได้จากที่เดียว ถ้าวันหนึ่งคุณต้องหาว่าทำไมของหายจากตะกร้า คุณอยากเปิดไฟล์เดียว (Cart.tsx) แล้วเห็นทุกคำสั่งที่แก้ตะกร้าในหน้านี้ ไม่ใช่ต้องไล่เปิดคอมโพเนนต์ลูกทุกตัวเพื่อดูว่าใครแอบเรียกอะไร

ไล่ดูการตัดสินใจที่เหลือในไฟล์นี้:

  • ปุ่มลบต่อแถว — เครื่องหมาย × เรียก onRemoveItem(item.id) ส่งแค่ id เพราะ reducer ฝั่งโน้นต้องการแค่นั้นในการ filter แถวทิ้ง
  • ช่อง Price โชว์ส่วนลดเมื่อมีข้อมูล — จำ originalPrice ที่เราตั้งใจเก็บติดลง CartItem ตั้งแต่บทเรียน 22 และคำนวณใส่ตอน Add to Cart ในบทเรียน 23 ได้ไหม? มาเก็บดอกตรงนี้: ถ้ามีค่า เราโชว์ราคาเต็ม (ขีดฆ่า) กับยอด "You Save" ได้ทันทีโดยไม่ต้องถาม API สักคำ — ข้อมูลทุกอย่างอยู่ในตะกร้าครบแล้ว นี่คือเหตุผลที่ตอนออกแบบ CartItem เราถึงยอมเก็บฟิลด์ที่ "ยังไม่ได้ใช้" ไว้ก่อน
  • ปุ่มปรับจำนวนกับกติกาขั้นต่ำ — ปุ่มลดจำนวนถูก disabled เมื่อ quantity <= 1: reducer ของเราไม่มีกติกากันจำนวนติดลบเลย (UPDATE_QUANTITY เขียนทับค่าที่ส่งมาตรง ๆ ไม่ว่าจะเป็นเลขอะไร) เราเลือกกันที่ UI แทน — จะเอาของออกจากตะกร้าต้องตั้งใจกดปุ่มลบ ไม่ใช่กดลดจนหายไปเองแบบงง ๆ สังเกตด้วยว่าใน JSX เราเขียนปุ่มด้วย &lt; / &gt; (HTML entity) ไม่ใช่พิมพ์ < > ตรง ๆ — เพราะเครื่องหมายน้อยกว่าใน JSX คือการเปิด tag เดี๋ยว parser งงตาย
  • ช่อง Total ต่อแถวเป็นค่าคำนวณ — price * quantity คิดสดตอน render ไม่เก็บลง state ตามหลักที่ย้ำกันมาตั้งแต่คอร์ส React พื้นฐาน: อะไร derive ได้จาก state อย่าเก็บซ้ำ เดี๋ยวมันคลาดเคลื่อนกันเอง
  • รูปมี fallback — item.image || "/placeholder.png" กันตารางเลย์เอาต์พังถ้าข้อมูลรูปหลุดมาว่าง ๆ (บรรทัดนี้มีเรื่องจะเล่า — อ่านกล่อง 💡 ใต้โค้ดอ้างอิง)
  • key={item.id} ไม่ใช่ key={index} — ต่างจาก thumbnail กับรายการรีวิวในบทเรียน 21 ที่ index ยอมรับได้ ตารางตะกร้ามีการลบแถวกลาง ๆ ออกได้จริง ถ้าใช้ index React จะจับคู่แถวผิดหลังลบ แล้ว state ภายในของแถว (เช่น focus ที่ปุ่ม) จะกระโดดไปอยู่ผิดที่

แล้ว style ล่ะ? สังเกตว่าคอมโพเนนต์นี้ไม่มี .module.scss ของตัวเอง — class ทั้งหมดที่ใช้ (table, table-actions, table-image, table-original-price, table-discount, table-quantity) เป็น global component class ที่เราเขียนรอไว้แล้วใน src/styles/_components.scss ตั้งแต่บทเรียน 04 ตารางเลยหน้าตาเรียบร้อยทันทีโดยไม่ต้องเขียน SCSS เพิ่มสักบรรทัด นี่คือเส้นแบ่งการใช้งานของทั้งสองระบบในโปรเจกต์นี้: style ที่เป็น "ภาษากลาง" ของแอปอยู่ใน global stylesheet ส่วน style เฉพาะตัวของคอมโพเนนต์ (แบบ badge ของ CartSummary บทที่แล้ว) ค่อยแยกเป็น module

และเพราะ class เหล่านั้นเป็น global ที่เขียนไว้ล่วงหน้าเมื่อยี่สิบบทก่อน มันจึงเป็นจุดที่ผิดได้เงียบ ๆ ที่สุดของบทนี้: ชื่อ class ที่สะกดผิดหรือวางผิด element จะไม่ทำให้อะไรพัง หน้าเว็บยังขึ้น ตารางยังใช้ได้ แค่หน้าตาไม่เหมือนที่ควรเป็น — และไม่มีใครในทีมเครื่องมือของเราบอกคุณได้เลย (เก็บประโยคนี้ไว้ เดี๋ยวกล่อง 💡 ท้ายบทจะกลับมาคุยด้วย)

Cart.tsx — empty state มาก่อน

ตัวหน้าเพจสั้นอย่างน่าพอใจ เพราะงานหนักถูกทำไว้หมดแล้วในบทก่อน ๆ เหลือแค่การประกอบ:

  • ดึงของจาก store สามชิ้น — cart ไว้อ่าน, removeFromCart กับ updateQuantity ไว้แก้ แล้วดูบรรทัดที่ส่งเข้า CartTable: onRemoveItem={removeFromCart} — action จาก store เสียบเข้า prop ได้ตรง ๆ เพราะ signature ตรงกันเป๊ะ ((id: number) => void) ไม่ต้องมี wrapper function ให้เสียเปล่า นี่ไม่ใช่ความบังเอิญ: เราออกแบบ CartContextProps ในบทเรียน 22 โดยคิดถึงคนใช้แบบนี้อยู่แล้ว
  • ยอดรวมเป็นค่า derive — calculateTotalPrice ใช้ useMemo reduce ราคาคูณจำนวนของทุกแถว แล้ว .toFixed(2) ให้เป็น string ทศนิยมสองตำแหน่งพร้อมแสดง คำนวณใหม่เฉพาะเมื่อ cart.items เปลี่ยน — สูตรเดียวกับ badge ใน CartSummary แค่เปลี่ยนจากนับจำนวนเป็นรวมราคา
  • Empty state มาก่อน — เช็ค cart.items.length === 0 แล้ว return โครงหน้าตะกร้าว่างไปเลยก่อนถึง JSX หลัก แพตเทิร์น early return แบบเดียวกับที่หน้า Product ใช้กับ loading/error: อ่านจากบนลงล่างเจอเงื่อนไขพิเศษก่อน แล้วเนื้อหลักด้านล่างไม่ต้องห่อ if ซ้อนกันให้รก ที่สำคัญคือเราออกแบบหน้าว่างไว้จริง ๆ (หัวข้อใหญ่ + คำอธิบาย) ไม่ใช่ปล่อยตารางหัวโด่ไม่มีสักแถวให้ผู้ใช้งงว่าเว็บพังหรือเปล่า
  • CategoryBanner ถูก reuse ข้าม feature — คอมโพเนนต์เดิมจากบทเรียน 20 รับ name="Cart" กลายเป็นแถบหัวเพจได้เลย ทั้งสองกิ่งของ return ใส่ banner เหมือนกัน หน้าเลยดูเป็นหน้าเดียวกันไม่ว่าตะกร้าจะมีของหรือไม่ นี่คือการ reuse ครั้งที่สองในสามครั้งที่บทเรียน 20 ทำนายไว้ (ครั้งแรกคือหน้า Product ในบทเรียน 21 ครั้งที่สามคือหน้า Checkout ในบทเรียน 28)
  • ปุ่ม Checkout ต่อ router ผ่าน hook เดิม — goToCheckout จาก useProductRoute (บทเรียน 10) พาไป /checkout ซึ่งตอนนี้ยังเป็น stub — มันคือพระเอกของ chapter หน้าทั้ง chapter ส่วนแถบยอดรวมใช้ class table-total จาก _components.scss จัดชิดขวาให้เข้าชุดกับตาราง

สังเกตว่าไฟล์นี้เป็นไฟล์แรกของคอร์สที่ใช้ useProductRoute เป็นตัวที่สอง ต่อจาก Header เมื่อวาน — ตอนนี้ hook ตัวนั้นมีคนใช้สองที่แล้ว และค่า URL ทั้งสี่เส้นยังนั่งอยู่ในไฟล์เดียวเหมือนวันที่สร้างมัน นั่นคือสิ่งที่การรวมศูนย์ควรได้ผลลัพธ์

สัญญาที่แต่ละไฟล์ต้องทำให้ได้ — และสิ่งที่มันต้องไม่ทำ:

  • CartTable — ต้องอ่าน cart.items จาก useCart เอง แต่ต้องไม่เรียกฟังก์ชันแก้ไขใด ๆ จาก store ทุกการแก้ต้องผ่าน props สองตัว และต้องกันไม่ให้จำนวนลงต่ำกว่า 1 ที่ตัวปุ่ม
  • Cart.tsx — ต้อง return หน้าตะกร้าว่างด้วย early return ก่อนถึง JSX หลัก ต้องคำนวณยอดรวมด้วย useMemo และต้องไม่มี useState ใด ๆ ในไฟล์ ต้องไม่ยิง API

🤖 Prompt ที่ส่งให้ Cursor

ข้อกำหนดทางเทคนิค:
- ทั้งสองไฟล์ประกาศคอมโพเนนต์เป็น React.FC พร้อม interface ของ props ไว้บนสุด
  (ไฟล์ที่ไม่มี props ก็ไม่ต้องมี interface) และปิดท้ายไฟล์ด้วย export default
  รูปทรงเดียวกับคอมโพเนนต์อื่นทั้งหมดในโปรเจกต์ตั้งแต่บทเรียน 12
- CartTable.tsx: import React แล้ว useCart จาก "@/features/cart/useCart"
  interface CartTableProps สองตัว:
    onRemoveItem: (id: number) => void
    onUpdateQuantity: (id: number, quantity: number) => void
  ในคอมโพเนนต์ดึงเฉพาะ const { cart } = useCart();
    ห้ามดึง removeFromCart หรือ updateQuantity จาก useCart ในไฟล์นี้
  JSX: div ครอบ table className="table" ที่มี

import React from "react";
import { useCart } from "@/features/cart/useCart";

interface CartTableProps {
  onRemoveItem: (id: number) => void;
  onUpdateQuantity: (id: number, quantity: number) => void;
}

const CartTable: React.FC<CartTableProps> = ({
  onRemoveItem,
  onUpdateQuantity,
}) => {
  const { cart } = useCart();

  return (
    <div>
      <table className="table">
        <thead>
          <tr>
            <th>Action</th>
            <th>Image</th>
            <th>Product Name</th>
            <th>Price</th>
            <th>Quantity</th>
            <th>Total</th>
          </tr>
        </thead>
        <tbody>
          {cart.items.map((item) => (
            <tr key={item.id}>
              <td>
                <button
                  className="table-actions pointer"
                  onClick={() => onRemoveItem(item.id)}
                >
                  ×
                </button>
              </td>
              <td>
                <img
                  src={item.image || "/placeholder.png"}
                  alt={item.title}
                  className="table-image"
                />
              </td>
              <td>{item.title}</td>
              <td>
                <span className="fw-bold mr-5 fs-18">
                  ${item.price.toFixed(2)}
                </span>
                {item.originalPrice && (
                  <>
                    <span className="table-original-price">
                      ${item.originalPrice.toFixed(2)}
                    </span>
                    <br />
                    <span className="table-discount mt-5 inline-block fw-bold">
                      You Save: ${(item.originalPrice - item.price).toFixed(2)}
                    </span>
                  </>
                )}
              </td>
              <td>
                <div className="table-quantity">
                  <button
                    onClick={() => onUpdateQuantity(item.id, item.quantity - 1)}
                    disabled={item.quantity <= 1}
                  >
                    &lt;
                  </button>
                  <span>{item.quantity}</span>
                  <button
                    onClick={() => onUpdateQuantity(item.id, item.quantity + 1)}
                  >
                    &gt;
                  </button>
                </div>
              </td>
              <td>${(item.price * item.quantity).toFixed(2)}</td>
            </tr>
          ))}
        </tbody>
      </table>
    </div>
  );
};

export default CartTable;

          </p>
        </div>
      </>
    );

    <>
      <CategoryBanner name="Cart" />
      <div className="container pt-30 pb-30">
        <CartTable
          onRemoveItem={removeFromCart}
          onUpdateQuantity={updateQuantity}
        />
        <div className="table-total pr-20 pt-20 text-right">
          <h3>Total Price: ${calculateTotalPrice}</h3>
          <div className="inline-block mt-15">
            <Button onClick={onCheckout}>Checkout</Button>
          </div>
        </div>
      </div>
    </>
  );
};

export default Cart;
💡 ของที่ควรถูกทักในรีวิว: calculateTotalPrice ไม่ใช่ฟังก์ชัน มันคือค่า — เป็น string อย่าง "39.98" ที่ useMemo คืนมา ชื่อที่ขึ้นต้นด้วยคำกริยาว่า "calculate" ชวนให้คนอ่านพิมพ์ calculateTotalPrice() ที่จุดใช้งานโดยอัตโนมัติ (โชคดีที่ TypeScript ฟ้องทันที ข้อนี้จึงเป็นบั๊กที่ดัง ไม่ใช่บั๊กเงียบ) ชื่อที่ตรงกว่าคือ totalPrice เฉย ๆ เทียบกับไฟล์ข้าง ๆ ได้เลย: CartSummary ในบทเรียน 23 ใช้ useMemo ท่าเดียวกันเป๊ะแต่ตั้งชื่อว่า totalItems ซึ่งอ่านออกทันทีว่าเป็นค่า — สองไฟล์ในฟีเจอร์เดียวกัน สองธรรมเนียมการตั้งชื่อ นี่คือรูปแบบเดิมที่คอร์สนี้เจอมาตลอด: สิ่งที่ไม่มีเครื่องมือบังคับจะเพี้ยนไปทีละไฟล์ เราสั่งชื่อตามต้นฉบับใน prompt เพื่อให้ diff ตรง แต่ในรีวิวจริงนี่คือ comment หนึ่งบรรทัดที่แก้ง่ายที่สุดในบทนี้ ข้อพ่วงในไฟล์เดียวกัน: onCheckout เป็น wrapper ที่เรียก goToCheckout() เฉย ๆ — <Button onClick={goToCheckout}> ให้ผลเหมือนกันทุกประการ และเป็นท่าเดียวกับที่ checklist สองข้อในบทนี้กับบทที่แล้วเพิ่งปฏิเสธไป (onRemoveItem={(id) => removeFromCart(id)} ข้างบน และ onIconClick={() => goToCartSummary()} ในบทเรียน 23) ด้วยเหตุผลว่าการห่อเพิ่มไม่ได้อะไรนอกจากฟังก์ชันใหม่ทุก render ที่ต้นฉบับห่อตรงนี้ก็เพราะมันตั้งชื่อ handler ตามชื่อ event (onCheckout) ซึ่งอ่านสวยตอนสแกนไฟล์ — แต่นั่นเป็นเหตุผลด้านการอ่าน ไม่ใช่เหตุผลทางเทคนิค เราสั่งตามต้นฉบับเพื่อให้ diff ตรง แต่ในรีวิวจริงข้อนี้ควรถูกทักคู่กับข้อชื่อตัวแปรข้างบน ไม่ใช่ปล่อยผ่านเพราะมันอยู่ในโค้ดอ้างอิง

ปิดท้ายด้วยข้อสังเกตที่มองเห็นได้เฉพาะตอนที่ทุกอย่างต่อกันครบแล้ว: ลองกดปุ่ม > ในตารางหนึ่งครั้ง แล้วดูสามจุดบนจอพร้อมกัน — Total ท้ายแถว, Total Price ล่างขวา และ badge บน Header ทั้งสามขยับพร้อมกันโดยที่คอมโพเนนต์ทั้งสามตัวไม่รู้จักกันเลย ไม่มีใครส่ง props หากัน ไม่มี event bus ไม่มีการ refetch สิ่งที่เกิดขึ้นคือ dispatch หนึ่งครั้ง → reducer คืน state ก้อนใหม่ → context เปลี่ยน → ทุกคนที่ subscribe อ่านค่าใหม่ นี่คือของที่คุณลงทุนสร้างไว้ในบทเรียน 22 กำลังทำงานเต็มรูปแบบ และเป็นเหตุผลที่บทนั้นยืนยันว่าตะกร้าต้องเป็น client state ที่มีเจ้าของชัดเจนหนึ่งเดียว

  3. CartTable อ่าน cart.items จาก useCart เอง แต่รับฟังก์ชันแก้ไขเป็น props — ลองแก้ให้มันเรียก removeFromCart จาก useCart เองเลย หน้าเว็บทำงานเหมือนเดิมทุกประการ อธิบายว่าอะไรที่ยากขึ้นสำหรับคนที่มาอ่านโค้ดนี้ในอีกหกเดือน และตอบด้วยว่าถ้าเป็นแบบนั้น Cart.tsx จะเหลือหน้าที่อะไรบ้าง (เสร็จแล้วแก้กลับ)
