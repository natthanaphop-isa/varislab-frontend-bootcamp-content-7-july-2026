Product List Components

ยินดีด้วย — คุณมาถึงช่วงที่สนุกที่สุดของคอร์สแล้ว ตอนนี้เรามีครบทุกอย่างที่หน้าเพจต้องใช้: โครงแอปกับ router, คอมโพเนนต์กลางอย่าง Button และ Pagination และชั้นข้อมูลสินค้าที่จบด้วย query factory ในบทที่แล้ว จากบทนี้ไปอีกสี่บท เราจะเอาทั้งหมดนั้นมาประกอบเป็นหน้าเพจจริง: Home, Category และ Product detail

แต่ก่อนจะสร้างหน้า Home ในบทถัดไป สังเกตว่าทั้งหน้า Home และหน้า Category ต่างต้องแสดงรายการสินค้าเป็นการ์ดและเมนูหมวดหมู่เหมือนกันเป๊ะ ถ้าเราเขียน markup ชุดนั้นซ้ำในทั้งสองหน้า วันที่ต้องแก้ดีไซน์การ์ดเราจะต้องแก้สองที่ (แล้วก็จะลืมแก้สักที่หนึ่งแน่นอน) บทนี้เราเลยจะสร้างชิ้นส่วนที่ใช้ร่วมกันเหล่านี้ก่อนหนึ่งบทเต็ม: utility คำนวณราคา, ProductCard, ProductsList และ CategoryMenu

💡 บทนี้จะยังไม่มีอะไรใหม่ปรากฏบนหน้าจอ เพราะคอมโพเนนต์ที่สร้างยังไม่ถูกเรียกใช้จากหน้าไหนเลย — เราจะได้เห็นมันพร้อมกันทั้งหมดตอนประกอบหน้า Home ในบทถัดไป ระหว่างทางใช้ npm run dev กับ npm run typecheck เป็นตัวยืนยันว่าไม่มีอะไรพังก็พอ

price.utils: คำนวณราคาก่อนลด

เปิดข้อมูลสินค้าจาก dummyjson ดูอีกครั้ง (เช่น https://dummyjson.com/products/1) จะเห็นว่า API ให้ราคามาสองส่วน: price ซึ่งเป็นราคาหลังหักส่วนลดแล้ว และ discountPercentage เป็นเปอร์เซ็นต์ส่วนลด แต่หน้าร้านออนไลน์ทั่วไปชอบแสดง "ราคาเต็มขีดฆ่า" คู่กับราคาจริงเพื่อให้เห็นว่าลดไปเท่าไร ปัญหาคือ API ไม่ได้ให้ราคาเต็มมา — เราต้องคำนวณย้อนกลับเอง

คณิตศาสตร์ไม่ยาก: ถ้าราคาเต็มคือ X แล้วลด d เปอร์เซ็นต์ ราคาหลังลดคือ X × (1 - d/100) ดังนั้นย้อนกลับ ราคาเต็มคือ price ÷ (1 - d/100) ลองแทนตัวเลขดู: สินค้าราคา 90 บาทหลังลด 10% → 90 ÷ 0.9 = 100 บาท ตรงตามคาด

การคำนวณแบบนี้เป็น pure function ที่ไม่เกี่ยวกับ React เลย เราจึงเก็บไว้ใน shared/utils ข้าง ๆ pagination.utils.ts จากบทเรียน 16 และเพราะมันเป็น pure function เดี่ยว ๆ ในบทเรียน 31 เราจะเขียน unit test ให้มันได้ง่ายมาก

สิ่งที่ต้องตัดสินใจให้ขาดก่อนส่ง prompt คือคำถามเดียว: ฟังก์ชันนี้คืน "ตัวเลข" หรือ "ข้อความราคาที่จัดรูปแบบแล้ว"? คำตอบของโปรเจกต์นี้คือตัวเลขดิบ — ผลหารตรง ๆ ไม่ปัดเศษ ไม่ใส่สัญลักษณ์สกุลเงิน การจัดรูปแบบเป็นงานของจุดที่แสดงผล ซึ่งใน ProductCard คือ ${originalPrice.toFixed(2)} เหตุผลไม่ใช่ความสวยงามเชิงทฤษฎี: ค่าที่ยังไม่ปัดจะถูกเอาไปคำนวณต่อจริง ๆ ในบทเรียน 24 (บรรทัด You Save: ${(item.originalPrice - item.price).toFixed(2)} ในตะกร้า) ถ้าปัดตั้งแต่ต้นทาง เราจะปัดสองรอบโดยไม่รู้ตัว จำย่อหน้านี้ไว้ให้ดี — มันคือข้อแรกของ checklist

Skeleton screen ด้วย react-loading-skeleton

ตอนนี้เรามี spinner (ClipLoader จาก react-spinners ที่ติดตั้งไปในบทเรียน 12) ไว้ใช้ตอนรอข้อมูลจาก API แล้ว แต่รูปภาพสินค้าเป็นการรอคนละแบบ: ข้อมูล query มาถึงแล้ว การ์ดวาดเสร็จแล้ว แต่ไฟล์รูปยังโหลดไม่เสร็จ ถ้าไม่ทำอะไรเลย การ์ดจะโผล่มาแบบไม่มีรูป แล้วรูปค่อยเด้งตามมาทีหลัง — layout กระตุกไปมาไม่น่าดู

วิธีที่เว็บสมัยใหม่นิยมคือ skeleton screen: วาดกล่องสีเทาวิบวับขนาดเท่าของจริงค้างไว้ก่อน พอของจริงพร้อมค่อยสลับเข้ามาแทนที่ ต่างจาก spinner ตรงที่ skeleton จองพื้นที่ไว้ให้เลย layout จึงไม่ขยับ และผู้ใช้เดาได้ทันทีว่ากำลังรออะไรอยู่ตรงไหน — spinner เหมาะกับ "รอทั้งก้อนใหญ่" ส่วน skeleton เหมาะกับ "รอชิ้นส่วนย่อยที่รู้ขนาดล่วงหน้า" เราจะได้ใช้ทั้งคู่ในโปรเจกต์นี้

ตามกติกาเดิมของคอร์ส dependency เราติดตั้งเอง ส่วนการต่อสายเข้าโค้ดเป็นงานของ Agent:

npm install react-loading-skeleton
git add -A && git commit -m "chore: install react-loading-skeleton"

react-loading-skeleton ต้องการ CSS ของตัวเองหนึ่งไฟล์ (สีพื้น สีวิบวับ และ animation) ซึ่งควร import ครั้งเดียวที่จุดเริ่มต้นของแอป — src/main.tsx จึงต้องถูกแก้เพิ่มหนึ่งบรรทัด และนั่นคือไฟล์ที่สองที่ prompt ของบทนี้จะสั่งแก้

💡 ตอนจบบทเรียน 09 เราทิ้งท้ายไว้ว่า main.tsx จะนิ่งไปอีกนาน และจะมีของมาเพิ่มอีกครั้งเดียวคือบรรทัด import CSS ของ react-loading-skeleton ในบทเรียน 18 — นี่คือบทนั้น หลังบทนี้ไฟล์นั้นจะไม่ถูกแตะอีกเลยตลอดคอร์ส

สามคอมโพเนนต์ สามระดับของการรู้จักข้อมูล

ก่อนไปดูโค้ด ทำความเข้าใจการแบ่งงานของสามตัวนี้ให้ขาดก่อน เพราะมันคือเหตุผลที่เราสร้างสามไฟล์แทนที่จะเป็นไฟล์เดียว:

  • ProductCard — รับ props เป็นชิ้น ๆ (image, title, price, …) ไม่รู้จัก type Product ของ dummyjson เลย และไม่รู้จัก router ด้วย ตอนถูกคลิกมันแค่เรียก callback onProductClick(productId) แล้วให้คนที่ใช้มันตัดสินใจเองว่าจะพาไปไหน — แบบเดียวกับที่ <button onClick={…}> ไม่รู้ว่า onClick ทำอะไร คอมโพเนนต์ยิ่งรู้น้อย ยิ่งเอาไปใช้ซ้ำได้กว้าง
  • ProductsList — ตัวกลางที่รู้จัก Product เต็ม ๆ หน้าที่เดียวของมันคือแปลงข้อมูลจาก query ให้เป็น props ของการ์ด: หยิบ thumbnail ไปเป็น image, นับ reviews.length เป็น reviewsCount, เรียก calculateOriginalPrice ตรงนี้ที่เดียว การแปลงทั้งหมดกระจุกอยู่ในไฟล์เดียวแบบนี้ วันที่ dummyjson เปลี่ยนชื่อฟิลด์ เราแก้ไฟล์เดียวจบ
  • CategoryMenu — เมนูที่ไม่มี state ของตัวเองเลยสักตัว มันไม่จำว่าหมวดไหนถูกเลือก หน้าเพจเป็นคนจำ แล้วส่งกลับลงมาผ่าน prop activeCategory คอมโพเนนต์แบบนี้เรียกกันว่า controlled component (แนวคิดเดียวกับ controlled input จากคอร์ส React พื้นฐาน แค่ขยับมาอยู่ระดับคอมโพเนนต์) ข้อดีคือหน้า Home กับหน้า Category ใช้เมนูตัวเดียวกันได้ทั้งที่พฤติกรรมหลังคลิกไม่เหมือนกันเลย — เดี๋ยวคุณจะได้เห็นในบทเรียน 19 กับ 20

สัญญาขาออกของ CategoryMenu มีจุดที่ต้องอ่านช้า ๆ: onCategoryClick ส่งทั้ง object Category กลับไป ไม่ใช่แค่ slug ทำไม? เพราะหน้าเพจที่รับ event ไปต้องใช้มากกว่านั้น — ใช้ slug ยิง query และใช้ name แสดงหัวหน้า การส่ง object เต็มทำให้ผู้ใช้เมนูไม่ต้องไปไล่หา object จาก slug อีกรอบ ส่วนขาเข้า activeCategory รับแค่ slug เพราะสิ่งเดียวที่เมนูต้องรู้คือ "ตัวไหนต้องไฮไลต์"

โฟลเดอร์ src/features/products/components/ ยังไม่มีอยู่ — Agent ต้องสร้างขึ้นใหม่ ส่วน src/shared/utils/ มี pagination.utils.ts จากบทเรียน 16 อยู่แล้ว

สัญญาที่แต่ละไฟล์ต้องทำให้ได้ — และสิ่งที่มันต้องไม่ทำ:

  • price.utils.ts — ต้องเป็น pure function ตัวเดียวที่รับ number คืน number และผลลัพธ์ต้องเป็นผลหารดิบ ต้องไม่ปัดเศษ ไม่จัดรูปแบบ ไม่แตะ Intl ไม่รู้จัก React และต้องไม่ import อะไรเลยสักบรรทัด
  • ProductCard.tsx — ต้องรับ props เป็นค่าพร้อมแสดงทีละตัว ต้องไม่ import Product, ไม่ import useNavigate และต้องไม่มีไฟล์ .module.scss ของตัวเอง
  • ProductsList.tsx — ต้องรับ products ที่เป็น undefined ได้ และเป็นที่เดียวในบทนี้ที่เรียก calculateOriginalPrice ต้องไม่ยิง query เอง ต้องไม่รู้จัก useQuery
  • CategoryMenu.tsx — ต้องไม่มี useState แม้แต่ตัวเดียว หมวดที่เลือกอยู่มาจาก prop เท่านั้น และ callback ต้องส่ง Category ทั้ง object กลับ ไม่ใช่ string
  • main.tsx — ต้องเพิ่มบรรทัด import CSS หนึ่งบรรทัด ต้องไม่แตะบรรทัดอื่นสักบรรทัด

ข้อกำหนดทางเทคนิค:
- price.utils.ts: ไม่มี import เลย มี export เดียวคือ arrow function ชื่อ
  calculateOriginalPrice ที่รับ (price: number, discountPercentage?: number)
  และประกาศ return type เป็น number
  ขึ้นต้นไฟล์ด้วย JSDoc สี่บรรทัดนี้ ลอกตามนี้ทุกตัวอักษร:
    Calculate the original price before the discount.
    @param {number} price - The discounted price of the product.
    @param {number | undefined} discountPercentage - The discount percentage (optional).
    @returns {string} - The original price as a formatted string.
  ไส้ในมีสองคำสั่งเท่านั้น:
    guard clause: ถ้า !discountPercentage หรือ discountPercentage <= 0
      หรือ discountPercentage >= 100 ให้ return price
      พร้อม comment ท้ายบรรทัดว่า // If no discount or invalid discount, return the current price
    บรรทัดสุดท้าย: return price / (1 - discountPercentage / 100)
  ห้ามปัดเศษ ห้ามใช้ toFixed, Math.round, Number(), parseFloat หรือ Intl.NumberFormat
  ห้ามคืน string ไม่ว่ากรณีใด แม้ JSDoc จะเขียนไว้แบบนั้น (บรรทัดนั้นลอกตามต้นฉบับ)
- ProductCard.tsx: import React, { useState } from "react"

    import StarReview จาก "@/shared/components/StarReview/StarReview"
  interface ProductCardProps เรียงตามนี้พอดี: productId: number, image: string,
    title: string, description: string, price: number, originalPrice?: number,
    discount?: number, rating: number, reviewsCount: number,
    skeletonHeight?: number, onProductClick: (id: number) => void
    ใส่ comment ท้ายบรรทัด rating ว่า // Rating out of 10
  destructure props ตามลำดับนี้ (ต่างจากลำดับใน interface โดยตั้งใจ): image, title,
    description, price, originalPrice, discount, rating, reviewsCount,
    skeletonHeight = 240, productId, onProductClick
  state เดียว: const [isImageLoaded, setIsImageLoaded] = useState(false)
  โครง JSX:
    div นอกสุด className={`flex flex-column`} (เขียนเป็น template literal ตามนี้)
      และ onClick={() => onProductClick(productId)}
    > div className="image-container" ที่มี
        {!isImageLoaded && <Skeleton height={skeletonHeight} />}
        img src={image} alt={title} style={{ display: isImageLoaded ? "block" : "none" }}
          onLoad ที่เรียก setIsImageLoaded(true)
    > div className={`pt-15 pb-15`} (template literal เช่นกัน) ที่มี
        h4 className="fs-18 mb-5 mt-0" แสดง title
        p className="fs-14 text-muted mb-10 mt-0" แสดง description
        div className="flex align-item-center mb-15" ที่มี StarReview score={rating}
          และ span className="fs-12 text-muted ml-5" แสดง ({reviewsCount}) ในวงเล็บ
        p className="fs-20 mb-5" แสดง ${price.toFixed(2)} โดย $ เป็นตัวอักษรธรรมดา
        div className="flex align-item-center" ที่มีสองบล็อกแบบมีเงื่อนไข:
          {originalPrice && ...} span className="fs-14 text-muted text-line-through"
            แสดง $ ตามด้วย originalPrice.toFixed(2)
          {discount && ...} span className="fs-14 fw-medium ml-10 text-primary"
            แสดง {discount}% Off

src/shared/utils/price.utils.ts:

/**
 * Calculate the original price before the discount.
 * @param {number} price - The discounted price of the product.
 * @param {number | undefined} discountPercentage - The discount percentage (optional).
 * @returns {string} - The original price as a formatted string.
 */
export const calculateOriginalPrice = (
  price: number,
  discountPercentage?: number,
): number => {
  if (
    !discountPercentage ||
    discountPercentage <= 0 ||
    discountPercentage >= 100
  ) {
    return price; // If no discount or invalid discount, return the current price
  }
  return price / (1 - discountPercentage / 100);
};

สังเกต guard clause ก่อนคำนวณ: ถ้าไม่มีส่วนลด (undefined หรือ 0), ส่วนลดติดลบ หรือส่วนลดตั้งแต่ 100% ขึ้นไป (ซึ่งจะทำให้ตัวหารเป็นศูนย์หรือติดลบ — ได้ราคา Infinity หรือราคาติดลบ!) เราคืน price เดิมไปเลย การเช็คขอบเขตข้อมูลก่อนคำนวณแบบนี้เป็นนิสัยที่ดีมากเวลาทำงานกับข้อมูลจาก API ภายนอกที่เราควบคุมไม่ได้

💡 ของที่ควรถูกทักในรีวิว: บรรทัด @returns {string} - The original price as a formatted string. ในต้นฉบับผิด — ฟังก์ชันประกาศ : number อยู่สามบรรทัดถัดลงมา และคืนตัวเลขจริง ๆ ทั้งสองทางออก JSDoc ก้อนนี้น่าจะเป็นซากของเวอร์ชันก่อนที่เคยคืน string แล้วเปลี่ยนใจทีหลังโดยลืมแก้คำอธิบาย นี่คือตัวอย่างที่ชัดที่สุดของcomment ที่แย่กว่าไม่มี comment: มันไม่ทำให้อะไรพัง TypeScript ไม่อ่าน JSDoc เพื่อตรวจ type (มันอ่าน signature) npm run lint ก็ไม่มีกฎที่จับเรื่องนี้ — แต่มันโกหกคนอ่านคนถัดไป และในคอร์สนี้ "คนอ่านคนถัดไป" คือ Agent ที่เรากำลังจะสั่งงานต่อ นั่นคือเหตุผลที่ prompt ต้องมีบรรทัด "ห้ามคืน string แม้ JSDoc จะเขียนไว้แบบนั้น" ต่อท้าย — เราสั่งลอกตามต้นฉบับเพราะโค้ดอ้างอิงของคอร์สนี้คือแอปจริง แต่ต้องกันไม่ให้คำโกหกนั้นกลายเป็นโค้ด ในงานจริงนี่คือ comment ที่ควรเขียนทิ้งไว้ในรีวิว และเป็นสองบรรทัดที่แก้ได้ใน 10 วินาที

src/features/products/components/ProductCard/ProductCard.tsx — คอมโพเนนต์ที่จะถูกวาดซ้ำมากที่สุดในแอปนี้:

import React, { useState } from "react";
import Skeleton from "react-loading-skeleton";
import StarReview from "@/shared/components/StarReview/StarReview";

interface ProductCardProps {
  productId: number;
  image: string;
  title: string;
  description: string;
  price: number;
  originalPrice?: number;
  discount?: number;
  rating: number; // Rating out of 10
  reviewsCount: number;
  skeletonHeight?: number;
  onProductClick: (id: number) => void;
}

const ProductCard: React.FC<ProductCardProps> = ({
  image,
  title,
  description,
  price,
  originalPrice,
  discount,
  rating,
  reviewsCount,
  skeletonHeight = 240,
  productId,
  onProductClick,
}) => {
  const [isImageLoaded, setIsImageLoaded] = useState(false);

  return (
    <div
      className={`flex flex-column`}
      onClick={() => onProductClick(productId)}
    >
      <div className="image-container">
        {!isImageLoaded && <Skeleton height={skeletonHeight} />}
        <img
          src={image}
          alt={title}
          style={{
            display: isImageLoaded ? "block" : "none",
          }}
          onLoad={() => {
            setIsImageLoaded(true);
          }}
        />
      </div>

      <div className={`pt-15 pb-15`}>
        <h4 className="fs-18 mb-5 mt-0">{title}</h4>
        <p className="fs-14 text-muted mb-10 mt-0">{description}</p>
        <div className="flex align-item-center mb-15">
          <StarReview score={rating} />
          <span className="fs-12 text-muted ml-5">({reviewsCount})</span>
        </div>
        <p className="fs-20 mb-5">${price.toFixed(2)}</p>
        <div className="flex align-item-center">
          {originalPrice && (
            <span className="fs-14 text-muted text-line-through">
              ${originalPrice.toFixed(2)}
            </span>
          )}
          {discount && (
            <span className="fs-14 fw-medium ml-10 text-primary">
              {discount}% Off
            </span>
          )}
        </div>
      </div>
    </div>
  );
};

export default ProductCard;

มีของให้แกะหลายชิ้นในไฟล์นี้:

  • ไม่มี .module.scss ของตัวเอง — การ์ดใบนี้แต่งตัวด้วย utility classes จาก _utilities.scss ที่เราวางไว้ตั้งแต่บทเรียน 04 ล้วน ๆ (flex, fs-18, text-muted, text-line-through, …) เมื่อ style ที่ต้องใช้มีครบใน utility อยู่แล้ว การไม่สร้างไฟล์ SCSS เปล่า ๆ เพิ่มก็เป็นการตัดสินใจที่ถูก — SCSS module มีไว้สำหรับ style ที่เฉพาะตัวจริง ๆ อย่างที่ CategoryMenu ด้านล่างจะได้ใช้
  • ลูกเล่น skeleton ของรูป — ตราบใดที่ isImageLoaded ยังเป็น false เราวาด <Skeleton height={skeletonHeight} /> ค้างไว้ และซ่อน <img> ด้วย display: "none" จุดสำคัญคือเราซ่อนรูป ไม่ใช่ไม่วาดรูป — ถ้าเขียน {isImageLoaded && <img … />} รูปจะไม่ถูกใส่เข้า DOM เบราว์เซอร์เลยไม่เริ่มโหลด แล้ว onLoad ก็จะไม่มีวันยิง — กลายเป็น skeleton ค้างตลอดกาล พอรูปโหลดเสร็จ เบราว์เซอร์ยิง event onLoad เราตั้ง state เป็น true React วาดใหม่ skeleton หายไป รูปโผล่ขึ้นมาแทนในพื้นที่เดิมพอดี
  • skeletonHeight = 240 — default parameter ให้การ์ดทั่วไปสูง 240px แต่หน้าไหนอยากได้การ์ดเตี้ยหรือสูงกว่านี้ก็ override ผ่าน prop ได้ (จนจบคอร์สยังไม่มีหน้าไหนใช้สิทธิ์นั้น — prop นี้เป็นความยืดหยุ่นที่เตรียมไว้แล้วไม่ได้ใช้ ซึ่งก็เป็นข้อสังเกตที่ควรเขียนในรีวิวได้)
  • reuse StarReview — ดาวรีวิวที่สร้างไว้ในบทเรียน 14 กลับมาทำงานแล้ว จำ convention ของมันได้ไหม: score เป็นคะแนนเต็ม 10 แล้วภายในหารสองเป็นดาว 5 ดวง คอมเมนต์ // Rating out of 10 ใน props ก็ย้ำเรื่องเดียวกัน — เก็บคำว่า "เต็ม 10" นี้ไว้ในหัว บทเรียน 21 จะเอาคำนี้ไปเทียบกับข้อมูลจริง
  • onProductClick callback prop — ตอนการ์ดถูกคลิก เราเรียก callback พร้อมส่ง productId กลับไปให้คนที่ใช้การ์ด สังเกตว่า ProductCard ไม่รู้จัก router เลย — มันไม่ import useNavigate ไม่รู้ว่าคลิกแล้วต้องไปหน้าไหน หน้าที่ของมันมีแค่ "แสดงผลและรายงานว่าถูกคลิก" ให้หน้าเพจที่เป็นเจ้าของตัดสินใจเรื่อง navigation เอง
  • className={`flex flex-column`} — backtick ที่ไม่มีตัวแปรอยู่ข้างในเลย เขียนเป็น className="flex flex-column" ก็ได้ผลเท่ากันทุกประการ (เหมือนกับ {`pt-15 pb-15`} อีกจุดหนึ่ง) เราสั่ง prompt ให้ลอกตามต้นฉบับเพราะโค้ดอ้างอิงของคอร์สนี้คือแอปจริง และ Prettier ไม่แปลง template literal กลับเป็น string ให้ ถ้าไม่สั่ง คุณจะได้ diff ที่ไม่ตรงกับโค้ดอ้างอิงโดยที่ไม่มีใครทำอะไรผิด
💡 ของที่ควรถูกทักในรีวิว: className="image-container" — grep -rn "image-container" src/styles/ ไม่เจออะไรเลย class นี้ไม่มีนิยามอยู่ที่ไหนในโปรเจกต์ นี่คือญาติสนิทของ text-white ใน Footer (บทเรียน 10) และ styles.starReview ใน StarReview (บทเรียน 14): ชื่อ class ที่ไม่มีนิยาม ไม่ทำอะไรเลยแบบเงียบสนิท ต่างกันตรงที่สองตัวก่อนหน้าเป็น class ของ SCSS module ส่วนตัวนี้เป็น class global ธรรมดา — ไม่มี TypeScript ไม่มี lint ไม่มีอะไรทั้งนั้นที่ตรวจว่า string ในแอตทริบิวต์ className มีอยู่จริงในไฟล์ CSS หรือเปล่า มันเป็นแค่ข้อความ ประเด็นที่ควรรู้จากสามกรณีรวมกันคือ: การไล่ grep ชื่อ class ทุกตัวที่ Agent เขียนมา เป็นขั้นตอนตรวจงานที่ไม่มีเครื่องมือตัวไหนทำแทนได้เลยในโปรเจกต์นี้ และในไฟล์ที่ Agent เขียนใหม่ทั้งไฟล์ ชื่อ class ที่มันแต่งขึ้นเองคือสิ่งที่หลุดรอดง่ายที่สุด

src/features/products/components/ProductsList/ProductsList.tsx — ProductCard รับ props เป็นชิ้น ๆ แต่ข้อมูลจาก query มาเป็น Product[] เต็ม ๆ ตัว ตัวกลางที่ map จากรูปแบบหนึ่งไปอีกรูปแบบหนึ่งคือไฟล์นี้:

import React from "react";
import { Product } from "@/features/products/types";
import ProductCard from "@/features/products/components/ProductCard/ProductCard";
import { calculateOriginalPrice } from "@/shared/utils/price.utils";

interface ProductsListProps {
  products: Product[] | undefined;
  onProductClick: (id: number) => void;
}

const ProductsList: React.FC<ProductsListProps> = ({
  products,
  onProductClick,
}) => {
  return (
    <>
      {products?.map(
        ({
          thumbnail,
          id,
          title,
          brand,
          price,
          discountPercentage,
          rating,
          reviews,
        }) => (
          <div key={id} className="mb-15 pointer">
            <ProductCard
              productId={id}
              image={thumbnail}
              title={title}
              description={brand}
              price={price}
              originalPrice={calculateOriginalPrice(price, discountPercentage)}
              discount={discountPercentage}
              rating={rating}
              reviewsCount={reviews.length}
              onProductClick={onProductClick}
            />
          </div>
        ),
      )}
    </>
  );
};

export default ProductsList;

ประเด็นที่น่าสนใจ:

  • products: Product[] | undefined — จงใจยอมรับ undefined เพราะคนที่จะส่ง prop นี้คือหน้าเพจที่ส่ง data?.products จาก useQuery มาตรง ๆ ซึ่งเป็น undefined ได้เสมอระหว่างรอโหลด optional chaining ใน products?.map(…) จัดการกรณีนั้นให้เงียบ ๆ (ไม่ render อะไรเลย) โดยหน้าเพจไม่ต้องเช็คก่อนส่ง
  • destructuring กลาง parameter ของ map — แทนที่จะรับ (product) => แล้วเขียน product.title, product.price ยาว ๆ เราแตกเฉพาะ field ที่ใช้ออกมาตั้งแต่หน้าประตู อ่านปุ๊บรู้เลยว่าคอมโพเนนต์นี้ใช้ข้อมูลอะไรจาก Product บ้าง
  • แปลงข้อมูลตรงนี้ที่เดียว — calculateOriginalPrice จาก utility เมื่อครู่ถูกเรียกตรงนี้ และ reviews.length ก็ถูกนับตรงนี้ ProductCard เลยได้รับค่าที่พร้อมแสดงผลทันที ไม่ต้องรู้จักโครงสร้าง Product ของ dummyjson เลยแม้แต่นิดเดียว
  • key={id} — ใช้ id จริงของสินค้าเป็น key ตามกฎเหล็กของ list rendering จากคอร์ส React พื้นฐาน ไม่ใช้ index เพราะรายการนี้เปลี่ยนชุดได้ทั้งชุดเวลาสลับหมวดหมู่หรือเปลี่ยนหน้า
  • description={brand} — บรรทัดที่ 33 ของไฟล์นี้ prop ชื่อ "คำอธิบาย" แต่ค่าที่ใส่คือ "แบรนด์" ซึ่งอ่านแล้วสะดุดนิดหนึ่ง (การ์ดไม่ได้แสดง description ของสินค้าจริง ๆ) แต่ประเด็นที่ใหญ่กว่าเรื่องชื่อ prop อยู่ในกล่องข้างล่าง
💡 สังเกตว่าเมื่อสินค้าไม่มีส่วนลด calculateOriginalPrice คืนราคาเดิมกลับมา การ์ดจึงยังแสดงราคาขีดฆ่าที่เท่ากับราคาจริง — ฟังดูแปลก แต่สินค้าของ dummyjson มี discountPercentage ติดมาครบทั้ง 194 ชิ้น (ตรวจมาแล้วในบทเรียน 16) เคสนี้จึงไม่ปรากฏบนจอเลย ส่วนป้าย "% Off" ถูกซ่อนอยู่แล้วด้วย {discount && …} ใน ProductCard

import React from "react";
import styles from "./CategoryMenu.module.scss";
import { Category } from "@/features/products/types";

interface CategoryMenuProps {
  categories: Category[];
  activeCategory: string | undefined;
  onCategoryClick: (category: Category) => void;
}

const CategoryMenu: React.FC<CategoryMenuProps> = ({
  categories,
  activeCategory,
  onCategoryClick,
}) => {
  return (
    <div className={`${styles.categoryMenu} text-right`}>
      {categories.map((cat) => (
        <span
          key={cat.slug}
          className={`nav-link block mb-20 pointer ${
            activeCategory === cat.slug ? "fw-bold text-primary" : ""
          }`}
          onClick={() => onCategoryClick(cat)}
        >
          {cat.name}
        </span>
      ))}
    </div>
  );
};

export default CategoryMenu;

สัญญา (contract) ของคอมโพเนนต์นี้ออกแบบมาอย่างจงใจ ลองอ่าน props ทีละตัว:

  • categories: Category[] — รายชื่อหมวดหมู่ทั้งหมด มาจาก query productQueries.categories() ที่เราสร้างไว้ในบทเรียน 17 จำ type Category ได้ไหม: { slug, name, url } — slug คือรหัสสำหรับเรียก API ส่วน name คือชื่อสวย ๆ สำหรับแสดงผล
  • activeCategory: string | undefined — รับเป็น slug ของหมวดที่กำลังเลือกอยู่ ไม่ใช่ทั้ง object เพราะสิ่งเดียวที่เมนูต้องรู้คือ "ตัวไหนต้องไฮไลต์" การเทียบ activeCategory === cat.slug แล้วเติมคลาส fw-bold text-primary คือทั้งหมดของลอจิกไฮไลต์ และการยอมรับ undefined ทำให้หน้าเพจส่งค่าจาก state ที่ยังโหลดไม่เสร็จมาได้เลยโดยไม่ต้อง fallback
  • onCategoryClick: (category: Category) => void — ขาออกกลับส่งทั้ง object คืนให้ ทำไมไม่ส่งแค่ slug? เพราะหน้าเพจที่รับ event ไปต้องใช้มากกว่านั้น — ต้องใช้ slug ยิง query และใช้ name แสดงหัวหน้า การส่ง object เต็มทำให้ผู้ใช้เมนูไม่ต้องไปไล่หา object จาก slug อีกรอบ
