รันสคริปต์และโปรเจกต์ Node

เมื่อติดตั้ง Node.js และ npm เรียบร้อยแล้ว บทสุดท้ายนี้จะพาใช้งานจริง ตั้งแต่รันไฟล์ JavaScript ธรรมดา ไปจนถึงสร้างโปรเจกต์ npm ติดตั้ง package และเรียกใช้ script ขั้นตอนเหล่านี้จะได้ใช้บ่อยมากในคอร์ส Node.js ต่อจากนี้

รันไฟล์ JavaScript ด้วย node

สร้างไฟล์ hello.js ขึ้นมาสักไฟล์ แล้วเปิดด้วย VS Code

$ touch hello.js
$ code hello.js

พิมพ์โค้ด JavaScript ธรรมดาลงไปหนึ่งบรรทัดแล้วบันทึก

console.log("hello")

จากนั้นรันไฟล์นี้ด้วย node

$ node hello.js
hello

node ตามด้วยชื่อไฟล์คือวิธีรันไฟล์ JavaScript ที่ใช้บ่อยที่สุด จุดที่ต้องระวังคือชื่อไฟล์ที่ให้ไปเป็น relative path เทียบกับ pwd ปัจจุบันเสมอ ตามที่เรียนไปในบทที่ 5 เรื่อง path ถ้ายืนอยู่ผิดโฟลเดอร์แล้วรัน node hello.js โดยที่ไฟล์นั้นไม่ได้อยู่ในโฟลเดอร์ปัจจุบัน จะได้ error ทันที 

$ node hello.js
node:internal/modules/cjs/loader:1433
  throw err;
  ^

Error: Cannot find module '/Users/mint/hello.js'

ในกรณีนี้ Cannot find module ไม่ได้แปลว่าไฟล์เสียหรือโค้ดผิด แต่ Node.js หาไฟล์ จาก path ที่ให้ไว้ไม่เจอ ให้เริ่มจากรัน pwd และ ls เพื่อเช็กว่าอยู่ใน โฟลเดอร์ที่มีไฟล์นั้นจริงหรือไม่

โหมด REPL

พิมพ์ node เฉย ๆ โดยไม่ใส่ชื่อไฟล์ตามหลัง จะเปิดโหมดโต้ตอบที่เรียกว่า REPL (Read-Eval-Print Loop) พิมพ์โค้ด JavaScript ทีละบรรทัดแล้วเห็นผลลัพธ์ทันที เหมาะกับการทดลองสั้น ๆ โดยไม่ต้องสร้างไฟล์ 

$ node
Welcome to Node.js v22.23.2.
Type ".help" for more information.
> 1 + 1
2
> .exit
$

ออกจาก REPL ได้สองวิธีคือพิมพ์ .exit แล้วกด Enter หรือกด Ctrl + D ที่บรรทัด prompt ว่าง ๆ

สร้างโปรเจกต์ด้วย npm init

โปรเจกต์ Node.js เกือบทุกโปรเจกต์เริ่มต้นด้วยไฟล์ package.json ที่เก็บข้อมูลของโปรเจกต์ ใช้คำสั่ง npm init เพื่อสร้างไฟล์นี้ขึ้นมา แต่ปกติ npm init จะถามคำถามทีละข้อ (ชื่อโปรเจกต์ เวอร์ชัน คำอธิบาย ฯลฯ) เติม flag -y เพื่อข้ามคำถามทั้งหมดแล้วใช้ค่า default ไปเลย เริ่มจากสร้างโฟลเดอร์โปรเจกต์เปล่า ๆ ขึ้นมาก่อน แล้ว cd เข้าไปข้างในให้เรียบร้อยก่อนรัน npm init เสมอ 

$ mkdir hello-node-demo
$ cd hello-node-demo
$ npm init -y
Wrote to /Users/mint/hello-node-demo/package.json:

{
  "name": "hello-node-demo",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC"
}

package.json ที่ได้คือไฟล์ config หลักของโปรเจกต์ เก็บชื่อ เวอร์ชัน สคริปต์ที่รันได้ และรายชื่อ package ที่โปรเจกต์นี้พึ่งพา ทุกโปรเจกต์ Node.js ที่จะเจอในคอร์สถัดไปมีไฟล์นี้เกือบทั้งหมด

ติดตั้ง package ด้วย npm install

ลองติดตั้ง package จากภายนอกสักตัวหนึ่ง เช่น dayjs ซึ่งเป็น library จัดการวันที่

$ npm install dayjs

added 1 package, and audited 2 packages in 906ms

found 0 vulnerabilities

คำสั่งนี้ทำให้เกิดการเปลี่ยนแปลงสามอย่างในโฟลเดอร์โปรเจกต์

  1. โฟลเดอร์ node_modules/ ถูกสร้างขึ้น เก็บโค้ดจริงของ dayjs (และของทุก package ที่ติดตั้งต่อจากนี้) ไว้ข้างใน
  2. package.json มี key dependencies เพิ่มขึ้นมา ระบุว่าโปรเจกต์นี้ต้องใช้ dayjs เวอร์ชันไหน
  3. ไฟล์ package-lock.json ถูกสร้างขึ้นใหม่ เก็บเวอร์ชันที่ติดตั้งจริงแบบละเอียดของทุก package รวมถึง package ที่ dayjs เองก็พึ่งพาอยู่อีกที 
$ ls
node_modules		package-lock.json	package.json

$ cat package.json
{
  "name": "hello-node-demo",
  "version": "1.0.0",
  ...
  "dependencies": {
    "dayjs": "^1.11.21"
  }
}

เพราะ node_modules สร้างใหม่ได้เสมอจาก package.json โปรเจกต์ Node.js ที่ clone มาจากคนอื่น จึงมักไม่มี node_modules ติดมาด้วยเลย (ดูเหตุผลเรื่อง .gitignore ด้านล่าง) วิธี restore ให้ครบคือลบ node_modules ทิ้งแล้วรัน npm install เฉย ๆ โดยไม่ระบุชื่อ package ตามหลัง มันจะอ่าน package.json แล้วติดตั้งทุกอย่างที่ระบุไว้ในนั้นให้ครบเหมือนเดิม 

$ rm -rf node_modules
$ npm install

added 1 package, and audited 2 packages in 660ms

found 0 vulnerabilities

node_modules เป็นโฟลเดอร์ที่ npm generate ขึ้นมาเองทั้งหมด สร้างใหม่ได้เสมอ จากข้อมูลใน package.json ด้วยการรัน npm install อีกครั้ง จึงไม่มีเหตุผลต้อง commit โฟลเดอร์นี้เข้า git เลย และเพราะขนาดของมันมักใหญ่มาก (บาง package เดียวก็ดึง package ย่อยตามมาอีกหลายสิบตัว) โปรเจกต์ Node.js แทบทุกโปรเจกต์จึงมี node_modules อยู่ในไฟล์ .gitignore เป็นบรรทัดแรก ๆ เสมอ ตามหลักการเดียวกับที่เรียนไปแล้วในคอร์ส Git เรื่องไม่ commit ไฟล์ที่ generate ขึ้นมาได้เอง

สคริปต์ใน package.json

package.json มี key scripts ไว้เก็บคำสั่งที่ตั้งชื่อไว้ล่วงหน้า เพิ่ม script ชื่อ start เข้าไปเพื่อสั่งให้รัน index.js 

{
  "scripts": {
    "start": "node index.js"
  }
}

ก่อนจะรันสคริปต์นี้ได้ ต้องมีไฟล์ index.js อยู่จริงก่อน สร้างไฟล์แล้วเปิดด้วย VS Code 

$ touch index.js
$ code index.js

พิมพ์โค้ดบรรทัดนี้ลงไปแล้วบันทึก

console.log("hello from my first node project")

แล้วเรียกใช้ script นี้ด้วย npm run ตามด้วยชื่อ script

$ npm run start

> hello-node-demo@1.0.0 start
> node index.js

hello from my first node project

เมื่อรัน npm run start npm จะเปิด package.json หา script ชื่อ start แล้วนำคำสั่งที่กำหนดไว้มารัน ข้อดีของการใช้ npm run แทนที่จะพิมพ์ node index.js ตรง ๆ คือทุกโปรเจกต์เรียกใช้งานได้ด้วยคำสั่งเดียวกันเป๊ะ ไม่ว่าเบื้องหลังไฟล์ entry point จะชื่ออะไรหรือซับซ้อนแค่ไหนก็ตาม คนที่มาเปิดโปรเจกต์นี้ทีหลังไม่จำเป็นต้องรู้รายละเอียดภายในเลย รู้แค่ว่าพิมพ์ npm run start ก็พอ

หยุด process ด้วย Ctrl + C

บางสคริปต์ไม่จบตัวเองหลังรันเสร็จ เช่น dev server ที่คอยรอรับ request อยู่ตลอด สคริปต์แบบนี้จะค้างอยู่ที่ terminal ไปเรื่อย ๆ โดยตั้งใจ ไม่ได้แปลว่าค้างเพราะพัง วิธีหยุดคือกด Ctrl + C ตามที่เรียนไปแล้วในบทที่ 9 ไม่ใช่ปิดหน้าต่าง terminal ทิ้งตรง ๆ

บน Windows: สคริปต์ใน package.json ของบางโปรเจกต์เขียนด้วยคำสั่งแบบ Unix เช่น rm -rf dist ซึ่งจะรันไม่ผ่านใน Command Prompt แต่รันได้ใน Git Bash หรือ WSL อีกเหตุผลหนึ่งที่คอร์สนี้แนะนำให้ใช้ Git Bash ตลอด

ข้อผิดพลาดที่พบบ่อย: รัน npm install ผิดโฟลเดอร์ เช่นรันที่ home directory แทนที่จะเป็นโฟลเดอร์โปรเจกต์ ทำให้เกิด node_modules แปลกปลอมขึ้นที่ home directory โดยไม่ตั้งใจ เปลืองพื้นที่และสร้างความสับสนภายหลัง ก่อนรัน npm install ทุกครั้งควรเช็ก pwd ก่อนเสมอว่ากำลังยืนอยู่ในโฟลเดอร์โปรเจกต์จริง ๆ

อีกข้อผิดพลาดที่พบบ่อยไม่แพ้กันคือ commit โฟลเดอร์ node_modules เข้า git โดยลืมเช็ก .gitignore ก่อน ทำให้ repository บวมขึ้นมหาศาลโดยไม่จำเป็น เพราะ node_modules สร้างขึ้นใหม่ได้เสมอจาก package.json ไม่มีเหตุผลต้องเก็บไว้ใน git เลย

แบบฝึกหัด

สร้างโปรเจกต์ขึ้นมาใหม่ทั้งหมดตั้งแต่ศูนย์ สร้างโฟลเดอร์ชื่อ hello-node เข้าไปข้างใน รัน npm init -y สร้างไฟล์ index.js ที่ print ข้อความทักทายอะไรก็ได้หนึ่งบรรทัด เพิ่ม start script เข้าไปใน package.json แล้วรันด้วย npm run start

ดูเฉลย

npm init -y ข้ามคำถามทั้งหมดแล้วใช้ค่า default ทันที ผลคือได้ package.json พร้อมใช้งานโดยไม่ต้องรอตอบทีละข้อ ส่วน start script ก็เป็นแค่คำสั่งที่บันทึกชื่อไว้ล่วงหน้าเฉย ๆ ไม่มีอะไรพิเศษ เหตุผลที่ควรใช้ npm run start แทนการพิมพ์ node index.js ตรง ๆ คือถ้าวันหนึ่ง entry point ของโปรเจกต์เปลี่ยนชื่อไฟล์หรือย้ายตำแหน่ง แค่แก้ script ใน package.json ที่เดียว คนอื่นที่เรียกใช้ด้วย npm run start เหมือนเดิมจะไม่ได้รับ ผลกระทบเลย ไม่ต้องมีใครมาจำใหม่ว่าต้องพิมพ์คำสั่งอะไร 

$ mkdir hello-node
$ cd hello-node
$ npm init -y
$ touch index.js
$ code .

หลังจากพิมพ์ console.log("hello from my first node project") ลงใน index.js และเพิ่ม start script แล้ว 

$ npm run start

> hello-node@1.0.0 start
> node index.js

hello from my first node project

สองบรรทัดที่ขึ้นต้นด้วย > ในผลลัพธ์ (> hello-node@1.0.0 start และ > node index.js) เป็นข้อความที่ npm พิมพ์ออกมาเองเพื่อบอกว่ากำลังจะรัน script ไหนด้วย คำสั่งอะไร ไม่ใช่ผลลัพธ์จากโปรแกรมของเรา บรรทัดสุดท้าย hello from my first node project เท่านั้นที่มาจาก console.log ในไฟล์ index.js จริง ๆ

ก้าวต่อไป

ถึงตรงนี้คุณมีทักษะ terminal ที่จำเป็นสำหรับคอร์ส Node.js แล้ว ตั้งแต่การเดินทางในระบบไฟล์ จัดการไฟล์ อ่าน environment variable และ PATH ไปจนถึงติดตั้ง Node.js และรันโปรเจกต์ npm ต่อไปก็พร้อมลงมือเขียน Node.js ในคอร์สถัดไป
