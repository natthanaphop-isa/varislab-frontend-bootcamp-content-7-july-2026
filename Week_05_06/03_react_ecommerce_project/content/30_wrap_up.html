บทเรียน 30 · ส่งท้าย (Wrap Up)

Build, Deploy และยินดีด้วย!

Wrap Up

มาถึงบทสุดท้ายแล้ว! ตอนนี้คุณมีเว็บ E-commerce ที่ทำงานครบทุก flow พร้อมชุดเทสต์ที่พิสูจน์ว่ามันทำงานจริง เหลือขั้นตอนเดียว: ทำให้มันขึ้นไปอยู่บนอินเทอร์เน็ตให้คนอื่นใช้ได้

ตรวจสุขภาพโปรเจกต์รอบสุดท้าย

ก่อน build ทุกครั้ง รันเช็กลิสต์คุณภาพให้ครบ นี่คือชุดคำสั่งเดียวกับที่ CI ของทีมจริงจะรันให้อัตโนมัติทุกครั้งที่มีคน push โค้ด:

npm run typecheck   # TypeScript ตรวจ type ทั้งโปรเจกต์
npm run lint        # ESLint ตรวจคุณภาพโค้ด
npm run format:check # Prettier ตรวจรูปแบบโค้ด
npm run test        # เทสต์ทั้งหมดต้องเขียว

ถ้าทั้งสี่คำสั่งผ่านหมด ก็พร้อม build:

npm run build

สังเกตว่าใน package.json ของเรา script นี้คือ tsc -b && vite build — TypeScript ตรวจ type ก่อน แล้ว Vite ค่อยแปลงและบีบอัดโค้ดทั้งหมดลงโฟลเดอร์ dist/: JavaScript ถูก minify, SCSS กลายเป็น CSS ไฟล์เดียว, ชื่อไฟล์มี hash ต่อท้ายเพื่อให้ browser cache ได้อย่างปลอดภัย ลองเปิดโฟลเดอร์ dist/ ดูว่าข้างในมีอะไรบ้าง

ทดลองรันเวอร์ชัน production บนเครื่องเราก่อน deploy จริงได้ด้วย:

npm run preview
💡 npm run dev กับ npm run preview ต่างกันสำคัญ: dev รันจาก source โดยตรงพร้อม hot reload ส่วน preview เสิร์ฟไฟล์ที่ build แล้วจาก dist/ จริง ๆ — ปัญหาบางอย่าง (เช่น path รูปภาพผิด หรือ environment variable หาย) โผล่เฉพาะตอน build แล้วเท่านั้น เจอใน preview ดีกว่าเจอบน production

Deploy แบบ SPA

แอปของเราเป็น Single Page Application: มีไฟล์ HTML จริงแค่ไฟล์เดียว แล้ว react-router จัดการ URL ทั้งหมดในฝั่ง browser นั่นแปลว่าตอน deploy มีกับดักหนึ่งที่เจอกันทุกคน: ถ้าผู้ใช้เปิด https://your-app.com/categories ตรง ๆ (หรือกด refresh) server จะมองหาไฟล์ /categories ซึ่งไม่มีอยู่จริง แล้วตอบ 404

ทางแก้คือบอก server ว่า "ทุก URL ที่หาไฟล์ไม่เจอ ให้ส่ง index.html กลับไป" แล้วปล่อยให้ react-router ตัดสินใจว่าจะแสดงหน้าไหน ผู้ให้บริการ hosting ยุคนี้ทำให้เรื่องนี้ง่ายมาก:

  • Vercel — ตรวจพบ Vite อัตโนมัติ แค่ npx vercel หรือเชื่อม GitHub repo ก็จบ SPA fallback ถูกตั้งให้เอง
  • Netlify — ลาก dist/ ไปวางบนหน้าเว็บก็ได้ หรือเชื่อม repo แล้วเพิ่มไฟล์ public/_redirects ที่มีบรรทัดเดียว: /*  /index.html  200
  • GitHub Pages — ใช้ได้แต่ต้องตั้ง base path และทำ 404 fallback เอง เหมาะกับคนอยากเข้าใจกลไกมากกว่าอยากเสร็จเร็ว

อย่าลืมเรื่อง environment variable: ค่า VITE_API_BASE_URL ถูกฝังลงในโค้ดตอน build ไม่ใช่ตอนรัน ดังนั้นถ้า deploy ผ่าน CI ของ Vercel/Netlify ให้ไปตั้งค่านี้ในหน้า Environment Variables ของโปรเจกต์ด้วย (ค่าเดียวกับใน .env ของเรา: https://dummyjson.com)

สิ่งที่คุณสร้างมาตลอด 30 บท

ถอยออกมามองภาพรวมกันหน่อยว่าตลอดคอร์สนี้คุณผ่านอะไรมาบ้าง:

  • วางรากฐานโปรเจกต์แบบมืออาชีพ — Vite + TypeScript strict, ESLint 10 flat config, Prettier, path alias และโครงสร้างโฟลเดอร์แบบ feature-based ที่โค้ดทุกไฟล์รู้ที่อยู่ของตัวเอง
  • ชั้นข้อมูลที่เป็นระบบ — axios client ตัวเดียวที่ normalize error ให้ทั้งแอป, typed API functions และ query key factory + queryOptions ที่ทำให้ TanStack Query แสดงพลังเต็มที่ทั้ง cache, keepPreviousData และ declarative data ไม่มี useEffect + refetch() ให้เห็นเลยสักที่
  • UI ที่ประกอบจากชิ้นส่วน — shared components ที่ถูกใช้ซ้ำทุกหน้า, SCSS Modules ที่ไม่มีทาง class ชนกัน และหน้า Home/Category/Product ที่จัดการทั้ง loading, error และ empty state ครบ
  • Client state ที่ถูกออกแบบ — ตะกร้าสินค้าด้วย Context + useReducer + localStorage: reducer ที่เทสต์ได้ล้วน ๆ, lazy initializer และ write-through persistence
  • ฟอร์มระดับ production — react-hook-form + zod ที่ schema เดียวให้ทั้ง validation และ TypeScript type, mutation flow ที่สั่งซื้อ เคลียร์ตะกร้า และนำทางต่ออย่างถูกลำดับ
  • ชุดเทสต์ครบทุกชั้น — unit tests ของ pure functions, hook tests ผ่าน MSW ที่จำลอง network จริง และ integration tests ที่เล่นบทผู้ใช้ตั้งแต่เปิดหน้าจนจ่ายเงินสำเร็จ

ที่สำคัญกว่าตัวแอปคือนิสัยที่คุณได้ฝึก: แยก server state ออกจาก client state, ทำ error ให้เป็นเรื่องปกติที่ต้องออกแบบ ไม่ใช่เรื่องเซอร์ไพรส์, เขียน type ให้ตรงกับความจริง และพิสูจน์พฤติกรรมด้วยเทสต์ก่อนจะเชื่อว่ามันเสร็จ — สี่อย่างนี้คือสิ่งที่แยกมือใหม่ออกจากคนที่ทีมอยากได้ตัว

ก้าวต่อไป

  • ต่อยอดแอปนี้ — เพิ่มช่องค้นหาสินค้า (dummyjson มี endpoint /products/search ให้แล้ว), ทำ URL ให้จำ category และหน้าที่เลือกไว้ (query params), เพิ่มระบบ favorite หรือเปลี่ยน react-modal เป็น <dialog> ของ HTML แท้ ๆ
  • ยกระดับ state — ถ้าตะกร้าเริ่มซับซ้อนกว่านี้ ลอง Zustand หรือ Redux Toolkit แล้วเปรียบเทียบกับ Context + useReducer ที่เราเขียนเอง จะเข้าใจทันทีว่าเครื่องมือพวกนี้แก้ปัญหาอะไร
  • ไปฝั่ง server — Next.js หรือ React Router framework mode จะพา React ไป render บน server ซึ่งเป็นโลกที่ต่อจากคอร์สนี้พอดี
  • สร้างโปรเจกต์ของตัวเอง — เลือกไอเดียที่คุณอยากใช้เองจริง ๆ แล้วเริ่มจาก npm create vite เหมือนบทที่ 2 ทุกขั้นตอนที่เราเดินมาด้วยกัน คุณเดินเองได้แล้วทั้งหมด

ขอบคุณที่อดทนพิมพ์โค้ดเองทุกบรรทัดตลอด 30 บท ยินดีด้วยจริง ๆ — คุณไม่ได้แค่ "เรียน React จบ" แต่คุณสร้างเว็บจริงเสร็จทั้งเว็บด้วยมือตัวเองแล้ว 🎉
