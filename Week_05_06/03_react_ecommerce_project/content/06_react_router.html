บทเรียน 06 · โครงแอปและเราเตอร์ (App Shell & Routing)

ตั้งค่า routing ด้วย react-router 8 (data mode)

react-router 8

ตอนนี้โปรเจกต์ของเรามีโครงสร้างโฟลเดอร์ครบแล้ว แต่ยังแสดงได้แค่หน้าเดียว เว็บ E-commerce ของเรามีถึง 6 หน้า — Home, Category, Product detail, Cart, Checkout และ Order Success — ผู้ใช้ต้องเดินไปมาระหว่างหน้าเหล่านี้ได้ด้วย URL ที่กด back/forward และ bookmark ได้จริง นั่นคือหน้าที่ของ router และในบทนี้เราจะวางมันให้เสร็จทั้งระบบ

ทำไมต้อง react-router

ในคอร์ส React พื้นฐาน คุณใช้ TanStack Router มาแล้ว ดังนั้นแนวคิดทั้งหมดของบทนี้คุณรู้จักอยู่แล้ว: แอปมี route หลายเส้น แต่ละเส้นจับคู่ URL กับ component, มี layout ที่ครอบทุกหน้า และมี <Outlet /> เป็นช่องว่างที่หน้าปัจจุบันจะถูกเสียบเข้าไป คราวนี้เราจะใช้ react-router ซึ่งเป็น router ที่แพร่หลายที่สุดในโลก React — โอกาสสูงมากที่โปรเจกต์แรกในงานจริงของคุณจะใช้ตัวนี้ การได้ลองทั้งสองตัวจะทำให้คุณเห็นชัดว่าสิ่งที่คุณเข้าใจคือแนวคิดของ routing ไม่ใช่แค่ API ของ library ใดตัวหนึ่ง

เทียบของที่คุณรู้จักจาก TanStack Router กับของที่กำลังจะเจอ:

  • createRouter + route tree → ที่นี่คือ createBrowserRouter + array ของ RouteObject
  • root route ที่ครอบทุกหน้า → ที่นี่คือ layout route (route ที่มี element แต่ไม่มี path และมี children)
  • <Outlet /> → ชื่อเดียวกัน หน้าที่เดียวกันเป๊ะ
  • <RouterProvider router={router} /> → ชื่อเดียวกันอีกเช่นกัน
  • dynamic segment $postId → ที่นี่เขียนเป็น :id

react-router รุ่นปัจจุบันมีโหมดการใช้งานหลายแบบ เราจะใช้ data mode คือสร้าง router ด้วย createBrowserRouter จาก object ที่บรรยาย route ทั้งหมด แทนการเขียน <Routes><Route> ซ้อนกันใน JSX แบบรุ่นเก่า ข้อดีคือ route กลายเป็นข้อมูลที่อยู่ในไฟล์เดียว อ่านผังทั้งเว็บได้ในสิบวินาที และปลดล็อกความสามารถระดับ router เช่น errorElement ที่เราจะใช้ในบทนี้

ติดตั้ง react-router

npm i react-router
🚨 สังเกตชื่อ package ให้ดี: react-router เฉย ๆ ไม่ใช่ react-router-dom — ตั้งแต่เวอร์ชัน 7 เป็นต้นมาทุกอย่างถูกรวมเข้า package เดียวแล้ว บทความและคำตอบเก่า ๆ ใน Stack Overflow จำนวนมากยังสอนให้ลง react-router-dom อยู่ ถ้าเผลอทำตามคุณจะได้ package ซ้ำซ้อนมาโดยไม่จำเป็น และอีกเรื่อง: react-router 8 กำหนด Node ขั้นต่ำไว้ที่ 22.22 ถ้าคำสั่งติดตั้งฟ้อง engine error ให้กลับไปเช็ค node -v แล้ว nvm use ตามที่ตั้งค่าไว้ในบทที่ 02

ย้าย App.tsx เข้าบ้านใหม่

ตามสถาปัตยกรรมที่วางไว้ในบทที่แล้ว ของที่เป็น "ระดับแอป" ทั้งหมด — ตัวแอป, router, layout, providers — ต้องอยู่ใน src/app/ แต่ตอนนี้ App.tsx ของเรายังนอนอยู่ที่ src/App.tsx จากตอน scaffold ย้ายมันเข้าที่กันก่อน:

mv src/App.tsx src/app/App.tsx

พอย้ายแล้ว import ใน main.tsx ก็พังทันที (TypeScript ฟ้องให้เห็นเลยว่าการย้ายไฟล์ไม่ใช่เรื่องเงียบ ๆ) — แก้ path ให้ชี้ตำแหน่งใหม่ ไฟล์ src/main.tsx ณ จุดนี้ทั้งไฟล์เป็นแบบนี้:

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import "./styles/main.scss";
import App from "./app/App";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);

ไฟล์นี้จะนิ่งอยู่แบบนี้ไปอีกนาน — จะมีของมาเพิ่มอีกครั้งเดียวคือบรรทัด import CSS ของ react-loading-skeleton ในบทที่ 15

สร้างหน้า stub ทั้งหกหน้า

Router ต้องรู้ว่าแต่ละ URL จะแสดง component ตัวไหน แต่หน้าจริง ๆ ของเรายังไม่มีสักหน้า เราจะใช้เทคนิคที่ทีมพัฒนาจริงใช้กันตลอด: สร้าง stub — component เปล่า ๆ ที่มีแค่ชื่อหน้า — เพื่อให้โครงของระบบ routing ทำงานครบวงจรได้ก่อน แล้วค่อยกลับมาเติมเนื้อแต่ละหน้าในบทของมันเอง วิธีนี้ทำให้เราทดสอบ router ได้ทันทีโดยไม่ต้องรอหน้าไหนเสร็จ

สร้างโฟลเดอร์ของแต่ละหน้าใน src/pages/ (ถ้าบางโฟลเดอร์มีอยู่แล้วจากบทที่ 05 คำสั่ง -p จะข้ามให้เอง):

mkdir -p src/pages/Home src/pages/Category src/pages/Product src/pages/Cart src/pages/Checkout src/pages/Order

แล้วสร้างไฟล์ทั้งหกตามนี้ — src/pages/Home/Home.tsx (หน้านี้จะกลายเป็นหน้าจริงในบทที่ 16):

export default function Home() {
  return <h1>Home</h1>;
}

src/pages/Category/Category.tsx (เป็นหน้าจริงบทที่ 17):

export default function Category() {
  return <h1>Category</h1>;
}

src/pages/Product/Product.tsx (เป็นหน้าจริงบทที่ 18):

export default function Product() {
  return <h1>Product</h1>;
}

src/pages/Cart/Cart.tsx (เป็นหน้าจริงบทที่ 21):

export default function Cart() {
  return <h1>Cart</h1>;
}

src/pages/Checkout/Checkout.tsx (เป็นหน้าจริงบทที่ 25):

export default function Checkout() {
  return <h1>Checkout</h1>;
}

และ src/pages/Order/OrderSuccess.tsx (เป็นหน้าจริงบทที่ 25 เช่นกัน):

export default function OrderSuccess() {
  return <h1>Order Success</h1>;
}

สังเกตว่าแต่ละหน้าได้โฟลเดอร์ของตัวเอง (src/pages/Home/Home.tsx ไม่ใช่ src/pages/Home.tsx) — เพราะอีกไม่นานแต่ละหน้าจะมีไฟล์ .module.scss, เทสต์ และ components ย่อยของตัวเองมาอยู่ข้าง ๆ ตามหลัก colocation ที่คุยกันในบทที่แล้ว

ErrorMessage: คอมโพเนนต์แสดงข้อผิดพลาด

ก่อนสร้าง router เราต้องเตรียมของอีกสองชิ้น ชิ้นแรกคือ component กลางสำหรับแสดงข้อความ error ซึ่งไม่ใช่ของเฉพาะระบบ routing — หน้า Home, Category และ Product ก็จะใช้มันเวลาโหลดข้อมูลไม่สำเร็จ มันจึงควรอยู่ใน src/shared/components/ สร้างไฟล์ src/shared/components/ErrorMessage/ErrorMessage.tsx:

import React from "react";

interface ErrorMessageProps {
  message?: string;
}

const ErrorMessage: React.FC<ErrorMessageProps> = ({
  message = "Something went wrong. Please try again.",
}) => {
  return (
    <div role="alert" className="text-center pt-30 pb-30">
      <p className="fs-18 text-muted">{message}</p>
    </div>
  );
};

export default ErrorMessage;

สามจุดที่น่าสนใจในไฟล์สั้น ๆ นี้:

  • message? เป็น optional prop พร้อม default value — ที่ไหนอยากใช้ข้อความมาตรฐานก็เขียนแค่ <ErrorMessage /> ได้เลย ที่ไหนมีข้อความเฉพาะก็ส่งมา
  • role="alert" บอก screen reader ว่านี่คือข้อความสำคัญที่ควรอ่านให้ผู้ใช้ฟังทันทีที่ปรากฏ — accessibility ไม่ใช่ของแถม แต่เป็นส่วนหนึ่งของการ "ทำให้ถูกวิธี"
  • class ทั้งหมด (text-center, pt-30, fs-18, text-muted) คือ utility classes ที่เราเขียนไว้เองในบทที่ 04 — component เล็กแบบนี้ไม่จำเป็นต้องมี .module.scss ของตัวเอง

RouteErrorFallback และ errorElement

ชิ้นที่สองคือหน้าที่จะแสดงเมื่อระบบ routing เองมีปัญหา เช่น ผู้ใช้พิมพ์ URL ที่ไม่มีอยู่จริง หรือ component ของหน้าไหนสักหน้า throw error ระหว่าง render ถ้าไม่มีตัวรับ ผู้ใช้จะเจอหน้าขาวเปล่าหรือหน้า error ดิบ ๆ ของ react-router ซึ่งทั้งสองแบบไม่ใช่สิ่งที่เว็บจริงควรปล่อยให้เกิด สร้าง src/app/RouteErrorFallback.tsx:

import { isRouteErrorResponse, useRouteError } from "react-router";
import ErrorMessage from "@/shared/components/ErrorMessage/ErrorMessage";

export default function RouteErrorFallback() {
  const error = useRouteError();
  const message = isRouteErrorResponse(error)
    ? `${error.status} ${error.statusText}`
    : "Something went wrong. Please reload the page.";

  return (
    <div className="container pt-60 pb-60">
      <ErrorMessage message={message} />
    </div>
  );
}

หลักการทำงาน: เดี๋ยวเราจะผูก component นี้เข้ากับ router ผ่าน property ชื่อ errorElement เมื่อเกิด error ที่ route ไหนก็ตาม react-router จะ render component นี้แทนหน้าปกติ แล้วภายใน component เราเรียก hook useRouteError() เพื่อดึงตัว error ออกมาดู

แต่ error มีสองพันธุ์: ถ้าเป็น error ที่ router สร้างเอง (เช่น 404 จาก URL ที่ไม่ match route ไหนเลย) มันจะมีรูปร่างมาตรฐานที่มี status และ statusText — ฟังก์ชัน isRouteErrorResponse() เป็น type guard สำหรับเช็คกรณีนี้ พอเช็คผ่าน TypeScript ก็ยอมให้เราอ่าน error.status ได้อย่างปลอดภัย ส่วน error พันธุ์อื่น (โค้ดเรา throw เอง) เราไม่รู้รูปร่างของมัน จึงแสดงข้อความกลาง ๆ แทน — สังเกตว่าเราไม่เอา error ดิบไปแปะหน้าจอ เพราะข้อความ error ภายในอาจมีรายละเอียดที่ผู้ใช้ไม่ควรเห็น

MainLayout: โครงที่ทุกหน้าใช้ร่วมกัน

ทั้ง 6 หน้าของเราจะมีโครงเดียวกัน: Header อยู่บนสุด เนื้อหาของหน้าอยู่ตรงกลาง Footer อยู่ล่างสุด เราไม่เขียนโครงนี้ซ้ำในทุกหน้า แต่เขียนครั้งเดียวเป็น layout component แล้วให้ router เสียบหน้าปัจจุบันเข้ามาตรงกลางผ่าน <Outlet /> — แบบเดียวกับ root route ของ TanStack Router ที่คุณใช้ในคอร์ส React พื้นฐาน ไม่มีผิด

สร้าง src/app/layouts/MainLayout/MainLayout.module.scss:

.container {
  display: flex;
  flex-direction: column;
  min-height: 100vh;
}

.main {
  flex-grow: 1;
}

สองกฎนี้คือสูตรคลาสสิกชื่อ "sticky footer": ตัว container เป็น flex column ที่สูงอย่างน้อยเต็มจอ (min-height: 100vh) และส่วนเนื้อหากลางถูกสั่งให้ flex-grow: 1 คือยืดกินพื้นที่ที่เหลือทั้งหมด ผลคือหน้าที่เนื้อหาสั้น ๆ Footer ก็ยังถูกดันไปอยู่ขอบล่างของจอเสมอ ไม่ลอยขึ้นมากลางหน้า

แล้วสร้าง src/app/layouts/MainLayout/MainLayout.tsx:

import React from "react";
import { Outlet } from "react-router";
import styles from "./MainLayout.module.scss";

const MainLayout: React.FC = () => {
  return (
    <div className={styles.container}>
      <main className={styles.main}>
        <Outlet />
      </main>
    </div>
  );
};

export default MainLayout;
💡 นี่คือ MainLayout เวอร์ชันแรก — ยังไม่มี Header กับ Footer เพราะเรายังไม่ได้สร้างมัน บทหน้า (บทที่ 07) เราจะสร้างทั้งสองตัวแล้วกลับมาเติมใน layout นี้ ตอนนี้ขอแค่โครง <Outlet /> ทำงานได้ก่อน

นี่เป็นไฟล์แรกของโปรเจกต์ที่ใช้ SCSS Module จริง ๆ สังเกต pattern ให้ดีเพราะเราจะใช้ซ้ำตลอดทั้งคอร์ส: ตั้งชื่อไฟล์ลงท้าย .module.scss, import เข้ามาเป็น object ชื่อ styles, แล้วอ้าง class ผ่าน styles.container — ตอน build ชื่อ class จะถูกแปลงเป็นชื่อไม่ซ้ำใคร (เช่น _container_x7f2k) ดังนั้นต่อให้ไฟล์อื่นมี class ชื่อ .container เหมือนกันก็ไม่มีทางชนกัน

ประกอบทุกอย่างใน router.tsx

ของครบแล้ว — ได้เวลาประกอบร่าง สร้าง src/app/router.tsx:

import { createBrowserRouter, RouteObject } from "react-router";
import RouteErrorFallback from "./RouteErrorFallback";
import MainLayout from "@/app/layouts/MainLayout/MainLayout";
import Home from "@/pages/Home/Home";
import Category from "@/pages/Category/Category";
import Product from "@/pages/Product/Product";
import Cart from "@/pages/Cart/Cart";
import Checkout from "@/pages/Checkout/Checkout";
import OrderSuccess from "@/pages/Order/OrderSuccess";

export const routes: RouteObject[] = [
  {
    element: <MainLayout />,
    errorElement: <RouteErrorFallback />,
    children: [
      { path: "/", element: <Home /> },
      { path: "/categories", element: <Category /> },
      { path: "/products/:id", element: <Product /> },
      { path: "/cart", element: <Cart /> },
      { path: "/checkout", element: <Checkout /> },
      { path: "/order/success", element: <OrderSuccess /> },
    ],
  },
];

export const router = createBrowserRouter(routes);

ไฟล์นี้คือแผนที่ทั้งเว็บของเรา ไล่ดูทีละส่วน:

  • RouteObject[] — เราประกาศ type ให้ array ชัด ๆ เพื่อให้ TypeScript ตรวจทุก route ให้: สะกด property ผิด ใส่ element เป็นอย่างอื่นที่ไม่ใช่ JSX หรือลืม path ก็โดนเส้นแดงทันที
  • Layout route — route ตัวนอกสุดมี element เป็น <MainLayout /> แต่ไม่มี path แปลว่ามันไม่จับคู่กับ URL ไหนเป็นพิเศษ แต่ครอบทุก route ที่อยู่ใน children — ทุกหน้าจะถูก render แทนที่ <Outlet /> ข้างใน MainLayout เสมอ
  • errorElement — วางไว้ที่ route นอกสุด error จากทุกหน้าจึงลอยขึ้นมาถึงตัวนี้ รวมถึงกรณี URL ไม่ match route ไหนเลย (ได้ 404) ด้วย
  • /products/:id — :id คือ dynamic segment: /products/1, /products/42 หรือ /products/อะไรก็ตาม จะเข้า route นี้ทั้งหมด โดยค่าที่อยู่ตรงตำแหน่งนั้นจะถูกเก็บเป็น param ชื่อ id ซึ่งหน้า Product จะอ่านผ่าน hook useParams() ในบทที่ 18 (ฝั่ง TanStack Router คุณเคยเขียนสิ่งเดียวกันนี้ว่า $id)
  • ทำไม export routes แยกจาก router — ตัวแอปจริงใช้ router ที่สร้างจาก createBrowserRouter (ผูกกับ History API ของเบราว์เซอร์) แต่ตอนเขียนเทสต์ในบทที่ 26 เราจะเอา array routes ตัวเดียวกันนี้ไปสร้าง router แบบ in-memory ด้วย createMemoryRouter แทน — ประกาศผังเว็บครั้งเดียว ใช้ได้ทั้งแอปจริงและเทสต์

App.tsx เวอร์ชันแรก

สุดท้าย เปิด src/app/App.tsx แล้วแทนที่ของเดิมทั้งไฟล์ด้วยหน้าที่เดียวของมันตอนนี้: ส่ง router เข้าไปให้ React render

import { RouterProvider } from "react-router/dom";
import { router } from "./router";

function App() {
  return <RouterProvider router={router} />;
}

export default App;

จุดที่มักสะดุด: RouterProvider ถูก import จาก react-router/dom ไม่ใช่ react-router ตรง ๆ — subpath /dom คือ entry สำหรับแอปที่รันบนเบราว์เซอร์ (ตัวมันใช้ความสามารถของ react-dom ในการอัปเดตหน้าจอให้ทันจังหวะ) ส่วน package หลัก react-router เก็บของที่ใช้ได้ทุกสภาพแวดล้อมอย่าง createBrowserRouter, Outlet และ hooks ต่าง ๆ

และเหมือน MainLayout — นี่คือ App.tsx เวอร์ชันแรก: ในบทที่ 08 เราจะสร้าง AppProviders มาครอบ RouterProvider อีกชั้นเพื่อเปิดใช้ TanStack Query ทั่วทั้งแอป

💡 เปิดเบราว์เซอร์แล้วลองเข้าทีละ URL: / ต้องเห็นคำว่า Home, /categories เห็น Category, /products/1 เห็น Product, /cart เห็น Cart, /checkout เห็น Checkout และ /order/success เห็น Order Success — ครบทั้งหกแปลว่า router ต่อติดทุกเส้น จากนั้นลองพิมพ์ URL มั่ว ๆ เช่น /banana ต้องเห็นข้อความ 404 Not Found จาก RouteErrorFallback ไม่ใช่หน้าขาวเปล่า ถ้าจุดไหนไม่ตรงตามนี้ อย่าเพิ่งไปต่อ — เช็คว่า path ใน router.tsx สะกดตรงกับที่พิมพ์ และทุกหน้า stub ถูก export default ครบ

โครงกระดูกของเว็บยืนได้แล้ว แต่ทุกหน้ายังโล่ง ๆ ไม่มีหัวไม่มีท้าย บทหน้าเราจะเติม Header และ Footer ให้มันดูเป็นเว็บจริงเสียที

ก่อนหน้า: สถาปัตยกรรม Feature-based สารบัญบทเรียน ถัดไป: Header และ Footer
