Product List Components

ยินดีด้วย — คุณมาถึงช่วงที่สนุกที่สุดของคอร์สแล้ว ตอนนี้เรามีครบทุกอย่างที่หน้าเพจต้องใช้: โครงแอปกับ router, คอมโพเนนต์กลางอย่าง Button และ Pagination และชั้นข้อมูลสินค้าที่จบด้วย query factory ในบทที่แล้ว จากบทนี้ไปอีกสี่บท เราจะเอาทั้งหมดนั้นมาประกอบเป็นหน้าเพจจริง: Home, Category และ Product detail

แต่ก่อนจะสร้างหน้า Home ในบทถัดไป สังเกตว่าทั้งหน้า Home และหน้า Category ต่างต้องแสดงรายการสินค้าเป็นการ์ดและเมนูหมวดหมู่เหมือนกันเป๊ะ ถ้าเราเขียน markup ชุดนั้นซ้ำในทั้งสองหน้า วันที่ต้องแก้ดีไซน์การ์ดเราจะต้องแก้สองที่ (แล้วก็จะลืมแก้สักที่หนึ่งแน่นอน) บทนี้เราเลยจะสร้างชิ้นส่วนที่ใช้ร่วมกันเหล่านี้ก่อนหนึ่งบทเต็ม: utility คำนวณราคา, ProductCard, ProductsList และ CategoryMenu

💡 บทนี้จะยังไม่มีอะไรใหม่ปรากฏบนหน้าจอ เพราะคอมโพเนนต์ที่สร้างยังไม่ถูกเรียกใช้จากหน้าไหนเลย — เราจะได้เห็นมันพร้อมกันทั้งหมดตอนประกอบหน้า Home ในบทถัดไป ระหว่างทางใช้ npm run dev กับ npm run typecheck เป็นตัวยืนยันว่าไม่มีอะไรพังก็พอ

price.utils: คำนวณราคาก่อนลด

เปิดข้อมูลสินค้าจาก dummyjson ดูอีกครั้ง (เช่น https://dummyjson.com/products/1) จะเห็นว่า API ให้ราคามาสองส่วน: price ซึ่งเป็นราคาหลังหักส่วนลดแล้ว และ discountPercentage เป็นเปอร์เซ็นต์ส่วนลด แต่หน้าร้านออนไลน์ทั่วไปชอบแสดง "ราคาเต็มขีดฆ่า" คู่กับราคาจริงเพื่อให้เห็นว่าลดไปเท่าไร ปัญหาคือ API ไม่ได้ให้ราคาเต็มมา — เราต้องคำนวณย้อนกลับเอง

คณิตศาสตร์ไม่ยาก: ถ้าราคาเต็มคือ X แล้วลด d เปอร์เซ็นต์ ราคาหลังลดคือ X × (1 - d/100) ดังนั้นย้อนกลับ ราคาเต็มคือ price ÷ (1 - d/100) ลองแทนตัวเลขดู: สินค้าราคา 90 บาทหลังลด 10% → 90 ÷ 0.9 = 100 บาท ตรงตามคาด

การคำนวณแบบนี้เป็น pure function ที่ไม่เกี่ยวกับ React เลย เราจึงเก็บไว้ใน shared/utils ข้าง ๆ pagination.utils.ts จากบทเรียน 13 สร้างไฟล์ src/shared/utils/price.utils.ts:

/**
 * Calculate the original price before the discount.
 * @param {number} price - The discounted price of the product.
 * @param {number | undefined} discountPercentage - The discount percentage (optional).
 * @returns {string} - The original price as a formatted string.
 */
export const calculateOriginalPrice = (
  price: number,
  discountPercentage?: number,
): number => {
  if (
    !discountPercentage ||
    discountPercentage <= 0 ||
    discountPercentage >= 100
  ) {
    return price; // If no discount or invalid discount, return the current price
  }
  return price / (1 - discountPercentage / 100);
};

สังเกต guard clause ก่อนคำนวณ: ถ้าไม่มีส่วนลด (undefined หรือ 0), ส่วนลดติดลบ หรือส่วนลดตั้งแต่ 100% ขึ้นไป (ซึ่งจะทำให้ตัวหารเป็นศูนย์หรือติดลบ — ได้ราคา Infinity หรือราคาติดลบ!) เราคืน price เดิมไปเลย การเช็คขอบเขตข้อมูลก่อนคำนวณแบบนี้เป็นนิสัยที่ดีมากเวลาทำงานกับข้อมูลจาก API ภายนอกที่เราควบคุมไม่ได้ และเพราะมันเป็น pure function เดี่ยว ๆ ในบทเรียน 27 เราจะเขียน unit test ให้มันได้ง่ายมาก

Skeleton screen ด้วย react-loading-skeleton

ตอนนี้เรามี spinner (ClipLoader จาก react-spinners ที่ติดตั้งไปในบทเรียน 09) ไว้ใช้ตอนรอข้อมูลจาก API แล้ว แต่รูปภาพสินค้าเป็นการรอคนละแบบ: ข้อมูล query มาถึงแล้ว การ์ดวาดเสร็จแล้ว แต่ไฟล์รูปยังโหลดไม่เสร็จ ถ้าไม่ทำอะไรเลย การ์ดจะโผล่มาแบบไม่มีรูป แล้วรูปค่อยเด้งตามมาทีหลัง — layout กระตุกไปมาไม่น่าดู

วิธีที่เว็บสมัยใหม่นิยมคือ skeleton screen: วาดกล่องสีเทาวิบวับขนาดเท่าของจริงค้างไว้ก่อน พอของจริงพร้อมค่อยสลับเข้ามาแทนที่ ต่างจาก spinner ตรงที่ skeleton จองพื้นที่ไว้ให้เลย layout จึงไม่ขยับ และผู้ใช้เดาได้ทันทีว่ากำลังรออะไรอยู่ตรงไหน — spinner เหมาะกับ "รอทั้งก้อนใหญ่" ส่วน skeleton เหมาะกับ "รอชิ้นส่วนย่อยที่รู้ขนาดล่วงหน้า" เราจะได้ใช้ทั้งคู่ในโปรเจกต์นี้

ติดตั้ง library:

npm i react-loading-skeleton

react-loading-skeleton ต้องการ CSS ของตัวเองหนึ่งไฟล์ (สีพื้น สีวิบวับ และ animation) ซึ่งควร import ครั้งเดียวที่จุดเริ่มต้นของแอป เปิด src/main.tsx แล้วเพิ่มบรรทัด import ต่อจาก main.scss ไฟล์ฉบับสมบูรณ์กลายเป็น:

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import "./styles/main.scss";
import "react-loading-skeleton/dist/skeleton.css";
import App from "./app/App";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
💡 นี่คือการแก้ main.tsx ครั้งสุดท้ายของคอร์สแล้ว — ไฟล์นี้อยู่ในรูปแบบสุดท้ายตรงกับ repo ต้นฉบับเป๊ะ

ProductCard: การ์ดสินค้าหนึ่งใบ

ถึงคิวการ์ดสินค้า — คอมโพเนนต์ที่จะถูกวาดซ้ำมากที่สุดในแอปนี้ มันเป็นของ feature products โดยตรง (ไม่ใช่ของ shared เพราะมันรู้จักแนวคิด "สินค้า") เราจึงวางไว้ที่ src/features/products/components/ ตามสถาปัตยกรรม feature-based จากบทเรียน 05 สร้างไฟล์ src/features/products/components/ProductCard/ProductCard.tsx:

import React, { useState } from "react";
import Skeleton from "react-loading-skeleton";
import StarReview from "@/shared/components/StarReview/StarReview";

interface ProductCardProps {
  productId: number;
  image: string;
  title: string;
  description: string;
  price: number;
  originalPrice?: number;
  discount?: number;
  rating: number; // Rating out of 10
  reviewsCount: number;
  skeletonHeight?: number;
  onProductClick: (id: number) => void;
}

const ProductCard: React.FC<ProductCardProps> = ({
  image,
  title,
  description,
  price,
  originalPrice,
  discount,
  rating,
  reviewsCount,
  skeletonHeight = 240,
  productId,
  onProductClick,
}) => {
  const [isImageLoaded, setIsImageLoaded] = useState(false);

  return (
    <div
      className={`flex flex-column`}
      onClick={() => onProductClick(productId)}
    >
      <div className="image-container">
        {!isImageLoaded && <Skeleton height={skeletonHeight} />}
        <img
          src={image}
          alt={title}
          style={{
            display: isImageLoaded ? "block" : "none",
          }}
          onLoad={() => {
            setIsImageLoaded(true);
          }}
        />
      </div>

      <div className={`pt-15 pb-15`}>
        <h4 className="fs-18 mb-5 mt-0">{title}</h4>
        <p className="fs-14 text-muted mb-10 mt-0">{description}</p>
        <div className="flex align-item-center mb-15">
          <StarReview score={rating} />
          <span className="fs-12 text-muted ml-5">({reviewsCount})</span>
        </div>
        <p className="fs-20 mb-5">${price.toFixed(2)}</p>
        <div className="flex align-item-center">
          {originalPrice && (
            <span className="fs-14 text-muted text-line-through">
              ${originalPrice.toFixed(2)}
            </span>
          )}
          {discount && (
            <span className="fs-14 fw-medium ml-10 text-primary">
              {discount}% Off
            </span>
          )}
        </div>
      </div>
    </div>
  );
};

export default ProductCard;

มีของให้แกะหลายชิ้นในไฟล์นี้:

  • ไม่มี .module.scss ของตัวเอง — การ์ดใบนี้แต่งตัวด้วย utility classes จาก _utilities.scss ที่เราวางไว้ตั้งแต่บทเรียน 04 ล้วน ๆ (flex, fs-18, text-muted, text-line-through, …) เมื่อ style ที่ต้องใช้มีครบใน utility อยู่แล้ว การไม่สร้างไฟล์ SCSS เปล่า ๆ เพิ่มก็เป็นการตัดสินใจที่ถูก — SCSS module มีไว้สำหรับ style ที่เฉพาะตัวจริง ๆ อย่างที่ CategoryMenu ด้านล่างจะได้ใช้
  • ลูกเล่น skeleton ของรูป — ตราบใดที่ isImageLoaded ยังเป็น false เราวาด <Skeleton height={skeletonHeight} /> ค้างไว้ และซ่อน <img> ด้วย display: "none" จุดสำคัญคือเราซ่อนรูป ไม่ใช่ไม่วาดรูป — ถ้าเขียน {isImageLoaded && <img … />} รูปจะไม่ถูกใส่เข้า DOM เบราว์เซอร์เลยไม่เริ่มโหลด แล้ว onLoad ก็จะไม่มีวันยิง — กลายเป็น skeleton ค้างตลอดกาล พอรูปโหลดเสร็จ เบราว์เซอร์ยิง event onLoad เราตั้ง state เป็น true React วาดใหม่ skeleton หายไป รูปโผล่ขึ้นมาแทนในพื้นที่เดิมพอดี
  • skeletonHeight = 240 — default parameter ให้การ์ดทั่วไปสูง 240px แต่หน้าไหนอยากได้การ์ดเตี้ยหรือสูงกว่านี้ก็ override ผ่าน prop ได้
  • reuse StarReview — ดาวรีวิวที่สร้างไว้ในบทเรียน 11 กลับมาทำงานแล้ว จำ convention ของมันได้ไหม: score เป็นคะแนนเต็ม 10 แล้วภายในหารสองเป็นดาว 5 ดวง คอมเมนต์ // Rating out of 10 ใน props ก็ย้ำเรื่องเดียวกัน
  • onProductClick callback prop — ตอนการ์ดถูกคลิก เราเรียก callback พร้อมส่ง productId กลับไปให้คนที่ใช้การ์ด สังเกตว่า ProductCard ไม่รู้จัก router เลย — มันไม่ import useNavigate ไม่รู้ว่าคลิกแล้วต้องไปหน้าไหน หน้าที่ของมันมีแค่ "แสดงผลและรายงานว่าถูกคลิก" ให้หน้าเพจที่เป็นเจ้าของ ตัดสินใจเรื่อง navigation เอง แบบเดียวกับที่ <button onClick={…}> ไม่รู้ว่า onClick ทำอะไร — คอมโพเนนต์ยิ่งรู้น้อย ยิ่งเอาไปใช้ซ้ำได้กว้าง

ProductsList: จากข้อมูล API สู่แถวของการ์ด

ProductCard รับ props เป็นชิ้น ๆ (image, title, price, …) แต่ข้อมูลจาก query มาเป็น Product[] เต็ม ๆ ตัว เราต้องมีตัวกลางที่ map จากรูปแบบหนึ่งไปอีกรูปแบบหนึ่ง สร้างไฟล์ src/features/products/components/ProductsList/ProductsList.tsx:

import React from "react";
import { Product } from "@/features/products/types";
import ProductCard from "@/features/products/components/ProductCard/ProductCard";
import { calculateOriginalPrice } from "@/shared/utils/price.utils";

interface ProductsListProps {
  products: Product[] | undefined;
  onProductClick: (id: number) => void;
}

const ProductsList: React.FC<ProductsListProps> = ({
  products,
  onProductClick,
}) => {
  return (
    <>
      {products?.map(
        ({
          thumbnail,
          id,
          title,
          brand,
          price,
          discountPercentage,
          rating,
          reviews,
        }) => (
          <div key={id} className="mb-15 pointer">
            <ProductCard
              productId={id}
              image={thumbnail}
              title={title}
              description={brand}
              price={price}
              originalPrice={calculateOriginalPrice(price, discountPercentage)}
              discount={discountPercentage}
              rating={rating}
              reviewsCount={reviews.length}
              onProductClick={onProductClick}
            />
          </div>
        ),
      )}
    </>
  );
};

export default ProductsList;

ประเด็นที่น่าสนใจ:

  • products: Product[] | undefined — จงใจยอมรับ undefined เพราะคนที่จะส่ง prop นี้คือหน้าเพจที่ส่ง data?.products จาก useQuery มาตรง ๆ ซึ่งเป็น undefined ได้เสมอระหว่างรอโหลด optional chaining ใน products?.map(…) จัดการกรณีนั้นให้เงียบ ๆ (ไม่ render อะไรเลย) โดยหน้าเพจไม่ต้องเช็คก่อนส่ง
  • destructuring กลาง parameter ของ map — แทนที่จะรับ (product) => แล้วเขียน product.title, product.price ยาว ๆ เราแตกเฉพาะ field ที่ใช้ออกมาตั้งแต่หน้าประตู อ่านปุ๊บรู้เลยว่าคอมโพเนนต์นี้ใช้ข้อมูลอะไรจาก Product บ้าง
  • แปลงข้อมูลตรงนี้ที่เดียว — calculateOriginalPrice จาก utility เมื่อครู่ถูกเรียกตรงนี้ และ reviews.length ก็ถูกนับตรงนี้ ProductCard เลยได้รับค่าที่พร้อมแสดงผลทันที ไม่ต้องรู้จักโครงสร้าง Product ของ dummyjson เลยแม้แต่นิดเดียว
  • key={id} — ใช้ id จริงของสินค้าเป็น key ตามกฎเหล็กของ list rendering จากคอร์ส React พื้นฐาน ไม่ใช้ index เพราะรายการนี้เปลี่ยนชุดได้ทั้งชุดเวลาสลับหมวดหมู่หรือเปลี่ยนหน้า
💡 สังเกตว่าเมื่อสินค้าไม่มีส่วนลด calculateOriginalPrice คืนราคาเดิมกลับมา การ์ดจึงยังแสดงราคาขีดฆ่าที่เท่ากับราคาจริง — ฟังดูแปลก แต่ในทางปฏิบัติสินค้าของ dummyjson มี discountPercentage ติดมาแทบทุกตัว เคสนี้จึงแทบไม่ปรากฏบนจอ (ส่วนป้าย "% Off" ถูกซ่อนอยู่แล้วด้วย {discount && …} ใน ProductCard)

CategoryMenu: เมนูหมวดหมู่พร้อมไฮไลต์

ชิ้นสุดท้ายของบท: เมนูรายชื่อหมวดหมู่ที่จะยืนอยู่ข้างรายการสินค้าทั้งในหน้า Home และหน้า Category คราวนี้มี style เฉพาะตัวเล็กน้อย (ความกว้างคอลัมน์) เลยได้ SCSS module มาคู่กัน สร้างไฟล์ src/features/products/components/CategoryMenu/CategoryMenu.tsx:

import React from "react";
import styles from "./CategoryMenu.module.scss";
import { Category } from "@/features/products/types";

interface CategoryMenuProps {
  categories: Category[];
  activeCategory: string | undefined;
  onCategoryClick: (category: Category) => void;
}

const CategoryMenu: React.FC<CategoryMenuProps> = ({
  categories,
  activeCategory,
  onCategoryClick,
}) => {
  return (
    <div className={`${styles.categoryMenu} text-right`}>
      {categories.map((cat) => (
        <span
          key={cat.slug}
          className={`nav-link block mb-20 pointer ${
            activeCategory === cat.slug ? "fw-bold text-primary" : ""
          }`}
          onClick={() => onCategoryClick(cat)}
        >
          {cat.name}
        </span>
      ))}
    </div>
  );
};

export default CategoryMenu;

และไฟล์ src/features/products/components/CategoryMenu/CategoryMenu.module.scss:

.categoryMenu {
  width: 16%;
}

สัญญา (contract) ของคอมโพเนนต์นี้ออกแบบมาอย่างจงใจ ลองอ่าน props ทีละตัว:

  • categories: Category[] — รายชื่อหมวดหมู่ทั้งหมด มาจาก query productQueries.categories() ที่เราสร้างไว้ในบทที่แล้ว จำ type Category ได้ไหม: { slug, name, url } — slug คือรหัสสำหรับเรียก API ส่วน name คือชื่อสวย ๆ สำหรับแสดงผล
  • activeCategory: string | undefined — รับเป็น slug ของหมวดที่กำลังเลือกอยู่ ไม่ใช่ทั้ง object เพราะสิ่งเดียวที่เมนูต้องรู้คือ "ตัวไหนต้องไฮไลต์" การเทียบ activeCategory === cat.slug แล้วเติมคลาส fw-bold text-primary คือทั้งหมดของลอจิกไฮไลต์ และการยอมรับ undefined ทำให้หน้าเพจส่งค่าจาก state ที่ยังโหลดไม่เสร็จมาได้เลยโดยไม่ต้อง fallback
  • onCategoryClick: (category: Category) => void — ขาออกกลับส่งทั้ง object คืนให้ ทำไมไม่ส่งแค่ slug? เพราะหน้าเพจที่รับ event ไปต้องใช้มากกว่านั้น — ต้องใช้ slug ยิง query และใช้ name แสดงหัวหน้า การส่ง object เต็มทำให้ผู้ใช้เมนูไม่ต้องไปไล่หา object จาก slug อีกรอบ

แบบแผนเดิมกลับมาอีกครั้ง: CategoryMenu ไม่มี state ของตัวเองเลยสักตัว มันไม่จำว่าหมวดไหนถูกเลือก — หน้าเพจเป็นคนจำ แล้วส่งกลับลงมาผ่าน activeCategory คอมโพเนนต์แบบนี้เรียกกันว่า controlled component (แนวคิดเดียวกับ controlled input จากคอร์ส React พื้นฐาน แค่ขยับมาอยู่ระดับคอมโพเนนต์) ข้อดีคือหน้า Home กับหน้า Category ใช้เมนูตัวเดียวกันได้ทั้งที่พฤติกรรมหลังคลิกไม่เหมือนกันเลย — เดี๋ยวคุณจะได้เห็นในสองบทถัดไป

💡 ตอนนี้โปรเจกต์ควรมีไฟล์ใหม่ 4 ไฟล์ (price.utils.ts, ProductCard.tsx, ProductsList.tsx, CategoryMenu.tsx + SCSS ของมัน) และ main.tsx ที่เพิ่ม import CSS ของ skeleton แล้ว รัน npm run typecheck และ npm run lint ต้องผ่านทั้งคู่ และ npm run dev ต้องยังแสดงแอปได้เหมือนเดิมทุกหน้า ถ้ามี error เรื่อง import path ตรวจ alias @/ และชื่อโฟลเดอร์ให้ตรงตัวพิมพ์ใหญ่-เล็กเป๊ะ ๆ
