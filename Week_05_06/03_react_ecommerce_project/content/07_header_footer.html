Header และ Footer

Header & Footer

ตอนนี้ทุก URL ของเราเปิดได้แล้ว แต่หน้าตายังเป็นแค่ตัวหนังสือลอย ๆ กลางหน้าขาว บทนี้เราจะเติมสองชิ้นส่วนที่ทำให้มัน "ดูเป็นเว็บ" ขึ้นมาทันที: Header ที่มีโลโก้และเมนูนำทางอยู่บนสุดของทุกหน้า และ Footer ที่มีข้อมูลร้านอยู่ล่างสุดของทุกหน้า — และเพราะเราวาง MainLayout ไว้แล้วในบทที่แล้ว ทั้งสองตัวจะเขียนครั้งเดียวแล้วโผล่ครบทุกหน้าโดยอัตโนมัติ

ติดตั้ง Font Awesome

Footer ของเรา (และอีกหลาย component ในบทถัด ๆ ไป) ใช้ไอคอนจาก Font Awesome ซึ่งเป็นชุดไอคอนที่แพร่หลายที่สุดชุดหนึ่งของเว็บ ติดตั้งตาม package.json ของโปรเจกต์จริงให้ครบชุดในครั้งเดียว:

npm i @fortawesome/fontawesome-svg-core @fortawesome/react-fontawesome @fortawesome/free-solid-svg-icons @fortawesome/free-regular-svg-icons @fortawesome/free-brands-svg-icons

ห้า package นี้แบ่งหน้าที่กันชัดเจน:

  • fontawesome-svg-core — เครื่องยนต์กลางที่แปลงข้อมูลไอคอนเป็น SVG
  • react-fontawesome — component <FontAwesomeIcon> สำหรับใช้ใน JSX
  • free-solid-svg-icons / free-regular-svg-icons / free-brands-svg-icons — ตัวไอคอนจริง ๆ สามสไตล์: แบบทึบ แบบเส้น และโลโก้แบรนด์ต่าง ๆ

วันนี้เราใช้แค่ชุด solid ส่วนชุด regular จะได้ใช้ตอนทำดาวรีวิวในบทที่ 11 และหน้า Home ในบทที่ 16 ข้อดีของ Font Awesome ยุคใหม่คือมันเป็น SVG + tree-shaking: เรา import ไอคอนเป็นราย ๆ ตัว ตัวไหนไม่ได้ import ก็ไม่ติดไปกับ bundle — ไม่เหมือนสมัยก่อนที่ต้องโหลดฟอนต์ไอคอนทั้งพันตัวมาเพื่อใช้สามตัว

useProductRoute: รวมเส้นทางไว้ที่เดียว

ก่อนสร้าง Header เราจะสร้าง hook เล็ก ๆ ที่เป็นการตัดสินใจเชิงสถาปัตยกรรมที่ดีมากของโปรเจกต์นี้ ลองนึกภาพ: ปุ่ม "ดูสินค้า" บนการ์ดสินค้า, ปุ่มไอคอนตะกร้าบน Header, ปุ่ม "ไปชำระเงิน" ในหน้า Cart — ทุกจุดต้องสั่ง navigate ไปยัง URL สักเส้น ถ้าแต่ละจุดเขียน navigate(`/products/${id}`) เองกระจัดกระจายทั่วแอป วันที่เราอยากเปลี่ยน URL scheme (เช่น /products/:id เป็น /p/:id) จะต้องไล่แก้ทุกไฟล์แล้วภาวนาว่าไม่ตกหล่นสักที่

ทางแก้คือรวม "เส้นทางที่แอปนี้เดินได้" ไว้ใน hook เดียว สร้าง src/shared/hooks/useProductRoute.tsx:

import { useNavigate } from "react-router";

const useProductRoute = () => {
  const navigate = useNavigate();

  const goToProductDetails = (id: number) => {
    navigate(`/products/${id}`);
  };

  const goToCartSummary = () => {
    navigate("/cart");
  };

  const goToCheckout = () => {
    navigate("/checkout");
  };

  const goToOrderSuccess = () => {
    navigate("/order/success");
  };

  return {
    goToProductDetails,
    goToCartSummary,
    goToCheckout,
    goToOrderSuccess,
  };
};

export default useProductRoute;

useNavigate คือ hook ของ react-router ที่คืนฟังก์ชันสำหรับสั่งเปลี่ยนหน้าออกมา (ฝั่ง TanStack Router ในคอร์ส React พื้นฐาน ก็มี hook ชื่อเดียวกันนี้เลย) สิ่งที่ hook ของเราทำคือห่อมันอีกชั้นให้ได้ประโยชน์สามข้อ:

  • แก้ที่เดียว — URL string ของทุกเส้นทางอยู่ในไฟล์นี้ไฟล์เดียว เปลี่ยนเมื่อไหร่ก็จบในไฟล์เดียว
  • อ่านรู้เรื่อง — จุดที่เรียกใช้เขียนว่า goToProductDetails(id) ซึ่งบอกเจตนา ชัดกว่า navigate(`/products/${id}`) ที่บอกแค่กลไก
  • type-safe — goToProductDetails บังคับรับ id: number จะลืมส่ง id หรือส่งผิด type ก็โดน TypeScript จับตั้งแต่ตอนพิมพ์

ตอนนี้ยังไม่มีใครเรียกใช้มัน — แต่อีกไม่กี่บทมันจะกลายเป็น hook ยอดนิยมของโปรเจกต์: หน้า Home, Category, Cart และตัว Header เอง (ในบทที่ 20) ล้วนต้องใช้

สร้าง Header

สร้าง src/shared/components/Header/Header.tsx:

import React from "react";
import { Link } from "react-router";

const Header: React.FC = () => {
  return (
    <header className="pt-25 pb-25">
      <div className="container">
        <div className="flex space-between align-item-center">
          <Link className="nav-link fw-bold fs-24" to="/">
            My Store
          </Link>

          <nav>
            <ul className="flex gap-20 m-0 p-0 list-none">
              <li>
                <Link to="/" className="nav-link">
                  Home
                </Link>
              </li>
              <li>
                <Link to="/categories" className="nav-link">
                  Products
                </Link>
              </li>
            </ul>
          </nav>
        </div>
      </div>
    </header>
  );
};

export default Header;
💡 นี่คือ Header เวอร์ชันแรก — เว็บ E-commerce จริงต้องมีไอคอนตะกร้าพร้อม badge บอกจำนวนสินค้าอยู่มุมขวา แต่ตัวเลขนั้นต้องอ่านจาก cart state ซึ่งเรายังไม่ได้สร้าง บทที่ 20 เราจะกลับมาเติม component <CartSummary /> ตรงมุมขวานี้ พร้อมเรียก goToCartSummary จาก useProductRoute ที่เพิ่งเขียนไป — เหตุผลที่ยังไม่ใส่บรรทัด useProductRoute() ค้างไว้ตั้งแต่ตอนนี้ ก็เพราะตัวแปรที่ประกาศแล้วไม่ได้ใช้จะโดน ESLint ของเราฟ้องทันที (และมันฟ้องถูกแล้ว)

จุดที่สำคัญที่สุดของไฟล์นี้คือเราใช้ <Link to="..."> ของ react-router ไม่ใช่ <a href="..."> ธรรมดา สองตัวนี้หน้าตาผลลัพธ์เหมือนกัน (Link ก็ render เป็น <a> ใน DOM) แต่พฤติกรรมต่างกันสุดขั้ว:

  • <a href> สั่งเบราว์เซอร์โหลดหน้าใหม่ทั้งหน้า — JavaScript ทั้งแอปถูกโยนทิ้งแล้วเริ่มใหม่หมด state ทุกอย่าง (เช่น ของในตะกร้าที่ยังไม่ได้ save) หายเกลี้ยง แถมผู้ใช้เห็นจอกะพริบ
  • <Link to> ดัก click ไว้แล้วบอก router ให้สลับ component พร้อมอัปเดต URL ผ่าน History API — ไม่มีการโหลดหน้าใหม่ แอปยังมีชีวิตต่อเนื่อง เร็วกว่ากันคนละโลก

กฎจำง่าย: ลิงก์ภายในแอปใช้ Link เสมอ ลิงก์ออกไปเว็บอื่นใช้ <a>

อีกจุดที่ควรสังเกต: Header ไม่มีไฟล์ .module.scss ของตัวเอง เพราะทุกอย่างที่มันต้องการ — ระยะห่าง (pt-25), การจัดแถว (flex space-between align-item-center), หน้าตาลิงก์ (nav-link) — มีครบใน utility classes ที่เราเขียนไว้บทที่ 04 แล้ว หลักคิดคือ สร้างไฟล์ style เมื่อมี style เฉพาะตัวจริง ๆ เท่านั้น ซึ่งเดี๋ยว Footer จะเป็นตัวอย่างของกรณีนั้นพอดี

สร้าง Footer

Footer มี style เฉพาะตัวที่ utility class ไม่ครอบคลุม: พื้นหลังสีเข้มทั้งแถบ สร้าง src/shared/components/Footer/Footer.module.scss:

@use "../../../styles/variables";

.footer {
  background-color: variables.$black02;
  color: variables.$white;

  p {
    line-height: 2;
  }
}

บรรทัด @use ดึงไฟล์ _variables.scss จากบทที่ 04 เข้ามาภายใต้ namespace ชื่อ variables เราจึงอ้างสีกลางของแอปได้ด้วย variables.$black02 แทนการ hardcode #212121 ซ้ำอีกรอบ — สีหลักของแบรนด์เปลี่ยนเมื่อไหร่ Footer ก็เปลี่ยนตามเองโดยไม่ต้องแตะไฟล์นี้

ไฟล์นี้สาธิตวิธีใช้ Font Awesome ครบวงจร: import ตัว component FontAwesomeIcon หนึ่งครั้ง, import ไอคอนที่ต้องการเป็นราย ๆ ตัวจากชุด solid, แล้ววางใน JSX ด้วย <FontAwesomeIcon icon={faPhone} /> — ตัวมัน render ออกมาเป็น SVG จึงคมทุกขนาด และรับ className ได้เหมือน element ปกติ (เราใช้ mr-10 ดันข้อความให้ห่างจากไอคอน)

สังเกตการผสม class สองระบบบนบรรทัด <footer>: `pt-60 pb-60 ${styles.footer}` — utility class จากระบบ global อยู่ร่วมกับ class จาก SCSS Module ได้สบาย ๆ ผ่าน template literal นี่คือ pattern ที่จะเห็นตลอดทั้งโปรเจกต์: ของทั่วไปใช้ utility ของเฉพาะตัวใช้ module

เติม Header/Footer เข้า MainLayout

สองชิ้นส่วนพร้อมแล้ว กลับไปที่ src/app/layouts/MainLayout/MainLayout.tsx เพื่ออัปเกรดจากเวอร์ชันแรกเป็นเวอร์ชันสมบูรณ์ — เพิ่ม import สองบรรทัดและ JSX สองบรรทัด:

import React from "react";
import { Outlet } from "react-router";
import styles from "./MainLayout.module.scss";
import Header from "@/shared/components/Header/Header";
import Footer from "@/shared/components/Footer/Footer";

const MainLayout: React.FC = () => {
  return (
    <div className={styles.container}>
      <Header />
      <main className={styles.main}>
        <Outlet />
      </main>
      <Footer />
    </div>
  );
};

export default MainLayout;

นี่แหละคือผลตอบแทนของการลงทุนทำ layout route ในบทที่แล้ว: เพิ่มโค้ดสี่บรรทัดในไฟล์เดียว แล้วทั้งหกหน้าได้ Header กับ Footer พร้อมกันทันที ไม่ต้องไปตามแปะทีละหน้า และเมื่อผู้ใช้เปลี่ยนหน้า react-router สลับเฉพาะส่วน <Outlet /> ตรงกลาง — Header กับ Footer ไม่ถูก render ใหม่โดยไม่จำเป็น

Checkpoint

💡 รัน npm run dev แล้วไล่เปิดทุก route จากบทที่แล้ว — ทุกหน้าต้องมี Header (โลโก้ My Store + เมนู Home/Products) อยู่บนสุด และ Footer พื้นดำอยู่ล่างสุดติดขอบจอเสมอแม้เนื้อหากลางจะสั้นนิดเดียว (ฝีมือ sticky footer จากบทที่แล้ว) จากนั้นลองคลิกสลับเมนู Home กับ Products ไปมา — หน้าต้องเปลี่ยนโดยจอไม่กะพริบและไม่มีการโหลดหน้าใหม่ ถ้าไม่แน่ใจ เปิด Network tab ของ DevTools ดู: คลิก Link แล้วต้องไม่มี request ของ document ใหม่โผล่มา สุดท้ายอย่าลืมรัน npm run lint ให้ผ่านเงียบ ๆ ก่อนไปบทถัดไป

เว็บของเรามีหน้าตาเป็นเว็บแล้ว ขั้นต่อไปคือวางระบบประปาให้ข้อมูล: ติดตั้ง TanStack Query แล้วประกอบ providers ของทั้งแอป
