ติดตั้ง Swiper

แบนเนอร์ด้านบนสุดของหน้าเป็น carousel — รูปหลายรูปสลับกันเลื่อนอัตโนมัติ พร้อมปุ่มลูกศรและจุดบอกตำแหน่ง การเขียน carousel เองให้ครบทั้ง touch swipe, loop, autoplay และ accessibility เป็นงานใหญ่เกินตัวมาก นี่คือจังหวะที่ควรใช้ library ที่พิสูจน์แล้ว เราใช้ Swiper ซึ่งเป็น carousel library ที่นิยมที่สุดตัวหนึ่งและมี React components ให้ในตัว:

npm i swiper

Banner: carousel ตัวแรกของเรา

Banner เป็นของหน้า Home โดยเฉพาะ ไม่มีหน้าอื่นใช้ เราจึงไม่วางมันใน shared แต่วางเป็นคอมโพเนนต์ลูกของหน้า Home เอง — สังเกต pattern โฟลเดอร์ components ซ้อนอยู่ใต้หน้าเพจ ซึ่งเราจะใช้อีกกับหน้า Category และ Product สร้างไฟล์ src/pages/Home/components/Banner/Banner.tsx:

import React from "react";
import { Swiper, SwiperSlide } from "swiper/react";
import { Navigation, Pagination, Autoplay } from "swiper/modules";

import "swiper/swiper-bundle.css";

const Banner: React.FC = () => {
  const banners = [
    {
      id: 1,
      image: "/images/banners/01.png",
      alt: "Banner 1",
    },
    {
      id: 2,
      image: "/images/banners/02.png",
      alt: "Banner 2",
    },
  ];

  return (
    <div className="banner-container">
      <Swiper
        modules={[Navigation, Pagination, Autoplay]}
        spaceBetween={30}
        slidesPerView={1}
        navigation
        pagination={{ clickable: true }}
        autoplay={{ delay: 3000, disableOnInteraction: false }}
        loop
      >
        {banners.map((banner) => (
          <SwiperSlide key={banner.id}>
            <img src={banner.image} alt={banner.alt} />
          </SwiperSlide>
        ))}
      </Swiper>
    </div>
  );
};

export default Banner;

วิธีใช้ Swiper ฝั่ง React มีสามส่วน:

  • Components — <Swiper> คือกรอบ carousel และ <SwiperSlide> คือสไลด์แต่ละใบ เรา map จาก array banners ที่ประกาศไว้ในไฟล์ (ใช้แค่รูป 01 กับ 02 — ส่วนรูป 03 เก็บไว้เป็นแบนเนอร์ยาวท้ายหน้า เดี๋ยวเจอใน Home.tsx)
  • Modules — Swiper แยกความสามารถเป็นโมดูลเพื่อไม่ให้ bundle บวม อยากได้อะไรต้องส่งเข้า prop modules เอง: Navigation ให้ปุ่มลูกศรซ้ายขวา, Pagination ให้จุดบอกตำแหน่งด้านล่าง (clickable: true = กดจุดเพื่อกระโดดข้ามสไลด์ได้), Autoplay เลื่อนเองทุก 3 วินาที (delay: 3000 มีหน่วยเป็น millisecond) โดย disableOnInteraction: false แปลว่าถึงผู้ใช้จะปัดเอง autoplay ก็ยังทำงานต่อ ไม่หยุดถาวร ปิดท้ายด้วย loop ให้สไลด์สุดท้ายวนกลับไปสไลด์แรกแบบไร้รอยต่อ
  • CSS — swiper/swiper-bundle.css คือ style ของปุ่ม จุด และ animation ทั้งหมด ไฟล์นี้ Banner import เองเพราะมีแค่คอมโพเนนต์นี้ที่ใช้ ต่างจาก skeleton.css ที่ import กลางใน main.tsx เพราะ skeleton โผล่ได้ทั่วแอป
  • ระวังชื่อชนกัน: Pagination ของ Swiper ในไฟล์นี้เป็นคนละตัวกับคอมโพเนนต์ Pagination ของเราจากบทเรียน 10 — อยู่กันคนละไฟล์เลยไม่มีปัญหา แต่ถ้าวันหนึ่งต้อง import ทั้งคู่ในไฟล์เดียว ใช้ import { Pagination as SwiperPagination } แก้ได้

Home.tsx: เดินดูทีละส่วน

ทีนี้ถึงไฟล์ใหญ่ของบท เราจะแทนที่ stub ใน src/pages/Home/Home.tsx ทั้งไฟล์ แต่เพราะมันยาว เราค่อย ๆ เดินดูทีละส่วนก่อน แล้วค่อยดูไฟล์ฉบับเต็มตอนท้าย

ส่วนที่ 1: state และ queries

const PRODUCTS_LIST_LIMIT = 12;

const Home: React.FC = () => {
  const [selectedCategory, setSelectedCategory] = useState<CategoryType | null>(
    null,
  );
  const { goToProductDetails } = useProductRoute();

  const {
    data: bestProductsData,
    isLoading: isBestProductsLoading,
    isError: isBestProductsError,
  } = useQuery(productQueries.list({ limit: 5 }));
  const { data: categories } = useQuery(productQueries.categories());

  const currentCategory = selectedCategory ?? categories?.[0] ?? null;

  const {
    data: categoryProducts,
    isLoading: isCategoryProductsLoading,
    isError: isCategoryProductsError,
  } = useQuery({
    ...productQueries.byCategory({
      category: currentCategory?.slug ?? "",
      limit: PRODUCTS_LIST_LIMIT,
    }),
    enabled: currentCategory !== null,
  });

หน้านี้ยิงสาม queries และทุกตัวใช้ factory จากบทเรียน 14 — ไม่มีการเขียน queryKey ด้วยมือแม้แต่ตัวเดียว:

  • productQueries.list({ limit: 5 }) — สินค้าขายดี 5 ตัวแรกสำหรับแถว "DEALS OF THE DAY" สังเกตการ rename ตอน destructure: data: bestProductsData, isLoading: isBestProductsLoading — จำเป็นเพราะหน้านี้มีหลาย query ชื่อ data เฉย ๆ จะชนกัน
  • productQueries.categories() — รายชื่อหมวดหมู่สำหรับ CategoryMenu จำได้ไหมว่า factory ตัวนี้ตั้ง staleTime 5 นาทีไว้ เพราะรายชื่อหมวดแทบไม่เปลี่ยน — หน้า Category ในบทถัดไปที่เรียก query เดียวกันจะได้ข้อมูลจาก cache ทันทีโดยไม่ยิง API ซ้ำ
  • productQueries.byCategory(…) — สินค้า 12 ตัวของหมวดที่กำลังเลือก ตัวนี้มีเงื่อนไขพิเศษ: enabled: currentCategory !== null แปลว่า "อย่าเพิ่งยิงจนกว่าจะรู้ว่าหมวดไหน" เพราะตอน mount แรกสุด รายชื่อหมวดยังโหลดไม่เสร็จ currentCategory ยังเป็น null — ถ้าไม่มี enabled เราจะยิง API ด้วย category="" ซึ่งไร้ความหมาย นี่คือ pattern "dependent query" ที่เจอในคอร์ส React พื้นฐาน: query หนึ่งรอผลของอีก query หนึ่ง

บรรทัดที่สำคัญที่สุดของหน้านี้คือบรรทัดสั้น ๆ นี้:

const currentCategory = selectedCategory ?? categories?.[0] ?? null;

โจทย์คือ: ตอนเปิดหน้ามาให้เลือกหมวดแรกโดยอัตโนมัติ แต่พอผู้ใช้คลิกหมวดอื่นก็ให้เปลี่ยนตาม มือใหม่จำนวนมากจะแก้โจทย์นี้ด้วย useEffect ที่คอยเฝ้า categories แล้ว setSelectedCategory(categories[0]) เมื่อโหลดเสร็จ — ซึ่งเป็น anti-pattern ที่บทเรียน Effects ของคอร์ส React พื้นฐาน เตือนไว้ตรง ๆ ว่า "อย่าใช้ effect เพื่อ sync state จาก props/data" เพราะได้ render เพิ่มฟรีหนึ่งรอบ แถมสร้างโอกาสที่ state สอง copy จะขัดแย้งกันเอง วิธีที่ถูกคือคำนวณสด (derive) ระหว่าง render: selectedCategory เก็บเฉพาะ "สิ่งที่ผู้ใช้เลือกเอง" (เริ่มจาก null = ยังไม่เคยเลือก) แล้วค่าที่ใช้จริงคือ "ที่ผู้ใช้เลือก ถ้าไม่มีก็หมวดแรก ถ้ายังโหลดไม่เสร็จก็ null" — nullish coalescing ต่อกันสองชั้นอ่านเป็นภาษาคนได้เลย และไม่มีทาง desync เพราะมันไม่ได้ถูกเก็บไว้ที่ไหนเลย

ส่วนที่ 2: targetDate สำหรับตัวนับถอยหลัง

  const targetDate = useMemo(() => {
    const date = new Date();
    date.setDate(date.getDate() + 1); // Add 1 days

    return date.toISOString();
  }, []);

แถวดีลประจำวันมี CountdownTimer จากบทเรียน 11 ซึ่งรับ prop targetDate เป็นเวลาเป้าหมาย เราตั้งไว้ที่ "พรุ่งนี้เวลานี้" ทำไมต้อง useMemo ด้วย dependency ว่าง? เพราะถ้าเขียน new Date() เปล่า ๆ ในตัวคอมโพเนนต์ ทุกครั้งที่ Home re-render (ซึ่งเกิดตลอด — ทุกการคลิกหมวด ทุกครั้งที่ query กลับมา) เป้าหมายจะถูกสร้างใหม่เลื่อนไปเรื่อย ๆ ตัวนับจะค้างที่ 24 ชั่วโมงตลอดกาล useMemo(…, []) ล็อกให้คำนวณครั้งเดียวตอน mount แล้วใช้ค่าเดิมไปตลอดชีวิตของหน้า

ส่วนที่ 3: pattern แสดงผล error → loading → data

ทั้งแถวดีลและรายการสินค้าตามหมวดใช้ pattern เดียวกันในการแสดงผล ดูตัวอย่างจากแถวดีล:

{isBestProductsError ? (
  <ErrorMessage />
) : isBestProductsLoading ? (
  <div className="text-center">
    <ClipLoader
      size={40}
      aria-label="Loading Spinner"
      data-testid="loader"
    />
  </div>
) : (
  <ProductsList
    products={bestProductsData?.products}
    onProductClick={onProductClick}
  />
)}

ternary ซ้อนสองชั้นอ่านจากบนลงล่าง: พังไหม → แสดง ErrorMessage, ยังโหลดอยู่ไหม → แสดง ClipLoader, ปกติ → แสดงรายการสินค้า ลำดับนี้สำคัญ: เช็ค error ก่อน loading เสมอ เพราะถ้าเช็ค loading ก่อนแล้ว query fail ไปแล้ว (isLoading เป็น false, isError เป็น true) โค้ดที่เช็คสลับลำดับบางแบบจะหลุดไปพยายาม render ข้อมูลที่ไม่มี และที่สำคัญกว่านั้น — การมี error state ในทุกจุดที่ยิง API คือสิ่งที่แยกแอปมืออาชีพจากแอปฝึกหัด: เน็ตล่มแล้วผู้ใช้ต้องเห็นข้อความบอก ไม่ใช่ spinner หมุนค้างตลอดกาลโดยไม่มีวันมีอะไรมา

สังเกตด้วยว่า error ของแต่ละ section เป็น inline — ถ้าแถวดีลโหลดพลาด ผู้ใช้เห็นข้อความ error เฉพาะแถวนั้น แต่แบนเนอร์ รูปโปรโมชัน และรายการหมวดหมู่ยังทำงานปกติ หน้าไม่ล้มทั้งหน้าเพราะ API ตัวเดียวสะดุด

ส่วนที่ 4: โครง JSX ของหน้า

ที่เหลือของ JSX คือการวางคอมโพเนนต์ที่มีอยู่แล้วเรียงจากบนลงล่าง: <Banner />, แถว FeatureCard สี่ใบ (Free Shipping / 24×7 / Festival offer / Online payment — ไอคอนจาก Font Awesome ที่ติดตั้งไว้บทเรียน 07), แถวดีลพร้อม CountdownTimer, ตาราง ImageZoom สามคอลัมน์จากรูป deals ที่เพิ่งดาวน์โหลด, section หมวดหมู่ที่ประกบ CategoryMenu กับ ProductsList และปิดท้ายด้วยแบนเนอร์ยาว (รูป banners/03.png) ใน ImageZoom

จุดเชื่อมต่อที่ควรสังเกตมีสองจุด จุดแรกคือ CategoryMenu:

<CategoryMenu
  activeCategory={currentCategory?.slug}
  categories={categories || []}
  onCategoryClick={setSelectedCategory}
/>

เพราะ contract ของ CategoryMenu ส่งทั้ง Category object กลับมา และ state ของเราก็เก็บ CategoryType | null พอดี เราจึงส่ง setSelectedCategory เป็น callback ได้ตรง ๆ ไม่ต้องห่อ arrow function เลย — คลิกปุ๊บ state เปลี่ยน, currentCategory ถูกคำนวณใหม่, query byCategory เห็น queryKey ใหม่แล้วยิงขอข้อมูลหมวดใหม่เอง ทั้ง chain นี้ไหลจากการ setState ครั้งเดียว

จุดที่สองคือการคลิกการ์ดสินค้า:

const onProductClick = (productId: number) => {
  goToProductDetails(productId);
};

useProductRoute จากบทเรียน 07 คือ hook รวมทางเดินของแอป — goToProductDetails(id) พาไป /products/:id ตอนนี้หน้านั้นยังเป็น stub อยู่ แต่บทเรียน 18 จะทำให้มันกลายเป็นหน้ารายละเอียดสินค้าเต็มตัว
