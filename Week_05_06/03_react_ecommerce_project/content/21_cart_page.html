สร้างหน้า Cart

Cart Page

ตอนนี้ผู้ใช้เพิ่มของเข้าตะกร้าได้ badge นับเลขได้ แต่พอคลิกไอคอนตะกร้าเข้ามาก็เจอหน้า stub ว่างเปล่าที่เราวางไว้ตั้งแต่บทที่ 06 บทนี้เราจะเปลี่ยนมันเป็นหน้า Cart จริง: ตารางรายการสินค้า ปรับจำนวนได้ ลบได้ เห็นยอดรวม มี empty state เวลาตะกร้าว่าง และปุ่ม Checkout พาไปหน้าถัดไปของ flow งานมีสองชิ้น: component CartTable และตัวหน้า Cart.tsx

CartTable — ตารางรายการสินค้าในตะกร้า

สร้าง src/features/cart/components/CartTable/CartTable.tsx:

import React from "react";
import { useCart } from "@/features/cart/useCart";

interface CartTableProps {
  onRemoveItem: (id: number) => void;
  onUpdateQuantity: (id: number, quantity: number) => void;
}

const CartTable: React.FC<CartTableProps> = ({
  onRemoveItem,
  onUpdateQuantity,
}) => {
  const { cart } = useCart();

  return (
    <div>
      <table className="table">
        <thead>
          <tr>
            <th>Action</th>
            <th>Image</th>
            <th>Product Name</th>
            <th>Price</th>
            <th>Quantity</th>
            <th>Total</th>
          </tr>
        </thead>
        <tbody>
          {cart.items.map((item) => (
            <tr key={item.id}>
              <td>
                <button
                  className="table-actions pointer"
                  onClick={() => onRemoveItem(item.id)}
                >
                  ×
                </button>
              </td>
              <td>
                <img
                  src={item.image || "/placeholder.png"}
                  alt={item.title}
                  className="table-image"
                />
              </td>
              <td>{item.title}</td>
              <td>
                <span className="fw-bold mr-5 fs-18">
                  ${item.price.toFixed(2)}
                </span>
                {item.originalPrice && (
                  <>
                    <span className="table-original-price">
                      ${item.originalPrice.toFixed(2)}
                    </span>
                    <br />
                    <span className="table-discount mt-5 inline-block fw-bold">
                      You Save: ${(item.originalPrice - item.price).toFixed(2)}
                    </span>
                  </>
                )}
              </td>
              <td>
                <div className="table-quantity">
                  <button
                    onClick={() => onUpdateQuantity(item.id, item.quantity - 1)}
                    disabled={item.quantity <= 1}
                  >
                    &lt;
                  </button>
                  <span>{item.quantity}</span>
                  <button
                    onClick={() => onUpdateQuantity(item.id, item.quantity + 1)}
                  >
                    &gt;
                  </button>
                </div>
              </td>
              <td>${(item.price * item.quantity).toFixed(2)}</td>
            </tr>
          ))}
        </tbody>
      </table>
    </div>
  );
};

export default CartTable;

ไล่ดูการตัดสินใจสำคัญในไฟล์นี้:

  • อ่านเอง แต่ให้พ่อเป็นคนแก้ — CartTable เรียก useCart() เพื่ออ่าน cart.items มาวาดตารางเองตรง ๆ แต่การแก้ไข (ลบ, ปรับจำนวน) กลับไม่เรียก store เอง — มันรับ onRemoveItem กับ onUpdateQuantity เป็น props แล้วโยนขึ้นไปให้หน้า Cart ตัดสินใจ การแยกแบบนี้ทำให้ตารางเป็นฝ่ายแสดงผลล้วน ๆ ส่วนคำสั่งแก้ข้อมูลรวมศูนย์อยู่ที่ตัวเพจ ซึ่งอ่านโค้ดตามหา "ใครแก้ตะกร้า" ได้ที่เดียวจบ
  • ปุ่มลบต่อแถว — เครื่องหมาย × เรียก onRemoveItem(item.id) ส่งแค่ id เพราะ reducer ฝั่งโน้นต้องการแค่นั้นในการ filter แถวทิ้ง
  • ช่อง Price โชว์ส่วนลดเมื่อมีข้อมูล — จำ originalPrice ที่เราตั้งใจเก็บติดลง CartItem ตั้งแต่บทที่ 19 และคำนวณใส่ตอน Add to Cart ในบทที่ 20 ได้ไหม? มาเก็บดอกตรงนี้: ถ้ามีค่า เราโชว์ราคาเต็ม (ขีดฆ่า) กับยอด "You Save" ได้ทันทีโดยไม่ต้องถาม API สักคำ — ข้อมูลทุกอย่างอยู่ในตะกร้าครบแล้ว
  • ปุ่มปรับจำนวนกับกติกาขั้นต่ำ — ปุ่มลดจำนวนถูก disabled เมื่อ quantity <= 1: reducer ของเราไม่มีกติกากันจำนวนติดลบ เราเลือกกันที่ UI แทน — จะเอาของออกจากตะกร้าต้องตั้งใจกดปุ่มลบ ไม่ใช่กดลดจนหายไปเองแบบงง ๆ สังเกตด้วยว่าใน JSX เราเขียนปุ่มด้วย &lt; / &gt; (HTML entity) ไม่ใช่พิมพ์ < > ตรง ๆ — เพราะเครื่องหมายน้อยกว่าใน JSX คือการเปิด tag เดี๋ยว parser งงตาย
  • ช่อง Total ต่อแถวเป็นค่าคำนวณ — price * quantity คิดสดตอน render ไม่เก็บลง state ตามหลักที่ย้ำกันมาตั้งแต่คอร์ส React พื้นฐาน: อะไร derive ได้จาก state อย่าเก็บซ้ำ เดี๋ยวมันคลาดเคลื่อนกันเอง
  • รูปมี fallback — item.image || "/placeholder.png" กันตารางเลย์เอาต์พังถ้าข้อมูลรูปหลุดมาว่าง ๆ

แล้ว style ล่ะ? สังเกตว่า component นี้ไม่มี .module.scss ของตัวเอง — class ทั้งหมดที่ใช้ (table, table-actions, table-image, table-original-price, table-discount, table-quantity) เป็น global component class ที่เราเขียนรอไว้แล้วใน src/styles/_components.scss ตั้งแต่บทที่ 04 ตารางเลยหน้าตาเรียบร้อยทันทีโดยไม่ต้องเขียน SCSS เพิ่มสักบรรทัด นี่คือเส้นแบ่งการใช้งานของทั้งสองระบบในโปรเจกต์นี้: style ที่เป็น "ภาษากลาง" ของแอปอยู่ใน global stylesheet ส่วน style เฉพาะตัวของ component (แบบ badge ของ CartSummary บทที่แล้ว) ค่อยแยกเป็น module

Cart.tsx — เปลี่ยน stub เป็นหน้าจริง

เปิด src/pages/Cart/Cart.tsx แล้วแทนที่ stub เดิมทั้งไฟล์ด้วยเวอร์ชันเต็ม:

import React, { useMemo } from "react";
import { useCart } from "@/features/cart/useCart";
import CategoryBanner from "@/pages/Category/components/CategoryBanner/CategoryBanner";
import CartTable from "@/features/cart/components/CartTable/CartTable";
import Button from "@/shared/components/Button/Button";
import useProductRoute from "@/shared/hooks/useProductRoute";

const Cart: React.FC = () => {
  const { cart, removeFromCart, updateQuantity } = useCart();
  const { goToCheckout } = useProductRoute();

  const calculateTotalPrice = useMemo(() => {
    return cart.items
      .reduce((total, item) => total + item.price * item.quantity, 0)
      .toFixed(2);
  }, [cart.items]);

  const onCheckout = () => {
    goToCheckout();
  };

  if (cart.items.length === 0) {
    return (
      <>
        <CategoryBanner name="Cart" />
        <div className="container text-center mt-50 pb-60">
          <h2 className="fs-32 fw-bold mb-40">Your Cart is Empty</h2>
          <p className="text-muted fs-24">
            You haven't added any items to your cart yet.
          </p>
        </div>
      </>
    );
  }

  return (
    <>
      <CategoryBanner name="Cart" />
      <div className="container pt-30 pb-30">
        <CartTable
          onRemoveItem={removeFromCart}
          onUpdateQuantity={updateQuantity}
        />
        <div className="table-total pr-20 pt-20 text-right">
          <h3>Total Price: ${calculateTotalPrice}</h3>
          <div className="inline-block mt-15">
            <Button onClick={onCheckout}>Checkout</Button>
          </div>
        </div>
      </div>
    </>
  );
};

export default Cart;

หน้านี้สั้นอย่างน่าพอใจ — เพราะงานหนักถูกทำไว้หมดแล้วในบทก่อน ๆ เหลือแค่การประกอบ:

  • ดึงของจาก store สามชิ้น — cart ไว้อ่าน, removeFromCart กับ updateQuantity ไว้แก้ แล้วดูบรรทัดที่ส่งเข้า CartTable: onRemoveItem={removeFromCart} — action จาก store เสียบเข้า prop ได้ตรง ๆ เพราะ signature ตรงกันเป๊ะ ((id: number) => void) ไม่ต้องมี wrapper function ให้เสียเปล่า นี่ไม่ใช่ความบังเอิญ: เราออกแบบ CartContextProps ในบทที่ 19 โดยคิดถึงคนใช้แบบนี้อยู่แล้ว
  • ยอดรวมเป็นค่า derive — calculateTotalPrice ใช้ useMemo reduce ราคาคูณจำนวนของทุกแถว แล้ว .toFixed(2) ให้เป็น string ทศนิยมสองตำแหน่งพร้อมแสดง คำนวณใหม่เฉพาะเมื่อ cart.items เปลี่ยน — สูตรเดียวกับ badge ใน CartSummary แค่เปลี่ยนจากนับจำนวนเป็นรวมราคา
  • Empty state มาก่อน — เช็ค cart.items.length === 0 แล้ว return โครงหน้าตะกร้าว่างไปเลยก่อนถึง JSX หลัก แพตเทิร์น early return แบบเดียวกับที่หน้า Product ใช้กับ loading/error: อ่านจากบนลงล่างเจอเงื่อนไขพิเศษก่อน แล้วเนื้อหลักด้านล่างไม่ต้องห่อ if ซ้อนกันให้รก ที่สำคัญคือเราออกแบบหน้าว่างไว้จริง ๆ (หัวข้อใหญ่ + คำอธิบาย) ไม่ใช่ปล่อยตารางหัวโด่ไม่มีสักแถวให้ผู้ใช้งงว่าเว็บพังหรือเปล่า
  • CategoryBanner ถูก reuse ข้าม feature — component เดิมจากบทที่ 17 รับ name="Cart" กลายเป็นแถบหัวเพจได้เลย ทั้งสองกิ่งของ return ใส่ banner เหมือนกัน หน้าเลยดูเป็นหน้าเดียวกันไม่ว่าตะกร้าจะมีของหรือไม่
  • ปุ่ม Checkout ต่อ router ผ่าน hook เดิม — goToCheckout จาก useProductRoute (บทที่ 07) พาไป /checkout ซึ่งตอนนี้ยังเป็น stub — มันคือพระเอกของ chapter หน้าทั้ง chapter ส่วนแถบยอดรวมใช้ class table-total จาก _components.scss จัดชิดขวาให้เข้าชุดกับตาราง
🚨 ถ้าเปิดหน้า /cart แล้วเจอ error "useCart must be used within a CartProvider" แปลว่า providers.tsx ของคุณยังไม่ได้เพิ่ม CartProvider จากบทที่ 19 — กลับไปเช็คก่อน อย่าแก้ด้วยการลบ throw ทิ้ง ยามคนนี้เพิ่งทำหน้าที่ของมันพอดี
💡 Checkpoint — ตะกร้าต้องจัดการได้ครบวงจรแล้ว: เพิ่มสินค้า 2–3 ตัวจากหน้า Product แล้วคลิกไอคอนตะกร้า → เห็นตารางครบทุกแถว พร้อมรูป ราคา และ "You Save" สำหรับตัวที่มีส่วนลด → กดปุ่ม > เพิ่มจำนวน แล้วดู Total ท้ายแถว, Total Price ล่างขวา และ badge บน Header ขยับพร้อมกันทั้งสามจุด (ทุกคนอ่านจาก store เดียวกัน) → กด < ลดจนเหลือ 1 แล้วปุ่มต้อง disabled → กด × ลบทีละแถวจนหมด → เจอ "Your Cart is Empty" และ badge หายไป → เพิ่มของใหม่แล้ว refresh → ทุกอย่างยังอยู่ครบจาก localStorage → กด Checkout → ไปโผล่หน้า stub /checkout ซึ่งเราจะเริ่มสร้างกันบทหน้า เริ่มจาก schema ของฟอร์มด้วย zod
