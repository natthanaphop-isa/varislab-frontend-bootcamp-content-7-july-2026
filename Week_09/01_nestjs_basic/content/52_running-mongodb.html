รัน MongoDB ด้วย Docker Compose

บทนี้เราจะทำอะไรบ้าง

  • เขียน docker-compose.yml ที่รัน MongoDB container พร้อม expose พอร์ต 27017 ให้แอปเชื่อมต่อได้
  • สั่งเปิด container แบบ detached และปิดลงอย่างสะอาดด้วยคำสั่งเดียว
  • อธิบายความหมายของแต่ละ key ในไฟล์ compose (image, ports, environment, restart) ได้

ทำไมใช้ Docker แทนการติดตั้ง MongoDB ลงเครื่อง

เช่นเดียวกับตอนที่เรารัน PostgreSQL ในเส้นทาง SQL การรันฐานข้อมูลผ่าน Docker Compose ทำให้ทุกคนในทีมได้สภาพแวดล้อมเดียวกันด้วยไฟล์ config ไฟล์เดียว: ไม่ต้องติดตั้ง MongoDB ลงเครื่องตรง ๆ, สลับเวอร์ชันได้ง่าย และเมื่อเลิกใช้ก็สั่งปิดทิ้งได้โดยไม่เหลือขยะในระบบ ไฟล์ docker-compose.yml วางไว้ที่ root ของโปรเจกต์ iluvcoffee

version: "3"

services:
  db:
    image: mongo:8.0    # container image ที่ใช้ — pin ที่ Major Release 8.0 (สายที่ได้ long-term support)
    restart: always
    ports:              # เปิดพอร์ตรูปแบบ "host:container"
      - 27017:27017
    environment:        # ตัวแปรแวดล้อมที่ส่งเข้า container
      MONGO_INITDB_DATABASE: nest-course

ความหมายของแต่ละส่วน: image: mongo:8.0 ดึง image ทางการของ MongoDB จาก registry โดยระบุเวอร์ชัน, restart: always ให้ Docker รีสตาร์ต container ให้อัตโนมัติถ้ามันล้ม, ports ผูกพอร์ต 27017 ของเครื่องเรา (host) เข้ากับพอร์ต 27017 ใน container ซึ่งเป็นพอร์ตมาตรฐานของ MongoDB และ environment ส่งตัวแปรแวดล้อมเข้าไปตั้งชื่อฐานข้อมูลเริ่มต้นเป็น nest-course (ต้องใช้ชื่อ MONGO_INITDB_DATABASE ให้ตรงตาม image ทางการเป๊ะ ๆ — ชื่ออื่นเช่น MONGODB_DATABASE จะถูก entrypoint script เพิกเฉยแบบเงียบ ๆ ไม่มี error ใด ๆ)

ทำไมต้อง pin เวอร์ชัน: MongoDB แบ่ง release เป็นสองสาย — Major Release (เช่น 7.0, 8.0) ออกทุกสองปี รองรับนานห้าปี เหมาะกับ production และการเรียนที่ต้องการสภาพแวดล้อมคงที่ กับ Rapid/Minor Release (เช่น 8.2, 8.3) ที่ออกถี่และเลิก patch ทันทีที่มีรุ่นถัดไป ถ้าเขียน image: mongo เฉย ๆ Docker จะดึง tag latest ซึ่งชี้ไปที่ Rapid Release ล่าสุด ทำให้ผู้เรียนแต่ละคนได้เวอร์ชันต่างกัน (และบางรุ่นอาจไม่ยอมสตาร์ตบน Docker Desktop บางเวอร์ชัน) คอร์สนี้จึง pin ที่ mongo:8.0 ซึ่งเป็น Major Release ปัจจุบัน ให้ทุกคนได้ MongoDB ตัวเดียวกัน

ถ้า container ขึ้นแล้วดับทันที และ docker logs บอกว่า Linux kernel versions 6.19 and newer has a known incompatibility with this version of MongoDB (MongoDB issue SERVER-121912) แปลว่า Docker Desktop ของคุณใช้ Linux kernel รุ่นที่ MongoDB 8.x ยังไม่รองรับ ทางแก้ชั่วคราวคืออัปเดต Docker Desktop เป็นรุ่นล่าสุด หรือ pin patch เก่ากว่าของสายเดียวกันเป็น image: mongo:8.0.4 ซึ่งสตาร์ตได้และเนื้อหาทุกบทในเส้นทางนี้ทดสอบผ่านบนรุ่นนี้แล้ว

จำชื่อฐานข้อมูล nest-course นี้ไว้ให้ดี — ในบทถัดไป connection string ของ MongooseModule.forRoot() ต้องชี้ไปที่ชื่อเดียวกันนี้ ไม่อย่างนั้นแอปจะต่อฐานข้อมูลคนละก้อนกับที่ตั้งใจ

คำสั่งเปิด–ปิดที่ใช้ประจำ

คำสั่งหลักมีสองคำสั่ง: docker-compose up -d สตาร์ตทุก service ในไฟล์แบบ detached (รันเบื้องหลัง คืน terminal ให้เราใช้งานต่อ) และ docker-compose down หยุดพร้อมถอด container ออก บน Docker รุ่นใหม่จะพิมพ์แบบเว้นวรรคเป็น docker compose up -d ก็ได้ ให้ผลเหมือนกัน

สตาร์ต MongoDB สำหรับโปรเจกต์ iluvcoffee

สร้างไฟล์ docker-compose.yml ตามตัวอย่างด้านบนไว้ที่ root ของโปรเจกต์ (บน branch ของ Chapter 2 ที่สลับมาเมื่อบทที่แล้ว) แล้วสั่งรัน container ขึ้นมา

# สตาร์ต container แบบ detached/เบื้องหลัง docker-compose up -d # ดูว่า container รันอยู่จริง docker ps # เมื่อต้องการปิด docker-compose down

ควรได้ผลลัพธ์แบบนี้

docker-compose up -d จบโดยไม่มี error และ docker ps แสดง container จาก image mongo สถานะ Up พร้อม mapping พอร์ต 0.0.0.0:27017->27017/tcp — แปลว่า MongoDB พร้อมรับการเชื่อมต่อจาก NestJS ที่ mongodb://localhost:27017 แล้ว

ลองเช็กให้แน่ใจ

  • docker ps เห็น container ของ mongo สถานะ Up และพอร์ต 27017 ถูก map ออกมา
  • docker compose logs db มีบรรทัดทำนอง Waiting for connections โดยไม่มี error ซ้ำ ๆ
  • ทดลอง docker exec -it <container-id> mongosh แล้วเข้า shell ของ MongoDB ได้
  • สั่ง docker-compose down แล้ว docker ps ไม่เหลือ container นี้ ก่อนสตาร์ตขึ้นมาใหม่เพื่อใช้บทถัดไป
