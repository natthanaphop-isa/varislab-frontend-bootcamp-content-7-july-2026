จัดการคำขอ Update และ Delete

บทนี้เราจะทำอะไรบ้าง

  • สร้าง endpoint อัปเดตข้อมูลด้วย @Patch(':id') ที่รับทั้ง param และ body
  • สร้าง endpoint ลบข้อมูลด้วย @Delete(':id')
  • อธิบายความต่างระหว่าง PATCH กับ PUT และเหตุผลที่คอร์สนี้เลือก PATCH

ปิดจ๊อบ CRUD ของ /coffees

เรามี Create (POST) และ Read (GET) แล้ว เหลือ Update และ Delete ซึ่งใช้ decorator @Patch และ @Delete จาก @nestjs/common ทั้งคู่ทำงานกับ resource รายตัวจึงต้องมี route parameter :id เหมือน findOne

/* CoffeesController */
import {
  Body,
  Controller,
  Delete,
  Get,
  Param,
  Patch,
  Post,
} from '@nestjs/common';

@Controller('coffees')
export class CoffeesController {
  @Get()
  findAll() {
    return 'This action returns all coffees';
  }

  @Get(':id')
  findOne(@Param('id') id: string) {
    return `This action returns #${id} coffee`;
  }

  @Post()
  create(@Body() body: any) {
    return body;
  }

  @Patch(':id')
  update(@Param('id') id: string, @Body() body: any) {
    return `This action updates #${id} coffee`;
  }

  @Delete(':id')
  remove(@Param('id') id: string) {
    return `This action removes #${id} coffee`;
  }
}

สังเกตว่า update() ใช้ decorator สองตัวพร้อมกันคนละ parameter: @Param('id') บอกว่าจะแก้ตัวไหน และ @Body() บอกว่าจะแก้อะไร — แพตเทิร์นนี้คือหัวใจของ endpoint แก้ไขข้อมูลแทบทุกตัวที่จะเจอ

ทำไม PATCH ไม่ใช่ PUT

Methodความหมายตาม conventionตัวอย่าง payload
PUTแทนที่ resource ทั้งตัว — ต้องส่งทุก field มาครบ{"name": "...", "brand": "...", "flavors": [...]}
PATCHแก้ไข บางส่วน — ส่งเฉพาะ field ที่ต้องการเปลี่ยน{"name": "New Name"}

คอร์สนี้ใช้ PATCH เพราะยืดหยุ่นกว่าสำหรับผู้ใช้ API — จะเปลี่ยนแค่ชื่อกาแฟก็ไม่ต้องส่ง flavors ทั้ง array มาด้วย ข้อดีนี้จะชัดขึ้นอีกในบทที่ 16 เมื่อเราสร้าง UpdateCoffeeDto ที่ทุก field เป็น optional

ยิงทดสอบให้ครบทั้ง 5 endpoints

เพิ่ม update() และ remove() ตามโค้ดด้านบน แล้วไล่ยิงทดสอบ CRUD ให้ครบทุก method ใน collection ของ Insomnia (หรือ curl)

curl -i -X PATCH http://localhost:3000/coffees/1 \ -H "Content-Type: application/json" \ -d '{"name": "Renamed Roast"}' curl -i -X DELETE http://localhost:3000/coffees/1

ควรได้ผลลัพธ์แบบนี้

PATCH ตอบ 200 พร้อม This action updates #1 coffee และ DELETE ตอบ 200 พร้อม This action removes #1 coffee — ตอนนี้ CoffeesController มี endpoint ครบทั้ง findAll, findOne, create, update, remove

ลองเช็กให้แน่ใจ

  • log แสดง route ใหม่ครบ: {/coffees/:id, PATCH} และ {/coffees/:id, DELETE}
  • PATCH ด้วย id ต่างกันให้ข้อความสะท้อน id ที่ถูกต้อง
  • DELETE ไม่ต้องแนบ body ก็ทำงานได้
  • นับ endpoint ใน controller ได้ 5 ตัว ครบ CRUD สำหรับ resource เดียว
