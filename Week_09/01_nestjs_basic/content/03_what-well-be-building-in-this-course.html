สิ่งที่เราจะสร้างกันในคอร์สนี้

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายขอบเขตของแอป iluvcoffee และแนวคิดหลักที่คอร์สนี้ครอบคลุม
  • วางแผนการเรียนแบบ incremental — เรียนตามลำดับโดยไม่ข้ามบท
  • เตรียมกลยุทธ์ git branch สำหรับแยกเส้นทาง SQL (PostgreSQL) และ NoSQL (MongoDB)

REST API เรื่องกาแฟล้วน ๆ ☕️

ตลอดคอร์สนี้เราจะสร้าง REST API ขนาดเล็กที่ว่าด้วยกาแฟทั้งหมด — resource หลักคือ coffees ที่มี entity Coffee (ประกอบด้วย id, name, brand และ flavors) แอปเล็กพอที่จะไม่บังหลักการ แต่ครบพอที่จะได้เจอปัญหาจริงทุกชั้นของ backend

แนวคิดหลักที่จะได้ลงมือทำ:

  • ห่อ feature / business domain ไว้ใน modules ของตัวเอง
  • สร้าง CRUD endpoints ครบชุดสำหรับ entity Coffee
  • ใช้ building blocks สำคัญของ NestJS: pipes, filters, guards, interceptors, middleware
  • เข้าใจ dependency injection ถึงระดับ custom providers และ scopes
  • เชื่อมฐานข้อมูลทั้ง SQL (PostgreSQL ผ่าน Prisma) และ NoSQL (MongoDB ผ่าน Mongoose)
  • เขียน unit tests และ e2e tests ด้วย Vitest

คอร์สออกแบบมาให้เรียนแบบสะสม

บทเรียนต่อยอดกันเป็นลูกโซ่: โค้ดของบทหลังสร้างต่อจากบทก่อนหน้าเสมอ ถ้าโค้ดตามไปด้วย (แนะนำมาก) ให้เรียงตามลำดับบทและ chapter อย่าข้าม เพราะ tips, best practices และการ setup โค้ดบางอย่างจะถูกใช้ต่อในบทถัด ๆ ไป

สำคัญ: คอร์สนี้มีทั้งเส้นทาง SQL และ NoSQL — หลังจบ Chapter 2 Creating a REST API Application (บทที่ 18) ให้ บันทึกความคืบหน้าไว้ใน branch แยกต่างหาก เพราะบทโบนัส MongoDB/Mongoose (บทที่ 70–77) จะเริ่มต่อจากจุดนั้นพอดี ไม่ใช่ต่อจากเส้นทาง PostgreSQL

# หลังเรียนจบบทที่ 18 (จบ Chapter 2)
git checkout -b end-of-chapter-2   # เก็บ snapshot ไว้ใช้กับบท MongoDB
git checkout master                # กลับมาเรียนเส้นทาง PostgreSQL ต่อ

การแตก branch แบบนี้ทำให้เลือกดูเฉพาะ section ฐานข้อมูลที่ตรงกับโปรเจกต์ของคุณได้ หรือจะโค้ดตามทั้งสองเส้นทางก็ได้เช่นกัน

วางแผนเส้นทางเรียนของตัวเอง

ก่อนไปต่อ ตัดสินใจ 2 อย่าง: (1) จะโค้ดตามหรืออ่านอย่างเดียว (2) จะเรียนเส้นทางฐานข้อมูลไหน — PostgreSQL, MongoDB หรือทั้งคู่ ถ้าโค้ดตาม ให้ init git ในโปรเจกต์ iluvcoffee ตั้งแต่ตอนนี้เพื่อรองรับการแตก branch ในอนาคต

cd iluvcoffee git init git add . git commit -m "initial scaffold"

ผลลัพธ์ที่คาดหวัง

มี repository ที่ commit แรกเป็นโค้ด scaffold สะอาด ๆ และคุณรู้ชัดว่าเมื่อถึงจุดจบ Chapter 2 จะต้องแตก branch เก็บไว้หนึ่งเส้นเพื่อใช้กับบทโบนัส MongoDB

ตรวจว่าใช้งานได้จริง

  • git log --oneline แสดง commit แรกของโปรเจกต์
  • git status สะอาด ไม่มีไฟล์ค้างที่ยังไม่ commit
  • บอกได้ว่า entity หลักของคอร์สคืออะไรและมี field อะไรบ้าง
  • บอกได้ว่าบทโบนัส MongoDB เริ่มต่อจากบทไหน (จบ Chapter 2 — บทที่ 18)
