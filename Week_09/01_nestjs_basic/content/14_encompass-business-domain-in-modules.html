ห่อ Business Domain ไว้ใน Modules

บทนี้เราจะทำอะไรบ้าง

  • อธิบายหน้าที่ของ controllers, providers, imports และ exports ใน @Module() ได้
  • สร้าง module ใหม่ด้วย Nest CLI และย้าย component ของ domain เข้าไปอยู่ในนั้น
  • ออกแบบโครงสร้างแอปให้แต่ละ business domain มีขอบเขตของตัวเอง

Module คือหน่วยจัดระเบียบของ NestJS

ตอนนี้ CoffeesController และ CoffeesService ยังแปะอยู่ใน AppModule ซึ่งพอแอปโตขึ้นจะกลายเป็นกองรวมของทุกอย่าง แนวคิดของ Nest คือหนึ่ง business domain ควรมี module ของตัวเอง — ทุกอย่างเกี่ยวกับกาแฟอยู่ในโฟลเดอร์ coffees/ ภายใต้ CoffeesModule เดียว

@Module() decorator รับ object ที่มี 4 ส่วนหลัก:

Propertyหน้าที่
controllersAPI routes ที่ให้ module นี้ instantiate — คิดง่าย ๆ ว่าเป็นเส้นทางเข้าของ HTTP
providersservices ที่ให้ Nest injector สร้างขึ้น — โดย default ใช้ได้เฉพาะภายใน module นี้ เว้นแต่ประกาศใน exports
importsรายชื่อ module อื่น ที่ module นี้ต้องใช้ — provider ที่ module เหล่านั้น export จะพร้อมใช้ที่นี่
exportsprovider ของ module นี้ที่เปิดให้ทุกที่ที่ import module นี้เข้าไปใช้ได้

สร้าง CoffeesModule

nest g module coffees
# shorthand: nest g mo coffees

CLI สร้าง coffees/coffees.module.ts และเพิ่ม CoffeesModule เข้า imports ของ AppModule ให้อัตโนมัติ จากนั้นย้าย controller และ service ของเราเข้ามาประกาศที่นี่แทน

/* coffees.module.ts */
import { Module } from '@nestjs/common';
import { CoffeesController } from './coffees.controller.js';
import { CoffeesService } from './coffees.service.js';

@Module({
  controllers: [CoffeesController],
  providers: [CoffeesService]
})
export class CoffeesModule {}

อย่าลืมลบ CoffeesController และ CoffeesService ออกจาก declaration ใน AppModule — ถ้าประกาศซ้ำสองที่ Nest จะสร้าง instance ซ้ำซ้อน ซึ่งทำให้เกิดพฤติกรรมแปลก ๆ เมื่อ service เก็บ state

เมื่อเสร็จแล้ว AppModule ควรเหลือแค่ imports: [CoffeesModule] และโครงสร้างโฟลเดอร์ของ domain กาแฟจะครบวงจรในที่เดียว:

src/
├── app.module.ts
└── coffees/
    ├── coffees.controller.ts
    ├── coffees.service.ts
    ├── coffees.module.ts
    ├── dto/
    └── entities/
        └── coffee.entity.ts

แยก domain กาแฟออกเป็น module ของตัวเอง

สร้าง CoffeesModule ด้วย CLI, ประกาศ controller/service ในนั้น แล้วลบการประกาศเดิมออกจาก AppModule ให้สะอาด

nest g mo coffees # แก้ coffees.module.ts ให้มี controllers + providers # ลบ CoffeesController / CoffeesService ออกจาก app.module.ts npm run start:dev

ควรได้ผลลัพธ์แบบนี้

แอปเปิดได้โดยไม่มี dependency resolution error และทุก endpoint ของ /coffees ยังตอบเหมือนเดิม การย้ายโครงสร้างครั้งนี้ต้องไม่เปลี่ยนพฤติกรรมที่ client มองเห็น

ลองเช็กให้แน่ใจ

  • log ตอน start มีบรรทัด CoffeesModule dependencies initialized
  • GET /coffees และ GET /coffees/1 ยังตอบเหมือนก่อน refactor
  • app.module.ts ไม่มีการอ้างถึง CoffeesController หรือ CoffeesService ตรง ๆ อีก
  • ไฟล์ทั้งหมดของ domain กาแฟอยู่ใต้โฟลเดอร์ src/coffees/
