รู้จัก Mongoose Module

เมื่อจบบทนี้ คุณจะสามารถ

  • ติดตั้ง dependencies ที่จำเป็นสำหรับใช้ Mongoose ใน NestJS ได้ครบและไม่เกินจำเป็น
  • ตั้งค่า MongooseModule.forRoot() ใน AppModule ให้ชี้ไปยังฐานข้อมูลที่รันอยู่ใน Docker
  • วินิจฉัยปัญหาการเชื่อมต่อเบื้องต้นได้ เช่น Docker ไม่ได้รัน หรือชื่อฐานข้อมูลไม่ตรงกัน

Nest ไม่ผูกกับฐานข้อมูลใดฐานข้อมูลหนึ่ง

ตัว NestJS เอง database agnostic — ออกแบบให้เชื่อมกับฐานข้อมูล SQL หรือ NoSQL ตัวไหนก็ได้ตามความชอบหรือความต้องการของโปรเจกต์ วิธีเชื่อมมีหลายทาง แต่สำหรับเส้นทาง MongoDB นี้เราใช้ Mongoose ซึ่งเป็นเครื่องมือ object modeling สำหรับ MongoDB ที่ได้รับความนิยมสูงสุด ผ่านแพ็กเกจ @nestjs/mongoose ที่ทีม NestJS ดูแลเอง

# ติดตั้ง dependencies ของ mongoose
npm i mongoose @nestjs/mongoose

ตั้งแต่ mongoose@5.11.1 เป็นต้นมา Mongoose เผยแพร่ type definitions ของตัวเองแล้ว จึงไม่ต้องติดตั้งแพ็กเกจ @types/mongoose เพิ่มอีก

ตั้งค่า MongooseModule ใน AppModule

เช่นเดียวกับ PrismaModule ในเส้นทาง SQL การเชื่อมต่อระดับแอปทำครั้งเดียวที่ root module — คราวนี้ผ่าน dynamic module MongooseModule.forRoot() (แพทเทิร์นจากบทที่ 39) โดยส่ง connection string ที่ชี้ไปยัง MongoDB ใน Docker ของบทที่แล้ว: host localhost, พอร์ต 27017 และชื่อฐานข้อมูล nest-course

/* ตั้งค่า MongooseModule ใน AppModule */
import { Module } from '@nestjs/common';
import { MongooseModule } from '@nestjs/mongoose';

@Module({
  imports: [
    MongooseModule.forRoot('mongodb://localhost:27017/nest-course'),
  ],
})
export class AppModule {}

ส่วนท้ายของ connection string (/nest-course) คือชื่อฐานข้อมูลที่จะใช้ ซึ่งต้องตรงกับที่ประกาศไว้ใน docker-compose.yml เมื่อ Nest สตาร์ต มันจะเปิด connection นี้ให้ทั้งแอปใช้ร่วมกัน และ module ฟีเจอร์ต่าง ๆ จะมาลงทะเบียน model ของตัวเองบน connection นี้ในบทถัดไป

ถ้าแอปสตาร์ตแล้วค้างหรือฟ้อง connect ไม่ได้ ให้ตรวจว่า Docker รันอยู่ด้วย docker compose up -d ก่อน — นี่คือสาเหตุที่พบบ่อยที่สุดของปัญหานี้ ส่วนชื่อฐานข้อมูลใน MongooseModule.forRoot() ที่ไม่ตรงกับ docker-compose.yml จะไม่ทำให้ connect ล้มเหลวหรือค้าง (MongoDB สร้างฐานข้อมูลใหม่ให้อัตโนมัติตามชื่อที่ระบุ โดยไม่สนใจว่าชื่อนั้นมีอยู่จริงหรือไม่) แต่จะทำให้แอปต่อกับฐานข้อมูลคนละก้อนกับที่ตั้งใจแบบเงียบ ๆ แทน — ให้ตรวจชื่อให้ตรงกันเสมอเพื่อเลี่ยงปัญหานี้

เชื่อม iluvcoffee เข้ากับ MongoDB

ติดตั้งแพ็กเกจ แล้วเพิ่ม MongooseModule.forRoot() เข้าไปใน imports ของ AppModule ตามโค้ดด้านบน จากนั้นสตาร์ตแอปโดยที่ container ของ MongoDB ยังรันอยู่

docker compose up -d npm i mongoose @nestjs/mongoose npm run start:dev

ผลลัพธ์ที่คาดหวัง

แอปสตาร์ตสำเร็จโดย log มีบรรทัด MongooseModule dependencies initialized และไม่มี error เรื่องการเชื่อมต่อ ถ้าปิด Docker แล้วสตาร์ตใหม่ จะเห็นแอปพยายาม retry การเชื่อมต่อ — เป็นการยืนยันว่า Nest ต่อกับ MongoDB ผ่าน config ของเราจริง

ตรวจว่าใช้งานได้จริง

  • package.json มี mongoose และ @nestjs/mongoose ใน dependencies แต่ไม่มี @types/mongoose
  • npm run start:dev ขึ้น Nest application successfully started โดยไม่มี MongooseServerSelectionError
  • ลองแก้ชื่อฐานข้อมูลใน connection string ให้ผิดชั่วคราวแล้วดูว่าปลายทางเปลี่ยน — จากนั้นแก้กลับเป็น nest-course
  • สั่ง docker compose down แล้วดู log ว่าแอปฟ้องเชื่อมต่อไม่ได้ ก่อน up -d กลับมาให้พร้อมใช้บทถัดไป
