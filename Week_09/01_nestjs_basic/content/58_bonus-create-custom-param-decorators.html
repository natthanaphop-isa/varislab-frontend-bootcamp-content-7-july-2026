โบนัส: สร้าง Custom Param Decorators

เมื่อจบบทนี้ คุณจะสามารถ

  • บอกได้ว่า param decorator อย่าง @Body() และ @Param() ทำงานอย่างไรเบื้องหลัง
  • สร้าง param decorator ของตัวเองด้วย createParamDecorator
  • ส่งค่า argument จากจุดที่ใช้ decorator เข้าไปยัง factory function ผ่านพารามิเตอร์ data

เบื้องหลัง @Body() และ @Param() คือ param decorator

decorator ที่เราใช้ดึงข้อมูลเข้า handler มาตลอดคอร์ส — @Body(), @Param(), @Query() — ล้วนเป็น param decorator: ฟังก์ชันที่รู้วิธีควักข้อมูลชิ้นหนึ่งออกจาก request แล้วส่งเป็น argument ให้ method เมื่อข้อมูลที่ต้องการไม่มี decorator สำเร็จรูป (เช่น custom header, ข้อมูลผู้ใช้ที่ middleware แนบไว้ หรือ protocol ของ request) เราสร้างเองได้ด้วย createParamDecorator

สร้าง @Protocol() decorator

factory function ที่ส่งให้ createParamDecorator รับสองอย่าง: data — ค่าที่ผู้ใช้ decorator ส่งเข้ามาตอนเรียก และ ctx — ExecutionContext ตัวเดียวกับที่ guard และ interceptor ใช้ ค่าที่ factory คืนออกมาคือค่าที่ handler ได้รับ

import {
  createParamDecorator,
  ExecutionContext,
} from '@nestjs/common';

export const Protocol = createParamDecorator(
  (data: unknown, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest();
    return request.protocol;
  },
);

การใช้งานเหมือน decorator ในตัวทุกประการ — ประกาศเป็น parameter ของ handler แล้ว NestJS จะเรียก factory ให้ทุก request

@Get()
findAll(@Protocol() protocol: string) {
  console.log(protocol); // 'http'
  return this.coffeesService.findAll();
}

ใช้พารามิเตอร์ data รับค่าจากจุดเรียก

สังเกตว่า decorator เรียกได้แบบ @Protocol(/* optional defaultValue */) — ค่าใด ๆ ที่ใส่ในวงเล็บจะไปโผล่ที่พารามิเตอร์ data ของ factory ทำให้ decorator ตัวเดียวปรับพฤติกรรมตามจุดใช้งานได้ เช่น รับ default value, รับชื่อฟิลด์ที่ต้องการดึง (แบบเดียวกับ @Param('id')) ในโค้ดข้างบนเรายังไม่ใช้ data จึงประกาศ type เป็น unknown ไว้ตามแนวทางที่ปลอดภัย

เมื่อจะใช้ custom param decorator ร่วมกับ pipe (เช่นส่งผลลัพธ์เข้า ValidationPipe) NestJS รองรับให้ pipe ทำงานกับค่าออกจาก decorator ได้เหมือน @Body() ทุกอย่าง — เป็นเหตุผลหนึ่งที่ควรดึงข้อมูลผ่าน decorator แทนการควัก request ดิบใน handler

ดึง protocol ของ request เข้า findAll()

สร้าง protocol.decorator.ts ใน common/decorators ตามโค้ดด้านบน แล้วใช้ @Protocol() ใน findAll() ของ CoffeesController เพื่อ log ค่า protocol ของทุก request

# common/decorators/protocol.decorator.ts — ตามโค้ดในบทเรียน # coffees.controller.ts @Public() @Get() findAll(@Protocol() protocol: string, @Query() paginationQuery: PaginationQueryDto) { console.log(protocol); return this.coffeesService.findAll(paginationQuery); } # ทดสอบ curl http://localhost:3000/coffees

ผลลัพธ์ที่คาดหวัง

endpoint ทำงานเหมือนเดิม แต่ terminal ของ dev server พิมพ์ http ทุกครั้งที่มี request เข้า — ค่านั้นมาจาก request.protocol ที่ decorator ควักออกมาให้ handler โดยที่ handler ไม่ต้องรู้จัก request object เลย

ตรวจว่าใช้งานได้จริง

  • ยิง GET /coffees แล้วเห็น http ใน log ของ server
  • ลองส่งค่าเข้า decorator เช่น @Protocol('https') แล้ว log พารามิเตอร์ data ใน factory เพื่อยืนยันว่าค่าเดินทางถึง
  • ตรวจว่า response ของ endpoint ไม่เปลี่ยน — decorator เพิ่ม argument ให้ handler เท่านั้น ไม่แตะ response
  • ย้าย decorator ไปใช้กับ handler อื่นแล้วยืนยันว่าใช้ซ้ำได้โดยไม่ต้องแก้โค้ด factory
