เปิดใช้ Swagger CLI Plugin

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายได้ว่าทำไม Swagger มองไม่เห็น TypeScript type ของ DTO โดยลำพัง
  • เปิดใช้ @nestjs/swagger/plugin ใน nest-cli.json
  • ยืนยันว่า schema ของ request body โผล่ใน Swagger UI โดยไม่ต้องติด decorator เพิ่มเลย

ปัญหา: TypeScript type หายไปตอน runtime

บทที่แล้วเราได้ Swagger UI มาแต่เอกสารยังโล่ง — POST /coffees ไม่บอกเลยว่า body ต้องหน้าตาอย่างไร สาเหตุคือ type ของ TypeScript (รวมถึง DTO ทุกตัวของเรา) ถูกลบทิ้งระหว่าง compile เหลือเพียง JavaScript ล้วน ๆ ตอน runtime จึงไม่มีข้อมูลให้ SwaggerModule สแกน ทางแก้แบบ manual คือไล่ติด @ApiProperty() ทุกฟิลด์ของทุก DTO — ทำได้แต่ซ้ำซากและลืมง่าย

ทางแก้ที่คอร์สนี้เลือกคือ CLI plugin: ปลั๊กอินของ compiler ที่วิเคราะห์โค้ดตอน build แล้วฝัง metadata ที่ Swagger ต้องใช้ให้เองอัตโนมัติ — DTO, entity, ชนิดข้อมูล, ความ optional ของฟิลด์ ทั้งหมดถูกอ่านจาก type ที่เราเขียนอยู่แล้ว

เปิดใช้ใน nest-cli.json

เพิ่ม plugin เข้าไปใน compilerOptions ของไฟล์ nest-cli.json ที่ root ของโปรเจกต์

"compilerOptions": {
  "deleteOutDir": true,
  "plugins": ["@nestjs/swagger/plugin"]
}

plugin ทำงานตามข้อตกลงชื่อไฟล์ (convention): โดย default มันประมวลผลไฟล์ที่ลงท้าย .dto.ts และ .entity.ts — ตรงกับที่เราตั้งชื่อมาตลอดคอร์สพอดี จึงไม่ต้องตั้งค่าอะไรเพิ่ม สิ่งที่ plugin ทำให้ ได้แก่ ติด @ApiProperty ให้ทุก property ของ DTO, อนุมานชนิดข้อมูลจาก type annotation และตั้ง required/optional ตามเครื่องหมาย ?

plugin ทำงานตอน compile — แก้ nest-cli.json แล้วต้อง restart npm run start:dev ใหม่จึงเห็นผล ถ้าเอกสารยังโล่งอยู่ ให้เช็กก่อนเลยว่า dev server ถูก start หลังแก้ไฟล์แล้วจริง ๆ

ให้ DTO ของ iluvcoffee โผล่ในเอกสารเอง

เพิ่ม plugin ใน nest-cli.json restart dev server แล้วเปิด Swagger UI ดู POST /coffees อีกครั้ง

# nest-cli.json { "collection": "@nestjs/schematics", "sourceRoot": "src", "compilerOptions": { "deleteOutDir": true, "plugins": ["@nestjs/swagger/plugin"] } } # restart แล้วเปิดดู npm run start:dev open http://localhost:3000/api

ผลลัพธ์ที่คาดหวัง

POST /coffees ใน Swagger UI แสดง schema ของ CreateCoffeeDto ครบทุกฟิลด์ (name, brand, flavors) พร้อมชนิดข้อมูลที่ถูกต้อง และส่วน Schemas ท้ายหน้าแสดง DTO ทั้งหมดของแอป — ทั้งที่เราไม่ได้ติด decorator ใด ๆ ใน DTO เลย

ตรวจว่าใช้งานได้จริง

  • กาง POST /coffees แล้วเห็น example body ที่ generate จาก CreateCoffeeDto
  • ดู schema ของ PATCH /coffees/{id} คร่าว ๆ — ตอนนี้ UpdateCoffeeDto ยังใช้ PartialType จาก @nestjs/mapped-types (บทที่ 18) อยู่ ฟิลด์อาจยังไม่ถูกทำเครื่องหมาย optional ครบในเอกสารจนกว่าจะสลับไปใช้ PartialType จาก @nestjs/swagger ในบทถัดไป — ยังไม่ต้องแก้อะไรตอนนี้
  • ดูส่วน Schemas ว่ามี DTO ของ pagination ด้วย (PaginationQueryDto)
  • ลองลบ plugin ออกชั่วคราวแล้ว restart เพื่อเห็นความต่าง จากนั้นใส่กลับ
