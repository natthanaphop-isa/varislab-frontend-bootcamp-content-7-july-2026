จัดการ Request Body (Payload)

บทนี้เราจะทำอะไรบ้าง

  • สร้าง endpoint POST /coffees ที่รับ JSON payload
  • ดึง request body เข้ามาใน handler ด้วย @Body()
  • ระบุข้อจำกัดของการรับ body แบบไม่มี type — เพื่อปูทางไปสู่ DTO

POST คือช่องทางส่งข้อมูลเข้า API

การสร้างข้อมูลใหม่ใน REST ใช้ HTTP POST พร้อมแนบข้อมูลมาใน request body เป็น JSON ฝั่ง Nest เรารับ body ได้ด้วย decorator @Body() ในตำแหน่ง parameter ของ handler

/* CoffeesController */
import { Body, Controller, Get, Param, Post } from '@nestjs/common';

@Controller('coffees')
export class CoffeesController {
  @Get()
  findAll() {
    return 'This action returns all coffees';
  }

  @Get(':id')
  findOne(@Param('id') id: string) {
    return `This action returns #${id} coffee`;
  }

  @Post()
  create(@Body() body: any) {
    return body;
  }
}

handler create() ตอนนี้ echo ค่า body กลับไปตรง ๆ เพื่อให้เห็นว่า Nest parse JSON ให้เราแล้วเป็น object พร้อมใช้ — ไม่ต้องตั้งค่า body parser เองเหมือน Express เปล่า ๆ

เช่นเดียวกับ @Param(), decorator @Body('name') แบบระบุ key จะดึงเฉพาะ property นั้นจาก payload มาให้ แต่ระวัง: ถ้ารับแบบเจาะบาง key การ validate ทั้งก้อนในอนาคตจะทำได้ไม่ครบ

รับได้ ไม่ได้แปลว่าปลอดภัย

สังเกตว่า body ตอนนี้ประกาศเป็น any ตรง ๆ (โปรเจกต์ Nest 12 เปิด strict mode ของ TypeScript ถ้าไม่ระบุ type เลย compiler จะฟ้อง implicitly has an 'any' type และ nest start จะไม่ยอมรันแอป) แปลว่าผู้ใช้ส่งอะไรมาก็ได้ — field เกิน, field ขาด, type ผิด — โค้ดเราก็รับหมด ปัญหานี้คือเหตุผลที่บทที่ 15–18 จะแนะนำ DTO (Data Transfer Object) และ ValidationPipe เพื่อประกาศหน้าตา payload ที่ยอมรับและปฏิเสธของแปลกปลอมโดยอัตโนมัติ ตอนนี้ให้จำไว้ก่อนว่า "รับ body ดิบ ๆ เป็นของชั่วคราว"

ยิง POST แรกด้วย JSON payload

เพิ่ม handler create() ตามโค้ดด้านบน แล้วใช้ Insomnia สร้าง request แบบ POST ไปที่ http://localhost:3000/coffees เลือก Body เป็น JSON แล้วส่งข้อมูลกาแฟหนึ่งตัว

curl -i -X POST http://localhost:3000/coffees \ -H "Content-Type: application/json" \ -d '{"name": "Shipwreck Roast", "brand": "Buddy Brew", "flavors": ["chocolate", "vanilla"]}'

ควรได้ผลลัพธ์แบบนี้

ได้ status 201 Created (ค่า default ของ POST ใน Nest) และ response body เป็น JSON ก้อนเดียวกับที่ส่งไป — ยืนยันว่า @Body() parse payload สำเร็จ

ลองเช็กให้แน่ใจ

  • log แสดง Mapped {/coffees, POST} route
  • POST พร้อม JSON ได้ echo กลับครบทุก field รวมถึง array flavors
  • ลองส่ง field แปลกปลอม เช่น "isAdmin": true แล้วสังเกตว่าถูก echo กลับด้วย — นี่คือช่องโหว่ที่ DTO จะมาปิดในบทที่ 16–17
  • ลอง POST โดยไม่ใส่ header Content-Type: application/json แล้วดูว่า body ที่ parse ได้ต่างไปอย่างไร
