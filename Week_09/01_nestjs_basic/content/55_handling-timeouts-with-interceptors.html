จัดการ Timeout ด้วย Interceptors

เมื่อจบบทนี้ คุณจะสามารถ

  • ใช้ RxJS operator (timeout, catchError) ขยายพฤติกรรมของ response stream ใน interceptor
  • ตัด request ที่ไม่ตอบภายในเวลากำหนด แล้วแปลงเป็น RequestTimeoutException
  • ผูก interceptor หลายตัวแบบ global พร้อมกันและเข้าใจลำดับการทำงาน

ขยาย response stream ด้วย RxJS operators

อีกเทคนิคที่ทรงพลังของ interceptor คือการต่อ RxJS operator เข้ากับ response stream เพื่อขยายพฤติกรรมพื้นฐานของ method ลองนึกภาพว่าเราต้องจัดการ timeout ให้กับทุก route: เมื่อ endpoint ไหนไม่ตอบภายในเวลาที่กำหนด เราต้องยุติ request นั้นและส่ง error message กลับไป แทนที่จะปล่อยให้ client ค้างรอไปเรื่อย ๆ — งานแบบนี้เขียนครั้งเดียวใน interceptor ตัวเดียวแล้วมีผลทั้งแอป

nest g interceptor common/interceptors/timeout

TimeoutInterceptor: timeout + catchError

import {
  CallHandler,
  ExecutionContext,
  Injectable,
  NestInterceptor,
  RequestTimeoutException,
} from '@nestjs/common';
import { Observable, throwError, TimeoutError } from 'rxjs';
import { catchError, timeout } from 'rxjs/operators';

@Injectable()
export class TimeoutInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    return next.handle().pipe(
      timeout(3000),
      catchError(err => {
        if (err instanceof TimeoutError) {
          return throwError(new RequestTimeoutException());
        }
        return throwError(err);
      }),
    );
  }
}

pipeline อ่านตรงตัว: timeout(3000) จะโยน TimeoutError ของ RxJS ถ้า handler ไม่ emit ค่าภายใน 3 วินาที จากนั้น catchError ดักทุก error ในสาย — ถ้าเป็น TimeoutError ก็แปลงเป็น RequestTimeoutException ของ NestJS (HTTP 408) เพื่อให้เข้าระบบ exception layer และ HttpExceptionFilter ของเราตามปกติ ส่วน error ชนิดอื่นถูกโยนต่อไม่แตะต้อง

ผูกหลาย interceptor พร้อมกัน

useGlobalInterceptors รับได้หลายตัวเรียงตามลำดับ — request ไหลผ่านจากซ้ายไปขวาขาเข้า และย้อนกลับขาออก

app.useGlobalInterceptors(
  new WrapResponseInterceptor(),
  new TimeoutInterceptor(),
);

ระหว่างทดสอบ เราบังคับให้ endpoint ช้าเกิน 3 วินาทีด้วยการหน่วงชั่วคราวใน handler เช่นใน findAll() ของ CoffeesController

await new Promise(resolve => setTimeout(resolve, 5000));

อย่าลืมลบบรรทัดหน่วงเวลานี้ออกหลังทดสอบเสร็จ — มันมีไว้เพียงเพื่อพิสูจน์ว่า interceptor ทำงาน ถ้าติดไปกับโค้ดจริงทุก request จะโดนตัดที่ 3 วินาทีทั้งหมด นอกจากนี้ throwError(value) เป็นรูปแบบเก่าของ RxJS — เวอร์ชันปัจจุบันแนะนำ throwError(() => new RequestTimeoutException())

บังคับ timeout ให้เกิดจริงใน iluvcoffee

สร้าง TimeoutInterceptor ผูกต่อจาก WrapResponseInterceptor ใน main.ts แล้วหน่วง findAll() 5 วินาทีเพื่อดู 408 ด้วยตาตัวเอง

nest g interceptor common/interceptors/timeout # coffees.controller.ts — ใน findAll() (ชั่วคราว) await new Promise(resolve => setTimeout(resolve, 5000)); # ทดสอบ curl -i http://localhost:3000/coffees

ผลลัพธ์ที่คาดหวัง

request ค้างประมาณ 3 วินาที (ไม่ใช่ 5) แล้วได้ 408 Request Timeout พร้อม body รูปแบบกลางจาก filter เช่น { "statusCode": 408, "message": "Request Timeout", "timestamp": "..." } เมื่อลบบรรทัดหน่วงออก endpoint กลับมาตอบปกติ

ตรวจว่าใช้งานได้จริง

  • จับเวลา request ที่หน่วงไว้ — ต้องถูกตัดที่ ~3 วินาทีตามค่า timeout(3000) ไม่ใช่รอครบ 5 วินาที
  • ตรวจ status code ว่าเป็น 408 และ body มี timestamp จาก HttpExceptionFilter
  • ลบบรรทัดหน่วงเวลาแล้วยิงซ้ำ — ต้องได้ 200 พร้อม response ที่ยังห่อใน data จาก interceptor ตัวแรก
  • ลองเปลี่ยนค่า timeout เป็น 100 ms เพื่อยืนยันว่า endpoint จริง ๆ ก็โดนตัดได้ แล้วปรับกลับ
