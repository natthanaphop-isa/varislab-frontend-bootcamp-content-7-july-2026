ใช้ Transactions (MongoDB)

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายได้ว่า transaction คืออะไร และเหตุใดงานที่เขียนข้อมูลหลายจุดต้อง "สำเร็จทั้งคู่หรือไม่สำเร็จเลย"
  • สร้าง Event schema สำหรับเก็บเหตุการณ์เพื่อใช้วิเคราะห์ข้อมูลภายหลัง
  • ใช้ @InjectConnection() เปิด session, commit และ abort transaction ใน Mongoose ได้ถูกจังหวะ

โจทย์ธุรกิจ: recommend กาแฟ แล้วต้องเก็บ Event ด้วย

สมมติมี requirement ใหม่เข้ามา: ทีม product อยากให้ผู้ใช้ "recommend" กาแฟได้ และทุกครั้งที่เกิดขึ้น ต้องบันทึก Event ลงฐานข้อมูลไว้ใช้ทำ data analytics ภายหลัง งานนี้จึงมีสองส่วน — endpoint ใหม่สำหรับ recommend และการบันทึก Event ต่อจากนั้น — ซึ่งทั้งสองอย่างต้องสำเร็จด้วยกัน ไม่อย่างนั้นข้อมูลใน database จะไม่สอดคล้องกัน (เช่น ยอด recommendations ขยับแต่ไม่มี Event หรือกลับกัน)

นี่คือหน้าที่ของ transaction: หน่วยของงาน (unit of work) ที่ระบบฐานข้อมูลรับประกันว่าคำสั่งข้างในจะเกิดผลทั้งหมดหรือไม่เกิดเลย และเป็นอิสระจาก transaction อื่นที่วิ่งอยู่พร้อมกัน

สร้าง Event schema

# Generate Event entity (ไม่เอาไฟล์ test)
nest g class events/entities/event.entity --no-spec
/* Event entity - FINAL CODE */
import { Prop, Schema, SchemaFactory } from '@nestjs/mongoose';
import * as mongoose from 'mongoose';

@Schema()
export class Event extends mongoose.Document {
  @Prop()
  type: string;

  @Prop()
  name: string;

  @Prop({ type: mongoose.SchemaTypes.Mixed }) // 👈 ต้องส่งเป็น { type } — @nestjs/mongoose 12 อนุมาน type ของ Record<string, any> เองไม่ได้
  payload: Record<string, any>;
}

export const EventSchema = SchemaFactory.createForClass(Event);

สังเกตว่าชื่อ class คือ Event เฉย ๆ (ตัดคำว่า "entity" ออกจากชื่อ) และ payload ใช้ชนิด Mixed เพื่อรับโครงสร้างอะไรก็ได้ อย่าลืมลงทะเบียน schema นี้เพิ่มใน MongooseModule.forFeature() ของ module ที่ใช้งาน เช่นเดียวกับที่ทำกับ Coffee

เปิด session แล้วครอบงานทั้งสองไว้ใน transaction เดียว

การทำ transaction ใน Mongoose เริ่มจาก connection ระดับแอป ซึ่ง inject ได้ด้วย @InjectConnection() จากนั้นเปิด session, สั่งงานทุกอย่างโดยแนบ { session }, แล้ว commit เมื่อครบ — หรือ abort เมื่อมีขั้นตอนใดล้ม

/* ส่วนสำคัญของ CoffeesService - FINAL CODE */
import { InjectConnection, InjectModel } from '@nestjs/mongoose';
import type { Connection, Model } from 'mongoose'; // 👈 import type — mongoose เป็น CommonJS และไม่ expose "Connection" เป็น named export ตอน runtime ใน ES module
import { Event } from '../events/entities/event.entity.js';

@Injectable()
export class CoffeesService {
  constructor(
    @InjectModel(Coffee.name) private readonly coffeeModel: Model<Coffee>,
    @InjectConnection() private readonly connection: Connection,
    @InjectModel(Event.name) private readonly eventModel: Model<Event>,
  ) {}

  // ...CRUD methods เดิมจากบทที่ 75 คงไว้ทั้งหมด...

  async recommendCoffee(coffee: Coffee) {
    const session = await this.connection.startSession();
    session.startTransaction();

    try {
      coffee.recommendations++;

      const recommendEvent = new this.eventModel({
        name: 'recommend_coffee',
        type: 'coffee',
        payload: { coffeeId: coffee._id }, // ใช้ _id (ObjectId) — virtual "id" ไม่มีใน type ของ Document ที่ extends มา
      });
      await recommendEvent.save({ session });
      await coffee.save({ session });

      await session.commitTransaction();
    } catch (err) {
      await session.abortTransaction();
    } finally {
      session.endSession();
    }
  }
}

โค้ดนี้อ้าง coffee.recommendations — อย่าลืมเพิ่ม @Prop({ default: 0 }) recommendations: number; เข้าไปใน Coffee schema ของบทที่ 73 ก่อน ไม่อย่างนั้นค่าจะเป็น NaN

MongoDB รองรับ multi-document transaction เฉพาะเมื่อรันเป็น replica set เท่านั้น container แบบ standalone จากบทที่ 71 ไม่โยน error ตอน session.startTransaction() (เมธอดนี้แค่ตั้งค่า flag ในตัว session เท่านั้น) แต่จะโยน error ตอนมีคำสั่งเขียนแรกที่แนบ { session } เข้าไปจริง (ในโค้ดนี้คือ recommendEvent.save({ session })) — สำหรับการเรียนแนวคิดนี้ถือว่าปกติ (โค้ดจับได้ใน catch อยู่แล้วไม่ว่า error จะเกิดจากบรรทัดไหนใน try) แต่ถ้าอยากเห็น transaction ทำงานจริง ต้องตั้งค่า mongo ใน docker-compose ให้เป็น replica set โหนดเดียว (--replSet) ก่อน

เพิ่ม endpoint สำหรับ recommend coffee

สร้าง Event schema, ลงทะเบียนใน forFeature, เพิ่มฟิลด์ recommendations ให้ Coffee, เพิ่ม method recommendCoffee() ตามด้านบน แล้วเปิด route ใหม่ใน controller ที่หา coffee จาก id ก่อนส่งเข้า method นี้

# ตัวอย่าง handler ใน CoffeesController # @Post(':id/recommend') # async recommend(@Param('id') id: string) { # const coffee = await this.coffeesService.findOne(id); # return this.coffeesService.recommendCoffee(coffee); # } POST http://localhost:3000/coffees/<_id>/recommend

ผลลัพธ์ที่คาดหวัง

บน replica set: ยิง recommend แล้ว recommendations ของกาแฟเพิ่มขึ้นหนึ่ง และ collection events มี document recommend_coffee ใหม่พร้อมกันเสมอ — ไม่มีทางเกิดอย่างใดอย่างหนึ่งเพียงลำพัง บน standalone: การเขียนทั้งคู่ถูก abort และข้อมูลไม่ขยับ ซึ่งพิสูจน์พฤติกรรม all-or-nothing เช่นกัน

ตรวจว่าใช้งานได้จริง

  • db.coffees.find() และ db.events.find() ใน mongosh ขยับพร้อมกันหลังยิง recommend สำเร็จ
  • จำนวน document ใน events เท่ากับจำนวนครั้งที่ recommend สำเร็จพอดี
  • ทดลองทำให้ขั้นตอนใน try ล้ม (เช่น throw ก่อน commitTransaction) แล้วยืนยันว่าไม่มีข้อมูลค้างครึ่งทาง
  • ไม่มี session รั่ว: endSession() อยู่ใน finally จึงถูกเรียกทุกเส้นทาง
