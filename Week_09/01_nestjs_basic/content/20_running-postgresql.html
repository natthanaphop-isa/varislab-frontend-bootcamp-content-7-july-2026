รัน PostgreSQL ด้วย Docker Compose

เมื่อจบบทนี้ คุณจะสามารถ

  • เขียน docker-compose.yml ที่รัน PostgreSQL container สำหรับพัฒนา
  • อธิบายความหมายของ image, ports และ environment ในไฟล์ compose
  • start และ stop ฐานข้อมูลด้วยคำสั่งเดียวโดยไม่ติดตั้ง Postgres ลงเครื่องตรง ๆ

ทำไมต้อง Docker

เราต้องการ PostgreSQL ไว้ให้แอปต่อ แต่การติดตั้งฐานข้อมูลลง OS ตรง ๆ ทั้งยุ่งยาก ผูกเวอร์ชันกับเครื่อง และลบออกยาก การรันเป็น Docker container แก้ครบทุกข้อ: ทีมทุกคนได้เวอร์ชันเดียวกัน สั่งเปิด-ปิดได้ในวินาที และเครื่องคุณไม่สกปรก สิ่งเดียวที่ต้องมีคือ Docker Desktop (หรือ Docker Engine) ที่รันอยู่

สร้างไฟล์ docker-compose.yml ที่ root ของโปรเจกต์:

version: "3"
services:
  db:
    image: postgres
    restart: always
    ports:
      - "5432:5432"
    environment:
      POSTGRES_PASSWORD: pass123

อ่านทีละบรรทัด: service ชื่อ db ใช้ official image postgres, restart: always ให้ container ฟื้นเองถ้าล่ม, ports map พอร์ต 5432 ใน container ออกมาที่ 5432 ของเครื่องเรา (พอร์ตมาตรฐานของ Postgres) และ environment ตั้งรหัสผ่านของ user postgres เป็น pass123

คำสั่งประจำวัน

# start ฐานข้อมูลแบบ detached (รันเบื้องหลัง)
docker-compose up -d

# stop และเก็บ container
docker-compose down

ธง -d (detached) ทำให้ container รันเบื้องหลังโดยไม่ยึด terminal ของเรา ส่วน docker-compose down หยุดและลบ container ทิ้ง (ข้อมูลจะหายด้วยหากยังไม่ได้ตั้ง volume — สำหรับการเรียนถือว่ายอมรับได้ เพราะบทถัด ๆ ไปเราสั่ง prisma db push ให้สร้าง schema ใหม่ได้ในคำสั่งเดียว)

Docker รุ่นใหม่ใช้ docker compose (เว้นวรรค) แทน docker-compose ได้เช่นกัน — ทั้งสองคำสั่งอ่านไฟล์ docker-compose.yml เดียวกัน

ถ้าเครื่องคุณเคยติดตั้ง PostgreSQL ไว้อยู่แล้ว พอร์ต 5432 จะชนกันและ container จะ start ไม่ขึ้น — ปิด service เดิมก่อน หรือเปลี่ยนฝั่งซ้ายของ mapping เป็นพอร์ตอื่น เช่น "5433:5432" (แล้วจำไว้ใส่ใน DATABASE_URL ตอนตั้งค่า Prisma ในบทที่ 22)

ยกฐานข้อมูลขึ้นมาให้ได้ในสามคำสั่ง

สร้าง docker-compose.yml ตามตัวอย่าง แล้ว start container และตรวจสถานะ

docker-compose up -d docker-compose ps docker-compose logs db

ผลลัพธ์ที่คาดหวัง

docker-compose ps แสดง service db สถานะ Up ที่พอร์ต 5432 และใน log มีบรรทัด database system is ready to accept connections — ฐานข้อมูลพร้อมให้ NestJS ต่อในบทที่ 22

ตรวจว่าใช้งานได้จริง

  • docker-compose ps เห็น container สถานะ Up และ mapping 0.0.0.0:5432->5432/tcp
  • log ของ db จบด้วย ready to accept connections โดยไม่มี error
  • ทดสอบต่อจากในเครื่อง: docker exec -it <container> psql -U postgres เข้า prompt postgres=# ได้
  • docker-compose down แล้ว docker-compose up -d ใหม่ ยังกลับมา Up ได้ปกติ
