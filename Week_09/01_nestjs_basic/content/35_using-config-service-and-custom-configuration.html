ใช้ ConfigService และจัดโครงสร้าง Configuration

บทนี้เราจะทำอะไรบ้าง

  • Inject ConfigService เข้า provider แทนการอ่าน process.env ตรง ๆ
  • อ่านค่าด้วย get<T>() พร้อมระบุ type และค่า default
  • สร้าง custom configuration file เพื่อจัดกลุ่มค่า แปลงชนิดข้อมูล และอ่านค่าซ้อนกันด้วย dot notation

จาก process.env สู่ ConfigService

การหยิบ process.env.DATABASE_URL ตรง ๆ ทำงานได้ แต่กระจาย dependency ไปทั่วโค้ดแบบมองไม่เห็น และ mock ยากเวลาเขียนเทสต์ @nestjs/config จึงมี ConfigService ให้ inject ผ่านระบบ dependency injection ปกติของ Nest — จุดเดียวที่รู้เรื่อง environment ทั้งหมด

import { ConfigService } from '@nestjs/config';

@Injectable()
export class CoffeesService {
  constructor(
    private readonly configService: ConfigService,
  ) {}
}

เนื่องจากบทที่แล้วเราประกาศ ConfigModule.forRoot({ isGlobal: true }) ไว้ที่ AppModule แล้ว ConfigService จึง inject ได้ทุก module โดยไม่ต้อง import ConfigModule ซ้ำ

อ่านค่าด้วย get() แบบระบุ type และ default

เมธอด get() รับชื่อ key และคืนค่าจาก environment; ใส่ generic type เพื่อบอก TypeScript ว่าคาดหวังชนิดใด และส่ง argument ตัวที่สองเป็นค่า default เมื่อ key ไม่ถูกตั้งไว้

const databaseUrl = this.configService.get<string>('DATABASE_URL');
console.log(databaseUrl);

// พร้อมค่า default เมื่อไม่พบ key
const port = this.configService.get<number>('PORT', 3000);
วิธีข้อดีข้อจำกัด
process.env.KEYสั้น ไม่ต้องพึ่งอะไรเป็น string | undefined เสมอ, mock ในเทสต์ยาก, dependency ซ่อนเร้น
configService.get<T>('KEY')ผ่าน DI จึง mock ง่าย, ระบุ type และ default ได้, จุดเข้าถึงเดียวต้อง import ConfigModule ให้ถูก scope

จัด config ให้เป็น object ที่อ่านง่าย

เมื่อจำนวน environment variables เพิ่มขึ้น การเรียก key แบน ๆ อย่าง DATABASE_URL กระจายทั่วโปรเจกต์จะเริ่มดูแลยาก เราจึงสร้าง factory function ที่รวมการอ่านค่า การกำหนด default และการแปลงชนิดข้อมูลไว้จุดเดียว

// src/config/app.config.ts
export default () => ({
  environment: process.env.NODE_ENV || 'development',
  port: parseInt(process.env.PORT ?? '3000', 10),
  database: {
    url: process.env.DATABASE_URL,
  },
});

ไฟล์นี้เป็นขอบเขตที่แตะ process.env ส่วน provider อื่นจะเห็น object ที่มีโครงสร้างชัดเจน และไม่ต้องแปลง PORT จาก string ซ้ำเองทุกจุด

โหลด custom configuration แล้วอ่านด้วย dot notation

// app.module.ts
import appConfig from './config/app.config.js';
import Joi from 'joi';

ConfigModule.forRoot({
  // เก็บ validation และ isGlobal จากบทก่อนเอาไว้
  validationSchema: Joi.object({
    DATABASE_URL: Joi.string().required(),
    PORT: Joi.number().default(3000),
  }),
  isGlobal: true,
  load: [appConfig],
});

// อ่านใน provider ผ่าน ConfigService
const databaseUrl = this.configService.get<string>('database.url');
const port = this.configService.get<number>('port', 3000);

load รับ array ของ factory functions จึงแยก config เป็นหลายไฟล์ได้ในอนาคต ส่วนตอนนี้มีไฟล์เดียวพอ และเรายังคง validationSchema จากบทก่อนเอาไว้ เพื่อให้แอปตรวจค่าก่อนนำไปสร้าง config object

อ่าน config ที่จัดกลุ่มแล้วผ่าน ConfigService

สร้าง src/config/app.config.ts, ลงทะเบียนผ่าน load แล้ว inject ConfigService ใน CoffeesService เพื่อลองอ่าน database.url และ port จาก object ใหม่

mkdir -p src/config # สร้าง src/config/app.config.ts ตามตัวอย่างด้านบน # ไม่ต้องแก้ coffees.module.ts เพราะ ConfigModule เป็น global แล้วตั้งแต่บทก่อน // coffees.service.ts import { ConfigService } from '@nestjs/config'; constructor( private readonly prisma: PrismaService, private readonly configService: ConfigService, ) { const databaseUrl = this.configService.get<string>('database.url'); const port = this.configService.get<number>('port', 3000); console.log(databaseUrl, port); } npm run start:dev

ควรได้ผลลัพธ์แบบนี้

เทอร์มินัลพิมพ์ connection string ที่ตรงกับ .env และเลขพอร์ต 3000 จากค่า default โดยที่ CoffeesService ไม่แตะ process.env โดยตรง ทดสอบเสร็จแล้วให้ลบ log เพื่อไม่ให้ credentials ค้างอยู่

ลองเช็กให้แน่ใจ

  • get('database.url') คืนค่าตรงกับ DATABASE_URL ใน .env
  • get('environment') คืน development เมื่อไม่ได้ตั้ง NODE_ENV
  • get('port') คืน number เพราะแปลงชนิดข้อมูลใน config factory แล้ว
  • แอปยัง start และ GET /coffees ทำงานปกติ ไม่มี DI error
