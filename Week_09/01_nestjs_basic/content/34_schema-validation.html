ตรวจ Environment Variables ด้วย Schema

บทนี้เราจะทำอะไรบ้าง

  • เข้าใจแนวคิด fail fast และเหตุผลที่ควรตรวจ config ตั้งแต่เปิดแอป
  • ติดตั้ง Joi และส่ง validationSchema ให้ ConfigModule
  • กำหนดได้ว่าค่าไหนจำเป็น และค่าไหนควรมี default

ทำไมต้องตรวจ env ตั้งแต่เปิดแอป

ลองนึกว่า DATABASE_URL หายไปหรือสะกดผิด ถ้าเราไม่ตรวจไว้ก่อน แอปอาจเปิดขึ้นมาได้ แล้วค่อยเจอ error จาก PostgreSQL ตอน PrismaService เริ่มเชื่อมต่อ ปัญหาคือ error แบบนี้อยู่ไกลจากต้นเหตุ ทำให้เสียเวลาตามหาว่าค่าไหนผิด

ทางแก้คือเขียน schema บอกว่าแอปต้องใช้ environment variables อะไรบ้าง แล้วให้ ConfigModule ตรวจระหว่าง bootstrap ถ้าค่าไหนหายไปหรือชนิดไม่ตรง แอปจะหยุดทันทีและบอกชื่อ key ที่มีปัญหา วิธีนี้เรียกว่า fail fast

ติดตั้ง Joi แล้วเขียน schema

เราจะใช้ Joi กำหนดรูปแบบของ config ที่แอปยอมรับ แพ็กเกจนี้มี TypeScript types มาให้แล้ว จึงไม่ต้องติดตั้ง @types เพิ่ม:

npm install joi
// app.module.ts
import Joi from 'joi';

@Module({
  imports: [
    ConfigModule.forRoot({
      validationSchema: Joi.object({
        DATABASE_URL: Joi.string().required(),
        PORT: Joi.number().default(3000),
      }),
      isGlobal: true,
    }),
    // ...
  ],
})
export class AppModule {}

schema นี้มีกติกาสองข้อ: DATABASE_URL ต้องมีเสมอ ส่วน PORT ต้องเป็นตัวเลข ถ้าไม่ได้กำหนดไว้ Joi จะใช้ 3000 เป็นค่า default ให้ จากนี้ config ที่ไม่ครบจะถูกจับได้ก่อนแอปเริ่มรับ request

คอร์สต้นฉบับใช้ @hapi/joi แต่แพ็กเกจนั้น deprecated แล้ว ปัจจุบันให้ติดตั้ง joi แทน โปรเจกต์ Nest 12 ของเราเป็น ES module จึงใช้ default import (import Joi from 'joi') ไม่ใช่ import * as Joi แบบเก่า ส่วนแนวคิดและ API ในบทนี้ยังเหมือนเดิม

ลองทำให้แอป fail fast

เพิ่ม validationSchema สำหรับ DATABASE_URL และ PORT จากนั้นลบ DATABASE_URL ออกจาก .env ชั่วคราว แล้วลองเปิดแอปเพื่อดูว่า error ชี้มาที่ config โดยตรงหรือไม่ เมื่อทดสอบเสร็จแล้วให้ใส่ค่ากลับ

npm install joi // เพิ่ม validationSchema ใน ConfigModule.forRoot() // จากนั้นทดสอบ fail fast: # 1) คอมเมนต์บรรทัด DATABASE_URL ใน .env # 2) npm run start:dev → ควรเห็น validation error # 3) เอาคอมเมนต์ออก แล้ว start ใหม่

ควรได้ผลลัพธ์แบบนี้

ถ้า DATABASE_URL หายไป แอปควรหยุดตั้งแต่เริ่มพร้อมข้อความประมาณ Config validation error: "DATABASE_URL" is required เมื่อใส่ค่ากลับ แอปควรเปิดและ query ฐานข้อมูลได้ตามปกติ

ลองเช็กให้แน่ใจ

  • ลบ DATABASE_URL แล้วเปิดแอป — error ระบุชื่อ key ชัดเจน ไม่ใช่ error จาก PostgreSQL driver
  • ไม่กำหนด PORT — แอปยังเปิดได้ที่พอร์ต default 3000
  • กำหนด PORT=abc — Joi แจ้งว่าค่านี้ต้องเป็น number
  • เมื่อ .env ครบถ้วน GET /coffees ยังทำงานปกติ
