รู้จัก Config Module

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายได้ว่าทำไม configuration ควรอยู่ใน environment ไม่ใช่ hardcode ในโค้ด
  • ติดตั้ง @nestjs/config และสร้างไฟล์ .env ที่ไม่ถูก track โดย git
  • ให้ ConfigModule เป็นผู้โหลด DATABASE_URL จาก .env แทนการ import 'dotenv/config' เองใน main.ts

ทำไม configuration ต้องแยกออกจากโค้ด

แอปพลิเคชันมักรันในหลาย environment — development, staging, production — ซึ่งแต่ละที่ใช้ค่าต่างกัน เช่น host ของฐานข้อมูล, credentials หรือ API key แนวปฏิบัติมาตรฐานของชุมชน Node.js คือเก็บค่าเหล่านี้ไว้ใน environment variables ผ่าน object global process.env เพื่อให้โค้ดชุดเดียวรันได้ทุกที่โดยเปลี่ยนแค่ค่าแวดล้อม

@nestjs/config ช่วยให้เรื่องนี้ง่ายขึ้น: เมื่อเรียก ConfigModule.forRoot() มันจะอ่านไฟล์ .env ที่ root ของโปรเจกต์ แล้ว merge คู่ key/value เข้ากับ process.env ให้อัตโนมัติ

npm i @nestjs/config
// app.module.ts
import { ConfigModule } from '@nestjs/config';

@Module({
  imports: [
    ConfigModule.forRoot(),
    // ...imports อื่น ๆ
  ],
})
export class AppModule {}

ไฟล์ .env ที่เรามีอยู่แล้ว และการกันไม่ให้หลุดขึ้น git

ตั้งแต่บทที่ 22 npx prisma init สร้างไฟล์ .env ที่ root ของ iluvcoffee ไว้ให้ และเราเก็บ connection string ของ PostgreSQL ไว้ในนั้นมาตลอด

DATABASE_URL="postgresql://postgres:pass123@localhost:5432/postgres"

ไฟล์ .env มี credentials จริง ห้าม commit ขึ้น repository เด็ดขาด — prisma init ในบทที่ 22 เพิ่ม .env ลง .gitignore ให้แล้ว แต่บทถัดไปเราจะมีไฟล์ env หลายชื่อ จึงควรขยายเป็นแพทเทิร์น *.env ตั้งแต่ตอนนี้ แล้วตรวจด้วย git status ว่าไฟล์ไม่โผล่ในรายการ

# .gitignore
# Env
.env
*.env

ให้ ConfigModule โหลด .env แทน dotenv ที่เราใส่เองใน main.ts

ในบทที่ 22 เราแก้ขัดด้วยการ import 'dotenv/config' ไว้บรรทัดแรกของ main.ts เพื่อให้ process.env.DATABASE_URL มีค่าก่อน PrismaService ถูกสร้าง ตอนนี้ลบบรรทัดนั้นทิ้งแล้วให้ ConfigModule.forRoot() รับหน้าที่แทน — ผลลัพธ์เหมือนกัน แต่ต่อจากนี้เราจะได้ ConfigService, การ validate และ namespaces ในบทถัด ๆ ไปเป็นของแถม

// main.ts — ลบบรรทัดนี้ออก
- import 'dotenv/config';

// app.module.ts
@Module({
  imports: [
    ConfigModule.forRoot(),
    PrismaModule,
    CoffeesModule,
  ],
})
export class AppModule {}

// prisma/prisma.service.ts — ไม่ต้องแก้อะไร ยังอ่านจาก process.env เหมือนเดิม
super({
  adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }),
});

ConfigModule.forRoot() อ่าน .env ตอนที่ imports array ถูกประเมิน ซึ่งเกิดก่อน Nest จะสร้าง provider ใด ๆ ดังนั้น constructor ของ PrismaService จึงเห็นค่าเสมอไม่ว่าจะวาง PrismaModule ไว้ก่อนหรือหลัง ส่วน prisma7.config.ts ยังต้องมี import "dotenv/config" ของตัวเองต่อไป เพราะ Prisma CLI ทำงานนอก NestJS

ข้อยกเว้นคือค่าที่ถูกอ่านจาก process.env ตอน import module แทนที่จะอ่านใน constructor — เช่น DatabaseModule.register({ connectionString: process.env.DATABASE_URL! }) ใน coffee-rating.module.ts จากบทที่ 39 ES module จะโหลด coffee-rating.module.ts (ซึ่งประเมิน process.env.DATABASE_URL ทันที) ก่อนที่ app.module.ts จะรัน ConfigModule.forRoot() เสมอ เพราะ static import ของไฟล์ที่ถูก import จะถูกประเมินก่อนโค้ดของไฟล์ที่ import มันทุกครั้ง ผลคือหลังลบ import 'dotenv/config' ออกจาก main.ts แล้ว connectionString ที่ DatabaseModule.register() ได้รับจะเป็น undefined — provider 'CONNECTION' ตัวนั้นเป็นแค่ของสาธิต ไม่ได้ถูกใช้จริงใน CoffeesService (ดูคำเตือนในบทที่ 39) และปัญหานี้จะถูกแก้ในบทที่ 48 ด้วย DatabaseModule.registerAsync()

ผลที่ตามมารุนแรงกว่านั้น: ถ้า CoffeeRatingService.onModuleInit() จากบทที่ 39 ยังเรียก this.connection.$queryRaw อยู่ (ตามที่บทนั้นให้ทำ) การได้ connectionString เป็น undefined จะไม่ใช่แค่ค่า demo ที่เงียบ ๆ — Postgres driver จะ throw Error: SASL: SCRAM-SERVER-FIRST-MESSAGE: client password must be a string เป็น unhandled rejection ระหว่าง bootstrap ซึ่ง ทำให้ทั้งแอป process ตายทันที (ไม่ใช่แค่ endpoint /coffees ใช้ไม่ได้ — แอปทั้งตัว start ไม่สำเร็จเลย) ก่อนลบ import 'dotenv/config' ให้ห่อ query สาธิตนั้นด้วย try/catch ชั่วคราวก่อน เพื่อกันไม่ให้บทนี้ถึงบทที่ 47 พังทั้งแอป

// coffee-rating.service.ts — กันชั่วคราวจนกว่าบทที่ 48 จะแก้ด้วย registerAsync
async onModuleInit() {
  try {
    console.log(await this.connection.$queryRaw`SELECT current_database()`);
  } catch (err) {
    console.warn('CONNECTION demo unavailable (expected until lesson 48):', (err as Error).message);
  }
}

ส่งมอบหน้าที่โหลด .env ให้ ConfigModule

ติดตั้ง @nestjs/config, ตรวจว่า *.env อยู่ใน .gitignore, ห่อ $queryRaw ใน CoffeeRatingService.onModuleInit() ด้วย try/catch ตามตัวอย่างด้านบน (ชั่วคราวจนกว่าบทที่ 48), import ConfigModule.forRoot() ใน AppModule แล้วลบ import 'dotenv/config' ออกจาก main.ts

npm i @nestjs/config # ห่อ this.connection.$queryRaw ใน coffee-rating.service.ts ด้วย try/catch (ดูตัวอย่างด้านบน) # ลบ import 'dotenv/config' ใน src/main.ts # เพิ่ม ConfigModule.forRoot() ใน AppModule # ตรวจว่า *.env อยู่ใน .gitignore npm run start:dev

ผลลัพธ์ที่คาดหวัง

แอป start ขึ้นและเชื่อมต่อ PostgreSQL ได้เหมือนเดิมทุกประการ ทั้งที่ main.ts ไม่มี dotenv แล้ว และ git status ไม่แสดงไฟล์ .env ในรายการไฟล์ที่จะถูก commit

ตรวจว่าใช้งานได้จริง

  • GET /coffees ยังตอบข้อมูลจากฐานข้อมูลได้ปกติหลังถอด dotenv ออกจาก main.ts
  • ลองแก้รหัสผ่านใน DATABASE_URL ของ .env ให้ผิดแล้ว restart — แอปต้องต่อฐานข้อมูลไม่ได้ ยืนยันว่าค่าถูกอ่านจากไฟล์ผ่าน ConfigModule จริง (แก้กลับเมื่อทดสอบเสร็จ)
  • git status ไม่มี .env โผล่ในรายการ untracked/staged
  • คอมเมนต์ ConfigModule.forRoot() ออกชั่วคราว — แอปต้อง start ไม่ผ่านเพราะ DATABASE_URL เป็น undefined (แล้วใส่กลับ)
