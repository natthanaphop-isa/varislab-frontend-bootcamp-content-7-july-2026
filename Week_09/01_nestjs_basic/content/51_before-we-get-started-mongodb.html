ก่อนเริ่มบท MongoDB: กลับไปที่จุดจบ Chapter 2

บทนี้เราจะทำอะไรบ้าง

  • อธิบายได้ว่าทำไมเส้นทาง MongoDB จึงแตกต่อจากจุดจบของ Chapter 2 (บทที่ 18) ไม่ใช่ต่อจากบทล่าสุด
  • สลับ repository กลับไปยัง branch ที่บันทึกไว้ในบทที่ 19 โดยไม่ทำให้งานฝั่ง SQL สูญหาย
  • วางแผนได้ว่าจะเรียนเส้นทาง SQL, NoSQL หรือทั้งสองอย่าง ให้เหมาะกับโปรเจกต์ของตัวเอง

เส้นทางโบนัสนี้เริ่มจากโค้ดของ Chapter 2 ไม่ใช่โค้ดล่าสุด

ทุกบทในเส้นทาง MongoDB (บทที่ 51–58) เขียนต่อจากโค้ดที่เราสร้างจบใน Chapter 2 "Creating a REST API Application" (บทที่ 18) — คือ CRUD ของ coffees ที่ยังเก็บข้อมูลใน memory และยังไม่พ่วง Prisma เหตุผลที่คอร์สออกแบบแบบนี้คือ ให้คุณเห็นและเปรียบเทียบได้ชัด ๆ ว่าแอปเดียวกันใช้ NoSQL หรือ SQL ทำฟีเจอร์แบบเดียวกันด้วย NestJS ต่างกันอย่างไร ตั้งแต่การประกาศ model, การ inject ตัวเข้าถึงข้อมูล ไปจนถึง pagination, transactions และ indexes

การแยก section NoSQL กับ SQL ออกจากกันยังทำให้คุณเลือกเรียนเฉพาะเส้นทางที่โปรเจกต์ของคุณใช้จริงได้ หรือจะเรียนทั้งสองเส้นทางเพื่อเทียบกันก็ได้เช่นกัน

สลับกลับไปยัง branch ที่บันทึกไว้ในบทที่ 19

ในบทที่ 19 เราเก็บโค้ดตอนจบ Chapter 2 ไว้ใน branch แยกก่อนเริ่ม PostgreSQL ตอนนี้เราจะกลับมาใช้ branch นั้น ก่อนสลับ branch ให้ commit งานฝั่ง SQL ที่ทำค้างไว้ให้เรียบร้อย เพื่อให้ทั้งสองเส้นทางไม่ปะปนกัน

อย่าเริ่มเส้นทาง MongoDB ทับโค้ดที่มี Prisma อยู่: dependencies และโครงของ CoffeesService จะปนกันจนเทียบกับเนื้อหาบทเรียนไม่ได้ ถ้าไม่แน่ใจว่า working tree สะอาดหรือยัง ให้รัน git status ก่อนสลับ branch เสมอ

เช็กพอยต์: พางานกลับไปที่จุดจบ Chapter 2

ใน repository iluvcoffee ให้ commit งานฝั่ง SQL ที่ค้างอยู่ แล้วสลับไปยัง branch ที่คุณตั้งชื่อไว้ในบทที่ 19 (ในตัวอย่างของบทที่ 19 ใช้ชื่อ end-of-chapter-2 — แทนด้วยชื่อจริงของคุณถ้าตั้งไว้ต่างออกไป)

git status git add -A && git commit -m "จบเส้นทาง PostgreSQL/Prisma" git branch --list git switch end-of-chapter-2 npm install npm run start:dev

ควรได้ผลลัพธ์แบบนี้

แอปกลับมารันได้ในสภาพเดียวกับตอนจบบทที่ 18: endpoint GET /coffees ตอบข้อมูลจาก in-memory array, ไม่มี @prisma/client ใน package.json และไม่มีโฟลเดอร์ prisma/, src/prisma/ หรือ src/generated/ เหลืออยู่ใน branch นี้ ส่วนงานฝั่ง SQL ทั้งหมดยังปลอดภัยอยู่ใน branch เดิม

ลองเช็กให้แน่ใจ

  • git branch --show-current แสดงชื่อ branch ของ Chapter 2 ไม่ใช่ branch ฝั่ง SQL
  • git log --oneline -1 บน branch ฝั่ง SQL ยังเห็น commit ล่าสุดของงาน Prisma ครบถ้วน
  • เปิด src/coffees/coffees.service.ts แล้วเห็นข้อมูลเก็บใน array ไม่ใช่ PrismaService
  • รัน npm run start:dev แล้วยิง GET http://localhost:3000/coffees ด้วย Insomnia ได้ 200 OK
