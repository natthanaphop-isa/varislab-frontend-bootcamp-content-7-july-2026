รู้จัก Vitest

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายได้ว่า NestJS 12 integrate กับ Vitest ให้ตั้งแต่ scaffold โปรเจกต์ โดยไม่ต้องตั้งค่าเพิ่ม
  • รัน unit tests แบบครั้งเดียวและแบบ watch, เก็บ coverage และรัน e2e tests ด้วย npm scripts ที่มีให้
  • ชี้ได้ว่าไฟล์ทดสอบและ config ของ Vitest (vitest.config.ts, vitest.config.e2e.ts) อยู่ตรงไหนและต่างกันอย่างไร

ทำไมถึงเป็น Vitest

NestJS ไม่ได้บังคับ testing framework — จะใช้ตัวไหนก็ได้ แต่การตั้งค่าทุกอย่างเองตั้งแต่ต้น (test runner, assertion, mocking, TypeScript transform) เป็นงานน่าเบื่อ ตั้งแต่ NestJS 12 โปรเจกต์ที่สร้างด้วย nest new จึงมาพร้อม Vitest แบบ out-of-the-box: test runner ที่สร้างบน Vite จึงรันไฟล์ TypeScript และ ES module ได้ตรง ๆ โดยไม่ต้อง transform แยก และเร็วเพราะรันแต่ละไฟล์ทดสอบขนานกันใน worker คนละตัว

Vitest ให้ครบในแพ็กเกจเดียวเช่นกัน: เป็น test runner, มี assertion API (expect), มีระบบ mock ในตัว (vi.fn(), vi.spyOn(), vi.mock()) และรายงาน coverage ผ่าน @vitest/coverage-v8 ที่ Nest ติดตั้งไว้ให้แล้ว API ของมันจงใจออกแบบให้เข้ากันได้กับ Jest — ถ้าเคยเขียน Jest มาก่อน สิ่งที่ต้องจำแทบมีแค่ jest.fn() กลายเป็น vi.fn()

Nest เปิด globals: true ไว้ใน config และประกาศ "types": ["vitest/globals", "node"] ใน tsconfig.json — describe, it, expect, beforeEach, vi ฯลฯ จึงใช้ได้ทันทีในไฟล์ทดสอบโดยไม่ต้อง import (import เฉพาะ type เช่น import type { Mock } from 'vitest' เมื่อต้องการ)

สองไฟล์ config: unit กับ e2e

Nest แยก config ของ Vitest เป็นสองไฟล์ที่ root ของโปรเจกต์ ต่างกันแค่ว่าจะมองหาไฟล์ทดสอบชื่อแบบไหน

// vitest.config.ts — unit tests
import { defineConfig } from 'vitest/config';
import tsconfigPaths from 'vite-tsconfig-paths';

export default defineConfig({
  plugins: [tsconfigPaths()],
  test: {
    globals: true,
    root: './',
    include: ['**/*.spec.ts'],
  },
});

// vitest.config.e2e.ts — e2e tests
export default defineConfig({
  plugins: [tsconfigPaths()],
  test: {
    globals: true,
    root: './',
    include: ['**/*.e2e-spec.ts'],
  },
});

คำสั่งที่มีให้ตั้งแต่ scaffold

# รัน unit tests ทั้งหมดครั้งเดียวแล้วจบ
npm run test

# รันแบบ watch: แก้ไฟล์แล้วรันซ้ำให้อัตโนมัติ
npm run test:watch

# รัน unit tests พร้อมเก็บ coverage
npm run test:cov

# รัน e2e tests
npm run test:e2e
คำสั่งสิ่งที่รันจริงทดสอบอะไร / ไฟล์ที่มอง
npm run testvitest rununit tests: class/function เดี่ยว ๆ พร้อม mock dependencies — **/*.spec.ts
npm run test:watchvitestเหมือน test แต่ค้างอยู่และรันซ้ำทุกครั้งที่ save ไฟล์ — เหมาะกับตอนพัฒนา
npm run test:covvitest run --coverageเหมือน test แต่สรุปสัดส่วนโค้ดที่ถูกทดสอบเป็นตารางใน terminal และโฟลเดอร์ coverage/
npm run test:e2evitest run --config ./vitest.config.e2e.tsระบบทั้งเส้นทาง: boot แอปจริงแล้วยิง HTTP เข้าไป — **/*.e2e-spec.ts

ทุกคำสั่งรับชื่อไฟล์ (หรือบางส่วนของชื่อ) ต่อท้ายเพื่อรันเฉพาะไฟล์ที่สนใจ เช่น npm run test -- coffees.service หรือ npm run test:e2e -- coffees ซึ่งเราจะใช้ตลอดบทถัด ๆ ไป

ตอน scaffold Nest สร้างไฟล์ตัวอย่างให้แล้วสองแบบ: src/app.controller.spec.ts (unit) และ test/app.e2e-spec.ts (e2e) — เปิดอ่านสองไฟล์นี้ได้เลยเพื่อเห็นโครงก่อนเราลงลึกในบทถัด ๆ ไป สังเกตว่า import ในไฟล์ทดสอบก็ลงท้ายด้วย .js เหมือนโค้ดส่วนอื่นของแอป เพราะเป็น ES module เดียวกัน

รันชุดทดสอบที่มากับโปรเจกต์

ยังไม่ต้องเขียนอะไรใหม่ — รันคำสั่งใน iluvcoffee เพื่อดูว่าแต่ละแบบให้ผลอย่างไร และสังเกตว่าไฟล์ spec ตัวอย่างบางไฟล์อาจ fail ถ้าเราแก้ controller/service ไปมากแล้ว (ซึ่งเป็นเรื่องปกติ เราจะแก้กันในบทถัดไป)

npm run test npm run test:cov npm run test:watch # ลองแก้ไฟล์ spec แล้ว save ดู จากนั้นกด q เพื่อออก # e2e จะ boot แอปจริง — ถ้า fail เพราะ dependency ของ database ให้จดไว้ก่อน npm run test:e2e

ผลลัพธ์ที่คาดหวัง

Vitest รายงานผลเป็นรายไฟล์ (✓/✗ พร้อมชื่อ test) และปิดท้ายด้วยสรุป Test Files / Tests; test:cov พิมพ์ตาราง coverage รายไฟล์ลง terminal พร้อมสร้างโฟลเดอร์ coverage/ — แต่เฉพาะเมื่อทุก test ผ่านเท่านั้น ถ้ามี test ไหน fail แม้แต่ตัวเดียว Vitest จะไม่สร้างโฟลเดอร์ coverage/ ให้เลย; ส่วน test:watch ค้างอยู่รอการแก้ไฟล์ — ถ้าบาง test fail เพราะโค้ดที่เราแก้ระหว่างคอร์ส ถือว่าตรงตามคาด และเป็นโจทย์ของบทถัดไป แต่หมายความว่าตอนนี้ npm run test:cov อาจยังไม่มีรายงานให้ดูจนกว่าจะแก้ spec ที่ fail ให้ผ่านก่อน

ตรวจว่าใช้งานได้จริง

  • npm run test รันจบและพิมพ์สรุป Test Files และ Tests พร้อมจำนวน passed/failed
  • ถ้า npm run test ผ่านหมดจริง ๆ: เปิด coverage/index.html ในเบราว์เซอร์แล้วเห็นรายงาน coverage รายไฟล์ (ถ้ามี spec ตัวอย่างที่ fail อยู่ตามที่คาดไว้ด้านบน โฟลเดอร์ coverage/ จะยังไม่ถูกสร้าง — เป็นเรื่องปกติ ไม่ใช่ปัญหา)
  • เปิด package.json ดูว่า scripts test, test:watch, test:cov, test:e2e ชี้ไปที่ vitest จริง
  • เปิด vitest.config.e2e.ts และสังเกต include ว่าจับเฉพาะ **/*.e2e-spec.ts ขณะที่ vitest.config.ts จับ **/*.spec.ts
