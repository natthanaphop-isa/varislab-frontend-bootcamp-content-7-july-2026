สร้าง Prisma Model

เมื่อจบบทนี้ คุณจะสามารถ

  • นิยาม model ใน schema.prisma ด้วย field, ชนิดข้อมูล และ attribute อย่าง @id, @default() และ @@map()
  • ใช้ prisma db push สร้างตารางในฐานข้อมูลจาก schema และ prisma generate สร้าง type ให้ตรงกัน
  • ยืนยันว่าตาราง coffee ใน PostgreSQL มีคอลัมน์ตรงกับ model จริง

Model คือหนึ่งบล็อกที่แทนหนึ่งตาราง

Model คือบล็อก model ในไฟล์ schema.prisma — Prisma จะ map หนึ่ง model เป็นหนึ่งตาราง SQL และ map แต่ละ field เป็นคอลัมน์ ต่างจากที่เราเคยเขียน class Coffee เปล่า ๆ ไว้ที่ entities/coffee.entity.ts ในบทที่ 12 ตอนนี้ความจริงเรื่องโครงสร้างข้อมูลจะอยู่ในไฟล์ schema ที่เดียว แล้ว TypeScript type ถูก generate ออกมาให้แทน เขียนต่อท้ายสองบล็อกของบทที่แล้วใน prisma/schema.prisma

// prisma/schema.prisma
model Coffee {
  id      Int      @id @default(autoincrement())
  name    String
  brand   String
  flavors String[]

  @@map("coffee")
}
  • Int @id @default(autoincrement()) ประกาศ primary key ชนิด auto-increment ให้ฐานข้อมูลรันเลขให้เอง
  • String เฉย ๆ กลายเป็นคอลัมน์ชนิด text ใน PostgreSQL และทุก field เป็น NOT NULL โดยปริยาย — ถ้าอยากให้เว้นว่างได้ต้องเติม ? ต่อท้ายชนิด เช่น String?
  • String[] คือ scalar list ที่ PostgreSQL รองรับเป็นคอลัมน์ชนิด array (text[]) — เหมาะกับ flavors ที่ตอนนี้ยังเป็น array ของ string ก่อนจะแยกเป็น model ของตัวเองในบทที่ 25
  • @@map("coffee") บอกชื่อตารางจริงในฐานข้อมูล ถ้าไม่ใส่ Prisma จะใช้ชื่อ model ตรง ๆ คือ "Coffee" ตัวใหญ่ ซึ่งเวลาเขียน SQL เองต้องใส่เครื่องหมายคำพูดครอบทุกครั้ง — เราเลือก map เป็นตัวเล็กเพื่อให้ SQL ในบทถัด ๆ ไปเรียบง่าย

db push: สร้างตารางจาก schema ในคำสั่งเดียว

Schema เป็นแค่ไฟล์ข้อความ ฐานข้อมูลยังไม่รู้เรื่องอะไรทั้งนั้น คำสั่ง prisma db push จะเทียบ schema กับสภาพจริงในฐานข้อมูลแล้วสร้าง/แก้ตารางให้ตรงกันโดยไม่สร้างไฟล์ migration ใด ๆ — เหมาะกับการเรียนรู้และ prototype ที่เราต้องการเห็นผลเร็ว แต่ ไม่ใช่วิธีสำหรับ production เพราะมันไม่บันทึกประวัติการเปลี่ยนแปลงและอาจลบคอลัมน์พร้อมข้อมูลได้ (บทที่ 31 จะเปลี่ยนไปใช้ prisma migrate)

npx prisma db push
npx prisma generate

ตั้งแต่ Prisma 7 db push ไม่รัน generate ให้อัตโนมัติแล้ว จึงต้องสั่งเองทุกครั้ง เพื่อให้ Prisma Client ใน src/generated/prisma รู้จัก model ใหม่และมี type Coffee ให้ import เมื่อรันครบสองคำสั่ง ตารางจะโผล่ในฐานข้อมูลทันที

+-------------+--------------+----------------------------+
|                          coffee                         |
+-------------+--------------+----------------------------+
| id          | integer      | PRIMARY KEY AUTO_INCREMENT |
| name        | text         | NOT NULL                   |
| brand       | text         | NOT NULL                   |
| flavors     | text[]       |                            |
+-------------+--------------+----------------------------+

อย่าเพิ่งลบ src/coffees/entities/coffee.entity.ts — coffees.service.ts ปัจจุบัน (จากบทที่ 15) ยัง import { Coffee } from './entities/coffee.entity.js' อยู่ ถ้าลบไฟล์นี้ตอนนี้จะได้ error TS2307: Cannot find module './entities/coffee.entity.js' ทันทีที่ build เก็บไฟล์นี้ไว้ก่อน แล้วบทที่ 24 จะลบให้พร้อมกับตอนที่เปลี่ยน service ไปใช้ type Coffee จาก Prisma Client โดยตรง

จำเป็นจังหวะให้ขึ้นใจ: แก้ schema.prisma → db push → generate ทุกครั้ง ถ้าลืมขั้นสุดท้าย type ในเอดิเตอร์กับตารางจริงจะไม่ตรงกันแบบเงียบ ๆ ทางลัดที่ช่วยได้คือเพิ่ม script ใน package.json เช่น "db:push": "prisma db push && prisma generate" แล้วเรียก npm run db:push คำสั่งเดียวจบ

นอกจาก pgAdmin ในบทที่ 21 Prisma มี GUI ของตัวเองด้วย: npx prisma studio เปิดหน้าเว็บที่อ่าน schema ของเราตรง ๆ แล้วให้ browse และแก้ข้อมูลทีละแถวได้ ใช้ตัวไหนก็ได้ตามถนัด

สร้างตาราง coffee ตัวแรกของโปรเจกต์

เพิ่ม model Coffee ลง prisma/schema.prisma ตามโค้ดด้านบน (ยังไม่ต้องลบ src/coffees/entities/coffee.entity.ts — ดูคำเตือนด้านบน) แล้ว push schema ขึ้นฐานข้อมูลโดยเปิด Docker ไว้

docker-compose up -d npx prisma db push npx prisma generate # แล้วเปิด pgAdmin (บทที่ 21) ดูตาราง: # Databases > postgres > Schemas > public > Tables > coffee

ผลลัพธ์ที่คาดหวัง

db push จบด้วยข้อความ Your database is now in sync with your Prisma schema และเมื่อ refresh ใน pgAdmin จะเห็นตาราง coffee โผล่ขึ้นมาพร้อมคอลัมน์ id, name, brand, flavors ตรงตาม model ทุกประการ — โดยที่เราไม่ได้เขียน SQL CREATE TABLE เองแม้แต่บรรทัดเดียว ส่วน generate ทำให้ import { Coffee } from '../generated/prisma/client.js' ใช้ได้พร้อม autocomplete ครบทั้ง 4 field

ตรวจว่าใช้งานได้จริง

  • prisma/schema.prisma มีบล็อก model Coffee ครบ 4 field และ @@map("coffee")
  • ผลของ npx prisma db push ขึ้น Your database is now in sync โดยไม่มี error
  • ใน pgAdmin หรือ GUI ที่ใช้ เห็นตาราง coffee พร้อม 4 คอลัมน์ และ id เป็น primary key
  • ลองเพิ่ม field ใหม่ชั่วคราวใน model แล้ว db push อีกครั้ง — ตารางควรได้คอลัมน์ใหม่ทันที (ลบออกแล้ว push กลับด้วย)
