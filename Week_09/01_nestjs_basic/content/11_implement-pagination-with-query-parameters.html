ทำ Pagination ด้วย Query Parameters

บทนี้เราจะทำอะไรบ้าง

  • อ่าน query parameters จาก URL ด้วย @Query() decorator ได้
  • อธิบายได้ว่าทำไม endpoint ที่คืนรายการควรรองรับ limit และ offset ตั้งแต่แรก
  • แยกความต่างระหว่าง route parameter, request body และ query parameter ได้ชัดเจน

ทำไมรายการต้องมี Pagination

endpoint อย่าง GET /coffees ที่คืน ทุก record ในระบบอาจดูไม่มีปัญหาตอนพัฒนา แต่เมื่อข้อมูลโตขึ้นเป็นหลักหมื่นหลักแสน รายการเดียวจะกินทั้ง memory, เวลา query และ bandwidth วิธีมาตรฐานคือให้ client ระบุ query parameters เช่น limit (จำนวนที่ต้องการ) และ offset (ข้ามไปกี่รายการ) เพื่อขอข้อมูลเป็นหน้า ๆ เช่น GET /coffees?limit=10&offset=20

ช่องทางDecoratorเหมาะกับ
Route parameter เช่น /coffees/1@Param()ระบุ resource ชิ้นเดียวแบบเจาะจง
Query parameter เช่น ?limit=10@Query()ตัวเลือกเสริม: pagination, การกรอง, การเรียงลำดับ
Request body (JSON payload)@Body()ข้อมูลสำหรับสร้างหรือแก้ไข resource

รับ Query Parameters ด้วย @Query()

เพิ่ม @Query() เข้าไปใน parameter ของ findAll() เพื่อรับ object ที่รวม query ทั้งหมดของ request นั้น จากนั้น destructure เอาเฉพาะ key ที่สนใจ

import {
  Body,
  Controller,
  Delete,
  Get,
  Param,
  Patch,
  Post,
  Query,
} from '@nestjs/common';

@Controller('coffees')
export class CoffeesController {
  @Get()
  findAll(@Query() paginationQuery: any) {
    const { limit, offset } = paginationQuery;
    return `This action returns all coffees. Limit ${limit}, offset: ${offset}`;
  }

  @Get(':id')
  findOne(@Param('id') id: string) {
    return `This action returns #${id} coffee`;
  }

  @Post()
  create(@Body() body: any) {
    return body;
  }

  @Patch(':id')
  update(@Param('id') id: string, @Body() body: any) {
    return `This action updates #${id} coffee`;
  }

  @Delete(':id')
  remove(@Param('id') id: string) {
    return `This action removes #${id} coffee`;
  }
}

ถ้าต้องการ query แค่ค่าเดียว เราระบุชื่อได้เหมือน @Param() เช่น @Query('limit') limit: number แต่เมื่อมีหลายค่า การรับทั้งหมดเป็น object จะอ่านง่ายกว่า ในบทที่ 28 เราจะเปลี่ยน object นี้เป็น DTO และเพิ่ม validation ให้เรียบร้อย

ตอนนี้ค่าใน query ยังเป็น string เสมอ (มาจาก URL) เช่น limit ที่ได้คือ "10" ไม่ใช่ 10 — บทที่ 18 จะเปิด auto-transform ของ ValidationPipe เพื่อแปลง type ให้อัตโนมัติ

เพิ่ม limit และ offset ให้ GET /coffees

แก้ findAll() ใน coffees.controller.ts ให้รับ @Query() ตามโค้ดด้านบน แล้วยิงทดสอบด้วย Insomnia หรือ curl โดยใส่ query ต่างกันหลายแบบ

curl "http://localhost:3000/coffees?limit=10&offset=20" curl "http://localhost:3000/coffees?limit=5" curl "http://localhost:3000/coffees"

ควรได้ผลลัพธ์แบบนี้

คำขอแรกตอบ This action returns all coffees. Limit 10, offset: 20; คำขอที่ไม่ส่ง query บางตัวจะเห็นค่านั้นเป็น undefined ซึ่งเป็นพฤติกรรมปกติ เพราะ query เป็นตัวเลือกเสริมที่ client จะส่งหรือไม่ก็ได้

ลองเช็กให้แน่ใจ

  • ยิง GET /coffees?limit=10&offset=20 แล้วเห็นค่า limit และ offset สะท้อนกลับมาในข้อความ
  • ยิงโดยไม่ใส่ query เลย แล้ว endpoint ยังทำงานได้ ไม่ throw error
  • ลอง console.log(typeof limit) เพื่อยืนยันว่าค่าที่ได้ตอนนี้เป็น string
  • route อื่น ๆ (GET /coffees/:id, POST /coffees) ยังทำงานเหมือนเดิม
