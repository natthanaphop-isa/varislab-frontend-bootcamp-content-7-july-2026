ส่ง Error Message ที่เป็นมิตรกับผู้ใช้

เมื่อจบบทนี้ คุณจะสามารถ

  • โยน exception มาตรฐานของ Nest เช่น NotFoundException พร้อมข้อความที่สื่อความหมาย
  • อธิบายได้ว่า built-in exceptions layer ของ Nest แปลง exception เป็น HTTP response อย่างไร
  • เลือก exception class ให้ตรงกับสถานการณ์ของ error แต่ละแบบ

เมื่อหาไม่เจอ อย่าตอบความว่างเปล่า

ตอนนี้ถ้า client ขอ GET /coffees/999 ที่ไม่มีอยู่ findOne() คืน undefined และ Nest ตอบ 200 พร้อม body ว่าง — client ไม่มีทางรู้ว่าผิดตรงไหน API ที่ดีต้องบอกอย่างชัดเจนว่า ไม่พบข้อมูล ด้วย status 404 พร้อมข้อความที่อ่านรู้เรื่อง Nest เตรียม exception class มาตรฐานไว้ให้ครบใน @nestjs/common

/* coffees.service.ts */
import { Injectable, NotFoundException } from '@nestjs/common';
import { Coffee } from './entities/coffee.entity.js';

@Injectable()
export class CoffeesService {
  private coffees: Coffee[] = [
    {
      id: 1,
      name: 'Shipwreck Roast',
      brand: 'Buddy Brew',
      flavors: ['chocolate', 'vanilla'],
    },
  ];

  findAll() {
    return this.coffees;
  }

  findOne(id: string) {
    const coffee = this.coffees.find(item => item.id === +id);
    if (!coffee) {
      throw new NotFoundException(`Coffee #${id} not found`);
    }
    return coffee;
  }

  create(createCoffeeDto: any) {
    this.coffees.push(createCoffeeDto);
  }

  update(id: string, updateCoffeeDto: any) {
    const existingCoffee = this.findOne(id);
    if (existingCoffee) {
      // update the existing entity
    }
  }

  remove(id: string) {
    const coffeeIndex = this.coffees.findIndex(item => item.id === +id);
    if (coffeeIndex >= 0) {
      this.coffees.splice(coffeeIndex, 1);
    }
  }
}

สังเกตว่าเราโยน exception จาก service ไม่ใช่ controller — logic การตัดสินว่า "มีหรือไม่มี" อยู่ที่ชั้น business ส่วน Nest จะจับ exception นี้ที่ exceptions layer แล้วแปลงเป็น response JSON ให้อัตโนมัติ:

{
  "statusCode": 404,
  "message": "Coffee #999 not found",
  "error": "Not Found"
}

เลือก Exception ให้ตรงสถานการณ์

Exception classStatusใช้เมื่อ
BadRequestException400ข้อมูลขาเข้าผิดรูปแบบหรือไม่ครบ
UnauthorizedException401ยังไม่ได้ยืนยันตัวตน
ForbiddenException403ยืนยันตัวตนแล้วแต่ไม่มีสิทธิ์
NotFoundException404ไม่พบ resource ที่ขอ
InternalServerErrorException500ข้อผิดพลาดภายในที่ไม่คาดคิด

ทุกตัวสืบทอดจาก HttpException ซึ่งใช้ตรง ๆ ก็ได้เมื่อต้องการกำหนด status เอง เช่น throw new HttpException('Message', HttpStatus.NOT_FOUND) และถ้า exception ที่หลุดออกมาไม่ใช่ ตระกูล HttpException Nest จะตอบ 500 Internal Server Error ให้โดยไม่รั่วรายละเอียดภายใน

ข้อความใน exception ควรบอกว่า "อะไรไม่พบ" แบบเจาะจง เช่น Coffee #999 not found แต่อย่าใส่ข้อมูลภายในระบบ เช่น SQL query หรือ stack trace ลงในข้อความที่ส่งถึง client

ทำให้ GET /coffees/:id ตอบ 404 อย่างสุภาพ

แก้ findOne() ใน coffees.service.ts ให้โยน NotFoundException เมื่อหาไม่เจอ แล้วยิงทดสอบทั้ง id ที่มีและไม่มี

curl -i http://localhost:3000/coffees/1 curl -i http://localhost:3000/coffees/999

ผลลัพธ์ที่คาดหวัง

GET /coffees/1 ตอบ 200 พร้อมข้อมูลกาแฟ ส่วน GET /coffees/999 ตอบ 404 พร้อม JSON ที่มี statusCode, message: "Coffee #999 not found" และ error: "Not Found"

ตรวจว่าใช้งานได้จริง

  • ยิง id ที่ไม่มีแล้วได้ status 404 จริง (ดูจาก curl -i หรือแถบ status ใน Insomnia)
  • body ของ 404 เป็น JSON ที่มีข้อความระบุหมายเลข id ที่หาไม่เจอ
  • id ที่มีอยู่ยังตอบ 200 พร้อมข้อมูลครบเหมือนเดิม
  • PATCH /coffees/999 ก็ได้ 404 ด้วย เพราะ update() เรียกใช้ findOne() ตัวเดียวกัน
