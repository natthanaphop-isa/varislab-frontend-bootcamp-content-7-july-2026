ตั้งค่า Swagger และเปิดใช้ CLI Plugin

บทนี้เราจะทำอะไรบ้าง

  • อธิบายบทบาทของ OpenAPI และ Swagger UI ต่อการสื่อสาร API
  • ติดตั้งและตั้งค่า @nestjs/swagger ใน main.ts
  • เปิดใช้ Swagger CLI plugin ใน nest-cli.json
  • ตรวจว่า request body schema ถูกสร้างจาก DTO โดยอัตโนมัติ

OpenAPI: ภาษากลางสำหรับบรรยาย REST API

บทชุดนี้จะสร้างเอกสาร OpenAPI จากแอป NestJS โดยใช้เครื่องมือของ Nest ช่วยดึงข้อมูลจากโค้ด ลดงานที่ต้องเขียนซ้ำด้วยมือ OpenAPI specification คือรูปแบบมาตรฐานสำหรับอธิบาย REST API และไม่ผูกกับภาษาโปรแกรมใด ภายในเอกสารเดียวระบุข้อมูลสำคัญได้ครบ เช่น

  • operations (endpoints) ที่มีให้เรียกทั้งหมด
  • parameters ของแต่ละ operation — ทั้ง input และ output
  • วิธี authentication
  • ข้อมูลติดต่อ, license, เงื่อนไขการใช้งาน และ metadata อื่น ๆ

ผลพลอยได้ที่สำคัญคือ Swagger UI — หน้าเว็บ interactive ที่ทีม frontend หรือผู้ใช้ API เปิดดู endpoint ทั้งหมดและลองยิงได้จากเบราว์เซอร์เลย

ติดตั้งและตั้งค่าใน main.ts

แอปของเราใช้ Express อยู่เบื้องหลัง จึงติดตั้ง swagger-ui-express คู่กับ @nestjs/swagger (ถ้าใช้ Fastify ให้ติดตั้ง fastify-swagger แทน)

npm install --save @nestjs/swagger swagger-ui-express

จากนั้นประกอบ document ใน main.ts ก่อน app.listen(): DocumentBuilder ใช้กำหนด metadata ของเอกสาร, SwaggerModule.createDocument สแกนแอปทั้งหมดเพื่อสร้างสเปก และ SwaggerModule.setup('api', ...) กำหนด path ที่จะเสิร์ฟ UI

const options = new DocumentBuilder()
  .setTitle('Iluvcoffee')
  .setDescription('Coffee application')
  .setVersion('1.0')
  .build();

const document = SwaggerModule.createDocument(app, options);

SwaggerModule.setup('api', app, document);

เมื่อแอปรันอยู่ (npm run start:dev) เปิด http://localhost:3000/api จะพบ Swagger UI พร้อม endpoint ของ coffees และ coffee-rating เรียงให้เห็นทันที

ตอนนี้เอกสารยังโล่ง — เห็นแค่ path กับ HTTP method แต่ไม่มีรายละเอียด body หรือ response เพราะ TypeScript type ถูกลบทิ้งตอน compile ทำให้ Swagger มองไม่เห็น DTO ของเรา ช่วงถัดไปจะแก้ด้วย CLI plugin ที่สอนให้ compiler ฝัง metadata เหล่านี้ให้อัตโนมัติ

ปัญหา: TypeScript type หายไปตอน runtime

หลังจากเปิด Swagger UI เราจะเห็นว่าเอกสารยังโล่ง — POST /coffees ไม่บอกเลยว่า body ต้องหน้าตาอย่างไร สาเหตุคือ type ของ TypeScript (รวมถึง DTO ทุกตัวของเรา) ถูกลบทิ้งระหว่าง compile เหลือเพียง JavaScript ล้วน ๆ ตอน runtime จึงไม่มีข้อมูลให้ SwaggerModule สแกน ทางแก้แบบ manual คือไล่ติด @ApiProperty() ทุกฟิลด์ของทุก DTO — ทำได้แต่ซ้ำซากและลืมง่าย

ทางแก้ที่คอร์สนี้เลือกคือ CLI plugin: ปลั๊กอินของ compiler ที่วิเคราะห์โค้ดตอน build แล้วฝัง metadata ที่ Swagger ต้องใช้ให้เองอัตโนมัติ — DTO, entity, ชนิดข้อมูล, ความ optional ของฟิลด์ ทั้งหมดถูกอ่านจาก type ที่เราเขียนอยู่แล้ว

เปิดใช้ใน nest-cli.json

เพิ่ม plugin เข้าไปใน compilerOptions ของไฟล์ nest-cli.json ที่ root ของโปรเจกต์

"compilerOptions": {
  "deleteOutDir": true,
  "plugins": ["@nestjs/swagger/plugin"]
}

plugin ทำงานตามข้อตกลงชื่อไฟล์ (convention): โดย default มันประมวลผลไฟล์ที่ลงท้าย .dto.ts และ .entity.ts — ตรงกับที่เราตั้งชื่อมาตลอดคอร์สพอดี จึงไม่ต้องตั้งค่าอะไรเพิ่ม สิ่งที่ plugin ทำให้ ได้แก่ ติด @ApiProperty ให้ทุก property ของ DTO, อนุมานชนิดข้อมูลจาก type annotation และตั้ง required/optional ตามเครื่องหมาย ?

plugin ทำงานตอน compile — แก้ nest-cli.json แล้วต้อง restart npm run start:dev ใหม่จึงเห็นผล ถ้าเอกสารยังโล่งอยู่ ให้เช็กก่อนเลยว่า dev server ถูก start หลังแก้ไฟล์แล้วจริง ๆ

เปิด Swagger UI และให้ DTO แสดงในเอกสารอัตโนมัติ

ขั้นที่ 1: เปิด Swagger UI ให้ iluvcoffee

ติดตั้ง dependency ทั้งสองตัว เพิ่มโค้ดตั้งค่า document ใน main.ts แล้วเปิดเบราว์เซอร์ดูผล

npm install --save @nestjs/swagger swagger-ui-express # main.ts — ก่อน app.listen() const options = new DocumentBuilder() .setTitle('Iluvcoffee') .setDescription('Coffee application') .setVersion('1.0') .build(); const document = SwaggerModule.createDocument(app, options); SwaggerModule.setup('api', app, document); # เปิดดู open http://localhost:3000/api

ขั้นที่ 2: ให้ DTO ของ iluvcoffee โผล่ในเอกสารเอง

เพิ่ม plugin ใน nest-cli.json restart dev server แล้วเปิด Swagger UI ดู POST /coffees อีกครั้ง

# nest-cli.json { "collection": "@nestjs/schematics", "sourceRoot": "src", "compilerOptions": { "deleteOutDir": true, "plugins": ["@nestjs/swagger/plugin"] } } # restart แล้วเปิดดู npm run start:dev open http://localhost:3000/api

ควรได้ผลลัพธ์แบบนี้

Swagger UI ที่ /api แสดง endpoint ทั้งหมดและทดลองยิง request ได้ ส่วน POST /coffees แสดง schema ของ CreateCoffeeDto ครบทั้ง name, brand และ flavors หลังเปิด CLI plugin โดยไม่ต้องติด decorator ให้ทุก property เอง

ลองเช็กให้แน่ใจ

  • เปิด http://localhost:3000/api แล้วเห็น Swagger UI โหลดสำเร็จ
  • เห็น endpoint ของ coffees ครบทุก HTTP method ที่เราสร้างไว้
  • ลอง Try it out กับ GET /coffees — ถ้า route ไม่ติด @Public() อย่าลืมใส่ Authorization header
  • เปิด http://localhost:3000/api-json เพื่อดูสเปก OpenAPI ดิบเป็น JSON
  • กาง POST /coffees แล้วเห็น example body ที่ generate จาก CreateCoffeeDto
  • ดู schema ของ PATCH /coffees/{id} คร่าว ๆ — ตอนนี้ UpdateCoffeeDto ยังใช้ PartialType จาก @nestjs/mapped-types (บทที่ 18) อยู่ ฟิลด์อาจยังไม่ถูกทำเครื่องหมาย optional ครบในเอกสารจนกว่าจะสลับไปใช้ PartialType จาก @nestjs/swagger ในบทถัดไป — ยังไม่ต้องแก้อะไรตอนนี้
  • ดูส่วน Schemas ว่ามี DTO ของ pagination ด้วย (PaginationQueryDto)
  • ลองลบ plugin ออกชั่วคราวแล้ว restart เพื่อเห็นความต่าง จากนั้นใส่กลับ
