ใช้ Mongoose Model เข้าถึง MongoDB

บทนี้เราจะทำอะไรบ้าง

  • Inject Model เข้า service ด้วย @InjectModel(Coffee.name) และอธิบายได้ว่า token นี้มาจากไหน
  • แทนที่ข้อมูล in-memory ของ CoffeesService ด้วยการเรียก MongoDB ผ่าน Model ครบทั้ง CRUD
  • โยน NotFoundException เมื่อหา document ไม่เจอ เพื่อให้ API ตอบ 404 อย่างถูกต้อง

ใช้ Model คุยกับ MongoDB

Mongoose Model หนึ่งตัวแทนหนึ่ง collection ส่วนข้อมูลแต่ละรายการที่ได้จาก Model เรียกว่า Document ซึ่งใกล้เคียงกับ row ในฐานข้อมูล SQL เราใช้ methods อย่าง find(), findOne() และ findOneAndUpdate() ผ่าน Model และเรียก save() เมื่อต้องการบันทึก Document ใหม่

/* การ inject Mongo Coffee Model */
constructor(
  @InjectModel(Coffee.name)
  private coffeeModel: Model<Coffee>,
) {}

@InjectModel(Coffee.name) ขอ Model ที่ลงทะเบียนไว้กับ MongooseModule.forFeature() ในบทที่แล้ว — เทียบกับฝั่ง SQL แล้วบทบาทเดียวกับการ inject PrismaService เข้า CoffeesService ต่างกันตรงที่ Mongoose ให้ Model แยกตัวต่อ collection ส่วน Prisma ให้ client ตัวเดียวที่มีทุก model เป็น property

CoffeesService ฉบับ MongoDB เต็มตัว

จากนั้นแทนที่ array in-memory ของ Chapter 2 ด้วยการเรียก Model ทั้งหมด สังเกตว่า query ของ Mongoose ปิดท้ายด้วย .exec() เพื่อให้ได้ Promise กลับมาอย่างชัดเจน

/* CoffeesService - FINAL CODE */
import { Injectable, NotFoundException } from '@nestjs/common';
import { InjectModel } from '@nestjs/mongoose';
import { Model } from 'mongoose';
import { CreateCoffeeDto } from './dto/create-coffee.dto.js';
import { UpdateCoffeeDto } from './dto/update-coffee.dto.js';
import { Coffee } from './entities/coffee.entity.js';

@Injectable()
export class CoffeesService {
  constructor(
    @InjectModel(Coffee.name) private readonly coffeeModel: Model<Coffee>,
  ) {}

  findAll() {
    return this.coffeeModel.find().exec();
  }

  async findOne(id: string) {
    const coffee = await this.coffeeModel.findOne({ _id: id }).exec();
    if (!coffee) {
      throw new NotFoundException(`Coffee #${id} not found`);
    }
    return coffee;
  }

  create(createCoffeeDto: CreateCoffeeDto) {
    const coffee = new this.coffeeModel(createCoffeeDto);
    return coffee.save();
  }

  async update(id: string, updateCoffeeDto: UpdateCoffeeDto) {
    const existingCoffee = await this.coffeeModel
      .findOneAndUpdate({ _id: id }, { $set: updateCoffeeDto }, { new: true })
      .exec();

    if (!existingCoffee) {
      throw new NotFoundException(`Coffee #${id} not found`);
    }
    return existingCoffee;
  }

  async remove(id: string) {
    const coffee = await this.findOne(id);
    return coffee.deleteOne(); // Mongoose 7+ ตัด Document#remove() ออกแล้ว
  }
}

จุดที่ควรสังเกต: create() สร้าง document ใหม่ด้วย new this.coffeeModel(dto) แล้ว save(); update() ใช้ operator $set เพื่ออัปเดตเฉพาะฟิลด์ที่ส่งมา และ option { new: true } ขอ document เวอร์ชันหลังอัปเดตกลับมา (ค่า default คือเวอร์ชันก่อนแก้); ส่วน remove() ของ service ใช้ findOne() ของเราเองก่อน จึงได้ 404 ฟรี ๆ เมื่อ id ไม่มีจริง แล้วค่อยเรียก deleteOne() บน document ที่ได้ (เมธอด remove() เดิมของ Mongoose Document ถูกถอดออกตั้งแต่ Mongoose 7 — คอร์สต้นฉบับใช้ชื่อนั้น ถ้าเห็นในวิดีโอเก่าให้แทนด้วย deleteOne())

id ที่รับเข้ามาเป็น string เพราะ _id ของ MongoDB เป็น ObjectId ไม่ใช่ตัวเลข ถ้า controller ของคุณเคยแปลง id เป็น number (เช่นด้วย ParseIntPipe หรือ +id) ต้องถอดออก ไม่อย่างนั้น query จะหาไม่เจอทุกครั้ง

ย้าย CRUD ของ coffees ลง MongoDB

แทนที่เนื้อใน src/coffees/coffees.service.ts ด้วยโค้ดด้านบน ปรับ controller ให้ส่ง id เป็น string แล้วทดสอบครบทุก endpoint ด้วย Insomnia

POST http://localhost:3000/coffees { "name": "Shipwreck Roast", "brand": "Buddy Brew", "flavors": ["chocolate", "vanilla"] } GET http://localhost:3000/coffees GET http://localhost:3000/coffees/<_id ที่ได้จาก POST> PATCH http://localhost:3000/coffees/<_id> { "name": "Better Roast" } DELETE http://localhost:3000/coffees/<_id>

ควรได้ผลลัพธ์แบบนี้

POST ตอบ document ที่มี _id และ __v ที่ MongoDB สร้างให้, GET เห็นข้อมูลเดิมแม้รีสตาร์ตแอป (เพราะเก็บในฐานข้อมูลแล้ว ไม่ใช่ memory), PATCH ตอบ document เวอร์ชันหลังแก้ และการยิงด้วย _id มั่ว ๆ ที่ format ถูกต้องได้ 404 พร้อมข้อความ Coffee #... not found

ลองเช็กให้แน่ใจ

  • สร้างกาแฟผ่าน POST แล้วรีสตาร์ตแอป — GET /coffees ยังเห็นข้อมูลอยู่
  • เปิด mongosh (docker exec -it <container> mongosh nest-course) แล้ว db.coffees.find() เห็น document ตรงกับที่ API ตอบ
  • PATCH ด้วยฟิลด์เดียวแล้วฟิลด์อื่นไม่หาย (ผลของ $set)
  • GET/PATCH/DELETE ด้วย id ที่ไม่มีจริงได้ status 404 ไม่ใช่ 500
