Validate ข้อมูลขาเข้าด้วย DTO

บทนี้เราจะทำอะไรบ้าง

  • เปิดใช้ ValidationPipe แบบ global ใน main.ts
  • กำหนดกฎ validation บน DTO ด้วย decorator ของ class-validator
  • ใช้ PartialType จาก @nestjs/mapped-types สร้าง UpdateDto โดยไม่เขียนซ้ำ

ทำให้สัญญาใน DTO มีผลจริงตอน Runtime

DTO จากบทที่แล้วช่วยเฉพาะตอนคอมไพล์ — client ยังส่ง payload มั่ว ๆ มาได้โดย Nest ไม่ปริปาก ValidationPipe คือกลไกมาตรฐานที่ตรวจ payload ทุกก้อนเทียบกับกฎที่ประกาศไว้บน DTO ให้อัตโนมัติ เริ่มจากติดตั้ง dependencies สองตัวและเปิด pipe แบบ global:

npm i class-validator class-transformer
/* main.ts */
app.useGlobalPipes(new ValidationPipe());

จากนั้นแปะ decorator บอกกฎลงบน property ของ CreateCoffeeDto:

import { IsString } from 'class-validator';

export class CreateCoffeeDto {
  @IsString()
  readonly name: string;

  @IsString()
  readonly brand: string;

  @IsString({ each: true })
  readonly flavors: string[];
}

{ each: true } บอกว่า flavors ต้องเป็น array ที่สมาชิกทุกตัวเป็น string ถ้า client ส่ง field ขาดหรือ type ผิด Nest จะตอบ 400 Bad Request พร้อมรายการข้อผิดพลาดโดยที่ handler ของเราไม่ถูกเรียกเลย:

{
  "statusCode": 400,
  "message": ["name must be a string"],
  "error": "Bad Request"
}

PartialType: UpdateDto ที่ไม่ต้องเขียนซ้ำ

UpdateCoffeeDto ของเราคือ CreateCoffeeDto เวอร์ชันที่ทุก field เป็น optional — การคัดลอกมาแก้มือทั้ง property และ validation rule คือโค้ดซ้ำที่จะหลุด sync กันในที่สุด @nestjs/mapped-types มี utility แก้ปัญหานี้ตรง ๆ:

npm i @nestjs/mapped-types
/* dto/update-coffee.dto.ts */
import { PartialType } from '@nestjs/mapped-types';
import { CreateCoffeeDto } from './create-coffee.dto.js';

export class UpdateCoffeeDto extends PartialType(CreateCoffeeDto) {}

PartialType คืน class ใหม่ที่มีทุก property ของต้นฉบับแบบ optional และสืบทอด validation rules ทั้งหมดมาด้วย — แก้กฎที่ CreateCoffeeDto ที่เดียว UpdateDto ได้ผลตามทันที

ถ้าภายหลังคุณใช้ Swagger (บทที่ 43 เป็นต้นไป) ให้เปลี่ยนไป import PartialType จาก @nestjs/swagger แทน เพื่อให้เอกสาร API รู้จัก field ที่เป็น optional ด้วย

เปิด validation แล้วลองส่งของผิด

ติดตั้ง dependencies, เปิด ValidationPipe ใน main.ts, ใส่กฎใน CreateCoffeeDto และเขียน UpdateCoffeeDto ใหม่ด้วย PartialType แล้วทดลองยิง payload ที่ตั้งใจให้ผิด

npm i class-validator class-transformer @nestjs/mapped-types curl -X POST http://localhost:3000/coffees \ -H "Content-Type: application/json" \ -d '{"brand": "Buddy Brew"}' curl -X POST http://localhost:3000/coffees \ -H "Content-Type: application/json" \ -d '{"name": "Shipwreck Roast", "brand": "Buddy Brew", "flavors": ["caramel"]}'

ควรได้ผลลัพธ์แบบนี้

คำขอแรก (ไม่มี name และ flavors) ตอบ 400 พร้อม message array ระบุทุก field ที่ผิด ส่วนคำขอที่สองผ่าน validation และสร้างกาแฟได้ตามปกติ

ลองเช็กให้แน่ใจ

  • ส่ง name เป็น number เช่น {"name": 123} แล้วได้ 400 พร้อมข้อความ name must be a string
  • ส่ง flavors ที่มีสมาชิกไม่ใช่ string แล้วโดนปฏิเสธเพราะ { each: true }
  • PATCH /coffees/1 ด้วย {"name": "New Roast"} ผ่านได้ แม้ส่งแค่ field เดียว — ยืนยันว่า PartialType ทำให้ทุก field เป็น optional
  • PATCH /coffees/1 ด้วย {"name": 123} ยังโดน 400 — ยืนยันว่า validation rule สืบทอดมาด้วย
