สร้าง Service พื้นฐาน

เมื่อจบบทนี้ คุณจะสามารถ

  • สร้าง service ด้วย Nest CLI และอธิบายบทบาทของ @Injectable() ได้
  • ย้าย business logic ออกจาก controller ไปไว้ใน service ตามหลัก separation of concerns
  • inject service เข้า controller ผ่าน constructor ด้วย dependency injection ของ Nest

Service คือบ้านของ Business Logic

จนถึงตอนนี้ CoffeesController ของเราตอบข้อความจำลองอย่างเดียว ในแอปจริง controller ควรทำหน้าที่แค่รับ request และคืน response ส่วนงานจริง — การค้นหา จัดเก็บ ตรวจสอบ และติดต่อฐานข้อมูล — เป็นหน้าที่ของ service การแยกแบบนี้ทำให้ logic ถูกใช้ซ้ำจากหลาย controller ได้ และทดสอบแยกจากชั้น HTTP ได้ง่าย

สร้าง service ใหม่ด้วย CLI ได้ทันที

nest generate service coffees
# shorthand: nest g s coffees

คลาสที่ได้จะติด decorator @Injectable() ซึ่งประกาศว่า class นี้เป็น provider ที่ Nest IoC container สามารถสร้าง instance และฉีด (inject) ให้ผู้อื่นใช้ได้ CLI ยังเพิ่ม service นี้เข้า providers array ของ module ให้อัตโนมัติ

เก็บข้อมูลกาแฟไว้ในหน่วยความจำก่อน

ระหว่างที่ยังไม่ต่อฐานข้อมูล (บทที่ 20 เป็นต้นไป) เราเก็บข้อมูลเป็น array ในหน่วยความจำ พร้อมสร้าง entity class ง่าย ๆ อธิบายหน้าตาของกาแฟหนึ่งรายการ

/* entities/coffee.entity.ts */
export class Coffee {
  id: number;
  name: string;
  brand: string;
  flavors: string[];
}
/* coffees.service.ts */
import { Injectable } from '@nestjs/common';
import { Coffee } from './entities/coffee.entity.js';

@Injectable()
export class CoffeesService {
  private coffees: Coffee[] = [
    {
      id: 1,
      name: 'Shipwreck Roast',
      brand: 'Buddy Brew',
      flavors: ['chocolate', 'vanilla'],
    },
  ];

  findAll() {
    return this.coffees;
  }

  findOne(id: string) {
    return this.coffees.find(item => item.id === +id);
  }

  create(createCoffeeDto: any) {
    this.coffees.push(createCoffeeDto);
  }

  update(id: string, updateCoffeeDto: any) {
    const existingCoffee = this.findOne(id);
    if (existingCoffee) {
      // update the existing entity
    }
  }

  remove(id: string) {
    const coffeeIndex = this.coffees.findIndex(item => item.id === +id);
    if (coffeeIndex >= 0) {
      this.coffees.splice(coffeeIndex, 1);
    }
  }
}

Inject Service เข้า Controller

ประกาศ service ใน constructor ของ controller — Nest จะเห็น type CoffeesService แล้วส่ง instance ที่สร้างไว้เข้ามาให้เอง คีย์เวิร์ด private readonly เป็น shorthand ของ TypeScript ที่ทั้งประกาศ property และ assign ค่าในบรรทัดเดียว

/* coffees.controller.ts */
import {
  Body,
  Controller,
  Delete,
  Get,
  Param,
  Patch,
  Post,
  Query,
} from '@nestjs/common';
import { CoffeesService } from './coffees.service.js';

@Controller('coffees')
export class CoffeesController {
  constructor(private readonly coffeesService: CoffeesService) {}

  @Get()
  findAll(@Query() paginationQuery: any) {
    return this.coffeesService.findAll();
  }

  @Get(':id')
  findOne(@Param('id') id: string) {
    return this.coffeesService.findOne(id);
  }

  @Post()
  create(@Body() body: any) {
    return this.coffeesService.create(body);
  }

  @Patch(':id')
  update(@Param('id') id: string, @Body() body: any) {
    return this.coffeesService.update(id, body);
  }

  @Delete(':id')
  remove(@Param('id') id: string) {
    return this.coffeesService.remove(id);
  }
}

สังเกตว่า findOne() ใช้ +id แปลง string เป็น number ก่อนเปรียบเทียบ เพราะ route parameter มาจาก URL จึงเป็น string เสมอ — เราจะจัดการเรื่อง type อย่างเป็นระบบด้วย ValidationPipe ในบทที่ 18

ย้าย logic ทั้งหมดเข้า CoffeesService

สร้าง service ด้วย CLI, สร้าง Coffee entity, ใส่ข้อมูลตัวอย่างหนึ่งรายการ แล้วแก้ทุก handler ใน controller ให้เรียกผ่าน this.coffeesService ตามโค้ดด้านบน

nest g s coffees nest g class coffees/entities/coffee.entity --no-spec curl http://localhost:3000/coffees curl http://localhost:3000/coffees/1

ผลลัพธ์ที่คาดหวัง

GET /coffees คืน array ที่มี Shipwreck Roast หนึ่งรายการเป็น JSON จริง ไม่ใช่ข้อความจำลองอีกต่อไป และ GET /coffees/1 คืน object รายการนั้น ส่วน id ที่ไม่มีจะได้ response ว่าง (ยังไม่มี error handling — บทถัดไปจะแก้)

ตรวจว่าใช้งานได้จริง

  • GET /coffees คืน JSON array ของข้อมูลใน service ไม่ใช่ string เดิม
  • POST /coffees ด้วย body ใหม่ แล้ว GET /coffees อีกครั้งเห็นรายการเพิ่มขึ้น
  • DELETE /coffees/1 แล้วรายการหายไปจริงจาก GET /coffees
  • coffees.module หรือ app.module มี CoffeesService อยู่ใน providers array
  • ไม่มี logic เก็บข้อมูลเหลืออยู่ใน controller — controller เรียก service เท่านั้น
