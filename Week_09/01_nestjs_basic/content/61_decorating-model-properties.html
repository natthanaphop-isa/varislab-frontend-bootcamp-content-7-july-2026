ตกแต่ง Model Properties ให้เอกสารครบ

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายได้ว่าทำไม UpdateCoffeeDto ที่ใช้ PartialType จาก @nestjs/mapped-types จึงหายไปจาก Swagger UI และแก้ได้ด้วยการ import จาก @nestjs/swagger
  • ใช้ @ApiProperty override ข้อมูลที่ CLI plugin อนุมานให้ เช่น เพิ่ม description ให้ property
  • ตัดสินใจได้ว่าเมื่อใดควรพึ่ง plugin อนุมานอัตโนมัติ และเมื่อใดควร annotate เอง

ทำไม DTO บางตัวยังหายไปจากเอกสาร

ในบทที่แล้วเราเปิดใช้ Swagger CLI plugin ซึ่งอ่าน type ของ TypeScript แล้วสร้าง schema ให้ DTO อัตโนมัติ แต่มีจุดบอดอยู่หนึ่งจุด: UpdateCoffeeDto ของเราสร้างจาก PartialType(CreateCoffeeDto) ที่ import มาจาก @nestjs/mapped-types ซึ่ง Swagger ไม่รู้จัก ผลคือ endpoint PATCH /coffees/:id แสดง request body ว่างเปล่าใน Swagger UI

ทางแก้ตรงไปตรงมา: แพ็กเกจ @nestjs/swagger มี PartialType ของตัวเองที่ทำงานเหมือนกันทุกอย่าง (ทำให้ทุก property เป็น optional) แต่เพิ่มการลงทะเบียน metadata ให้ OpenAPI ด้วย เพียงเปลี่ยนบรรทัด import ก็พอ

// update-coffee.dto.ts
// เดิม: import { PartialType } from '@nestjs/mapped-types';
import { PartialType } from '@nestjs/swagger'; // 👈 เปลี่ยนเฉพาะ import

export class UpdateCoffeeDto extends PartialType(CreateCoffeeDto) {}

พฤติกรรม validation ไม่เปลี่ยน: PartialType ของ @nestjs/swagger สืบทอด validation rules จาก CreateCoffeeDto เช่นเดียวกับของ @nestjs/mapped-types แต่เพิ่มความสามารถด้านเอกสารเข้ามา

เติมรายละเอียดด้วย @ApiProperty

CLI plugin อนุมาน type และ required ให้แล้ว แต่บอกไม่ได้ว่า property นี้หมายถึงอะไร เมื่อต้องการคำอธิบาย ตัวอย่างค่า หรือ metadata อื่น ให้ใช้ @ApiProperty ประกาศทับเฉพาะจุดที่ต้องการ

// create-coffee.dto.ts
import { ApiProperty } from '@nestjs/swagger';
import { IsString } from 'class-validator';

export class CreateCoffeeDto {
  @ApiProperty({ description: 'The name of a coffee.' }) // 👈 override ข้อมูลที่ plugin อนุมาน
  @IsString()
  readonly name: string;

  @ApiProperty({ description: 'The brand of a coffee.' })
  @IsString()
  readonly brand: string;

  @ApiProperty({ example: ['chocolate', 'vanilla'] })
  @IsString({ each: true })
  readonly flavors: string[];
}

หลักคิดคือ ให้ plugin ทำงานหนัก แล้ว annotate เฉพาะส่วนที่เครื่องอนุมานไม่ได้ — ถ้าใส่ @ApiProperty ทุกบรรทัดทั้งที่ plugin อนุมานได้อยู่แล้ว จะได้ DTO ที่รกโดยไม่จำเป็น

ทำให้ PATCH /coffees/:id มีเอกสารครบ

ใน iluvcoffee เปลี่ยน import ของ PartialType ใน update-coffee.dto.ts แล้วเพิ่ม description ให้ property อย่างน้อยหนึ่งตัวใน create-coffee.dto.ts จากนั้นรีเฟรช Swagger UI

npm run start:dev # เปิด http://localhost:3000/api # ตรวจ PATCH /coffees/{id} → ควรเห็น schema ของ UpdateCoffeeDto แล้ว

ผลลัพธ์ที่คาดหวัง

Swagger UI แสดง request body ของ PATCH /coffees/:id เป็น UpdateCoffeeDto ที่มีทุก property (เป็น optional) และในส่วน Schemas ท้ายหน้า property name ของ CreateCoffeeDto มีคำอธิบาย The name of a coffee. กำกับ

ตรวจว่าใช้งานได้จริง

  • เปิด http://localhost:3000/api แล้วกางส่วน Schemas: UpdateCoffeeDto ต้องปรากฏพร้อม property ครบ ไม่ใช่ object ว่าง
  • ลอง Try it out ที่ PATCH /coffees/1 — ฟอร์มตัวอย่าง JSON ต้องมี field name, brand, flavors
  • ยิง PATCH ด้วย Insomnia พร้อม body บางส่วน (เช่นแค่ name) เพื่อยืนยันว่า validation แบบ partial ยังทำงานเหมือนเดิม
  • ค้นทั้งโปรเจกต์ว่าไม่เหลือ @nestjs/mapped-types ใน DTO ที่ต้องการให้ปรากฏในเอกสาร
