Provider Tokens ที่ไม่ใช่ Class

เมื่อจบบทนี้ คุณจะสามารถ

  • ประกาศ provider ที่ใช้ string เป็น token สำหรับค่าที่ไม่มี class รองรับ
  • inject token แบบ string ด้วย decorator @Inject() ใน constructor
  • จัดเก็บชื่อ token ไว้ในไฟล์ constants เพื่อกัน typo และให้ refactor ง่าย

เมื่อสิ่งที่อยาก inject ไม่ใช่ class

ผ่านมา token ของเราเป็น class เสมอ (CoffeesService) ซึ่งสะดวกเพราะ TypeScript ใช้ type ใน constructor หา provider ให้อัตโนมัติ แต่บางค่าไม่มี class เป็นตัวแทน เช่น array ของชื่อแบรนด์กาแฟ, connection object หรือ config ธรรมดา กรณีนี้เราตั้ง token เป็น string ได้ แล้วผูกค่าเข้าไปด้วย useValue

// ประกาศ provider ที่ใช้ string เป็น token
{
  provide: 'COFFEE_BRANDS',
  useValue: ['buddy brew', 'nescafe'], // array ของแบรนด์กาแฟ
},

inject ด้วย @Inject เพราะ type ช่วยไม่ได้แล้ว

พอ token ไม่ใช่ class Nest จะเดาจาก type ใน constructor ไม่ได้อีกต่อไป (type string[] ไม่ได้บอกว่าหมายถึง token ไหน) จึงต้องระบุ token ตรง ๆ ด้วย decorator @Inject()

// inject string token เข้า CoffeesService
@Injectable()
export class CoffeesService {
  constructor(@Inject('COFFEE_BRANDS') coffeeBrands: string[]) {}
}

การพิมพ์ string ซ้ำสองที่ (ตอนประกาศและตอน inject) เปิดช่องให้ typo แบบที่ compiler จับไม่ได้ แนวปฏิบัติที่คอร์สแนะนำคือเก็บชื่อ token ไว้ในไฟล์ constants แล้ว import ไปใช้ทั้งสองฝั่ง

/* coffees.constants.ts */
export const COFFEE_BRANDS = 'COFFEE_BRANDS';

// ฝั่ง module
{ provide: COFFEE_BRANDS, useValue: ['buddy brew', 'nescafe'] }

// ฝั่ง service
constructor(@Inject(COFFEE_BRANDS) coffeeBrands: string[]) {}

นอกจาก string แล้ว token ยังเป็น Symbol ได้เช่นกัน ยิ่งกันชนกันข้าม library ได้ดีขึ้น ประเด็นสำคัญคือ token เป็นเพียง "กุญแจ" ใน DI container — จะเป็น class, string หรือ symbol ก็ทำหน้าที่เดียวกัน

เพิ่ม COFFEE_BRANDS เข้า CoffeesModule

สร้างไฟล์ coffees.constants.ts, ประกาศ provider COFFEE_BRANDS ใน coffees.module.ts แล้ว inject เข้า CoffeesService พร้อม log ค่าออกมาดูใน constructor เพื่อยืนยันว่าได้ array จริง

// coffees.constants.ts export const COFFEE_BRANDS = 'COFFEE_BRANDS'; // coffees.module.ts — เพิ่มใน providers { provide: COFFEE_BRANDS, useValue: ['buddy brew', 'nescafe'] } // coffees.service.ts constructor(@Inject(COFFEE_BRANDS) coffeeBrands: string[]) { console.log(coffeeBrands); } npm run start:dev

ผลลัพธ์ที่คาดหวัง

ตอนแอป start terminal พิมพ์ [ 'buddy brew', 'nescafe' ] หนึ่งครั้ง (constructor ของ singleton ถูกเรียกครั้งเดียว) แสดงว่า Nest resolve string token แล้วส่ง array เข้ามาให้ตามที่ประกาศไว้ ทุก endpoint อื่นยังทำงานปกติ

ตรวจว่าใช้งานได้จริง

  • เห็น log array แบรนด์กาแฟตอน start และเห็นเพียงครั้งเดียว
  • ลองลบ @Inject(COFFEE_BRANDS) ออก — แอปต้องพังตอน start เพราะ Nest หา provider ให้ type string[] ไม่เจอ
  • ลองพิมพ์ token ผิดหนึ่งตัวอักษรฝั่ง inject — เห็น error resolve dependency ซึ่งคือเหตุผลที่ควรใช้ไฟล์ constants
  • ตรวจว่าทั้ง module และ service import ค่า COFFEE_BRANDS จาก coffees.constants.ts ไม่ได้พิมพ์ string ซ้ำเอง
