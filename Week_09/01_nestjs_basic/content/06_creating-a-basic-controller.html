สร้าง Controller พื้นฐาน

บทนี้เราจะทำอะไรบ้าง

  • Generate controller ใหม่ด้วย Nest CLI ทั้งแบบเต็มและแบบย่อ
  • อธิบายว่า @Controller('coffees') กับ @Get() ประกอบกันเป็น route path ได้อย่างไร
  • ยิงทดสอบ endpoint แรกของ resource coffees ได้

Controller คือด่านรับ request

Controller มีหน้าที่เดียว: รับ HTTP request ที่เข้ามา แล้วคืน response กลับไป การสร้าง controller ใหม่ไม่ต้องสร้างไฟล์เอง — ใช้ CLI generate ได้เลย ซึ่งจะสร้างทั้งไฟล์ controller, ไฟล์ test และอัปเดต module ให้อัตโนมัติ

# Generate a Controller
nest generate controller coffees

# แบบย่อ (ผลเหมือนกันทุกอย่าง)
nest g co coffees

ถ้ารัน nest generate controller โดยไม่ใส่ชื่อ CLI จะถามชื่อจากเราแทน และเติม flag --dry-run ได้เสมอเพื่อดูว่าจะสร้าง/แก้ไฟล์อะไรบ้างโดยยังไม่เขียนจริง

อ่านโค้ดที่ได้ทีละ decorator

โค้ดสุดท้ายของบทนี้สั้นมาก แต่ทุกบรรทัดสำคัญ

/* CoffeesController */
import { Controller, Get } from '@nestjs/common';

@Controller('coffees')
export class CoffeesController {
  @Get()
  findAll() {
    return 'This action returns all coffees';
  }
}
  • @Controller('coffees') ประกาศว่า class นี้เป็น controller และกำหนด route prefix เป็น /coffees — ทุก handler ในนี้จะอยู่ใต้ path นี้
  • @Get() ผูก method findAll() เข้ากับ HTTP GET ที่ path ของ prefix ตรง ๆ ดังนั้น route เต็มคือ GET /coffees
  • ค่า string ที่ return จะถูกส่งกลับเป็น response body ให้เอง — Nest จัดการ serialization และ status code เริ่มต้น (200) ให้

ชื่อ method (findAll) ตั้งอะไรก็ได้ ไม่มีผลต่อ route — สิ่งที่กำหนด route คือ decorator เท่านั้น แต่ตั้งชื่อให้สื่อความหมายไว้จะอ่านง่ายเมื่อ controller โตขึ้นในบทถัด ๆ ไป

สร้าง CoffeesController แล้วยิง endpoint แรก

ระหว่างที่ npm run start:dev รันอยู่ ให้ generate controller ชื่อ coffees แล้วเพิ่ม handler findAll() ตามโค้ดด้านบน จากนั้นยิง GET http://localhost:3000/coffees ด้วย Insomnia

nest g co coffees # ตรวจผลด้วย curl (หรือใช้ Insomnia) curl -i http://localhost:3000/coffees

ควรได้ผลลัพธ์แบบนี้

CLI สร้าง src/coffees/coffees.controller.ts พร้อมไฟล์ .spec.ts และเพิ่ม CoffeesController เข้า AppModule ให้อัตโนมัติ เมื่อยิง GET /coffees ได้ status 200 พร้อมข้อความ This action returns all coffees

ลองเช็กให้แน่ใจ

  • log ของ watch mode มีบรรทัด Mapped {/coffees, GET} route
  • curl -i http://localhost:3000/coffees ได้ HTTP/1.1 200 OK พร้อม body ตามที่ return
  • เปิด app.module.ts แล้วเห็น CoffeesController ถูกเพิ่มใน array controllers โดย CLI
  • ลองยิง GET /coffee (ไม่มี s) แล้วได้ 404 — ยืนยันว่า prefix มาจาก @Controller('coffees') จริง
