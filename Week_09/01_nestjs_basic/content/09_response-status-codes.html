กำหนด Response Status Codes

บทนี้เราจะทำอะไรบ้าง

  • บอกค่า status code เริ่มต้นที่ Nest ใช้กับแต่ละ HTTP method
  • เปลี่ยน status code ของ handler ด้วย @HttpCode และ HttpStatus enum
  • อธิบายได้ว่าทำไมการหยิบ @Res() มาใช้ตรง ๆ จึงควรทำอย่างระมัดระวัง

ค่า default ดีอยู่แล้ว — แต่บางครั้งต้องกำหนดเอง

Nest เลือก status code ให้อัตโนมัติ: ทุก handler คืน 200 OK ยกเว้น POST ที่คืน 201 Created ซึ่งครอบคลุมกรณีส่วนใหญ่ แต่เมื่อ endpoint ต้องสื่อสถานะเฉพาะ เช่น deprecated แล้ว ให้ใช้ decorator @HttpCode ประกบกับ HttpStatus enum — ทั้งคู่มาจาก @nestjs/common

/*
  💡 BEST PRACTICE:
  ใช้ @HttpCode คู่กับ HttpStatus enum แทนการพิมพ์เลขดิบ
*/
import { HttpStatus, HttpCode } from '@nestjs/common';

@Post()
@HttpCode(HttpStatus.GONE) // 👈 ตอบ 410 Gone
create(@Body() body: any) {
  // ...
}

การใช้ enum อย่าง HttpStatus.GONE แทนเลข 410 ทำให้โค้ดอ่านออกทันทีว่าตั้งใจสื่ออะไร และช่วยกัน typo ของเลข status ด้วย ตัวอย่างนี้ตั้ง 410 ชั่วคราวเพื่อทดลองเท่านั้น — เดี๋ยวเราจะเปลี่ยนกลับ

@Res(): ทรงพลังแต่ผูกติดแพลตฟอร์ม

อีกทางหนึ่งคือขอ response object ของแพลตฟอร์มข้างใต้ (Express หรือ Fastify) มาควบคุมเองผ่าน @Res()

/*
  🚨 ใช้อย่างระวัง — โค้ดจะผูกกับแพลตฟอร์ม (Express/Fastify)
*/
import { Res } from '@nestjs/common';
import { Response } from 'express'; // 👈 ต้อง type ให้ชัด ไม่งั้น TypeScript strict mode ฟ้อง implicit any

@Get()
findAll(@Res() response: Response) {
  // ตัวอย่างแบบ Express: ใช้ status() และ send()
  response.status(200).send('This action returns all coffees');
}

เมื่อใช้ @Res() เราต้องรับผิดชอบการส่ง response เองทั้งหมด และเสียความสามารถอัตโนมัติของ Nest ไปหลายอย่าง (เช่น interceptors ที่ทำงานกับค่า return) ที่สำคัญคือโค้ดจะ platform-dependent — ย้ายจาก Express ไป Fastify แล้วพังได้ ใช้เมื่อจำเป็นจริง ๆ เท่านั้น เช่น ต้อง stream ไฟล์หรือตั้ง header เฉพาะทาง

ทดลองเปลี่ยน status ของ POST /coffees

เพิ่ม @HttpCode(HttpStatus.GONE) ให้ handler create() แล้วยิง POST ดู status ที่เปลี่ยนไป จากนั้นลบ decorator ออกเพื่อกลับสู่ 201 ตามเดิม (อย่าลืม import HttpCode และ HttpStatus)

curl -i -X POST http://localhost:3000/coffees \ -H "Content-Type: application/json" \ -d '{"name": "Test Roast"}' # สังเกตบรรทัดแรก: HTTP/1.1 410 Gone

ควรได้ผลลัพธ์แบบนี้

ระหว่างที่ decorator ติดอยู่ POST ตอบ 410 Gone แทน 201; เมื่อลบออกแล้ว ตอบ 201 Created เหมือนเดิม โดย response body ไม่เปลี่ยน

ลองเช็กให้แน่ใจ

  • ก่อนแก้: curl -i -X POST /coffees ได้ 201 (ค่า default ของ POST)
  • หลังใส่ @HttpCode(HttpStatus.GONE): ได้ 410
  • GET /coffees ยังได้ 200 — ยืนยันว่า @HttpCode มีผลเฉพาะ handler ที่ติด decorator
  • หลังลบ decorator แล้ว status กลับเป็น 201 และไม่มี import ค้างที่ไม่ได้ใช้
