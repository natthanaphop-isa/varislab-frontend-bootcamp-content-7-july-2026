เพิ่ม Indexes ให้ Schemas

บทนี้เราจะทำอะไรบ้าง

  • อธิบายได้ว่า index ช่วยให้ MongoDB เลี่ยง collection scan ได้อย่างไร
  • ใส่ index ให้ property เดี่ยวผ่านตัวเลือกของ @Prop()
  • สร้าง compound index ที่ครอบหลาย property พร้อมกำหนดทิศทางการเรียง (ascending/descending)

Index คือทางลัดของ search engine ในฐานข้อมูล

Index คือโครงสร้างข้อมูลที่ช่วยให้ฐานข้อมูลค้นหาได้เร็วขึ้น ถ้าไม่มี index MongoDB ต้องทำ collection scan หรือไล่อ่านทุก document เพื่อหาข้อมูลที่ตรงกับ query ยิ่ง collection ใหญ่ งานนี้ก็ยิ่งช้า ดังนั้นถ้าเรารู้ว่าระบบค้นหา Event ด้วย name บ่อย ฟิลด์นี้ก็ควรมี index

Index ไม่ใช่ของฟรี: ทุกครั้งที่เขียน document ฐานข้อมูลต้องอัปเดต index ด้วย จึงควรใส่เฉพาะฟิลด์ที่ถูก query บ่อยจริง ไม่ใช่หว่านทุกฟิลด์

Index ฟิลด์เดียวผ่าน @Prop

รูปแบบที่ง่ายที่สุดคือ index บน property เดียว — ส่ง option เข้า decorator ได้เลย เช่นทำกับฟิลด์ name ของ Event ที่งานฝั่ง analytics ต้องค้นบ่อย:

// Index บน property เดียว
@Prop({ index: true })
name: string;

Compound index ครอบหลายฟิลด์บน schema

เมื่อ query กรองด้วยหลายฟิลด์พร้อมกัน (เช่น name คู่กับ type) ให้ประกาศ compound index ที่ตัว schema หลังสร้างจาก SchemaFactory แล้ว:

/* Event entity - FINAL CODE */
import { Prop, Schema, SchemaFactory } from '@nestjs/mongoose';
import * as mongoose from 'mongoose';

@Schema()
export class Event extends mongoose.Document {
  @Prop()
  type: string;

  @Prop({ index: true })
  name: string;

  @Prop({ type: mongoose.SchemaTypes.Mixed }) // 👈 ต้องส่งเป็น { type } — @nestjs/mongoose 12 อนุมาน type ของ Record<string, any> เองไม่ได้
  payload: Record<string, any>;
}

export const EventSchema = SchemaFactory.createForClass(Event);
EventSchema.index({ name: 1, type: -1 });

ตัวเลขคือทิศทางการเรียงใน index: 1 ที่ name หมายถึงเรียงจากน้อยไปมาก (ascending) ส่วน -1 ที่ type หมายถึงเรียงจากมากไปน้อย (descending) — ทิศทางมีผลกับ query ที่ sort หลายฟิลด์สวนทางกัน

ใส่ index ให้ Event schema

อัปเดต src/events/entities/event.entity.ts ตามโค้ดด้านบน: เพิ่ม index: true ให้ name และประกาศ compound index { name: 1, type: -1 } จากนั้นรีสตาร์ตแอปเพื่อให้ Mongoose สร้าง index ในฐานข้อมูล แล้วเข้าไปดูด้วย mongosh

npm run start:dev # ตรวจ index ที่ถูกสร้างจริงใน MongoDB docker exec -it <container-id> mongosh nest-course > db.events.getIndexes()

ควรได้ผลลัพธ์แบบนี้

db.events.getIndexes() แสดงอย่างน้อยสาม index: _id_ (ค่า default ของทุก collection), index ฟิลด์เดียวของ name และ compound index name_1_type_-1 — ยืนยันว่า query ที่ค้นตาม name หรือ name+type จะไม่ต้อง scan ทั้ง collection อีกต่อไป

ลองเช็กให้แน่ใจ

  • db.events.getIndexes() มีรายการ key { name: 1 } และ { name: 1, type: -1 }
  • รัน db.events.find({ name: "recommend_coffee" }).explain() แล้ว plan เป็น IXSCAN ไม่ใช่ COLLSCAN
  • โค้ดประกาศ compound index อยู่หลังบรรทัด SchemaFactory.createForClass เสมอ
  • แอปยังสตาร์ตและ endpoint เดิมทั้งหมดของเส้นทาง MongoDB ทำงานครบ — จบคอร์สอย่างสมบูรณ์ 🎉
