ใช้งาน ConfigService

เมื่อจบบทนี้ คุณจะสามารถ

  • Inject ConfigService เข้า provider ใดก็ได้แทนการอ่าน process.env ตรง ๆ
  • อ่านค่าด้วย get<T>() พร้อมระบุ type และค่า default
  • อธิบายข้อดีของการเข้าถึง config ผ่าน DI ต่อการเขียนเทสต์และการดูแลโค้ด

จาก process.env สู่ ConfigService

การหยิบ process.env.DATABASE_URL ตรง ๆ ทำงานได้ แต่กระจาย dependency ไปทั่วโค้ดแบบมองไม่เห็น และ mock ยากเวลาเขียนเทสต์ @nestjs/config จึงมี ConfigService ให้ inject ผ่านระบบ dependency injection ปกติของ Nest — จุดเดียวที่รู้เรื่อง environment ทั้งหมด

import { ConfigService } from '@nestjs/config';

@Injectable()
export class CoffeesService {
  constructor(
    private readonly configService: ConfigService,
  ) {}
}

ถ้า inject แล้ว Nest ฟ้องว่า resolve ConfigService ไม่ได้ ให้ตรวจว่า module ที่ใช้งาน import ConfigModule แล้ว หรือประกาศ ConfigModule.forRoot({ isGlobal: true }) ที่ AppModule เพื่อให้ทุก module มองเห็นโดยไม่ต้อง import ซ้ำ

อ่านค่าด้วย get() แบบระบุ type และ default

เมธอด get() รับชื่อ key และคืนค่าจาก environment; ใส่ generic type เพื่อบอก TypeScript ว่าคาดหวังชนิดใด และส่ง argument ตัวที่สองเป็นค่า default เมื่อ key ไม่ถูกตั้งไว้

const databaseUrl = this.configService.get<string>('DATABASE_URL');
console.log(databaseUrl);

// พร้อมค่า default เมื่อไม่พบ key
const port = this.configService.get<number>('PORT', 3000);
วิธีข้อดีข้อจำกัด
process.env.KEYสั้น ไม่ต้องพึ่งอะไรเป็น string | undefined เสมอ, mock ในเทสต์ยาก, dependency ซ่อนเร้น
configService.get<T>('KEY')ผ่าน DI จึง mock ง่าย, ระบุ type และ default ได้, จุดเข้าถึงเดียวต้อง import ConfigModule ให้ถูก scope

อ่านค่า DATABASE_URL ผ่าน ConfigService

ใน CoffeesService ของ iluvcoffee inject ConfigService (คู่กับ PrismaService ที่มีอยู่แล้ว) แล้วลอง log ค่า DATABASE_URL ใน constructor เพื่อยืนยันว่าอ่านค่าจาก .env ผ่าน service ได้จริง

// coffees.module.ts → imports: [ConfigModule] (ไม่งั้น Nest resolve ConfigService ใน CoffeesModule ไม่ได้) // coffees.service.ts import { ConfigService } from '@nestjs/config'; constructor( private readonly prisma: PrismaService, private readonly configService: ConfigService, ) { const databaseUrl = this.configService.get<string>('DATABASE_URL'); console.log(databaseUrl); } npm run start:dev

ผลลัพธ์ที่คาดหวัง

ตอนแอป start (หรือเมื่อ service ถูกสร้าง) เทอร์มินัลพิมพ์ postgresql://postgres:pass123@localhost:5432/postgres — ค่าเดียวกับใน .env — โดยที่ CoffeesService ไม่แตะ process.env เลย (ลบ log ทิ้งเมื่อทดสอบเสร็จ อย่าปล่อย credentials ไว้ใน log)

ตรวจว่าใช้งานได้จริง

  • Log แสดงค่า DATABASE_URL ตรงกับ .env
  • เปลี่ยนค่าใน .env แล้ว restart — log เปลี่ยนตาม
  • ลองอ่าน key ที่ไม่มีอยู่พร้อม default: get('NOT_EXIST', 'fallback') คืน fallback
  • แอปยัง start และ GET /coffees ทำงานปกติ ไม่มี DI error
