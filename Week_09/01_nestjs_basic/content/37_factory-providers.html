Factory Providers (useFactory)

เมื่อจบบทนี้ คุณจะสามารถ

  • สร้าง provider ที่คำนวณค่าด้วยฟังก์ชัน factory แทนการส่งค่าตายตัว
  • ส่ง dependency อื่นเข้า factory ผ่าน property inject
  • เลือกได้ว่าเมื่อไหร่ควรขยับจาก useValue ไป useFactory

useFactory: ให้ฟังก์ชันเป็นคนสร้างค่า

บางค่าไม่เหมาะจะเขียนตายตัวแบบ useValue เพราะต้องคำนวณก่อน เช่น ประกอบจาก environment, สุ่ม, หรืออ่านจาก service อื่น useFactory รับฟังก์ชันเข้าไป แล้วสิ่งที่ฟังก์ชัน return จะกลายเป็นค่าที่ผูกกับ token

// ตัวอย่าง syntax "useFactory"
{
  provide: 'COFFEE_BRANDS',
  useFactory: () => ['buddy brew', 'nescafe']
}

ตัวอย่างนี้ให้ผลเหมือน useValue ทุกประการ แต่เปิดประตูบานใหม่: ใน factory เราใส่ logic ได้เต็มที่ และที่สำคัญที่สุด — factory ขอ inject provider อื่นมาใช้ประกอบการสร้างค่าได้

inject: ส่ง dependency เข้า factory

ประกาศ token ที่ต้องการไว้ใน array inject แล้ว Nest จะ resolve และส่งเข้าเป็น parameter ของ factory ตามลำดับ

{
  provide: 'COFFEE_BRANDS',
  useFactory: (coffeesService: CoffeesService) => {
    // ใช้ service อื่นประกอบการสร้างค่าได้
    return ['buddy brew', 'nescafe'];
  },
  inject: [CoffeesService], // 👈 ลำดับตรงกับ parameter ของ factory
}

ลำดับใน inject ต้องตรงกับลำดับ parameter ของ factory แบบตัวต่อตัว และ token ที่ขอ inject ต้องมองเห็นได้จาก module นี้ (อยู่ใน providers เดียวกัน หรือถูก export มาจาก module ที่เรา import) ไม่อย่างนั้นจะเจอ error resolve dependency ตอน start นอกจากนี้ห้าม inject provider ที่ย้อนกลับมาพึ่ง token เดียวกันนี้ — เช่น CoffeesService เอง ก็ @Inject('COFFEE_BRANDS') อยู่แล้ว (บทที่ 35) ถ้า factory ของ COFFEE_BRANDS ไป inject: [CoffeesService] ด้วย จะกลายเป็น circular dependency แล้วแอปจะพังตอน start ทันที

บันไดสามขั้นของ provider แบบกำหนดค่า

รูปแบบค่าเกิดจากinject dependency ได้ไหมใช้เมื่อ
useValueค่าที่เขียนไว้ล่วงหน้าไม่ได้ค่าคงที่, mock
useClassNest instantiate class ที่เลือกได้ ผ่าน constructor ของ classสลับ implementation ทั้งก้อน
useFactoryค่าที่ฟังก์ชัน returnได้ ผ่าน inject arrayค่าที่ต้องมี logic หรือพึ่ง provider อื่น

เปลี่ยน COFFEE_BRANDS ให้มาจาก factory

ใน coffees.module.ts แก้ provider COFFEE_BRANDS จาก useValue (บทที่ 35) เป็น useFactory จากนั้นทดลองเพิ่ม inject: [PrismaService] (ห้ามใช้ CoffeesService — มันพึ่ง COFFEE_BRANDS อยู่แล้ว จะกลายเป็น circular dependency) และ log ใน factory เพื่อดูลำดับการสร้างของ container

// coffees.module.ts { provide: COFFEE_BRANDS, useFactory: () => ['buddy brew', 'nescafe'], } // ขั้นทดลองต่อ: เพิ่ม parameter + inject array แล้วสังเกต log // ใช้ provider ที่ไม่พึ่ง COFFEE_BRANDS กลับมา เช่น PrismaService { provide: COFFEE_BRANDS, useFactory: (prisma: PrismaService) => { console.log('factory: got', typeof prisma); return ['buddy brew', 'nescafe']; }, inject: [PrismaService], } npm run start:dev

ผลลัพธ์ที่คาดหวัง

แอป start ปกติ และ log ใน CoffeesService (จากบทที่ 35) ยังแสดง array แบรนด์เหมือนเดิม — ผู้บริโภค token ไม่รับรู้ว่าเบื้องหลังเปลี่ยนวิธีสร้าง เมื่อเพิ่ม inject จะเห็นว่า factory ถูกเรียกหลังจาก dependency ที่ขอถูกสร้างเสร็จแล้ว

ตรวจว่าใช้งานได้จริง

  • log ตอน start ยังแสดง [ 'buddy brew', 'nescafe' ] หลังสลับเป็น factory
  • ใส่ console.log ใน factory แล้วเห็นมันรันหนึ่งครั้งตอน bootstrap (default scope เป็น singleton)
  • ลองใส่ token ใน inject ที่ module นี้มองไม่เห็น — ต้องเจอ error resolve dependency ตามคาด
  • อธิบายได้ว่ากรณีไหนที่ useValue ไม่พอและต้องใช้ factory (เช่น ค่าขึ้นกับ provider อื่น)
