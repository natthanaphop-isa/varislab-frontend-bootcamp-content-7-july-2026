ใช้ Route Parameters

เมื่อจบบทนี้ คุณจะสามารถ

  • ประกาศ route ที่มีส่วนไดนามิกด้วย @Get(':id')
  • ดึงค่า parameter จาก URL เข้ามาใน handler ด้วย @Param('id')
  • เลือกได้ว่าจะรับ params ทั้ง object หรือเจาะจงตัวเดียว

Route แบบคงที่ไม่พอสำหรับ REST

GET /coffees คืนกาแฟทั้งหมดได้ แต่ REST API ต้องดึง รายตัว ได้ด้วย เช่น GET /coffees/1 ส่วนของ URL ที่เปลี่ยนไปตามข้อมูล (เลข 1) เรียกว่า route parameter — ประกาศด้วย : นำหน้าใน path ของ decorator

/* CoffeesController */
import { Controller, Get, Param } from '@nestjs/common';

@Controller('coffees')
export class CoffeesController {
  @Get()
  findAll() {
    return 'This action returns all coffees';
  }

  @Get(':id')
  findOne(@Param('id') id: string) {
    return `This action returns #${id} coffee`;
  }
}
  • @Get(':id') ประกอบกับ prefix ของ class เป็น route GET /coffees/:id — :id จับคู่กับค่าอะไรก็ได้ในตำแหน่งนั้น
  • @Param('id') บอก Nest ให้ส่งเฉพาะค่า id จาก URL เข้ามาเป็น argument ของ method
  • ค่า route parameter มาเป็น string เสมอ — แม้ผู้ใช้จะพิมพ์ตัวเลขก็ตาม (เราจะจัดการแปลง type อย่างเป็นระบบในบทหลัง ๆ ด้วย pipes)

รับทั้งก้อนหรือเจาะจงตัวเดียว

@Param() ใช้ได้สองแบบ: ถ้าไม่ส่ง argument จะได้ object รวมทุก parameter (params.id) ถ้าส่งชื่อจะได้ค่านั้นตรง ๆ ซึ่งอ่านง่ายกว่าและประกาศ type ให้ตัวแปรได้ทันที — โค้ดในคอร์สนี้จึงใช้แบบระบุชื่อเป็นหลัก

ลำดับของ route มีผล: ถ้ามี route คงที่อย่าง @Get('flavors') ต้องประกาศไว้ ก่อน @Get(':id') ไม่อย่างนั้นคำว่า flavors จะถูกจับเป็นค่า :id ไปเสียก่อน

เพิ่ม endpoint ดึงกาแฟรายตัว

เพิ่ม handler findOne ตามโค้ดด้านบนเข้า CoffeesController แล้วยิงทดสอบด้วย id หลาย ๆ ค่า ทั้งตัวเลขและข้อความ เพื่อดูว่า :id จับคู่อะไรบ้าง

curl http://localhost:3000/coffees/1 curl http://localhost:3000/coffees/42 curl http://localhost:3000/coffees/espresso

ผลลัพธ์ที่คาดหวัง

ทุก request ได้ status 200 พร้อมข้อความที่สะท้อนค่า id กลับมา เช่น This action returns #1 coffee และ This action returns #espresso coffee — ยืนยันว่า parameter เป็น string ที่จับคู่ได้ทุกค่า

ตรวจว่าใช้งานได้จริง

  • log แสดง Mapped {/coffees/:id, GET} route เพิ่มขึ้นมา
  • GET /coffees/1 กับ GET /coffees/2 ให้ข้อความต่างกันตามค่า id
  • GET /coffees (ไม่มี id) ยังคงเข้า handler findAll() เหมือนเดิม
  • ลองพิมพ์ typeof id ลง console ใน handler แล้วยืนยันว่าได้ string เสมอ
