สร้าง Configuration Files ของตัวเอง

เมื่อจบบทนี้ คุณจะสามารถ

  • สร้าง configuration file ที่ return object ซ้อนชั้น พร้อมค่า default และการแปลงชนิดข้อมูล
  • โหลดไฟล์นั้นเข้า ConfigModule ด้วย option load
  • อ่านค่า nested ผ่าน ConfigService ด้วย dot notation

จาก key แบน ๆ สู่ config ที่มีโครงสร้าง

ไฟล์ .env เก็บได้แค่คู่ key/value แบน ๆ ที่เป็น string ทั้งหมด เมื่อ config โตขึ้นเราอยากได้โครงสร้าง: จัดกลุ่มค่าที่เกี่ยวข้องกัน แปลงชนิดข้อมูล และกำหนด default ในที่เดียว custom configuration file คือ factory function ธรรมดาที่ return object — เราจะเขียน logic อะไรในนั้นก็ได้

// src/config/app.config.ts
export default () => ({
  environment: process.env.NODE_ENV || 'development',
  port: parseInt(process.env.PORT ?? '3000', 10),
  database: {
    url: process.env.DATABASE_URL,
  },
});

สังเกตว่าไฟล์นี้เป็นจุดเดียวที่ยังแตะ process.env — ทั้งการอ่าน, fallback ด้วย ?? เมื่อไม่ได้ตั้งค่า (จำเป็นใน strict mode เพราะ process.env.PORT มีชนิด string | undefined) และการแปลงเป็นตัวเลขด้วย parseInt ถูกรวมไว้ที่เดียว ส่วนอื่นของแอปเห็นแค่ object ที่มีโครงสร้างชัดเจนแล้ว

โหลดเข้า ConfigModule ด้วย option load

// app.module.ts
import appConfig from './config/app.config.js';

@Module({
  imports: [
    ConfigModule.forRoot({
      load: [appConfig],
    }),
  ],
})
export class AppModule {}

load รับ array จึงแยก config เป็นหลายไฟล์ตามหมวดได้เมื่อโปรเจกต์โตขึ้น (และบทถัดไปจะพาไปอีกขั้นด้วย namespaces)

อ่านค่า nested ด้วย dot notation

ค่าใน object ที่โหลดแล้วเข้าถึงผ่าน ConfigService เหมือนเดิม โดยชี้ลึกลงไปด้วยรูปแบบ a.b และยังใส่ default เป็น argument ตัวที่สองได้

const databaseUrl = this.configService.get('database.url');
const port = this.configService.get('port', 3000);

รวม config ของ iluvcoffee ไว้ใน app.config.ts

สร้าง src/config/app.config.ts ตามตัวอย่าง, ลงทะเบียนผ่าน load ใน ConfigModule.forRoot() แล้วเปลี่ยนจุดที่อ่าน DATABASE_URL ในบทก่อนให้ใช้ database.url แทน

mkdir -p src/config # สร้าง src/config/app.config.ts ตามตัวอย่างด้านบน // coffees.service.ts — ทดสอบอ่านค่า nested const databaseUrl = this.configService.get('database.url'); console.log(databaseUrl, this.configService.get('port')); npm run start:dev

ผลลัพธ์ที่คาดหวัง

เทอร์มินัลพิมพ์ connection string จาก .env ผ่านเส้นทางใหม่ database.url และเมื่อไม่ได้ตั้ง PORT ใน .env ค่า port จะกลายเป็น 3000 จาก fallback ใน config file ไม่ใช่ NaN

ตรวจว่าใช้งานได้จริง

  • get('database.url') คืนค่าตรงกับ DATABASE_URL ใน .env
  • get('environment') คืน development เมื่อไม่ได้ตั้ง NODE_ENV
  • port เป็น number (ลอง typeof) เพราะผ่าน parseInt แล้ว
  • แอป start และ GET /coffees ทำงานปกติหลัง refactor
