สร้าง Mongoose Model

บทนี้เราจะทำอะไรบ้าง

  • อธิบายบทบาทของ Model ใน MongoDB และความต่างระหว่าง collections/documents กับ tables/rows ได้
  • ประกาศ Schema ด้วย decorators @Schema() และ @Prop() แล้วสร้าง schema จริงด้วย SchemaFactory
  • ลงทะเบียน Model ให้กับ feature module ด้วย MongooseModule.forFeature()

Model คือประตูเข้าออกของข้อมูลใน MongoDB

แนวคิดที่สำคัญที่สุดอย่างหนึ่งของ MongoDB คือ Data Model: ตัวที่รับผิดชอบการสร้าง อ่าน และลบ documents ออกจากฐานข้อมูล ถ้าคุณมาจากสาย SQL สิ่งที่ต้องจำคือ documents เหล่านี้ถูกเก็บใน collections ไม่ใช่ tables

ฝั่ง SQL (Prisma)ฝั่ง MongoDB (Mongoose)หมายเหตุ
TableCollectionที่เก็บข้อมูลของ resource หนึ่ง ๆ
RowDocumentข้อมูลหนึ่งรายการ
model Coffee { ... } ใน schema.prisma@Schema() บน classประกาศโครงสร้างข้อมูล — Prisma ใช้ไฟล์ schema แยก ส่วน Mongoose ใช้ decorator บน TypeScript class
บรรทัด field เช่น name String@Prop()ประกาศ property ที่จะถูกเก็บ

ประกาศ Coffee Schema ด้วย decorators

เขียนไว้ที่ src/coffees/entities/coffee.entity.ts โดย class ต้อง extend Document ของ mongoose เพื่อให้ instance ที่ได้กลับมาเป็น document ที่มี method อย่าง save() ติดตัว ส่วน @Prop([String]) บอกว่า flavors เป็น array ของ string

/* Coffee Schema - FINAL CODE */
import { Schema, Prop, SchemaFactory } from '@nestjs/mongoose';
import { Document } from 'mongoose';

@Schema()
export class Coffee extends Document {
  @Prop()
  name: string;

  @Prop()
  brand: string;

  @Prop([String])
  flavors: string[];
}

export const CoffeeSchema = SchemaFactory.createForClass(Coffee);

บรรทัดสุดท้ายสำคัญมาก: SchemaFactory.createForClass(Coffee) แปลง class ที่ตกแต่งด้วย decorators ให้กลายเป็น Mongoose schema จริง ๆ ที่ระบบนำไปสร้าง Model ได้ สังเกตว่าเราไม่ต้องประกาศ id เอง — MongoDB สร้าง _id ให้ทุก document โดยอัตโนมัติ

ลงทะเบียน Model ใน CoffeesModule

ต่างจากฝั่ง Prisma ที่ทุก model อยู่ในไฟล์ schema เดียวและ inject ผ่าน PrismaService ตัวเดียว ฝั่ง Mongoose แต่ละ feature module ต้องบอกว่าตัวเองใช้ Model อะไรบ้าง ผ่าน MongooseModule.forFeature() ใน imports ของ CoffeesModule:

/* เพิ่ม Schema เข้า MongooseModule ใน CoffeesModule */
MongooseModule.forFeature([{
  name: Coffee.name,
  schema: CoffeeSchema
}])

Coffee.name ในที่นี้คือ property name ของ JavaScript class (ได้ค่า "Coffee") ไม่ใช่ฟิลด์ name ของกาแฟ — ค่านี้ถูกใช้เป็น token สำหรับ inject model ในบทถัดไป และ Mongoose จะตั้งชื่อ collection ให้เป็นพหูพจน์ตัวพิมพ์เล็กโดยอัตโนมัติ (coffees)

เปลี่ยน Coffee entity ให้เป็น Mongoose Schema

แก้ไฟล์ src/coffees/entities/coffee.entity.ts จาก class ธรรมดาของ Chapter 2 ให้เป็น Schema ตามโค้ดด้านบน แล้วเพิ่ม MongooseModule.forFeature() ใน coffees.module.ts

# แอปควรรันอยู่ระหว่างแก้ เพื่อดู compile error ทันที npm run start:dev # จุดที่ต้องแก้ # 1) coffee.entity.ts → @Schema() + @Prop() + SchemaFactory.createForClass # 2) coffees.module.ts → imports: [MongooseModule.forFeature([{ name: Coffee.name, schema: CoffeeSchema }])]

ควรได้ผลลัพธ์แบบนี้

แอป compile ผ่านและสตาร์ตได้ตามปกติ โดย CoffeesModule รู้จัก Model Coffee แล้ว (ส่วน CoffeesService จะยัง error อยู่ถ้าอ้างข้อมูล in-memory เดิม — เราจะเปลี่ยนให้มันใช้ Model นี้ทั้งหมดในบทถัดไป)

ลองเช็กให้แน่ใจ

  • coffee.entity.ts มีทั้ง @Schema(), @Prop() ครบสามฟิลด์ และ export CoffeeSchema
  • class Coffee extend Document จาก mongoose ไม่ใช่จากที่อื่น
  • coffees.module.ts import MongooseModule.forFeature พร้อมคู่ name/schema ที่ถูกต้อง
  • ไม่มีโค้ดของ Prisma (PrismaService, schema.prisma, src/generated/) หลงเหลืออยู่บน branch นี้
