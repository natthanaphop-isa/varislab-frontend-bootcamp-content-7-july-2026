Validate ตัวแปรแวดล้อมด้วย Schema

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายประโยชน์ของ fail fast: ให้แอปปฏิเสธการ start เมื่อ environment ไม่ครบ แทนที่จะพังกลางทาง
  • ติดตั้ง Joi และประกาศ validationSchema ให้ ConfigModule
  • กำหนดตัวแปรแบบ required และแบบมีค่า default ได้

ทำไมต้อง validate environment ตั้งแต่ตอน start

ถ้า DATABASE_URL หายไปหรือพิมพ์ผิด สิ่งที่เห็นคือ error จาก driver ของ PostgreSQL ตอน PrismaService พยายามเชื่อมต่อ ซึ่งไม่ได้บอกเลยว่าต้นเหตุคือ environment variable ตัวไหน — อาการแบบนี้วินิจฉัยยากเพราะ error โผล่ไกลจากต้นเหตุ วิธีที่ดีกว่าคือประกาศ schema ของตัวแปรที่จำเป็นทั้งหมด แล้วให้ ConfigModule ตรวจตอน bootstrap: ถ้าขาดหรือผิดชนิด แอปจะ throw ทันทีพร้อมข้อความบอกว่า key ไหนมีปัญหา

ติดตั้ง Joi และประกาศ schema

เราใช้ไลบรารี Joi สำหรับเขียน object schema แบบ declarative (มี type definitions ในตัว ไม่ต้องติดตั้ง @types แยก):

npm install joi
// app.module.ts
import Joi from 'joi';

@Module({
  imports: [
    ConfigModule.forRoot({
      validationSchema: Joi.object({
        DATABASE_URL: Joi.string().required(),
        PORT: Joi.number().default(3000),
      }),
    }),
    // ...
  ],
})
export class AppModule {}

สองบรรทัดใน schema นี้เล่าเรื่องต่างกัน: DATABASE_URL เป็นค่า required — ไม่มีแล้ว start ไม่ได้; ส่วน PORT (พอร์ตที่แอป listen ใน main.ts) ต้องเป็นตัวเลข แต่ถ้าไม่ตั้งมาก็ fallback เป็น 3000 ให้อัตโนมัติ

คอร์สต้นฉบับใช้แพ็กเกจ @hapi/joi ซึ่ง deprecated ไปแล้ว — เวอร์ชันปัจจุบันอยู่ที่แพ็กเกจชื่อ joi และเพราะโปรเจกต์ Nest 12 ของเราเป็น ES module จึง import แบบ default (import Joi from 'joi') ไม่ใช่ import * as Joi แบบเดิม แนวคิดและ API ที่ใช้ในบทนี้เหมือนเดิมทุกประการ ตรวจรายละเอียดจากเอกสาร NestJS หัวข้อ Schema validation

ทำให้แอป fail fast เมื่อ env ไม่ครบ

เพิ่ม validationSchema ให้ครอบคลุม DATABASE_URL และ PORT ของ iluvcoffee จากนั้นทดสอบโดยลบ DATABASE_URL ออกจาก .env ชั่วคราวเพื่อดู error ตอน start แล้วใส่กลับ

npm install joi // เพิ่ม validationSchema ใน ConfigModule.forRoot() // จากนั้นทดสอบ fail fast: # 1) คอมเมนต์บรรทัด DATABASE_URL ใน .env # 2) npm run start:dev → ควรเห็น validation error # 3) เอาคอมเมนต์ออก แล้ว start ใหม่

ผลลัพธ์ที่คาดหวัง

เมื่อ DATABASE_URL หายไป แอปหยุดทันทีพร้อมข้อความประมาณ Config validation error: "DATABASE_URL" is required — ไม่ใช่ start สำเร็จแล้วไปพังตอน query และเมื่อใส่ค่ากลับ แอปกลับมา start ได้ปกติ

ตรวจว่าใช้งานได้จริง

  • ลบ DATABASE_URL แล้ว start — เห็น validation error ที่ระบุชื่อ key ชัดเจน ไม่ใช่ error จาก driver ของ Postgres
  • ไม่ตั้ง PORT แล้ว start — แอปทำงานได้บนพอร์ต default 3000
  • ตั้ง PORT=abc — เห็น error ว่าต้องเป็น number
  • เมื่อ .env ครบถ้วน GET /coffees ยังทำงานปกติ
