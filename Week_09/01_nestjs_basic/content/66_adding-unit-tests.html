เขียน Unit Tests

เมื่อจบบทนี้ คุณจะสามารถ

  • สร้าง mock ของ PrismaService ที่ควบคุมค่าตอบกลับได้ด้วย vi.fn() แทน mock ว่าง
  • เขียน test ครอบคลุมทั้งขาสำเร็จ (พบ coffee) และขาล้มเหลว (throw NotFoundException) ของ findOne
  • จัดโครง describe ซ้อนกันให้อ่านเป็นสเปกพฤติกรรมได้

จาก mock ว่างสู่ mock ที่ตอบได้

บทที่แล้ว mock ของเราเป็น object ว่าง ซึ่งพอให้ DI resolve ได้แต่ทดสอบพฤติกรรมจริงไม่ได้ ปัญหาคือ findOne ของ service เรียก this.prisma.coffee.findUnique(...) ข้างใน — ถ้า mock ไม่มี property coffee ที่มีเมธอดนี้ test จะพัง เราจึงยกระดับเป็น mock ที่เลียนโครง prisma.<model>.<method> โดยให้แต่ละเมธอดเป็น vi.fn() เพื่อกำหนดค่าตอบกลับได้ในแต่ละ test

type MockPrisma = {
  coffee: {
    findMany: Mock;
    findUnique: Mock;
    create: Mock;
  };
};
const createMockPrisma = (): MockPrisma => ({
  coffee: {
    findMany: vi.fn(),
    findUnique: vi.fn(),
    create: vi.fn(),
  },
});

Type helper นี้บอกว่า: mock ของเราเป็น object ที่มี property ชื่อเดียวกับ model และข้างในเป็นเมธอดที่เป็น Mock (type จาก vitest — ตัวเดียวที่ต้อง import เพราะ vi, describe, expect เป็น global อยู่แล้ว) — ได้ autocomplete และกันพิมพ์ชื่อเมธอดผิดไปพร้อมกัน ประกาศเฉพาะเมธอดที่ test ต้องใช้ก็พอ

ถ้าอยากได้ mock ที่ครบทุก model และทุกเมธอดโดยไม่ต้องพิมพ์เอง ไลบรารี vitest-mock-extended มี mockDeep<PrismaClient>() ให้ใช้ — แต่ในบทนี้เราเขียนมือเพื่อให้เห็นว่าไม่มีเวทมนตร์อะไรซ่อนอยู่

โค้ดเต็มของ suite

/* coffees.service.spec.ts - FINAL CODE */
import type { Mock } from 'vitest'; // describe/it/expect/vi เป็น global อยู่แล้ว import เฉพาะ type
import { Test, TestingModule } from '@nestjs/testing';
import { NotFoundException } from '@nestjs/common';
import { CoffeesService } from './coffees.service.js';
import { PrismaService } from '../prisma/prisma.service.js';

type MockPrisma = {
  coffee: {
    findMany: Mock;
    findUnique: Mock;
    create: Mock;
  };
};
const createMockPrisma = (): MockPrisma => ({
  coffee: {
    findMany: vi.fn(),
    findUnique: vi.fn(),
    create: vi.fn(),
  },
});

describe('CoffeesService', () => {
  let service: CoffeesService;
  let prisma: MockPrisma;

  beforeEach(async () => {
    const module: TestingModule = await Test.createTestingModule({
      providers: [
        CoffeesService,
        { provide: PrismaService, useValue: createMockPrisma() },
      ],
    }).compile();

    service = module.get<CoffeesService>(CoffeesService);
    prisma = module.get<MockPrisma>(PrismaService);
  });

  it('should be defined', () => {
    expect(service).toBeDefined();
  });

  describe('findOne', () => {
    describe('when coffee with ID exists', () => {
      it('should return the coffee object', async () => {
        const coffeeId = '1';
        const expectedCoffee = {};

        prisma.coffee.findUnique.mockReturnValue(expectedCoffee);
        const coffee = await service.findOne(coffeeId);
        expect(coffee).toEqual(expectedCoffee);
      });
    });
    describe('otherwise', () => {
      it('should throw the "NotFoundException"', async () => {
        const coffeeId = '1';
        prisma.coffee.findUnique.mockReturnValue(null); // Prisma คืน null เมื่อไม่พบ

        try {
          await service.findOne(coffeeId);
          expect(false).toBeTruthy(); // ต้องไม่มาถึงบรรทัดนี้
        } catch (err) {
          expect(err).toBeInstanceOf(NotFoundException);
          expect((err as Error).message).toEqual(`Coffee #${coffeeId} not found`); // strict: err เป็น unknown
        }
      });
    });
  });
});

สังเกตสองจุดสำคัญ: เราดึง mock กลับออกมาจาก container ด้วย module.get(PrismaService) เพื่อสั่ง mockReturnValue บน prisma.coffee.findUnique ในแต่ละ test และโครง describe('findOne') → describe('when …') → it('should …') ทำให้รายงานผลอ่านเป็นประโยคสเปกได้ทันที

ขาที่คาดว่า throw ให้ยืนยันว่า throw เกิดขึ้นจริง — โค้ดนี้ใช้ expect(false).toBeTruthy() เป็นกับดักกันกรณี findOne ไม่ throw แล้ว test ผ่านแบบหลอก ๆ ถ้าลืมจุดนี้ test ขาล้มเหลวอาจ เขียว ทั้งที่ไม่เคยทดสอบอะไรเลย

ทดสอบ findOne ให้ครบสองขา

แทนที่เนื้อหา coffees.service.spec.ts ด้วยโค้ดเต็มด้านบน แล้วรันแบบ watch จนผ่านทั้ง 3 tests จากนั้นลองสลับค่า mock เพื่อดูว่า test จับความผิดปกติได้จริง

npm run test:watch -- coffees.service # ผ่านแล้วลองทดสอบว่า test แข็งแรง: # เปลี่ยน mockReturnValue(null) เป็น mockReturnValue({}) ชั่วคราว # → test ขา NotFoundException ต้อง fail

ผลลัพธ์ที่คาดหวัง

Suite รายงาน 3 tests ผ่านทั้งหมด: should be defined, ขา when coffee with ID exists และขา otherwise → should throw the "NotFoundException" โดยไม่ต้องต่อฐานข้อมูลจริงเลย

ตรวจว่าใช้งานได้จริง

  • npm run test:watch -- coffees.service เขียวทั้ง suite และไม่มี connection ไปยัง Postgres (ปิด Docker ก็ยังผ่าน)
  • ทดลอง sabotage: แก้ message ใน NotFoundException ของ service ชั่วคราว → test ต้อง fail ที่ err.message
  • ตรวจว่า prisma ที่ใช้ใน test เป็นตัวเดียวกับที่ดึงจาก module.get(PrismaService) ไม่ใช่ object ใหม่จาก createMockPrisma() อีกตัว
  • รัน npm run test:cov แล้วดูว่า coverage ของ coffees.service.ts ขยับขึ้นจากบทก่อน
