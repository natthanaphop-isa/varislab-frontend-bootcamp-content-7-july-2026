ตั้งค่า ConfigModule และ Environment Files

บทนี้เราจะทำอะไรบ้าง

  • อธิบายได้ว่าทำไม configuration ควรอยู่ใน environment ไม่ใช่ hardcode ในโค้ด
  • ติดตั้ง @nestjs/config และดูแลไฟล์ .env โดยไม่ให้ credentials หลุดขึ้น git
  • ให้ ConfigModule โหลด DATABASE_URL แทนการ import dotenv เองใน main.ts
  • เลือกใช้ envFilePath หรือ ignoreEnvFile ให้เหมาะกับสภาพแวดล้อมที่รันแอป

ทำไม configuration ต้องแยกออกจากโค้ด

แอปของเรามักรันในหลาย environment — development, staging, production — ซึ่งแต่ละที่ใช้ค่าต่างกัน เช่น host ของฐานข้อมูล, credentials หรือ API key แนวปฏิบัติมาตรฐานของชุมชน Node.js คือเก็บค่าเหล่านี้ไว้ใน environment variables ผ่าน object global process.env เพื่อให้โค้ดชุดเดียวรันได้ทุกที่โดยเปลี่ยนแค่ค่าแวดล้อม

@nestjs/config ช่วยให้เรื่องนี้ง่ายขึ้น: เมื่อเรียก ConfigModule.forRoot() มันจะอ่านไฟล์ .env ที่ root ของโปรเจกต์ แล้ว merge คู่ key/value เข้ากับ process.env ให้อัตโนมัติ

npm i @nestjs/config
// app.module.ts
import { ConfigModule } from '@nestjs/config';

@Module({
  imports: [
    ConfigModule.forRoot(),
    // ...imports อื่น ๆ
  ],
})
export class AppModule {}

ไฟล์ .env ที่เรามีอยู่แล้ว และการกันไม่ให้หลุดขึ้น git

ตั้งแต่บทที่ 22 npx prisma init สร้างไฟล์ .env ที่ root ของ iluvcoffee ไว้ให้ และเราเก็บ connection string ของ PostgreSQL ไว้ในนั้นมาตลอด

DATABASE_URL="postgresql://postgres:pass123@localhost:5432/postgres"

ไฟล์ .env มี credentials จริง ห้าม commit ขึ้น repository เด็ดขาด — prisma init ในบทที่ 22 เพิ่ม .env ลง .gitignore ให้แล้ว ถ้าทีมใช้ไฟล์อย่าง .env.development เพิ่ม ให้ใส่แพทเทิร์น *.env ด้วย แล้วตรวจ git status ทุกครั้งว่าไฟล์เหล่านี้ไม่โผล่ในรายการ

# .gitignore
# Env
.env
*.env

ให้ ConfigModule โหลด .env แทน dotenv ที่เราใส่เองใน main.ts

ในบทที่ 22 เราแก้ขัดด้วยการ import 'dotenv/config' ไว้บรรทัดแรกของ main.ts เพื่อให้ process.env.DATABASE_URL มีค่าก่อน PrismaService ถูกสร้าง ตอนนี้ลบบรรทัดนั้นทิ้งแล้วให้ ConfigModule.forRoot() รับหน้าที่แทน — ผลลัพธ์เหมือนกัน แต่ต่อจากนี้เราจะได้ ConfigService, การ validate และ custom configuration files ในบทถัด ๆ ไปเป็นของแถม

// main.ts — ลบบรรทัดนี้ออก
- import 'dotenv/config';

// app.module.ts
@Module({
  imports: [
    ConfigModule.forRoot(),
    PrismaModule,
    CoffeesModule,
  ],
})
export class AppModule {}

// prisma/prisma.service.ts — ไม่ต้องแก้อะไร ยังอ่านจาก process.env เหมือนเดิม
super({
  adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }),
});

ConfigModule.forRoot() อ่าน .env ตอนที่ imports array ถูกประเมิน ซึ่งเกิดก่อน Nest จะสร้าง provider ใด ๆ ดังนั้น constructor ของ PrismaService จึงเห็นค่าเสมอไม่ว่าจะวาง PrismaModule ไว้ก่อนหรือหลัง ส่วน prisma7.config.ts ยังต้องมี import "dotenv/config" ของตัวเองต่อไป เพราะ Prisma CLI ทำงานนอก NestJS

ข้อควรระวังของแพทเทิร์นนี้คือค่าที่ถูกอ่านจาก process.env ตอน import module แทนที่จะอ่านใน constructor เช่น SomeModule.register({ connectionString: process.env.DATABASE_URL }) ที่เขียนตรง ๆ ใน imports array — ES module จะประเมินค่านั้นตอนโหลดไฟล์ ซึ่งเกิดก่อน ConfigModule.forRoot() จะได้ทำงานเสมอ ผลคือได้ undefined แบบงง ๆ ของเราไม่มีปัญหานี้เพราะ PrismaService อ่าน process.env.DATABASE_URL ใน constructor ซึ่งรันใน DI phase หลัง ConfigModule โหลด .env เรียบร้อยแล้ว

เลือกแหล่ง environment ให้เหมาะกับตอนรันแอป

ตอนพัฒนาในเครื่อง ค่า default ที่อ่าน .env มักเพียงพอ แต่บางทีมแยกไฟล์ตาม environment หรือให้ hosting platform ส่งค่าเข้า process.env โดยตรง เราปรับพฤติกรรมนี้ได้จาก options ของ forRoot()

// อ่านจากไฟล์ที่กำหนด โดยไฟล์ด้านหน้ามี priority สูงกว่า
ConfigModule.forRoot({
  envFilePath: ['.env.development.local', '.env.development'],
});

// production ที่ platform inject environment variables ให้แล้ว
ConfigModule.forRoot({
  ignoreEnvFile: true,
});
สถานการณ์Option ที่ใช้ผล
ใช้ไฟล์ .env ที่ rootไม่ต้องเพิ่ม optionConfigModule อ่านไฟล์ให้อัตโนมัติ
ใช้ไฟล์ชื่ออื่นหรือมีหลายไฟล์envFilePathอ่าน path ตามลำดับที่กำหนด
Hosting platform จัดการค่าให้ignoreEnvFile: trueใช้ค่าจาก process.env โดยไม่อ่านไฟล์

envFilePath มีผลกับแอป NestJS เท่านั้น ส่วน Prisma CLI ทำงานนอก Nest ถ้าเปลี่ยนชื่อไฟล์ .env ต้องตั้งค่าใน prisma7.config.ts ให้โหลดชื่อใหม่ด้วย

ส่งมอบหน้าที่โหลด .env ให้ ConfigModule

ติดตั้ง @nestjs/config, ตรวจว่าไฟล์ environment อยู่ใน .gitignore, เพิ่ม ConfigModule.forRoot() ใน AppModule แล้วลบ import 'dotenv/config' ออกจาก main.ts จากนั้นลองเปลี่ยนชื่อไฟล์ชั่วคราวเพื่อทดสอบ envFilePath

npm i @nestjs/config # ลบ import 'dotenv/config' ใน src/main.ts # เพิ่ม ConfigModule.forRoot() ใน AppModule # ตรวจว่า *.env อยู่ใน .gitignore npm run start:dev

ควรได้ผลลัพธ์แบบนี้

แอปยังเชื่อมต่อ PostgreSQL ได้หลังลบ dotenv ออกจาก main.ts และยังเปิดได้เมื่อเปลี่ยนชื่อไฟล์พร้อมตั้ง envFilePath ให้ตรงกัน ส่วน git status ต้องไม่แสดงไฟล์ environment ในรายการที่จะ commit

ลองเช็กให้แน่ใจ

  • GET /coffees ยังตอบข้อมูลจากฐานข้อมูลได้ปกติหลังถอด dotenv ออกจาก main.ts
  • อธิบายได้ว่าเมื่อไรควรใช้ค่า default, envFilePath และ ignoreEnvFile
  • git status ไม่มี .env โผล่ในรายการ untracked/staged
  • รู้ว่า Prisma CLI ต้องตั้งค่าการโหลด env แยกจาก NestJS
