กำหนด Path ของ Environment File เอง

เมื่อจบบทนี้ คุณจะสามารถ

  • ชี้ให้ ConfigModule อ่านไฟล์ environment จากชื่อหรือ path ที่กำหนดเองด้วย envFilePath
  • ปิดการอ่านไฟล์ .env ด้วย ignoreEnvFile เมื่อ platform เป็นผู้จัดการ environment variables ให้
  • เลือก option ที่เหมาะกับสถานการณ์ deploy ของทีมได้

envFilePath: เมื่อไฟล์ไม่ได้ชื่อ .env

ค่า default ของ ConfigModule.forRoot() คือมองหาไฟล์ .env ที่ root directory แต่บางทีมตั้งชื่อไฟล์ต่างออกไป หรือแยกไฟล์ตาม environment การส่ง options object เข้าไปช่วยให้กำหนดได้เอง — ตัวอย่างนี้ให้มองหาไฟล์ชื่อ .environment แทน

ConfigModule.forRoot({
  envFilePath: '.environment',
});

envFilePath รับเป็น array ได้ด้วย เช่น envFilePath: ['.env.development.local', '.env.development'] — เมื่อ key ซ้ำกัน ไฟล์ที่อยู่ก่อนใน array ชนะ

การเปลี่ยนชื่อไฟล์มีผลแค่กับฝั่งแอป NestJS เท่านั้น prisma7.config.ts (บทที่ 22) ยังมี import "dotenv/config" ของตัวเองซึ่งมองหาไฟล์ชื่อ .env ตรง ๆ เสมอ ไม่รู้จัก envFilePath ของ ConfigModule เลย — ถ้าเปลี่ยนเป็น .environment แล้วสั่ง npx prisma <command> แบบเปล่า ๆ (เช่น npx prisma studio) ในภายหลัง จะเจอ Error: datasource.url property is required เพราะ DATABASE_URL ไม่มีใครโหลดให้ ถ้าจะเก็บชื่อไฟล์ใหม่ต่อไปให้แก้ prisma7.config.ts เป็น dotenv.config({ path: '.environment' }) ด้วย

ignoreEnvFile: เมื่อ platform จัดการ environment ให้แล้ว

บริการ hosting อย่าง Heroku หรือ platform อื่น ๆ มักมีหน้า UI สำหรับตั้ง environment variables โดยตรง ค่าเหล่านั้นถูก inject เข้า process.env ตอนรันอยู่แล้ว จึงไม่มีไฟล์ .env ในเครื่อง production เลย กรณีนี้สั่งให้ ConfigModule ข้ามการอ่านไฟล์ไปได้

ConfigModule.forRoot({
  ignoreEnvFile: true,
});
สถานการณ์Option ที่ใช้ผล
ไฟล์ env ชื่อมาตรฐานที่ rootไม่ต้องตั้งอะไรอ่าน .env อัตโนมัติ
ไฟล์ env ชื่อ/ตำแหน่งอื่น หรือหลายไฟล์envFilePathอ่านตาม path ที่ระบุ ตามลำดับความสำคัญ
Platform ตั้งค่าให้ผ่าน UI (เช่น Heroku)ignoreEnvFile: trueใช้เฉพาะ process.env ที่มีอยู่ ไม่แตะไฟล์

ทดลองย้ายไฟล์ env ไปชื่อใหม่

ใน iluvcoffee เปลี่ยนชื่อ .env เป็น .environment แล้วเพิ่ม envFilePath ให้ ConfigModule ยังอ่านค่าได้ เมื่อยืนยันว่าทำงานแล้วจะย้ายกลับเป็น .env ตามเดิมก็ได้

mv .env .environment // app.module.ts ConfigModule.forRoot({ envFilePath: '.environment', }), npm run start:dev

ผลลัพธ์ที่คาดหวัง

แอปยังเชื่อมต่อฐานข้อมูลได้ปกติทั้งที่ไม่มีไฟล์ชื่อ .env แล้ว และถ้าลองลบ option envFilePath ออก แอปจะต่อฐานข้อมูลไม่ได้ เพราะ ConfigModule หาไฟล์ default ไม่เจอ

ตรวจว่าใช้งานได้จริง

  • GET /coffees ตอบข้อมูลได้หลังเปลี่ยนไปใช้ .environment
  • ลบ envFilePath ชั่วคราวแล้ว restart — การเชื่อมต่อฐานข้อมูลล้มเหลว ยืนยันว่า option มีผลจริง
  • .gitignore ยังครอบคลุมชื่อไฟล์ใหม่ (แพทเทิร์น *.env ไม่ครอบ .environment — เพิ่มบรรทัดถ้าจำเป็น)
  • ถ้าทดลอง ignoreEnvFile: true ต้อง export ตัวแปรผ่าน shell เองแล้วแอปจึงต่อฐานข้อมูลได้
