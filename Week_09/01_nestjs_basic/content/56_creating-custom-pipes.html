สร้าง Custom Pipes

เมื่อจบบทนี้ คุณจะสามารถ

  • แยกบทบาทสองด้านของ pipe: transformation (แปลงข้อมูล) และ validation (ตรวจแล้วปล่อยผ่านหรือโยน exception)
  • อธิบายว่า NestJS เรียก pipe เมื่อไรและ pipe เห็นข้อมูลอะไรบ้าง
  • เขียน pipe ของตัวเองด้วย PipeTransform และผูกกับ parameter ที่ต้องการ

Pipe ทำงานกับ arguments ก่อนถึง handler

pipe มี use case หลักสองแบบ: transformation — แปลง input ให้อยู่ในรูปที่ต้องการ (เช่น string จาก URL ให้เป็น number) และ validation — ประเมิน input ถ้าถูกต้องก็ปล่อยผ่านไปตามเดิม ถ้าไม่ถูกต้องให้โยน exception ทั้งสองกรณี pipe ทำงานกับ arguments ที่กำลังจะถูกส่งเข้า route handler: NestJS เรียก pipe ก่อน method ถูก invoke เสมอ pipe ได้รับค่า argument นั้น ทำการแปลงหรือตรวจสอบ ณ จุดนั้น แล้ว handler จึงถูกเรียกด้วย argument ที่ (อาจ) ถูกแปลงแล้ว

เราใช้ pipe ในตัวของ NestJS มาแล้วหลายบท — ValidationPipe ที่ตรวจ DTO ก็คือ pipe ตัวหนึ่ง คราวนี้เราจะเขียนเองบ้าง โดยทำ ParseIntPipe ฉบับของเราเพื่อเข้าใจกลไกข้างใน

nest g pipe common/pipes/parse-int

implement PipeTransform

pipe เป็นคลาสติด @Injectable() ที่ implement PipeTransform — เมธอด transform(value, metadata) รับค่า argument ดิบ (value) กับ ArgumentMetadata ที่บอกว่า argument นี้มาจากไหน (body, query, param) และประกาศ type อะไรไว้ ค่าที่ transform คืนออกไปคือค่าที่ handler จะได้รับจริง

import {
  ArgumentMetadata,
  BadRequestException,
  Injectable,
  PipeTransform,
} from '@nestjs/common';

@Injectable()
export class ParseIntPipe implements PipeTransform {
  transform(value: string, metadata: ArgumentMetadata) {
    const val = parseInt(value, 10);
    if (isNaN(val)) {
      throw new BadRequestException(
        `Validation failed. "${val}" is not an integer.`,
      );
    }
    return val;
  }
}

โค้ดนี้ทำทั้งสองบทบาทในตัวเดียว: แปลง string เป็น integer ด้วย parseInt และ validate ว่าแปลงได้จริง — ถ้าไม่ได้ (เช่นผู้ใช้ส่ง /coffees/abc) ก็โยน BadRequestException ซึ่งกลายเป็น 400 ที่มีข้อความอธิบายชัดเจน

ผูก pipe ระดับ parameter

pipe ผูกได้หลายระดับ (global, controller, method) แต่ระดับที่ตรงจุดที่สุดสำหรับงานนี้คือ parameter level — ระบุใน @Param() ว่า param ตัวนี้ต้องผ่าน pipe ไหน

@Get(':id')
findOne(@Param('id', ParseIntPipe) id: number) {
  return this.coffeesService.findOne('' + id);
}

NestJS มี ParseIntPipe สำเร็จรูปใน @nestjs/common อยู่แล้ว — บทนี้เขียนซ้ำเพื่อเรียนรู้กลไก เวลาใช้งานจริงให้เลือกของ framework ก่อน แล้วเขียน custom pipe เฉพาะเมื่อ logic การแปลง/ตรวจของคุณไม่มีใครทำไว้ให้

บังคับให้ :id ของ coffees เป็น integer เสมอ

สร้าง ParseIntPipe ของตัวเองตามโค้ดด้านบน ผูกกับ param id ใน findOne() ของ CoffeesController แล้วยิงทดสอบทั้งค่าที่แปลงได้และแปลงไม่ได้

nest g pipe common/pipes/parse-int # coffees.controller.ts @Get(':id') findOne(@Param('id', ParseIntPipe) id: number) { ... } # ทดสอบ curl -i http://localhost:3000/coffees/1 curl -i http://localhost:3000/coffees/abc

ผลลัพธ์ที่คาดหวัง

GET /coffees/1 ทำงานเหมือนเดิมโดย handler ได้ id เป็น number จริง ส่วน GET /coffees/abc ถูกตัดก่อนถึง handler ด้วย 400 Bad Request พร้อมข้อความ Validation failed. "NaN" is not an integer.

ตรวจว่าใช้งานได้จริง

  • ยิง id ที่เป็นตัวเลขแล้วได้ข้อมูลกาแฟตามปกติ
  • ยิง id ที่ไม่ใช่ตัวเลขแล้วได้ 400 พร้อมข้อความจาก pipe (และ timestamp จาก filter)
  • ใส่ console.log(typeof id) ชั่วคราวใน handler เพื่อยืนยันว่า type เป็น number ไม่ใช่ string แล้วลบออก
  • ลองสลับไปใช้ ParseIntPipe ของ @nestjs/common แล้วดูว่าพฤติกรรมภายนอกเทียบเท่ากัน
