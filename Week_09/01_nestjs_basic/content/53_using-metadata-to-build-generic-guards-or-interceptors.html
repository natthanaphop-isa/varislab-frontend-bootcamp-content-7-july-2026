ใช้ Metadata สร้าง Guards และ Interceptors แบบ Generic

เมื่อจบบทนี้ คุณจะสามารถ

  • สร้าง custom decorator ที่แนบ metadata ให้ route handler ด้วย SetMetadata
  • อ่าน metadata นั้นใน guard ผ่าน Reflector เพื่อเปลี่ยนพฤติกรรมตาม route
  • ย้าย guard เข้า DI container เพื่อ inject ConfigService แทนการอ่าน process.env ตรง ๆ

ปัญหาจากบทที่แล้ว: guard เหมารวมทุก route

ApiKeyGuard เวอร์ชันแรกบังคับ key กับทุก endpoint รวมถึงหน้า list กาแฟที่ควรเปิดสาธารณะ วิธีแก้ที่สวยคือให้แต่ละ route ประกาศตัวเอง ว่าเป็น public ผ่าน decorator แล้วให้ guard อ่านคำประกาศนั้นตอนตัดสินใจ — กลไกที่ NestJS เตรียมไว้ให้คือ custom metadata: ข้อมูลเสริมที่แนบกับ class หรือ method ด้วย SetMetadata แล้วอ่านกลับด้วย Reflector

สร้าง @Public() decorator

เราไม่เรียก SetMetadata ตรง ๆ ใน controller เพราะ key ที่เป็น string หลุดกระจายทั่วโค้ดได้ง่าย แนวทางที่ดีคือห่อไว้ใน decorator ของตัวเองไฟล์เดียวจบ

import { SetMetadata } from '@nestjs/common';

export const IS_PUBLIC_KEY = 'isPublic';

export const Public = () => SetMetadata(IS_PUBLIC_KEY, true);

จากนั้นติด @Public() ไว้เหนือ handler ที่ต้องการเปิด เช่น findAll() ของ CoffeesController — ตัว decorator แค่ฝัง key isPublic: true ไว้กับ handler นั้น ยังไม่มีผลอะไรจนกว่าจะมีคนอ่าน

อ่าน metadata ใน guard ด้วย Reflector

อัปเกรด ApiKeyGuard ให้ inject สองอย่าง: Reflector สำหรับอ่าน metadata และ ConfigService แทนการแตะ process.env ตรง ๆ

import { CanActivate, ExecutionContext, Injectable } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { Reflector } from '@nestjs/core';
import { Request } from 'express';
import { Observable } from 'rxjs';
import { IS_PUBLIC_KEY } from '../decorators/public.decorator.js';

@Injectable()
export class ApiKeyGuard implements CanActivate {
  constructor(
    private readonly reflector: Reflector,
    private readonly configService: ConfigService,
  ) {}

  canActivate(
    context: ExecutionContext,
  ): boolean | Promise<boolean> | Observable<boolean> {
    const isPublic = this.reflector.get(IS_PUBLIC_KEY, context.getHandler());
    if (isPublic) {
      return true;
    }
    const request = context.switchToHttp().getRequest<Request>();
    const authHeader = request.header('Authorization');
    return authHeader === this.configService.get('API_KEY');
  }
}

หัวใจคือ context.getHandler() — guard รู้ว่า method ไหนกำลังจะถูกเรียก จึงส่งให้ reflector.get() ดึง metadata ของ method นั้นออกมาได้ ถ้าเจอ isPublic ก็ปล่อยผ่านทันที ไม่เจอจึงค่อยตรวจ key ตามปกติ pattern เดียวกันนี้ใช้สร้าง interceptor ที่อ่าน metadata ได้เช่นกัน เช่น decorator กำหนด cache key หรือ role ที่ต้องมี

เพราะตอนนี้ guard ต้อง inject dependency ได้ การ new ApiKeyGuard() ใน main.ts จึงใช้ไม่ได้แล้ว — ให้ลงทะเบียนผ่าน DI ด้วย APP_GUARD token ใน module (เช่น CommonModule) แทน: { provide: APP_GUARD, useClass: ApiKeyGuard } แล้วอย่าลืม import ConfigModule ใน module นั้นด้วย

เปิด GET /coffees ให้สาธารณะ แต่ล็อก route อื่นไว้

สร้าง public.decorator.ts ใน common/decorators อัปเกรด ApiKeyGuard ตามโค้ดด้านบน ย้ายการลงทะเบียนจาก main.ts ไปเป็น APP_GUARD แล้วติด @Public() ที่ findAll()

# coffees.controller.ts @Public() @Get() findAll(@Query() paginationQuery: PaginationQueryDto) { ... } # common.module.ts providers: [{ provide: APP_GUARD, useClass: ApiKeyGuard }] # ทดสอบ curl -i http://localhost:3000/coffees # ควรผ่านโดยไม่มี key curl -i -X POST http://localhost:3000/coffees # ควรได้ 403

ผลลัพธ์ที่คาดหวัง

GET /coffees เข้าถึงได้โดยไม่ต้องแนบ key ส่วน endpoint อื่นทั้งหมด (POST, PATCH, DELETE) ยังต้องมี Authorization header ที่ถูกต้อง และ guard อ่านค่า key ผ่าน ConfigService จากไฟล์ .env เดิม

ตรวจว่าใช้งานได้จริง

  • ยิง GET /coffees โดยไม่มี header — ต้องได้ 200 เพราะติด @Public() แล้ว
  • ยิง POST /coffees โดยไม่มี header — ต้องได้ 403 เพราะ handler นี้ไม่มี metadata
  • ยิง POST /coffees พร้อม key ที่ถูกต้อง — ต้องทำงานปกติ
  • ลองย้าย @Public() ไป handler อื่นแล้วดูว่าพฤติกรรมตามไปทันที โดยไม่ต้องแก้ guard เลย — นี่คือความ generic ที่ metadata มอบให้
  • ตรวจว่าไม่มีการเรียก process.env เหลืออยู่ใน guard
