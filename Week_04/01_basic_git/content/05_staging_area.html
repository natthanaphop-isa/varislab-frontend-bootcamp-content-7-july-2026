บทเรียน 05 · บันทึกประวัติใน Local Repository (Local Repository)

Working Directory, Staging Area และ git add

The Three Areas & git add

เมื่อจบบทนี้ คุณจะสามารถ

  • จำ workflow พื้นฐาน แก้ไฟล์ → git status → git add → git commit
  • อธิบายสามพื้นที่ของ Git: Working Directory, Staging Area และ Local Repository
  • เพิ่มไฟล์ทีละไฟล์หรือทั้งหมดเข้า staging area ด้วย git add
  • อธิบายความหมายของจุดใน git add .

Git Workflow พื้นฐาน

ก่อนลงมือ มาดูภาพรวมของ workflow ที่เราจะใช้ซ้ำไปตลอดชีวิตการเป็น developer:

แก้ไขไฟล์
    ↓
git status
    ↓
git add
    ↓
git commit
    ↓
git push

ช่วงแรกที่เรายังไม่ได้เชื่อมกับ GitHub จะใช้แค่สี่ขั้นแรก:

แก้ไขไฟล์
    ↓
git status
    ↓
git add
    ↓
git commit

สามพื้นที่ของ Git

Git แบ่งการทำงานออกเป็น 3 พื้นที่หลัก ไฟล์จะเดินทางจากพื้นที่หนึ่งไปอีกพื้นที่หนึ่งด้วยคำสั่งต่าง ๆ:

Working Directory
ไฟล์ที่เรากำลังแก้ไข
        ↓ git add

Staging Area
ไฟล์ที่เราเลือกเตรียมไว้
        ↓ git commit

Local Repository
ประวัติที่ถูกบันทึกในเครื่อง
  • Working Directory — ไฟล์จริงที่เราเปิดแก้อยู่ใน VS Code
  • Staging Area — “พื้นที่พักรอ” ของการเปลี่ยนแปลงที่เราเลือกแล้วว่าจะใส่ใน commit ถัดไป
  • Local Repository — ประวัติ commit ที่บันทึกไว้ในโฟลเดอร์ .git ในเครื่องเรา

เปรียบเทียบกับการแพ็กกล่องพัสดุ

Gitการแพ็กกล่องพัสดุ
Working Directoryของทั้งหมดที่อยู่ในห้อง
Staging Areaของที่เลือกใส่กล่อง
Commitการปิดกล่องและเขียนป้ายว่าข้างในมีอะไร

เราไม่จำเป็นต้องยัดของทุกอย่างในห้องลงกล่องเดียวกัน ฉันใดก็ฉันนั้น เราไม่จำเป็นต้องนำทุกไฟล์เข้า commit เดียวกัน staging area ทำให้เราเลือกได้ว่า commit นี้จะมีอะไรบ้าง เพื่อให้แต่ละ commit มีความหมายชัดเจน

เพิ่มไฟล์เข้า Staging Area

ลองเพิ่มทีละไฟล์ก่อน เพื่อให้เห็นว่าเกิดอะไรขึ้น:

git add index.html

ตรวจสอบ:

git status

ผลลัพธ์จะคล้าย:

On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   index.html

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        style.css

ตอนนี้ index.html ย้ายไปอยู่ในส่วน Changes to be committed แล้ว (อยู่ใน staging area) ส่วน style.css ยังอยู่ในส่วน Untracked เพราะเรายังไม่ได้เลือกมัน

เพิ่ม style.css ด้วย:

git add style.css

หรือถ้าต้องการเพิ่มทุกไฟล์ในครั้งเดียว:

git add .

จุดใน git add . หมายถึงอะไร

จุด . หมายถึงโฟลเดอร์ปัจจุบัน (แบบเดียวกับ code . ในบทที่ 03) ดังนั้น git add . จึงแปลว่า “เพิ่มไฟล์ที่เปลี่ยนแปลงทั้งหมดในโฟลเดอร์ปัจจุบันเข้า staging area”

หลังเพิ่มครบ รัน git status อีกครั้ง ควรเห็นทั้งสองไฟล์อยู่ใต้ Changes to be committed:

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   index.html
        new file:   style.css

git add . สะดวกก็จริง แต่มันเพิ่มทุกอย่างที่เปลี่ยน ก่อนใช้ให้รัน git status ดูก่อนเสมอว่ามีไฟล์แปลก ๆ ที่ไม่ได้ตั้งใจจะ commit ติดมาด้วยหรือเปล่า และต้องรันจากโฟลเดอร์ root ของโปรเจกต์

ถ้าแก้ไฟล์หลังจาก git add ไปแล้ว การแก้ครั้งหลังจะยังไม่อยู่ใน staging area ต้อง git add ไฟล์นั้นซ้ำอีกรอบ — นิสัยดีคือรัน git status ก่อน commit ทุกครั้ง

  • อธิบายได้ว่า Working Directory, Staging Area และ Local Repository ต่างกันอย่างไร
  • หลัง git add index.html เห็นไฟล์นั้นย้ายไปอยู่ใต้ Changes to be committed
  • หลัง git add . (หรือ add ครบทั้งสองไฟล์) git status ไม่มี Untracked files เหลือ
ก่อนหน้า: เริ่ม Repository ด้วย git init และ git status สารบัญบทเรียน ถัดไป: สร้าง Commit แรกและเขียน Commit Message ที่ดี
