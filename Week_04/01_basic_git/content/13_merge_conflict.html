บทเรียน 13 · Branch และ Merge (Branch & Merge)

รู้จัก Merge Conflict

Merge Conflict Overview

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายได้ว่า merge conflict เกิดขึ้นเมื่อไร
  • อ่าน conflict marker <<<<<<<, ======= และ >>>>>>> ได้
  • บอกทางเลือกในการแก้ conflict และขั้นตอนหลังแก้เสร็จ

บทนี้เป็นการทำความรู้จักแนวคิดก่อน ยังไม่ต้องฝึกแก้ conflict แบบเต็มรูปแบบ เป้าหมายคือให้รู้ว่า conflict เป็นเรื่องปกติ ไม่ใช่ว่าเราทำอะไรพัง และเมื่อเจอแล้ว Git ต้องการให้มนุษย์เป็นคนตัดสินใจ

Merge Conflict คืออะไร

ในบทที่แล้ว merge ของเราผ่านไปแบบ fast-forward เพราะ main ไม่มีอะไรเปลี่ยน แต่ถ้าทั้งสอง branch แก้บรรทัดเดียวกัน Git จะไม่สามารถตัดสินใจได้ว่าจะใช้โค้ดจากฝั่งใด นี่คือ merge conflict

ตัวอย่าง บน main มีคนแก้ตำแหน่งเป็น:

<p class="role">Frontend Developer</p>

ขณะเดียวกัน บน feature branch feature/update-role แก้บรรทัดเดียวกันเป็น:

<p class="role">Full-Stack Developer</p>

เมื่ออยู่บน main แล้วรัน git merge feature/update-role Git จะแจ้งประมาณนี้:

Auto-merging index.html
CONFLICT (content): Merge conflict in index.html
Automatic merge failed; fix conflicts and then commit the result.

และในไฟล์ index.html ตรงบรรทัดที่ชนกัน Git จะใส่เครื่องหมายไว้แบบนี้:

<<<<<<< HEAD
<p class="role">Frontend Developer</p>
=======
<p class="role">Full-Stack Developer</p>
>>>>>>> feature/update-role

อ่าน Conflict Marker

ส่วนความหมาย
ระหว่าง <<<<<<< HEAD กับ =======โค้ดจาก branch ปัจจุบัน (branch ที่เรายืนอยู่ ในตัวอย่างคือ main)
ระหว่าง ======= กับ >>>>>>> feature/update-roleโค้ดจาก branch ที่กำลัง merge เข้ามา

ผู้พัฒนาต้องตัดสินใจว่าจะ:

  • เลือกเวอร์ชันบน
  • เลือกเวอร์ชันล่าง
  • หรือเขียนเวอร์ชันใหม่ที่รวมทั้งสองฝั่ง

เช่น ถ้าตัดสินใจใช้เวอร์ชันล่าง ให้ลบ marker ทั้งสามบรรทัดและเวอร์ชันบนออก จนเหลือแค่:

<p class="role">Full-Stack Developer</p>

ต้องลบ marker <<<<<<<, ======= และ >>>>>>> ออกให้หมดก่อน commit ถ้าลืมไว้ มันจะถูกบันทึกลงไฟล์จริงและโผล่ขึ้นมาบนหน้าเว็บ

Workflow หลังแก้ Conflict

เมื่อแก้ไฟล์เรียบร้อยและ save แล้ว ให้บอก Git ว่าแก้เสร็จแล้วด้วยการ add:

git add .

จากนั้น commit เพื่อจบการ merge:

git commit -m "Resolve merge conflict"

ระหว่างที่ conflict ยังไม่ถูกแก้ git status จะบอกว่าไฟล์ไหนยังชนกันอยู่ (จะเห็นคำว่า both modified) เมื่อไม่แน่ใจว่าเหลืออะไรต้องทำ ให้กลับไปพึ่ง git status เหมือนเดิม ส่วน VS Code เองก็ไฮไลต์ส่วนที่ conflict และมีปุ่มช่วยเลือกฝั่งให้ด้วย

  • อธิบายได้ว่า conflict เกิดเมื่อสอง branch แก้บรรทัดเดียวกัน จน Git ตัดสินใจเองไม่ได้
  • บอกได้ว่าส่วนไหนของ marker คือโค้ดจาก HEAD และส่วนไหนคือโค้ดจาก branch ที่ merge เข้ามา
  • รู้ว่าหลังแก้เสร็จต้องลบ marker แล้ว git add และ git commit
