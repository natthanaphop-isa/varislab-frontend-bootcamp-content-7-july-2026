บทเรียน 09 · ส่งงานขึ้น GitHub (GitHub & Remote Repository)

เชื่อม Local กับ GitHub และ Push ครั้งแรก

Connect & Push to GitHub

เมื่อจบบทนี้ คุณจะสามารถ

  • เพิ่ม remote ด้วย git remote add origin และตรวจสอบด้วย git remote -v
  • อธิบายได้ว่า origin คืออะไร
  • ตรวจสอบและเปลี่ยนชื่อ branch หลักเป็น main
  • push ครั้งแรกด้วย git push -u origin main และอธิบายแต่ละส่วนของคำสั่งได้

เชื่อม Local กับ GitHub

นำ URL ที่ได้จากบทที่แล้วมาเพิ่มเป็น remote (อย่าลืมเปลี่ยน username เป็นชื่อ GitHub ของคุณ):

git remote add origin https://github.com/username/developer-profile-page.git

คำสั่งนี้ไม่มีผลลัพธ์อะไรแสดงออกมาถ้าสำเร็จ ให้ตรวจสอบด้วย:

git remote -v

ผลลัพธ์ตัวอย่าง:

origin  https://github.com/username/developer-profile-page.git (fetch)
origin  https://github.com/username/developer-profile-page.git (push)

สองบรรทัดนี้บอกว่า remote ชื่อ origin ใช้ URL นี้ทั้งตอนดึงข้อมูล (fetch) และตอนส่งข้อมูล (push)

origin คืออะไร

origin คือชื่อเล่นของ remote repository แทนที่จะต้องพิมพ์ URL ยาว ๆ ทุกครั้ง เราใช้คำว่า origin แทนได้เลย ชื่อนี้ตั้งอะไรก็ได้ แต่โดยธรรมเนียม remote หลักมักตั้งชื่อว่า origin

ถ้าเจอ error: remote origin already exists. แปลว่าเคยเพิ่ม origin ไปแล้ว ให้ตรวจด้วย git remote -v ถ้า URL ผิด ให้แก้ด้วย git remote set-url origin NEW_REPOSITORY_URL (แทน NEW_REPOSITORY_URL ด้วย URL ที่ถูกต้อง)

ตรวจสอบ Branch หลัก

git branch

Git บางเครื่องตั้งชื่อ branch เริ่มต้นเป็น master บางเครื่องเป็น main ส่วน GitHub ใช้ main เป็นค่าเริ่มต้น เพื่อให้ตรงกัน ถ้าเห็น branch ชื่อ master ให้เปลี่ยนเป็น main: 

git branch -M main

ตรวจสอบอีกครั้ง:

git branch
* main

เครื่องหมาย * หมายถึง branch ที่กำลังใช้งานอยู่ (ถ้าเดิมเป็น main อยู่แล้ว จะรัน git branch -M main ซ้ำก็ไม่มีผลเสียอะไร)

Push ครั้งแรก

ส่ง repository ขึ้น GitHub:

git push -u origin main

ถ้าสำเร็จ ท้ายผลลัพธ์จะคล้าย:

To https://github.com/username/developer-profile-page.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.

การ push ครั้งแรกผ่าน HTTPS Git จะขอให้ยืนยันตัวตนกับ GitHub บางเครื่องจะเปิดหน้าต่าง browser ให้ sign in ถ้าถูกถาม password ใน Terminal ให้รู้ไว้ว่า GitHub ไม่รับ password ของบัญชีสำหรับคำสั่ง Git แล้ว ต้องใช้ personal access token แทน ดูรายละเอียดได้ที่ docs.github.com/en/authentication

หลัง push สำเร็จ ให้ refresh หน้า repository บน GitHub ควรเห็น:

  • ไฟล์ index.html, style.css และ README.md
  • เนื้อหาของ README แสดงอยู่ใต้รายการไฟล์
  • จำนวน commit (3 commits) ซึ่งกดเข้าไปดู commit history ได้

อธิบายคำสั่ง git push -u origin main

ส่วนของคำสั่งความหมาย
git pushส่ง commit ขึ้น remote
originชื่อ remote repository ที่จะส่งไป
mainbranch ที่ต้องการส่งขึ้นไป
-uจดจำความสัมพันธ์ระหว่าง main ในเครื่องกับ main บน GitHub

เพราะ -u จำความสัมพันธ์ไว้แล้ว การ push ครั้งต่อ ๆ ไปบน main ใช้แค่:

git push

Workflow ตอนนี้ครบวงจรแล้ว

แก้ไขไฟล์
    ↓
git status
    ↓
git add
    ↓
git commit
    ↓
git push
  • git remote -v แสดง origin พร้อม URL ของ repository คุณ ทั้ง fetch และ push
  • git branch แสดง * main
  • git push -u origin main สำเร็จ
  • หน้า GitHub แสดงไฟล์ครบ 3 ไฟล์และมี commit history
ก่อนหน้า: Local, Remote และการสร้าง Repository บน GitHub สารบัญบทเรียน ถัดไป: Branch คืออะไร และสร้าง Feature Branch
