บทเรียน 14 · แก้ปัญหาและสรุป (Troubleshooting & Wrap Up)

ปัญหาที่พบบ่อยและวิธีแก้

Common Problems

เมื่อจบบทนี้ คุณจะสามารถ

  • จำแนกสาเหตุของ error ที่พบบ่อยจากข้อความของ Git
  • แก้ปัญหาพื้นฐานได้ด้วยตัวเองโดยเริ่มจาก git status
  • หลีกเลี่ยงการ merge ผิดทิศทางและการบังคับลบ branch

บทนี้ใช้เป็น “คู่มือฉุกเฉิน” ได้ตลอด เมื่อเจอข้อความแปลก ๆ ให้เลื่อนหาหัวข้อที่ตรงกัน และจำไว้ว่าจุดเริ่มต้นของการแก้ปัญหาแทบทุกครั้งคือ git status

ปัญหาที่ 1: fatal: not a git repository

สาเหตุ: อยู่ผิดโฟลเดอร์ หรือยังไม่ได้รัน git init

ตรวจสอบตำแหน่งปัจจุบัน:

pwd

ดูไฟล์ในโฟลเดอร์:

# macOS หรือ Linux
ls

# Windows (PowerShell)
dir

เข้าโฟลเดอร์โปรเจกต์ แล้วลองใหม่:

cd developer-profile-page
git status

ปัญหาที่ 2: Author identity unknown

สาเหตุ: ยังไม่ได้ตั้งชื่อและอีเมลให้ Git แก้ด้วย:

git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"

จากนั้น commit ใหม่อีกครั้ง

ปัญหาที่ 3: nothing to commit

nothing to commit, working tree clean

สาเหตุที่เป็นไปได้:

  • ยังไม่ได้แก้ไฟล์
  • แก้แล้วแต่ยังไม่ได้ save
  • การเปลี่ยนแปลงถูก commit ไปแล้ว

ตรวจสอบด้วย git status และดูว่าแท็บใน VS Code ยังมีจุดกลม (ยังไม่ save) หรือไม่

ปัญหาที่ 4: ลืม git add

ถ้ารัน git commit แล้วไม่มีอะไรถูก commit (เช่นเห็น no changes added to commit) ให้ตรวจสอบ:

git status

เพิ่มไฟล์เข้า staging area:

git add .

แล้ว commit:

git commit -m "Update profile page"

ปัญหาที่ 5: remote origin already exists

สาเหตุ: เคยเพิ่ม remote ชื่อ origin ไปแล้ว ตรวจสอบ:

git remote -v

ถ้า URL ผิด ให้เปลี่ยนเป็น URL ที่ถูกต้อง (แทน NEW_REPOSITORY_URL ด้วย URL ของคุณ):

git remote set-url origin NEW_REPOSITORY_URL

ปัญหาที่ 6: สร้างหรือสลับ Branch ขณะที่ยังมีไฟล์ไม่ได้ commit

ก่อนสลับ branch ให้ตรวจสอบเสมอ:

git status

ถ้ายังมีไฟล์ที่แก้ค้างอยู่ ให้ add และ commit งานปัจจุบันให้เรียบร้อยก่อนสร้างหรือสลับ branch เพื่อให้แต่ละ branch แยกงานกันชัดเจน

ปัญหาที่ 7: Merge ผิดทิศทาง

ถ้ายืนอยู่บน feature branch แล้วรัน:

git merge main

คำสั่งนี้จะนำ main เข้า feature branch ไม่ใช่นำ feature เข้า main วิธีที่ต้องการในคู่มือนี้คือ:

git switch main
git merge feature/add-projects-section

คำถามที่ต้องถามตัวเองก่อน merge ทุกครั้ง:

เราต้องการให้งานเข้า Branch ไหน?

ให้ย้ายไป branch ปลายทางก่อน แล้วจึง merge branch ต้นทางเข้ามา

ปัญหาที่ 8: ลบ Branch ไม่ได้

สาเหตุ: ข้อความบอกว่า branch ยังไม่ถูก merge (not fully merged) ให้ merge ก่อน:

git switch main
git merge feature/branch-name

จากนั้นค่อยลบ:

git branch -d feature/branch-name

ยังไม่ควรใช้ git branch -D (ตัว D ใหญ่) เพราะเป็น force delete ที่ลบได้แม้ branch ยังไม่ merge และอาจทำให้งานที่ยังไม่ merge เข้าถึงได้ยาก

นอกจากนี้ ถ้าลืม -m ตอน commit แล้วติดอยู่ในหน้าจอ editor ให้กด Esc พิมพ์ :q! แล้ว Enter และถ้า push แล้วถูกถาม password ให้ดูหมายเหตุเรื่องการยืนยันตัวตนในบทเรียนที่ 09

  • รู้ว่า fatal: not a git repository ให้เช็กด้วย pwd ก่อน
  • รู้ว่า Author identity unknown แก้ด้วย git config --global
  • แยกได้ระหว่าง “ไม่มีอะไรเปลี่ยน” กับ “ลืม git add”
  • รู้วิธีแก้ URL ของ origin ด้วย git remote set-url
  • merge ในทิศทางที่ถูกต้อง และลบ branch ด้วย -d ไม่ใช่ -D
ก่อนหน้า: รู้จัก Merge Conflict สารบัญบทเรียน ถัดไป: สรุปบทเรียน แบบฝึกหัด และการบ้าน
