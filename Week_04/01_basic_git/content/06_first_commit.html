บทเรียน 06 · บันทึกประวัติใน Local Repository (Local Repository)

สร้าง Commit แรกและเขียน Commit Message ที่ดี

Your First Commit

เมื่อจบบทนี้ คุณจะสามารถ

  • สร้าง commit จากไฟล์ใน staging area ด้วย git commit -m
  • แยก commit message ที่ดีออกจาก message ที่ไม่มีประโยชน์ได้
  • ตรวจสอบสถานะหลัง commit และเข้าใจข้อความ working tree clean

สร้าง Commit แรก

จากบทที่แล้ว ไฟล์ index.html และ style.css อยู่ใน staging area เรียบร้อยแล้ว ถึงเวลา “ปิดกล่อง” และติดป้าย:

git commit -m "Create developer profile page"

โครงสร้างของคำสั่งคือ:

git commit -m "ข้อความอธิบายการเปลี่ยนแปลง"

-m ย่อมาจาก message คือข้อความที่อธิบายว่า commit นี้ทำอะไร

ผลลัพธ์จะคล้าย:

[main (root-commit) 8c41a22] Create developer profile page
 2 files changed, 114 insertions(+)
 create mode 100644 index.html
 create mode 100644 style.css
  • main — branch ที่ commit นี้ถูกบันทึก (อาจเป็น master ในบางเครื่อง)
  • root-commit — นี่คือ commit แรกสุดของ repository
  • 8c41a22 — commit ID แบบย่อ ในเครื่องคุณจะเป็นตัวอักษรคนละชุด เพราะ ID แต่ละ commit ไม่ซ้ำกัน
  • ตัวเลขจำนวนบรรทัดที่เพิ่มอาจต่างเล็กน้อยตามการเว้นบรรทัดในไฟล์ของคุณ

ถ้าลืมใส่ -m Git จะเปิด text editor (มักเป็น Vim) ขึ้นมาให้พิมพ์ message ถ้าติดอยู่ในหน้าจอนั้น ให้กด Esc แล้วพิมพ์ :q! ตามด้วย Enter เพื่อออกโดยไม่ commit จากนั้นรันคำสั่งใหม่พร้อม -m

Commit Message ที่ดี

commit message ไม่ได้เขียนให้ Git อ่าน — Git ไม่สนใจเลยว่าข้อความคืออะไร เราเขียนเพื่อให้มนุษย์เข้าใจ ซึ่งอาจเป็นเพื่อนร่วมทีม หรือตัวเราเองในอีกหลายเดือนข้างหน้าที่กลับมาไล่ดูว่าเคยเปลี่ยนอะไรไป message ที่ดีจึงควรอธิบายว่า commit นี้ทำอะไร

ตัวอย่างที่ดีตัวอย่างที่ไม่ดี
Create developer profile pageupdate
Update personal profile informationfix
Improve profile card designtest
Add projects sectiondone
Fix contact button spacingnew / final
Add project documentationasdf / 123

ลองนึกภาพว่าอ่าน history แล้วเจอ final ติดกันห้า commit — ไม่ต่างอะไรกับโฟลเดอร์ developer-profile-final-real ในบทที่ 01 เลย

คำขึ้นต้นที่ใช้บ่อย

ขึ้นต้นด้วยคำกริยาภาษาอังกฤษที่บอกว่าทำอะไร จะช่วยให้ message กระชับและอ่านง่าย:

  • Add — เพิ่มสิ่งใหม่
  • Create — สร้างขึ้นมาใหม่
  • Update — ปรับปรุงข้อมูลที่มีอยู่
  • Fix — แก้ bug หรือจุดผิด
  • Remove — ลบออก
  • Improve — ทำให้ดีขึ้น
  • Change — เปลี่ยนแปลง

ตรวจสอบสถานะหลัง Commit

git status

ถ้าทุกอย่างถูก commit แล้ว จะเห็น:

On branch main
nothing to commit, working tree clean

ความหมายคือ:

  • ไม่มีไฟล์ใหม่ที่ยังไม่ถูกติดตาม
  • ไม่มีไฟล์ที่ถูกแก้แต่ยังไม่ได้ commit
  • ไฟล์ในโปรเจกต์ตรงกับ commit ล่าสุดทุกประการ

ถ้ารัน git commit แล้วได้ Author identity unknown แปลว่ายังไม่ได้ตั้งชื่อ/อีเมล ให้ย้อนไปทำตามบทที่ 02 แล้ว commit ใหม่ และถ้าได้ nothing added to commit แปลว่าลืม git add ก่อน

ลองฝึก

เขียน commit message ที่ดีสำหรับสถานการณ์เหล่านี้ (ยังไม่ต้อง commit จริง แค่คิด):

  1. เปลี่ยนสีปุ่ม Contact Me ให้เข้มขึ้น
  2. แก้คำสะกดผิดในคำอธิบายตัวเอง
  3. เพิ่มรายการทักษะใหม่
  • รัน git commit -m "Create developer profile page" สำเร็จ และเห็น root-commit
  • git status แสดง nothing to commit, working tree clean
  • อธิบายได้ว่าทำไม update หรือ final ไม่ใช่ commit message ที่ดี
