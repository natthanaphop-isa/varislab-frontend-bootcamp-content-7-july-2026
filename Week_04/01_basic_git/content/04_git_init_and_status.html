บทเรียน 04 · บันทึกประวัติใน Local Repository (Local Repository)

เริ่ม Repository ด้วย git init และ git status

git init & git status

เมื่อจบบทนี้ คุณจะสามารถ

  • ตรวจสอบว่า Terminal อยู่ในโฟลเดอร์โปรเจกต์ที่ถูกต้อง
  • สร้าง Git repository ด้วย git init
  • อธิบายว่าโฟลเดอร์ .git เก็บอะไร และทำไมไม่ควรแตะมัน
  • อ่านผลลัพธ์ของ git status และเข้าใจคำว่า untracked

ตรวจสอบว่าอยู่ในโฟลเดอร์โปรเจกต์

ความผิดพลาดที่พบบ่อยที่สุดของมือใหม่คือรันคำสั่ง Git ผิดโฟลเดอร์ ก่อนเริ่มทุกครั้งให้เช็กก่อน เปิด Terminal (ใน VS Code กด Terminal → New Terminal ได้เลย) แล้วรัน: 

pwd

pwd (print working directory) จะแสดง path ของโฟลเดอร์ปัจจุบัน ซึ่งควรลงท้ายด้วย developer-profile-page คำสั่งนี้ใช้ได้ทั้งบน macOS/Linux และ Windows PowerShell

ดูไฟล์ในโฟลเดอร์:

# macOS หรือ Linux
ls

# Windows (PowerShell)
dir

ควรเห็น index.html และ style.css

เริ่ม Git Repository

git init

ผลลัพธ์ตัวอย่าง:

Initialized empty Git repository in /Users/you/developer-profile-page/.git/

ตอนนี้โฟลเดอร์ธรรมดาของเรากลายเป็น Git repository แล้ว คำว่า empty หมายถึงยังไม่มี commit ใด ๆ — ไฟล์ของเรายังอยู่ครบ แค่ Git ยังไม่ได้บันทึกอะไรเลย

Git บางเวอร์ชันอาจแสดงข้อความ hint: ยาว ๆ เกี่ยวกับชื่อ branch เริ่มต้น (master) เพิ่มมาด้วย ไม่ต้องตกใจ ไม่ใช่ error เราจะจัดการชื่อ branch ให้เป็น main ในบทเรียนที่ 09

โฟลเดอร์ .git

เมื่อรัน git init Git จะสร้างโฟลเดอร์พิเศษชื่อ .git ไว้ในโปรเจกต์ โฟลเดอร์นี้ใช้เก็บ:

  • commit history
  • branch
  • การตั้งค่าของ repository
  • ข้อมูล remote repository (เช่น GitHub)
  • สถานะภายในของ Git

ชื่อที่ขึ้นต้นด้วยจุดทำให้มันเป็นโฟลเดอร์ซ่อน คำสั่ง ls ธรรมดาจึงไม่แสดง ถ้าอยากเห็นให้ใช้ ls -a (macOS/Linux) หรือ dir -Force (PowerShell) 

developer-profile-page/
├── .git/        ← สมองของ Git (ห้ามแก้เอง)
├── index.html
└── style.css

Git จำประวัติทั้งหมดได้ก็เพราะมีโฟลเดอร์ .git นี่เอง

ไม่ควรแก้ไขไฟล์ใน .git ด้วยตัวเอง และห้ามลบทิ้ง ถ้าลบ .git ออก โค้ดของเรายังอยู่ แต่ commit history และ branch ทั้งหมดจะหายไป

ตรวจสอบสถานะด้วย git status

git status

ผลลัพธ์จะคล้ายแบบนี้:

On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        index.html
        style.css

nothing added to commit but untracked files present (use "git add" to track)

บรรทัดแรกอาจเป็น On branch master ก็ได้ ขึ้นกับการตั้งค่าของ Git ในเครื่อง ส่วนที่สำคัญคือคำว่า Untracked ซึ่งหมายถึง:

มีไฟล์อยู่ใน Project
แต่ Git ยังไม่ได้เริ่มติดตามไฟล์นั้น

Git มองเห็นไฟล์ของเราแล้ว แต่ยังไม่ได้ “รับเข้าระบบ” — บทถัดไปเราจะบอก Git ว่าอยากให้ติดตามไฟล์ไหน

คำสั่งที่ควรใช้เมื่อสับสน

ใช้ Git แล้วไม่แน่ใจว่าตอนนี้เกิดอะไรขึ้น? ให้เริ่มจาก git status เสมอ คำสั่งนี้บอกว่าเราอยู่ branch ไหน มีไฟล์อะไรเปลี่ยน และมีไฟล์อะไรพร้อม commit แล้ว ที่สำคัญคือมันปลอดภัย เพราะใช้ดูข้อมูลอย่างเดียว ไม่แก้ไขไฟล์ใด ๆ รันกี่ครั้งก็ได้

ถ้าเจอ fatal: not a git repository (or any of the parent directories): .git แปลว่าคุณอยู่ผิดโฟลเดอร์ หรือยังไม่ได้รัน git init ให้ใช้ pwd เช็กตำแหน่ง แล้ว cd developer-profile-page ก่อนลองใหม่

  • pwd แสดง path ที่ลงท้ายด้วย developer-profile-page
  • รัน git init แล้วเห็น Initialized empty Git repository
  • ls -a (หรือ dir -Force) มองเห็นโฟลเดอร์ .git
  • git status แสดง index.html และ style.css อยู่ใต้ Untracked files
ก่อนหน้า: สร้าง Developer Profile Page สารบัญบทเรียน ถัดไป: Working Directory, Staging Area และ git add
