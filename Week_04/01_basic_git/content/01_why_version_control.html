บทเรียน 01 · รู้จัก Git และเตรียมเครื่อง (Getting Started)

ทำไมต้องใช้ Git และ Git ต่างจาก GitHub อย่างไร

Why Version Control

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายปัญหาของการเก็บหลายเวอร์ชันด้วยการ copy โฟลเดอร์
  • อธิบายได้ว่า Git คืออะไร และ commit คืออะไร
  • แยกความแตกต่างระหว่าง Git กับ GitHub ได้
  • รู้ว่าตลอดคู่มือนี้เราจะสร้างอะไร และหัวข้อไหนยังไม่ได้เรียน

สิ่งที่เราจะสร้างในคู่มือนี้

ตลอดคู่มือเราจะใช้โปรเจกต์เล็ก ๆ ชื่อ Developer Profile Page เป็นสนามฝึก Git โปรเจกต์นี้มีแค่ HTML และ CSS ไม่มี npm, Vite, JavaScript, TypeScript, framework, package หรือ build tool ใด ๆ เพราะเราอยากให้สมาธิทั้งหมดอยู่ที่ Git ไม่ต้องเสียเวลาแก้ปัญหา setup หรือ dependency 

developer-profile-page/
├── index.html
├── style.css
└── README.md

เส้นทางการเรียนทั้งหมดจะเป็นแบบนี้:

สร้าง Project
    ↓
เริ่ม Git Repository
    ↓
บันทึก Commit
    ↓
ส่งขึ้น GitHub
    ↓
สร้าง Feature Branch
    ↓
พัฒนา Feature แยกจาก main
    ↓
Merge กลับเข้า main

ปัญหาก่อนมี Git

สมมติว่าเรากำลังสร้างเว็บไซต์ และเก็บแต่ละเวอร์ชันด้วยการ copy โฟลเดอร์ไปเรื่อย ๆ:

developer-profile
developer-profile-new
developer-profile-final
developer-profile-final-2
developer-profile-final-real
developer-profile-final-use-this

คุ้น ๆ ไหม? พอเวลาผ่านไปเราจะเริ่มเจอปัญหา:

  • ไม่รู้ว่าโฟลเดอร์ไหนใหม่ที่สุด
  • ไม่รู้ว่าแต่ละโฟลเดอร์ต่างกันตรงไหน
  • ไม่รู้ว่าแก้โค้ดไปตอนไหน
  • ย้อนกลับไปเวอร์ชันก่อนหน้าได้ยาก
  • เผลอแก้ผิดโฟลเดอร์ หรือส่งโฟลเดอร์ผิดให้เพื่อน
  • ยิ่งทำงานหลายคน ยิ่งสับสน

Git ถูกสร้างขึ้นมาเพื่อแก้ปัญหานี้โดยตรง

Git คืออะไร

Git คือระบบที่ใช้ติดตามและบันทึกประวัติการเปลี่ยนแปลงของไฟล์ จัดอยู่ในประเภท Version Control System Git ช่วยให้เรารู้ว่า:

  • ไฟล์ไหนถูกแก้ และแก้ส่วนใด
  • แก้เมื่อไร และใครเป็นคนแก้
  • เปลี่ยนแปลงไปเพื่ออะไร
  • โปรเจกต์เคยมีหน้าตาอย่างไรในอดีต

Git เปรียบเหมือน Save Point ในเกม

เวลาเขียนโปรแกรม เราไม่ได้เขียนทุกอย่างเสร็จในครั้งเดียว เราค่อย ๆ เพิ่มหน้า เพิ่มปุ่ม ปรับดีไซน์ และแก้ bug Git ช่วยให้เราบันทึกความคืบหน้าเป็นช่วง ๆ เหมือน save point ในเกม: 

เริ่มสร้าง Project
        ↓
Save Point 1: สร้างหน้า HTML
        ↓
Save Point 2: เพิ่มข้อมูลส่วนตัว
        ↓
Save Point 3: เพิ่ม CSS
        ↓
Save Point 4: เพิ่ม Feature

ใน Git เราเรียก save point แต่ละจุดว่า commit — commit คือจุดบันทึกการเปลี่ยนแปลงของโปรเจกต์ ณ ช่วงเวลาหนึ่ง ถ้าวันหนึ่งเราแก้โค้ดแล้วพัง เราสามารถย้อนกลับมาดูได้ว่าก่อนหน้านี้เราเปลี่ยนอะไรไปบ้าง

Git กับ GitHub ต่างกันอย่างไร

หลายคนเข้าใจผิดว่า Git กับ GitHub คือสิ่งเดียวกัน แต่จริง ๆ แล้วไม่ใช่:

GitGitHub
เป็นโปรแกรมที่ทำงานในเครื่องเป็นบริการออนไลน์
ใช้บันทึกประวัติของโปรเจกต์ใช้เก็บและแชร์ repository
ใช้งาน offline ได้ต้องใช้อินเทอร์เน็ตในการส่งข้อมูล
มีคำสั่ง เช่น add และ commitมีหน้า repository และ commit history
ประวัติอยู่ในเครื่องประวัติถูกเก็บออนไลน์
ไม่จำเป็นต้องมี accountต้องมี GitHub account

ประโยคที่ควรจำให้ขึ้นใจ:

Git    = ระบบบันทึกประวัติของ Project
GitHub = เว็บไซต์สำหรับเก็บและแชร์ Git Repository

Git ทำงานอยู่ในเครื่องของเรา ถึงไม่มีอินเทอร์เน็ตก็ยังสร้าง commit ได้ ส่วน GitHub เป็นบริการออนไลน์ที่เราใช้ส่ง repository ขึ้นไปเก็บ สำรอง และแชร์กับคนอื่น เราใช้ Git โดยไม่ใช้ GitHub ได้ แต่ในการทำงานจริงเรามักใช้ทั้งสองอย่างคู่กัน

สิ่งที่ยังไม่เรียนในคู่มือนี้

คู่มือนี้ตั้งใจเน้นพื้นฐาน จึงยังไม่ลงลึกเรื่อง Pull Request, การทำงานเป็นทีม, remote feature branch, แบบฝึกหัดแก้ merge conflict แบบเต็ม, rebase, cherry-pick, stash, reset, revert, squash commit, Git Flow และ GitHub Actions — หัวข้อเหล่านี้จะได้เจอภายหลังเมื่อเริ่มทำ React project หรือทำงานร่วมกับคนอื่น

อย่าพยายามท่องคำสั่งทั้งหมดตั้งแต่ตอนนี้ ให้จับภาพรวมให้ได้ก่อนว่า “Git บันทึกประวัติในเครื่อง / GitHub เก็บประวัตินั้นไว้ออนไลน์” คำสั่งจะจำได้เองเมื่อได้ใช้ซ้ำ ๆ

  • อธิบายได้ว่าการ copy โฟลเดอร์เพื่อเก็บเวอร์ชันมีปัญหาอะไร
  • อธิบายได้ว่า Git คือ Version Control System ที่บันทึกประวัติการเปลี่ยนแปลงของไฟล์
  • อธิบายได้ว่า commit คือ “save point” ของโปรเจกต์
  • บอกความต่างระหว่าง Git (โปรแกรมในเครื่อง) กับ GitHub (บริการออนไลน์) ได้
สารบัญบทเรียน ถัดไป: ตรวจสอบการติดตั้งและตั้งค่า Git
