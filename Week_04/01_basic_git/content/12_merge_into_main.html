บทเรียน 12 · Branch และ Merge (Branch & Merge)

Merge Feature กลับเข้า main

Merge into Main

เมื่อจบบทนี้ คุณจะสามารถ

  • merge feature branch เข้า main ในทิศทางที่ถูกต้อง
  • อธิบายความหมายของ fast-forward merge
  • push งานหลัง merge ขึ้น GitHub
  • ลบ branch ที่ merge แล้วอย่างปลอดภัยด้วย git branch -d
  • ทำ feature branch workflow ครบวงจรได้

ตรวจสอบก่อน Merge

ก่อน merge ต้องแน่ใจว่าเรายืนอยู่บน main:

git branch

ควรเห็น:

  feature/add-projects-section
* main

ถ้า * ยังอยู่หน้า feature branch ให้รัน git switch main ก่อน

Merge Feature กลับเข้า main

git merge feature/add-projects-section

Mental model ของคำสั่งนี้:

เราอยู่ที่ main
        ↓
นำงานจาก feature/add-projects-section
        ↓
เข้ามารวมใน main

ผลลัพธ์จะคล้าย (commit ID และตัวเลขในเครื่องคุณอาจต่างออกไป):

Updating f18ad55..7f2a1b3
Fast-forward
 index.html | 9 +++++++++
 1 file changed, 9 insertions(+)

refresh หน้าเว็บ — Projects Section กลับมาแล้ว เพราะตอนนี้ feature ถูก merge เข้า main เรียบร้อย

merge ผิดทิศทาง เป็นความผิดพลาดที่พบบ่อย ถ้าเรายืนอยู่บน feature branch แล้วรัน git merge main จะเป็นการนำ main เข้า feature branch ไม่ใช่นำ feature เข้า main ก่อน merge ให้ถามตัวเองว่า “ต้องการให้งานเข้า branch ไหน?” แล้วย้ายไปbranch ปลายทางก่อน จากนั้นจึง merge branch ต้นทางเข้ามา

Fast-forward Merge คืออะไร

คำว่า Fast-forward ในผลลัพธ์หมายความว่า หลังจากสร้าง feature branch แล้ว ไม่มี commit ใหม่เกิดขึ้นบน main Git จึงไม่ต้องผสมอะไรเลย แค่เลื่อนป้าย main ไปชี้ที่ commit ล่าสุดของ feature branch ได้ทันที 

ก่อน Merge

A ← B ← C ← D
        ↑   ↑
     main   feature/add-projects-section
หลัง Merge (fast-forward)

A ← B ← C ← D
            ↑
          main
          feature/add-projects-section

ในที่นี้ A, B, C คือ 3 commit แรก และ D คือ Add projects section ถ้าลองรัน git log --oneline --graph --all ตอนนี้จะเห็นว่า main กับ feature branch ชี้ที่ commit เดียวกันแล้ว

สำหรับผู้เริ่มต้น ยังไม่ต้องจำรายละเอียดของ merge strategy แบบอื่น ๆ แค่เข้าใจว่า feature ถูกนำเข้ามาใน main สำเร็จแล้วก็พอ

Push หลัง Merge

ตอนนี้ main ในเครื่องมี feature ใหม่แล้ว แต่ GitHub ยังไม่มี ส่งขึ้นไป:

git push

ใช้แค่ git push ได้เลย เพราะเราตั้ง -u ไว้ตอน push ครั้งแรกแล้ว จากนั้น refresh หน้า GitHub แล้วตรวจสอบ:

  • index.html บน GitHub มี Projects Section
  • commit Add projects section ปรากฏใน commit history
  • branch หลัก (main) บน GitHub มีโค้ดล่าสุด

ลบ Branch ที่ Merge แล้ว

หลังจาก feature ถูก merge แล้ว เราไม่ต้องใช้ feature branch อีก ลบ local branch ได้ด้วย:

git branch -d feature/add-projects-section
Deleted branch feature/add-projects-section (was 7f2a1b3).

ตรวจสอบ:

git branch

ควรเหลือ:

* main

การลบ branch ไม่ได้ลบโค้ดที่ merge เข้า main แล้ว branch เป็นเหมือนป้ายที่ชี้ไปยังเส้นทางการพัฒนา เมื่องานถูกนำเข้า main เรียบร้อย commit เหล่านั้นก็อยู่ใน main แล้ว เราจึงลบป้ายที่ไม่ใช้งานทิ้งได้ — refresh หน้าเว็บดู Projects Section ยังอยู่ครบ

ถ้า git branch -d ปฏิเสธและบอกว่า branch ยังไม่ถูก merge (not fully merged) แปลว่างานบน branch นั้นยังไม่อยู่ใน main ให้ git switch main แล้ว git merge branch นั้นก่อน จากนั้นค่อยลบ อย่าเพิ่งใช้ git branch -D (ตัว D ใหญ่) เพราะเป็นการบังคับลบ (force delete) ซึ่งอาจทำให้งานที่ยังไม่ merge เข้าถึงได้ยาก

Workflow ของ Feature Branch

นี่คือชุดคำสั่งที่เราจะใช้ซ้ำกับทุก feature (แทน feature-name ด้วยชื่อ feature จริง):

# 1. สร้างและย้ายไป feature branch
git switch -c feature/feature-name

# 2. แก้ไขโค้ด แล้ว commit
git status
git add .
git commit -m "Add new feature"

# 3. กลับ main
git switch main

# 4. merge feature เข้า main
git merge feature/feature-name

# 5. push ขึ้น GitHub
git push

# 6. ลบ branch ที่ merge แล้ว
git branch -d feature/feature-name
  • git merge feature/add-projects-section บน main สำเร็จ และเห็นคำว่า Fast-forward
  • หน้าเว็บบน main มี Projects Section
  • git push สำเร็จ และ GitHub มี commit Add projects section
  • git branch เหลือแค่ * main
  • อธิบายได้ว่าทำไมต้อง switch ไป branch ปลายทางก่อน merge
ก่อนหน้า: พัฒนา Feature บน Branch แยก สารบัญบทเรียน ถัดไป: รู้จัก Merge Conflict
