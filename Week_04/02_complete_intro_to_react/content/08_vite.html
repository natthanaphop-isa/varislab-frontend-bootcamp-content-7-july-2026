Vite และ TypeScript

Vite

Vite

build tool ที่เราจะใช้วันนี้ชื่อ Vite Vite (ออกเสียงว่า “veet” แปลว่าเร็วในภาษาฝรั่งเศส) เป็นเครื่องมือจากทีม Vue ที่ท้ายที่สุดห่อ Rollup ซึ่งเป็นตัวทำ bundling จริง ผลลัพธ์สุดท้ายคือเครื่องมือที่ทั้งใช้ง่ายและสร้างผลลัพธ์ที่ยอดเยี่ยม

เรื่องน่าสนใจ: มีโปรเจกต์ใหม่ชื่อ Rolldown กำลังพัฒนาอยู่ ซึ่งเขียนด้วย Rust และตั้งเป้าจะแทนที่ Rollup

ผลลัพธ์สุดท้ายที่เราต้องการจาก build tool คือ

  • เราสามารถแยกไฟล์เพื่อจัดระเบียบโค้ด และมีเครื่องมือเย็บมันเข้าด้วยกันให้เรา
  • เราสามารถรวม external, third-party libraries จาก npm (อย่าง React!)
  • เครื่องมือจะ optimize โค้ดให้เราด้วยการ minify และเทคนิค optimization อื่น ๆ

Parcel เป็นอีกตัวเลือกที่ดีมากและตั้งค่าง่ายพอ ๆ กัน แนะนำให้ลองดูถ้ามีโอกาส คอร์สนี้เลือก Vite เพราะชุมชน React ใช้มันเป็นมาตรฐานในขณะนี้ และเราตั้งใจให้คุณได้เรียนรู้บรรทัดฐานของชุมชน React ส่วน Webpack คือรุ่นก่อนหน้าที่ยังเจอได้บ่อยในโปรเจกต์เก่า

ก่อนอื่น มาติดตั้งสิ่งที่เราต้องใช้สำหรับ Vite

npm install -D vite@^8.1.1 @vitejs/plugin-react@^5.0.0

ตัวแรกคือตัวเครื่องมือ และตัวหลังคือความสามารถเฉพาะ React ทั้งหมดที่เราต้องใช้

เพิ่ม TypeScript

ตั้งแต่บทนี้เป็นต้นไป เราจะเขียนแอปด้วย TypeScript ไม่ใช่ JavaScript ล้วนอีกต่อไป คุณได้เรียนพื้นฐาน TypeScript ไปแล้วในคอร์ส TypeScript พื้นฐาน — type annotation, union type, type alias, tsconfig.json — บทเรียนจากนี้ไปจะเป็นการเอาความรู้ชุดนั้นมาใช้กับของจริง

ทำไมต้องรอถึงตอนนี้? เพราะ TypeScript ต้องมีขั้นตอน build ถึงจะทำงานได้ เบราว์เซอร์ไม่เข้าใจ type annotation เมื่อกี้เรายังไม่มี build tool จึงเขียน TypeScript ไม่ได้ พอมี Vite แล้วเราถึงเริ่มได้ (Vite ตัด type ทิ้งตอน build ให้เราอัตโนมัติ)

แล้วทำไมต้องใช้ TypeScript กับ React? สามเหตุผลที่คุณจะสัมผัสได้เองในบทถัด ๆ ไป

  • props ของ component จะมีสัญญาที่ชัดเจน — ส่ง prop ผิดชื่อ ผิดชนิด หรือลืมส่ง จะรู้ทันทีตอนพิมพ์ ไม่ใช่ตอนเปิดเบราว์เซอร์แล้วเจอหน้าขาว
  • ข้อมูลจาก API จะไม่ลอยเป็น any — เราจะประกาศรูปร่างของข้อมูลพิซซ่าไว้ที่เดียว แล้วทุกที่ที่ใช้มันจะได้ auto-complete และการตรวจสอบตามมา
  • editor จะช่วยคุณมากขึ้นมาก — auto-complete ชื่อ prop, ชื่อ field, ชื่อ event ได้แม่นยำ เพราะมันรู้ type จริง ๆ ไม่ได้เดา

ติดตั้งสามตัวนี้

npm install -D typescript@~6.0.2 @types/react@^19.2.0 @types/react-dom@^19.2.0
  • typescript คือตัว compiler เราจะใช้มันเป็น ตัวตรวจ type เป็นหลัก ส่วนการแปลงโค้ดจริงเป็นหน้าที่ของ Vite
  • @types/react และ @types/react-dom คือไฟล์ type ของ React ตัว React เองเขียนด้วย JavaScript จึงต้องมี package แยกมาบอก TypeScript ว่า useState, createRoot ฯลฯ รับอะไรและคืนอะไร ธรรมเนียม @types/ชื่อแพ็กเกจ นี้ใช้กับ library เก่า ๆ อีกหลายตัว ส่วน library สมัยใหม่มักแถม type มาในตัวเลย

ตอนนี้สร้างไฟล์ tsconfig.json ที่ root ของโปรเจกต์

{
  "compilerOptions": {
    "target": "ES2023",
    "lib": ["ES2023", "DOM", "DOM.Iterable"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "moduleDetection": "force",
    "types": ["vite/client"],

    /* React */
    "jsx": "react-jsx",

    /* เราให้ Vite เป็นคนแปลงโค้ด tsc มีหน้าที่ตรวจ type อย่างเดียว */
    "noEmit": true,
    "isolatedModules": true,
    "verbatimModuleSyntax": true,
    "skipLibCheck": true,

    "strict": true
  },
  "include": ["src", "*.ts"]
}

อธิบายเฉพาะบรรทัดที่สำคัญ

  • "jsx": "react-jsx" บอก TypeScript ว่าไฟล์นี้มี JSX อยู่ และให้ใช้ JSX transform แบบใหม่ (แบบที่ไม่ต้อง import React) บทหน้าเราจะได้ใช้ JSX จริง
  • "noEmit": true คือหัวใจของการทำงานร่วมกับ Vite เราไม่ให้ tsc สร้างไฟล์ .js ออกมาเลย เพราะ Vite แปลงโค้ดให้อยู่แล้ว tsc จึงเหลือหน้าที่เดียวคือตรวจ type แล้วรายงาน error
  • "strict": true เปิดการตรวจสอบชุดเข้มทั้งหมด รวมถึง strictNullChecks ที่จะบังคับให้เราจัดการกรณี null / undefined เอง อาจรู้สึกจู้จี้ในตอนแรก แต่มันคือส่วนที่ให้ประโยชน์มากที่สุด และเดี๋ยวคุณจะได้เจอตัวอย่างแรกในอีกไม่กี่บรรทัดข้างล่างนี้
  • "types": ["vite/client"] ดึง type ของ Vite เข้ามา ทำให้เรื่องอย่าง import.meta.env และการ import ไฟล์ .css / .webp มี type ถูกต้อง
  • "verbatimModuleSyntax": true บังคับให้เวลา import สิ่งที่เป็น type ล้วน ๆ ต้องเขียน import type ให้ชัดเจน เช่น import type { Pizza } from "./types" ข้อดีคืออ่านแล้วรู้ทันทีว่า import ไหนหายไปตอน build จริง เราจะได้ใช้ตั้งแต่บทที่ 13 เป็นต้นไป
  • "include" บอกว่าให้ตรวจไฟล์ในโฟลเดอร์ src และไฟล์ .ts ที่ root (ซึ่งก็คือ vite.config.ts ที่เรากำลังจะสร้าง)

💡 ถ้าเคยรัน npm create vite@latest แล้วเลือก template react-ts คุณจะเห็นว่ามันแตก tsconfig ออกเป็นสามไฟล์ (tsconfig.json, tsconfig.app.json, tsconfig.node.json) นั่นเป็นการแยก config ของโค้ดฝั่งเบราว์เซอร์กับฝั่ง Node ออกจากกัน ซึ่งดีในโปรเจกต์ใหญ่ แต่ในคอร์สนี้เราใช้ไฟล์เดียวเพื่อให้เห็นภาพรวมง่ายกว่า

เมื่อติดตั้งแล้ว เราต้องแก้ index.html เล็กน้อย

<!-- delete the two unpkg script lines -->
<script type="module" src="./src/App.tsx"></script>

เราต้องเพิ่ม module ให้ script tag เพื่อให้เบราว์เซอร์รู้ว่ากำลังทำงานกับเทคโนโลยีเบราว์เซอร์สมัยใหม่ ที่อนุญาตให้ใช้ modules ได้โดยตรงใน development mode แทนที่จะต้อง reload ทั้ง bundle ทุกครั้ง เบราว์เซอร์ของคุณ reload เฉพาะ JS ที่เปลี่ยนได้ มันทำให้เบราว์เซอร์ไล่ dependency graph ด้วยตัวเองได้ ซึ่งหมายความว่า Vite ทำงานใน dev mode ได้เร็วมาก มันยังคง package ทุกอย่างสำหรับ production เพื่อให้เรารองรับเบราว์เซอร์ได้หลากหลาย

สังเกตว่าเราชี้ไปที่ .tsx ไม่ใช่ .ts กฎง่าย ๆ คือ ไฟล์ไหนมี JSX อยู่ข้างในให้ใช้ .tsx ไฟล์ไหนเป็น TypeScript ล้วน (เช่น ไฟล์เก็บ type หรือฟังก์ชันเรียก API) ให้ใช้ .ts เทียบกับตอนเขียน JavaScript ก็คือคู่ของ .jsx กับ .js นั่นเอง

ต่อไปมาสร้าง config file สร้างไฟล์ชื่อ vite.config.ts ใน root ของโปรเจกต์ แล้วใส่สิ่งนี้ลงไป:

import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
});

สังเกตว่าไฟล์ config เองก็เป็น .ts ได้ ประโยชน์ที่ได้ทันทีคือ defineConfig จะคอย auto-complete ชื่อ option ทั้งหมดให้ และเตือนทันทีถ้าคุณพิมพ์ชื่อ option ผิด — เป็นเรื่องที่เกิดขึ้นบ่อยมากกับไฟล์ config

โดยค่าเริ่มต้น Vite จะมองหาไฟล์ index.html ใน root directory และถือว่ามันเป็นหัวของ source graph มันจะไล่ HTML, CSS และ JavaScript ทั้งหมดที่คุณ link จากตรงนั้น แล้วสร้างโปรเจกต์ให้คุณ เราไม่ต้องตั้งค่าอะไรเพิ่ม Vite จะดูแลส่วนที่เหลือเอง

โอเค มา install React เข้าโปรเจกต์ของเราจริง ๆ กัน

npm install react@^19.2.0 react-dom@^19.2.0
  • เราไม่ได้ใส่ -D เพราะ React ไม่ใช่ development tool แต่เป็น production dependency
  • React และ ReactDOM ใช้ version ร่วมกัน ดังนั้นคุณถือว่า versions จะเหมือนกันเสมอได้ และเลข version ของ @types/react ก็ควรอยู่ในรุ่นเดียวกันด้วย

สุดท้าย เปลี่ยนชื่อไฟล์ App.js เป็น App.tsx โค้ดของ Pizza และ App ที่เขียนไว้ก่อนหน้านี้ยังต้องอยู่ครบ จากนั้นเพิ่ม import, ใส่ type ให้ props และเปลี่ยนการเรียก ReactDOM.createRoot เป็น createRoot ดังนี้

import React from "react";
import { createRoot } from "react-dom/client";

type PizzaProps = {
  name: string;
  description: string;
};

const Pizza = (props: PizzaProps) => {
  return React.createElement("div", {}, [
    React.createElement("h1", {}, props.name),
    React.createElement("p", {}, props.description),
  ]);
};

const App = () => {
  return React.createElement("div", {}, [
    React.createElement("h1", {}, "Pixel Perfect Pizzas"),
    React.createElement(Pizza, {
      name: "The Pepperoni Pizza",
      description: "Mozzarella Cheese, Pepperoni",
    }),
    React.createElement(Pizza, {
      name: "The Hawaiian Pizza",
      description: "Sliced Ham, Pineapple, Mozzarella Cheese",
    }),
    React.createElement(Pizza, {
      name: "The Big Meat Pizza",
      description: "Bacon, Pepperoni, Italian Sausage, Chorizo Sausage",
    }),
  ]);
};

const container = document.getElementById("root");
const root = createRoot(container);
root.render(React.createElement(App));

หมายเหตุผู้แปล: พอหน้านี้รันได้ คุณจะเห็นคำเตือน Each child in a list should have a unique "key" prop. ใน console เหมือนที่เจอในบทที่ 3 · สาเหตุเดิมคือเราส่ง child เป็น array เข้า createElement และมันยังไม่ใช่ความผิดพลาด ที่ต้องแก้ตอนนี้ · บทหน้าเราจะเปลี่ยนไปเขียน JSX แล้วคำเตือนนี้จะหายไปเอง

บันทึกไฟล์แล้วคุณจะเจอ error แรกจาก TypeScript ทันที ตรงบรรทัด createRoot(container)

Argument of type 'HTMLElement | null' is not assignable to parameter of type 'Container'.
  Type 'null' is not assignable to type 'Container'.

นี่คือ strictNullChecks กำลังทำงาน และมันพูดถูก: document.getElementById() อาจคืน null ได้ ถ้าในหน้าไม่มี element ที่ id ตรงนั้น TypeScript จึงไม่ยอมให้เราส่งมันเข้า createRoot ตรง ๆ วิธีจัดการมีสองแบบ เลือกแบบไหนก็ได้

// แบบที่ 1 — เช็คก่อนใช้ ปลอดภัยที่สุด และได้ error message ที่อ่านรู้เรื่องถ้ามันเกิดขึ้นจริง
const container = document.getElementById("root");
if (!container) {
  throw new Error("ไม่พบ element ที่มี id=\"root\" ใน index.html");
}
const root = createRoot(container);

// แบบที่ 2 — non-null assertion บอก TypeScript ว่า "เชื่อฉัน ตรงนี้ไม่มีทางเป็น null"
const container = document.getElementById("root")!;
const root = createRoot(container);

คอร์สนี้จะใช้ แบบที่ 1 เพราะมันซื่อสัตย์กว่า เครื่องหมาย ! ในแบบที่ 2 คือการปิดปาก TypeScript ไม่ใช่การแก้ปัญหา ถ้าวันหนึ่งมีคนลบ <div id="root"> ออกจาก index.html แบบที่ 1 จะบอกคุณตรง ๆ ว่าเกิดอะไรขึ้น ส่วนแบบที่ 2 จะพังด้วย error ที่งงกว่ามาก

💡 นี่คือตัวอย่างแรกของสิ่งที่จะเกิดซ้ำตลอดคอร์สนี้ — TypeScript ไม่ได้แค่ "บ่น" แต่มันชี้ไปที่กรณีที่โค้ดของเราจัดการไม่ครบจริง ๆ เวลาเจอ error แบบนี้ ให้อ่านมันเป็นคำถามว่า "แล้วถ้าค่านี้ไม่มีจริง ๆ จะให้ทำยังไง" แล้วตอบคำถามนั้นในโค้ด

ตอนนี้มาตั้งค่า scripts เพื่อเริ่ม Vite ใน package.json ให้ใส่:

// inside scripts
"dev": "vite",
"build": "tsc && vite build",
"preview": "vite preview",
"typecheck": "tsc --watch"

อย่าลืมเพิ่ม "type": "module" ลงใน package.json ด้วย Vite เลิกสนับสนุน Common.js แล้ว และตอนนี้กำหนดให้คุณใช้ ESM style modules

  • build ของเรารัน tsc ก่อน vite build เพราะ tsc จะตรวจ type ทั้งโปรเจกต์และหยุด build ทันทีถ้ามี type error นี่สำคัญมาก เพราะโดยลำพัง Vite จะตัด type ทิ้งเฉย ๆ โดยไม่ตรวจ ทำให้ dev server รันผ่านแม้โค้ดจะมี type ผิดอยู่
  • ด้วยเหตุผลเดียวกัน typecheck จึงมีประโยชน์มาก เปิดไว้อีกหน้าต่างหนึ่งข้าง ๆ dev server แล้วมันจะคอยบอกคุณตลอดว่ามี type error ตรงไหน (VS Code ก็ขีดเส้นแดงให้อยู่แล้ว แต่เฉพาะไฟล์ที่คุณเปิดอยู่เท่านั้น)
หมายเหตุ: คุณจะได้รับคำเตือนจาก Vite เช่น Files in the public directory are served at the root path. Instead of /public/style.css, use /style.css. – ไม่ต้องสนใจ เราจะแก้ในอีกสักครู่

dev จะเริ่ม development server โดยทั่วไปที่ http://localhost:5173/ build จะเตรียม static files เพื่อ deploy (ไปยังที่อย่าง GitHub Pages, Vercel, Netlify, AWS S3 ฯลฯ) preview ให้คุณ preview production build ในเครื่อง

สังเกตว่าเราเปลี่ยน domains แล้ว โดยค่าเริ่มต้น Vite ใช้ localhost:5173 เรื่องน่าสนใจ: 5173 ดูคล้ายสะกดว่า VITE หากคุณทำให้เลข 5 เป็นเวอร์ชันเลขโรมัน คือ V
