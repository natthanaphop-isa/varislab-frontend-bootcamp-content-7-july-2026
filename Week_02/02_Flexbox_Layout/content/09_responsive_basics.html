บทเรียน 09 · Responsive และฝึกฝน (Responsive & Practice)

Responsive เบื้องต้นด้วย @media และ flex-wrap

Basic Responsive Layout

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายได้ว่า @media ใช้ทำอะไร
  • ใช้ flex-direction: column เปลี่ยน layout จากซ้าย-ขวาเป็นบน-ล่างบนจอเล็ก
  • อธิบายได้ว่าทำไมต้องใส่ align-items: stretch คู่กับ flex-direction: column
  • ใช้ flex-wrap: wrap ให้เมนูขึ้นบรรทัดใหม่ได้เมื่อพื้นที่ไม่พอ

ปัญหาบนจอเล็ก

เปิด DevTools ของเบราว์เซอร์ (คลิกขวา > Inspect) แล้วเปิดโหมดจำลองอุปกรณ์มือถือ หรือย่อหน้าต่างให้แคบลงเรื่อย ๆ จะเห็นว่า:

  • hero ยังพยายามอยู่ซ้าย-ขวา ข้อความหัวข้อตัวใหญ่ถูกบีบจนอ่านยาก
  • feature card 3 ใบถูกบีบจนแคบมาก
  • pricing card และ navbar ก็อึดอัดเช่นกัน

ที่เป็นแบบนี้เพราะ Flexbox พยายามบีบลูกทุกตัวให้อยู่ในแถวเดียวโดยค่าเริ่มต้น

@media คืออะไร

@media ใช้กำหนด CSS ที่จะทำงานเฉพาะเมื่อตรงเงื่อนไข เช่น ขนาดหน้าจอ:

@media (max-width: 768px) {
    /* CSS ในนี้ทำงานเฉพาะตอนหน้าจอกว้างไม่เกิน 768px */
}

ถ้าหน้าจอกว้างไม่เกิน 768px layout ที่เคยเรียงซ้าย-ขวา จะเปลี่ยนเป็นเรียงบน-ล่าง นี่คือพื้นฐานของ responsive design

เพิ่ม responsive ท้ายไฟล์

เพิ่มโค้ดนี้ไว้ท้ายสุดของ style.css:

@media (max-width: 768px) {

    .navbar,
    .hero-section,
    .features-section,
    .pricing-cards {
        flex-direction: column;
        align-items: stretch;
    }

    h1 {
        font-size: 40px;
    }

    .nav-links {
        flex-wrap: wrap;
    }
}

1. flex-direction: column

ค่าเริ่มต้นของ flex-direction คือ row (เรียงแนวนอน) เมื่อเปลี่ยนเป็น column ลูกจะเรียงจากบนลงล่างแทน เราใส่ให้ flex container ทั้ง 4 ตัวพร้อมกันด้วย selector แบบคั่นจุลภาค

เมื่อเปลี่ยนเป็น column "แนวหลัก" จะกลายเป็นแนวตั้ง ส่วน align-items จะคุมแนวนอนแทน นี่คือเหตุผลที่ในบทที่ 03 เราพูดว่า justify-content คุมแนวหลัก "โดยปกติ" คือแนวนอน

2. ทำไมต้อง align-items: stretch

.navbar และ .hero-section ตั้ง align-items: center ไว้ เมื่อเปลี่ยนเป็น column แล้ว align-items คุมแนวนอน ค่า center จะทำให้ลูกหดเหลือกว้างเท่าเนื้อหาและลอยอยู่กลางจอ เช่น .hero-card ไม่เต็มความกว้าง การตั้ง align-items: stretch ทำให้ลูกยืดเต็มความกว้างของ container ส่วน .features-section และ .pricing-cards เป็น stretch อยู่แล้ว ใส่ซ้ำก็ไม่มีผลเสีย

3. ลดขนาด h1

หัวข้อ 52px ใหญ่เกินไปบนมือถือ ลดเหลือ 40px

4. flex-wrap: wrap ที่เมนู

ถ้าเมนูมีหลายลิงก์จนแถวเดียวไม่พอ flex-wrap: wrap จะให้ลิงก์ขึ้นบรรทัดใหม่แทนที่จะล้นออกนอกจอ

ผิดบ่อย: วาง @media ไว้บนสุดของไฟล์ แล้ว responsive ไม่ทำงาน เพราะเมื่อ specificity เท่ากัน กฎที่เขียนทีหลังจะชนะ เช่น h1 { font-size: 52px; } ที่อยู่ด้านล่างจะทับ font-size: 40px ใน @media ให้วาง @media ไว้ท้ายไฟล์เสมอ

เมื่อจอกว้างไม่เกิน 768px: navbar เป็น logo อยู่บนและเมนูอยู่ล่าง, hero เป็นข้อความอยู่บนและ card อยู่ล่างเต็มความกว้าง, feature card และ pricing card เรียงลงมาทีละใบ และหัวข้อเล็กลง เมื่อขยายจอกลับเกิน 768px layout ซ้าย-ขวาจะกลับมาเหมือนเดิม

เก็บงาน: เทียบ start/ กับ finish/

โค้ดใน start/ เป็นฉบับร่างที่หน้าตาใกล้เคียงของจริงมากแล้ว แต่ยังมีจุดที่ต้องเก็บงาน ถ้าคุณเริ่มจาก start/ ให้แก้ตามตารางนี้ (ถ้าเขียนตามคู่มือมาตั้งแต่บทที่ 04 โค้ดของคุณเป็นแบบ finish/ อยู่แล้ว ใช้ตารางนี้ฝึกอ่านโค้ดได้):

จุดใน start/ใน finish/เหตุผล
@media ของ h1เขียน @media ซ้อนไว้ข้างใน rule h1ย้ายไปรวมใน @media ก้อนเดียวท้ายไฟล์CSS สำหรับจอเล็กอยู่ที่เดียว หาง่าย แก้ง่าย
@media ของ flex containerมีแค่ flex-direction: columnเพิ่ม align-items: stretchให้ลูกยืดเต็มความกว้างเมื่อเรียงบน-ล่าง
.hero-descriptionไม่มี colorcolor: #cbd5e1คำอธิบายเป็นสีเทาอ่อน ไม่แย่งความเด่นจากหัวข้อ
.nav-linksมี list-style: noneไม่มี.nav-links เป็น <div> ไม่ใช่ list property นี้จึงไม่มีผล
.site-headerเส้นขอบ #334155เส้นขอบ #1e293bสีเดียวกับเส้นขอบบนของ footer
ตำแหน่ง .hero-cardอยู่ห่างจาก .hero-contentอยู่ถัดจาก .hero-content ทันทีเห็น flex ratio 1.4 : 1 ของสองฝั่งได้ในที่เดียว
.pricing-card pอยู่ก่อน .priceอยู่หลัง .priceเรียงตามลำดับที่อ่าน ผลลัพธ์เหมือนเดิมเพราะตัดสินด้วย specificity
margin0 0 16px 00 0 16pxแบบ 3 ค่าได้ผลเหมือนกันแต่สั้นกว่า
HTML ราคาแผนผ่อน<p id="price-secondary" class="price"><p class="price">ไม่มี CSS หรือโค้ดใดใช้ id นี้ จึงลบออก
