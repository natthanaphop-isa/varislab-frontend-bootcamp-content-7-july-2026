บทเรียน 09 · ขัดเกลา UI และ Responsive (UI Polish & Responsive)

จัด CSS เป็นหมวด

CSS Organization

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายได้ว่าทำไมควรจัด CSS เป็นหมวด
  • จัดเรียง style.css เป็นหมวดด้วย comment ตามลำดับที่เหมาะสม
  • ย้าย rule โดยไม่ทำให้ผลลัพธ์บนหน้าเว็บเปลี่ยน

ทำไมต้องจัดหมวด

ช่วงแรกเราอาจเขียน CSS ต่อ ๆ กันไปก่อนเพื่อให้เห็นผลเร็ว แต่พอหน้าเว็บใหญ่ขึ้น (ตอนนี้ไฟล์ของเรายาวหลายร้อยบรรทัดแล้ว) ถ้าไม่จัดเป็นหมวดจะหา code ยากมาก Developer ที่ดีไม่ได้แค่เขียนให้รันได้ แต่ต้องเขียนให้กลับมาอ่านแล้วเข้าใจด้วย — ทั้งตัวเราในอนาคตและคนอื่นที่เปิด repository ของเรา

หมวดที่ใช้

ใน CSS เขียน comment ด้วย /* ... */ เราจะใช้ comment เป็น “ป้ายหมวด” เรียงจากสิ่งที่กว้างที่สุดไปเฉพาะที่สุด และเรียง section ตามลำดับที่อยู่บนหน้าเว็บ:

/* Reset */

/* Base */

/* Header */

/* Layout */

/* Shared Components */

/* Hero */

/* Features */

/* Curriculum */

/* Audience */

/* Pricing */

/* CTA */

/* Footer */

/* Responsive */
หมวดมีอะไรอยู่ข้างใน
Reset* { box-sizing: border-box; }
Basestyle พื้นฐานของ tag: body, a
Header.site-header, .navbar, .logo, .nav-links
Layoutmain — ความกว้างสูงสุดและ padding ของเนื้อหา
Shared Componentsของที่ใช้ร่วมหลาย section: .eyebrow, .card-label, .primary-button, .section-header
Hero → CTAstyle เฉพาะของแต่ละ section เรียงตามลำดับบนหน้า
Footer.site-footer
Responsivemedia query ทั้งหมด — ต้องอยู่ท้ายสุดเสมอ

การย้าย rule ไม่ได้เปลี่ยนแค่ความสวยงามของไฟล์ — ใน CSS ถ้า selector มีน้ำหนักเท่ากัน rule ที่อยู่ทีหลังชนะ ดังนั้น:

  • หมวด Responsive ต้องอยู่ล่างสุด ไม่อย่างนั้น rule ปกติจะเขียนทับค่าใน media query
  • ย้ายทีละหมวดแล้ว refresh ดูผลทุกครั้ง ถ้าหน้าเว็บเปลี่ยนไปจากก่อนย้าย แปลว่ามีลำดับบางอย่างเพี้ยน
  • ระวัง copy ซ้ำจนมี rule เดียวกันสองที่ (เช่น .section-header เดิมกับชุดใหม่) — ให้เหลือแค่ชุดล่าสุด

ตัวเลือกชื่อหมวดและลำดับไม่มีกฎตายตัว สิ่งสำคัญคือ สม่ำเสมอ — ถ้า section บนหน้าเรียงแบบไหน หมวดใน CSS ก็ควรเรียงแบบนั้น และถ้าเพิ่ม section ใหม่ในอนาคต (เช่น Student Outcomes) ก็เพิ่มหมวดใหม่ในตำแหน่งที่ตรงกับหน้าเว็บ

HTML ที่ครบทุก section

ลำดับ element ใน index.html ฉบับสมบูรณ์ (เทียบรายละเอียดกับ finish/index.html):

body
├── header.site-header > nav.navbar
├── main
│   ├── section#overview.hero-section
│   ├── section.features-section
│   ├── section#curriculum.curriculum-section
│   ├── section.audience-section
│   ├── section#pricing.pricing-section
│   └── section.cta-section
└── footer.site-footer
  • style.css มี comment หมวดครบ และหมวด Responsive อยู่ท้ายสุด
  • ไม่มี rule ซ้ำสองที่ (ลองค้นหา .section-header { ในไฟล์ ต้องเจอแค่ครั้งเดียว)
  • หน้าเว็บหลังจัดหมวดหน้าตาเหมือนก่อนจัดทุกขนาดจอ
ก่อนหน้า: ทำ Grid ให้ Responsive สารบัญบทเรียน ถัดไป: Git และ GitHub เบื้องต้น
