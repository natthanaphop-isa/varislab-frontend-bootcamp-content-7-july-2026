Git, GitHub และ Repository

คำคืออะไรตัวอย่างในงานนี้
Gitเครื่องมือเก็บประวัติการเปลี่ยนแปลงของ code ในเครื่องเราเขียนหน้าเว็บเสร็จแล้วบันทึก version นี้ไว้ ถ้าวันหลังแก้แล้วพัง ยังมีประวัติว่า version ก่อนหน้าหน้าตาเป็นอย่างไร
GitHubเว็บไซต์สำหรับเก็บ repository แบบ online และแชร์ให้คนอื่นดูได้ที่ที่เรา push project ขึ้นไป แล้วส่ง link ให้ผู้สอน
Repository (repo)folder project ที่ถูกเก็บด้วย Gitโฟลเดอร์ Bootcamp Landing Page ที่มี index.html, style.css และ README.md

คำสั่งที่จะใช้

ทุกคำสั่งรันใน terminal ภายในโฟลเดอร์ project (ใน VS Code เปิด Terminal แล้วจะอยู่ในโฟลเดอร์ที่เปิดไว้ให้อัตโนมัติ)

1. เช็กสถานะ

git status

ดูว่า Git เห็นไฟล์อะไรเปลี่ยนแปลงบ้าง — ใช้บ่อยที่สุด รันได้ทุกเมื่อที่ไม่แน่ใจ ไม่ทำให้อะไรเปลี่ยน

2. เริ่มใช้ Git ใน project

git init

เปลี่ยนโฟลเดอร์ธรรมดาให้เป็น Git repository ใช้ครั้งแรกครั้งเดียวต่อ project

3. เลือกไฟล์เข้า staging

git add .

จุด . หมายถึง “ทุกไฟล์ในโฟลเดอร์นี้” คำสั่งนี้เลือกไฟล์ทั้งหมดเตรียมบันทึกเป็น version ใหม่ (staging คือพื้นที่พักไฟล์ที่จะเข้า commit ถัดไป)

4. Commit งาน

git commit -m "Complete bootcamp landing page"

Commit คือการบันทึก snapshot ของงาน ณ ตอนนั้น ข้อความหลัง -m คือ commit message ที่อธิบายว่า version นี้เปลี่ยนอะไร

5. ตั้งชื่อ branch หลักเป็น main

git branch -M main

ตั้งชื่อ branch หลักเป็น main ให้ตรงกับที่ GitHub ใช้

6. เชื่อมกับ repo บน GitHub

git remote add origin <your-repo-url>

บอก Git ว่า repo ปลายทางบน GitHub อยู่ที่ไหน โดยตั้งชื่อเล่นว่า origin ให้แทน <your-repo-url> ด้วย URL จริงของคุณ เช่น:

git remote add origin https://github.com/username/bootcamp-landing-page.git

7. Push code ขึ้น GitHub

git push -u origin main

ส่ง commit จากเครื่องเราขึ้น GitHub โดย -u จำไว้ว่า branch main ในเครื่องคู่กับ origin/main ครั้งต่อไปจึงพิมพ์แค่ git push ได้

จำภาพรวมง่าย ๆ: add = เลือกไฟล์ → commit = บันทึก version ในเครื่อง → push = ส่ง version ขึ้น GitHub ถ้า commit แล้วแต่ยังไม่ push งานจะยังไม่ขึ้นไปบน GitHub

อย่าพิมพ์ < > ลงไปด้วยตอนแทน URL — <your-repo-url> เป็นแค่ตัวแทนในเอกสาร และอย่าลืมว่า commit message ต้องอยู่ในเครื่องหมายคำพูด

อ่านเพิ่มเติมได้ที่ git-scm.com/doc และ docs.github.com

  • อธิบายได้ว่า Git ต่างจาก GitHub อย่างไร
  • อธิบายได้ว่า commit คือการบันทึก snapshot ของงานพร้อมข้อความอธิบาย
  • เรียงลำดับได้: init → add → commit → branch -M main → remote add → push
  • ในเครื่องมี Git พร้อมใช้ (ลองรัน git --version แล้วเห็นเลขเวอร์ชัน)
