บทเรียน 02 · โครงสร้างหน้าเว็บด้วย Semantic HTML

Semantic HTML คืออะไร

What is Semantic HTML

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายความหมายของ Semantic HTML ด้วยคำพูดของตัวเอง
  • เลือกใช้ header, nav, main, section, article และ footer ได้ถูกที่
  • บอกข้อดีของ Semantic HTML เมื่อเทียบกับการใช้ div ทั้งหน้า

HTML เขียนได้หลายแบบ

ในทางเทคนิค เราสามารถสร้างหน้าเว็บทั้งหน้าด้วย div อย่างเดียวก็ได้ เบราว์เซอร์ก็แสดงผลได้ปกติ แต่ปัญหาคือโค้ดจะอ่านยาก — มองแล้วไม่รู้เลยว่าส่วนไหนคือ header ส่วนไหนคือเนื้อหาหลัก ส่วนไหนคือ footer

Semantic HTML คือการใช้ tag ที่มีความหมายตรงกับเนื้อหาส่วนนั้น ๆ ชื่อ tag จะบอกเราทันทีว่าข้างในคืออะไร

Semantic tags ที่ใช้บ่อย

Tag ความหมาย
header ส่วนหัวของหน้า เช่น โลโก้และเมนู
nav เมนูนำทาง (กลุ่มลิงก์สำหรับไปส่วนต่าง ๆ ของเว็บ)
main เนื้อหาหลักของหน้า
section หมวดเนื้อหา แบ่งหน้าออกเป็นส่วน ๆ
article เนื้อหาที่เป็นชิ้น ๆ แยกออกมาได้ เช่น content card
footer ส่วนท้ายของหน้า

ตัวอย่างที่ไม่ดี vs ตัวอย่างที่ดีกว่า

ลองดูโค้ดที่ใช้แต่ div:

<div>
  <div>
    <div>Full-Stack Bootcamp</div>
    <div>เรียนเขียนเว็บพร้อม AI Workflow</div>
  </div>
</div>

โค้ดนี้ใช้งานได้ แต่ถ้าไม่อ่านข้อความข้างใน เราไม่มีทางรู้เลยว่า div แต่ละชั้นทำหน้าที่อะไร อันไหนคือหัวข้อ อันไหนคือคำอธิบาย

ทีนี้ลองเขียนใหม่ด้วย Semantic HTML:

<header>
  <nav>
    <p>Varis Lab</p>
    <a href="#">Courses</a>
  </nav>
</header>

<main>
  <section>
    <h1>Full-Stack Software Developer Bootcamp</h1>
    <p>เรียนเขียนเว็บพร้อม AI Workflow</p>
  </section>
</main>

แค่ดูชื่อ tag ก็รู้ทันทีว่า ด้านบนคือส่วนหัวที่มีเมนูนำทาง ด้านล่างคือเนื้อหาหลัก ซึ่งมี section หนึ่งที่มีหัวข้อ h1 และย่อหน้าคำอธิบาย

ทำไม Semantic HTML ถึงสำคัญ

  • โค้ดอ่านง่ายขึ้น — เปิดไฟล์มาก็เห็นโครงสร้างหน้าเว็บทันที
  • คนอื่นดูแลต่อได้ง่ายขึ้น — เพื่อนร่วมทีม (หรือตัวเราเองในอีกหลายเดือน) ไม่ต้องเดาว่า div ไหนคืออะไร
  • เบราว์เซอร์และ screen reader เข้าใจหน้าเว็บดีขึ้น — เช่น screen reader รู้ว่าส่วนไหนคือเมนู ส่วนไหนคือเนื้อหาหลัก ช่วยให้ผู้ใช้ที่มองไม่เห็นใช้งานเว็บได้
  • เตรียมตัวเข้าสู่ React — การคิดแบ่งหน้าเว็บเป็นส่วนที่มีความหมาย (header, section, card) คือพื้นฐานของการคิดแบบ component

Semantic tags อย่าง header หรือ section ไม่ได้ทำให้หน้าตาเปลี่ยนไปจาก div มากนัก — มันเปลี่ยนความหมาย ไม่ใช่หน้าตา หน้าตาเป็นหน้าที่ของ CSS ซึ่งเราจะจัดการในบทที่ 04 เป็นต้นไป

Semantic HTML ไม่ได้แปลว่าห้ามใช้ div เลย เมื่อเราต้องการกล่องสำหรับจัดกลุ่มเพื่อ styling เฉย ๆ โดยไม่มีความหมายพิเศษ div ก็ยังเหมาะสม — ในบทถัดไปเราจะใช้ <div class="nav-links"> ครอบลิงก์เมนูด้วยเหตุผลนี้

ลองทำดู

ดูโครงสร้างนี้แล้วลองเปลี่ยน div ให้เป็น semantic tag ที่เหมาะสมที่สุด:

<div>
  <div>
    <a href="#">หน้าแรก</a>
    <a href="#">ติดต่อเรา</a>
  </div>
</div>
<div>
  <div>บทความที่ 1</div>
  <div>บทความที่ 2</div>
</div>
<div>© 2026 My Website</div>

คำใบ้: มีส่วนหัวที่มีเมนู เนื้อหาหลักที่มีเนื้อหาเป็นชิ้น ๆ และส่วนท้าย

  • อธิบายได้ว่า Semantic HTML คือการใช้ tag ที่มีความหมายกับเนื้อหา
  • บอกได้ว่า main ใช้ครอบเนื้อหาหลักของหน้า และ article เหมาะกับเนื้อหาที่เป็นชิ้น ๆ เช่น card
  • บอกข้อดีของ Semantic HTML ได้อย่างน้อย 3 ข้อ
