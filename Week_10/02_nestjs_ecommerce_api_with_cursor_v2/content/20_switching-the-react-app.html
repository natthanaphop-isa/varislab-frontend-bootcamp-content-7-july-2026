NestJS E-commerce API Workshop

สลับ React app มาใช้ API ของเรา

เมื่อจบบทนี้ คุณจะสามารถ

  • สลับ React app ไปใช้ API ที่คุณสร้างเองด้วยการแก้บรรทัดเดียวใน .env.local
  • ไล่ตรวจห้าจุดในเบราว์เซอร์ พร้อมอ่าน Network tab ว่า request วิ่งไปที่ host ไหนและได้สถานะอะไร
  • ยืนยันคำสั่งซื้อที่เพิ่งกดด้วย psql และอธิบายได้ว่าทำไม npm test ของ React app ให้ผลเท่าเดิม

ช่วงเวลาตัดสิน

ตลอด workshop ที่ผ่านมาเราทำงานอยู่กับ curl, psql และ e2e test ของสัญญา ซึ่งทั้งหมดเป็นการตรวจว่า API ของเราตรงกับสัญญาที่เราออกแบบไว้เองหรือเปล่า บทนี้เป็นบทที่เอาของจริงมาชน: React e-commerce app จากคอร์ส React E-commerce ที่เขียนไว้ตั้งแต่ก่อนเราจะมี API — โค้ดของมันไม่รู้เลยว่าเรามีตัวตน ถ้าสัญญาที่เราออกแบบเองตั้งแต่ต้นตรงกับที่โค้ด client ต้องการจริง สิ่งที่ต้องเปลี่ยนคือ base URL หนึ่งบรรทัด ไม่ต้องแตะโค้ด ไม่ต้องแก้ type ไม่ต้องแก้ mapper ฝั่ง client — นี่คือหลักฐานว่าการอ่าน client โค้ดให้ถูกต้องตั้งแต่ตอนออกแบบสัญญานั้นได้ผลจริง ไม่ใช่หลักฐานว่าเราก็อปพฤติกรรมของ dummyjson ได้แม่นแค่ไหน

แอปตัวนี้อ่าน base URL จาก environment variable ชื่อ VITE_API_BASE_URL — Vite เปิดเผยให้โค้ดฝั่ง client เห็นเฉพาะตัวแปรที่ขึ้นต้นด้วย VITE_ และอ่านไฟล์ .env ตระกูลนี้ ตอนเริ่ม dev server เท่านั้น (รายละเอียดอยู่ใน คู่มือ Env Variables and Modes ของ Vite) แปลว่าแก้ไฟล์แล้วต้องหยุด npm run dev แล้วสั่งใหม่ ไม่ใช่รอ hot reload

เตรียมของให้พร้อมก่อนสลับ

สองอย่างที่ต้องรันอยู่พร้อมกัน: ฐานข้อมูลที่ seed แล้ว กับ API ของเราที่พอร์ต 3000 และอีกอย่างที่ควรทำก่อนสลับคือรัน npm test ในโปรเจกต์ React หนึ่งรอบเพื่อเก็บ baseline ไว้เทียบ — ถ้าไม่รู้ผลก่อนสลับ ก็เถียงไม่ได้ว่าผลหลังสลับเปลี่ยนหรือไม่เปลี่ยน

สลับ base URL แล้วเดินดูทีละหน้า

เปิดสอง terminal ค้างไว้ตามนี้ แล้วแก้ .env.local ของโปรเจกต์ React ให้ชี้มาที่ API ของเรา — นี่คือการแก้ไฟล์เดียวบรรทัดเดียวในบทนี้

# terminal A — API ของเรา cd ecommerce-api docker compose up -d npm run start:dev # terminal B — โปรเจกต์ React จากคอร์ส React E-commerce cd react-ecommerce-app npm test # เก็บ baseline ไว้ก่อน แล้วจดผลบรรทัดสุดท้ายไว้ # แก้ (หรือสร้าง) ไฟล์ .env.local ให้มีบรรทัดนี้ # VITE_API_BASE_URL=http://localhost:3000 # แล้วเริ่ม dev server ใหม่ (Vite อ่านไฟล์ env ตอนเริ่มเท่านั้น) npm run dev

เปิด http://localhost:5173 แล้วเปิด DevTools ค้างไว้ที่แท็บ Network ทุกครั้งที่เดิน — สิ่งที่เราต้องเห็นคือ request ทุกตัววิ่งไปที่ host localhost:3000 แล้วไล่ห้าจุดนี้ตามลำดับ

  1. หน้าแรก / — ส่วน DEALS OF THE DAY ต้องขึ้นสินค้า 5 ชิ้น และเมนูหมวดหมู่ต้องขึ้นครบ 24 หมวด (Beauty, Fragrances, Furniture, Groceries, … , Womens Watches) ใน Network tab จะเห็นสามคำขอตอนโหลดหน้า ได้ 200 ทั้งหมด: GET http://localhost:3000/products?skip=0&limit=5, GET http://localhost:3000/products/categories และ GET http://localhost:3000/products/category/beauty?skip=0&limit=12 ลองกดหมวด Fragrances จะมีคำขอใหม่ GET http://localhost:3000/products/category/fragrances?skip=0&limit=12 ได้ 200 และ grid เปลี่ยนตาม
  2. หน้าหมวดหมู่ /categories — อย่าใช้ Beauty ทดสอบ pagination เพราะข้อมูล seed ของเรามีแค่ 5 ชิ้น จึงมีหน้าเดียวและปุ่มถูก disable (ถูกต้องแล้ว ไม่ใช่บั๊ก) ให้เลือก Groceries ที่มี 27 ชิ้นแทน หน้า 1 ขึ้น 20 ชิ้นพร้อมแถบ 1 | 2 | Next และคำขอ GET http://localhost:3000/products/category/groceries?skip=0&limit=20 เมื่อกดหน้า 2 จะได้คำขอ GET http://localhost:3000/products/category/groceries?skip=20&limit=20 คืนสินค้าอีก 7 ชิ้นที่ไม่ซ้ำกับหน้าแรกเลย (Mulberry, Juniper Berry, Chinese Cabbage, White Bread, Peppers, Cabbage, Bean Shoots)
  3. หน้าสินค้า /products/1 — ต้องขึ้นชื่อ Velvet Matte Lipstick แบรนด์ Lumina ราคา $9.99 (จากราคาเต็ม $11.16 ลด 10.48%) และรีวิวครบ 3 รายการพร้อมชื่อผู้รีวิว วันที่ และคอมเมนต์ กด Add To Cart แล้วต้องเด้ง modal Product Added to Cart พร้อมตัวเลขบนไอคอนตะกร้าขึ้นเป็น 1
  4. /cart → /checkout → /order/success — ที่หน้า /cart ต้องเห็นสินค้าที่เพิ่งเพิ่ม 1 รายการพร้อมยอดรวม กด Checkout แล้วกรอกที่อยู่ อีเมล เบอร์โทร (ฟอร์มที่อยู่มีปุ่ม Submit ของตัวเอง ต้องกดก่อนปุ่ม Place Order จึงจะกดได้) เลือก delivery/payment ตามค่าเริ่มต้นได้ แล้วกด Place Order จะไปหน้า /order/success ขึ้นหัวข้อ Order Placed Successfully! และตัวเลขบนตะกร้าหายไป ใน Network tab ต้องเห็น POST http://localhost:3000/carts/add ได้ 201 Created
  5. ตรวจในฐานข้อมูล — คำสั่งซื้อที่เพิ่งกดต้องมีอยู่จริงในตาราง Order ไม่ใช่แค่หน้าจอสวย ใช้คำสั่ง psql ด้านล่าง
docker compose exec db psql -U postgres -d ecommerce \ -c 'SELECT id, email, "totalQuantity" FROM "Order" ORDER BY id DESC LIMIT 1;'

ตอนตรวจของจริงได้แถวนี้ (อีเมลและจำนวนตรงกับที่กรอกและใส่ตะกร้าไว้ ส่วนเลข id ของคุณจะต่างออกไปตามจำนวนคำสั่งซื้อที่เคยสร้าง)

 id |           email           | totalQuantity
----+---------------------------+---------------
  2 | customer@example.com      |             1

ทำไม npm test ของ React app ไม่เปลี่ยนผล

คำถามที่ควรค้างอยู่ในหัวคือ สลับ backend แล้วเทสต์ของ frontend ไม่พังเหรอ คำตอบคือไม่ เพราะชุดเทสต์ของแอปนี้ไม่ได้คุยกับ backend จริงเลย ดูบรรทัด test.env ใน vite.config.ts ของโปรเจกต์ React

/* vite.config.ts (โปรเจกต์ React — อ่านเท่านั้น ไม่ต้องแก้) */
  test: {
    environment: 'jsdom',
    globals: true,
    setupFiles: './src/test/setup.ts',
    // MSW handlers hardcode the host, so tests must not depend on .env
    env: { VITE_API_BASE_URL: 'https://dummyjson.com' },
  },

ตอนรันเทสต์ Vitest จะตรึง VITE_API_BASE_URL ไว้ที่ https://dummyjson.com ทับค่าจากไฟล์ env ทุกไฟล์ แล้ว MSW (mock server worker) ก็ดักคำขอไปที่ host นั้นตอบด้วยข้อมูลปลอมที่เตรียมไว้ ดังนั้นไม่ว่า .env.local ของคุณจะชี้ไปที่ไหน API ของเราก็เปลี่ยนผลเทสต์ไม่ได้ — ผลหลังสลับต้องเท่ากับผลของ baseline ที่คุณรันไว้ก่อนสลับ ไม่มากไม่น้อยกว่านั้น และนี่คือสิ่งที่บทนี้ให้คุณตรวจ (ไม่ใช่ เทสต์เขียวตลอด)

บนเครื่องที่ใช้ตรวจ (Node 26.7 + jsdom 30 + Vitest 4) ชุดเทสต์นี้ ล้มทั้งหมด ทั้งก่อนและหลังสลับ: Test Files 12 failed (12) / Tests 34 failed (34) พร้อมข้อความ ExperimentalWarning: localStorage is not available because --localstorage-file was not provided แล้วพังที่ src/test/setup.ts ตรง localStorage.clear() สาเหตุคือ global localStorage แบบ experimental ของ Node บังตัวที่ jsdom เตรียมไว้ — เป็นเรื่องของ Node/jsdom ไม่เกี่ยวกับ API ของเราเลย (พิสูจน์ได้จากไฟล์เทสต์ที่เป็นฟังก์ชันคำนวณราคาล้วน ๆ ก็ล้มเหมือนกัน) ถ้าเครื่องคุณใช้ Node รุ่นอื่นอาจไม่เจอ ประเด็นเดียวที่ต้องยืนยันคือ ผลก่อนและหลังสลับตรงกัน

อยากกลับไปใช้ dummyjson เมื่อไหร่ก็แก้บรรทัดเดิมกลับ (หรือลบ .env.local ทิ้ง) แล้ว restart npm run dev — การสลับไปกลับได้ในบรรทัดเดียวคือนิยามของคำว่า drop-in replacement ที่เราตั้งเป้าไว้ตั้งแต่ต้น workshop

ผลลัพธ์ที่คาดหวัง

React app ทำงานครบวงจรตั้งแต่หน้าแรกไปจนถึงหน้า Order Placed Successfully! โดยข้อมูลทุกชิ้นมาจาก Postgres ของคุณ ไม่ใช่จากอินเทอร์เน็ต: รายการสินค้า, 24 หมวดหมู่, pagination, รีวิว, ราคาและส่วนลด รวมถึงคำสั่งซื้อที่ถูกบันทึกเป็นแถวจริงในตาราง Order สิ่งเดียวที่คุณแก้ในโปรเจกต์ React คือบรรทัด VITE_API_BASE_URL ใน .env.local — ไม่มีไฟล์ .ts/.tsx ถูกแตะแม้บรรทัดเดียว

ตรวจว่าใช้งานได้จริง

  • ทั้งห้าจุดข้างบนผ่านครบ โดยเฉพาะ pagination หน้า 2 ของ Groceries ที่ต้องคืนสินค้าไม่ซ้ำหน้าแรก
  • ใน Network tab ทุกคำขอมี host เป็น localhost:3000 ทั้งหมด (ยกเว้นไฟล์รูปที่ชี้ไป CDN ตามข้อมูล seed)
  • POST /carts/add ได้ 201 และคำสั่ง SELECT … FROM "Order" ORDER BY id DESC LIMIT 1; คืนแถวที่อีเมลกับ totalQuantity ตรงกับที่คุณกรอกและใส่ตะกร้า
  • ไม่มี error CORS ใน Console ของเบราว์เซอร์ — ถ้ามี ให้กลับไปดู CORS_ORIGIN ตอนเปิด CORS ว่าตรงกับพอร์ตที่ Vite ใช้จริงหรือไม่
  • npm test ในโปรเจกต์ React ให้ผลบรรทัดสุดท้ายเหมือน baseline ที่รันไว้ก่อนสลับทุกตัวเลข
  • ไม่มีไฟล์อื่นในโปรเจกต์ React ถูกแก้: git status ในโปรเจกต์นั้นควรสะอาด (ไฟล์ .env.local ปกติถูก gitignore ไว้)
