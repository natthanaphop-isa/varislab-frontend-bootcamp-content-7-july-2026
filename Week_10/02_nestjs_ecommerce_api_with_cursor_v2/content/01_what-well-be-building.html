เราจะแทนที่ dummyjson ด้วย API ของเราเอง

React e-commerce app ที่เราสร้างไว้ใน Week_05_06 ไม่มีฐานข้อมูลของตัวเอง มันดึงข้อมูลสินค้าทั้งหมดจาก dummyjson.com ผ่าน endpoint เพียง 5 เส้น เป้าหมายของคอร์สนี้คือสร้าง API ของเราเองที่ตอบ 5 เส้นนี้ได้ ด้วย path เดิมและรูปทรง JSON เดิม เพื่อให้ React app ไม่ต้องแก้โค้ดแม้แต่บรรทัดเดียว — เปลี่ยนแค่ค่า VITE_API_BASE_URL จาก https://dummyjson.com เป็น http://localhost:3000 ก็ใช้งานได้ทันที นี่คือความหมายของคำว่า drop-in replacement

Method + PathReact ใช้ที่ไหนตอบอะไร
GET /products/categoriesหน้า Home และเมนูหมวดสินค้าarray ของ {slug, name, url} จำนวน 24 รายการ
GET /products?limit&skipแถบดีลบนหน้า Homeซอง {products, total, skip, limit}
GET /products/category/:slug?limit&skipหน้า Home และหน้า Category ที่มีการแบ่งหน้าซองเดียวกับด้านบน แต่กรองด้วย slug
GET /products/:idหน้ารายละเอียดสินค้าproduct เต็มรูปแบบ พร้อม reviews
POST /carts/addหน้า Checkoutcart ที่คิดส่วนลดแล้ว พร้อม id ของคำสั่งซื้อ

ข้อผูกมัดจึงชัดเจนมาก: ทุกชื่อ field ทุก status code และทุกพฤติกรรมขอบ ๆ (เช่น หมวดที่ไม่มีจริงตอบอะไร) ต้องตรงกับของ dummyjson เพราะถ้าไม่ตรง หน้าจอของ React จะพังโดยที่ API ของเราไม่ฟ้อง error อะไรเลย บทที่ 3 จะวาง สัญญา (contract) นี้ลงเป็นไฟล์จริงในโปรเจกต์ — payload ที่คอร์สยิงเก็บมาจาก dummyjson ให้แล้ว — และทุกบทหลังจากนั้นจะอ้างถึงไฟล์เหล่านั้นเสมอ

กติกาของคอร์ส: เข้าใจก่อน แล้วค่อยสั่ง

AI พิมพ์แทนคุณได้ แต่คุณต้องอธิบายทุกบรรทัดได้ — ถ้าอธิบายไม่ได้ แปลว่ายังไม่ผ่านบทนี้

ทุกบทที่ใช้ Cursor เดินตามลำดับเดียวกันห้าขั้น: แนวคิด (ทำความเข้าใจว่า endpoint นี้ต้องทำอะไร และข้อเท็จจริงจาก dummyjson ข้อไหนบังคับมันอยู่) → เป้าหมายของบทนี้ (ไฟล์ที่จะเกิดขึ้นและสัญญาของแต่ละไฟล์) → 🤖 prompt (คำสั่งห้าส่วนที่ส่งให้ Cursor Agent) → ✅ review (ตรวจโค้ดที่ AI สร้างทีละข้อ เทียบกับโค้ดอ้างอิงของบทนั้น) → ตรวจว่าใช้งานได้จริง (ยิง curl แล้วเทียบกับไฟล์ใน docs/contract/) ลำดับนี้ไม่สลับ เพราะ prompt ที่ดีเขียนได้เฉพาะเมื่อคุณรู้คำตอบคร่าว ๆ อยู่ก่อนแล้ว

มีห้าบทที่เรา ไม่ ใช้ Cursor แต่ลงมือเองทั้งบท (บทที่ 2, 3, 4, 8 และ 23) ด้วยเหตุผลสามข้อ

  • บทที่ 3 คือ ความจริงที่ AI เดาแทนไม่ได้ — สัญญาของ dummyjson ต้องมาจากการยิงของจริง คอร์สจึงยิงเก็บไว้ให้แล้วเป็นไฟล์ (คุณแค่ก๊อปเข้าโปรเจกต์แล้วอ่านให้เข้าใจ) ถ้าปล่อยให้ AI เขียนไฟล์ contract ให้ มันจะแต่ง field ที่ไม่มีอยู่จริงขึ้นมา แล้วทุกบทหลังจากนั้นจะผิดตามกันไปหมด
  • บทที่ 2 และ 8 คือ งานที่รัน ไม่ใช่งานที่เขียน — nest new และ prisma migrate dev เป็นคำสั่งที่คุณต้องเห็นผลลัพธ์ด้วยตาตัวเอง (และ Cursor rules ที่เราเขียนในบทที่ 4 ก็สั่งห้าม AI รัน migration เองอยู่แล้ว)
  • บทที่ 4 คือ กติกาที่คุณตั้งให้ AI และบทที่ 23 คือ หลักฐาน ว่างานทั้งหมดใช้ได้จริง — สองอย่างนี้เป็นความรับผิดชอบของคน ไม่ใช่ของเครื่องมือ
