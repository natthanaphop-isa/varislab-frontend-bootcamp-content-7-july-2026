POST /carts/add

เมื่อจบบทนี้ คุณจะสามารถ

  • เปิด route POST /carts/add ให้ตรงกับ path ที่ React app เรียกโดยไม่แก้ฝั่ง frontend
  • อธิบายได้ว่าทำไมไฟล์ controller ชื่อ carts แต่ module และ service ใช้คำว่า orders
  • พิสูจน์ทั้งสี่พฤติกรรมด้วย curl: 201, 400 ขาด userId, 404 สินค้าไม่มีจริงพร้อม rollback, 400 email ผิดรูป

path มาจาก client ไม่ใช่จากเรา

ถ้าออกแบบ API ใหม่ตั้งแต่ต้น การสั่งซื้อควรเป็น POST /orders แต่คอร์สนี้มีข้อจำกัดที่ชัดเจน: React app เรียก POST /carts/add และเราสัญญาว่าจะไม่แก้โค้ด frontend นอกจาก base URL ดังนั้น path ต้องเป็น /carts/add เป๊ะ ๆ — พลาดตัวเดียวก็ได้ 404 ทุกครั้งที่กดสั่งซื้อ

ทางออกคือแยกสองเรื่องนี้ออกจากกัน: path เป็นเรื่องของสัญญากับ client จึงตั้งชื่อไฟล์ controller ตาม path (carts.controller.ts + @Controller('carts')) ส่วน module และ service เป็นเรื่องของ domain คือการสั่งซื้อ จึงใช้คำว่า orders (orders.module.ts, orders.service.ts) โครงสร้างนี้บอกคนอ่านโค้ดคนต่อไปได้ทันทีว่า "ชื่อ carts มาจากข้อจำกัดภายนอก ไม่ใช่จากวิธีที่เราคิดเรื่องธุรกิจ"

ทั้งสองไฟล์อยู่ในโฟลเดอร์ src/orders/ เดียวกัน ตามหลักการรวม domain ไว้ใน module เดียวจากบทที่ 14 ของคอร์ส NestJS Fundamentals — คนหาโค้ดเรื่องคำสั่งซื้อจะเจอทุกอย่างในที่เดียว แม้ route จะชื่อ /carts

ทวนของเดิม: @Body และ status 201

บทที่ 8 และ 9 ของคอร์ส NestJS Fundamentals วางพื้นไว้แล้วสองข้อที่ใช้ตรง ๆ ในบทนี้ ข้อแรก @Body() dto: AddCartDto — การประกาศชนิดของ parameter ให้เป็น class ของ DTO คือสิ่งที่ทำให้ ValidationPipe รู้ว่าต้องเอา rule ชุดไหนมาตรวจ ถ้าเขียนเป็น @Body() dto: any หรือลืมใส่ชนิด DTO ทั้งชุดของบทที่ 17 จะไม่ทำงานเลยแม้แต่ข้อเดียว และไม่มี error ใด ๆ เตือน

ข้อสอง handler ที่เป็น @Post() ของ Nest ตอบ 201 Created เป็นค่าเริ่มต้นอยู่แล้ว ตรงกับสัญญาของ dummyjson พอดี จึงไม่ต้องใส่ @HttpCode() — ใส่ @HttpCode(200) ไปจะกลายเป็นการทำสัญญาเสียเอง

สุดท้าย OrdersModule ต้องถูก import เข้า AppModule ไม่ทำขั้นนี้ Nest จะไม่รู้จัก controller ตัวใหม่ และจะไม่มีบรรทัด Mapped {/carts/add, POST} ใน log ตอน start — ซึ่งเป็นวิธีตรวจที่เร็วที่สุดว่าลืมหรือไม่ลืม

    └── orders/

  • src/app.module.ts — สัญญา: ต้องเพิ่ม OrdersModule ต่อจาก ProductsModule ใน imports · ต้องไม่แตะ ConfigModule, controllers หรือ providers เดิม

สั่ง Cursor เปิด route แล้วยิงทดสอบสี่กรณี

commit งานก่อน แล้วเปิดแชทใหม่ใน Cursor โหมด Agent (git add -A && git commit -m "chore: before carts controller") — prompt ยก @src/products/products.controller.ts และ @src/products/products.module.ts ให้เป็นแบบอย่าง และย้ำเรื่องชื่อไฟล์กับ path ไว้ชัด ๆ เพราะนี่คือจุดที่ AI ชอบ "แก้ให้ดีขึ้น" โดยไม่ได้ขอ

ก่อนส่ง อ่านกติกาของคอร์สอีกครั้ง: AI พิมพ์แทนคุณได้ แต่คุณต้องอธิบายทุกบรรทัดได้ — ถ้าอธิบายไม่ได้ แปลว่ายังไม่ผ่านบทนี้

สร้าง CartsController ที่เปิด POST /carts/add และลงทะเบียน OrdersModule บริบท: @src/orders/orders.service.ts @src/orders/dto/add-cart.dto.ts @src/products/products.controller.ts @src/products/products.module.ts @src/app.module.ts @.cursor/rules/project.mdc React app เรียก POST /carts/add (path นี้ต้องตรงตัว เพราะเราแทนที่ dummyjson โดยไม่แก้ฝั่ง frontend) และคาดหวัง status 201 OrdersService.create(dto: AddCartDto) คืน Promise<CartResponseDto> แล้ว products.controller.ts และ products.module.ts คือรูปแบบมาตรฐานของ controller และ module ในโปรเจกต์นี้ โครงสร้าง: สร้าง/แก้ไฟล์ตามนี้ ไม่มากไม่น้อยกว่านี้ - src/orders/carts.controller.ts (สร้างใหม่) - src/orders/orders.module.ts (สร้างใหม่) - src/app.module.ts (แก้ไข: เพิ่ม OrdersModule ต่อจาก ProductsModule) ข้อกำหนดทางเทคนิค: - carts.controller.ts: @Controller('carts') export class CartsController constructor(private readonly ordersService: OrdersService) handler @Post('add') create(@Body() dto: AddCartDto) return this.ordersService.create(dto) ไม่ต้องใส่ @HttpCode เพราะ POST ของ Nest ตอบ 201 อยู่แล้ว - orders.module.ts: @Module({ controllers: [CartsController], providers: [OrdersService] }) - ชื่อไฟล์ controller คือ carts.controller.ts (ตาม path) แต่ module และ service ใช้คำว่า orders (ตาม domain) ขอบเขต: - ห้ามติดตั้ง dependency ใหม่ - ห้ามแก้ไฟล์อื่นนอกจากที่ระบุ - ยังไม่ต้องเปิด CORS

ตรวจโค้ดที่ AI สร้าง

  • ชื่อไฟล์คือ carts.controller.ts และ class คือ CartsController ไม่ใช่ OrdersController
  • @Controller('carts') คู่กับ @Post('add') — รวมกันได้ POST /carts/add ไม่มี /orders โผล่ที่ไหน
  • parameter เป็น @Body() dto: AddCartDto มีชนิดกำกับครบ ไม่ใช่ any และไม่มี @Body('products') แยกส่วน
  • ไม่มี @HttpCode() ใน controller เลย
  • handler บรรทัดเดียว return this.ordersService.create(dto) — ไม่มี try/catch, ไม่มีการคิดเลข, ไม่มีการเรียก Prisma ตรง
  • orders.module.ts มี controllers: [CartsController] และ providers: [OrdersService] ไม่มี imports เกินมา
  • app.module.ts เพิ่ม OrdersModule ต่อจาก ProductsModule และ git diff src/app.module.ts เห็นแค่บรรทัด import กับบรรทัดใน array
  • import ทุกตัวลงท้ายด้วย .js ตามกติกา ESM ของโปรเจกต์

AI มักพลาดตรงนี้: ตั้งชื่อเป็น OrdersController พร้อม @Controller('orders') เพราะมันดูสอดคล้องกับชื่อ service และ module มากกว่า ผลคือโค้ดดูสวยแต่ React app ได้ 404 ทุกครั้งที่กดสั่งซื้อ อีกกรณีคือแถม @HttpCode(201) (ไม่ผิดผลลัพธ์ แต่เกินความจำเป็นและ prompt สั่งห้าม) หรือเผลอ import PrismaModule เข้า OrdersModule ซ้ำ ทั้งที่มันเป็น global module อยู่แล้ว

โค้ดอ้างอิงของบทนี้ (เทียบกับของคุณทีละบรรทัด):

// src/orders/carts.controller.ts
import { Body, Controller, Post } from '@nestjs/common';
import { AddCartDto } from './dto/add-cart.dto.js';
import { OrdersService } from './orders.service.js';

@Controller('carts')
export class CartsController {
  constructor(private readonly ordersService: OrdersService) {}

  @Post('add')
  create(@Body() dto: AddCartDto) {
    return this.ordersService.create(dto);
  }
}
// src/orders/orders.module.ts
import { Module } from '@nestjs/common';
import { CartsController } from './carts.controller.js';
import { OrdersService } from './orders.service.js';

@Module({
  controllers: [CartsController],
  providers: [OrdersService],
})
export class OrdersModule {}
// src/app.module.ts
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';
import { AppController } from './app.controller.js';
import { AppService } from './app.service.js';
import { OrdersModule } from './orders/orders.module.js';
import { PrismaModule } from './prisma/prisma.module.js';
import { ProductsModule } from './products/products.module.js';

@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    PrismaModule,
    ProductsModule,
    OrdersModule,
  ],
  controllers: [AppController],
  providers: [AppService],
})
export class AppModule {}

ถ้าอธิบายบรรทัดไหนไม่ได้ ยังไม่ผ่านบทนี้ — กลับไปอ่านส่วนแนวคิดก่อน

ผลลัพธ์ที่คาดหวัง

รัน npm run start:dev แล้ว log ต้องมีสองบรรทัดนี้ ถ้าไม่มี แปลว่าลืม import OrdersModule เข้า AppModule

LOG [RoutesResolver] CartsController {/carts}: +0ms
LOG [RouterExplorer] Mapped {/carts/add, POST} route +0ms

ยิง body เดียวกับที่ React app ส่ง จะได้ 201 Created พร้อมตัวเลขตรงกับ docs/contract/cart-add.txt ทุกตัว

curl -s -i -X POST http://localhost:3000/carts/add -H 'Content-Type: application/json' \
  -d '{"userId":1,"products":[{"id":1,"quantity":2}],"address":{"address":"1 Sukhumvit Rd","email":"a@b.com","phone":"0812345678"}}'
HTTP/1.1 201 Created

{"id":1,"products":[{"id":1,"title":"Essence Mascara Lash Princess","price":9.99,"quantity":2,"total":19.98,"discountPercentage":10.48,"discountedPrice":18,"thumbnail":"https://cdn.dummyjson.com/product-images/beauty/essence-mascara-lash-princess/thumbnail.webp"}],"total":19.98,"discountedTotal":18,"userId":1,"totalProducts":1,"totalQuantity":2}

id ที่ได้คือ 1 เพราะเป็นคำสั่งซื้อใบแรกในฐานข้อมูลของคุณ ส่วนในสัญญาที่จับจาก dummyjson เป็น 209 — ค่านี้เป็น id ที่รันตามลำดับของแต่ละฐานข้อมูล จึงต่างกันได้และไม่ถือว่าผิดสัญญา field อื่นทั้งหมด (total, discountedTotal, discountedPrice, totalProducts, totalQuantity) ต้องตรงเป๊ะ

สามกรณีที่เหลือคือกรณีที่พลาดแล้วรู้ยาก จึงต้องยิงดูให้เห็นด้วยตาทั้งหมด ไม่มี userId → 400 จาก ValidationPipe โดยที่ message เป็น array และมีสองข้อ เพราะทั้ง @IsInt() และ @Min(1) ไม่ผ่านพร้อมกัน

curl -s -i -X POST http://localhost:3000/carts/add -H 'Content-Type: application/json' \
  -d '{"products":[{"id":1,"quantity":1}],"address":{"address":"x","email":"a@b.com","phone":"1"}}'
HTTP/1.1 400 Bad Request

{"message":["userId must not be less than 1","userId must be an integer number"],"error":"Bad Request","statusCode":400}

สินค้า id ที่ไม่มีจริง → 404 จาก NotFoundException ที่ throw อยู่ข้างใน transaction ข้อความตรงกับที่ GET /products/:id ตอบในบทที่ 12

curl -s -i -X POST http://localhost:3000/carts/add -H 'Content-Type: application/json' \
  -d '{"userId":1,"products":[{"id":99999,"quantity":1}],"address":{"address":"x","email":"a@b.com","phone":"1"}}'
HTTP/1.1 404 Not Found

{"message":"Product with id '99999' not found","error":"Not Found","statusCode":404}

email ผิดรูป → 400 โดยชื่อ field ใน message มีคำนำหน้า address. ซึ่งเป็นหลักฐานว่า @ValidateNested() ของบทที่ 17 ไล่ตรวจเข้าไปข้างใน object จริง

curl -s -i -X POST http://localhost:3000/carts/add -H 'Content-Type: application/json' \
  -d '{"userId":1,"products":[{"id":1,"quantity":1}],"address":{"address":"x","email":"not-an-email","phone":"1"}}'
HTTP/1.1 400 Bad Request

{"message":["address.email must be an email"],"error":"Bad Request","statusCode":400}

ตรวจว่าใช้งานได้จริง

  • log ตอน start มีบรรทัด Mapped {/carts/add, POST} route
  • ยิงทั้งสี่ curl ข้างบนแล้วได้ status 201, 400, 404, 400 ตามลำดับ พร้อม body ตรงกับตัวอย่าง
  • แถวที่บันทึกลงฐานข้อมูลมีจริง และยอดตรงกับ response 
    docker compose exec db psql -U postgres -d ecommerce \
  -c 'SELECT id, "userId", total, "discountedTotal", "totalQuantity" FROM "Order";'
     id | userId | total | discountedTotal | totalQuantity
----+--------+-------+-----------------+---------------
  1 |      1 | 19.98 |              18 |             2
(1 row)
  • พิสูจน์ว่า transaction rollback จริง: หลังยิงครบทั้งสี่กรณี จำนวนคำสั่งซื้อต้องยังเป็น 1 ใบ — กรณี 404 ไม่ทิ้งใบครึ่ง ๆ ไว้ และสองกรณี 400 ถูกปัดตกก่อนถึง service 
    docker compose exec db psql -U postgres -d ecommerce -c 'SELECT count(*) FROM "Order";'
     count
-------
     1
(1 row)
  • docker compose exec db psql -U postgres -d ecommerce -c 'SELECT "orderId", "productId", title, price, quantity, total, "discountedPrice" FROM "OrderItem";' เห็นบรรทัดเดียวที่เก็บ snapshot ชื่อและราคาสินค้าไว้ครบ ไม่ใช่แค่ productId
  • npm run build && npm run lint ผ่านทั้งคู่
  • commit ผลงานของบทนี้: git add -A && git commit -m "feat: POST /carts/add"
