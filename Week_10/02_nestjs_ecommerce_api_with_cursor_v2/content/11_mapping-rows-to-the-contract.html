แปลงแถวจากฐานข้อมูลเป็นรูปทรงของ Product ใน docs/api-spec.md

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายความต่างระหว่าง รูปทรงที่เก็บ (แถวใน Postgres) กับ รูปทรงที่ตอบ (JSON ตาม docs/api-spec.md) ได้ทีละคีย์
  • เขียน mapper บริสุทธิ์ที่เป็นที่เดียวในโปรเจกต์ที่รู้จักทั้งสองรูปทรง
  • จัดการคีย์ที่ต้องหายไปทั้งคีย์ (ไม่ใช่เป็น null) ด้วย conditional spread ได้อย่างถูก type

สองรูปทรงที่ไม่เหมือนกัน และไม่ควรทำให้เหมือนกัน

ฐานข้อมูลกับ API มีเป้าหมายต่างกัน ตารางอยากได้คอลัมน์แบน ๆ ที่ index ได้ ส่วน client อยากได้ JSON ที่อ่านง่ายและซ้อนเป็นชั้น ลองดูจุดที่ทั้งสองไม่ตรงกันใน schema.prisma ของเรา

ในฐานข้อมูลใน docs/api-spec.mdงานที่ mapper ต้องทำ
คอลัมน์ width, height, depthobject dimensions { width, height, depth }ห่อสามคอลัมน์เป็น object เดียว
คอลัมน์ barcode, qrCode, createdAt, updatedAtobject meta { createdAt, updatedAt, barcode, qrCode }ห่อสี่คอลัมน์เป็น meta
categoryId + relation category (ทั้ง object)category เป็น string เช่น "beauty"ดึงแค่ category.slug ออกมา
DateTime → JavaScript DateISO string เช่น "2025-04-30T09:41:02.053Z"เรียก .toISOString() ทั้งสามจุด
discountPercentage Float? → ค่า null ได้ถ้าไม่มีส่วนลดจะไม่มีคีย์ discountPercentage เลยใส่คีย์เฉพาะเมื่อไม่ใช่ null
Review มี id และ productIdreview มีเพียงห้าคีย์เลือกเฉพาะห้าคีย์ ตัด id/productId ออก

ถ้าเราปล่อยให้แต่ละ endpoint แปลงเอง ความรู้เรื่อง 22 คีย์นี้จะกระจายไปทั้งโปรเจกต์ แล้ววันหนึ่งจะมี endpoint ที่ลืมแปลง date เราจึงรวบไว้ที่ฟังก์ชันเดียวชื่อ toProductResponse

ทำไม mapper ต้องเป็นฟังก์ชันบริสุทธิ์ ไม่ใช่ method ใน service

toProductResponse(product) รับค่าเข้า คืนค่าออก ไม่แตะฐานข้อมูล ไม่แตะ config ไม่มี state — เรียก export function ธรรมดาก็พอ ไม่ต้อง @Injectable() ผลที่ได้คือ

  • เทสได้โดยไม่ต้องยก Nest ขึ้นมาเลย: ประกอบ object เข้าไปตรง ๆ แล้วเทียบผลลัพธ์ ไม่ต้องมี Test.createTestingModule ไม่ต้องมีฐานข้อมูล
  • ทุก endpoint ที่คืนสินค้า (สินค้าชิ้นเดียว, รายการสินค้า, สินค้าตามหมวด) เรียกฟังก์ชันเดียวกัน จึงตอบรูปทรงเดียวกันแน่นอน
  • เวลา contract เปลี่ยน มีที่เดียวที่ต้องแก้

ทำไมใช้ class ไม่ใช่ interface สำหรับ response DTO

interface หายไปตอน compile จึงไม่เหลือข้อมูลอะไรให้ tool อ่านตอน runtime ภายหลังเราจะเปิด Swagger CLI plugin ซึ่งอ่าน field ของ class เพื่อสร้าง schema ของเอกสาร API ให้อัตโนมัติ ถ้าเราประกาศเป็น interface ไว้ตอนนี้ ก็ต้องมาเขียนใหม่ทั้งหมดตอนนั้น

ข้อกังวลปกติของการใช้ class คือ TypeScript จะบ่นว่า field ไม่ถูก assign ใน constructor (strictPropertyInitialization) แต่ tsconfig.json ของ scaffold Nest 12 ตั้ง "strictPropertyInitialization": false ไว้ให้แล้ว ดังนั้นการประกาศเปล่า ๆ แบบ title: string; จึง compile ผ่าน โดยที่ "strict": true ยังเปิดอยู่ตามปกติ

คีย์ที่ต้องหายไปทั้งคีย์: conditional spread

docs/api-spec.md ระบุ discountPercentage?: number — ไม่ใช่ discountPercentage: number | null สินค้าที่ไม่มีส่วนลดต้องไม่มีคีย์ discountPercentage เลยในสัญญาของเรา ไม่ใช่ null วิธีที่เราใช้คือ spread แบบมีเงื่อนไข

...(product.discountPercentage !== null ? { discountPercentage: product.discountPercentage } : {}),

ถ้าเงื่อนไขเป็นเท็จ เรา spread object ว่าง คีย์จึงไม่เกิดขึ้นเลย ทั้งใน object จริงและใน type ที่ TypeScript อนุมาน

ทางเลือกที่ดูสั้นกว่าคือ discountPercentage: product.discountPercentage ?? undefined — ผล JSON เหมือนกัน เพราะ JSON.stringify ตัดคีย์ที่เป็น undefined ทิ้งอยู่แล้ว แต่มันเปิดช่องให้เขียน type ของ DTO เป็น discountPercentage: number | null ตามไปด้วย ซึ่งจะกลายเป็นการประกาศว่า API ของเราส่ง null ได้ (ทั้งที่ไม่เคยส่ง) เราจึงเลือก spread แบบมีเงื่อนไข คู่กับ DTO ที่ประกาศ discountPercentage?: number — ? ตัวเดียวในไฟล์ทั้งไฟล์

type ของแถวที่มี relation ติดมาด้วย

Product ที่ Prisma export ให้คือแถวเปล่า ๆ ของตาราง Product เท่านั้น — ไม่มี category ไม่มี reviews ค่าพวกนี้จะติดมาเฉพาะเมื่อ query สั่ง include เราจึงประกาศ type ของ input ให้ตรงกับที่สั่ง

export type ProductWithRelations = Product & { category: Category; reviews: Review[] };

type สามตัวนี้มาจาก Prisma Client ที่เรา generate ไว้ที่ src/generated/prisma/client.ts (ตามที่ตั้ง output ไว้ใน schema.prisma) ไฟล์นั้น export Product, Category, Review ให้พร้อมใช้ และเราเรียกด้วย import type เพราะต้องการเฉพาะ type ไม่ต้องการโค้ดตอน runtime

โครงไฟล์ด้านบนคือของโค้ดอ้างอิง — Cursor อาจแบ่งหรือตั้งชื่อต่างไปได้ ขอแค่ได้ผลลัพธ์นี้

  • response DTO — class ของ Product ที่มี 22 field เรียงตาม docs/api-spec.md, มี ? ได้ที่ discountPercentage ที่เดียว พร้อม class ของ Category และซองรายการ { products, total, skip, limit }
  • mapper — ฟังก์ชันบริสุทธิ์ที่รับแถวสินค้าพร้อม category และ reviews แล้วคืนรูปทรง Product ตามสัญญา / ไม่มี any ไม่มี as และไม่ส่ง id/productId ของ review ออกไป

บทนี้ยังไม่แตะ service เลย — ยังไม่มี endpoint ไหนเรียก mapper จนถึงบทถัดไป

สั่ง Cursor สร้าง DTO และ mapper แล้วตรวจคีย์ให้ครบ 22 ตัว

commit งานก่อน แล้วเปิดแชทใหม่ใน Cursor โหมด Agent (git add -A && git commit -m "chore: before product mapper") เปิด docs/api-spec.md ไว้ข้าง ๆ ด้วย เพราะรอบนี้เราจะนับคีย์เทียบกันจริง ๆ

สร้าง response DTO และ mapper ที่แปลงแถวสินค้าจาก Prisma เป็นรูปทรง Product ตาม docs/api-spec.md ผลลัพธ์ที่ต้องได้: - npm run build ได้ exit 0 และ npm run lint ไม่พิมพ์อะไรออกมา - มี response DTO เป็น class (ไม่ใช่ interface เพราะตัวสร้างเอกสาร Swagger อ่าน field จาก class เท่านั้น) ของ Product ที่มี field ครบ 22 ตัวเรียงตาม section Product ใน docs/api-spec.md โดย discountPercentage เป็น field optional ตัวเดียว และไม่มี type null ในไฟล์ DTO - มี DTO class ของ Category { slug, name, url } และของซองรายการ { products, total, skip, limit } ด้วย - มีฟังก์ชันแปลงแถวเป็นรูปทรง Product ที่ใช้ซ้ำได้ใน endpoint ถัดไป เป็นฟังก์ชันบริสุทธิ์ (ไม่แตะฐานข้อมูล ไม่แตะ config) รับแถวสินค้าที่มี category และ reviews ติดมา แล้วคืนรูปทรง Product ตาม docs/api-spec.md: category เป็น slug string, dimensions { width, height, depth } และ meta { createdAt, updatedAt, barcode, qrCode } เป็น object ซ้อน, date/createdAt/updatedAt เป็น ISO string เช่น "2025-04-30T09:41:02.053Z" review แต่ละตัวมีห้าคีย์ { rating, comment, date, reviewerName, reviewerEmail } เท่านั้น (ไม่มี id หรือ productId) สินค้าที่ discountPercentage เป็น null ใน DB ต้องไม่มีคีย์ discountPercentage เลย ไม่ใช่มีคีย์เป็น null หรือ undefined - ถ้าลองส่ง category ทั้ง object แทน slug ต้อง build ไม่ผ่าน (type ของ DTO เป็นยามจริง) ขอบเขต: - ห้ามติดตั้ง dependency ใหม่ - ยังไม่ต้องสร้าง endpoint ที่ใช้ mapper และยังไม่ต้องแก้ service

ตรวจโค้ดที่ AI สร้าง

  • DTO เป็น class (ไม่ใช่ interface) และ response DTO ของ Product มีเครื่องหมาย ? เพียงจุดเดียวที่ discountPercentage — ค้นคำว่า null ในไฟล์ DTO ต้องไม่เจอเลย
  • response DTO ของ Product มี 22 field เรียงตามลำดับของ docs/api-spec.md (นับเทียบกับ product id 1 จริงในฐานข้อมูล — SELECT * FROM "Product" WHERE id = 1 — ทีละบรรทัด)
  • ไม่มี Date object หลุดออกไปเป็น field — วันที่ทั้งสามจุด (date ของ review, createdAt, updatedAt) กลายเป็น ISO string
  • สินค้าที่ไม่มีส่วนลดไม่มีคีย์ discountPercentage เลย และ type ใน DTO ไม่ได้ประกาศว่าเป็น null ได้
  • review ที่ map ออกมามีห้าคีย์เท่านั้น ไม่มี id ไม่มี productId
  • mapper ไม่ inject อะไร ไม่แตะฐานข้อมูลหรือ config, ไม่มีไฟล์ที่ไม่เกี่ยวกับเป้าหมายถูกแก้ (service เดิมยังไม่ถูกแตะ), npm run build ผ่าน และไม่มี any / as / !

AI มักพลาดตรงนี้: เขียน discountPercentage: product.discountPercentage ?? undefined — runtime ยังถูก (JSON ตัด undefined ทิ้ง) แต่เมื่อเขียนแบบนี้ Cursor มักไปประกาศใน DTO เป็น discountPercentage: number | null หรือ discountPercentage: number | undefined ตามด้วย ให้เปิด DTO เช็กเสมอ อีกข้อที่พลาดบ่อยคือ category: product.category (ยัด object ทั้งก้อนเข้าไป) แทนที่จะเป็น product.category.slug — TypeScript จะฟ้องให้ ถ้า DTO ประกาศ category: string ไว้ถูก ซึ่งเป็นอีกเหตุผลที่เราเขียน DTO ก่อน mapper

src/products/product.mapper.ts

import type { Category, Product, Review } from '../generated/prisma/client.js';
import { ProductResponseDto } from './dto/product-response.dto.js';

export type ProductWithRelations = Product & { category: Category; reviews: Review[] };

export function toProductResponse(product: ProductWithRelations): ProductResponseDto {
  return {
    id: product.id,
    title: product.title,
    description: product.description,
    category: product.category.slug,
    price: product.price,
    ...(product.discountPercentage !== null ? { discountPercentage: product.discountPercentage } : {}),
    rating: product.rating,
    stock: product.stock,
    tags: product.tags,
    brand: product.brand,
    sku: product.sku,
    weight: product.weight,
    dimensions: { width: product.width, height: product.height, depth: product.depth },
    warrantyInformation: product.warrantyInformation,
    shippingInformation: product.shippingInformation,
    availabilityStatus: product.availabilityStatus,
    reviews: product.reviews.map((review) => ({
      rating: review.rating,
      comment: review.comment,
      date: review.date.toISOString(),
      reviewerName: review.reviewerName,
      reviewerEmail: review.reviewerEmail,
    })),
    returnPolicy: product.returnPolicy,
    minimumOrderQuantity: product.minimumOrderQuantity,
    meta: {
      createdAt: product.createdAt.toISOString(),
      updatedAt: product.updatedAt.toISOString(),
      barcode: product.barcode,
      qrCode: product.qrCode,
    },
    images: product.images,
    thumbnail: product.thumbnail,
  };
}

ผลลัพธ์ที่คาดหวัง

มีไฟล์ใหม่สองไฟล์ และ npm run build จบด้วย exit 0 โดยไม่มี error ตามด้วย npm run lint ที่เงียบสนิท — ยังไม่มีอะไรให้ยิง curl ในบทนี้ เพราะไม่มี endpoint ไหนเรียก toProductResponse เลย คนที่พิสูจน์ว่า mapper ถูกจริงคือบทถัดไป

การที่ build ผ่านไม่ได้แค่บอกว่า syntax ถูก — มันบอกว่า type ของทุกคอลัมน์ที่ mapper หยิบมามีอยู่จริงใน Prisma Client ที่ generate ไว้ และรูปทรงที่ประกอบขึ้นตรงกับ ProductResponseDto ทุกคีย์

ตรวจว่าใช้งานได้จริง

  • npm run build ได้ exit 0 (ไม่มี error TS ใด ๆ) และ npm run lint ไม่พิมพ์อะไรออกมา
  • นับคีย์: sed -n '/export class ProductResponseDto/,/^}/p' src/products/dto/product-response.dto.ts | grep -c ';' ต้องได้ 22 — ยังไม่มี endpoint ให้ยิง curl ในบทนี้ (ดูหัวข้อ "ผลลัพธ์ที่คาดหวัง") จึงนับจาก field ของ DTO เอง เทียบกับ docs/api-spec.md ทีละบรรทัด
  • ลองแก้ category: product.category.slug เป็น category: product.category ชั่วคราวแล้ว npm run build — ต้องได้ error ทันที (ยืนยันว่า DTO ทำหน้าที่เป็นยาม) แล้วแก้กลับ
  • grep -n "any\|as " src/products/product.mapper.ts src/products/dto/product-response.dto.ts — ต้องไม่เจอ
  • commit ผลงานด้วย git add -A && git commit -m "feat: product response dto and mapper"
