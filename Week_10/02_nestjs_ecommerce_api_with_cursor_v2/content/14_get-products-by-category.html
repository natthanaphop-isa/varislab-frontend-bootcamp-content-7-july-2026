GET /products/category/:slug

เมื่อจบบทนี้ คุณจะสามารถ

  • กรองสินค้าด้วยเงื่อนไขที่อยู่บน relation ({ category: { slug } }) โดยไม่ต้อง query ตาราง category แยก
  • อธิบายว่าทำไม slug ที่ไม่มีอยู่จริงต้องได้ 200 พร้อม list ว่าง ไม่ใช่ 404
  • เห็นผลตอบแทนของการแยก paginate ออกมาในบทที่ 13: endpoint ใหม่ใช้โค้ดสองบรรทัด

บทนี้สั้นมาก และนั่นคือประเด็น

บทที่ 13 เราไม่ได้เขียนแค่ findAll — เราเขียน paginate(where, skip, limit) ที่รับ เงื่อนไขอะไรก็ได้ เข้ามา แล้วให้ findAll ส่ง {} (ไม่กรองอะไร) เข้าไป บทนี้จึงเหลืองานแค่หาว่า "เงื่อนไขของหมวดหมู่" เขียนอย่างไร

findByCategory(slug: string, query: PaginationQueryDto) {
  return this.paginate({ category: { slug } }, query.skip, query.limit);
}

เท่านี้ก็ได้ pagination, total ที่นับเฉพาะหมวดนั้น, orderBy, include, การ map เป็น contract และกติกา limit=0 มาครบ โดยไม่ต้อง copy อะไรเลย ถ้าตอนนั้นเราปล่อยให้ findAll เขียน $transaction ไว้ในตัวเอง บทนี้จะกลายเป็นการ copy สามสิบบรรทัดมาแก้คำเดียว — ซึ่งคือจุดเริ่มของความไม่ตรงกันในอนาคต

กรองผ่าน relation ไม่ใช่ผ่าน categoryId

ในฐานข้อมูล สินค้าอ้างหมวดหมู่ด้วยคอลัมน์ categoryId ที่เป็นตัวเลข แต่ client ส่ง slug มาให้ ทางที่คิดขึ้นมาก่อนคือสองขั้น: หา category จาก slug ก่อน ได้ id แล้วค่อยกรองสินค้า — แต่ Prisma ให้เราเขียนเงื่อนไขข้าม relation ได้ในครั้งเดียว (ทบทวน Week_09 บทที่ 26)

where: { category: { slug } }

Prisma แปลงก้อนนี้เป็น SQL ที่ join ไปที่ตาราง Category แล้วกรองด้วย slug ในคำสั่งเดียว ผลคือไป-กลับฐานข้อมูลครั้งเดียวแทนสองครั้ง และไม่มีช่องให้ข้อมูลเปลี่ยนระหว่างสอง query

slug ที่ไม่มีอยู่: 200 ไม่ใช่ 404

นี่คือจุดที่ความรู้สึกเรื่อง REST จะขัดกับสัญญา เปิด docs/contract/products-by-category-unknown.json ที่วางไว้ในบทที่ 3 — dummyjson ตอบ status 200 พร้อม

{"products":[],"total":0,"skip":0,"limit":0}

เหตุผลที่มันสมเหตุสมผล: endpoint นี้ตอบ ผลการค้นหา ไม่ใช่ ตัว resource การค้นหาที่ไม่พบอะไรคือการค้นหาที่สำเร็จแต่ได้ศูนย์รายการ ต่างจาก GET /products/9999 ในบทที่ 12 ที่ขอ resource ชิ้นหนึ่งซึ่งไม่มีอยู่ — อันนั้น 404 ถูกต้อง

และเหตุผลที่สำคัญกว่า: หน้า Category ของ React app อ่าน total เพื่อตัดสินใจว่าจะโชว์ข้อความ "ไม่พบสินค้า" หรือโชว์ตะแกรงสินค้า ถ้าเราตอบ 404 มันจะเด้งไปหน้า error ทั้งหน้า แทนที่จะโชว์ข้อความว่างเปล่าอย่างสุภาพ

สังเกต limit: 0 ด้วย — ตามกติกาที่เราคุยไว้ในบทที่ 13 คือ limit = จำนวนสินค้าที่ส่งกลับจริง ไม่ใช่ค่าที่ client ขอมา ดังนั้นแม้จะยิง ?limit=5 หมวดที่ว่างเปล่าก็ตอบ limit: 0 — และเพราะ paginate ของเราคืน rows.length อยู่แล้ว ข้อนี้จึงถูกต้องโดยอัตโนมัติ ไม่ต้องเขียนกรณีพิเศษ

ข้อกำหนดในรอบนี้จึงมีคำว่า ห้าม throw อยู่ด้วย — เป็นการปิดทางที่ AI (และคนส่วนใหญ่) จะเลือกโดยสัญชาตญาณ

ลำดับ route: ปลอดภัยอยู่แล้ว แต่ยังต้องวางให้ถูก

category/:slug มีสอง segment ส่วน :id มีหนึ่ง segment จึงชนกันไม่ได้ทางเทคนิค — /products/category/beauty ไม่มีทางถูกจับด้วย /products/:id แต่เราก็ยังวาง handler ใหม่ไว้ก่อน @Get() และ @Get(':id') ด้วยเหตุผลสองข้อ

  • รักษากฎเดียวที่จำง่าย: คำตายตัวมาก่อน parameter ตลอดทั้งไฟล์ ไม่ต้องมานั่งคิดเป็นราย route ว่าอันนี้ชนไหม
  • อ่าน controller จากบนลงล่างแล้วเห็นลำดับจากเฉพาะเจาะจงไปกว้าง ซึ่งตรงกับลำดับที่ router ลองจับจริง

ลำดับสุดท้ายของ ProductsController คือ findCategories → findByCategory → findAll → findOne

เป้าหมายของบทนี้

src/products/

└── products.service.ts               (แก้ไข: เพิ่ม method เดียว)
  • src/products/products.service.ts — สัญญา: ต้องเพิ่ม findByCategory(slug, query) ที่เรียก this.paginate({ category: { slug } }, …) / ต้องไม่ query ตาราง Category แยก และต้องไม่ throw เมื่อไม่พบหมวดหมู่
  • src/products/products.controller.ts — สัญญา: ต้องเพิ่ม @Get('category/:slug') ไว้ถัดจาก findCategories และก่อน findAll / ต้องไม่แก้ handler อื่น

ห้ามแตะ paginate, findAll, findOne และ productInclude — ถ้า diff ของบทนี้ยาวกว่าสิบบรรทัด แปลว่ามีอะไรเกินมา

สั่ง Cursor เพิ่ม endpoint ตามหมวดหมู่

commit งานก่อน แล้วเปิดแชทใหม่ใน Cursor โหมด Agent (git add -A && git commit -m "chore: before category endpoint") จากนั้นส่ง prompt นี้

เพิ่ม endpoint GET /products/category/:slug ที่ใช้ pagination เดิม และตอบ list ว่างเมื่อไม่พบหมวดหมู่ บริบท: @src/products/products.controller.ts @src/products/products.service.ts @src/products/dto/pagination-query.dto.ts @docs/contract/products-by-category.json @docs/contract/products-by-category-unknown.json @.cursor/rules/project.mdc มี private method paginate(where, skip, limit) ที่คืน ProductListResponseDto อยู่แล้ว docs/contract/products-by-category.json คือ response จริงของ GET /products/category/beauty?limit=2&skip=0 (envelope เดียวกับ GET /products, total คือจำนวนสินค้าในหมวดนั้น) docs/contract/products-by-category-unknown.json คือ response จริงของ slug ที่ไม่มี: status 200 กับ { products: [], total: 0, skip, limit } — ไม่ใช่ 404 โครงสร้าง: แก้ไฟล์ตามนี้ ไม่มากไม่น้อยกว่านี้ - src/products/products.service.ts (แก้ไข: เพิ่ม method เดียว) - src/products/products.controller.ts (แก้ไข: เพิ่ม handler เดียว) ข้อกำหนดทางเทคนิค: - service: findByCategory(slug: string, query: PaginationQueryDto) คืน this.paginate({ category: { slug } }, query.skip, query.limit) ห้าม query ตาราง category แยกต่างหาก ห้าม throw เมื่อไม่พบ - controller: handler @Get('category/:slug') findByCategory(@Param('slug') slug: string, @Query() query: PaginationQueryDto) วางไว้ถัดจาก findCategories และก่อน findAll - ห้ามแก้ paginate, findAll, findOne, productInclude ขอบเขต: - ห้ามติดตั้ง dependency ใหม่ - ห้ามแก้ไฟล์อื่นนอกจากที่ระบุ - ยังไม่ต้องเขียน script ตรวจ contract

ตรวจโค้ดที่ AI สร้าง

  • เงื่อนไขเขียนเป็น relation filter { category: { slug } } — ไม่ใช่ { categoryId: … }
  • ไม่มี findUnique หรือ findFirst บนตาราง category เพิ่มเข้ามา
  • ไม่มี NotFoundException ใน findByCategory และไม่มี if (!category) ใด ๆ
  • ใน controller handler ใหม่อยู่ระหว่าง findCategories กับ findAll
  • @Param('slug') slug: string ไม่มี pipe แปลงค่า (slug เป็น string ตามธรรมชาติ)
  • git diff --stat เห็นแค่สองไฟล์ และรวมกันประมาณสิบบรรทัด — paginate, findAll, findOne, productInclude ไม่ถูกแตะ

AI มักพลาดตรงนี้: หา category จาก slug ก่อนแล้วโยน 404 ถ้าไม่พบ — เป็นพฤติกรรมที่ดูถูกหลักการ REST และเป็นสิ่งที่ทุกคอร์สสอน แต่มันผิดสัญญาของ dummyjson และทำให้หน้า Category ของ React app เด้งไปหน้า error ตอนที่ควรจะโชว์ข้อความ "ไม่พบสินค้า" ถ้าเจอโค้ดแบบนี้ ให้ลบทั้งก้อนทิ้ง ไม่ใช่แก้ status code

โค้ดอ้างอิงของบทนี้ (เทียบกับของคุณทีละบรรทัด):

src/products/products.service.ts

import { Injectable, NotFoundException } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import type { Prisma } from '../generated/prisma/client.js';
import { PrismaService } from '../prisma/prisma.service.js';
import { PaginationQueryDto } from './dto/pagination-query.dto.js';
import { ProductListResponseDto, ProductResponseDto } from './dto/product-response.dto.js';
import { toProductResponse } from './product.mapper.js';

const productInclude = {
  category: true,
  reviews: { orderBy: { id: 'asc' } },
} satisfies Prisma.ProductInclude;

@Injectable()
export class ProductsService {
  constructor(
    private readonly prisma: PrismaService,
    private readonly config: ConfigService,
  ) {}

  async findCategories() {
    const appUrl = this.config.getOrThrow<string>('APP_URL');
    const categories = await this.prisma.category.findMany({ orderBy: { id: 'asc' } });
    return categories.map(({ slug, name }) => ({
      slug,
      name,
      url: `${appUrl}/products/category/${slug}`,
    }));
  }

  findAll(query: PaginationQueryDto) {
    return this.paginate({}, query.skip, query.limit);
  }

  findByCategory(slug: string, query: PaginationQueryDto) {
    return this.paginate({ category: { slug } }, query.skip, query.limit);
  }

  async findOne(id: number): Promise<ProductResponseDto> {
    const product = await this.prisma.product.findUnique({
      where: { id },
      include: productInclude,
    });
    if (!product) {
      throw new NotFoundException(`Product with id '${id}' not found`);
    }
    return toProductResponse(product);
  }

  private async paginate(
    where: Prisma.ProductWhereInput,
    skip: number,
    limit: number,
  ): Promise<ProductListResponseDto> {
    const [rows, total] = await this.prisma.$transaction([
      this.prisma.product.findMany({
        where,
        skip,
        take: limit === 0 ? undefined : limit,
        orderBy: { id: 'asc' },
        include: productInclude,
      }),
      this.prisma.product.count({ where }),
    ]);
    return { products: rows.map(toProductResponse), total, skip, limit: rows.length };
  }
}

src/products/products.controller.ts

import { Controller, Get, Param, ParseIntPipe, Query } from '@nestjs/common';
import { PaginationQueryDto } from './dto/pagination-query.dto.js';
import { ProductsService } from './products.service.js';

@Controller('products')
export class ProductsController {
  constructor(private readonly productsService: ProductsService) {}

  @Get('categories')
  findCategories() {
    return this.productsService.findCategories();
  }

  @Get('category/:slug')
  findByCategory(@Param('slug') slug: string, @Query() query: PaginationQueryDto) {
    return this.productsService.findByCategory(slug, query);
  }

  @Get()
  findAll(@Query() query: PaginationQueryDto) {
    return this.productsService.findAll(query);
  }

  @Get(':id')
  findOne(@Param('id', ParseIntPipe) id: number) {
    return this.productsService.findOne(id);
  }
}
