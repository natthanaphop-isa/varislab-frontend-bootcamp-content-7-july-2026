Seed สินค้าจริงจาก dummyjson

เมื่อจบบทนี้ คุณจะสามารถ

  • เขียน seed script ที่รันนอก NestJS ด้วย tsx และสร้าง PrismaClient พร้อม adapter เอง
  • อธิบายได้ว่าทำไมต้องลบข้อมูลตามลำดับ foreign key และทำไมต้องห่อทั้งหมดไว้ใน transaction
  • ยืนยันด้วย psql ว่าฐานข้อมูลมีสินค้า 194 ชิ้น หมวดหมู่ 24 หมวด และรีวิว 582 รายการ

seed คือสคริปต์ธรรมดา ไม่ใช่ส่วนหนึ่งของแอป

เราเคย seed ฐานข้อมูลมาแล้วใน Week_08 บทที่ 19 แนวคิดเดิมทั้งหมด: seed คือไฟล์ที่รันด้วยมือเมื่อเราต้องการเติมข้อมูลตั้งต้น ไม่ใช่ provider ของ Nest และไม่ถูกเรียกตอนแอป boot สามข้อที่ต้องคุมให้ดีคือ ลบของเก่าตามลำดับ foreign key, แทรกทีเดียวหลายแถวด้วย createMany และทำให้รันซ้ำได้ไม่พัง

ลำดับการลบของเราคือ review → product → category เสมอ — ลูกก่อนแม่ ถ้าสลับไปลบ category ก่อน PostgreSQL จะปฏิเสธ เพราะยังมีแถวใน Product ที่ categoryId ชี้มาหาอยู่ (foreign key เป็น restrict ตามค่าปริยาย) สังเกตว่าเราไม่พึ่ง onDelete: Cascade ของ Review ให้ลบแทน ทั้งที่มันทำได้ เพราะการเขียนลำดับออกมาชัด ๆ อ่านแล้วเข้าใจเจตนาได้ทันที

ทำไมดึงสดจาก dummyjson ไม่ commit สินค้า 194 ชิ้นไว้ในโปรเจกต์

ไฟล์ใน docs/contract/ คือ ตัวอย่างรูปทรง ของ response ที่เราใช้เป็นสัญญา (สินค้าหนึ่งชิ้น หนึ่งหน้า หนึ่งรายการหมวดหมู่) ส่วนแคตตาล็อกทั้งก้อนคือ ข้อมูล ซึ่งไม่ควรอยู่ใน git — มันใหญ่ เปลี่ยนได้ตลอดโดยไม่กระทบสัญญา และการดึงสดยังทำให้บทที่ 15 (ตรวจสัญญาอัตโนมัติ) เทียบกับของจริงได้ตรงกันมากขึ้น สิ่งที่เราคงไว้เหมือนเดิมเป๊ะ ๆ คือ id ของทุกชิ้น เพราะ React app ลิงก์ด้วย id ตรง ๆ — ถ้า id ขยับ ลิงก์ที่ผู้ใช้บุ๊กมาร์กไว้จะพาไปสินค้าผิดชิ้น

createMany สามครั้ง ไม่ใช่ create 194 ครั้ง

เขียนแบบวน loop เรียก create ทีละชิ้นก็ได้ผลถูกต้อง แต่หมายถึงการคุยกับฐานข้อมูลอย่างน้อย 194 + 582 รอบ ช้ากว่ากันหลายเท่า createMany ส่งทั้งชุดไปใน statement เดียว

  • เรียกสามครั้งตามลำดับ: category → product → review (แม่ก่อนลูก ตรงข้ามกับลำดับการลบ) เพราะ Product.categoryId ต้องมีหมวดหมู่อยู่ก่อน และ Review.productId ต้องมีสินค้าอยู่ก่อน
  • ระหว่างสองขั้นแรกเราต้องอ่าน Category กลับมาทำ Map จาก slug ไป id เพราะ dummyjson ส่งหมวดหมู่มาเป็น slug string ("category": "beauty") แต่ตารางเราต้องการเลข categoryId
  • createMany แทรกตามลำดับของ array ที่ส่งไป จึงได้ลำดับรีวิวเหมือนที่ dummyjson ส่งมา — สำคัญกับบทที่ 11 ที่ต้อง map ออกไปให้เหมือนต้นฉบับ

ทำไมต้องรันด้วย tsx

Prisma generate client ออกมาเป็นไฟล์ .ts ใน src/generated/prisma/ แต่ข้างในไฟล์เหล่านั้น import กันด้วยนามสกุล .js (ตามกติกาของ ES module) Node เปล่า ๆ รันไฟล์ .ts ไม่ได้และไล่ import แบบนี้ไม่ถูก ส่วน tsx ทำทั้งสองอย่าง: แปลง TypeScript ให้ตอนรัน และแก้ปัญหา path ให้ด้วย เราจึงเพิ่ม script "db:seed": "tsx prisma/seed.ts" ไว้ใน package.json แล้วเรียกด้วย npm run db:seed

เพราะสคริปต์นี้อยู่นอก NestJS มันจึงไม่มี ConfigModule มาโหลด .env ให้ ต้อง import 'dotenv/config' เป็นบรรทัดแรกเอง และต้อง new PrismaClient({ adapter: … }) เองเหมือนที่ PrismaService ทำ — นี่เป็นข้อยกเว้นเดียวของกฎ ห้าม new PrismaClient ในไฟล์อื่น ใน .cursor/rules/project.mdc เพราะไฟล์นี้ไม่ได้อยู่ใน dependency injection ของ Nest เลย

ทำไมต้องห่อด้วย transaction

ขั้นตอนของเราคือ ลบทั้งหมดแล้วเติมใหม่ ถ้า fetch ล้มกลางทาง หรือสินค้าชิ้นใดมี slug ที่ไม่มีในตาราง Category แล้ว error ถูก throw หลังลบไปแล้ว เราจะเหลือฐานข้อมูลว่างหรือมีแคตตาล็อกครึ่งเดียว prisma.$transaction(async (tx) => { … }) ทำให้ทุกคำสั่งข้างในสำเร็จพร้อมกันหรือย้อนกลับพร้อมกัน — หลักการเดียวกับ Week_09 บทที่ 29 ข้อสำคัญคือข้างใน block นี้ต้องเรียกผ่าน tx ไม่ใช่ prisma ไม่อย่างนั้นคำสั่งนั้นจะหลุดออกไปนอก transaction

ตรวจโค้ดที่ AI สร้าง

  • บรรทัดแรกของไฟล์คือ import 'dotenv/config'; — ถ้าอยู่บรรทัดอื่นหรือไม่มี DATABASE_URL จะเป็น undefined ตอนสร้าง client
  • สร้าง client ด้วย new PrismaClient({ adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }) }) และ import PrismaClient จาก '../src/generated/prisma/client.js' (สังเกต ../src/ เพราะไฟล์นี้อยู่ในโฟลเดอร์ prisma/)
  • ลำดับ deleteMany คือ review → product → category และทุกคำสั่งข้างใน transaction เรียกผ่าน tx ไม่ใช่ prisma
  • มี createMany สามครั้งพอดี ไม่มี upsert และไม่มี for/map ที่เรียก create ทีละชิ้น
  • ส่ง id: product.id ตรง ๆ (ถ้า AI ตัด field นี้ออก id จะหลุดไปเป็นค่าอื่นและ React app จะลิงก์ผิด)
  • brand: product.brand ?? null — ใช้ ?? ไม่ใช่ || (ถ้าใช้ || แบรนด์ที่เป็น string ว่างจะกลายเป็น null ไปด้วย)
  • สาม field ที่เป็นวันเวลาถูกห่อด้วย new Date(...): createdAt, updatedAt ของสินค้า และ date ของรีวิว — Prisma ต้องการ DateTime ไม่ใช่ string
  • ไม่มี any และไม่มี non-null assertion (!) — การหา id จาก slug ต้องเป็นฟังก์ชันที่ throw Error พร้อมชื่อ slug เมื่อไม่พบ
  • package.json มี "db:seed": "tsx prisma/seed.ts" และ dependencies ไม่มีตัวใหม่ (โดยเฉพาะต้องไม่มี axios หรือ node-fetch)

AI มักพลาดตรงนี้: วน create ทีละชิ้น (ได้ผลถูกแต่ช้ามาก และผิดข้อกำหนดที่เราเขียนไว้) หรือลืม ?limit=0 แล้วดึงมาแค่ 30 ชิ้นตามค่าปริยายของ dummyjson — ข้อหลังนี้ดูจาก log ไม่ออกเลยถ้าไม่นับแถว การตรวจจำนวนด้วย psql ในหัวข้อถัดไปคือด่านที่จับได้

โค้ดอ้างอิงของบทนี้ (เทียบกับของคุณทีละบรรทัด):

// prisma/seed.ts
import 'dotenv/config';
import { PrismaPg } from '@prisma/adapter-pg';
import { PrismaClient } from '../src/generated/prisma/client.js';

interface DummyCategory {
  slug: string;
  name: string;
  url: string;
}

interface DummyReview {
  rating: number;
  comment: string;
  date: string;
  reviewerName: string;
  reviewerEmail: string;
}

interface DummyProduct {
  id: number;
  title: string;
  description: string;
  category: string;
  price: number;
  discountPercentage: number;
  rating: number;
  stock: number;
  tags: string[];
  brand?: string;
  sku: string;
  weight: number;
  dimensions: { width: number; height: number; depth: number };
  warrantyInformation: string;
  shippingInformation: string;
  availabilityStatus: string;
  reviews: DummyReview[];
  returnPolicy: string;
  minimumOrderQuantity: number;
  meta: { createdAt: string; updatedAt: string; barcode: string; qrCode: string };
  images: string[];
  thumbnail: string;
}

const SOURCE = 'https://dummyjson.com';

const prisma = new PrismaClient({
  adapter: new PrismaPg({ connectionString: process.env.DATABASE_URL }),
});

async function fetchJson<T>(path: string): Promise<T> {
  const response = await fetch(`${SOURCE}${path}`);
  if (!response.ok) {
    throw new Error(`${path} responded ${response.status}`);
  }
  return response.json() as Promise<T>;
}

async function main() {
  const categories = await fetchJson<DummyCategory[]>('/products/categories');
  const { products } = await fetchJson<{ products: DummyProduct[] }>('/products?limit=0');

  await prisma.$transaction(async (tx) => {
    await tx.review.deleteMany();
    await tx.product.deleteMany();
    await tx.category.deleteMany();

    await tx.category.createMany({
      data: categories.map(({ slug, name }) => ({ slug, name })),
    });
    const categoryIdBySlug = new Map(
      (await tx.category.findMany()).map((category) => [category.slug, category.id]),
    );
    const categoryId = (slug: string): number => {
      const id = categoryIdBySlug.get(slug);
      if (id === undefined) {
        throw new Error(`Unknown category slug: ${slug}`);
      }
      return id;
    };

    await tx.product.createMany({
      data: products.map((product) => ({
        id: product.id,
        title: product.title,
        description: product.description,
        price: product.price,
        discountPercentage: product.discountPercentage,
        rating: product.rating,
        stock: product.stock,
        tags: product.tags,
        brand: product.brand ?? null,
        sku: product.sku,
        weight: product.weight,
        width: product.dimensions.width,
        height: product.dimensions.height,
        depth: product.dimensions.depth,
        warrantyInformation: product.warrantyInformation,
        shippingInformation: product.shippingInformation,
        availabilityStatus: product.availabilityStatus,
        returnPolicy: product.returnPolicy,
        minimumOrderQuantity: product.minimumOrderQuantity,
        barcode: product.meta.barcode,
        qrCode: product.meta.qrCode,
        images: product.images,
        thumbnail: product.thumbnail,
        createdAt: new Date(product.meta.createdAt),
        updatedAt: new Date(product.meta.updatedAt),
        categoryId: categoryId(product.category),
      })),
    });

    await tx.review.createMany({
      data: products.flatMap((product) =>
        product.reviews.map((review) => ({
          productId: product.id,
          rating: review.rating,
          comment: review.comment,
          date: new Date(review.date),
          reviewerName: review.reviewerName,
          reviewerEmail: review.reviewerEmail,
        })),
      ),
    });
  });

  const reviewCount = products.reduce((count, product) => count + product.reviews.length, 0);
  console.log(`Seeded ${categories.length} categories, ${products.length} products, ${reviewCount} reviews`);
}

try {
  await main();
} finally {
  await prisma.$disconnect();
}
// package.json (เฉพาะบรรทัดที่เพิ่ม ในบล็อก scripts)
    "db:seed": "tsx prisma/seed.ts",

  • สินค้าที่ไม่มียี่ห้อต้องเป็น NULL ไม่ใช่ string ว่าง: docker compose exec db psql -U postgres -d ecommerce -c 'SELECT count(*) FROM "Product" WHERE brand IS NULL;' ต้องได้ 92
  • หมวดหมู่เรียงตามที่ dummyjson ส่งมา: docker compose exec db psql -U postgres -d ecommerce -c 'SELECT id, slug FROM "Category" ORDER BY id LIMIT 3;' ต้องได้ beauty, fragrances, furniture เรียงตามลำดับนี้
  • npm run lint ผ่าน แต่ต้องรัน npx oxlint prisma/seed.ts เพิ่มด้วย เพราะ script lint ของ scaffold ครอบแค่ src/ กับ test/ — ไฟล์ใน prisma/ ไม่ถูกตรวจถ้าไม่สั่งเอง (ไม่มี output = ไม่มีปัญหา)
  • commit ด้วย git add -A && git commit -m "feat: seed from dummyjson"

ตัวเลข id ของหมวดหมู่จะไม่ใช่ 1, 2, 3 ถ้าคุณ seed ซ้ำ — รอบแรกได้ 1–24 รอบที่สองได้ 25–48 ไปเรื่อย ๆ เพราะ deleteMany (คือ DELETE) ไม่รีเซ็ต sequence ของ PostgreSQL ให้ (มีแต่ TRUNCATE … RESTART IDENTITY ที่ทำ) ไม่ต้องแก้อะไร: สิ่งที่ต้องตรงคือลำดับของ slug ไม่ใช่ตัวเลข และไม่มี endpoint ไหนในคอร์สนี้ส่ง id ของหมวดหมู่ออกไปให้ client เลย — React app อ้างอิงหมวดหมู่ด้วย slug เท่านั้น
