GET /products พร้อม skip และ limit

เมื่อจบบทนี้ คุณจะสามารถ

  • รับ query parameter ด้วย DTO ที่มีค่าเริ่มต้นในตัว แล้วเปิด ValidationPipe แบบ global
  • อธิบายกติกา pagination ของ dummyjson ได้ครบ รวมข้อที่ขัดความรู้สึกที่สุด: limit ใน response ไม่ใช่ค่าที่ client ขอมา
  • ดึงหน้าข้อมูลกับ total จาก snapshot เดียวด้วย $transaction ใน method กลางชื่อ paginate ที่บทที่ 14 จะเพิ่ม endpoint ใหม่ได้ด้วยโค้ดสองบรรทัด

กติกา pagination ของ dummyjson ทีละข้อ

ก่อนเขียนโค้ด ต้องอ่านกติกาให้ครบ เพราะสามข้อหลังเป็นข้อที่คนเดาผิดบ่อยที่สุด

กรณีdummyjson ทำอะไรเราต้องทำอะไร
ไม่ส่ง limitคืน 30 ชิ้นค่าเริ่มต้นของ limit = 30
ไม่ส่ง skipเริ่มจากชิ้นแรกค่าเริ่มต้นของ skip = 0
limit=0คืนทั้งหมด ไม่ใช่คืนศูนย์ชิ้นtake: undefined คือ "ไม่จำกัด" ใน Prisma
ลำดับสินค้าเรียงตาม id น้อยไปมากorderBy: { id: 'asc' }
?limit=10&skip=190 (เหลือของแค่ 4 ชิ้น)ตอบ limit: 4limit = จำนวนที่ส่งกลับจริง
หมวดที่ไม่มีสินค้าตอบ limit: 0เช่นเดียวกัน — rows.length

สองแถวล่างสุดคือหัวใจ: limit ใน response ของ dummyjson ไม่ใช่ การสะท้อนค่าที่ client ขอมา มันคือ จำนวนสินค้าที่ส่งกลับจริง เราจึงคืน limit: rows.length ไม่ใช่ limit: query.limit ตรงนี้ถ้าเขียนผิด curl บนหน้าแรกจะยังดูถูกต้องทุกอย่าง แล้วจะพังเฉพาะเมื่อขอเลยขอบข้อมูล — ซึ่งเป็นบั๊กชนิดที่หาเจอตอนดึกที่สุด

ค่าเริ่มต้นอยู่ที่ field ของ DTO ไม่ใช่ที่ ?? ใน service

ใน Week_09 บทที่ 11 เราอ่าน query parameter แบบดิบ ๆ แล้วเติมค่าเริ่มต้นเอง บทที่ 16 และ 18 พาเราไปถึงวิธีที่สะอาดกว่า: ประกาศ DTO แล้วปล่อยให้ pipe จัดการ

export class PaginationQueryDto {
  @IsInt()
  @Min(0)
  skip: number = 0;

  @IsInt()
  @Min(0)
  limit: number = 30;
}

ค่าเริ่มต้นเขียนเป็น field initialiser ธรรมดา ไม่ต้องมี @IsOptional() และไม่ต้องมี ? เหตุผลคือ option transform: true ทำให้ ValidationPipe สร้าง instance ของ class ขึ้นมาจริง ก่อนส่งเข้า handler — เมื่อ instance เกิดขึ้น initialiser ก็ทำงาน ดังนั้น request ที่ไม่ส่ง limit มาจะได้ 30 ติดมาโดยอัตโนมัติ

ผลพลอยได้คือใน service เราเขียน query.limit ได้ตรง ๆ โดยไม่ต้องมี ?? 30 โปรยอยู่ทั่วไฟล์ และ type ก็เป็น number ไม่ใช่ number | undefined

app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,
    transform: true,
    transformOptions: { enableImplicitConversion: true },
  }),
);
  • enableImplicitConversion: true — query string เป็น string เสมอ ("2") option นี้แปลงเป็น number ตาม type ที่ประกาศไว้ให้ก่อน validate จึงไม่ต้องใส่ @Type(() => Number) ทีละ field
  • whitelist: true — คีย์ที่ไม่มีใน DTO ถูกตัดออกเงียบ ๆ ใครยิง ?sort=price&skip=0 มาก็ได้แค่ skip ส่วน React app ส่งมาแค่ skip กับ limit อยู่แล้ว
  • transform: true — ทำให้ handler ได้ instance ของ PaginationQueryDto จริง (จุดที่ทำให้ค่าเริ่มต้นทำงาน)

total กับหน้าข้อมูลต้องมาจาก snapshot เดียว

response envelope ต้องมี total คือจำนวนสินค้าทั้งหมด ซึ่งเป็นอีก query หนึ่ง (count) ถ้ายิงสอง query แยกกัน มีช่องให้ข้อมูลเปลี่ยนระหว่างนั้น แล้ว client จะได้ total: 194 พร้อมหน้าข้อมูลที่มาจากโลกที่มี 195 ชิ้น เราจึงห่อทั้งคู่ไว้ใน transaction เดียว (ทบทวน Week_09 บทที่ 29)

const [rows, total] = await this.prisma.$transaction([
  this.prisma.product.findMany({ /* … */ }),
  this.prisma.product.count({ where }),
]);

รูปแบบ array ของ $transaction รับ list ของ query แล้วคืน array ของผลลัพธ์ตามลำดับเดิม — เขียนสั้นกว่าแบบ callback และเพียงพอเพราะสอง query นี้ไม่ต้องพึ่งผลของกันและกัน

take: undefined และ productInclude ที่ใช้ร่วมกัน

Prisma ตีความ take: undefined ว่า "ไม่จำกัดจำนวน" ซึ่งพอดีกับกติกา limit=0 ของ dummyjson จึงเขียนได้ตรง ๆ ว่า take: limit === 0 ? undefined : limit — ถ้าเผลอเขียน take: limit เฉย ๆ limit=0 จะกลายเป็นหน้าเปล่า

อีกอย่างคือ include ก้อนเดียวกันตอนนี้ต้องใช้ทั้งใน findOne และใน list ถ้าปล่อยให้ copy กันไว้สองที่ วันหนึ่งจะแก้ที่เดียวแล้ว list กับ detail ตอบไม่เหมือนกัน เราจึงยกขึ้นมาเป็นค่าคงที่ระดับไฟล์

const productInclude = {
  category: true,
  reviews: { orderBy: { id: 'asc' } },
} satisfies Prisma.ProductInclude;

satisfies สำคัญกว่าที่เห็น: ถ้าเขียน const productInclude: Prisma.ProductInclude = {...} TypeScript จะกว้างเกินไป และถ้าไม่ใส่อะไรเลย 'asc' จะถูกอนุมานเป็น string ซึ่ง Prisma ไม่รับ satisfies ตรวจว่าก้อนนี้เข้ากับ Prisma.ProductInclude จริง โดยยังคง literal type 'asc' ไว้ให้

ตรวจโค้ดที่ AI สร้าง

  • DTO มีค่าเริ่มต้น = 0 และ = 30 เขียนอยู่ที่ field พร้อม @IsInt() @Min(0) — ไม่มี ? ไม่มี @IsOptional()
  • option ของ pipe มีครบสามข้อและไม่มีข้ออื่นแถมมา: whitelist, transform, transformOptions: { enableImplicitConversion: true }
  • $transaction ใช้รูปแบบ array [findMany, count] ไม่ใช่ callback
  • take: limit === 0 ? undefined : limit ตรงตามนี้
  • envelope คืน limit: rows.length — ไม่ใช่ limit ที่รับเข้ามา
  • findOne เปลี่ยนมาใช้ include: productInclude แล้ว ไม่มี include แบบเขียนสดค้างอยู่
  • ใน controller ลำดับ handler เป็น findCategories → findAll → findOne

AI มักพลาดตรงนี้: ประกาศ skip?: number คู่กับ @IsOptional() แล้วไปโปรย query.skip ?? 0 ตามจุดต่าง ๆ ใน service — ใช้งานได้ แต่ย้ายกฎเรื่องค่าเริ่มต้นออกจาก DTO ไปกระจายในโค้ด ซึ่งบทที่ 21 (Swagger) จะอ่านค่าเริ่มต้นไม่เจอ อีกข้อคือเขียน take: limit เฉย ๆ ทำให้ ?limit=0 คืนหน้าเปล่าแทนที่จะคืนทั้งหมด — curl หน้าแรกไม่จับได้ ต้องทดสอบ limit=0 โดยเฉพาะ

import { IsInt, Min } from 'class-validator';

export class PaginationQueryDto {
  @IsInt()
  @Min(0)
  skip: number = 0;

  @IsInt()
  @Min(0)
  limit: number = 30;
}

src/main.ts

import { ValidationPipe } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module.js';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      transform: true,
      transformOptions: { enableImplicitConversion: true },
    }),
  );
  await app.listen(process.env.PORT ?? 3000);
}
await bootstrap();

src/products/products.service.ts

import { Injectable, NotFoundException } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import type { Prisma } from '../generated/prisma/client.js';
import { PrismaService } from '../prisma/prisma.service.js';
import { PaginationQueryDto } from './dto/pagination-query.dto.js';
import { ProductListResponseDto, ProductResponseDto } from './dto/product-response.dto.js';
import { toProductResponse } from './product.mapper.js';

const productInclude = {
  category: true,
  reviews: { orderBy: { id: 'asc' } },
} satisfies Prisma.ProductInclude;

@Injectable()
export class ProductsService {
  constructor(
    private readonly prisma: PrismaService,
    private readonly config: ConfigService,
  ) {}

  async findCategories() {
    const appUrl = this.config.getOrThrow<string>('APP_URL');
    const categories = await this.prisma.category.findMany({ orderBy: { id: 'asc' } });
    return categories.map(({ slug, name }) => ({
      slug,
      name,
      url: `${appUrl}/products/category/${slug}`,
    }));
  }

  findAll(query: PaginationQueryDto) {
    return this.paginate({}, query.skip, query.limit);
  }

  async findOne(id: number): Promise<ProductResponseDto> {
    const product = await this.prisma.product.findUnique({
      where: { id },
      include: productInclude,
    });
    if (!product) {
      throw new NotFoundException(`Product with id '${id}' not found`);
    }
    return toProductResponse(product);
  }

  private async paginate(
    where: Prisma.ProductWhereInput,
    skip: number,
    limit: number,
  ): Promise<ProductListResponseDto> {
    const [rows, total] = await this.prisma.$transaction([
      this.prisma.product.findMany({
        where,
        skip,
        take: limit === 0 ? undefined : limit,
        orderBy: { id: 'asc' },
        include: productInclude,
      }),
      this.prisma.product.count({ where }),
    ]);
    return { products: rows.map(toProductResponse), total, skip, limit: rows.length };
  }
}

src/products/products.controller.ts

import { Controller, Get, Param, ParseIntPipe, Query } from '@nestjs/common';
import { PaginationQueryDto } from './dto/pagination-query.dto.js';
import { ProductsService } from './products.service.js';

@Controller('products')
export class ProductsController {
  constructor(private readonly productsService: ProductsService) {}

  @Get('categories')
  findCategories() {
    return this.productsService.findCategories();
  }

  @Get()
  findAll(@Query() query: PaginationQueryDto) {
    return this.productsService.findAll(query);
  }

  @Get(':id')
  findOne(@Param('id', ParseIntPipe) id: number) {
    return this.productsService.findOne(id);
  }
}

GET /products?limit=2&skip=0 ตอบ envelope สี่คีย์ { products, total, skip, limit } โดย total เป็น 194 และ products มีสองชิ้นคือ id 1 และ 2 ส่วน GET /products เปล่า ๆ ได้ 30 ชิ้น และ ?limit=0 ได้ทั้ง 194 ชิ้น

query ที่ผิดรูปจะได้ 400 ตั้งแต่ก่อนเข้า handler เช่น ?limit=abc

HTTP/1.1 400 Bad Request
{"message":["limit must not be less than 0","limit must be an integer number"],"error":"Bad Request","statusCode":400}

สังเกตว่า message เป็น array สองข้อความ ไม่ใช่ข้อความเดียว — เพราะ Number('abc') คือ NaN ซึ่งทั้ง @IsInt() และ @Min(0) ถือว่าไม่ผ่าน validator ทั้งสองตัวจึงรายงานพร้อมกัน

  | node -e "let d='';process.stdin.on('data',c=>d+=c).on('end',()=>console.log(JSON.stringify(JSON.parse(d),Object.keys(JSON.parse(d)).sort())))" > /tmp/actual.json
node -e "const d=require('./docs/contract/products-page.json');console.log(JSON.stringify(d,Object.keys(d).sort()))" > /tmp/expected.json
diff /tmp/actual.json /tmp/expected.json && echo IDENTICAL
  • ขอเลยขอบข้อมูล — curl -s "http://localhost:3000/products?limit=10&skip=190" ต้องได้ limit: 4 (ไม่ใช่ 10) กับ total: 194
  • whitelist ทำงาน — curl -s "http://localhost:3000/products?limit=2&sort=price" ต้องได้ 200 ปกติ ไม่ใช่ 400
  • commit ผลงานด้วย git add -A && git commit -m "feat: GET /products with pagination"
