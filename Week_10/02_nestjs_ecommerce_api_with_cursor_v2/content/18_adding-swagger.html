เพิ่มเอกสาร API ด้วย Swagger

เมื่อจบบทนี้ คุณจะสามารถ

  • อธิบายหน้าที่ของ DocumentBuilder, SwaggerModule.createDocument และ SwaggerModule.setup แยกกันได้
  • เปิด CLI plugin ของ @nestjs/swagger ใน nest-cli.json และบอกได้ว่าทำไมต้อง restart start:dev
  • อ่าน /api-json แล้วแยกได้ว่าอะไรอยู่ใน paths อะไรอยู่ใน components.schemas และอะไรกลายเป็น query parameters

Swagger ประกอบจากสามชิ้น

เราเคยทำเรื่องนี้มาแล้วในคอร์ส NestJS Fundamentals บทนี้จึงเป็นการเอาของเดิมมาวางในโปรเจกต์ใหม่ ไม่ใช่ของใหม่ทั้งหมด ชิ้นแรกคือ DocumentBuilder — ตัวสร้าง metadata ของเอกสาร (ชื่อ, คำอธิบาย, เวอร์ชัน) ด้วย chain ที่ปิดท้ายด้วย .build() ชิ้นที่สองคือ SwaggerModule.createDocument(app, config) ซึ่งเดินดู controller ทุกตัวใน app ที่ประกอบเสร็จแล้ว อ่าน decorator ที่เจอ แล้วประกอบเป็น OpenAPI document ขึ้นมาในหน่วยความจำ ชิ้นที่สามคือ SwaggerModule.setup('api', app, document) ซึ่งเสิร์ฟเอกสารนั้นออกมาสองหน้า: UI แบบกดเล่นได้ที่ /api และ JSON ดิบที่ /api-json

ลำดับสำคัญ: createDocument ต้องถูกเรียกหลัง app ประกอบ module เสร็จ และ setup ต้องถูกเรียกก่อน await app.listen(...) เพราะ listen คือจุดที่เปิดรับ request — route ของ Swagger ต้องถูกลงทะเบียนไว้ก่อนหน้านั้น

CLI plugin อ่าน .dto.ts ให้เราเอง

ปัญหาคลาสสิกของ OpenAPI ใน TypeScript คือ type ของ field หายไปตอน compile — ตอน runtime price: number ไม่เหลือร่องรอยให้ Swagger อ่าน วิธีดั้งเดิมคือใส่ @ApiProperty() ทุก field ซึ่งกลายเป็นโค้ดยาวเหยียดที่ไม่ได้ให้ข้อมูลอะไรใหม่ CLI plugin ของ @nestjs/swagger แก้ปัญหานี้ด้วยการทำงานตอน compile: มันอ่าน class ในไฟล์ที่ลงท้ายด้วย .dto.ts (ค่าเริ่มต้นของ option dtoFileNameSuffix ซึ่งตรงกับชื่อไฟล์ DTO ทั้งหมดในโปรเจกต์เราพอดี) แล้วแทรก metadata ของ type ให้อัตโนมัติ เราจึงใส่ decorator เฉพาะที่ต้องการอธิบายเพิ่มจริง ๆ

ผลพลอยได้ที่ต้องจำ: เพราะ plugin ทำงานตอน compile ไม่ใช่ตอน runtime การแก้ nest-cli.json ระหว่างที่ watch mode รันอยู่จะไม่มีผล — watch จะ recompile แค่ไฟล์ที่เปลี่ยน (main.ts) ส่วนไฟล์ DTO ที่ compile ไว้ก่อนหน้ายังเป็นของเก่าที่ไม่มี metadata ต้องหยุด start:dev แล้วสั่งใหม่ให้ compile รอบเต็มหนึ่งครั้ง

ติดตั้งด้วยมือก่อนสั่ง Cursor

prompt ของบทนี้เขียนไว้ว่า ติดตั้ง @nestjs/swagger แล้ว ดังนั้นทำขั้นนี้เองก่อน แล้วจด version ที่ได้ไว้

npm install @nestjs/swagger
npm ls @nestjs/swagger

ตอนตรวจของจริงได้ @nestjs/swagger@12.0.1 คู่กับ @nestjs/common@12.0.1 ที่ใช้อยู่

npm 11.19 ที่มาพร้อม Node 26 กั้น install script ไว้เหมือนตอนติดตั้ง Prisma รอบนี้จะเจอข้อความ npm warn install-scripts 1 package has install scripts not yet covered by allowScripts: @scarf/scarf@1.4.0 (postinstall: node ./report.js) ให้อนุมัติแล้ว rebuild ตามนี้ npm install-scripts approve @scarf/scarf@1.4.0 แล้วต่อด้วย npm rebuild — package.json จะมีรายการเพิ่มในบล็อก allowScripts ซึ่งเป็นเรื่องปกติ อย่าลบออก ถ้า npm ของคุณไม่มีการกั้นนี้ ก็จะไม่เห็นข้อความดังกล่าวและข้ามขั้นนี้ไปได้เลย

ไฟล์ด้านล่างมาจากโค้ดอ้างอิงของคอร์ส — Cursor อาจแก้ไฟล์ต่างออกไปได้ ขอแค่ไม่แตะไฟล์ที่ไม่เกี่ยวกับเป้าหมายและผ่านผลลัพธ์ที่ต้องได้ใน prompt

  • src/main.ts — สัญญา: ต้องเสิร์ฟ Swagger UI ที่ /api และ JSON ที่ /api-json / validation และ CORS ที่มีอยู่ต้องทำงานเหมือนเดิม
  • nest-cli.json — สัญญา: CLI plugin ของ @nestjs/swagger ต้องทำงานจริง (DTO ขึ้นใน components.schemas) / ค่าเดิมในไฟล์ต้องไม่หาย

สั่ง Cursor ตั้งค่า Swagger และเปิด plugin

commit งานก่อน แล้วเปิดแชทใหม่ใน Cursor โหมด Agent (git add -A && git commit -m "chore: install swagger") จากนั้นส่ง prompt นี้ — กติกาเดิม: AI พิมพ์แทนคุณได้ แต่คุณต้องอธิบายทุกบรรทัดได้

ตั้งค่า Swagger UI ที่ /api และเปิดใช้ CLI plugin ของ @nestjs/swagger @src/main.ts @nest-cli.json ผลลัพธ์ที่ต้องได้: - หลัง restart npm run start:dev เปิด http://localhost:3000/api ได้หน้า Swagger UI status 200 - http://localhost:3000/api-json คืน OpenAPI document ที่ info.title เป็น E-commerce API, info.version เป็น 1.0 และ description อ้างถึง docs/api-spec.md - paths มีครบ /products/categories, /products/category/{slug}, /products, /products/{id}, /carts/add - components.schemas มี AddCartDto, CartProductDto และ AddressDto ทั้งที่ยังไม่มี decorator ของ swagger ใน DTO (แปลว่า CLI plugin ของ @nestjs/swagger ทำงานจริง) - CORS และ validation เดิมยังทำงานเหมือนเดิม ขอบเขต: - ห้ามติดตั้ง dependency ใหม่ (@nestjs/swagger ติดตั้งแล้ว) - ห้ามใส่ decorator ของ swagger ใน controller หรือ DTO ในรอบนี้

ตรวจโค้ดที่ AI สร้าง

  • หลัง restart /api ตอบ 200 และ /api-json มี title, version และ description ตามที่ prompt ระบุ
  • paths ใน /api-json มีครบทุก endpoint และ components.schemas มี AddCartDto, CartProductDto, AddressDto — ถ้า schema ว่าง แปลว่า plugin ไม่ทำงาน
  • ยิง curl ด้วย Origin: http://localhost:5173 ยังได้ header CORS และ GET /products?limit=0 ยังได้ 400
  • ยังไม่มี decorator ของ @nestjs/swagger ในไฟล์ controller หรือ DTO เลย (บทหน้าเป็นรอบของมัน)
  • git status ไม่มีไฟล์ที่ไม่เกี่ยวกับเป้าหมายถูกแก้ (นอกจาก package.json / package-lock.json ที่เปลี่ยนจากขั้นติดตั้ง) และไม่มี decorator ของ swagger ใน controller หรือ DTO

AI มักพลาดตรงนี้: ใส่ "plugins" ไว้ระดับบนสุดของ nest-cli.json (ข้าง ๆ sourceRoot) แทนที่จะอยู่ใน compilerOptions ซึ่ง Nest CLI จะไม่ร้อง error อะไรเลย — plugin แค่ไม่ทำงานเงียบ ๆ แล้วคุณจะไปเจอผลตอนอ่าน /api-json ว่า schema ของ DTO ว่างเปล่า อีกจุดคือ AI ชอบเพิ่ม .addTag() หรือ .addBearerAuth() ที่เราไม่ได้ขอ ไม่ผิดผลลัพธ์ แต่เป็นของแถมที่ควรถามตัวเองว่าต้องการจริงไหม

โค้ดอ้างอิงของบทนี้ — เป็นหนึ่งในวิธีที่ถูก ของคุณไม่จำเป็นต้องเหมือนทุกบรรทัด ขอแค่ผ่านผลลัพธ์ที่ต้องได้:

/* src/main.ts */
import { ValidationPipe } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import { DocumentBuilder, SwaggerModule } from '@nestjs/swagger';
import { AppModule } from './app.module.js';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      transform: true,
      transformOptions: { enableImplicitConversion: true },
    }),
  );
  app.enableCors({ origin: process.env.CORS_ORIGIN ?? 'http://localhost:5173' });

  const config = new DocumentBuilder()
    .setTitle('E-commerce API')
    .setDescription("E-commerce API designed from the React storefront's own contract (see docs/api-spec.md)")
    .setVersion('1.0')
    .build();
  SwaggerModule.setup('api', app, SwaggerModule.createDocument(app, config));

  await app.listen(process.env.PORT ?? 3000);
}

await bootstrap();

ถ้าอธิบายบรรทัดไหนไม่ได้ ยังไม่ผ่านบทนี้ — กลับไปอ่านส่วนแนวคิดก่อน

ผลลัพธ์ที่คาดหวัง

หลัง หยุดแล้วสั่ง npm run start:dev ใหม่ เปิด http://localhost:3000/api จะได้หน้า Swagger UI ที่ตอบ 200 และลิสต์ endpoint ทั้งห้าตัวของเรา (/products/categories, /products/category/{slug}, /products, /products/{id}, /carts/add) บวก / ที่ติดมากับ AppController ของ scaffold ส่วน /api-json จะคืน OpenAPI document ดิบ ซึ่ง components.schemas มี DTO ที่ plugin อ่านจากไฟล์ .dto.ts ให้แล้ว ทั้งที่เรายังไม่ได้ใส่ decorator แม้แต่ตัวเดียว

ตรวจว่าใช้งานได้จริง

  • หยุด start:dev ด้วย Ctrl+C แล้วสั่งใหม่ — ขั้นนี้ข้ามไม่ได้ ตอนตรวจของจริงต้อง restart จริง ๆ plugin จึงจะทำงาน (watch recompile เฉย ๆ ไม่พอ)
  • curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/api ได้ 200
  • อ่าน paths และ components.schemas ด้วย one-liner นี้
curl -s http://localhost:3000/api-json | node -e "let d='';process.stdin.on('data',c=>d+=c).on('end',()=>{const j=JSON.parse(d);console.log(Object.keys(j.paths));console.log(Object.keys(j.components?.schemas??{}))})"

สังเกตว่าไม่มี PaginationQueryDto ในลิสต์ schema — ไม่ใช่ความผิดพลาด class ที่ใช้ผ่าน @Query() จะถูก OpenAPI กระจาย ออกเป็น query parameter รายตัวบน path นั้นแทนที่จะถูกตีพิมพ์เป็น schema ให้อ้างถึง ตรวจได้ด้วยการเรียก one-liner เดิมแล้วเปลี่ยนไปพิมพ์ j.paths['/products'].get.parameters จะเห็น skip กับ limit เป็นสองรายการแยกกัน ส่วน class ที่ใช้ผ่าน @Body() (AddCartDto และเพื่อน) จึงเป็นพวกที่โผล่ใน components.schemas
