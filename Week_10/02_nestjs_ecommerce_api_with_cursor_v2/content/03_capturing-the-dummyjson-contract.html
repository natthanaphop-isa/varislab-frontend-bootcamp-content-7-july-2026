อ่านสัญญาของ dummyjson แล้ววางลงในโปรเจกต์

เมื่อจบบทนี้ คุณจะสามารถ

  • วางไฟล์สัญญาแปดไฟล์ที่คอร์สยิงเก็บมาให้ลงใน docs/contract/ ของโปรเจกต์ แล้ว commit
  • อ่านสัญญาแล้วสรุปข้อเท็จจริงที่ API ของเราต้องทำตาม รวมถึงกรณีขอบสี่ข้อที่เดาเองไม่ได้
  • อธิบายได้ว่าทำไมสัญญาต้องเป็น ไฟล์ในโปรเจกต์ ไม่ใช่ความรู้ของ AI และไม่ใช่ความจำของเรา

สัญญามาพร้อมกับคอร์ส ไม่ต้องยิงเอง

บทนี้ไม่มีคำสั่ง curl ให้รัน และไม่ต้องสั่ง Cursor ไปยิง API ให้ เพราะคอร์สยิง dummyjson เก็บ payload ดิบไว้ให้แล้วเมื่อ 13 กันยายน 2026 — งานของบทนี้คือ ก๊อปไฟล์เข้าโปรเจกต์แล้วอ่านให้เข้าใจ เหตุผลมีสามข้อ

  • ตัวเลขในบทเรียนต้องตรงกับของในเครื่องคุณ — dummyjson เป็น API สาธารณะที่ข้อมูลเปลี่ยนได้ทุกเมื่อ ถ้าแต่ละคนยิงเก็บเองในวันต่างกัน จำนวนสินค้า จำนวน review หรือ rating ของสินค้าชิ้นแรกอาจไม่เท่ากัน แล้วเกณฑ์ตรวจในบทที่ 10–19 ที่อ้างเลข 194 กับ 24 จะใช้ไม่ได้ทันที การแช่สัญญาไว้เป็นไฟล์คือสิ่งที่ทำให้ทุกคนตรวจงานด้วยเกณฑ์เดียวกัน
  • สัญญาไม่ใช่สิ่งที่เราต้องฝึกยิง — สิ่งที่คอร์สนี้ฝึกคือการอ่านสัญญาแล้วสร้าง API ให้ตรง การพิมพ์ curl เจ็ดบรรทัดไม่ได้สอนอะไรที่บทอื่นไม่ได้สอนอยู่แล้ว (ทุกบทหลังจากนี้จบด้วยการยิง curl ใส่ API ของเราเอง)
  • AI เดาสัญญาแทนไม่ได้ และเราก็ไม่ควรให้มันเดา — ถ้าถาม Cursor ตรง ๆ ว่า product ของ dummyjson มี field อะไร มันจะตอบด้วยรูปทรงที่ ดูสมเหตุสมผล: มี brand ทุกชิ้น มี createdAt อยู่ระดับบนสุด ไม่มี availabilityStatus — ใกล้เคียงแต่ไม่ตรง และความไม่ตรงแบบนี้ทำให้หน้าจอ React พังแบบเงียบ ๆ: ช่องราคาว่าง รูปไม่ขึ้น ปุ่มกดไม่ติด โดยที่ API ของเราตอบ 200 อย่างหน้าตาเฉย

พอสัญญาเป็นไฟล์ในโปรเจกต์แล้ว ทุก prompt ในบทถัด ๆ ไปจะ @-mention ไฟล์เหล่านี้ เพื่อให้ Cursor อ่าน payload จริงแทนที่จะเดา และเราก็ได้เกณฑ์ตรวจงานที่วัดได้ในเวลาเดียวกัน — ทุกบทจบด้วยการยิง endpoint ของเราแล้วเทียบกับไฟล์ใน docs/contract/

แปดไฟล์ใน docs/contract/

เจ็ดไฟล์แรกคือ payload ดิบ หนึ่ง request ต่อหนึ่งไฟล์ (ไม่จัดรูปแบบใหม่ ไม่แก้ด้วยมือ) และไฟล์ที่แปดคือเอกสารสรุปที่อ่านจบได้เร็ว คลิกชื่อไฟล์เพื่อเปิดดูของจริงได้เลย

ไฟล์Request ที่ใช้จับสิ่งที่ต้องสังเกต
README.md—สรุปสัญญาทั้งหมด: interface ของ Product, ซองของรายการ, สูตรคิดส่วนลด, กรณีขอบ และตัวเลขของชุดข้อมูล
categories.jsonGET /products/categoriesเป็น array ตรง ๆ ไม่มีซองห่อ 24 รายการ แต่ละรายการคือ {slug, name, url}
products-page.jsonGET /products?limit=2&skip=0ซอง {products, total, skip, limit} — "total":194 คือจำนวนสินค้าทั้งหมด ไม่ใช่จำนวนในหน้านี้
product-1.jsonGET /products/1รูปทรงเต็มของ product: 22 key ระดับบนสุด มี object ซ้อนและ array ของ review
product-not-found.txtGET /products/9999status และข้อความ error ที่เราต้องลอกให้ตรงตัวอักษร
products-by-category.jsonGET /products/category/beauty?limit=2&skip=0ซองเดิม แต่ total เป็นจำนวนในหมวดนั้น (beauty มี 5)
products-by-category-unknown.jsonGET /products/category/nope?limit=2&skip=0หมวดที่ไม่มีจริงตอบ 200 ไม่ใช่ 404 — และ limit ที่ตอบกลับไม่ใช่ 2
cart-add.txtPOST /carts/addstatus 201 และวิธีคิดส่วนลดที่ต้องคำนวณให้ได้เลขเดียวกัน

สองไฟล์ที่เป็น .txt จับด้วย curl -i จึงมี header ของ response ติดมาด้วย (วันเวลา, cf-ray, ตัวนับ rate limit) ค่าเหล่านั้นเป็นของรอบที่จับ ไม่มีความหมายกับสัญญา — สิ่งที่เราสนใจคือบรรทัดแรก (status) และ body บรรทัดสุดท้ายเท่านั้น

วางลงในโปรเจกต์

ก๊อปโฟลเดอร์ทั้งก้อนจากคอร์สมาไว้ที่ docs/contract/ ในโปรเจกต์ ecommerce-api แก้ค่า COURSE ให้เป็นที่เก็บ repo ของคอร์สในเครื่องคุณ (โฟลเดอร์ที่มีไฟล์บทเรียนนี้อยู่)

COURSE=~/Sites/frontend-bootcamp-content-7-july-2026/Week_10/02_nestjs_ecommerce_api_with_cursor_v2/content mkdir -p docs cp -R "$COURSE/contract" docs/contract ls -1 docs/contract

ไฟล์เหล่านี้ต้องอยู่ใน git (ไม่ใช่ .gitignore) เพราะมันเป็นส่วนหนึ่งของโปรเจกต์เหมือน schema หรือ test — และเพราะ Cursor จะอ่านมันทุกครั้งที่เราสั่งงาน

อ่านสัญญา: ข้อเท็จจริงที่ต้องจำ

ข้อเท็จจริงต่อไปนี้อยู่ใน docs/contract/README.md ครบทุกข้อ แต่ห้าข้อนี้คือข้อที่จะกลับมาเป็นเงื่อนไขในบทที่ 10–19 บ่อยที่สุด แต่ละข้อมีไฟล์กำกับว่าพิสูจน์ได้จากที่ไหน

  • ค่าเริ่มต้นของการแบ่งหน้า คือ limit 30 และ skip 0 ถ้าไม่ส่ง query มาเลย และ limit=0 มีความหมายพิเศษคือ เอาทั้งหมด (194 ชิ้น) — ไม่ใช่ "เอา 0 ชิ้น" (products-page.json และตาราง pagination ใน README.md)
  • limit ที่ตอบกลับคือจำนวนสินค้าที่ส่งมาจริง ไม่ใช่ค่าที่เราขอ — ยิง ?limit=10&skip=190 ได้สินค้า 4 ชิ้น และซองก็ตอบ "limit":4 ไม่ใช่ 10 ในกรณีสุดขั้วคือหมวดที่ไม่มีจริง ได้ "limit":0 ทั้งที่ query ส่ง limit=2 ไป (products-by-category-unknown.json) ข้อนี้สำคัญมาก เพราะตอนเขียน pagination เราต้องคืน limit เป็นจำนวนแถวที่ query ได้ ไม่ใช่ echo ค่าที่รับมา
  • product มี 22 key ระดับบนสุด (product-1.json): id, title, description, category, price, discountPercentage, rating, stock, tags, brand, sku, weight, dimensions, warrantyInformation, shippingInformation, availabilityStatus, reviews, returnPolicy, minimumOrderQuantity, meta, images, thumbnail — โดย category เป็น string ของ slug ไม่ใช่ object
  • มีของซ้อนอยู่สามที่: dimensions คือ {width, height, depth}, meta คือ {createdAt, updatedAt, barcode, qrCode} และ reviews คือ array ของ {rating, comment, date, reviewerName, reviewerEmail} จำนวน 3 รายการต่อสินค้าหนึ่งชิ้น — ในฐานข้อมูลของเราจะแยกเป็นคอลัมน์แบนและตาราง Review แล้วประกอบรูปทรงซ้อนคืนด้วย mapper ในบทที่ 11
  • brand ไม่ใช่ field ที่มีทุกชิ้น — คอร์สยิง GET /products?limit=0 (เอาทั้ง 194 ชิ้น) แล้วนับได้ว่า
194 products; 92 without brand

นั่นคือ 92 ชิ้นจาก 194 ชิ้น ไม่มี key brand เลย (ไม่ใช่มีแล้วเป็น null) คอลัมน์ brand ในฐานข้อมูลจึงต้อง nullable และ mapper ต้องตัด key นี้ออกเมื่อค่าเป็น null เพื่อให้เหมือนของจริง

  • วันเวลาเป็น string รูปแบบ ISO ทั้งใน meta.createdAt, meta.updatedAt และ reviews[].date — ห้ามส่ง Date object ออกไปตรง ๆ และตัวเลขทุกตัว (price, rating, discountPercentage) เป็น JSON number ไม่ใช่ string
  • หมวดที่ไม่มีจริงไม่ใช่ error — GET /products/category/nope ตอบ 200 พร้อมซองเปล่า ไม่ใช่ 404 (products-by-category-unknown.json)
{"products":[],"total":0,"skip":0,"limit":0}
  • id ที่ไม่มีจริงคือ 404 พร้อมข้อความเฉพาะ — บรรทัดแรกของ product-not-found.txt คือ HTTP/2 404 (มีช่องว่างต่อท้าย เพราะเป็นบรรทัด status ดิบจาก curl -i) และ body คือ
{"message":"Product with id '9999' not found"}

ข้อความนี้ต้องลอกให้ตรงทุกตัวอักษร รวมถึง single quote ครอบตัวเลข เพราะ React แสดงค่านี้ให้ผู้ใช้เห็นตรง ๆ

  • POST /carts/add ตอบ 201 — บรรทัดแรกของ cart-add.txt คือ HTTP/2 201 และ body คือ cart เต็มรูปแบบ
{"id":209,"products":[{"id":1,"title":"Essence Mascara Lash Princess","price":9.99,
"quantity":2,"total":19.98,"discountPercentage":10.48,"discountedPrice":18,
"thumbnail":"https://cdn.dummyjson.com/product-images/beauty/essence-mascara-lash-princess/thumbnail.webp"}],
"total":19.98,"discountedTotal":18,"userId":1,"totalProducts":1,"totalQuantity":2}

ตัวเลขในนี้บอกสูตรทั้งหมด: total ของรายการคือ price × quantity = 9.99 × 2 = 19.98 ส่วน discountedPrice คือราคาหลังหักส่วนลดแล้ว ปัดเป็นจำนวนเต็ม — 19.98 × (1 − 10.48/100) = 19.98 × 0.8952 = 17.886 แล้ว Math.round ได้ 18 พอดี จากนั้น discountedTotal คือผลรวมของ discountedPrice ทุกรายการ ส่วน totalProducts คือจำนวน รายการ (1) และ totalQuantity คือจำนวน ชิ้น (2) — สองค่านี้ต่างกันและมักถูกสลับกัน

"id":209 ในไฟล์นี้เป็น id ที่ dummyjson แจกมา ของเราจะเริ่มนับจาก 1 เพราะเก็บคำสั่งซื้อในฐานข้อมูลของเราเอง — ตัวเลขนี้เป็นข้อเดียวในสัญญาที่เราไม่ต้องทำให้ตรงกัน (บทที่ 19 พูดถึงเรื่องนี้อีกครั้ง)

ถ้าอยากพิสูจน์ว่าไฟล์เป็นของจริง

ไม่บังคับ แต่ทำได้ในหนึ่งบรรทัด: ยิง dummyjson สด ๆ แล้ว diff กับไฟล์ที่ก๊อปมา ถ้า dummyjson ยังไม่เปลี่ยนข้อมูลจะได้คำว่า IDENTICAL

curl -s https://dummyjson.com/products/1 | diff - docs/contract/product-1.json && echo IDENTICAL # นับสินค้าและชิ้นที่ไม่มี brand ด้วยตัวเอง node -e "fetch('https://dummyjson.com/products?limit=0').then(r=>r.json()).then(({products})=>console.log(products.length,'products;',products.filter(p=>!('brand' in p)).length,'without brand'))"

ถ้าได้ diff ออกมาแปลว่า dummyjson เปลี่ยนข้อมูลหลังวันที่คอร์สจับไฟล์ — ให้ยึด ไฟล์ใน docs/contract/ เป็นเป้าต่อไป เพราะทุกบทและทุกเกณฑ์ตรวจในคอร์สนี้อ้างอิงตัวเลขชุดนั้น (ยกเว้นบทที่ 15 ที่เราจะเขียน script ยิง dummyjson สดเพื่อ จับ ความเปลี่ยนแปลงแบบนี้โดยเฉพาะ)

วางสัญญาแล้ว commit เป็น commit ที่สอง

รันคำสั่งก๊อปจากโฟลเดอร์ ecommerce-api (ยังไม่ต้องเปิด dev server) แล้วอ่านด้วยตาตัวเองอย่างน้อยสามไฟล์ก่อน commit: README.md ทั้งไฟล์, product-1.json และ cart-add.txt

ls -1 docs/contract head -1 docs/contract/product-not-found.txt head -1 docs/contract/cart-add.txt node -e "console.log(require('./docs/contract/categories.json').length)" git add docs git commit -m "docs: add dummyjson contract"

ถ้าใช้ Cursor อยู่แล้ว ลองถามด้วยแชทโหมด Ask (ยังไม่ใช่ Agent) หนึ่งคำถามเพื่อซ้อมการ @-mention: @docs/contract/product-1.json สินค้าชิ้นนี้มี field ระดับบนสุดกี่ field และอันไหนเป็น object ซ้อน — คำตอบต้องได้ 22 และชี้ dimensions, meta, reviews ถ้ามันตอบเลขอื่น แปลว่ามันยังไม่ได้อ่านไฟล์จริง

ผลลัพธ์ที่คาดหวัง

โฟลเดอร์ docs/contract/ มีแปดไฟล์ครบ, head -1 ของสองไฟล์ .txt ได้ HTTP/2 404 และ HTTP/2 201 ตามลำดับ, คำสั่ง node -e พิมพ์ 24 และ git log --oneline มีสอง commit คือ scaffold กับ contract

ตรวจว่าใช้งานได้จริง

  • ls -1 docs/contract | wc -l ได้ 8
  • head -1 docs/contract/product-not-found.txt ขึ้นต้นด้วย HTTP/2 404
  • head -1 docs/contract/cart-add.txt ขึ้นต้นด้วย HTTP/2 201
  • node -e "console.log(require('./docs/contract/categories.json').length)" ได้ 24
  • grep -o '"total":194' docs/contract/products-page.json พบข้อความ — ยืนยันว่า total คือ 194
  • cat docs/contract/products-by-category-unknown.json ได้ {"products":[],"total":0,"skip":0,"limit":0} — จำ "limit":0 ข้อนี้ไว้ให้ดี
  • git status สะอาด และ git log --oneline แสดงสอง commit
