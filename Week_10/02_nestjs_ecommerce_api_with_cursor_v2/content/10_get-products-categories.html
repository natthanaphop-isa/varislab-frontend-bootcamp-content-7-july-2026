GET /products/categories

เมื่อจบบทนี้ คุณจะสามารถ

  • ประกอบ module + controller + service ของ resource products ขึ้นมาใหม่ทั้งชุด แล้วลงทะเบียนเข้า AppModule
  • อธิบายได้ว่าทำไม field url ของ category ต้องอ่าน host จาก APP_URL ไม่ใช่ hard-code
  • ยืนยันด้วย diff ว่า response ของเราตรงกับ docs/contract/categories.json แบบไบต์ต่อไบต์

เลือก endpoint ที่ง่ายที่สุดขึ้นมาทำก่อน

ใน contract ที่วางไว้ในโปรเจกต์ตั้งแต่บทที่ 3 มี endpoint เดียวที่ไม่มี query parameter ไม่มี route parameter และมีรูปทรง response แบนราบสามคีย์ — นั่นคือ GET /products/categories เราจึงเริ่มจากตัวนี้ เพราะมันพิสูจน์ว่าเส้นทางทั้งเส้น (request → controller → service → Prisma → Postgres → response) เชื่อมกันได้จริง โดยยังไม่ต้องยุ่งกับ mapper หรือ pagination ที่จะมาในบทถัด ๆ ไป

โครงสร้างสามไฟล์เป็นแบบเดียวกับที่คุณเคยทำใน Week_09 บทที่ 6 (controller), บทที่ 12 (service) และบทที่ 14 (module) ต่างกันแค่คราวนี้เราไม่พิมพ์เอง — เราสั่ง Cursor พิมพ์ แล้วเราอ่านทุกบรรทัด

  • controller รู้แค่เรื่อง HTTP: path, method, parameter — แล้วส่งต่อให้ service ทันที
  • service เป็นที่เดียวที่รู้จักฐานข้อมูลและรู้จักรูปทรงของ response
  • module ผูกสองตัวนี้เข้าด้วยกันเป็นก้อน แล้วเราเอาก้อนนี้ไปเสียบใน AppModule

field url คือจุดที่ต้องคิด ไม่ใช่จุดที่ต้อง copy

เปิด docs/contract/categories.json ดูสักแถว dummyjson ตอบมาแบบนี้

{ "slug": "beauty", "name": "Beauty", "url": "https://dummyjson.com/products/category/beauty" }

ถ้าเรา copy ค่า url มาตรง ๆ React app จะยิงกลับไปที่ dummyjson แทนที่จะยิงมาที่ API ของเรา — API ของเราต้องตอบ http://localhost:3000/products/category/beauty คือ host ของตัวเอง ต่อท้ายด้วย path เดียวกัน

host ของตัวเองเปลี่ยนไปตามที่รัน (เครื่องคุณ, staging, production) จึงต้องมาจาก environment variable ไม่ใช่จากโค้ด เรามี APP_URL อยู่ใน .env ตั้งแต่บทที่ 5 แล้ว และ ConfigModule ถูกตั้งเป็น global ในบทที่ 6 แล้ว จึงฉีด ConfigService เข้า service ได้เลย

const appUrl = this.config.getOrThrow<string>('APP_URL');

สังเกตว่าเราใช้ getOrThrow ไม่ใช่ get — get คืน undefined เงียบ ๆ เมื่อไม่มีคีย์นั้น ผลคือ url จะกลายเป็น undefined/products/category/beauty แล้วหลุดขึ้น production ไปเงียบ ๆ ส่วน getOrThrow ทำให้แอปพังทันทีที่ request แรก ซึ่งเป็นสิ่งที่เราต้องการ (ทบทวน Week_09 บทที่ 45 เรื่อง ConfigService)

ทำไมแค่ orderBy: { id: 'asc' } ก็ตรงกับ dummyjson

ลำดับของ array มีผลต่อ diff — ถ้าเรียงไม่ตรง ถึงข้อมูลจะครบก็ถือว่าไม่ผ่าน seed ในบทที่ 9 ส่ง category เข้า createMany เป็น array ตามลำดับที่ GET /products/categories คืนมา ดังนั้น id ที่ sequence แจกให้ (auto-increment) จึงเรียงตรงกับลำดับของ dummyjson อยู่แล้ว การสั่ง orderBy: { id: 'asc' } คือการเขียนเจตนานั้นออกมา ไม่ใช่การหวังว่า Postgres จะคืนแถวตามลำดับที่ insert — Postgres ไม่รับประกันลำดับให้เลยถ้าไม่สั่ง ORDER BY

ค่า id ที่แท้จริงจะขยับขึ้นทุกครั้งที่ re-seed (ตามที่เจอในบทที่ 9) แต่ไม่มีผลกับบทนี้ เพราะ id ไม่ถูกส่งออกไปใน response — dummyjson ส่งแค่สามคีย์ slug, name, url เท่านั้น

เป้าหมายของบทนี้

src/
├── app.module.ts                     (แก้ไข)
└── products/
    ├── products.module.ts            (สร้างใหม่)
    ├── products.controller.ts        (สร้างใหม่)

  • src/products/products.service.ts — สัญญา: ต้องดึง category ทุกแถวด้วย findMany({ orderBy: { id: 'asc' } }) แล้ว map เป็น { slug, name, url } โดย host มาจาก this.config.getOrThrow<string>('APP_URL') / ต้องไม่ส่ง id ออกไป และต้องไม่ hard-code host
  • src/products/products.controller.ts — สัญญา: ต้องมี prefix @Controller('products') และ handler @Get('categories') ที่ return ผลจาก service ตรง ๆ / ต้องไม่มี logic ฐานข้อมูลอยู่ในนี้
  • src/products/products.module.ts — สัญญา: ต้องประกาศ controllers และ providers ของ products / ต้องไม่ import ConfigModule หรือ PrismaModule ซ้ำ เพราะทั้งสองเป็น global แล้ว
  • src/app.module.ts — สัญญา: ต้องเพิ่ม ProductsModule ต่อจาก PrismaModule ใน imports / ต้องไม่ลบ AppController หรือ AppService

สั่ง Cursor สร้าง ProductsModule แล้วอ่านทุกบรรทัด

commit งานก่อน แล้วเปิดแชทใหม่ใน Cursor โหมด Agent (git add -A && git commit -m "chore: before products module") จากนั้นส่ง prompt นี้ทั้งก้อน — กติกาของคอร์สยังเหมือนเดิม: AI พิมพ์แทนคุณได้ แต่คุณต้องอธิบายทุกบรรทัดได้

สร้าง ProductsModule พร้อม endpoint GET /products/categories ที่ตอบเหมือน dummyjson บริบท: @src/app.module.ts @src/prisma/prisma.service.ts @prisma/schema.prisma @docs/contract/categories.json @.env @.cursor/rules/project.mdc ฐานข้อมูลถูก seed แล้ว ตาราง Category มี 24 แถว (id เรียงตามลำดับเดียวกับ dummyjson) docs/contract/categories.json คือ response จริง: array ของ { slug, name, url } โดย url คือ https://dummyjson.com/products/category/<slug> ของเรา url ต้องเป็น <APP_URL>/products/category/<slug> โดย APP_URL อ่านจาก .env ผ่าน ConfigService (ConfigModule เป็น global แล้ว) PrismaModule เป็น global แล้ว ฉีด PrismaService ผ่าน constructor ได้เลย โครงสร้าง: สร้าง/แก้ไฟล์ตามนี้ ไม่มากไม่น้อยกว่านี้ - src/products/products.module.ts (สร้างใหม่) - src/products/products.controller.ts (สร้างใหม่) - src/products/products.service.ts (สร้างใหม่) - src/app.module.ts (แก้ไข: เพิ่ม ProductsModule ใน imports ต่อจาก PrismaModule) ข้อกำหนดทางเทคนิค: - products.service.ts: @Injectable() export class ProductsService constructor(private readonly prisma: PrismaService, private readonly config: ConfigService) method async findCategories() ดึง category ทั้งหมดด้วย findMany({ orderBy: { id: 'asc' } }) แล้ว map เป็น { slug, name, url } โดย url = `${appUrl}/products/category/${slug}` และ appUrl มาจาก this.config.getOrThrow<string>('APP_URL') ห้ามคืน id ของ category ออกไป - products.controller.ts: @Controller('products') export class ProductsController constructor(private readonly productsService: ProductsService) handler @Get('categories') findCategories() return this.productsService.findCategories() - products.module.ts: @Module({ controllers: [ProductsController], providers: [ProductsService] }) - import ไฟล์ในโปรเจกต์ทุกตัวลงท้าย .js - ห้ามสร้าง DTO หรือ interface ในรอบนี้ ขอบเขต: - ห้ามติดตั้ง dependency ใหม่ - ห้ามแก้ไฟล์อื่นนอกจากที่ระบุ ห้ามลบ AppController/AppService - ห้ามสร้าง index.ts / barrel - ยังไม่ต้องสร้าง endpoint อื่นของสินค้า

ตรวจโค้ดที่ AI สร้าง

  • service เรียก this.config.getOrThrow<string>('APP_URL') — ถ้าเห็น this.config.get(...) ให้แก้เป็น getOrThrow
  • findMany({ orderBy: { id: 'asc' } }) มีจริง ไม่ใช่ findMany() เปล่า
  • object ที่ map ออกมามีเพียงสามคีย์ — ไม่มี id หลุดออกไป
  • import ที่ชี้ไปไฟล์ในโปรเจกต์ลงท้าย .js ครบทั้งสี่จุด (prisma.service.js, products.service.js, products.controller.js, products.module.js)
  • ProductsModule ถูกเพิ่มใน imports ของ AppModule ต่อจาก PrismaModule จริง

AI มักพลาดตรงนี้: hard-code http://localhost:3000 ลงไปใน template string ตรง ๆ (อ่านผ่านตาแล้วดูเหมือนใช้ได้ เพราะ run บนเครื่องแล้วผลตรงกัน แต่สัญญาที่ตั้งไว้คือ host ต้องมาจาก APP_URL) อีกแบบคือ import ConfigModule เข้ามาใน ProductsModule ด้วย — ไม่เสียหายอะไร แต่ไม่จำเป็นเพราะ ConfigModule.forRoot({ isGlobal: true }) ทำให้ ConfigService ใช้ได้ทั่วแอปแล้ว ลบออกให้เหลือเท่าที่จำเป็น

โค้ดอ้างอิงของบทนี้ (เทียบกับของคุณทีละบรรทัด):

src/products/products.service.ts

import { Injectable } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { PrismaService } from '../prisma/prisma.service.js';

@Injectable()
export class ProductsService {
  constructor(
    private readonly prisma: PrismaService,
    private readonly config: ConfigService,
  ) {}

  async findCategories() {
    const appUrl = this.config.getOrThrow<string>('APP_URL');
    const categories = await this.prisma.category.findMany({ orderBy: { id: 'asc' } });
    return categories.map(({ slug, name }) => ({
      slug,
      name,
      url: `${appUrl}/products/category/${slug}`,
    }));
  }
}

src/products/products.controller.ts

import { Controller, Get } from '@nestjs/common';
import { ProductsService } from './products.service.js';

@Controller('products')
export class ProductsController {
  constructor(private readonly productsService: ProductsService) {}

  @Get('categories')
  findCategories() {
    return this.productsService.findCategories();
  }
}

src/products/products.module.ts

import { Module } from '@nestjs/common';
import { ProductsController } from './products.controller.js';
import { ProductsService } from './products.service.js';

@Module({
  controllers: [ProductsController],
  providers: [ProductsService],
})
export class ProductsModule {}

src/app.module.ts

import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';
import { AppController } from './app.controller.js';
import { AppService } from './app.service.js';
import { PrismaModule } from './prisma/prisma.module.js';
import { ProductsModule } from './products/products.module.js';

@Module({
  imports: [ConfigModule.forRoot({ isGlobal: true }), PrismaModule, ProductsModule],
  controllers: [AppController],
  providers: [AppService],
})
export class AppModule {}

ผลลัพธ์ที่คาดหวัง

นี่คือ endpoint แรกของคอร์สที่ตรงกับ contract จริง — ครั้งแรกที่ Postgres, Prisma, seed และ ConfigService ทำงานพร้อมกันทั้งสาย

ตรวจว่าใช้งานได้จริง

  • log ตอน start มีทั้ง ProductsModule dependencies initialized และ Mapped {/products/categories, GET} route
  • เทียบกับ contract โดยแทน host ของเรากลับเป็นของ dummyjson ก่อน แล้ว diff — ต้องได้คำว่า IDENTICAL 
    curl -s http://localhost:3000/products/categories \
  | sed 's#http://localhost:3000#https://dummyjson.com#g' > /tmp/actual.json
diff /tmp/actual.json docs/contract/categories.json && echo IDENTICAL
  • พิสูจน์ว่า host มาจาก config จริง: แก้ APP_URL ใน .env เป็น http://127.0.0.1:3000 restart แล้วยิงซ้ำ — ทุก url ต้องเปลี่ยนตาม (จากนั้นแก้กลับเป็น http://localhost:3000 แล้ว restart)
  • ลบบรรทัด APP_URL ออกจาก .env ชั่วคราว restart แล้วยิงซ้ำ — ต้องได้ error 500 จาก getOrThrow ไม่ใช่ url ที่มีคำว่า undefined (แล้วใส่กลับ)
  • commit ผลงานด้วย git add -A && git commit -m "feat: GET /products/categories"
