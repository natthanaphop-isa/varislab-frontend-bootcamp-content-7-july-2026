GET /products/categories

เมื่อจบบทนี้ คุณจะสามารถ

  • ประกอบ module + controller + service ของ resource products ขึ้นมาใหม่ทั้งชุด แล้วลงทะเบียนเข้า AppModule
  • อธิบายได้ว่าทำไม field url ของ category ต้องอ่าน host จาก APP_URL ไม่ใช่ hard-code
  • ยืนยันด้วย node script ว่า response ของเราตรงกับ section Category ใน docs/api-spec.md — 24 รายการ แต่ละรายการมีเพียงสามคีย์ slug/name/url

เลือก endpoint ที่ง่ายที่สุดขึ้นมาทำก่อน

ใน docs/api-spec.md ที่เขียนไว้ตั้งแต่ตอนออกแบบสัญญา section Category คือ endpoint เดียวที่ไม่มี query parameter ไม่มี route parameter และมีรูปทรง response แบนราบสามคีย์ — นั่นคือ GET /products/categories เราจึงเริ่มจากตัวนี้ เพราะมันพิสูจน์ว่าเส้นทางทั้งเส้น (request → controller → service → Prisma → Postgres → response) เชื่อมกันได้จริง โดยยังไม่ต้องยุ่งกับ mapper หรือ pagination ที่จะมาในบทถัด ๆ ไป

โครงสร้างสามไฟล์เป็นแบบเดียวกับที่คุณเคยทำใน NestJS Fundamentals ตอน controller, service และ module ต่างกันแค่คราวนี้เราไม่พิมพ์เอง — เราสั่ง Cursor พิมพ์ แล้วเราอ่านทุกบรรทัด

  • controller รู้แค่เรื่อง HTTP: path, method, parameter — แล้วส่งต่อให้ service ทันที
  • service เป็นที่เดียวที่รู้จักฐานข้อมูลและรู้จักรูปทรงของ response
  • module ผูกสองตัวนี้เข้าด้วยกันเป็นก้อน แล้วเราเอาก้อนนี้ไปเสียบใน AppModule

field url คือจุดที่ต้องคิด ไม่ใช่จุดที่ต้อง copy

เปิด docs/api-spec.md ดู section Category — response หน้าตาแบบนี้

{ "slug": "beauty", "name": "Beauty", "url": "http://localhost:3000/products/category/beauty" }

url ต้องเป็น host ของตัวเอง ต่อท้ายด้วย path เดียวกัน ไม่ใช่ path เปล่า ๆ — เพราะ type Category ฝั่ง client (src/features/products/types.ts) กำหนดให้ url เป็น URL เต็มเสมอ

host ของตัวเองเปลี่ยนไปตามที่รัน (เครื่องคุณ, staging, production) จึงต้องมาจาก environment variable ไม่ใช่จากโค้ด เรามี APP_URL อยู่ใน .env ตั้งแต่ตอนตั้งค่า Postgres แล้ว และ ConfigModule ถูกตั้งเป็น global ตั้งแต่ตอนต่อ Prisma แล้ว จึงฉีด ConfigService เข้า service ได้เลย

const appUrl = this.config.getOrThrow<string>('APP_URL');

สังเกตว่าเราใช้ getOrThrow ไม่ใช่ get — get คืน undefined เงียบ ๆ เมื่อไม่มีคีย์นั้น ผลคือ url จะกลายเป็น undefined/products/category/beauty แล้วหลุดขึ้น production ไปเงียบ ๆ ส่วน getOrThrow ทำให้แอปพังทันทีที่ request แรก ซึ่งเป็นสิ่งที่เราต้องการ (ทบทวน NestJS Fundamentals ตอนที่ว่าด้วย ConfigService)

ทำไมต้องสั่ง orderBy: { id: 'asc' } ทั้งที่ไม่มีใครขอ

ลำดับของ array ที่ตอบกลับมามีผลต่อ node script ที่ตรวจสัญญาในบทถัด ๆ ไป (นับจำนวน, ตรวจ key) — seed script ส่ง category เข้า createMany เป็น array ตามลำดับที่เขียนไว้ใน CATEGORIES ดังนั้น id ที่ sequence แจกให้ (auto-increment) จึงเรียงตามลำดับนั้นอยู่แล้ว แต่การสั่ง orderBy: { id: 'asc' } คือการเขียนเจตนานั้นออกมา ไม่ใช่การหวังว่า Postgres จะคืนแถวตามลำดับที่ insert — Postgres ไม่รับประกันลำดับให้เลยถ้าไม่สั่ง ORDER BY

ค่า id ที่แท้จริงจะขยับขึ้นทุกครั้งที่ re-seed (ตามที่เจอตอน seed ข้อมูล) แต่ไม่มีผลกับบทนี้ เพราะ id ไม่ถูกส่งออกไปใน response — docs/api-spec.md กำหนดให้ Category มีแค่สามคีย์ slug, name, url เท่านั้น

เป้าหมายของบทนี้

module, controller และ service ของสินค้าที่ถูกลงทะเบียนเข้าแอปแล้ว (ในโค้ดอ้างอิงคือโฟลเดอร์ src/products/ และ ProductsModule ใน src/app.module.ts — Cursor เลือกที่วางและชื่อไฟล์เองได้ตามกติกาใน .cursor/rules) โดยต้องได้ผลลัพธ์นี้

  • GET /products/categories ตอบ 24 รายการตามลำดับที่ seed ไว้ แต่ละรายการมีแค่ { slug, name, url } ไม่มี id
  • host ใน url มาจาก APP_URL — เปลี่ยนค่าแล้ว url เปลี่ยนตาม และถ้าไม่มีค่าต้องพังทันที ไม่ใช่เงียบ
  • controller รู้แค่เรื่อง HTTP ส่วนงานฐานข้อมูลอยู่ใน service และ AppController/AppService เดิมยังอยู่ครบ

สั่ง Cursor สร้าง ProductsModule แล้วอ่านทุกบรรทัด

commit งานก่อน แล้วเปิดแชทใหม่ใน Cursor โหมด Agent (git add -A && git commit -m "chore: before products module") จากนั้นส่ง prompt นี้ทั้งก้อน — กติกาของคอร์สยังเหมือนเดิม: AI พิมพ์แทนคุณได้ แต่คุณต้องอธิบายทุกบรรทัดได้

สร้าง ProductsModule พร้อม endpoint GET /products/categories ตาม section Category ใน docs/api-spec.md @src/app.module.ts ผลลัพธ์ที่ต้องได้: - log ตอน start มีบรรทัด Mapped {/products/categories, GET} route - GET /products/categories ตอบ 200 เป็น array 24 รายการ เรียงตาม id ของหมวด (ลำดับที่ seed ไว้ เริ่มด้วย beauty, fragrances, furniture) - แต่ละรายการมีเพียงสามคีย์ { slug, name, url } ไม่มี id หลุดออกไป - url เป็น URL เต็ม = <APP_URL>/products/category/<slug> โดย APP_URL อ่านจาก .env — เปลี่ยน APP_URL แล้ว restart ทุก url ต้องเปลี่ยนตาม (ห้าม hard-code host) - ถ้าไม่มี APP_URL ใน .env ต้องตอบ error 500 ไม่ใช่ url ที่มีคำว่า undefined - AppController/AppService เดิมยังอยู่ครบ ขอบเขต: - ห้ามติดตั้ง dependency ใหม่ - ยังไม่ต้องสร้าง endpoint อื่นของสินค้า

ตรวจโค้ดที่ AI สร้าง

  • ลบ APP_URL ออกจาก .env ชั่วคราวแล้วยิงซ้ำ ต้องได้ 500 — ถ้าได้ url ที่มีคำว่า undefined แปลว่าโค้ดอ่าน config แบบเงียบ (get) ไม่ใช่แบบพังทันที
  • ลำดับของ array เป็นลำดับที่ seed ไว้ และคงที่ทุกครั้งที่ยิง — โค้ดต้องสั่งเรียงเอง ไม่ใช่หวังพึ่งลำดับที่ Postgres คืนมา
  • แต่ละรายการมีเพียงสามคีย์ — ไม่มี id หลุดออกไป
  • host ไม่ได้ hard-code: ค้น localhost ในไฟล์ที่ Cursor สร้างหรือแก้ต้องไม่เจอ
  • ไม่มีไฟล์ที่ไม่เกี่ยวกับเป้าหมายถูกแก้ (git status), npm run build ผ่าน (import ลงท้าย .js ครบ) และไม่มี any / as / !

AI มักพลาดตรงนี้: hard-code http://localhost:3000 ลงไปใน template string ตรง ๆ (อ่านผ่านตาแล้วดูเหมือนใช้ได้ เพราะ run บนเครื่องแล้วผลตรงกัน แต่สัญญาที่ตั้งไว้คือ host ต้องมาจาก APP_URL) อีกแบบคือ import ConfigModule เข้ามาใน ProductsModule ด้วย — ไม่เสียหายอะไร แต่ไม่จำเป็นเพราะ ConfigModule.forRoot({ isGlobal: true }) ทำให้ ConfigService ใช้ได้ทั่วแอปแล้ว ลบออกให้เหลือเท่าที่จำเป็น

โค้ดอ้างอิงของบทนี้ — เป็นหนึ่งในวิธีที่ถูก ของคุณไม่จำเป็นต้องเหมือนทุกบรรทัด ขอแค่ผ่านผลลัพธ์ที่ต้องได้:

src/products/products.service.ts

import { Injectable } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { PrismaService } from '../prisma/prisma.service.js';

@Injectable()
export class ProductsService {
  constructor(
    private readonly prisma: PrismaService,
    private readonly config: ConfigService,
  ) {}

  async findCategories() {
    const appUrl = this.config.getOrThrow<string>('APP_URL');
    const categories = await this.prisma.category.findMany({ orderBy: { id: 'asc' } });
    return categories.map(({ slug, name }) => ({
      slug,
      name,
      url: `${appUrl}/products/category/${slug}`,
    }));
  }
}

src/products/products.controller.ts

import { Controller, Get } from '@nestjs/common';
import { ProductsService } from './products.service.js';

@Controller('products')
export class ProductsController {
  constructor(private readonly productsService: ProductsService) {}

  @Get('categories')
  findCategories() {
    return this.productsService.findCategories();
  }
}

src/products/products.module.ts

import { Module } from '@nestjs/common';
import { ProductsController } from './products.controller.js';
import { ProductsService } from './products.service.js';

@Module({
  controllers: [ProductsController],
  providers: [ProductsService],
})
export class ProductsModule {}

src/app.module.ts

import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';
import { AppController } from './app.controller.js';
import { AppService } from './app.service.js';
import { PrismaModule } from './prisma/prisma.module.js';
import { ProductsModule } from './products/products.module.js';

@Module({
  imports: [ConfigModule.forRoot({ isGlobal: true }), PrismaModule, ProductsModule],
  controllers: [AppController],
  providers: [AppService],
})
export class AppModule {}
