NestJS E-commerce API Workshop

Scaffold โปรเจกต์ด้วย Nest CLI

เมื่อจบบทนี้ คุณจะสามารถ

  • สร้างโปรเจกต์ ecommerce-api ด้วย nest new และยืนยันได้ว่าได้ scaffold แบบ ESM ของ Nest 12 จริง
  • อธิบายได้ว่า "type": "module" ในไฟล์ package.json ส่งผลอะไรกับทุก import ที่เราจะเขียนต่อจากนี้
  • ตั้งนิสัย commit ก่อนส่ง prompt ทุกครั้ง และใช้ git checkout -- . เป็นปุ่ม undo ของงานที่ AI เขียน

บทนี้ไม่สั่ง AI เพราะไม่มีอะไรให้สั่ง

การสร้างโปรเจกต์เป็นคำสั่งเดียวจบ (nest new ecommerce-api -p npm) และผลลัพธ์ของมันคือ ฐาน ที่ prompt ทุกขั้นหลังจากนี้อ้างอิงอยู่ — ESM, TypeScript strict, Vitest, oxlint ถ้าเราให้ AI สร้างโครงโปรเจกต์เอง มันมีแนวโน้มจะได้ scaffold แบบ CommonJS ของ Nest รุ่นเก่า แล้วกติกาเรื่อง .js ต่อท้าย import ที่เราจะเขียนใน .cursor/rules จะกลายเป็นคำสั่งที่ขัดกับความจริงของโปรเจกต์ทันที งานที่ถูกต้องกว่าคือรันคำสั่งเอง แล้วเอาผลลัพธ์ที่เห็นด้วยตาไปเป็นบริบทให้ AI

สี่คำสั่งที่ต้องเห็นผลด้วยตา

เริ่มจากตรวจเวอร์ชันของ CLI ก่อน คอร์สนี้ต้องได้เลข 12 ถ้าเครื่องคุณยังเป็น 10 หรือ 11 ให้ติดตั้งใหม่ด้วย npm i -g @nestjs/cli@12 (หรือเรียกผ่าน npx @nestjs/cli@12 โดยไม่ติดตั้งแบบ global ก็ได้)

nest --version
# 12.0.0

nest new ecommerce-api -p npm

flag -p npm บอก CLI ว่าใช้ npm เป็น package manager เลย ไม่ต้องถาม ส่วนเรื่องที่ต้องรู้คือ nest new รัน git init ให้เองแล้ว พร้อมสร้าง .gitignore มาให้ — เราจึงไม่ต้อง init ซ้ำ แต่ยังต้อง commit แรกด้วยมือ (CLI ไม่ commit ให้)

ข้างใน scaffold มีอะไร และอะไรที่ต่างจากคอร์ส NestJS Fundamentals

รายละเอียดของแต่ละไฟล์ในโปรเจกต์ Nest เราดูกันไปแล้วใน NestJS Fundamentals — มีอะไรอยู่ในแอป NestJS บทนี้ขอเน้นเฉพาะสามจุดที่กำหนดวิธีเขียนโค้ดของเราไปทั้งคอร์ส

  • "type": "module" ใน package.json — โปรเจกต์นี้เป็น ES module ล้วน ผลตรง ๆ คือ ทุก import ที่ชี้ไฟล์ในโปรเจกต์ต้องลงท้ายด้วย .js แม้ไฟล์จริงจะเป็น .ts (เห็นได้จาก ./app.module.js ด้านล่าง) นี่เป็นข้อผิดพลาดอันดับหนึ่งที่ AI ทำในคอร์สนี้ เราจึงเขียนเป็นกฎถาวรใน .cursor/rules
  • top-level await — ไฟล์ src/main.ts ปิดท้ายด้วย await bootstrap(); เฉย ๆ ไม่มี .catch() ห่อ เพราะ ESM ให้ใช้ await ที่ระดับบนสุดของไฟล์ได้
  • Vitest และ oxlint — scaffold ของ Nest 12 มาพร้อม vitest.config.ts (ไม่มี Jest) และใช้ oxlint เป็น linter โดย script lint คือ oxlint src/ test/ คอร์สนี้ไม่เขียนเทสต์เพิ่ม แต่จะเรียก npm run lint ทุกครั้งหลัง AI แก้โค้ด จึงควรรู้ว่ามันคือ oxlint ไม่ใช่ ESLint
/* src/main.ts ที่ CLI สร้างให้ */
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module.js';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(process.env.PORT ?? 3000);
}
await bootstrap();

process.env.PORT ?? 3000 ที่ CLI ใส่มาให้จะกลายเป็นของจริงตอนที่เราอ่านค่า PORT จาก .env ในขั้นตั้งค่า CORS และ port ภายหลัง ผ่าน ConfigService ตอนนี้ปล่อยไว้ตามเดิม แอปจึงรันที่ port 3000

นิสัยสำคัญที่สุดของคอร์สนี้: commit ก่อนทุก prompt

ตั้งแต่ขั้นที่เริ่มใช้ Cursor เป็นต้นไป ทุกขั้นจะจบด้วยการที่ Cursor แก้ไฟล์หลายไฟล์ในคราวเดียว วิธีเดียวที่จะตรวจงานได้จริงคือให้ git status สะอาด ก่อน ส่ง prompt เพราะเมื่อนั้นทุกบรรทัดที่เปลี่ยนไปคือฝีมือของ AI ทั้งหมด และ git diff ก็จะเป็น checklist ให้เราอ่านทีละบรรทัดได้พอดี

ถ้าผลลัพธ์ไม่เข้าท่า คุณมีปุ่ม undo ที่ไม่ต้องพึ่ง AI: git checkout -- . ย้อนไฟล์ที่ถูกแก้กลับสู่ commit ล่าสุด แล้วเริ่ม prompt ใหม่ได้เลย (ถ้ามีไฟล์ใหม่ที่ AI สร้างค้างอยู่ ใช้ git clean -fd เก็บกวาดต่อ) commit แรกของโปรเจกต์จึงสำคัญกว่าที่คิด — มันคือจุดกลับแรกของเรา

git status
# On branch main
# No commits yet   ← nest new รัน git init ให้แล้ว แต่ยังไม่มี commit

git add -A
git commit -m "chore: scaffold ecommerce-api"

สร้างโปรเจกต์ บูตหนึ่งครั้ง แล้ว commit

เปิด terminal ที่โฟลเดอร์ที่คุณเก็บโปรเจกต์ แล้วรันตามลำดับนี้ด้วยมือทั้งหมด (เปิด terminal ที่สองไว้ยิง curl ขณะที่ start:dev ยังรันอยู่)

nest --version nest new ecommerce-api -p npm cd ecommerce-api npm run start:dev # terminal ที่สอง curl -i http://localhost:3000 # กลับมา terminal แรก กด Ctrl+C หยุด dev server แล้ว commit git add -A git commit -m "chore: scaffold ecommerce-api"

ส่วน git commit รายงานว่ามีไฟล์ถูกเพิ่มประมาณ 17 ไฟล์ — ถ้าตัวเลขเป็นหมื่น แปลว่า node_modules หลุดเข้าไปด้วยเพราะ .gitignore หาย ให้ลบ commit นั้นแล้วตรวจว่ามีไฟล์ .gitignore ที่ CLI สร้างให้อยู่จริงก่อน commit ใหม่

ตรวจว่าใช้งานได้จริง

  • nest --version ขึ้นต้นด้วย 12.
  • git log --oneline แสดง commit เดียวคือ chore: scaffold ecommerce-api
  • cat package.json | grep '"type"' ได้ "type": "module",
  • ls vitest.config.ts พบไฟล์ และ grep '"lint"' package.json ได้ "lint": "oxlint src/ test/"
  • บรรทัดสุดท้ายของ src/main.ts คือ await bootstrap(); และ import ของ AppModule ลงท้ายด้วย .js
  • git status ตอบ nothing to commit, working tree clean — พร้อมสำหรับบทต่อไป
