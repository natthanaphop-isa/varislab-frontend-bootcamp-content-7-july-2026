สร้างคำสั่งซื้อใน Transaction

เมื่อจบบทนี้ คุณจะสามารถ

  • คำนวณ total, discountedPrice และ discountedTotal ให้ตรงกับ dummyjson ทุกหลัก
  • ใช้ interactive transaction อ่านสินค้าและเขียนคำสั่งซื้อในก้อนเดียว และอธิบายได้ว่า rollback เกิดตอนไหน
  • เขียน mapper แปลง Order + OrderItem เป็น response ตามสัญญา โดยไม่ปล่อยข้อมูลส่วนตัวหลุดออกไป

เลขทุกตัวใน response มาจากไหน

ก่อนเขียนโค้ด ต้องถอดสูตรจาก docs/contract/cart-add.txt ให้ครบก่อน ตัวอย่างจริงที่เราจับมาคือสินค้า id 1 ราคา 9.99 ส่วนลด 10.48 เปอร์เซ็นต์ จำนวน 2 ชิ้น

Fieldสูตรตัวอย่างจาก cart-add.txt
products[].totalprice × quantity ปัด 2 ตำแหน่ง9.99 × 2 = 19.98
products[].discountedPriceMath.round(total × (1 − discountPercentage / 100))19.98 × 0.8952 = 17.886 → 18
totalผลรวม total ของทุกรายการ ปัด 2 ตำแหน่ง19.98
discountedTotalผลรวม discountedPrice ของทุกรายการ18
totalProductsจำนวนรายการ ใน products[]1
totalQuantityผลรวม quantity ของทุกรายการ2

จุดที่ต้องระวังที่สุดคือบรรทัดที่สอง: discountedPrice ถูกปัดเป็น จำนวนเต็ม ไม่ใช่ทศนิยมสองตำแหน่ง ค่าที่ถูกคือ 18 ไม่ใช่ 17.89 ถ้าเราทำเป็นทศนิยม ตัวเลขบนหน้า checkout ของ React app จะไม่ตรงกับตอนที่ยังใช้ dummyjson ทันที เราไม่ได้กำลังออกแบบสูตรคิดเงินที่ดีที่สุด เรากำลังเลียนแบบสัญญาเดิมให้เป๊ะ — นั่นคือทั้งหมดของงานนี้

ส่วน total ใช้การปัดสองตำแหน่งผ่าน helper round2 เพราะเลขทศนิยมแบบ floating point ทำให้การบวกราคาสะสมเพี้ยนได้ (เช่น 0.1 + 0.2 ได้ 0.30000000000000004) และ totalProducts นับจำนวนบรรทัด ไม่ใช่จำนวนชิ้น — สั่งสินค้าตัวเดียว 2 ชิ้นจะได้ totalProducts: 1 กับ totalQuantity: 2

อ่านและเขียนในก้อนเดียวด้วย interactive transaction

การสร้างคำสั่งซื้อต้องทำสองอย่าง: อ่านราคาสินค้าจากตาราง Product แล้วเขียน Order พร้อมรายการลงไป ถ้าปล่อยสองอย่างนี้อยู่นอก transaction จะเกิดปัญหาสองแบบ — ราคาถูกแก้ระหว่างที่เราอ่านเสร็จแต่ยังไม่เขียน (ใบเสร็จได้ราคาผีที่ไม่มีอยู่จริงในช่วงเวลาใดเลย) และถ้าการเขียนพังกลางทางก็จะเหลือข้อมูลค้างครึ่ง ๆ

คำตอบคือ interactive transaction แบบเดียวกับบทที่ 29 ของคอร์ส NestJS Fundamentals: this.prisma.$transaction(async (tx) => { … }) ทุก query ข้างในต้องเรียกผ่าน tx ไม่ใช่ this.prisma ไม่งั้น query นั้นจะหลุดออกไปอยู่นอก transaction เงียบ ๆ

สิ่งที่ทำให้ pattern นี้สวยคือการจัดการ error: ถ้ามี id สินค้าที่ไม่มีจริง เรา throw new NotFoundException(...) ข้างใน callback ได้เลย Prisma จะ rollback ทุกอย่างให้อัตโนมัติเพราะ callback reject และ Nest จะแปลง exception ตัวนั้นเป็น response 404 ให้เอง เราจึงไม่ต้องเขียนโค้ดลบข้อมูลที่เพิ่งสร้างเลยแม้แต่บรรทัดเดียว

การเขียน Order กับ OrderItem ใช้ nested write (บทที่ 27 ของคอร์ส NestJS Fundamentals) คือ items: { create: items } ข้างใน tx.order.create() — Prisma ออก INSERT ให้ทั้งใบและทุกบรรทัดในคำสั่งเดียว โดยเติม orderId ให้เองหลังได้ id ของ Order ส่วน include: { items: { orderBy: { id: 'asc' } } } ทำให้ได้รายการกลับมาพร้อมกันในลำดับที่เขียนลงไป — ไม่ต้อง query ซ้ำ และ products[] ใน response เรียงตรงกับที่ client ส่งมา

เราอ่านสินค้าทั้งหมดด้วย findMany({ where: { id: { in: ids } } }) ครั้งเดียวแล้วทำ Map จาก id ไปหา product ไม่ใช่ loop findUnique ทีละตัว — ตะกร้า 10 รายการจึงเป็น 1 query ไม่ใช่ 10 query ส่วนการวน dto.products.map(...) ต่อจากนั้นทำให้ลำดับของ response ตรงกับลำดับที่ client ส่งมาเสมอ ไม่ใช่ลำดับที่ฐานข้อมูลคืนแถวมา

อีกเรื่องที่ตั้งใจไม่ทำ: เราไม่ลด stock ของสินค้า เพราะ dummyjson ก็ไม่ลด และ React app อ่าน stock จาก GET /products/:id ใหม่ทุกครั้งที่เปิดหน้าสินค้า ถ้าเราลด stock ขึ้นมาเอง พฤติกรรมของแอปจะเปลี่ยนไปจากเดิมทันทีทั้งที่เราไม่ได้แก้ frontend — ขัดกับเป้าหมายของคอร์สนี้

mapper กันข้อมูลส่วนตัวหลุด

แถวที่ Prisma คืนมามีมากกว่าที่สัญญาอนุญาตให้ส่งออก: Order มี address, email, phone, createdAt ที่ response ของ dummyjson ไม่มี และ OrderItem มี id ของตัวเองซึ่งไม่ใช่ products[].id ที่ client ต้องการ — client ต้องการ productId เพราะมันใช้ค่านั้นลิงก์ไปหน้าสินค้า

เราจึงใช้ mapper แบบเดียวกับบทที่ 11 คือฟังก์ชันบริสุทธิ์ที่แปลงแถวเป็น response DTO ทีละ field อย่างชัดเจน ข้อดีคือ field ที่เพิ่มใน schema วันหลังจะไม่รั่วออก API เอง เพราะถ้าไม่เขียนไว้ใน mapper มันก็ไม่ถูกส่ง

สั่ง Cursor เขียน OrdersService

commit งานก่อน แล้วเปิดแชทใหม่ใน Cursor โหมด Agent (git add -A && git commit -m "chore: before orders service") — prompt นี้ยาวที่สุดในคอร์ส เพราะมันต้องบอกทั้งสูตรคำนวณ ทั้งโครงสร้างของ transaction และยกไฟล์ @src/products/products.service.ts กับ @src/products/product.mapper.ts เป็นแบบอย่างของสไตล์โปรเจกต์ ให้ AI ไม่ต้องเดา

ก่อนส่ง อ่านกติกาของคอร์สอีกครั้ง: AI พิมพ์แทนคุณได้ แต่คุณต้องอธิบายทุกบรรทัดได้ — ถ้าอธิบายไม่ได้ แปลว่ายังไม่ผ่านบทนี้

สร้าง OrdersService ที่บันทึกคำสั่งซื้อใน transaction และคืน cart ตามรูปทรง dummyjson บริบท: @prisma/schema.prisma @src/orders/dto/add-cart.dto.ts @src/products/products.service.ts @src/products/product.mapper.ts @src/products/dto/product-response.dto.ts @docs/contract/cart-add.txt @.cursor/rules/project.mdc schema มี Order และ OrderItem แล้ว (migrate และ generate แล้ว) docs/contract/cart-add.txt คือ response จริงของ POST /carts/add ด้วย body { userId: 1, products: [{ id: 1, quantity: 2 }] }: { "id": 209, "products": [{ "id": 1, "title": "Essence Mascara Lash Princess", "price": 9.99, "quantity": 2, "total": 19.98, "discountPercentage": 10.48, "discountedPrice": 18, "thumbnail": "..." }], "total": 19.98, "discountedTotal": 18, "userId": 1, "totalProducts": 1, "totalQuantity": 2 } กติกาคำนวณ: total ของรายการ = price × quantity ปัดทศนิยม 2 ตำแหน่ง, discountedPrice = Math.round(total × (1 − discountPercentage / 100)) เป็นจำนวนเต็ม, total ของ cart = ผลรวม total ของทุกรายการปัด 2 ตำแหน่ง, discountedTotal = ผลรวม discountedPrice, totalProducts = จำนวนรายการ, totalQuantity = ผลรวม quantity products.service.ts และ product.mapper.ts คือรูปแบบมาตรฐานของ service และ mapper ในโปรเจกต์นี้ ให้ทำตาม สินค้าที่ id ไม่มีจริงต้องได้ 404 ข้อความ Product with id '<id>' not found แบบเดียวกับ ProductsService โครงสร้าง: สร้างไฟล์ตามนี้ ไม่มากไม่น้อยกว่านี้ - src/orders/dto/cart-response.dto.ts (สร้างใหม่) - src/orders/cart.mapper.ts (สร้างใหม่) - src/orders/orders.service.ts (สร้างใหม่) ข้อกำหนดทางเทคนิค: - cart-response.dto.ts: export class CartProductResponseDto { id, title, price, quantity, total, discountPercentage, discountedPrice, thumbnail } (type ตาม contract) และ export class CartResponseDto { id: number; ตรวจโค้ดที่ AI สร้าง

  • ทั้ง tx.product.findMany และ tx.order.create อยู่ข้างใน callback ของ $transaction และเรียกผ่าน tx ไม่มี this.prisma. โผล่ข้างในเลย
  • discountedPrice ใช้ Math.round(...) ได้จำนวนเต็ม ไม่ใช่ round2(...) — ตรวจว่าตัวอย่าง 9.99 × 2 ที่ 10.48% ให้ 18 ไม่ใช่ 17.89
  • round2() ประกาศเป็นฟังก์ชันระดับไฟล์นอก class และถูกใช้กับ total ของรายการและ total ของใบ
  • วนสร้างรายการจาก dto.products.map(...) (ลำดับตาม request) แล้วหา product จาก Map ไม่ใช่วนจากผลลัพธ์ของ findMany
  • ข้อความ 404 ตรงกับ ProductsService ทุกตัวอักษร: Product with id '${id}' not found
  • tx.order.create ใช้ items: { create: items } พร้อม include: { items: { orderBy: { id: 'asc' } } }
  • address ที่ลงคอลัมน์คือ dto.address.address ส่วน email และ phone มาจาก dto.address.* เช่นกัน (ไม่ใช่เก็บ object ทั้งก้อนเป็น JSON)
  • mapper ใช้ item.productId เป็น id ของ products[] และไม่มี address, email, phone, createdAt ใน object ที่ return
  • ไม่มีคำว่า stock, any หรือ as ในสามไฟล์นี้ และ import ทุกตัวลงท้ายด้วย .js

AI มักพลาดตรงนี้: คำนวณ discountedPrice เป็นทศนิยมสองตำแหน่ง (ได้ 17.89 ทั้งที่ dummyjson ให้ 18) เพราะดู "ถูกต้องกว่า" ในแง่คณิตศาสตร์ แต่ทำให้ยอดบนหน้าจอ React เปลี่ยนไปจากเดิม อีกกรณีคือดึงสินค้าด้วย this.prisma.product.findMany ไว้ก่อน เปิด transaction แล้วค่อยเปิด transaction เพื่อ create — แบบนั้นการอ่านไม่ได้อยู่ใน snapshot เดียวกับการเขียน และถ้า throw 404 ก็ไม่มีอะไรต้อง rollback จริง (ดูเหมือนทำงานถูก แต่ผิดเจตนา) กรณีที่สามคือ mapper ส่ง item.id ออกไปเป็น products[].id ซึ่งจะทำให้ลิงก์ไปหน้าสินค้าของ React พาไปสินค้าผิดตัว

โค้ดอ้างอิงของบทนี้ (เทียบกับของคุณทีละบรรทัด):

// src/orders/dto/cart-response.dto.ts
export class CartProductResponseDto {
  id: number;
  title: string;
  price: number;
  quantity: number;
  total: number;
  discountPercentage: number;
  discountedPrice: number;
  thumbnail: string;
}

export class CartResponseDto {
  id: number;
  products: CartProductResponseDto[];
  total: number;
  discountedTotal: number;
  userId: number;
  totalProducts: number;
  totalQuantity: number;
}
// src/orders/cart.mapper.ts
import type { Order, OrderItem } from '../generated/prisma/client.js';
import { CartResponseDto } from './dto/cart-response.dto.js';

export type OrderWithItems = Order & { items: OrderItem[] };

export function toCartResponse(order: OrderWithItems): CartResponseDto {
  return {
    id: order.id,
    products: order.items.map((item) => ({
      id: item.productId,
      title: item.title,
      price: item.price,
      quantity: item.quantity,
      total: item.total,
      discountPercentage: item.discountPercentage,
      discountedPrice: item.discountedPrice,
      thumbnail: item.thumbnail,
    })),
    total: order.total,
    discountedTotal: order.discountedTotal,
    userId: order.userId,
    totalProducts: order.totalProducts,
    totalQuantity: order.totalQuantity,
  };
}
// src/orders/orders.service.ts
import { Injectable, NotFoundException } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service.js';
import { toCartResponse } from './cart.mapper.js';
import { AddCartDto } from './dto/add-cart.dto.js';
import { CartResponseDto } from './dto/cart-response.dto.js';

function round2(value: number): number {
  return Math.round(value * 100) / 100;
}

@Injectable()
export class OrdersService {
  constructor(private readonly prisma: PrismaService) {}

  async create(dto: AddCartDto): Promise<CartResponseDto> {
    const order = await this.prisma.$transaction(async (tx) => {
      const ids = dto.products.map((product) => product.id);
      const products = await tx.product.findMany({ where: { id: { in: ids } } });
      const productById = new Map(products.map((product) => [product.id, product]));

      const items = dto.products.map(({ id, quantity }) => {
        const product = productById.get(id);
        if (!product) {
          throw new NotFoundException(`Product with id '${id}' not found`);
        }
        const total = round2(product.price * quantity);
        return {
          productId: product.id,
          title: product.title,
          thumbnail: product.thumbnail,
          price: product.price,
          discountPercentage: product.discountPercentage,
          quantity,
          total,
          discountedPrice: Math.round(total * (1 - product.discountPercentage / 100)),
        };
      });

      return tx.order.create({
        data: {
          userId: dto.userId,
          address: dto.address.address,
          email: dto.address.email,
          phone: dto.address.phone,
          total: round2(items.reduce((sum, item) => sum + item.total, 0)),
          discountedTotal: items.reduce((sum, item) => sum + item.discountedPrice, 0),
          totalProducts: items.length,
          totalQuantity: items.reduce((sum, item) => sum + item.quantity, 0),
          items: { create: items },
        },
        include: { items: { orderBy: { id: 'asc' } } },
      });
    });

    return toCartResponse(order);
  }
}

ผลลัพธ์ที่คาดหวัง

ได้ไฟล์ใหม่สามไฟล์ใน src/orders/ และ npm run build กับ npm run lint ผ่านทั้งคู่โดยไม่มี error หรือ warning ยังไม่มี route ใหม่ใน log ของ dev server และยังไม่มีอะไรให้ curl เพราะ OrdersService ยังไม่ถูกลงทะเบียนใน module ไหน — ถ้า build ผ่านแต่ลืมสิ่งนี้ Nest จะไม่บ่นอะไรเลย มันแค่ไม่มีใครเรียก service ตัวนี้

type ที่ tx.order.create คืนมาต้องเข้ากับ OrderWithItems ได้เองโดยไม่ต้อง cast — ถ้า TypeScript บ่นตรงบรรทัดที่เรียก toCartResponse(order) ให้กลับไปดูว่า include: { items: … } หายไปหรือเปล่า นั่นคือกลไกที่ทำให้ include ที่หายไปกลายเป็น compile error ไม่ใช่บั๊กตอน runtime

ตรวจว่าใช้งานได้จริง

  • npm run build && npm run lint ผ่านทั้งสองคำสั่ง
  • grep -n "Math.round" src/orders/orders.service.ts เจอสองที่: ใน round2 และที่ discountedPrice
  • grep -n "this.prisma" src/orders/orders.service.ts เจอแค่สองบรรทัด คือ constructor และบรรทัดที่เปิด $transaction — ยืนยันว่าไม่มี query หลุดออกนอก transaction
  • grep -n "stock\|: any\| as " src/orders/orders.service.ts ไม่เจออะไรเลย
  • คิดเลขตามด้วยมือใน node -e "console.log(Math.round(19.98 * (1 - 10.48 / 100)))" ได้ 18 ตรงกับ discountedPrice ใน docs/contract/cart-add.txt
  • git status เห็นเฉพาะสามไฟล์ใหม่ ไม่มี app.module.ts หรือไฟล์ใน src/products/ ติดมา
  • commit ผลงานของบทนี้: git add -A && git commit -m "feat: orders service"
