GET /products/:id

เมื่อจบบทนี้ คุณจะสามารถ

  • รับ route parameter ด้วย @Param('id', ParseIntPipe) แล้วส่งต่อเป็น number ให้ service
  • อธิบายว่าทำไม @Get('categories') ต้องประกาศไว้ก่อน @Get(':id') เสมอ
  • พิสูจน์ด้วย diff ว่า response ของสินค้าชิ้นที่ 1 ตรงกับ contract ทุกคีย์ และข้อความใน NotFoundException ตรงตัวอักษรต่ออักษรกับ dummyjson

บทนี้คือบทที่ mapper ได้ทำงานจริง

บทที่ 11 เขียน toProductResponse ไว้แต่ยังไม่มีใครเรียก บทนี้เราต่อสายให้ครบ: controller รับ id → service query สินค้าพร้อม relation → ส่งแถวเข้า mapper → คืน JSON ที่ตรงกับ docs/contract/product-1.json

รูปแบบการรับ parameter เป็นแบบเดียวกับ Week_09 บทที่ 7 (route parameters) และการโยน error เป็นแบบเดียวกับบทที่ 13 (ข้อความ error ที่อ่านรู้เรื่อง) ต่างกันที่คราวนี้ข้อความไม่ใช่เรื่องรสนิยม — มันคือส่วนหนึ่งของสัญญา

ข้อความ 404 คือสัญญา ไม่ใช่ข้อความประกอบ

เปิด docs/contract/product-not-found.txt ที่วางไว้ในบทที่ 3 dummyjson ตอบ status 404 พร้อม body

{ "message": "Product with id '9999' not found" }

React app ที่เราจะต่อในบทที่ 23 อ่าน data.message มาโชว์ให้ผู้ใช้เห็นตรง ๆ ผ่าน ApiError ของมัน ถ้าเราเขียนเป็น Product #9999 not found แบบที่เคยทำใน Week_09 หน้าเว็บก็ยังไม่พัง แต่ข้อความที่ผู้ใช้เห็นจะเปลี่ยนไป และ script ตรวจสัญญาในบทที่ 15 จะจับได้ทันที จุดที่ต้องระวังเป็นพิเศษคือ single quote ครอบตัวเลข — ไม่ใช่ double quote ไม่ใช่ backtick ไม่ใช่ไม่มีเลย

throw new NotFoundException(`Product with id '${id}' not found`);

backtick ด้านนอกคือ template literal ของ JavaScript ส่วน single quote ด้านในเป็นตัวอักษรจริงที่จะโผล่ใน JSON

include และเหตุผลที่ต้องสั่ง orderBy ให้ reviews

แถว Product เปล่า ๆ ไม่มี category และไม่มี reviews ติดมา เราจึงต้องสั่ง include (ทบทวน Week_09 บทที่ 26 เรื่องดึง model พร้อม relation)

include: { category: true, reviews: { orderBy: { id: 'asc' } } }

ทำไมต้องมี orderBy ให้ reviews ด้วย? เพราะ array ที่ลำดับไม่ตรงกันคือ diff ที่ไม่ผ่าน และ Postgres ไม่รับประกันลำดับของแถวที่คืนมาถ้าไม่มี ORDER BY — มันจะเรียงตามที่สะดวกที่สุดในแผนการ query นั้น ๆ ซึ่งอาจเปลี่ยนเมื่อข้อมูลโตขึ้นหรือมี index ใหม่ seed ในบทที่ 9 ใส่ review ตามลำดับที่ dummyjson ส่งมาใน products[].reviews ดังนั้น id น้อยไปมากคือลำดับเดียวกับ dummyjson

ลำดับการประกาศ route คือลำดับที่ Nest ลองจับ

Nest ลงทะเบียน handler ตามลำดับที่ประกาศไว้ใน class และ router จะจับ pattern แรกที่ตรง ถ้าเราเผลอวาง @Get(':id') ไว้ก่อน

GET /products/categories
  → ตรงกับ pattern /products/:id  (id = "categories")
  → ParseIntPipe แปลง "categories" ไม่ได้
  → 400 Bad Request

endpoint ที่เคยทำงานในบทที่ 10 จะตายเงียบ ๆ ทั้งที่เราไม่ได้แตะโค้ดของมันเลย กฎง่าย ๆ คือ route ที่เป็นคำตายตัวต้องมาก่อน route ที่มี parameter เสมอ ดังนั้นใน ProductsController เราวาง findOne เป็น handler สุดท้ายของ class ตั้งแต่วันนี้ แล้วบทที่ 13 และ 14 จะแทรก handler ใหม่ไว้ก่อนมันทุกครั้ง

ความต่างหนึ่งข้อที่เรายอมรับ

ถ้ายิง GET /products/abc dummyjson ตอบ 404 แต่ของเราตอบ 400 พร้อมข้อความ Validation failed (numeric string is expected) เพราะ ParseIntPipe ดักไว้ก่อนที่ handler จะทำงาน

เราเลือกที่จะไม่แก้ เพราะ React app ไม่เคยยิง id ที่ไม่ใช่ตัวเลข (มันได้ id มาจาก list ที่ API ตอบไป) และ 400 เป็นคำตอบที่ตรงความจริงกว่า: request นั้นผิดรูป ไม่ใช่ resource ไม่มีอยู่ ความต่างข้อนี้จะถูกบันทึกไว้ในตารางของบทที่ 15 พร้อมเหตุผล — การรู้และเขียนไว้ว่าต่างที่ไหน ต่างจากการไม่รู้ว่าต่าง

สั่ง Cursor ต่อ endpoint สินค้าหนึ่งชิ้น

commit งานก่อน แล้วเปิดแชทใหม่ใน Cursor โหมด Agent (git add -A && git commit -m "chore: before product by id") จากนั้นส่ง prompt นี้

เพิ่ม endpoint GET /products/:id ที่ตอบสินค้าหนึ่งชิ้นตามรูปทรง dummyjson และ 404 ด้วยข้อความเดียวกัน บริบท: @src/products/products.controller.ts @src/products/products.service.ts @src/products/product.mapper.ts @src/products/dto/product-response.dto.ts @docs/contract/product-1.json @docs/contract/product-not-found.txt @.cursor/rules/project.mdc มี toProductResponse(product: ProductWithRelations) ที่รับแถวสินค้าพร้อม category และ reviews แล้วคืน ProductResponseDto docs/contract/product-not-found.txt คือ response จริงของ GET /products/9999: status 404 body { "message": "Product with id '9999' not found" } reviews ต้องเรียงตามลำดับที่ seed (id น้อยไปมาก) เพื่อให้ตรงกับ dummyjson controller มี route GET /products/categories อยู่แล้ว route ใหม่ที่มี parameter ต้องประกาศไว้หลัง route ที่เป็นคำตายตัวเสมอ โครงสร้าง: แก้ไฟล์ตามนี้ ไม่มากไม่น้อยกว่านี้ - src/products/products.service.ts (แก้ไข: เพิ่ม method) - src/products/products.controller.ts (แก้ไข: เพิ่ม handler) ข้อกำหนดทางเทคนิค: - service: async findOne(id: number): Promise<ProductResponseDto> ใช้ this.prisma.product.findUnique({ where: { id }, include: { category: true, reviews: { orderBy: { id: 'asc' } } } }) ถ้าได้ null ให้ throw new NotFoundException(`Product with id '${id}' not found`) ข้อความต้องตรงตัวอักษรต่ออักษรรวม single quote คืน toProductResponse(product) - controller: handler @Get(':id') findOne(@Param('id', ParseIntPipe) id: number) วางไว้เป็น handler สุดท้ายของ class ต่อจาก findCategories - ห้ามแก้ findCategories ห้ามแตะ mapper ขอบเขต: - ห้ามติดตั้ง dependency ใหม่ - ห้ามแก้ไฟล์อื่นนอกจากที่ระบุ - ยังไม่ต้องทำ GET /products (list) หรือ pagination

ตรวจโค้ดที่ AI สร้าง

  • controller ใช้ @Param('id', ParseIntPipe) id: number — ไม่ใช่ @Param('id') id: string แล้วแปลงเองในภายหลัง
  • service ใช้ findUnique และมี include: { category: true, reviews: { orderBy: { id: 'asc' } } } ครบทั้งสองส่วน
  • ข้อความ error ตรงตัวอักษรต่ออักษร: Product with id '9999' not found — single quote ครอบตัวเลข
  • findOne เป็น handler สุดท้าย ของ class อยู่ใต้ findCategories
  • return type ของ service เขียนไว้ชัดเป็น Promise<ProductResponseDto>
  • findCategories เดิมไม่ถูกแก้ และไฟล์ mapper/DTO ไม่มีการเปลี่ยนแปลง (git diff --stat ต้องเห็นแค่สองไฟล์)

AI มักพลาดตรงนี้: เขียนข้อความเป็น Product #9999 not found ตามสไตล์ที่เคยเห็นใน Week_09 (ซึ่งเป็นข้อความที่ถูกต้องในคอร์สนั้น แต่ผิดสัญญาในคอร์สนี้) อีกแบบคือใช้ findFirst({ where: { id } }) โดยลืม include ทั้งก้อน — TypeScript จะฟ้องเมื่อส่งเข้า toProductResponse เพราะ type ProductWithRelations ไม่ยอม แต่บางครั้ง Cursor จะแก้ปัญหาด้วยการเติม as เข้าไปกลบ ให้ค้นคำว่า as ในไฟล์แล้วลบออก แก้ที่ include แทน

โค้ดอ้างอิงของบทนี้ (เทียบกับของคุณทีละบรรทัด):

src/products/products.service.ts

import { Injectable, NotFoundException } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { PrismaService } from '../prisma/prisma.service.js';
import { toProductResponse } from './product.mapper.js';
import { ProductResponseDto } from './dto/product-response.dto.js';

@Injectable()
export class ProductsService {
  constructor(
    private readonly prisma: PrismaService,
    private readonly config: ConfigService,
  ) {}

  async findCategories() {
    const appUrl = this.config.getOrThrow<string>('APP_URL');
    const categories = await this.prisma.category.findMany({ orderBy: { id: 'asc' } });
    return categories.map(({ slug, name }) => ({
      slug,
      name,
      url: `${appUrl}/products/category/${slug}`,
    }));
  }

  async findOne(id: number): Promise<ProductResponseDto> {
    const product = await this.prisma.product.findUnique({
      where: { id },
      include: { category: true, reviews: { orderBy: { id: 'asc' } } },
    });
    if (!product) {
      throw new NotFoundException(`Product with id '${id}' not found`);
    }
    return toProductResponse(product);
  }
}

src/products/products.controller.ts

import { Controller, Get, Param, ParseIntPipe } from '@nestjs/common';
import { ProductsService } from './products.service.js';

@Controller('products')
export class ProductsController {
  constructor(private readonly productsService: ProductsService) {}

  @Get('categories')
  findCategories() {
    return this.productsService.findCategories();
  }

  @Get(':id')
  findOne(@Param('id', ParseIntPipe) id: number) {
    return this.productsService.findOne(id);
  }
}

ตรวจว่าใช้งานได้จริง

  • เทียบสินค้าชิ้นที่ 1 กับ contract โดยเรียงคีย์ทั้งสองฝั่งให้เหมือนกันก่อน — ต้องได้ IDENTICAL 
    curl -s http://localhost:3000/products/1 \
  | node -e "let d='';process.stdin.on('data',c=>d+=c).on('end',()=>console.log(JSON.stringify(JSON.parse(d),Object.keys(JSON.parse(d)).sort())))" > /tmp/actual.json
node -e "const d=require('./docs/contract/product-1.json');console.log(JSON.stringify(d,Object.keys(d).sort()))" > /tmp/expected.json
diff /tmp/actual.json /tmp/expected.json && echo IDENTICAL

    (คำสั่ง node -e ใช้ require ได้ ทั้งที่โปรเจกต์เป็น "type": "module" เพราะสคริปต์ที่ส่งผ่าน -e ถูกรันเป็น CommonJS โดยปริยาย)

  • curl -i http://localhost:3000/products/9999 ได้ 404 พร้อม "message":"Product with id '9999' not found" ตรงตัวอักษร
  • curl -s http://localhost:3000/products/categories ยังตอบ array 24 ก้อนเหมือนบทที่ 10 — พิสูจน์ว่าลำดับ route ถูก (ถ้าได้ 400 แปลว่า @Get(':id') ไปอยู่ข้างบน)
  • หาสินค้าที่ไม่มีแบรนด์แล้วยืนยันว่าคีย์ brand หายไปทั้งคีย์ — ในฐานข้อมูลที่ seed มา สินค้า id 16 คือตัวหนึ่งที่ brand เป็น null 
    curl -s http://localhost:3000/products/16 \
  | node -e "let d='';process.stdin.on('data',c=>d+=c).on('end',()=>console.log('brand' in JSON.parse(d)))"
# ต้องพิมพ์ false
  • curl -i http://localhost:3000/products/abc ได้ 400 พร้อม Validation failed (numeric string is expected) — ความต่างที่เรายอมรับ ไม่ใช่ bug
