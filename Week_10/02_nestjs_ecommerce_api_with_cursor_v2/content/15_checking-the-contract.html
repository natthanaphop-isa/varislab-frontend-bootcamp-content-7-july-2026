ตรวจสัญญากับ dummyjson อัตโนมัติ

เมื่อจบบทนี้ คุณจะสามารถ

  • เปลี่ยนการตรวจสัญญาจาก curl ทีละคำสั่งเป็นคำสั่งเดียวที่ตรวจแปด request ให้ครบ
  • อธิบายว่าทำไมการเทียบต้อง normalize ก่อน และเขียนตัวเทียบที่บอก path แรกที่ต่างกัน ไม่ใช่แค่บอกว่า "ต่าง"
  • รู้และเขียนไว้เป็นลายลักษณ์อักษรว่า API ของเราต่างจาก dummyjson ที่จุดไหน และทำไมยอมรับได้

curl ทีละคำสั่งไม่ขยายตาม

ห้าบทที่ผ่านมาเราตรวจสัญญาด้วยมือ: ยิง curl เรียงคีย์ diff ดูคำว่า IDENTICAL วิธีนี้ได้ผลตอนมี endpoint เดียว แต่ตอนนี้มีสี่ตัว และแต่ละตัวมีหลายกรณี (หน้าแรก, หน้าสุดท้าย, id ที่ไม่มี, หมวดที่ไม่มี) การจะรู้ว่าการแก้โค้ดวันนี้ทำสัญญาพังหรือไม่ ต้องไล่ยิงใหม่หมดทุกครั้ง ซึ่งจะไม่มีใครทำ

สิ่งที่เราต้องการคือ regression test ของสัญญา: คำสั่งเดียวที่ยิง request ชุดเดิมไปทั้งสองฝั่ง (ของเราและ dummyjson จริง) เทียบผล แล้วบอกว่าต่างที่ path ไหน — และคืน exit code ที่ไม่ใช่ศูนย์เมื่อพัง เพื่อให้เอาไปแขวนใน CI ได้ในอนาคต

จุดที่ทำให้ script นี้ต่างจาก unit test คือมันยิง dummyjson จริง ไม่ได้เทียบกับไฟล์สัญญาที่วางไว้ตอนบทที่ 3 ดังนั้นถ้าวันหนึ่ง dummyjson เปลี่ยนรูปทรง เราจะรู้ (ข้อเสียคือมันต้องมีเน็ต และช้ากว่า test ปกติ — จึงเป็นคำสั่งแยก ไม่ผูกกับ npm test)

normalize: ทำให้สองฝั่งเทียบกันได้อย่างเป็นธรรม

ถ้าเอา JSON สองก้อนมาเทียบตรง ๆ จะพังด้วยเรื่องที่ไม่ใช่ความผิด สองเรื่อง

  • ลำดับคีย์ — JSON object ไม่มีความหมายเรื่องลำดับ (ต่างจาก array) ถ้าเราสลับตำแหน่ง brand กับ sku client ก็อ่านได้เหมือนกัน เราจึงสร้าง object ใหม่ที่เรียงคีย์ตามตัวอักษรทั้งสองฝั่งก่อนเทียบ
  • host ใน string — field url ของ category ต้องต่างกันโดยตั้งใจ (นั่นคือประเด็นทั้งหมดของบทที่ 10) เราจึงแทนที่ https://dummyjson.com ด้วย http://localhost:3000 ในทุก string ก่อนเทียบ

สังเกตว่า normalize ทำงานกับ ทุก string ไม่ใช่เฉพาะ field url — เขียนแบบนี้สั้นกว่าและปลอดภัยกว่าการไล่ระบุ field ทีละตัว เพราะถ้า dummyjson เพิ่ม field ที่มี host ขึ้นมาใหม่ เราก็ยังเทียบได้

ส่วน response ที่เป็น error เราเทียบ เฉพาะ message เพราะ body ของ HttpException ใน Nest มีคีย์ error และ statusCode เพิ่มมาเสมอ ซึ่งเป็นความต่างที่เราตั้งใจยอมรับ (client อ่านแค่ message) ถ้าเทียบทั้งก้อน ทุก error path จะขึ้น ❌ ตลอดกาลจนเราเลิกดูมัน — และ test ที่แดงตลอดเวลาคือ test ที่ไม่มีอยู่

บอก path แรกที่ต่างกัน ไม่ใช่บอกว่า "ต่าง"

วิธีที่ง่ายที่สุดคือ JSON.stringify(a) === JSON.stringify(b) ซึ่งบอกได้แค่ว่าเหมือนหรือไม่เหมือน เมื่อ response มีสินค้า 30 ชิ้น แต่ละชิ้น 22 คีย์ คำตอบว่า "ไม่เหมือน" ไม่ช่วยอะไรเลย

firstDifference จึงเดินลงไปทีละชั้นแล้วคืน path เป็น string เช่น

$.thumbnail missing on local
$.products.length 3 vs 2
$.products[0].brand: "Essence" vs undefined

สิ่งที่มันต้องจับให้ครบมีสามแบบ: ความยาว array ไม่เท่ากัน, คีย์ที่หายไปฝั่งใดก็ได้ (จึงต้องวน union ของคีย์ทั้งสองฝั่ง ไม่ใช่วนแค่ฝั่งเดียว), และค่าที่ต่างกัน

ทำไม node scripts/contract-check.ts รันได้เลย ไม่ต้องมี tsx

ใน package.json เราใช้ tsx รัน prisma/seed.ts แต่ script นี้เรียก node ตรง ๆ เพราะ Node 24 ขึ้นไปรันไฟล์ .ts ได้เองด้วยการ ลบ type ออก (type stripping) ไม่ได้ compile — จึงเร็วและไม่ต้องมี dependency เพิ่ม

ข้อแลกเปลี่ยนคือมันลบได้เฉพาะ syntax ที่ "ลบแล้วโค้ดยังถูก" (erasable syntax) สิ่งที่ใช้ไม่ได้คือ enum, namespace และ parameter property (constructor(private x: number)) เพราะสามอย่างนี้ต้อง สร้างโค้ดเพิ่ม ไม่ใช่แค่ลบ prompt ของบทนี้จึงห้ามทั้งสามตัวไว้ชัด ๆ และห้าม import ด้วย เพื่อให้ script เป็นไฟล์เดียวจบ ไม่ต้องพึ่ง resolution ของโปรเจกต์เลย

fetch, Promise.all และ top-level await เป็นของที่มีใน Node อยู่แล้ว ไม่ต้องติดตั้ง node-fetch หรืออะไรเพิ่ม

ความต่างที่เรายอมรับ — และเหตุผล

เอกสารนี้สำคัญเท่ากับตัว script เพราะมันคือเส้นแบ่งระหว่าง "รู้ว่าต่าง" กับ "ไม่รู้ว่าต่าง"

จุดที่ต่างdummyjsonของเราทำไมยอมรับได้
GET /products/abc (id ที่ไม่ใช่ตัวเลข) 404 400 Validation failed (numeric string is expected) ParseIntPipe ดักก่อนเข้า handler และ 400 ตรงความจริงกว่า (request ผิดรูป ไม่ใช่ของไม่มี) React app ไม่เคยส่ง id ที่ไม่ใช่ตัวเลข
body ของ error มีแค่ message มี message + error + statusCode เป็นรูปแบบมาตรฐานของ HttpException ใน Nest และ client อ่านแค่ message — script จึงเทียบเฉพาะ message

เขียน script ตรวจว่า API ของเราตอบเหมือน dummyjson สำหรับทุก endpoint ฝั่ง GET บริบท: @package.json @docs/contract @.cursor/rules/project.mdc API ของเรารันที่ http://localhost:3000 และ dummyjson อยู่ที่ https://dummyjson.com endpoint ที่ต้องเทียบ: /products/categories, /products (มี limit/skip), /products/:id, /products/category/:slug ความต่างที่ยอมรับได้: (1) field url ของ category ต่างกันแค่ host (2) response error ของเรามี key statusCode และ error เพิ่มจาก message (3) ลำดับ key ใน object ไม่สำคัญ script รันด้วย node ตรง ๆ (Node 24 รัน .ts ที่มีแต่ type annotation ได้เอง) ห้าม import อะไรเลย และห้ามใช้ enum, namespace หรือ parameter properties โครงสร้าง: สร้าง/แก้ไฟล์ตามนี้ ไม่มากไม่น้อยกว่านี้ - scripts/contract-check.ts (สร้างใหม่) - package.json (แก้ไข: เพิ่ม script "contract:check": "node scripts/contract-check.ts") ข้อกำหนดทางเทคนิค: - const LOCAL = process.env.LOCAL_URL ?? ตรวจโค้ดที่ AI สร้าง

  • ไม่มีบรรทัด import ในไฟล์เลย (grep -n "^import" scripts/contract-check.ts ต้องไม่เจอ)
  • REQUESTS มีแปดรายการ เรียงตามลำดับที่สั่งไว้เป๊ะ
  • normalize เรียงคีย์ด้วย .sort() จริง และเรียก normalize ซ้ำกับค่าข้างในทั้ง array และ object
  • การแทน host ทำกับค่าที่เป็น string ทุกตัว ไม่ใช่เฉพาะ field ชื่อ url
  • firstDifference วน union ของคีย์สองฝั่ง (new Set([...Object.keys(a), ...Object.keys(b)])) จึงจับคีย์ที่หายไปได้ทั้งสองทาง และมีข้อความแยกระหว่าง missing on remote กับ missing on local
  • เส้นทาง error เทียบเฉพาะ message ไม่ใช่ทั้ง body
  • ปิดท้ายด้วย process.exit(1) เมื่อมี ❌ และไม่มี enum, namespace หรือ parameter property ในไฟล์

AI มักพลาดตรงนี้: ตัดจบด้วย JSON.stringify(a) === JSON.stringify(b) — โค้ดสั้นลงมาก แต่ทำลายคุณค่าทั้งหมดของ script เพราะพอ ❌ ขึ้นแล้วเราไม่รู้ว่าต่างที่ไหน อีกข้อคือเติม import fetch from 'node-fetch' เข้ามาตามความเคยชิน ซึ่งจะทำให้ node รันไฟล์นี้ไม่ได้ทันที (ทั้งที่ fetch มีอยู่ใน Node แล้ว) ถ้าเห็นบรรทัด import ให้ลบ ไม่ใช่ไปติดตั้งแพ็กเกจ

โค้ดอ้างอิงของบทนี้ (เทียบกับของคุณทีละบรรทัด):

scripts/contract-check.ts

const LOCAL = process.env.LOCAL_URL ?? 'http://localhost:3000';
const REMOTE = 'https://dummyjson.com';

const REQUESTS = [
  '/products/categories',
  '/products?limit=3&skip=0',
  '/products?limit=2&skip=190',
  '/products/1',
  '/products/194',
  '/products/9999',
  '/products/category/beauty?limit=2&skip=1',
  '/products/category/nope?limit=5&skip=0',
];

type Json = null | boolean | number | string | Json[] | { [key: string]: Json };

function isObject(value: Json): value is { [key: string]: Json } {
  return value !== null && typeof value === 'object' && !Array.isArray(value);
}

function normalize(value: Json): Json {
  if (Array.isArray(value)) {
    return value.map(normalize);
  }
  if (isObject(value)) {
    return Object.fromEntries(
      Object.keys(value)
        .sort()
        .map((key) => [key, normalize(value[key])]),
    );
  }
  if (typeof value === 'string') {
    return value.replace(REMOTE, LOCAL);
  }
  return value;
}

function firstDifference(a: Json, b: Json, path = '$'): string | null {
  if (Array.isArray(a) && Array.isArray(b)) {
    if (a.length !== b.length) {
      return `${path}.length ${a.length} vs ${b.length}`;
    }
    for (let i = 0; i < a.length; i++) {
      const diff = firstDifference(a[i], b[i], `${path}[${i}]`);
      if (diff) return diff;
    }
    return null;
  }
  if (isObject(a) && isObject(b)) {
    for (const key of new Set([...Object.keys(a), ...Object.keys(b)])) {
      if (!(key in a)) return `${path}.${key} missing on remote`;
      if (!(key in b)) return `${path}.${key} missing on local`;
      const diff = firstDifference(a[key], b[key], `${path}.${key}`);
      if (diff) return diff;
    }
    return null;
  }
  return a === b ? null : `${path}: ${JSON.stringify(a)} vs ${JSON.stringify(b)}`;
}

async function load(base: string, path: string): Promise<{ status: number; body: Json }> {
  const response = await fetch(`${base}${path}`);
  const body = (await response.json()) as Json;
  return { status: response.status, body };
}

function messageOf(body: Json): Json {
  return isObject(body) ? body.message : null;
}

let failures = 0;
for (const path of REQUESTS) {
  const [remote, local] = await Promise.all([load(REMOTE, path), load(LOCAL, path)]);
  let diff: string | null;
  if (remote.status !== local.status) {
    diff = `status ${remote.status} vs ${local.status}`;
  } else if (remote.status >= 400) {
    diff = firstDifference(messageOf(remote.body), messageOf(local.body), '$.message');
  } else {
    diff = firstDifference(normalize(remote.body), normalize(local.body));
  }
  console.log(`${diff ? '❌' : '✅'} ${path}${diff ? `  ${diff}` : ''}`);
  if (diff) failures += 1;
}
process.exit(failures === 0 ? 0 : 1);

  • ทำให้พังเพื่อดูว่ามันจับได้จริง: ใน src/products/product.mapper.ts แก้บรรทัดสุดท้ายของ object ที่ return เป็น thumbnail: product.thumbnail + '-broken', ชั่วคราว — แก้ที่ค่า ไม่ใช่เปลี่ยนชื่อ field เพราะถ้าเปลี่ยนชื่อ TypeScript จะฟ้องว่าไม่ตรงกับ ProductResponseDto แล้ว watch mode จะไม่ restart ให้เลย (นั่นคือกลไกป้องกันชั้นแรกของเรา แต่มันทำให้แบบฝึกหัดนี้ไม่ได้ทดสอบอะไร) รอ watch mode compile แล้วรันตรวจซ้ำ — ห้าบรรทัดที่มีสินค้าติดมาใน response จะกลายเป็น ❌
