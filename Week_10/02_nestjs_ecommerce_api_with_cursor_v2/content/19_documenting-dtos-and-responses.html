ตกแต่ง DTO และ Response ให้เอกสารครบ

เมื่อจบบทนี้ คุณจะสามารถ

  • ประกาศ response ของแต่ละ handler ด้วย @ApiOkResponse, @ApiCreatedResponse, @ApiNotFoundResponse และ @ApiBadRequestResponse
  • อธิบายได้ว่าทำไม response DTO ต้องเป็น class และทำไม [Type] ต่างจาก Type
  • ใช้ @ApiPropertyOptional กับ field ที่อาจไม่มี และ @ApiTags เพื่อจัดกลุ่ม endpoint ใน UI

plugin รู้ รูปร่าง แต่ไม่รู้ว่า handler คืนอะไร

บทที่แล้ว CLI plugin อ่านไฟล์ .dto.ts แล้วใส่ metadata ของ field ให้ครบ แต่เปิด /api ดูจะพบว่า endpoint ทุกตัวยังไม่มี response schema — เพราะไม่มีใครบอก Swagger ว่า findOne() คืน ProductResponseDto TypeScript รู้ (จาก return type ของ service) แต่ข้อมูลนั้นหายไปตอน compile ส่วน OpenAPI document สร้างตอน runtime จึงต้องมี decorator ที่ถือ ตัว class จริง มาบอก: @ApiOkResponse({ type: ProductResponseDto })

นี่คือเหตุผลย้อนหลังที่ตอนสร้าง mapper เราประกาศ response DTO เป็น class ไม่ใช่ interface — interface หายไปหมดตอน compile จึงเขียน type: ProductResponseDto ไม่ได้เลย ขณะที่ class ยังเหลือเป็นค่าจริงให้ส่งเข้า decorator ได้ และเพราะ class ถูก อ้างถึง จาก handler มันจึงถูกดึงเข้า components.schemas ให้เอกสารอ้างถึงด้วย $ref ได้ (NestJS Fundamentals เล่าเรื่องเดียวกันในมุมของ @ApiProperty)

สามรูปแบบที่ใช้ในบทนี้

Decoratorใช้ตอนไหนจุดที่ควรสังเกต
@ApiTags('products')บน class ของ controllerจัดกลุ่มใน Swagger UI ให้ endpoint ของ products แยกจาก carts — ไม่มีผลต่อ route
@ApiOkResponse({ type: X })บน handler ที่คืน 200ใส่ [X] เมื่อ handler คืน array เช่น findCategories ที่คืนลิสต์ของ category
@ApiCreatedResponse({ type: X })บน handler ที่คืน 201POST /carts/add คืน 201 ตามค่าเริ่มต้นของ @Post() จึงใช้ตัวนี้ ไม่ใช่ @ApiOkResponse
@ApiNotFoundResponse({ description }) / @ApiBadRequestResponse({ description })บน handler ที่มีทางออก 404 / 400เรามีแค่ข้อความอธิบาย ไม่ต้องมี type เพราะรูปร่าง error มาจาก exception filter ของ Nest
@ApiPropertyOptional()บน field ที่อาจไม่มีใน responseทำให้ discountPercentage หลุดจาก required ของ schema — ตรงกับ mapper ที่ตัด discountPercentage ออกเมื่อค่าเป็น null
@ApiProperty({ example: 1 })บน field ของ body DTO ที่อยากให้มีค่าตัวอย่างค่า example คือค่าที่ Swagger UI เติมให้ในกล่อง Try it out ทำให้ทดลองยิง POST /carts/add ได้เร็ว

สำหรับ field ที่เป็น nested object หรือ array ของ object ใน body DTO เราต้องบอก type ให้ชัดด้วย @ApiProperty({ type: [CartProductDto] }) และ @ApiProperty({ type: AddressDto }) — วงเล็บเหลี่ยมคือความต่างเดียวระหว่าง หนึ่งตัว กับ อาเรย์ ในสายตาของ OpenAPI

รายการด้านล่างคือไฟล์และ decorator ที่โค้ดอ้างอิงของคอร์สใช้ — Cursor อาจเลือก decorator หรือแก้ไฟล์ต่างออกไปได้ ขอแค่ไม่แตะไฟล์ที่ไม่เกี่ยวกับเป้าหมายและผ่านผลลัพธ์ที่ต้องได้ใน prompt

  • src/products/products.controller.ts — สัญญา: ต้องมี @ApiTags('products') บน class และ response decorator บนทั้งสี่ handler / ต้องไม่แก้ logic และต้องไม่สลับลำดับ handler
  • src/orders/carts.controller.ts — สัญญา: ต้องมี @ApiTags('carts') และ @ApiCreatedResponse + @ApiBadRequestResponse บน create / ต้องไม่แตะ OrdersService
  • src/products/dto/product-response.dto.ts — สัญญา: ต้องใส่ @ApiPropertyOptional() ให้ discountPercentage ตัวเดียว / ต้องไม่ใส่ decorator ให้ field อื่น
  • src/orders/dto/add-cart.dto.ts — สัญญา: ต้องใส่ @ApiProperty ให้สาม field ของ AddCartDto ตามที่ระบุ / ต้องไม่แตะ decorator ของ class-validator ที่มีอยู่

สั่ง Cursor ตกแต่งเอกสารให้ครบทุก endpoint

commit งานก่อน แล้วเปิดแชทใหม่ใน Cursor โหมด Agent (git add -A && git commit -m "chore: checkpoint before swagger decorations") จากนั้นส่ง prompt นี้ — กติกาเดิม: AI พิมพ์แทนคุณได้ แต่คุณต้องอธิบายทุกบรรทัดได้

ตกแต่ง controller และ DTO ด้วย decorator ของ @nestjs/swagger ให้เอกสารที่ /api บอก response ของทุก endpoint @<controller และ DTO ที่ต้องติด decorator — โค้ดอ้างอิงคือ src/products/products.controller.ts, src/orders/carts.controller.ts, src/products/dto/product-response.dto.ts, src/orders/dto/add-cart.dto.ts> ผลลัพธ์ที่ต้องได้: - /api แบ่ง endpoint เป็นสองกลุ่ม: products และ carts - ใน /api-json ทุก endpoint มี response schema: GET /products/categories → array ของ category, GET /products และ GET /products/category/{slug} → list envelope, GET /products/{id} → product (200) และ 404 ที่ description เป็น Product 9999 not found, POST /carts/add → receipt (201) และ 400 - components.schemas.ProductResponseDto.required ไม่มี discountPercentage (ตรงกับ docs/api-spec.md ที่ key นี้ optional) ส่วน field อื่นยังเป็น required ตามเดิม - schema ของ AddCartDto แสดง products เป็น array ของ object และ address เป็น object ซ้อน ไม่ใช่ type ว่าง และปุ่ม Try it out ของ POST /carts/add มี userId ตัวอย่างเป็น 1 - พฤติกรรม API ไม่เปลี่ยน: npm run test:e2e ผ่านครบทั้งสิบ test ของสัญญา และ GET /products/categories ยังตอบ 200 (ไม่โดน route :id) - npm run build และ npm run lint ผ่าน ขอบเขต: - ห้ามติดตั้ง dependency ใหม่ - ห้ามแก้ logic หรือ validation เดิม — งานนี้เพิ่มแค่เอกสาร

ตรวจโค้ดที่ AI สร้าง

  • /api แบ่ง endpoint เป็นกลุ่ม products และ carts
  • GET /products/categories มี response schema เป็น array ของ category — ไม่ใช่ category ตัวเดียว
  • list endpoint ชี้ไป list envelope, GET /products/{id} ชี้ไป product พร้อม 404 ที่ข้อความตรงตัวทุกตัวอักษร และ POST /carts/add ประกาศ 201 ไม่ใช่ 200
  • GET /products/categories ยังตอบ 200 — ถ้าได้ 400 แปลว่า handler ถูกจัดลำดับใหม่จน route :id มาก่อน
  • discountPercentage ไม่อยู่ใน required ของ ProductResponseDto แต่ field อื่นยังอยู่
  • validation ของ POST /carts/add ยังทำงาน — ยิง body ที่ไม่มี userId ยังได้ 400 (decorator ของ class-validator ไม่ถูกแทนที่)
  • git status ไม่มีไฟล์ที่ไม่เกี่ยวกับเป้าหมายถูกแก้ (service, mapper และ main.ts ไม่ถูกแตะ), import ทุกเส้นลงท้าย .js และ npm run build / npm run lint ผ่าน

AI มักพลาดตรงนี้: ใส่ decorator เพลินจนใส่ @ApiProperty() ให้ทุก field ของทุก DTO — ซึ่งเป็นสิ่งที่ CLI plugin มีไว้เพื่อไม่ให้เราต้องทำ ผลคือไฟล์ยาวขึ้นเท่าตัวโดยเอกสารไม่ได้ดีขึ้นเลย ถ้าเจอให้ถามตัวเองว่ามันเพิ่มอะไรให้เอกสารจริงไหม อีกอันตรายที่แนบเนียนกว่าคือมันจัดเรียง handler ใหม่ตาม ความสวยงาม (เช่นย้าย @Get(':id') ขึ้นไปไว้ต้น class) ซึ่งทำให้ GET /products/categories กลายเป็นการหา product id ชื่อ categories แล้วได้ 400 จาก ParseIntPipe — ยิง GET /products/categories ตรวจทุกครั้ง

โค้ดอ้างอิงของบทนี้ — เป็นหนึ่งในวิธีที่ถูก ของคุณไม่จำเป็นต้องเหมือนทุกบรรทัด ขอแค่ผ่านผลลัพธ์ที่ต้องได้:

/* src/products/products.controller.ts */
import { Controller, Get, Param, ParseIntPipe, Query } from '@nestjs/common';
import { ApiNotFoundResponse, ApiOkResponse, ApiTags } from '@nestjs/swagger';
import { PaginationQueryDto } from './dto/pagination-query.dto.js';
import {
  CategoryResponseDto,
  ProductListResponseDto,
  ProductResponseDto,
} from './dto/product-response.dto.js';
import { ProductsService } from './products.service.js';

@ApiTags('products')
@Controller('products')
export class ProductsController {
  constructor(private readonly productsService: ProductsService) {}

  @Get('categories')
  @ApiOkResponse({ type: [CategoryResponseDto] })
  findCategories() {
    return this.productsService.findCategories();
  }

  @Get('category/:slug')
  @ApiOkResponse({ type: ProductListResponseDto })
  findByCategory(@Param('slug') slug: string, @Query() query: PaginationQueryDto) {
    return this.productsService.findByCategory(slug, query);
  }

  @Get()
  @ApiOkResponse({ type: ProductListResponseDto })
  findAll(@Query() query: PaginationQueryDto) {
    return this.productsService.findAll(query);
  }

  @Get(':id')
  @ApiOkResponse({ type: ProductResponseDto })
  @ApiNotFoundResponse({ description: "Product 9999 not found" })
  findOne(@Param('id', ParseIntPipe) id: number) {
    return this.productsService.findOne(id);
  }
}
/* src/orders/carts.controller.ts */
import { Body, Controller, Post } from '@nestjs/common';
import { ApiBadRequestResponse, ApiCreatedResponse, ApiTags } from '@nestjs/swagger';
import { AddCartDto } from './dto/add-cart.dto.js';
import { CartResponseDto } from './dto/cart-response.dto.js';
import { OrdersService } from './orders.service.js';

@ApiTags('carts')
@Controller('carts')
export class CartsController {
  constructor(private readonly ordersService: OrdersService) {}

  @Post('add')
  @ApiCreatedResponse({ type: CartResponseDto })
  @ApiBadRequestResponse({ description: 'Validation failed' })
  create(@Body() dto: AddCartDto) {
    return this.ordersService.create(dto);
  }
}

  discountPercentage?: number;
  rating: number;
  stock: number;
  tags: string[];
  brand: string;
  sku: string;
  weight: number;
  /* … field ที่เหลือเหมือนเดิม ไม่มี decorator … */
}
/* src/orders/dto/add-cart.dto.ts — เฉพาะส่วนที่เปลี่ยน */
import { ApiProperty } from '@nestjs/swagger';
import { Type } from 'class-transformer';
/* … import ของ class-validator เหมือนเดิม … */

export class AddCartDto {
  @ApiProperty({ example: 1 })
  @IsInt()
  @Min(1)
  userId: number;

  @ApiProperty({ type: [CartProductDto] })
  @IsArray()
  @ArrayMinSize(1)
  @ValidateNested({ each: true })
  @Type(() => CartProductDto)
  products: CartProductDto[];

  @ApiProperty({ type: AddressDto })
  @ValidateNested()
  @Type(() => AddressDto)
  address: AddressDto;
}

ถ้าอธิบายบรรทัดไหนไม่ได้ ยังไม่ผ่านบทนี้ — กลับไปอ่านส่วนแนวคิดก่อน

ผลลัพธ์ที่คาดหวัง

เปิด http://localhost:3000/api จะเห็น endpoint ถูกแบ่งเป็นสองกลุ่มคือ products และ carts แต่ละตัวกางดูได้ว่า response 200/201 หน้าตาอย่างไร ตัว GET /products/{id} มีทั้ง 200 ที่ชี้ไป ProductResponseDto และ 404 พร้อมข้อความ Product 9999 not found ส่วน POST /carts/add มีปุ่ม Try it out ที่เติม body ตัวอย่างให้แล้ว (เพราะ example: 1 ที่ userId) การแก้รอบนี้เป็นการแก้ไฟล์ source ธรรมดา watch mode จึง recompile เองได้ ไม่ต้อง restart เหมือนบทที่แล้ว
