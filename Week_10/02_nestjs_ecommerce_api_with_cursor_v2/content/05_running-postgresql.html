รัน PostgreSQL ด้วย Docker Compose

เมื่อจบบทนี้ คุณจะสามารถ

  • เขียน docker-compose.yml สำหรับ postgres:17 ที่เก็บข้อมูลถาวรด้วย named volume
  • อธิบายได้ว่า .env ทั้งสี่ key ถูกใช้ที่ไหนในโปรเจกต์นี้
  • พิสูจน์ด้วย psql ในคอนเทนเนอร์ว่า database ชื่อ ecommerce เกิดขึ้นจริง

ฐานข้อมูลอยู่ในคอนเทนเนอร์ ไม่ใช่ในเครื่องเรา

เราใช้วิธีเดียวกับ NestJS Fundamentals บทรัน PostgreSQL ด้วย Docker Compose: ไม่ติดตั้ง PostgreSQL ลงเครื่องโดยตรง แต่ประกาศมันเป็น service ในไฟล์ docker-compose.yml แล้วให้ Docker ยกขึ้นให้ ข้อดีคือทุกคนในทีมได้ PostgreSQL เวอร์ชันเดียวกันจากไฟล์เดียว และลบทิ้งทั้งชุดได้เมื่อจบคอร์ส คำสั่งที่ใช้ตลอดคอร์สมีแค่สามคำสั่งนี้

# ยกฐานข้อมูลขึ้นแบบ background (detached)
docker compose up -d

# ดูว่า service ไหนรันอยู่ และ map port อะไร
docker compose ps

# ปิดคอนเทนเนอร์ (ข้อมูลยังอยู่ใน volume)
docker compose down

เราปักเวอร์ชันเป็น postgres:17 ไม่ใช่ postgres:latest เพราะ latest จะเปลี่ยน major version ใต้เท้าเราเมื่อ Docker Hub ปล่อยรุ่นใหม่ แล้ว volume ที่สร้างด้วย PostgreSQL รุ่นเก่าจะเปิดด้วยรุ่นใหม่ไม่ได้

named volume ทำให้ข้อมูลไม่หายตอน down

ถ้าไม่ประกาศ volume ข้อมูลทุกแถวจะอยู่ใน filesystem ของคอนเทนเนอร์และหายไปพร้อมกับคอนเทนเนอร์ เราจึงเมานต์ named volume ชื่อ pgdata ไว้ที่ /var/lib/postgresql/data ซึ่งเป็น data directory ของ PostgreSQL

  • docker compose down ลบคอนเทนเนอร์ แต่ ไม่ ลบ volume — ยกขึ้นใหม่แล้วสินค้าที่ seed ไว้ยังอยู่ครบ
  • docker compose down -v ลบ volume ด้วย — เท่ากับเริ่มจากฐานข้อมูลว่าง ต้อง migrate และ seed ใหม่ (มีประโยชน์เวลาต้องการล้างของจริง)

เราเลือก named volume (pgdata:) แทน bind mount (./data:/var/lib/postgresql/data) เพราะ named volume ถูกจัดการโดย Docker ไม่โผล่เป็นโฟลเดอร์ในโปรเจกต์ให้เผลอ commit ขึ้น git

ทำไมต้อง POSTGRES_DB=ecommerce

ในคอร์ส NestJS Fundamentals เราต่อกับ database ปริยายชื่อ postgres ได้เพราะมีโปรเจกต์เดียว คอร์สนี้เราตั้ง POSTGRES_DB=ecommerce ให้คอนเทนเนอร์สร้าง database เฉพาะของโปรเจกต์ตั้งแต่ boot ครั้งแรก เหตุผลคือ DATABASE_URL ของ Prisma ลงท้ายด้วยชื่อ database (…/ecommerce) ถ้าลืม key นี้ database จะไม่มีจริง แล้วขั้น migration แรก (prisma migrate dev) จะล้มด้วย error ว่าหา database ไม่เจอ

ตัวแปร POSTGRES_PASSWORD เป็น key เดียวที่ image บังคับให้ใส่ ส่วน user เราไม่ตั้งเอง จึงได้ superuser ปริยายชื่อ postgres — ตรงกับ -U postgres ในคำสั่ง psql และตรงกับ postgres:pass123 ใน DATABASE_URL รหัสผ่านแบบนี้ใช้ได้เพราะฐานข้อมูลนี้เปิดอยู่แค่บนเครื่องเราเพื่อเรียน ไม่ใช่ของจริงบน production

.env สี่บรรทัด ใครใช้บรรทัดไหน

เราสร้าง .env ครบทั้งสี่ key ตั้งแต่บทนี้ แล้วบทหลัง ๆ ค่อยมาหยิบไปใช้ทีละตัว จะได้ไม่ต้องกลับมาแก้ไฟล์เดิมซ้ำ ๆ

Keyใครอ่านใช้ทำอะไร
DATABASE_URLPrisma CLI (prisma7.config.ts) และ PrismaServiceconnection string ของ PostgreSQL — ใช้ตั้งแต่ตอนตั้งค่า Prisma
PORTsrc/main.tsport ที่แอปฟัง (ภายหลังจะอ่านผ่าน ConfigService แทนเลข 3000 ที่ฝังไว้)
APP_URLProductsServiceฐานของ url ในผลลัพธ์ GET /products/categories เพราะ type Category ฝั่ง client (src/features/products/types.ts) กำหนดให้มี url เต็มเสมอ
CORS_ORIGINsrc/main.tsorigin ของ React app ที่อนุญาตให้เรียกข้าม origin ได้ (ตอนเปิด CORS ภายหลัง)

ไฟล์ .env จะไม่ถูก commit (ถูก ignore ไว้) เราจึง commit .env.example คู่กันเสมอ เพื่อให้คนที่ clone โปรเจกต์รู้ว่าต้องมี key อะไรบ้าง ในโปรเจกต์เรียนนี้ไม่มี secret จริง ค่าทั้งสองไฟล์จึงเหมือนกันทุกบรรทัด — ในงานจริง .env.example จะเว้นค่าไว้ว่างหรือใส่ค่าตัวอย่างเท่านั้น

เป้าหมายของบทนี้

ecommerce-api/
├── docker-compose.yml      (สร้างใหม่)
├── .env                    (สร้างใหม่ — ไม่ commit)
├── .env.example            (สร้างใหม่ — commit)
└── .gitignore              (แก้ไข: ต้องมีบรรทัด .env)
  • docker-compose.yml — สัญญา: ต้องมี service เดียวชื่อ db จาก image postgres:17, map 5432:5432, ตั้ง POSTGRES_PASSWORD กับ POSTGRES_DB และใช้ named volume pgdata / ต้องไม่มี key version และต้องไม่เพิ่ม service อื่น
  • .env — สัญญา: ต้องมีสี่บรรทัดตามลำดับ DATABASE_URL, PORT, APP_URL, CORS_ORIGIN / ต้องไม่ครอบค่าด้วยเครื่องหมายคำพูด และต้องไม่ถูก commit
  • .env.example — สัญญา: ต้องมี key และค่าเหมือน .env ทั้งสี่บรรทัด / ต้องไม่มี key เกินมา
  • .gitignore — สัญญา: ต้องทำให้ .env ถูก ignore / ต้องไม่ลบบรรทัดเดิมของ scaffold

ให้ Cursor สร้าง compose file และ .env

commit งานก่อน แล้วเปิดแชทใหม่ใน Cursor โหมด Agent (git add -A && git commit -m "chore: add cursor rules" ถ้ายังไม่ได้ commit ไฟล์ rules) แชทใหม่หมายถึงบริบทสะอาด ไม่มีคำสั่งเก่าค้างมากวน แล้วส่ง prompt นี้ทั้งก้อน

สร้าง Docker Compose สำหรับ PostgreSQL และไฟล์ .env ของโปรเจกต์ @.gitignore ผลลัพธ์ที่ต้องได้: - docker compose up -d แล้ว docker compose ps เห็น service เดียวชื่อ db จาก image postgres:17 สถานะ Up และ port 5432 ของเครื่อง map เข้าคอนเทนเนอร์ - docker compose exec db psql -U postgres -d ecommerce -c '\l' เห็น database ชื่อ ecommerce (รหัสผ่าน superuser คือ pass123) - docker compose down แล้ว up -d ใหม่ database ecommerce ยังอยู่ (ข้อมูลเก็บใน named volume ไม่ใช่ bind mount) - docker compose up ไม่ขึ้น warning เรื่อง key ที่เลิกใช้แล้ว - .env มีสี่บรรทัดตามลำดับนี้ ค่าไม่ครอบด้วยเครื่องหมายคำพูด DATABASE_URL=postgresql://postgres:pass123@localhost:5432/ecommerce PORT=3000 APP_URL=http://localhost:3000 CORS_ORIGIN=http://localhost:5173 - diff .env .env.example ไม่มีผลต่าง (โปรเจกต์นี้ไม่มี secret จริง) - git status ไม่เห็น .env และบรรทัดเดิมของ .gitignore ยังอยู่ครบ ขอบเขต: - ห้ามติดตั้ง dependency ใหม่ - ห้ามรัน docker compose up ให้ผมรันเอง - ยังไม่ต้องติดตั้งหรือตั้งค่า Prisma

เมื่อ Cursor สร้างไฟล์ครบแล้ว ยกฐานข้อมูลขึ้นเอง (prompt สั่งห้าม Agent รัน docker ให้)

docker compose up -d docker compose ps

ตรวจโค้ดที่ AI สร้าง

  • docker compose up -d ไม่ขึ้น warning ว่ามี key ที่เลิกใช้ (เช่น version)
  • image เป็น postgres:17 ที่ปักเวอร์ชันไว้ ไม่ใช่ postgres:latest
  • database ecommerce เกิดขึ้นจริงตอน boot — ถ้าไม่มี DATABASE_URL จะชี้ไป database ที่ไม่มีอยู่
  • ข้อมูลอยู่รอดหลัง docker compose down / up -d และไม่มีโฟลเดอร์ข้อมูลโผล่ในโปรเจกต์ (ใช้ named volume ไม่ใช่ bind mount)
  • .env มีสี่บรรทัดพอดี เรียงตามที่สั่ง และไม่มีเครื่องหมายคำพูดครอบค่า (PORT=3000 ไม่ใช่ PORT="3000")
  • diff .env .env.example ต้องไม่มีผลต่าง
  • git status ไม่เห็น .env และไม่มีไฟล์ที่ไม่เกี่ยวกับเป้าหมายถูกแก้ (เช่นไฟล์ใน src/)

AI มักพลาดตรงนี้: เติม version: "3" ไว้บนสุด (เป็นรูปแบบเก่าที่ยังเจอในบทความทั่วเน็ต), เพิ่มบรรทัด POSTGRES_USER: … ที่เราไม่ได้สั่ง (ทำให้ user ไม่ตรงกับ postgres ใน DATABASE_URL), หรือครอบค่าใน .env ด้วยเครื่องหมายคำพูด (บาง loader จะอ่านเครื่องหมายคำพูดติดไปเป็นส่วนของค่า)

scaffold ของ Nest ใส่ .env ไว้ใน .gitignore ให้แล้วใต้หัวข้อ # dotenv environment variable files ดังนั้นถ้า Agent บอกว่า ไม่ต้องแก้ .gitignore เพราะมีอยู่แล้ว ก็ถูกต้อง สิ่งที่เราตรวจคือผลลัพธ์ (git status ไม่โชว์ .env) ไม่ใช่จำนวนบรรทัดที่ถูกเพิ่ม

โค้ดอ้างอิงของบทนี้ — เป็นหนึ่งในวิธีที่ถูก ของคุณไม่จำเป็นต้องเหมือนทุกบรรทัด ขอแค่ผ่านผลลัพธ์ที่ต้องได้:

# docker-compose.yml
services:
  db:
    image: postgres:17
    restart: always
    ports:
      - "5432:5432"
    environment:
      POSTGRES_PASSWORD: pass123
      POSTGRES_DB: ecommerce
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
# .env และ .env.example (เนื้อหาเหมือนกัน)
DATABASE_URL=postgresql://postgres:pass123@localhost:5432/ecommerce
PORT=3000
APP_URL=http://localhost:3000
CORS_ORIGIN=http://localhost:5173

ถ้าอธิบายบรรทัดไหนไม่ได้ ยังไม่ผ่านบทนี้ — กลับไปอ่านส่วนแนวคิดก่อน

ผลลัพธ์ที่คาดหวัง

ครั้งแรก docker compose up -d จะดึง image postgres:17 ลงมาก่อน (ใช้เวลาสักครู่) แล้วจบด้วยบรรทัด Container ecommerce-api-db-1 Started ส่วน docker compose ps ต้องเห็นหนึ่งแถว: service db, STATUS ขึ้นต้นด้วย Up และ PORTS เป็น 0.0.0.0:5432->5432/tcp ถ้า STATUS ขึ้น Restarting ค้าง ให้ดู docker compose logs db — สาเหตุที่พบบ่อยคือลืม POSTGRES_PASSWORD

ถ้าได้ error port is already allocated แปลว่ามี PostgreSQL ตัวอื่นจับ 5432 อยู่ในเครื่องแล้ว (อาจเป็นของโปรเจกต์อื่นหรือที่ติดตั้งไว้ตรง ๆ) ปิดตัวนั้นก่อนแล้วสั่ง docker compose up -d ใหม่ ถ้าปิดไม่ได้ ต้องเปลี่ยน port ฝั่งซ้ายของ 5432:5432 พร้อมเปลี่ยนเลข port ใน DATABASE_URL ให้ตรงกันทั้งสองที่ — คอร์สนี้จะใช้ 5432 ตลอด

ตรวจว่าใช้งานได้จริง

  • ถาม PostgreSQL ตรง ๆ ว่ามี database ecommerce จริงไหม — เข้าไปรัน psql ในคอนเทนเนอร์ (ไม่ต้องติดตั้ง client ในเครื่อง)
docker compose exec db psql -U postgres -d ecommerce -c '\l' | grep ecommerce
 ecommerce | postgres | UTF8     | libc            | en_US.utf8 | en_US.utf8 |        |
  • ถ้าครั้งแรกได้ socket … failed: No such file or directory ไม่ต้องตกใจ — คอนเทนเนอร์ยัง restart ตัวเองอยู่ในขั้น init รออีกไม่กี่วินาทีแล้วรันซ้ำ จะได้แถวข้างบน
  • git status ต้องไม่มี .env โผล่มาในรายการ (ถ้าโผล่ แปลว่า .gitignore ยังไม่ครอบ ต้องแก้ก่อน commit)
  • ทดสอบว่า volume ทำงาน: docker compose down แล้ว docker compose up -d อีกครั้ง — คำสั่ง \l ข้างบนยังเห็น ecommerce เหมือนเดิม
  • เมื่อผ่านทุกข้อแล้ว commit ด้วย git add -A && git commit -m "feat: postgres via docker compose"
